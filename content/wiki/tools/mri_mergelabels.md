# mri_mergelabels

## Summary

`mri_mergelabels` concatenates multiple FreeSurfer `.label` files into a single output label file. It preserves the header from the first input file, sums the vertex counts, and appends the vertex data rows from all inputs. It is a simple tcsh script that performs label file merging for use in defining combined cortical ROIs.

## Source Information

- **Language:** tcsh shell script
- **Source file:** `scripts/mri_mergelabels`

## Purpose and Context

FreeSurfer label files (`.label`) define sets of surface vertices that belong to a region of interest. When working with cortical parcellations, it is often necessary to combine multiple labels — for example, merging individual parcellation labels from `mri_annotation2label` to define a larger ROI, or combining left and right hemisphere labels for bilateral analyses.

`mri_mergelabels` handles this by simply concatenating the vertex lists: it reads the header from the first label, computes the total vertex count, and appends all vertex data rows. The result is a valid FreeSurfer label file.

## Inputs

| Input | Format | Description |
|-------|--------|-------------|
| Input labels | `.label` | Two or more label files, specified with `-i` or `-d` |

## Outputs

| Output | Format | Description |
|--------|--------|-------------|
| Merged label | `.label` | Combined label file containing all input vertices |

## Mathematical Foundations

Label merging is purely concatenative:

$$
L_{merged} = L_1 \cup L_2 \cup \cdots \cup L_N
$$

The output vertex count is $\sum_{i=1}^N |L_i|$. No deduplication is performed — if a vertex appears in multiple input labels, it will appear multiple times in the output. Downstream tools that read the merged label should handle duplicates appropriately (most will treat the label as a set and deduplicate).

## Configuration Options

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `-i <fname>` | string | repeatable | Add an input label file to the merge list |
| `-d <dir>` | string | null | Add all `.label` files in this directory to the merge list |
| `-o <fname>` | string | required | Output merged label filename |

## Configuration Interactions

- `-i` and `-d` can be freely mixed. All files collected by both flags are merged into the single output.
- `-d` adds all `.label` files found in the specified directory — no filtering by name or content.
- The header (first line of the output label) is taken verbatim from the first input label. This means the subject/surface context is preserved from the first input.

## Typical Use Cases

```bash
# Merge two specific labels
mri_mergelabels \
  -i lh.superiortemporal.label \
  -i lh.middletemporal.label \
  -o lh.temporal_combined.label

# Merge all labels in a directory
mri_mergelabels \
  -d /path/to/labeldir \
  -o combined_all.label

# Merge labels from multiple subjects' outputs
mri_mergelabels \
  -i subject1/lh.roi.label \
  -i subject2/lh.roi.label \
  -o group_roi.label
```

## Pipeline Context

Not part of standard `recon-all`. Used in analysis workflows where:
- Labels from `mri_annotation2label` need to be combined into larger ROIs.
- Bilateral ROIs are built from separate lh/rh labels.
- Custom ROI masks are built from multiple anatomical regions.

## Gotchas and Caveats

> [!gotcha] No deduplication
> The script does not check for duplicate vertices. If a vertex appears in two input labels, it will appear twice in the merged output. Tools like `mri_label2vol` typically handle this gracefully (the voxel is simply included), but tools that expect unique vertex lists may behave unexpectedly.

> [!gotcha] Header taken from first input
> The output header line `#label, from subject ??` (as shown in the source comment) is taken from the first input file. If input labels are from different subjects or hemispheres, the header may not accurately reflect the merged label's provenance.

> [!gotcha] All labels must have the same column structure
> Label files have a specific column structure: `<vertex_index> <x> <y> <z> <value>`. All input files must follow this structure. If any label was generated by a non-standard tool with different columns, the merge will produce a malformed output.

> [!gotcha] Empty directory with -d
> If `-d` points to a directory with no `.label` files, the merge will produce an output with an empty vertex list (just a header and `0`). No error or warning is raised.
