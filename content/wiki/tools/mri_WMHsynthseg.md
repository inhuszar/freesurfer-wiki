# mri_WMHsynthseg

## Summary

`mri_WMHsynthseg` is a deep learning tool for joint segmentation of brain anatomy and white matter hyperintensities (WMHs) from T2-FLAIR or T1-weighted MRI. It wraps the WMH-SynthSeg model (a 3D U-Net trained on synthetic data) and produces a segmentation volume labelling both standard neuroanatomical structures and WMH lesions simultaneously. It requires a separately downloaded model weight file and PyTorch.

## Source Information

- **Language:** Python (bash launcher + Python inference script)
- **Launcher:** `mri_WMHsynthseg/mri_WMHsynthseg` (bash script)
- **Python entry point:** `mri_WMHsynthseg/WMHSynthSeg/inference.py`
- **Model weight:** `$FREESURFER_HOME/models/WMH-SynthSeg_v10_231110.pth` (PyTorch checkpoint — must be downloaded separately)
- **Backend:** PyTorch 3D U-Net (`WMHSynthSeg/unet3d/model.py`)

## Purpose and Context

White matter hyperintensities (WMHs) — also called leukoaraiosis or white matter lesions — appear as hyperintense regions on T2-FLAIR MRI and are associated with cerebrovascular disease, normal ageing, and various neurological conditions. Accurate WMH quantification requires:

1. Detecting the WMH lesions themselves
2. Segmenting surrounding anatomical structures (to provide spatial context and volume normalisation)

WMH-SynthSeg performs both simultaneously in a single forward pass. The tool is designed to generalise across MRI contrasts and scanner manufacturers without retraining (following the SynthSeg paradigm of training on synthetic data generated from label maps).

## Inputs

| Flag | Description |
|------|-------------|
| `--i input` | Input image (`.nii`, `.nii.gz`, `.mgz`) or directory of images |
| `--o output` | Output segmentation (file or directory) |
| `--csv_vols file` | Optional: CSV file to record ROI volumes |
| `--device device` | Computing device: `cpu` (default) or `cuda` |

| `--save_lesion_probabilities` | Save lesion probability maps (optional) |
| `--crop` | Two-pass processing for GPU: crops to 192×224×192 cuboid |

## Outputs

| Output | Description |
|--------|-------------|
| Segmentation volume | Integer label map; includes anatomical labels plus WMH labels |
| CSV volumes (optional) | Per-ROI volume table when `--csv_vols` is specified |
| Lesion probability maps (optional) | Float probability maps when `--save_lesion_probabilities` is specified |

## Mathematical Foundations

WMH-SynthSeg is based on the SynthSeg framework:

1. **Training:** The U-Net is trained entirely on synthetic MRI images generated by sampling random label maps and applying spatial deformations, intensity augmentation, and contrast variation. This removes dependence on specific imaging protocols.

2. **Architecture:** 3D U-Net with encoder-decoder structure and skip connections (`WMHSynthSeg/unet3d/model.py`). The model takes a 3D MRI volume as input and outputs a multi-class segmentation.

3. **Inference:** The model performs a single forward pass through the U-Net to produce the segmentation. With `--crop`, the volume is first padded/cropped to a standard 192×224×192 size (required to fit in typical GPU memory), the model is applied, and the result is mapped back to the original space.

> [!math] SynthSeg training paradigm
> All training images are synthesised from anatomical label maps using:
> $$
> I_{\text{synth}} = \mathcal{G}(\sigma) * \sum_k \mathcal{N}(\mu_k, \sigma_k^2) \cdot \mathbb{1}[L = k]
> $$
> where $\mathcal{G}(\sigma)$ is a Gaussian smoothing kernel, $L$ is the label map, and $(\mu_k, \sigma_k^2)$ are randomly sampled intensity parameters per label. This makes the model contrast-agnostic.

## Configuration Interactions

- `--device cuda` requires a CUDA-compatible GPU and PyTorch with CUDA support. If CUDA is unavailable, inference falls back or fails.
- `--crop` is recommended when using --device cuda to avoid GPU memory overflow on high-resolution inputs.
- If `--i` is a directory, `--o` must also be a directory. All `.nii`, `.nii.gz`, and `.mgz` files in the input directory are processed.
- `--threads -1` uses all available CPU cores for parallel inference.

## Typical Use Cases

```bash
# Segment WMHs from a single T2-FLAIR volume (CPU)
mri_WMHsynthseg \
    --i flair.mgz \
    --o wmh_seg.mgz \
    --csv_vols wmh_volumes.csv

# GPU inference with crop mode
mri_WMHsynthseg \
    --i flair.nii.gz \
    --o wmh_seg.nii.gz \
    --device cuda \
    --crop

# Process all images in a directory
mri_WMHsynthseg \
    --i /data/subjects/ \
    --o /data/wmh_outputs/

# Save lesion probability maps
mri_WMHsynthseg \
    --i flair.mgz \
    --o wmh_seg.mgz \
    --save_lesion_probabilities
```

## Pipeline Context

`mri_WMHsynthseg` is not part of the standard `recon-all` pipeline. It is a standalone post-processing tool for:

- Clinical and research WMH burden quantification
- Longitudinal WMH tracking
- Studies of cerebrovascular disease

It can be applied to T2-FLAIR volumes or T1-weighted volumes, although T2-FLAIR typically provides better WMH contrast.

## Gotchas and Caveats

> [!gotcha] Model file must be downloaded separately
> The model weight file `WMH-SynthSeg_v10_231110.pth` is not bundled with FreeSurfer. The launcher script checks for this file and displays download instructions if it is absent:
> ```
> wget https://ftp.nmr.mgh.harvard.edu/pub/dist/lcnpublic/dist/WMH-SynthSeg/WMH-SynthSeg_v10_231110.pth
> ```
> Place it in `$FREESURFER_HOME/models/`.

> [!gotcha] Python environment must have PyTorch
> The tool runs via `fspython` (FreeSurfer's managed Python environment). If PyTorch is not installed in this environment, the tool will fail with an import error. See FreeSurfer's Python setup documentation.

> [!gotcha] CPU inference is slow
> Running on CPU without `--threads` can be very slow for large volumes. Use `--threads -1` to parallelise or `--device cuda` for GPU acceleration.

> [!gotcha] Tool name uses mixed case
> The binary is `mri_WMHsynthseg` (capital `WMH`, lowercase `synthseg`). Tab completion on case-sensitive filesystems will require exact capitalisation.
