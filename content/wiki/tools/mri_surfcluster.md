# mri_surfcluster

## Summary

`mri_surfcluster` performs cluster-growing and cluster-wise inference on surface-encoded statistical maps. It identifies contiguous regions (clusters) of vertices exceeding a threshold, computes cluster size (area in mm²), and optionally assigns cluster-wise p-values using either a precomputed permutation/simulation distribution (CSD) or Gaussian Random Field (GRF) theory. It is the surface analogue of `mri_volcluster`.

## Source Information

- **Language:** C++
- **Source file:** `mri_surfcluster/mri_surfcluster.cpp`
- **Key libraries:** `surfcluster`, `randomfields`, `volcluster`, `annotation`
- **Original author:** Douglas N. Greve (MGH)

## Purpose and Context

After running a vertex-wise GLM (e.g., with `mri_glmfit`) on surface data resampled to `fsaverage`, one needs to control the family-wise error rate (FWER) across ~163,000 vertices. `mri_surfcluster` addresses this by:

1. Applying a vertex-wise threshold to identify suprathreshold vertices.
2. Growing connected clusters of suprathreshold vertices.
3. Measuring cluster area (mm²) weighted by group-average vertex areas.
4. Assigning p-values using either CSD (permutation) or GRF theory.

It reads the source surface for metric properties (area computation) and the statistical map as a surface overlay.

## Mathematical Foundations

### Cluster-Wise Inference via GRF

When `--fwhm` is specified, `mri_surfcluster` uses Gaussian Random Field theory to estimate the cluster-wise p-value. The expected Euler characteristic of a smooth random field on a 2D manifold is used to approximate the distribution of the maximum cluster size.

> [!math] GRF cluster p-value (approximate)
> For a 2D surface search space of area $A$ (mm²) with smoothness FWHM and threshold $u$:
> $$P(\text{max cluster size} \geq S) \approx \mathbb{E}[\chi(\mathcal{E}_u)] \cdot P(S_1 \geq S \mid \text{cluster exists})$$
> The precise formula used is in `surfcluster.c` (`SurfClusterSumAlloc`, `sclustGRFpval`).

### Cluster-Wise Inference via CSD (Permutation)

When `--csd` is specified, the empirical distribution of maximum cluster sizes (from Monte Carlo simulation or permutation testing, generated by tools such as `mri_glmfit-sim`) is used to directly assign p-values:

$$p_{\text{cluster}} = \frac{\#\{\text{simulations where max cluster size} \geq S_{\text{obs}}\}}{N_{\text{sim}}}$$

with confidence intervals given by the `--ciPct` parameter.

### Bonferroni Correction

When `--bonf` or `--bonf-max` is specified, a Bonferroni correction is applied to the cluster-wise p-values:
$$p_{\text{corrected}} = 1 - (1 - p_{\text{raw}})^N$$

## Configuration Interactions

- `--csd` and `--fwhm` are mutually exclusive methods for cluster-wise p-values. Using both is undefined.
- `--cwpvalthresh` prunes clusters after p-values are computed; it requires either `--csd` or `--fwhm` to be specified.
- `--clabel` and `--cortex` both constrain the search space; `--cortex` is shorthand for `?h.cortex.label`.
- `--thsign abs` tests absolute value; `--thmin` is then the absolute value threshold.
- `--fdr` replaces the manual `--thmin` with an FDR-derived threshold.
- When `--annot` is given, the summary file reports the parcellation label of each cluster's maximum vertex.

> [!gotcha] MNI vs Talairach coordinates
> The `--fixmni` flag (default: on) reports cluster coordinates in Talairach MNI space by applying the subject's `talairach.xfm`. When off, coordinates are reported in the volume's native RAS. Many users are unaware of this default correction.

## Typical Use Cases

**1. Basic cluster analysis with GRF correction:**
```bash
mri_surfcluster --in lh.sig.mgh --subject fsaverage --hemi lh \
  --thmin 2.0 --thsign abs --surf white \
  --fwhm 10 --cwpvalthresh 0.05 \
  --sum lh.clusters.summary.txt --out lh.clusters.sig.mgh
```

**2. Cluster analysis using permutation CSD:**
```bash
mri_surfcluster --in lh.sig.mgh --subject fsaverage --hemi lh \
  --thmin 2.0 --thsign pos \
  --csd lh.permutation.csd --cwpvalthresh 0.05 \
  --sum lh.clusters.txt --olab lh.cluster
```

**3. Constrain to cortex label only:**
```bash
mri_surfcluster --in lh.sig.mgh --subject fsaverage --hemi lh \
  --thmin 1.3 --cortex --minarea 20 \
  --sum lh.clusters.txt
```

## Pipeline Context

`mri_surfcluster` sits at the end of a surface-based group analysis pipeline:

1. `recon-all` → per-subject surfaces and overlays
2. `mri_surf2surf` → resample to fsaverage
3. `mris_preproc` → concatenate across subjects
4. `mri_glmfit` → vertex-wise GLM, produces `sig.mgh`
5. **`mri_surfcluster`** → cluster-wise inference, produce cluster maps and summary

Also used for single-subject analyses (e.g., fMRI activation maps on individual surfaces).

## Gotchas and Caveats

> [!gotcha] Group-average vertex areas
> By default, `mri_surfcluster` uses `group_avg_vtxarea` if available (loaded from the `fsaverage` surface file), which provides more accurate area estimates for group-level data. If not available, individual surface areas are used.

> [!gotcha] Cluster area vs. number of vertices
> Cluster size is reported in mm² (area), not number of vertices. This is the correct metric for surface-based analyses because vertex density varies across the cortex.

> [!gotcha] One-tail vs. two-tail threshold adjustment
> When `--thsign pos` or `--thsign neg` is used (one-tailed), the threshold is automatically adjusted for one-tail testing. Set `--no-adjust` to disable this.

> [!gotcha] Summary file coordinate system
> The summary file reports (x, y, z) in Talairach/MNI305 space (after applying `talairach.xfm`), not in scanner RAS or surface RAS. This is the default; see `--fixmni`.
