# [severity-2] [bug-00078] Cropped-region `xend`/`yend`/`zend` uses `mri_src->xstart` as base instead of `mri_dst->xstart`

> [!bug] Synopsis
> When a function allocates a destination MRI from a
> cropped region of a source, it sets the destination's
> origin (`xstart`) to `mri_src->xstart + region->x *
> mri_src->xsize`. The matching `xend` is supposed to
> be `mri_dst->xstart + w * xsize` (where `w` is the
> destination's width in voxels), but at least seven
> sites across `utils/` write
> `mri_src->xstart + w * xsize` — which omits the
> `region->x * xsize` shift. The same defect repeats
> for `yend` and `zend`.
>
> Effect: `mri_dst->xend - mri_dst->xstart` is wrong
> by `region->x * xsize` whenever `region->x != 0`.
> Latent for the common path where the region offset
> is zero. Active when the region origin is offset
> from the source origin (typical when extracting a
> sub-region with non-trivial position).

## Detailed Description

```cpp
/* utils/mriset.cpp:2041-2048 in MRIerodeRegion */
mri_dst = MRIalloc(w, h, d, MRI_UCHAR);
MRIcopyHeader(mri_src, mri_dst);
mri_dst->xstart = mri_src->xstart + region->x * mri_src->xsize;     /* correct base */
mri_dst->ystart = mri_src->ystart + region->y * mri_src->ysize;
mri_dst->zstart = mri_src->zstart + region->z * mri_src->zsize;
mri_dst->xend = mri_src->xstart + w * mri_src->xsize;               /* (!) base should be mri_dst->xstart */
mri_dst->yend = mri_src->ystart + h * mri_src->ysize;
mri_dst->zend = mri_src->zstart + d * mri_src->zsize;
```

Substituting:
- `mri_dst->xstart = mri_src->xstart + region->x * xsize`
- `mri_dst->xend - mri_dst->xstart = (mri_src->xstart + w * xsize) - (mri_src->xstart + region->x * xsize) = (w - region->x) * xsize`

The intended value is `w * xsize` (the dst's
voxel-count-in-x times xsize). The actual value is
`(w - region->x) * xsize` — wrong by
`region->x * xsize`.

For `region->x == 0` the values coincide, hiding the
defect.

The same pattern repeats verbatim across the six
other sites listed above.

## Code Reference

- **Files:** `utils/mriset.cpp`, `utils/mrifilter.cpp`,
  `utils/mripolv.cpp`.
- **Defect template:**
  `mri_dst->xend = mri_src->xstart + w * mri_src->xsize;`
  (and parallel y/z lines).
- **Correct pattern (sister sites):**
  `mri_dst->xend = mri_dst->xstart + wsize * mri_dst->xsize;`
- **Commit:** `d932c45b79`

## Root Cause

Author copy-pasted the start-line template
(`mri_src->xstart + ... * xsize`) into the end-line
without adjusting the base. The correct end-line
either uses `mri_dst->xstart` as base or adds
`region->x` to the multiplier:

```cpp
/* both equivalent: */
mri_dst->xend = mri_dst->xstart + w * mri_src->xsize;
mri_dst->xend = mri_src->xstart + (region->x + w) * mri_src->xsize;
```

## Impact

- **Latent for typical inputs.** Many callers pass
  `region` with origin at zero (whole volume).
- **When `region->x > 0`:**
  `mri_dst->xend - mri_dst->xstart` is wrong by
  `region->x * xsize`. Downstream consumers of
  xstart/xend (e.g. for FoV-aware resampling) see a
  smaller-than-actual FoV in x.
- **No effect on voxel data:** the stored voxel
  values are correct; only the geometry metadata is
  wrong.
- **Severity:** low.

## Recommended Fix

Replace the wrong base across all sites:

```diff
-    mri_dst->xend = mri_src->xstart + w * mri_src->xsize;
-    mri_dst->yend = mri_src->ystart + h * mri_src->ysize;
-    mri_dst->zend = mri_src->zstart + d * mri_src->zsize;
+    mri_dst->xend = mri_dst->xstart + w * mri_src->xsize;
+    mri_dst->yend = mri_dst->ystart + h * mri_src->ysize;
+    mri_dst->zend = mri_dst->zstart + d * mri_src->zsize;
```

Apply the same fix to all eight affected sites.

## Workarounds

For users sensitive to xstart/xend metadata: re-run
`MRIreInitCache` or recompute the FoV manually from
the dst's voxel dimensions and resolutions.
