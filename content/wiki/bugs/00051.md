# [severity-2] [bug-00051] `MatrixDemean` — writes back to `M` instead of `Mdm`

> [!bug] Synopsis
> `MatrixDemean`
> ([`utils/matrix.cpp:4039-4059`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L4039-L4059))
> takes an input matrix `M` and an optional output
> `Mdm`. Its signature suggests "demean each column of
> `M` and store the result in `Mdm`." The body
> computes the per-column mean from `M` correctly but
> then writes the demeaned values *back into `M`*
> rather than `Mdm`:
>
> ```cpp
> for (r = 1; r <= M->rows; r++) M->rptr[r][c] -= vmean;   // :4056
> ```
>
> The function then returns `Mdm` — which is either an
> uninitialised freshly-allocated matrix (when caller
> passed `Mdm == NULL`) or whatever the caller passed
> (untouched). Only when the caller passes
> `Mdm == M` (in-place) does the function produce a
> correct result.

## Affected Artefacts

- **Sole caller in-tree:**
  [`utils/fmriutils.cpp:2802`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fmriutils.cpp#L2802):
  `M = MatrixDemean(M, M);` — passes `Mdm == M`, so
  the bug is masked. Used inside `fMRIspatialCorMatrix`
  (which is itself only invoked by
  `mri_glmfit --eres-scm`, opt-in).
- **Pipeline stage(s):** none in default `recon-all`.
- **Triggering configuration:** any caller that passes
  `Mdm != M` (NULL or a separate matrix). No such
  caller exists in-tree.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

```cpp
MATRIX *MatrixDemean(MATRIX *M, MATRIX *Mdm)
{
  int r, c;
  double vsum, vmean;

  if (Mdm == NULL) {
    Mdm = MatrixAlloc(M->rows, M->cols, MATRIX_REAL);          /* alloc, uninitialised */
    if (Mdm == NULL) return (NULL);
  }
  if (Mdm->rows != M->rows || Mdm->cols != M->cols) {
    printf("MatrixDemean: dimension mismatch\n");
    return (NULL);
  }
  for (c = 1; c <= M->cols; c++) {
    vsum = 0.0;
    for (r = 1; r <= M->rows; r++) vsum += M->rptr[r][c];
    vmean = vsum / M->rows;
    for (r = 1; r <= M->rows; r++) M->rptr[r][c] -= vmean;     /* (!) writes to M, not Mdm */
  }
  return (Mdm);
}
```

Three caller patterns and their actual behaviour:

| Call form | Behaviour |
|-----------|-----------|
| `MatrixDemean(M, NULL)` | Returns a *new* uninitialised matrix; `M` is silently demeaned in-place. |
| `MatrixDemean(M, Mout)` (separate `Mout`) | Returns `Mout` unchanged; `M` is silently demeaned in-place. |
| `MatrixDemean(M, M)` | Correctly demeans `M` in-place and returns it. |

Only the third form does what the function is named for.
The sole in-tree caller uses that form, so the function
appears to work — but the API is broken.

## Root Cause

The `Mdm == NULL` allocation branch was added without
fixing the inner loop, which still operates on `M`.
Because the only caller uses the in-place form, the
defect was never exercised.

## Impact

- **Currently latent.** The single in-tree caller's
  `M = MatrixDemean(M, M)` form makes the bug invisible
  during normal use.
- **API risk.** Any future or external caller writing
  the natural `Mdm = MatrixDemean(M, NULL)` form gets
  uninitialised-memory garbage as `Mdm` and silently
  has `M` mutated.

## Recommended Fix

```diff
--- a/utils/matrix.cpp
+++ b/utils/matrix.cpp
@@ -4053,7 +4053,8 @@ MATRIX *MatrixDemean(MATRIX *M, MATRIX *Mdm)
     vsum = 0.0;
     for (r = 1; r <= M->rows; r++) vsum += M->rptr[r][c];
     vmean = vsum / M->rows;
-    for (r = 1; r <= M->rows; r++) M->rptr[r][c] -= vmean;
+    for (r = 1; r <= M->rows; r++)
+      Mdm->rptr[r][c] = M->rptr[r][c] - vmean;
   }
   return (Mdm);
 }
```

This makes the function honour its signature: in-place
when `Mdm == M`, copy-and-demean otherwise.

## Workarounds

Use `MatrixDemean(M, M)` explicitly for in-place
behaviour. Avoid `MatrixDemean(M, NULL)` — it returns
garbage and modifies `M`.
