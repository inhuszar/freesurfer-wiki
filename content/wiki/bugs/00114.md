# [severity-3] [bug-00114] `RFexpectedMeanStddev` dispatches `"F"` to the t-distribution helper; F-distribution mean/stddev are silently wrong

> [!bug] Synopsis
> ```cpp
> /* utils/randomfields.cpp:153-162 */
> int RFexpectedMeanStddev(RFS *rfs)
> {
>   if (!strcmp(rfs->name, "uniform"))  return (RFexpectedMeanStddevUniform(rfs));
>   if (!strcmp(rfs->name, "gaussian")) return (RFexpectedMeanStddevGaussian(rfs));
>   if (!strcmp(rfs->name, "t"))        return (RFexpectedMeanStddevt(rfs));
>   if (!strcmp(rfs->name, "F"))        return (RFexpectedMeanStddevt(rfs));   /* :158 — should be …F */
>   if (!strcmp(rfs->name, "chi2"))     return (RFexpectedMeanStddevChi2(rfs));
>   printf("ERROR: RFexpectedMeanStddev(): field type %s unknown\n", rfs->name);
>   return (1);
> }
> ```
>
> Both lines `:157` and `:158` route to
> the same function — `RFexpectedMeanStddevt`.
> The F-distribution variant
> `RFexpectedMeanStddevF` exists at
> [`:497-505`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/randomfields.cpp#L497-L505)
> but has **no caller**.
>
> The two formulas are completely
> different:
>
> ```cpp
> /* :486-493 — t */
> int RFexpectedMeanStddevt(RFS *rfs) {
>   double dof = rfs->params[0];
>   rfs->mean   = 0;
>   rfs->stddev = sqrt(dof / (dof - 2));
>   return 0;
> }
>
> /* :497-505 — F (unused) */
> int RFexpectedMeanStddevF(RFS *rfs) {
>   double ndof = rfs->params[0];      /* numerator dof   */
>   double ddof = rfs->params[1];      /* denominator dof */
>   rfs->mean   = ddof / (ddof - 2);
>   rfs->stddev = 2 * (ddof*ddof) * (ndof + ddof - 2)
>               / (ndof * (ddof - 2)*(ddof - 2) * (ddof - 4));
>   return 0;
> }
> ```
>
> When the user supplies an F-distribution
> RFS:
>
> | property        | correct (F)                  | actual (t applied to F's params)         |
> |-----------------|-------------------------------|-------------------------------------------|
> | `rfs->mean`     | `ddof / (ddof - 2)`           | `0`                                       |
> | `rfs->stddev`   | F variance formula           | `sqrt(ndof / (ndof - 2))` — t's formula on F's numerator dof |

## Affected Artefacts

- **Tool:** [[mri_volsynth]] —
  `--pdf F` synthesises an F-distributed
  random field and calls `RFrescale` to
  shift/scale it to the expected mean and
  stddev
  ([`mri_volsynth.cpp:494`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_volsynth/mri_volsynth.cpp#L494)).
- **Pipeline stage(s):** none in default
  `recon-all`. Used in random-field
  simulation and Monte Carlo cluster
  threshold tools.
- **Triggering configuration:** any
  invocation that requests an
  F-distributed random field via
  `RFexpectedMeanStddev` →
  `RFrescale` chain.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit
  `d932c45b79`).

## Detailed Description

### What `RFrescale` does with the wrong mean/stddev

[`RFrescale`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/randomfields.cpp#L283-L310)
applies the linear transform

```
v_out = (v_in - gmean_actual) * (rfs->stddev_expected / gstddev_actual)
        + rfs->mean_expected
```

at every voxel. With wrong
`stddev_expected` and `mean_expected`,
the rescaled field has:

- **wrong mean** — shifted toward 0
  instead of `ddof/(ddof-2)`. For
  ddof = 100 (typical large df), the
  expected F mean is ~1.02; the bug
  centers it on 0.
- **wrong stddev** — t's stddev formula
  applied to F's numerator dof gives
  a number unrelated to the true F
  stddev. For ndof=2, ddof=100: t says
  `sqrt(2/0)` → undefined / infinite.
  F says `2 · 100² · 100 / (2 · 98² · 96)`
  ≈ 1.08. Off by orders of magnitude.

### Why other dispatch sites are not affected

The companion dispatchers in the same
file all handle "F" correctly:

- `RFdrawVal`
  ([`:368-372`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/randomfields.cpp#L368-L372))
  — calls `sc_ran_fdist(rng, ndof, ddof)`.
- `RFstat2PVal`
  ([`:407-411`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/randomfields.cpp#L407-L411))
  — calls `sc_cdf_fdist_Q(...)`.
- `RFp2StatVal`
  ([`:447-453`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/randomfields.cpp#L447-L453))
  — explicit error (GSL lacks Qinv).

So drawing values, computing
p-values, and checking distribution
type all work for F. Only the
expected-mean/stddev dispatch is wrong.

### Why the bug went undetected

The F branch is one line in a small
dispatcher. Without a unit test that
specifically validates F-distribution
mean/stddev, the bug never surfaces.

A user running
`mri_volsynth --pdf F --ndof 2 --ddof
100 --o out.mgh` would get an
F-shaped random field rescaled with
the wrong center and spread. Because
the field is random, the visual
output looks "F-distributed-ish" and
the bug isn't obvious without
comparing against analytical
moments.

## Root Cause

Copy-paste typo. The author wrote four
similar dispatch lines for
{uniform, gaussian, t, F, chi2} and
copy-pasted the t handler when adding
the F line, forgetting to rename the
target function from
`RFexpectedMeanStddevt` to
`RFexpectedMeanStddevF`.

The header (`include/randomfields.h`)
declares both functions, and the
implementations exist in the cpp file —
the bug is purely in the dispatcher,
which makes the F implementation dead.

## Impact

- **`mri_volsynth --pdf F` rescaled
  output:** wrong mean (centered on 0
  instead of ~1) and wrong stddev (t's
  formula applied to ndof). The shape
  of the distribution (the F shape) is
  preserved by `sc_ran_fdist`, but the
  centering / scaling step shifts and
  stretches it incorrectly.
- **Downstream:** anything using the
  rescaled volume for thresholding or
  comparison expects the proper
  F-moments, gets wrong-shifted ones.
- **Severity:** 3 — niche tool, real
  conceptual bug, silent (no
  diagnostic).

## Recommended Fix

```diff
--- a/utils/randomfields.cpp
+++ b/utils/randomfields.cpp
@@ -155,7 +155,7 @@ int RFexpectedMeanStddev(RFS *rfs)
   if (!strcmp(rfs->name, "uniform")) return (RFexpectedMeanStddevUniform(rfs));
   if (!strcmp(rfs->name, "gaussian")) return (RFexpectedMeanStddevGaussian(rfs));
   if (!strcmp(rfs->name, "t")) return (RFexpectedMeanStddevt(rfs));
-  if (!strcmp(rfs->name, "F")) return (RFexpectedMeanStddevt(rfs));
+  if (!strcmp(rfs->name, "F")) return (RFexpectedMeanStddevF(rfs));
   if (!strcmp(rfs->name, "chi2")) return (RFexpectedMeanStddevChi2(rfs));
```

Single-character edit (`t` → `F`).

## Workarounds

For users running `mri_volsynth --pdf F`
who need correct moments: apply the
patch and rebuild, or pre/post-process
the output volume manually using the
known F mean and stddev formulas.
