# JointHisto::smooth Gaussian kernel uses exp(−i²/σ²) instead of exp(−i²/2σ²); actual FWHM is 1/√2 of requested

> [!bug] Synopsis
> `JointHisto::smooth(fwhm)` converts the requested FWHM to a
> Gaussian standard deviation `sm = fwhm / sqrt(8·ln2)` (correct)
> but then builds the 1-D kernel as `exp(i² / −sm²) = exp(−i²/σ²)`
> when the standard Gaussian is `exp(−i²/(2σ²))`. The factor of
> 2 in the denominator is missing. The kernel is post-normalised
> to sum to 1, so the prefactor doesn't matter, but the
> **shape** is a Gaussian with effective `σ_eff = σ/√2`. The
> actual smoothing FWHM is therefore `fwhm/√2 ≈ 0.707·fwhm` —
> the joint histogram is smoothed **less** than the user
> requested. This affects every registration cost in
> `mri_robust_register` / `mri_robust_template` that goes
> through `JointHisto::smooth`: MI, NMI, ECC, NCC, SCR, LS-on-
> joint-histo.

## Affected Artefacts

- **Tool(s):** [[mri_robust_register]] and
  [[mri_robust_template]] when invoked with any
  joint-histogram cost (`--cost MI`, `--cost NMI`,

- **Platforms:** all
- **Triggering configuration:** any user invocation that selects

## Detailed Description

### Expected Behaviour

The 1-D Gaussian kernel `g(i) = exp(−i² / (2σ²))` has FWHM
`= 2·σ·√(2·ln2)`. Conversion: `σ = FWHM / (2·√(2·ln2)) =
FWHM / √(8·ln2)`. So a kernel built with `σ` from this
conversion should reproduce the requested FWHM. The standard
construction is

```
g(i) = exp( −i² / (2·σ²) )
```

(then normalise to sum to 1).

### Observed Behaviour

The kernel construction at
[`mri_robust_register/JointHisto.cpp:615-637`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_robust_register/JointHisto.cpp#L615-L637):

```cpp
void JointHisto::smooth(double fwhm)
{
  // compute sigma from fwhm:
  double sm = fwhm / sqrt(8 * log(2));     /* sm = σ ✓ */
  if (sm < 0.001) sm = 0.001;
  int t = (int) floor(3 * sm + 0.5);
  // create kernel
  double filter[2 * t + 1];
  double fsum = 0.0;
  double sm2 = -sm * sm;                   /* sm2 = −σ²; missing the 2 */
  for (int i = -t; i <= t; i++)
  {
    filter[i + t] = exp((i * i) / sm2);    /* exp(−i²/σ²), not exp(−i²/(2σ²)) */
    fsum += filter[i + t];
  }
  // normalize
  for (int i = 0; i <= 2 * t; i++)
    filter[i] /= fsum;
}
```

Because the sum-to-1 normalisation absorbs the missing
prefactor, the kernel is a valid Gaussian — but with a
**different σ**. The exponent `−i²/σ²` is the standard
Gaussian exponent for a kernel of standard deviation
`σ_eff = σ / √2`. The achieved FWHM is therefore
`2·(σ/√2)·√(2·ln2) = σ·√(4·ln2) = (σ·√(8·ln2))/√2 =
fwhm/√2`.

For the typical default `fwhm = 7`
([`JointHisto.h:78`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_robust_register/JointHisto.h#L78)
and the hard-coded call at
[`RegPowell.cpp:193`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_robust_register/RegPowell.cpp#L193)),
the actual smoothing FWHM is `7/√2 ≈ 4.95` rather than the
documented `7`. The MI / NMI / ECC cost surfaces are
correspondingly less smooth than the user / author intended.

## Root Cause

The author built the Gaussian kernel from the formula
`exp(i² / sm2)` with `sm2 = −σ²`. The standard Gaussian PDF is
`exp(−i²/(2σ²))`, so `sm2` should have been `−2·σ²`, or
equivalently the kernel should have been
`exp(−i²/(2·sm·sm))`. The missing factor of 2 produces a
kernel with effective standard deviation `σ/√2` and FWHM
`fwhm/√2`.

## Impact

- **`mri_robust_register --cost {MI,NMI,ECC,NCC,SCR}`.** The
  cost surface is the information-theoretic measure of a
  joint PDF that is **less smoothed** than the user
  requested. Less smoothing → noisier cost surface → the
  Powell minimiser can land in different local minima. The
  registration result deviates by an amount that depends on
  image content and Powell's starting state.
- **`mri_robust_template`** with cross-modal subject pairs
  (which engage the same joint-histogram cost). Same
  bias.
- **Latent for default [[recon-all]].** `recon-all` uses the
  default robust LS cost (no joint histogram) for `talairach`
  registration. The bug fires only when the user explicitly
  picks an MI / NMI / ECC / NCC / SCR cost.
- **Bounded but non-zero.** The discrepancy is exactly a
  factor of √2 in FWHM. Whether this is a meaningful
  registration drift depends on image properties and the
  shape of the cost surface.
- **No crash, no warning.** Output looks plausible but
  reproduces a smoother registration in the limit only when
  the user passes `fwhm = 7·√2 ≈ 9.9` to compensate.

## Recommended Fix

```diff
   double sm = fwhm / sqrt(8 * log(2));
   if (sm < 0.001) sm = 0.001;
   int t = (int) floor(3 * sm + 0.5);
   double filter[2 * t + 1];
   double fsum = 0.0;
-  double sm2 = -sm * sm;
+  double sm2 = -2.0 * sm * sm;
   for (int i = -t; i <= t; i++)
   {
     filter[i + t] = exp((i * i) / sm2);
     fsum += filter[i + t];
   }
```

Single-line change. The kernel becomes the standard Gaussian
`exp(−i²/(2σ²))`, normalised to sum to 1, matching the
documented FWHM.

### Alternative Fixes Considered

- **Adjust the FWHM-to-σ conversion.** Could write
  `sm = fwhm / sqrt(4·ln2)` to make the existing
  `exp(−i²/sm²)` formula match the requested FWHM. Equivalent
  numerically; the exponent fix is more readable and matches
  the standard Gaussian formula.

## Workarounds (If Any)

- For users who already calibrated their `mri_robust_register
  --cost MI` workflow against the buggy behaviour: passing
  `fwhm = requested · √2` reproduces the buggy smoothing.
  Note that this workaround inverts after the fix, so any
  downstream pipeline that relies on the current behaviour
  needs corresponding updates.
