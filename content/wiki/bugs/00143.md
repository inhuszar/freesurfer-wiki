> Five sibling branches use `<=`. The "only GM" branch alone uses `<`. The function copies the GM column from the full 3-column design matrix `m_A3` (rows `1..nvox`) into the 1-column `m_A1`, but the off-by-one leaves `m_A1[nvox][1]` untouched. `m_A1` is `MatrixAlloc`'d **once** at [`:223`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_intensities.cpp#L223) before the `(x,y,z)` triple loop and **never re-zeroed between voxels**, so the missed last row carries stale data from whichever earlier voxel most recently wrote `m_A1[nvox][1]` (or `0.0` on the first hit — `MatrixAlloc` calloc-zeroes).
>
> The least-squares fit at [`:358-362`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_intensities.cpp#L358-L362) is
>
> ```cpp
> m_A_pinv = MatrixPseudoInverse(m_A1, NULL) ;
> MatrixMultiply(m_A_pinv, v_I, v_s1) ;
> ```
>
> — solving `v_s1 = pinv(m_A1) · v_I` where `v_I` has `nvox` entries (all freshly computed at [`:267`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_intensities.cpp#L267) for the current voxel) and `m_A1` has `nvox` entries with the last one stale. The recovered GM intensity `v_s1[1]` is biased toward whatever voxel last wrote `m_A1[nvox][1]`.
>
> The identical defect is present in [`mris_simulate_atrophy/mris_simulate_atrophy.cpp:735`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_simulate_atrophy/mris_simulate_atrophy.cpp#L735), in a copy-pasted clone of the same function. Both tools ship from `compute_unpartial_volumed_intensities` declarations at the top of their respective files (mri_compute_volume_intensities.cpp:55, mris_simulate_atrophy.cpp:67).

## Affected Artefacts

- **Tool(s):** `mri_compute_volume_intensities` (PVC intensity recovery), `mris_simulate_atrophy` (synthetic atrophy simulation for validation studies).
- **Pipeline stage(s):** _not on default `recon-all`_. `mri_compute_volume_intensities` is invoked manually as part of PET partial-volume-correction (PVC) pipelines that feed downstream `mri_gtmpvc` / kinetic-modelling. `mris_simulate_atrophy` is invoked by validation/methods scripts (e.g., for cortical-thickness benchmarking).
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`; earliest known: _unknown_ (both copies present in the project's initial public history).
- **Platforms:** all.
- **Triggering configuration:** every invocation. The pure-GM branch fires for any voxel whose 3-D Gaussian neighbourhood (default `whalf = 1`, configurable via `-w N`; default `sigma = 1`, configurable via `-s N`) contains only cortex/sub-cortical-GM volume fraction with effectively zero WM and CSF — i.e., deep-cortex interior voxels far from white-matter or pial surfaces. For a typical conformed 1 mm³ T1, such voxels are a non-trivial fraction (~5–15 %) of the cortical ribbon.

## Detailed Description

`compute_unpartial_volumed_intensities` implements a per-voxel local Gaussian-weighted least-squares fit that recovers tissue-pure intensities from a partial-volumed source image. For each output voxel `(x,y,z)` it scans a `(2·whalfx+1) × (2·whalfy+1) × (2·whalfz+1)` neighbourhood (`nvox` voxels total), builds a design matrix whose columns are the WM / GM / CSF volume fractions weighted by a spatial Gaussian, and solves for the latent tissue intensities `(I_wm, I_gm, I_csf)`. When the neighbourhood contains only one or two tissue classes (the others being numerically negligible by the 1% cross-tissue threshold at [`:282-287`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_intensities.cpp#L282-L287)), the function falls back to a 2-column (`m_A2`) or 1-column (`m_A1`) sub-design that is filled by copying the relevant columns of `m_A3`.

### Expected Behaviour

In each fallback branch, copy *all* `nvox` rows of the relevant column(s) of `m_A3` into the smaller `m_A*`, so that the down-rank design matrix matches the freshly-computed observation vector `v_I` exactly. The pure-GM branch should look like its WM-only and CSF-only siblings:

```cpp
else   /* only GM */
{
  for (row = 1 ; row <= m_A3->rows ; row++)
    *MATRIX_RELT(m_A1, row, 1) = *MATRIX_RELT(m_A3, row, 2) ;
  v_s = v_s1 ;
  m_A = m_A1 ;
}
```

### Observed Behaviour

```cpp
else   /* only gm in this voxel */
{
  for (row = 1 ; row < m_A3->rows ; row++)              /* < instead of <= */
    *MATRIX_RELT(m_A1, row, 1) = *MATRIX_RELT(m_A3, row, 2) ;
  v_s = v_s1 ;
  m_A = m_A1 ;
}
```

`m_A1[nvox][1]` is **not** overwritten; it retains its previous value. Because `m_A1` is allocated once outside the voxel loops at [`:223`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_intensities.cpp#L223) and never cleared between voxels (no `MatrixClear`, no second `MatrixAlloc`), the stale value is either:

- `0.0` on the first voxel that hits this branch (because `MatrixAlloc` calloc-zeroes), OR
- the value of `w·vgm` (Gaussian-weighted GM volume fraction) at the previous "only WM" or "only CSF" voxel that last wrote `m_A1[nvox][1]` (since both of those branches *do* write the full `nvox` rows of `m_A1`, but with the *wrong* column for the current GM-only voxel — they wrote the WM or CSF column).

The least-squares fit then has the wrong last row in `m_A1` paired against a freshly-correct `v_I[nvox]`. The recovered intensity `v_s1[1]` (the pure-GM intensity) absorbs a fitting error proportional to how much `m_A1[nvox][1]` deviates from the missing `w·vgm` value at the local last voxel.

For typical PVC inputs (1 mm³ conformed T1; `whalf=1` → 3³ = 27 voxels per neighborhood; default `sigma=1` → roughly Gaussian-tapered weights):

- `m_A3->rows = nvox = 27` (with default `whalf=1`), so the missed row is `m_A1[27][1]` — the most heavily weighted voxel position (the corner of the neighborhood, `xk=yk=zk=whalf`, with `w = exp(-0.5·3·whalf²·xsize²/sigma²)`).
- For `whalf=2` (user passes `-w 2`), `nvox = 125`, and the missed row is `m_A1[125][1]` — the diagonal corner. With `sigma=1`, that corner has `w ≈ exp(-6)` ≈ 2.5e-3, so the missed row is the *smallest*-weighted of all entries; its absence has only a tiny effect on the fit.
- For `whalf=1` (the default), the missed row is `m_A1[27][1]` — the `(+1,+1,+1)` corner, with `w = exp(-1.5/sigma²)`. At default `sigma=1` that's `exp(-1.5) ≈ 0.223` — a 22 % weight. The corruption is noticeable.

## Root Cause

A `<` typo where `<=` was intended. `MATRIX_RELT` is 1-indexed in FreeSurfer's matrix library, so iterating `row = 1; row <= m_A3->rows; row++` covers all `nvox` rows. The five sibling branches in the same `if/else` cascade get this right; the "only GM" branch alone uses `<`. Almost certainly a copy-paste from one of the multi-tissue branches followed by an editing slip — the surrounding logic is internally consistent with the `<=` convention.

The defect is amplified by two design choices:

1. **`m_A1` is reused across voxels.** Allocated once at `:223`, never re-cleared. If the off-by-one had been paired with a per-voxel `MatrixClear(m_A1)` before each fill, the missed row would be `0.0` rather than stale — still wrong, but with bounded magnitude.
2. **The off-by-one is in the smallest sub-matrix.** Because `m_A1` has only one column, every row is load-bearing for the fit; there is no redundant column to absorb the stale entry.

## Impact

- **Silent intensity bias at pure-GM voxels.** For every voxel in the volume whose 3-D Gaussian neighbourhood contains only cortex/sub-cortical GM volume fraction (no WM or CSF above the 1 % cross-tissue threshold), the recovered partial-volume-corrected intensity at that voxel is biased by the stale contents of `m_A1[nvox][1]`. The bias depends on the previous voxel's GM weight, so it is spatially correlated rather than random.
- **Quantitative effect.** For default `whalf=1` (3³ = 27-voxel neighborhood), `nvox` is the `(+1,+1,+1)` corner with Gaussian weight ≈ `exp(-1.5/sigma²)`. At default `sigma=1` that's ~22 % weight; the missed row's contribution to the least-squares sum is comparable to a single voxel's contribution. The recovered GM intensity at deep-cortex voxels deviates from the true value by a few percent on typical T1 data — large enough to bias PVC downstream, small enough to escape visual inspection.
- **Downstream PVC pipelines.** `mri_compute_volume_intensities` feeds `mri_unpv_intensities` into PET PVC (`mri_gtmpvc`) and kinetic-modelling steps. Biased GM intensities propagate into TAC (time-activity curve) extraction and kinetic-parameter estimation.
- **Atrophy simulation studies.** `mris_simulate_atrophy` uses `pvi.mgz` to drive `MRISsimulateAtrophy` (`:265-266`). Biased input intensities produce subtly-wrong simulated-atrophy ground truth, which then propagates into thickness-method validation benchmarks.
- **No `recon-all` impact.** Neither tool is invoked on the default `recon-all` path.

## Recommended Fix

One-character patch in both files: change `<` to `<=`.

### `mri_compute_volume_fractions/mri_compute_volume_intensities.cpp`

```diff

-    for (row = 1 ; row < m_A3->rows ; row++)
+    for (row = 1 ; row <= m_A3->rows ; row++)
```

### Alternative Fixes Considered

- **Defensive per-voxel `MatrixClear(m_A1)`.** Bounds the bias to a known value (`0.0`) but still leaves the design matrix with one missing row. Worse than the `<=` fix on correctness; only marginally cheaper than re-allocating.
- **Refactor to a helper that copies a column from `m_A3` to a single-column `m_A*`.** Eliminates the copy-paste-and-edit class of bug. Higher diff cost; reasonable for a follow-up cleanup.

## Workarounds (If Any)

- **Increase `-w N` to widen the neighborhood.** With `whalf=2`, `nvox=125` and the missed row is the `(+2,+2,+2)` corner with Gaussian weight `exp(-6) ≈ 2.5e-3` — the bias becomes numerically negligible. This is *not* an endorsement: it changes the smoothing kernel and may introduce other tissue-boundary blurring; but for users who must work around the bug without recompiling, `-w 2` substantially reduces it.
- **Inspect `mri_unpv_intensities` for spatial patterns at pure-GM voxels.** A scatter of mri_unpv_intensities vs the input T1, restricted to voxels where `mri_vfrac_cortex + mri_vfrac_subcort_gm > 0.99` and `mri_vfrac_wm + mri_vfrac_csf < 0.01`, should produce a tight slope-1 line if the function is correct. A patterned deviation flags this bug.

## Confidence and Gaps

> [!gap] Magnitude of bias on real PVC data
> The static defect is unambiguous; the magnitude of the recovered-GM-intensity bias at deep-cortex voxels under default `whalf=1, sigma=1` settings has not been quantified on a real PVC vfracs set. A grid sweep over `whalf ∈ {1, 2, 3}` and `sigma ∈ {0.5, 1, 2}` mm, comparing patched vs unpatched outputs on a single conformed T1, would put a percentage on it.

> [!gap] Frequency of the pure-GM branch
> The pure-GM branch fires only when both `total_wm` and `total_csf` are zeroed by the 1 %-cross-tissue rule at `:282-287`. For deep-cortex voxels far from any WM/CSF boundary in a conformed T1, this is common; for voxels near the WM/GM border or near the pial/CSF border, it is rare. A coarse upper bound based on cortical-ribbon geometry is ~5–15 % of cortical voxels; precise quantification was not performed.
