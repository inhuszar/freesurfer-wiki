# [severity-4] [bug-00083] CMAT round-trip is broken; `CMATtransform` aliases caller storage

> [!bug] Synopsis
> Two independent defects in
> [`utils/cmat.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp)
> corrupt the Connectome MATrix file workflow:
>
> 1. **`CMATwrite` writes weights with no
>    separator.**
>    [`:96`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp#L96)
>    is `fprintf(fp, "%f", cmat->weights[i][j])` —
>    no trailing space, no newline between values
>    in the same row. The reader at
>    [`:56`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp#L56)
>    uses `fscanf("%lf")`, which expects
>    whitespace-separated tokens. The CMAT file
>    written by FreeSurfer cannot be parsed back
>    by FreeSurfer.
>
> 2. **`CMATtransform` aliases caller storage and
>    leaks the fresh allocation.**
>    [`:165-167`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp#L165-L167)
>    calls `CMATalloc(... )` (which calloc-
>    allocates fresh `cdst->weights[i]` rows) and
>    then immediately overwrites the pointer with
>    `cdst->weights[i] = csrc->weights[i]`. The
>    fresh row is leaked; `cdst` and `csrc` now
>    share the row; the next `CMATfree(&cdst)` (or
>    `CMATfree(&csrc)`) frees the shared row, and
>    the second free is a double-free on the
>    sibling.

## Affected Artefacts

- **Tools:**
  - [[mri_transform]] when the input is a CMAT
    file: writes broken output via
    [`mri_transform/mri_transform.cpp:161`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_transform/mri_transform.cpp#L161),
    `:168`, `:231`. Also calls `CMATtransform` at
    [`:203`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_transform/mri_transform.cpp#L203).
  - [[mris_init_global_tractography]] writes a
    CMAT at
    [`:457`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_init_global_tractography/mris_init_global_tractography.cpp#L457).
  - [[freeview]] (`LayerConnectomeMatrix`) reads a
    CMAT at
    [`freeview/LayerConnectomeMatrix.cpp:71`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/freeview/LayerConnectomeMatrix.cpp#L71)
    and so will fail to parse files produced by
    the writer.
- **Pipeline stage(s):** none in default
  `recon-all`. Affects connectome / tractography
  workflows.
- **Triggering configuration:** any invocation of
  the writers above; any subsequent attempt to
  read the produced file.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

### Defect 1: missing separator in `CMATwrite`

```cpp
/* utils/cmat.cpp:85-108 — writer */
for (i = 0; i < cmat->nlabels - 1; i++) {
  for (j = i + 1; j < cmat->nlabels; j++)
    fprintf(fp, "%f", cmat->weights[i][j]);   /* :96 — no separator */
  fprintf(fp, "\n");
}
```

Two adjacent values like `0.123456` and `0.654321`
are written as `0.1234560.654321` — the reader
parses this as one float `0.1234560654321` (or
similar, depending on `%lf` greedy behaviour),
not two values. The next `fscanf("%lf")` then
mis-reads the row's remainder.

```cpp
/* utils/cmat.cpp:54-63 — matching reader */
for (i = 0; i < cmat->nlabels - 1; i++) {
  for (j = i + 1; j < cmat->nlabels; j++) {
    if (fscanf(fp, "%lf", &cmat->weights[i][j]) != 1) { ... }
  }
  if (fscanf(fp, "\n") != 1) { ... }
}
```

The reader expects whitespace-separated values
(standard `fscanf("%lf")` behaviour). The writer
violates that contract.

### Defect 2: `CMATtransform` aliases input storage

```cpp
/* utils/cmat.cpp:161-176 */
CMAT *CMATtransform(CMAT *csrc, TRANSFORM *xform, MRI *mri_src, MRI *mri_dst, CMAT *cdst)
{
  int i, j;

  cdst = CMATalloc(csrc->nlabels, csrc->labels);   /* :165 — overwrites argument; cdst row weights[i] freshly calloc'd */
  for (i = 0; i < csrc->nlabels; i++) {
    cdst->weights[i] = csrc->weights[i];           /* :167 — leaks fresh row, aliases csrc */
    for (j = i + 1; j < csrc->nlabels; j++) {
      if (csrc->splines[i][j]) {
        cdst->splines[i][j] = LabelTransform(csrc->splines[i][j], xform, mri_src, NULL);
      }
    }
  }
  return (cdst);
}
```

Three problems compound:

1. The `cdst` argument is silently discarded
   (`cdst = CMATalloc(...)`); a caller-provided
   destination is leaked.
2. The freshly allocated `cdst->weights[i]` row
   is overwritten without `free`, leaking
   `nlabels * sizeof(double)` per row.
3. `cdst->weights[i]` and `csrc->weights[i]` now
   point to the same memory. The first
   `CMATfree` on either struct
   ([`:153`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp#L153))
   frees the row; the second free is a
   double-free with undefined behaviour
   (typically heap corruption / SIGABRT under
   glibc's malloc).

The same self-assignment-as-no-op pattern
(`cmat->weights[i] = cmat->weights[i]`) appears
in `CMATtoVoxel`
([`:184`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp#L184)),
`CMATtoTKreg`
([`:200`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp#L200)),
and `CMATtoScannerRAS`
([`:216`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cmat.cpp#L216))
— harmless dead stores there but evidence the
intent was a real copy that was never written.

## Root Cause

- **Writer separator:** typo / oversight in
  format-string maintenance. The matching reader
  was written with the standard whitespace-
  separated `%lf` convention, but the writer
  format never grew the trailing space the reader
  expects.
- **`CMATtransform` aliasing:** the function
  appears to have been scaffolded with the
  spline-transform logic completed and the
  weight-handling left as a placeholder. The
  self-assignment in three sibling `CMATto*`
  functions confirms the placeholder pattern was
  never replaced.

## Impact

- **CMAT round-trip:** any CMAT written by
  FreeSurfer cannot be read back by FreeSurfer
  (or by `freeview`'s connectome layer). For
  inputs with `nlabels >= 3` the corruption is
  immediate — the very first row contains at
  least two adjacent floats with no separator.
  Single-label CMATs and the trivial `nlabels ==
  2` case (one weight) round-trip by accident.
- **`CMATtransform`:** every call leaks
  `nlabels` rows of `double *` and creates a
  double-free between `csrc` and the returned
  `cdst`. `mri_transform` invokes this on the
  CMAT input path
  ([`mri_transform/mri_transform.cpp:203`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_transform/mri_transform.cpp#L203))
  before writing the (separately-broken) output
  via `CMATwrite`.
- **Severity:** 4 — an auxiliary tool's default
  output is malformed and unreadable.

## Recommended Fix

```diff
+    for (j = 0; j < csrc->nlabels; j++)
+      cdst->weights[i][j] = csrc->weights[i][j];
     for (j = i + 1; j < csrc->nlabels; j++) {

```

The first hunk uses a trailing space; an
equivalent fix is `"%f\n"` per value (matches
some downstream parsers more robustly). The
second hunk preserves caller-provided
destinations and deep-copies the weights row.

While there, the three `CMATto*` self-
assignments (`:184`, `:200`, `:216`) should be
deleted or replaced with the actual weight
transformation if one was ever intended.

## Workarounds

- For Defect 1: post-process the CMAT file with
  `sed 's/\\([0-9]\\)\\(-\\?[0-9]\\)/\\1 \\2/g'`
  is unreliable for negative weights. The only
  safe workaround is to patch the writer.
- For Defect 2: avoid `CMATtransform` and roll
  the transform at the call site by deep-copying
  weights manually before calling
  `LabelTransform` on each spline.
