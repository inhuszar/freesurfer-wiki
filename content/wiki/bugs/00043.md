# [severity-4] [bug-00043] GLMcMatrices guards the partial-correlation-coefficient setup with `if (glm->Dt[n] == NULL) continue;` — Dt[n] is always NULL on entry, so PCC is never computed and `mri_glmfit`'s `pcc.mgh` is identically zero

> [!bug] Synopsis
> `GLMcMatrices` allocates the matrices that drive the
> partial-correlation-coefficient (PCC) computation: `Dt[n]`
> (transpose of the contrast null-space basis), `XCt[n]`,
> `XDt[n]`, `RD[n]`, `Xcd[n]`, `Xcdt[n]`, `sumXcd[n]`,
> `sumXcd2[n]`. Inside the per-contrast loop, it calls
> `MatrixColNullSpace(glm->Ct[n], &err)` to obtain the
> null-space basis `D`, then guards the rest of the block
> with `if (glm->Dt[n] == NULL) continue;`. The intended
> guard is `if (D == NULL) continue;` (i.e., skip on
> null-space-computation failure), but the typo references
> `glm->Dt[n]`, which is set to `NULL` for every contrast in
> `GLMalloc` (line 213). The guard therefore always fires:
> the freshly-allocated `D` is leaked, `glm->Dt[n]` is never
> assigned, and none of the eight downstream PCC matrices
> are populated. Later, `GLMtest`'s PCC block is gated on
> `if (glm->Dt[n] != NULL)`, so it is never entered, and
> `glm->pcc[n]` is permanently `0`. `mri_glmfit` writes
> `<glmdir>/<contrast>/pcc.mgh` per contrast — every entry
> is zero. The flag `DoPCC` defaults to `1`, so the bug
> fires unconditionally for any contrast with a single row.

## Affected Artefacts

- **Tool(s):** [[wiki/tools/mri_glmfit|mri_glmfit]] for every per-contrast PCC
  output (`<glmdir>/<contrast>/pcc.mgh` or `pcc.<format>`),
  written at
  [`mri_glmfit.cpp:2219-2220`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L2219-L2220).
- **Pipeline stage(s):** any group analysis that uses PCC
  for effect-size reporting alongside the GLM contrast
  test. Default [[wiki/pipelines/recon-all|recon-all]] does not run `mri_glmfit`, so
  this is a downstream-analysis defect, not a recon-all
  defect.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_.
- **Platforms:** all
- **Triggering configuration:** any `mri_glmfit` invocation
  that does not pass `--no-pcc`, since `DoPCC = 1` is the
  default
  ([`mri_glmfit.cpp:767`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L767)).
  In practice this is *every* default `mri_glmfit` run with
  one or more single-row contrasts.

## Detailed Description

### Expected Behaviour

`GLMcMatrices` is documented (header at
[`utils/fsglm.cpp:404-413`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L404-L413))
to compute, for every contrast with one row when PCC is
requested, the null-space basis of the contrast and the
projection of the design matrix onto that null space, then
to construct `Xcd[n]` (the design-matrix's contrast
direction orthogonalised against the nuisance regressors)
and its sums. `GLMtest`'s PCC block
([`:641-652`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L641-L652))
combines those quantities with the per-voxel residuals to
yield the partial correlation coefficient.

### Observed Behaviour

The PCC setup
([`utils/fsglm.cpp:422-449`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L422-L449)):

```cpp
if (glm->C[n]->rows == 1 && glm->DoPCC) {
  // These are for the computation of partial correlation coef
  // null space of contrast space
  MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
  if (glm->Dt[n] == NULL) continue;                          /* (a) WRONG variable */
  glm->Dt[n] = MatrixCopy(D,glm->Dt[n]);                     /* (b) never reached */
  MatrixFree(&D);                                             /*     never reached */
  // design matrix projected onto contrast space
  glm->XCt[n] = MatrixMultiplyD(glm->X, glm->Ct[n], glm->XCt[n]);
  glm->XDt[n] = MatrixMultiplyD(glm->X, glm->Dt[n], glm->XDt[n]);
  glm->RD[n]  = MatrixResidualForming(glm->XDt[n], glm->RD[n]);
  /* … */
  glm->Xcd[n]   = MatrixMultiplyD(glm->RD[n], glm->XCt[n], glm->Xcd[n]);
  glm->Xcdt[n]  = MatrixTranspose(glm->Xcd[n], glm->Xcdt[n]);
  glm->sumXcd[n]  = MatrixSum(glm->Xcd[n], 1, glm->sumXcd[n]);
  glm->sumXcd2[n] = MatrixSumSquare(glm->Xcd[n], 1, glm->sumXcd2[n]);
}
else
  glm->Dt[n] = NULL;  // make sure
```

`glm->Dt[n]` is initialised to `NULL` for every contrast in
`GLMalloc`
([`:213`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L213)),
and is never modified anywhere else in the codebase before
this point. The guard at (a) therefore *always* matches on
the first (and typically only) call to `GLMcMatrices`, and
the function `continue`s without:
- copying `D` into `glm->Dt[n]`,
- freeing `D` (memory leak — small, one matrix per
  contrast per call),
- populating `glm->XDt[n]`, `glm->RD[n]`, `glm->Xcd[n]`,
  `glm->Xcdt[n]`, `glm->sumXcd[n]`, `glm->sumXcd2[n]`.

The PCC consumer in `GLMtest`
([`:641-655`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L641-L655)):

```cpp
if (glm->Dt[n] != NULL) {
  // compute partial correlation coefficient (pcc)
  glm->yhatd[n] = MatrixMultiplyD(glm->RD[n], glm->yhat, glm->yhatd[n]);
  glm->Xcdyhatd[n] = MatrixMultiplyD(glm->Xcdt[n], glm->yhatd[n], glm->Xcdyhatd[n]);
  glm->sumyhatd[n]  = MatrixSum(glm->yhatd[n], 1, glm->sumyhatd[n]);
  glm->sumyhatd2[n] = MatrixSumSquare(glm->yhatd[n], 1, glm->sumyhatd2[n]);
  glm->sumyhatd2[n]->rptr[1][1] += (glm->dof * glm->rvar);
  glm->pcc[n] =
      (glm->Xcdyhatd[n]->rptr[1][1] - glm->sumXcd[n]->rptr[1][1] * glm->sumyhatd[n]->rptr[1][1]) /
      sqrt(/* … */);
}
else
  glm->pcc[n] = 0;
```

Since `glm->Dt[n]` is permanently `NULL`, this branch is
never entered. `glm->pcc[n] = 0` for every voxel and
every frame.

The output is then written by `mri_glmfit`:

```cpp
// Compute and Save CNR and PCC
/* … */
if(mriglm->glm->Dt[n] != NULL){          /* same NULL gate at the writer */
  // Write out the pcc
  sprintf(tmpstr,"%s/%s/pcc.%s",GLMDir,mriglm->glm->Cname[n],format);
  MRIwrite(mriglm->pcc[n],tmpstr);
}
```

([`mri_glmfit.cpp:2217-2220`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L2217-L2220).)
The writer at the call site is *also* gated on `Dt[n] !=
NULL` — meaning the file is *not even produced* in the
default case! So users who expect `pcc.mgh` to exist after
a default `mri_glmfit` run will instead find the file is
*missing*, not zero-valued. (The same gate prevents both
the computation in `GLMtest` and the file write in
`mri_glmfit`.)

## Root Cause

The intended check at line 426 is "if the null-space
computation failed (returned `D == NULL`), skip the rest
of the PCC setup". The typo references `glm->Dt[n]` (the
*destination*) instead of `D` (the *source*). The shape of
the variable name probably enabled the typo — `glm->Dt[n]`
and `D` are visually similar in a half-line edit.

## Impact

- **Every default `mri_glmfit` run loses its PCC output.**
  Users who consume `pcc.mgh` for effect-size reporting
  (e.g., to report Cohen's d or partial-correlation effect
  sizes alongside p-values) get a missing file (or, if
  the writer-side gate is bypassed, an all-zero map).
- **Group analysis that depends on PCC for ranking or
  thresholding** silently produces no PCC maps.
- **CSV/log artifacts**: tools that scan `glmdir` for the
  presence of `pcc.mgh` (e.g., post-hoc effect-size
  collation scripts) silently skip every contrast.
- **Latent for [[wiki/pipelines/recon-all|recon-all]]**: `recon-all` does not run
  `mri_glmfit`. The defect is downstream-analysis-only.

## Recommended Fix

```diff
   if (glm->C[n]->rows == 1 && glm->DoPCC) {
     // These are for the computation of partial correlation coef
     // null space of contrast space
     MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
-    if (glm->Dt[n] == NULL) continue;
+    if (D == NULL) continue;            /* skip on null-space-computation failure */
     glm->Dt[n] = MatrixCopy(D,glm->Dt[n]);
     MatrixFree(&D);
     /* … */
   }
```

A one-token fix. The two-character change `glm->Dt[n]` →
`D` makes the guard match its intent.

The mirrored writer-side gate at
[`mri_glmfit.cpp:2217`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L2217)
is *correct* under the fixed code — it suppresses the file
write only when the null-space computation legitimately
failed (e.g., a contrast with full row rank).

### Alternative Fixes Considered

- **Pre-initialise `glm->Dt[n]` to a marker value** so the
  existing typo would not always match. Brittle and
  doesn't fix the actual logic.
- **Drop the guard entirely** — `MatrixCopy(D, NULL)`
  handles `D == NULL` gracefully (returns NULL). But the
  later `MatrixMultiplyD` calls would crash on a NULL
  `Dt[n]`. Better to keep the guard and fix the variable
  name.

## Workarounds (If Any)

- Source-patch the single line in `utils/fsglm.cpp` and
  rebuild FreeSurfer.
- Use FSL's GLM tools (or another package's GLM) for PCC
  reporting until the upstream fix lands.
- Compute PCC manually from the residuals and design
  matrix using `mris_calc` or external tooling.

## Confidence and Gaps

> [!gap] Whether this defect was ever observed by users
> The writer-side gate at `mri_glmfit.cpp:2217` *suppresses*
> the file when `Dt[n] == NULL`, so users see a *missing*
> file instead of a corrupted file. A user who expects
> `pcc.mgh` to be present might assume it was disabled by
> a flag they accidentally passed and not file a bug.

> [!gap] Permutation testing
> `mri_glmfit-sim --perm` runs many GLM-fit cycles. Each
> cycle re-uses the same `GLMMAT` instance, so the
> permanent-NULL `Dt[n]` carries through every permutation.
> No path to PCC computation exists during permutation
> either.
