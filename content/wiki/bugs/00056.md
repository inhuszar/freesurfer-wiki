# [severity-3] [bug-00056] `MRIcomputeVolumeFractions` — three independent defects in laminar volume-fraction sampling

> [!bug] Synopsis
> `MRIcomputeVolumeFractions`
> ([`utils/mri.cpp:16690-16774`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L16690-L16774))
> projects a high-resolution `mri_seg` (typically a
> WM/GM/CSF layered volume) into the lower-resolution
> `mri_src` voxel grid, accumulating per-label
> fractional counts in `mri_fractions` (one frame per
> label). Three independent defects co-exist in this
> function:
>
> 1. **Dead-store duplicate**:
>    [`:16754-16755`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L16754-L16755)
>    is `MatrixMultiply(m_inv, v1, v2);` written twice
>    in a row. The second call overwrites the first
>    with identical arguments; the second is dead, the
>    first is wasted compute.
>
> 2. **Off-by-one accepting `label=0`**:
>    [`:16727`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L16727)
>    reads `if (label >= 0 && label <= mri_fractions->nframes)`,
>    then accesses frame `label - 1`. With `label=0`,
>    the access is to frame `-1`, an out-of-bounds
>    read/write.
>
> 3. **Inconsistent bound silently drops top label**:
>    [`:16762`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L16762)
>    in the inverse-sampling fallback uses
>    `label < mri_fractions->nframes` (note `<` not
>    `<=`). For the laminar caller where `nframes=3`
>    and labels are `{1=WM, 2=GM, 3=CSF}`, the check
>    excludes `label=3` (CSF) — when the fallback fires
>    on uncovered target voxels, CSF voxels are
>    silently not written.

## Affected Artefacts

- **Sole caller in-tree:**
  `MRIcomputeLaminarVolumeFractions`
  ([`utils/mrisurf_metricProperties.cpp:13173`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_metricProperties.cpp#L13173))
  — used by [[mri_compute_layer_fractions]] and other
  laminar-analysis tools.
- **Pipeline stage(s):** none in default `recon-all`.
- **Triggering configuration:** any laminar
  WM/GM/CSF volume-fraction computation. The CSF-drop
  defect (3) only manifests when the inverse-sampling
  fallback branch fires, i.e. when a `mri_src` voxel
  has no forward-mapped contribution from the
  high-res `mri_seg` (typical when source resolution
  is finer than target — opposite of the usual
  high-res-to-low-res case).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

For the only caller, labels are `WM_VAL=1`, `GM_VAL=2`,
`CSF_VAL=3` (defined at
[`utils/mrisurf_metricProperties.cpp:13127-13129`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_metricProperties.cpp#L13127-L13129)).
Background voxels are explicitly replaced by `CSF_VAL`
prior to the call
([`mrisurf_metricProperties.cpp:13167`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_metricProperties.cpp#L13167)),
so `label=0` does not occur for this caller. Defect (b)
is therefore latent for the laminar use case but live
for any other caller that admits `label=0`.

Defect (c) fires for `label=3` (CSF_VAL):
- forward branch at `:16727`: `label <= 3` passes,
  writes to frame 2. ✓
- fallback branch at `:16762`: `label < 3` fails,
  no write — CSF voxels are silently dropped.

Defect (a) is a pure compute-waste / dead-store; the
output `v2` is set twice from the same inputs.

## Root Cause

(a) Copy-paste duplicate; one of the two
`MatrixMultiply(m_inv, v1, v2);` lines was likely
intended to be a different multiply (e.g. forward
`m_vox2vox`) that was edited away without removing the
second statement.

(b) and (c) are independent off-by-one bound checks
written at different times. The label-to-frame mapping
is `frame = label - 1`, so the correct check is
`label >= 1 && label <= nframes` (yielding frame
indices `0..nframes-1`). Neither branch implements
exactly that.

## Impact

- **Defect (a):** wasted compute. One redundant 4×4
  × 4×1 matrix multiply per uncovered target voxel —
  negligible.
- **Defect (b):** latent for the laminar caller (no
  `label=0` voxels reach the function); *active* for any
  external caller that admits `label=0`. With `label=0`,
  `MRIgetVoxVal(mri_fractions, ..., -1)` and
  `MRIsetVoxVal(mri_fractions, ..., -1)` produce
  undefined behaviour (likely silent OOB read/write to
  the last frame's previous-row data due to MRI's
  per-frame slice layout).
- **Defect (c):** **active** for the laminar caller.
  When the inverse-sampling fallback fires on a target
  voxel that maps back to a CSF (label=3) source voxel,
  no write occurs and that target voxel's CSF fraction
  remains zero. The target voxel's WM and GM fractions
  may still be nonzero (from the forward pass), but the
  CSF fraction is artificially low. Net effect:
  fractions do not sum to 1 in the affected voxels.
- **Magnitude:** the fallback branch only fires when
  no forward-mapped voxel covers the target — in
  practice rare when `mri_seg` is upsampled relative
  to `mri_src` (the typical use case). Common when
  `mri_src` is finer than `mri_seg`, where the
  fallback fires on most voxels.

This unifies the two bound checks to `label >= 1 &&
label <= nframes`, which is the correct range for
`frame = label - 1` indexing, and removes the
duplicated `MatrixMultiply`.

### Alternative

Index by `label` directly with no `-1` and treat
`mri_fractions` as having `nframes` frames for labels
`1..nframes`, with frame 0 reserved for "no label".
That would require touching all callers; not
recommended.

## Workarounds

For the laminar caller, ensure that `mri_src` has
*coarser* resolution than `mri_seg` so the
inverse-sampling fallback rarely fires. The defect (c)
then has minimal impact.

    the second's output overwriting the first's.
  - Defect (b): `:16727` reads `label <= nframes`,
    paired with `frame = label - 1` indexing at the
    next line — admits `label=0` → frame -1.
  - Defect (c): `:16762` reads `label < nframes`,
    paired with the same `frame = label - 1`
    indexing — excludes `label=nframes`.
