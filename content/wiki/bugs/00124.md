# [severity-3] [bug-00124] `FCDcomputeThicknessLabels` parcel-boundary stop is unreachable; thickness anomalies leak along the surface normal across parcel boundaries

> [!bug] Synopsis
> ```cpp
> /* utils/fcd.cpp:434-468 (LH; RH mirror at :501-534) */
> for (d = 0, base_label = 0; d < thickness; d += 0.25) {
>   double xs = v->x + d * v->nx;
>   double ys = v->y + d * v->ny;
>   double zs = v->z + d * v->nz;
>   MRISsurfaceRASToVoxel(fcd->mris_lh, fcd->mri_thickness_increase, xs, ys, zs, &xv, &yv, &zv);
>   int xvi = nint(xv), yvi = nint(yv), zvi = nint(zv);
>   int label = MRIgetVoxVal(fcd->mri_aparc, xvi, yvi, zvi, 0);
>   if (IS_WM(label) == 0
>       && label >= MIN_CORTICAL_PARCELLATION
>       && label != ctx_lh_unknown) {
>     if (label != base_label) {
>       if (base_label) {        /* :446 — never true */
>         break;                  /* :447 — unreachable */
>       }
>     }
>     else {
>       base_label = label;       /* :451 — unreachable */
>     }
>     /* …write val into mri_thickness_increase / mri_thickness_decrease… */
>   }
> }
> ```
>
> The intent of `base_label`
> is to capture the cortical
> parcel found at the first
> valid step along the normal,
> and stop the walk when the
> parcel changes. The actual
> control flow:
>
> | iteration | `label`     | `label != base_label` | `if (base_label)` | result |
> |-----------|-------------|-----------------------|-------------------|--------|
> | 1st valid | 1006 (ctx)  | `1006 != 0` → true    | `if (0)` → false  | no break, **base_label not updated** |
> | 2nd (same parcel) | 1006 | `1006 != 0` → true | `if (0)` → false  | no break |
> | 3rd (different parcel) | 1011 | `1011 != 0` → true | `if (0)` → false | **no break**, anomaly written into 1011 |
>
> The `else { base_label = label; }`
> branch fires only when
> `label == base_label == 0`,
> but the entry filter rejects
> `label == 0` (it requires
> `label >= MIN_CORTICAL_PARCELLATION`
> and `label != ctx_*_unknown`).
> So the assignment is
> structurally dead code; the
> `break` is structurally
> dead; `base_label` stays
> `0` for the entire walk;
> the parcel-boundary stop
> never fires.
>
> Consequence: each
> thickness-anomaly value
> (`val`) is deposited at
> every cortical voxel along
> the normal, regardless of
> whether the trace crosses
> into a neighbouring parcel.

## Detailed Description

### Why `base_label` never updates

```cpp
if (label != base_label) {     /* outer */
  if (base_label) break;       /* inner */
  /* else: implicit empty */
}
else {
  base_label = label;          /* only here is base_label assigned */
}
```

The `else` branch fires only
when `label == base_label`.
Initially `base_label = 0`,
so the first time `else`
could fire is when
`label == 0`. But execution
only reaches this `if/else`
after passing the outer
filter

```cpp
IS_WM(label) == 0
  && label >= MIN_CORTICAL_PARCELLATION
  && label != ctx_lh_unknown
```

For lh aparc labels,
`MIN_CORTICAL_PARCELLATION`
is `1000` (FreeSurfer
ctx-lh-* labels start at
1000;
ctx-rh-* at 2000). So
`label >= 1000` and
`label != 0`. The `else`
is permanently dead.

`base_label = label` never
executes. `base_label`
stays 0 throughout the walk.
`if (base_label) break;`
evaluates `if (0)` → false
on every iteration. The
break never fires.

### What the walk actually does

For each vertex `v` on the
white surface:
- Compute thickness anomaly
  `val` from the lh-vs-rh
  smoothed thickness
  difference.
- Skip the vertex unless
  `|val| >= thickness_thresh`.
- Walk along the surface
  normal in steps of
  `d = 0, 0.25, 0.5, …,
  thickness` mm.
- At each step, find the
  underlying voxel in
  `mri_aparc`.
- If the underlying label
  is cortical (not WM,
  not unknown, not
  background), deposit
  `val` into
  `mri_thickness_increase`
  (if val > 0) or
  `mri_thickness_decrease`
  (if val < 0).

With the bug, the walk
continues past parcel
boundaries. With the
**intended** logic, the
walk would stop as soon as
the parcel changes from
the one found on the first
valid step.

### Concrete leak scenario

Consider a vertex on lh
near the boundary between
ctx-lh-lateralorbitofrontal
(1012) and
ctx-lh-medialorbitofrontal
(1014). The surface normal
at this vertex is roughly
perpendicular to cortex.
The voxel-trace might pass
through:

| d (mm) | aparc label | parcel              | with bug | intended |
|--------|-------------|---------------------|----------|----------|
| 0.00   | 1012        | lateral OFC         | write val | write val (set base) |
| 0.25   | 1012        | lateral OFC         | write val | write val |
| 0.50   | 1012        | lateral OFC         | write val | write val |
| 0.75   | 1014        | medial OFC          | **write val into 1014** | **break** |
| 1.00   | 1014        | medial OFC          | **write val into 1014** | (already broken) |

The buggy version stamps
`val` onto medial-OFC
voxels even though the
anomaly originated at a
lateral-OFC vertex.

### Downstream consequence

After per-vertex tracing,
`mri_thickness_increase`
and `mri_thickness_decrease`
are segmented into
connected clusters by
[`utils/fcd.cpp:540`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fcd.cpp#L540):

```cpp
mriseg = MRIsegment(fcd->mri_thickness_increase, thickness_thresh, 1e10);
MRIeraseSmallSegments(mriseg, fcd->mri_thickness_increase, thickness_thresh);
…
MRIclose(fcd->mri_thickness_increase, fcd->mri_thickness_increase);
mriseg = MRIsegment(fcd->mri_thickness_increase, thickness_thresh, 1e10);
MRIremoveSmallSegments(mriseg, size_thresh);
```

Then each cluster is given
the name of its most
frequent aparc label
[`:559-561`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fcd.cpp#L559-L561):

```cpp
fcd->labels[s] = MRIsegmentToLabel(mriseg, fcd->mri_thickness_increase, s);
label = most_frequent_label(fcd->mri_aparc, &mriseg->segments[s]);
strcpy(fcd->labels[s]->name, cma_label_to_name(label));
```

So:
- The displayed **name** of
  each cluster is robust:
  it's the majority parcel
  inside the cluster, and
  leaked voxels are a
  minority near the
  parcel boundary.
- The displayed **extent**
  of each cluster is
  inflated where it
  crosses parcel
  boundaries.
- Two thickness anomalies
  in adjacent parcels can
  potentially merge into a
  single connected cluster
  via the leaked voxels.

### Why this is severity 3 (not 4)

- **Severity-4 threshold**
  in this audit means
  "silently produces
  user-facing wrong output
  via a documented code
  path." The bug here is
  borderline: the FCD
  layer's primary
  user-visible artefact —
  the cluster name and
  the underlying anomaly
  detection — is preserved,
  because:
  - The detection of the
    anomaly at each
    vertex is independent
    of `base_label`.
  - The most-frequent-label
    naming makes cluster
    labels robust to a
    small amount of
    boundary leakage.
- The defect IS clearly
  reachable, IS silent,
  and DOES cause visibly
  inflated cluster extent
  in cross-parcel cases.
  Severity 3 reflects
  "clinically visible
  imprecision" rather
  than "catastrophically
  wrong output."

## Root Cause

The if/else structure was
inverted. The author
intended:

> "On the first valid
> cortical step, set
> `base_label`. On any
> subsequent step where
> `label != base_label`,
> break."

The corresponding code
should be:

```cpp
if (base_label == 0) {
    base_label = label;
} else if (label != base_label) {
    break;
}
```

But what was written is:

```cpp
if (label != base_label) {
    if (base_label) break;
}
else {
    base_label = label;
}
```

The `else` (`label ==
base_label`) is where the
assignment lives — but
that branch is reachable
only when `label` already
equals `base_label`,
which means the
assignment can never
take effect. Classic
structural-inversion bug.
