# [severity-3] [bug-00202] `surf2vol` — `VolumeMorph::save()` cuts the live transform chain it shares with the caller; with `-dbg_output` the final `-out`, `-out_mesh` and `-gcam` contain only the last FEM step

> [!bug] Synopsis
> `VolumeMorph::save()` first calls `serialize()`, which flattens each
> transform's `initial()` chain into the morph's own list **by calling
> `setInitial( TransformPointer() )` on the shared `Transform` objects**. In
> [[surf2vol]] those objects are the same ones the caller keeps using as its
> running total (`ptransform`). With `-dbg_output <prefix>` surf2vol saves a
> morph after every FEM step, so after the first save the running chain is cut;
> every later step starts a new chain of length one, and the final `-out`
> volume, `-out_mesh` `.tm3d` and `-gcam` `.m3z` (and the per-step "FEM error"
> printouts) contain the affine plus only the **last** FEM step instead of the
> composition of all steps. Without `-dbg_output` (the default, and what
> [[mri_cvs_register]] uses) the destructive save happens only after the
> chain is no longer needed, so the default path is unaffected.

## Affected Artefacts

- **Tool(s):** [[surf2vol]]; downstream consumers of its outputs
  ([[exportGcam]], [[createMorph]] `morph` inputs) receive the truncated morph.
- **Pipeline stage(s):** _N/A_ (not used by [[mri_cvs_register]], which does not pass `-dbg_output`)
- **FreeSurfer version(s):** confirmed in 8.2.0. `serialize()`'s destructive
  relinking is in the 2008-03-14 import (`4b881dc775f`); the surf2vol call
  site that shares the chain and saves it inside the step loop
  (`-dbg_output`) arrived on 2008-04-18 (`9761aeb9b6b`).
- **Platforms:** all
- **Triggering configuration:** `-dbg_output <prefix>` together with more than
  one FEM step (`-fem_steps N`, N ≥ 2; with `-fem_end_step`, the executed
  steps count).

## Detailed Description

`Transform<n>` objects form singly-linked chains through a shared pointer:
a transform's `initial()` is applied before its own mapping, so the total
morph of the running registration is the *last* step's transform whose
`initial()` chain leads back to the first step
(`img()` = `doOwnImg( processInitial(pt) )`, [`fem_elastic/morph.h:84-90`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.h#L84-L90)).
surf2vol builds this chain as it goes:

```cpp
        pBufTransform->m_strName = os.str();
        pBufTransform->setInitial( ptransform );
        ptransform = pBufTransform;
```

(compressed branch; the uncompressed branch does the same at
[`fem_elastic/fsurf2vol.cpp:614-616`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L614-L616)).

`VolumeMorph::save()` writes each transform of `m_transforms` as a separate,
independently compressed record and, to do so with one chain element per
record, first flattens the chain:

```cpp
void
VolumeMorph::save(const char* fname)
{
  std::string strTag;

  // serialize transforms to help handle the compressor problem
  this->serialize();
```

```cpp
void
VolumeMorph::serialize()
{
  TransformContainerType::iterator it = m_transforms.begin();
  TransformPointer pt;

  while ( it != m_transforms.end() )
  {
    if ( (pt = (*it)->initial()) )
    {
      (*it)->setInitial( TransformPointer() );
      it = m_transforms.insert(it, pt);
    }
    else
    {
      ++it;
    }
  }
}
```

The flattening mutates the **shared** objects: for every element with a
non-null `initial()` it sets that link to null (`setInitial( TransformPointer() )`)
and inserts the former predecessor in front of it in the morph's own list.
The morph's list ends up correct for writing, but the `Transform` objects —
which `morph.m_transforms` shares with surf2vol's `ptransform` — have lost
their `initial()` links permanently.

surf2vol's `-dbg_output` option saves a morph inside the step loop:

```cpp
      // if dbg option, save the mesh as a volumetric transform
      if ( !params.strDebug.empty() )
      {
        std::shared_ptr<gmp::AffineTransform3d > paffine( new gmp::AffineTransform3d(inv_t) );

        gmp::VolumeMorph morph;
        morph.set_volGeom_fixed( mri_fixed );
        morph.set_volGeom_moving(mri_moving);
        morph.m_transforms.push_back(ptransform);
        morph.m_transforms.push_back(paffine);
        std::ostringstream os;
        os << params.strDebug << "_" << step << ".tm3d";
        std::cout << " saving dbg morph\n";
        morph.save(os.str().c_str());
      }

      compute_fem_error(ptransform,initContainer);
```

The test at [`fem_elastic/fsurf2vol.cpp:622`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L622) is the `-dbg_output` check (the option is parsed at
[`fem_elastic/fsurf2vol.cpp:1404-1408`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1404-L1408)). At the end of step *k* the morph is
`[ptransform_k, affine]`; `serialize()` cuts `ptransform_k → ptransform_{k+1}`
and every earlier link. Step *k−1* then does
`pBufTransform->setInitial( ptransform )` ([`fem_elastic/fsurf2vol.cpp:590`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L590))
to a transform whose own predecessors are gone, and its `save()` cuts that
link in turn. After the final step the chain has length one (plus the
affine, which is pushed separately), and the outputs are built from it:

```cpp
      std::cout << " axe\n";
      gmp::VolumeMorph morph;
      morph.m_template = mri_fixed;
      morph.set_volGeom_fixed( mri_fixed );
      morph.set_volGeom_moving( mri_moving );
      morph.m_transforms.push_back(ptransform);
      morph.m_transforms.push_back(paffine);

      MRI* warped = morph.apply_transforms(mri_moving);

      MRIwrite(warped,
               const_cast<char*>( params.strOutput.c_str())  );
```

(`-out`; `-gcam` follows at [`fem_elastic/fsurf2vol.cpp:659-662`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L659-L662), `-out_mesh` at
[`fem_elastic/fsurf2vol.cpp:670-686`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L670-L686), `compute_fem_error(ptransform, …)` at
[`fem_elastic/fsurf2vol.cpp:637`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L637) and [`fem_elastic/fsurf2vol.cpp:667-668`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L667-L668)).

### Expected Behaviour

`-dbg_output` should only *add* per-step debug morphs. The final `-out`,
`-out_mesh`, `-gcam` and the error report must be identical with and without
it, and each `dbg_<step>.tm3d` should hold the transforms of all steps up to
that step.

### Observed Behaviour

The running transform is destroyed by the first save, and every later output is built from what is left:

- Each per-step file is written from the list at that moment, but because the
  earlier saves already cut the chain, `dbg_<k>.tm3d` contains only
  `[step k+1, step k, affine]` — from the third file on, older steps are
  missing (the first file contains `[identity, step N, affine]`).
- The final `-out_mesh` contains one delta transform plus the affine.
- The FEM-error report after each step is computed on the truncated chain
  and **grows** instead of shrinking.

### Reproducer

Two runs of the installed 8.2.0 `surf2vol` on `cvs_avg35` that differ only in
`-dbg_output` (fixed = moving = `mri/norm.mgz`, `-fixed_surf lh.white`,
`-moving_surf` = the same `lh.white` with every vertex translated +3.0 mm in
tkr x, `-aparc lh.aparc.annot`, identity cached affine
`"1 0 0 0 1 0 0 0 1 0 0 0"`):

```bash
S=$FREESURFER_HOME/subjects/cvs_avg35
COMMON="-fixed_mri $S/mri/norm.mgz -moving_mri $S/mri/norm.mgz \
  -fixed_surf $S/surf/lh.white -moving_surf lh.white.shift3 -aparc $S/label/lh.aparc.annot \
  -cache_transform id.txt -lin_res 20 -penalty_weight 1000 -topology_old -compress \
  -poisson .3 -young 1000 -pc_type jacobi -ksp_type preonly \
  -elt_vol_range 30,60 -fem_steps 3 -fem_end_step 0"
surf2vol $COMMON -out A.mgz -out_mesh A_mesh -gcam A.m3z                    # run A
surf2vol $COMMON -out B.mgz -out_mesh B_mesh -gcam B.m3z -dbg_output dbg    # run B
```

Observed (both runs finish with exit status 0, about one minute each):

| | step 3 | step 2 | step 1 / final |
|---|---|---|---|
| run A, "FEM error / Final displacement" (initial = 3) | 1.60844 | 0.449487 | 0.165208 |
| run B (`-dbg_output`), same line | 1.60844 | 1.84315 | 2.47808 |

- Step 3 is identical (nothing to truncate yet); from step 2 on B diverges.
  In B the error grows although the mesh solves are identical, because
  `compute_fem_error` is evaluated on the cut chain.
- Records written to the final `out_mesh.tm3d`: run A has four transforms
  (identity 16 bytes, three step transforms of 3.86 MB, 3.84 MB, 3.72 MB
  compressed) plus the 30-byte affine, file size 11,424,355 bytes; run B has
  one step transform (3,721,324 bytes) plus the affine, file size 3,721,554 bytes.
- The per-step debug files of run B hold `[id, step 3, affine]` (`dbg_3.tm3d`),
  `[step 3, step 2, affine]` (`dbg_2.tm3d`) and `[step 2, step 1, affine]`
  (`dbg_1.tm3d`): step 3 vanishes from the chain after the second save.
- The final `-out` volumes differ in 722,554 of 16,777,216 voxels
  (maximum intensity difference 69); the `.m3z` files differ in size
  (31,951,164 vs 31,149,913 bytes).

## Root Cause

`serialize()` implements "flatten for writing" by editing the `Transform`
objects themselves rather than a copy: `(*it)->setInitial( TransformPointer() )`
is a write to an object owned jointly (`std::shared_ptr`) with the caller.
`VolumeMorph::save()` calls it unconditionally. That is harmless when `save()`
is the last use of the morph (the default surf2vol `-out_mesh` save, the
applyMorph call at [`fem_elastic/fapplyMorph.cpp:477`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fapplyMorph.cpp#L477)), but surf2vol's
`-dbg_output` saves inside the loop and then keeps extending and reading the
same chain.

## Impact

- **Output affected (gated):** only runs with `-dbg_output`. The final `-out`,
  `-out_mesh` `.tm3d`, `-gcam` `.m3z`, and the FEM-error report silently reflect
  only the affine and the last executed step. Anyone who turns on
  `-dbg_output` to inspect a registration therefore gets a different, less
  converged final result than the same command without it — and no warning.
- **Default path unaffected:** [[mri_cvs_register]] never passes
  `-dbg_output`, and the `-out_mesh` save in surf2vol is after the last
  use of the chain.
- **Why 3:** the wrong output is gated behind a specific option
  (`-dbg_output`), which is the schema's severity-3 criterion; it is a
  debugging option, but its failure mode (silently wrong *final* outputs) is
  not cosmetic.

## Recommended Fix

Make `save()` non-destructive: serialize from a snapshot and restore the
links afterwards (including on exception). The sketch below keeps
`serialize()` untouched (it is also called by applyMorph) and wraps the
call in `save()` with a guard that records every `(transform, initial)` pair
reachable from `m_transforms` beforehand and restores the original list and
links when `save()` leaves scope:

```diff
--- a/fem_elastic/morph.cpp
+++ b/fem_elastic/morph.cpp
@@ VolumeMorph::save(const char* fname)
 void
 VolumeMorph::save(const char* fname)
 {
   std::string strTag;
 
-  // serialize transforms to help handle the compressor problem
-  this->serialize();
+  // serialize transforms to help handle the compressor problem, but undo
+  // the relinking when done: the Transform objects are shared with the caller
+  struct InitialLinkGuard
+  {
+    TransformContainerType& list;
+    TransformContainerType  listCopy;
+    std::vector< std::pair<TransformPointer, TransformPointer> > links;
+    explicit InitialLinkGuard(TransformContainerType& l) : list(l), listCopy(l)
+    {
+      for ( TransformContainerType::const_iterator it = l.begin(); it != l.end(); ++it )
+        for ( TransformPointer p = *it; p; p = p->initial() )
+          links.push_back( std::make_pair( p, p->initial() ) );
+    }
+    ~InitialLinkGuard()
+    {
+      for ( size_t i = 0; i < links.size(); ++i )
+        links[i].first->setInitial( links[i].second );
+      list = listCopy;
+    }
+  } guard( m_transforms );
+  this->serialize();
```

This was exercised on a stand-alone model of the `Transform` / `serialize()`
logic (a four-element chain `step1 → step2 → step3 → id` held by the caller):
the original code leaves the caller's `step1` with chain length 1 after
`save()`, the guarded version leaves it at 4 while the saved list is
unchanged (`id step3 step2 step1 affine`). It has **not** been compiled
inside `morph.cpp` (the ITK headers needed by that translation unit are not
installed here); a build and a CVS-style regression run (with and without
`-dbg_output` the outputs must be bit-identical) are required.

### Alternative Fixes Considered

- Add a `Transform::saveStandalone()` (writes `TWrite(os, false)` + `doOutput`
  without touching `m_pInitial`) and iterate over a flattened local list in
  `save()`; no mutation at all, but needs the transform-type tag logic of
  `saveTransform` duplicated.
- Make surf2vol pass copies to the debug morph (`std::make_shared` clones),
  which fixes this call site only.

## Workarounds (If Any)

Do not combine `-dbg_output` with `-fem_steps` greater than 1 when the final
outputs matter; run once without it for the real result.
