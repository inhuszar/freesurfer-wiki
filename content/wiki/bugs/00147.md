# [severity-2] [bug-00147] `mris_label2annot` per-label-point bounds check is off-by-one (`>` instead of `>=`), allowing `vtxno == nvertices` to pass and OOB-write into `labelStat` and `mris->vertices`

> [!bug] Synopsis
> ```cpp
> /* mris_label2annot/mris_label2annot.cpp:853-898 (abridged) */
> for (int n = 0; n < label->n_points; n++) {
>   int vtxno = label->lv[n].vno;
>   if (vtxno < 0 || vtxno > mris->nvertices) {       /* :855 — should be >= */
>     printf("ERROR: %s, n=%d, vertex %d out of range\n", LabelFiles[nthlabel], n, vtxno);
>     exit(1);
>   }
>
>   /* record all labels assigned to the vertex before applying LabelThresh and maxstat */
>   MRIsetVoxVal(labelStat, vtxno, 2, 0, 0, MRIgetVoxVal(labelStat, vtxno, 2, 0, 0)+1);
>   MRIsetVoxVal(labelStat, vtxno, 5+nthlabel, 0, 0, nthlabel);
>   …
>   /* annot and label assinged to the vertex after applying LabelThresh and maxstat */
>   MRIsetVoxVal(labelStat, vtxno, 0, 0, 0, label_annot);
>   MRIsetVoxVal(labelStat, vtxno, 1, 0, 0, nthlabel);
>   …
>   MRIsetVoxVal(nhits, vtxno, 0, 0, 0, MRIgetVoxVal(nhits, vtxno, 0, 0, 0)+1);
>
>   mris->vertices[vtxno].annotation = label_annot;
> }
> ```
>
> `labelStat` is allocated at [`:789-790`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_label2annot/mris_label2annot.cpp#L789-L790) with `width = mris->nvertices`. `nhits` is allocated at [`:257`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_label2annot/mris_label2annot.cpp#L257) with `width = mris->nvertices`. `mris->vertices` is an array of `mris->nvertices` elements. The valid index range for all three is `[0, mris->nvertices)`.
>
> The check `vtxno > mris->nvertices` lets `vtxno == mris->nvertices` pass. The subsequent `MRIsetVoxVal(labelStat, vtxno=nvertices, …)` writes one slot past the end of the labelStat width axis; `mris->vertices[vtxno=nvertices].annotation = …` writes past the end of the vertex array. Both are out-of-bounds writes.
>
> `MRIsetVoxVal` does not bounds-check the column index (see [`utils/mri.cpp:1737-1825`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L1737-L1825) — it clips the *value* for type but does not validate `c, r, s`), so the OOB write is silent.

## Affected Artefacts

- **Tool(s):** [[mris_label2annot]]
- **Pipeline stage(s):** invoked by `recon-all` default for atlas-to-annotation conversion (`scripts/recon-all:744`, `:5480`, `:5519`, `:5546`). For the FreeSurfer-bundled BA / vpnl / DKT labels, vertex indices are always `< nvertices` and the bug doesn't fire. The bug requires a label file with `vno == nvertices` — typically only seen with stale or hand-edited labels.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`; earliest known: _unknown_.
- **Platforms:** all.
- **Triggering configuration:** any `--l <file.label>` whose `lv[n].vno == mris->nvertices` for some `n`.

## Detailed Description

`mris_label2annot` converts one or more `.label` files into a single `.annot` annotation file. Each label is a list of `(vno, x, y, z, stat)` tuples; `vno` is the vertex index that the label point refers to. The function `label2annotationV2` iterates the points of each label and writes annotation / vote bookkeeping at column `vno` of two MRI structs (`labelStat`, `nhits`) plus the vertex array `mris->vertices`.

### Expected Behaviour

The bounds check should reject any `vno >= mris->nvertices` (since valid range is `[0, nvertices)`):

```cpp
if (vtxno < 0 || vtxno >= mris->nvertices) {
  printf("ERROR: ... vertex %d out of range\n", ...);
  exit(1);
}
```

### Observed Behaviour

The check `vtxno > mris->nvertices` lets `vtxno == mris->nvertices` pass. Subsequent writes are OOB:

- `MRIsetVoxVal(labelStat, nvertices, c, 0, 0, …)` — writes to slot `nvertices` of the width axis, but valid width is `[0, nvertices-1]`.
- `MRIsetVoxVal(nhits, nvertices, 0, 0, 0, …)` — same OOB.
- `mris->vertices[nvertices].annotation = …` — OOB read/write of `mris->vertices` element past the array end.

Outcome under glibc: silent corruption of adjacent heap memory; under ASAN: heap-buffer-overflow trap.

### Reproducer

```bash
# Craft a label file whose last entry has vno == nvertices
# (lh.white in fsaverage has 163842 vertices; here we set vno=163842).

cat > stale.label << EOF
#!ascii label  , from subject fsaverage vox2ras=TkReg
1
163842 0.0 0.0 0.0 0.0
EOF

# Run the conversion:
mris_label2annot --s fsaverage --hemi lh \
  --ctab /path/to/lh.aparc.ctab \
  --l stale.label \
  --annot out

# Expected: "ERROR: stale.label, n=0, vertex 163842 out of range" (exit 1)
# Observed: silent OOB write; output annotation may include the bogus entry,
#           or program crashes with stack-trace, depending on heap state.
```

> [!gap] Live reproducer not executed
> The static read of the check is unambiguous (`>` vs `>=`). The observable behaviour under glibc heap (silent corruption) vs ASAN (trap) is allocator-dependent; the cleanest demonstration would be running under ASAN with the synthetic label above.

## Root Cause

Off-by-one in the comparison operator. The author wrote `>` where `>=` is correct, conflating "out of range" with "strictly greater". Common typo when the natural-language description ("must be less than `nvertices`") gets transcribed into the negated check.

## Impact

- **OOB writes when triggered.** `MRIsetVoxVal(labelStat, nvertices, …)` and `mris->vertices[nvertices] = …` corrupt adjacent heap memory. Outcomes range from silent garbage in the output annotation to a downstream crash. Under ASAN: clean trap.
- **No fire under bundled FreeSurfer labels.** The label files distributed with FreeSurfer (`fsaverage`'s BA labels, DKT, etc.) all have vno < nvertices. The bug requires a malformed input.
- **Likely-trigger scenarios:**
  - Hand-edited label files with a typo.
  - Labels copied from a different subject's surface (different `nvertices`).
  - Labels regenerated against a remeshed surface (`mris_remesh` changes `nvertices`).
  - Custom atlases imported from non-FreeSurfer pipelines.

## Recommended Fix

One-character patch:

```diff
-    if (vtxno < 0 || vtxno > mris->nvertices) {
+    if (vtxno < 0 || vtxno >= mris->nvertices) {
       printf("ERROR: %s, n=%d, vertex %d out of range\n", LabelFiles[nthlabel], n, vtxno);
       exit(1);
     }
```

## Workarounds (If Any)

- **Validate label files before passing to `mris_label2annot`.** A simple check: every `vno` in every `--l <file>` must be `< nvertices` of the surface.
- **Run under ASAN** to catch the OOB write immediately during pipeline development.
