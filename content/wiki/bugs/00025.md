# [severity-3] [bug-00025] MRIconcatenateFrames type-check tests mri_frame1 twice (silent garbage if mri_frame2 is non-UCHAR)

> [!bug] Synopsis
> The two-frame concatenation primitive `MRIconcatenateFrames` declares
> "src must be UCHAR" but its guard tests `mri_frame1->type != MRI_UCHAR`
> twice, never validating `mri_frame2`. If a caller passes
> `mri_frame1` as `MRI_UCHAR` and `mri_frame2` as a different type
> (e.g., `MRI_FLOAT` variance image read from disk), the guard is
> silent. The body then reads `*pf2` through a `BUFTYPE *` (`unsigned
> char *`) pointer aliased onto `mri_frame2`'s actual storage. For
> `MRI_FLOAT` storage the per-byte reads pick up the IEEE-754
> bit-pattern of the floats — silent garbage, not even a
> recognisable scaled value.

## Affected Artefacts

- **Tool(s):** [[mri_linear_register]] is the most exposed in-tree
  caller; `mri_linear_register/mri_linear_register.cpp:207` calls
  `MRIconcatenateFrames(mri_ref, mri_var, NULL)` after reading
  `mri_var` from a user-supplied file via `MRIread(var_fname)` —
  the type of `mri_var` is whatever the file's on-disk type is,
  not necessarily `MRI_UCHAR`.
- **Pipeline stage(s):** _N/A_ for standard [[wiki/pipelines/recon-all|recon-all]]
  (`mri_linear_register` is not invoked by recon-all). Other
  in-tree callers in `utils/mrifilter.cpp:2804, 2859, 4483` feed
  byte-typed reductions (`MRIreduceByte` outputs) and are not
  affected in normal use.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_
- **Platforms:** all
- **Triggering configuration:** `mri_linear_register --var FILE.mgz`
  where `FILE.mgz` is `MRI_FLOAT` / `MRI_SHORT` / `MRI_INT` /
  `MRI_USHRT` / `MRI_LONG` (anything other than `MRI_UCHAR`).
  Variance volumes saved by other FreeSurfer tools are typically
  `MRI_FLOAT`, so this is the realistic case.

## Detailed Description

### Expected Behaviour

`MRIconcatenateFrames` documents that "src must be UCHAR". The
guard should refuse if either input is not `MRI_UCHAR`; otherwise
the guard is meaningless because the body unconditionally reads
through `BUFTYPE *` (a typedef for `unsigned char *`). The
documented contract is a one-line check on both arguments:

```c
if (mri_frame1->type != MRI_UCHAR || mri_frame2->type != MRI_UCHAR)
    ErrorReturn(NULL, (ERROR_UNSUPPORTED, "MRIconcatenateFrames: src must be UCHAR"));
```

### Observed Behaviour

The check evaluates `mri_frame1` twice — `mri_frame2` is never
inspected. If a caller passes `(UCHAR, FLOAT)`, `(UCHAR, SHORT)`,
or any other `(UCHAR, non-UCHAR)` combination, the guard returns
silently. The function then enters the inner loop:

```c
pf2 = &MRIvox(mri_frame2, 0, y, z);   /* (BUFTYPE *)mri_frame2->slices[..]
                                         — wrong-type alias when type != UCHAR */
*pdst2++ = *pf2++;                    /* per-byte read of FLOAT storage */
```

For `MRI_FLOAT` storage, every UCHAR byte read picks up one of the
four IEEE-754 bytes of a float — exponent / mantissa / sign bytes
in some order depending on endianness. The output `mri_dst`
(allocated as `MRI_UCHAR`) then contains four-byte-aliased garbage
for each source voxel, with no warning.

### Reproducer

```bash
# Construct a UCHAR reference and a FLOAT variance volume, then call
# mri_linear_register with --var:
mri_convert ref.mgz ref_uchar.mgz --conform   # produces UCHAR
mri_convert var.mgz var_float.mgz --out_type float
mri_linear_register --var var_float.mgz ref_uchar.mgz subject.mgz xform.lta
# Internal MRIconcatenateFrames call at mri_linear_register.cpp:207
# silently produces a 2-frame UCHAR mri_dst whose second frame is
# byte-garbled FLOAT data.
```

## Root Cause

The guard at [`utils/mri.cpp:11572`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L11572)
is a copy-paste typo. The author wrote
`mri_frame1->type != MRI_UCHAR` for both halves of the disjunction,
where the intent was clearly to validate each input separately:

```c
if (mri_frame1->type != MRI_UCHAR || mri_frame1->type != MRI_UCHAR)
                                     ^^^^^^^^^^                       /* should be mri_frame2 */
```

Compounding the missed check, the function unconditionally takes
`MRIvox(mri_frame2, ...)` — the `BUFTYPE *` accessor that assumes
UCHAR storage layout. For any non-UCHAR `mri_frame2`, the read is
a strict-aliasing violation and the bytes returned are not the
volume's logical voxel values.

## Impact

- **`mri_linear_register --var=FILE`.** The variance frame in the
  resulting concatenated `mri_ref` is corrupted. Every subsequent
  use of frame 1 of `mri_ref` (which the registration uses as a
  per-voxel weight when `var_fname` is supplied) reads
  byte-aliased garbage. The downstream linear registration is
  silently degraded, with no warning to the user.
- **In-tree `MRIreduceMeanAndStdByte` paths.** The other call
  sites at `utils/mrifilter.cpp:2804, 2859, 4483` operate on the
  output of `MRIreduceByte`, which is `MRI_UCHAR` by construction.
  They are not affected.
- **Silent.** The error path documented in the function's own
  message ("src must be UCHAR") is the only signal that should
  fire — but the bug is precisely that the guard does not check
  the second argument, so the message is never printed.
- **No memory error.** Because `mri_frame2`'s underlying storage
  for `MRI_FLOAT` is `width × height × depth × 4` bytes (vs UCHAR's
  `width × height × depth`), the per-byte loop at
  `for (x = 0; x < width; x++) *pdst2++ = *pf2++` reads only the
  first `width` bytes of each row of `mri_frame2`'s float storage.
  This is _within_ the allocated buffer (not a buffer overrun),
  so there is no segfault — just silently wrong values.

## Recommended Fix

```diff
-  if (mri_frame1->type != MRI_UCHAR || mri_frame1->type != MRI_UCHAR)
+  if (mri_frame1->type != MRI_UCHAR || mri_frame2->type != MRI_UCHAR)
     ErrorReturn(NULL, (ERROR_UNSUPPORTED, "MRIconcatenateFrames: src must be UCHAR"));
```

Optionally also rewrite the body to use type-aware accessors
(`MRIgetVoxVal` / `MRIsetVoxVal`) and allocate `mri_dst` with the
wider of the two input types — this would lift the UCHAR-only
restriction. That is a larger change; the minimal fix above
restores the documented contract.

### Alternative Fixes Considered

- **Generalise to arbitrary types.** Replace the body with
  `MRIgetVoxVal`/`MRIsetVoxVal` and choose `mri_dst->type` as the
  wider input type. This removes the UCHAR-only restriction
  entirely. Rejected for the minimal fix because it is a
  behaviour change for in-tree callers that depend on UCHAR
  output.

## Workarounds (If Any)

- Callers that may pass non-UCHAR `mri_frame2` should explicitly
  convert it to UCHAR before the call:
  `MRIchangeType(mri_frame2, MRI_UCHAR, ...)`. For a variance image
  this is generally a destructive cast (`float → unsigned char`),
  so the caller must scale the data into `[0, 255]` first. There
  is no safe workaround that preserves the original variance
  semantics without modifying the function.
