# [severity-2] [bug-00090] `MRIfillFG` / `MRIfillBG` clamp y/z seeds to `width − 1` instead of `height − 1` / `depth − 1`

> [!bug] Synopsis
> Both `MRIfillFG`
> ([`utils/mri.cpp:8122-8221`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L8122-L8221))
> and `MRIfillBG`
> ([`:8221-8313`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L8221-L8313))
> clamp out-of-range seed coordinates with the
> wrong dimension on the y and z axes:
>
> ```cpp
> /* MRIfillFG :8132-8143 — same pattern in MRIfillBG :8231-8242 */
> if (seed_x < 0)         seed_x = 0;
> else if (seed_x >= width)  seed_x = width  - 1;
> if (seed_y < 0)         seed_y = 0;
> else if (seed_y >= height) seed_y = width  - 1;     /* should be height - 1 */
> if (seed_z < 0)         seed_z = 0;
> else if (seed_z >= depth)  seed_z = width  - 1;     /* should be depth  - 1 */
> ```
>
> The sister function `MRIfill`
> ([`:8035-8046`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L8035-L8046))
> clamps correctly (`height - 1` and `depth - 1`),
> confirming the typo. After the clamp, the seed
> is written via
> [`:8163` (FG)](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L8163)
> and
> [`:8262` (BG)](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L8262)
> as `MRIvox(mri_dst, seed_x, seed_y, seed_z) =
> fill_val;`. For non-cubic volumes the wrong-axis
> clamp may write to the wrong voxel; for 2D-slice
> volumes (`depth == 1`), `seed_z = width - 1` is
> out-of-bounds and the write is undefined.

- **Tools (callers in non-attic):**
  - [[mri_fill]]
    ([`mri_fill/mri_fill.cpp:3998`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_fill/mri_fill.cpp#L3998),

  - [[mri_cc]]

  - [[mri_segment]]
    ([`mri_segment/mri_segment.cpp:1382`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segment/mri_segment.cpp#L1382))
- **Pipeline stage(s):** all three callers run
  in default `recon-all` (autorecon2 — WM
  filling, corpus-callosum labeling,
  intensity-based segmentation). The bug,
  however, fires only when a caller passes a
  seed that is out of range on the y or z axis,
  which none of the in-tree callers do (every
  call passes a known in-range slice/seed).
- **Triggering configuration:** any caller that
  passes `seed_y >= height` or `seed_z >= depth`
  on a non-cubic volume. With cubic volumes
  (256³) the wrong clamp produces the right
  numerical answer by coincidence
  (`width - 1 == height - 1 == depth - 1`).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mri.cpp:8122-8146 — MRIfillFG */
MRI *MRIfillFG(MRI *mri_src, MRI *mri_dst, int seed_x, int seed_y, int seed_z,
               int threshold, int fill_val, int *npix)
{
  ...
  if (seed_x < 0)            seed_x = 0;
  else if (seed_x >= width)  seed_x = width  - 1;     /* :8135 — correct */

  if (seed_y < 0)            seed_y = 0;

  else if (seed_z >= depth)  seed_z = width  - 1;     /* :8143 — wrong (should be depth - 1) */
  ...

  ...
}
```

```cpp

  if (seed_z < 0)            seed_z = 0;

  ...
```

For comparison, the matching block in `MRIfill`:

```cpp
/* utils/mri.cpp:8035-8046 — MRIfill, correct */
  if (seed_x < 0)            seed_x = 0;
  else if (seed_x >= width)  seed_x = width  - 1;
  if (seed_y < 0)            seed_y = 0;
  else if (seed_y >= height) seed_y = height - 1;
  if (seed_z < 0)            seed_z = 0;
  else if (seed_z >= depth)  seed_z = depth  - 1;
```

### Effect by volume shape

- **Cubic conformed volume (256³, 1 mm
  isotropic):** `width == height == depth`, so
  `width - 1` happens to equal `height - 1` and
  `depth - 1`. The bug produces the correct
  clamp by coincidence. This is the typical
  recon-all input.
- **Non-cubic 3D volume (e.g.,
  `width=64, height=128, depth=32`):** an
  out-of-range `seed_y = 200` clamps to
  `seed_y = 63` (= `width - 1`) instead of
  `127` (= `height - 1`); subsequent
  `MRIvox(..., seed_x, 63, ...)` writes to a
  voxel inside the volume but not the one the
  caller intended. The flood fill grows from the
  wrong seed.
- **2D-slice volume (`depth == 1`):** any
  out-of-range `seed_z` clamps to
  `seed_z = width - 1` (typically 63 or 255 — far
  outside the single slice). `MRIvox(mri_dst,
  seed_x, seed_y, seed_z)` is then an
  out-of-bounds write through the
  contiguous-buffer-backed `MRIvox` macro: it
  scribbles into a neighbouring slice's slot
  for whatever volume happens to share that
  layout (typically heap memory beyond the
  voxel buffer).

## Root Cause

Copy-paste from the seed_x branch. The pattern
`seed_x = width - 1;` was duplicated for `seed_y`
and `seed_z` and the trailing identifier was
not updated. `MRIfill` was either written first
correctly and the FG/BG variants were
copy-pasted from a buggy interim version, or
the FG/BG variants were copy-paste-shortcutted
without the careful clamp updates.

## Impact

- **Default `recon-all` on conformed cubic
  volumes:** none. The wrong clamp produces the
  right value by coincidence.
- **Non-cubic inputs:** the seed is silently
  relocated when out-of-range; the flood-fill
  grows from the wrong starting point. Output
  is wrong but the function does not crash.
- **2D slices with out-of-range `seed_z`:**
  out-of-bounds write through `MRIvox`. None of
  the current in-tree callers exercise this
  case.
- **Severity:** 2 — latent under typical
  recon-all inputs; conceptual defect that
  manifests on any non-cubic volume passed to
  these functions with an out-of-range seed.

## Workarounds

calling these functions until the patch lands.
