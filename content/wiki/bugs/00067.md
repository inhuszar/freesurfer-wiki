# [severity-2] [bug-00067] `MRIlrswapSeg` — transposed indexing happens to work for column-vector input

> [!bug] Synopsis
> `MRIlrswapSeg`
> ([`utils/cma.cpp:1030-1070`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/cma.cpp#L1030-L1070))
> takes two `MATRIX *` parameters `lh` and `rh`
> holding the left/right label pairs to swap. The
> per-voxel inner loop reads:
>
> ```cpp
> for (int n = 1; n <= lh->rows; n++) {
>   if (id == lh->rptr[1][n]) { id2 = rh->rptr[1][n]; ... break; }
>   else if (id == rh->rptr[1][n]) { id2 = lh->rptr[1][n]; ... break; }
> }
> ```
>
> The loop bound is `lh->rows` but the index pattern
> `lh->rptr[1][n]` accesses **row 1, column n** —
> implying the natural layout is a *row* vector
> (`rows=1`, `cols=N`). With the actual `MatrixReadTxt`-
> produced **column** vector (`rows=N`, `cols=1`),
> `lh->rptr[1][n]` for `n=1..N` walks past row 1's
> single column into adjacent memory; FreeSurfer's
> contiguous flat-data layout means this happens to
> read row 2's column 1, row 3's column 1, …
> producing the correct labels by accident.
>
> For a row-vector input (`rows=1`, `cols=N`), the
> loop runs only once (`n = 1..1`) and only the first
> label is processed.

- **Sole caller:**

## Detailed Description

```cpp
for(int n=1; n<=lh->rows; n++){
  if(id == lh->rptr[1][n]) {                           /* (!) [1][n] not [n][1] */
    id2 = rh->rptr[1][n];
    nswaps++;
    break;
  }
  else if(id == rh->rptr[1][n]) {
    id2 = lh->rptr[1][n];
    nswaps++;
    break;
  }
}
```

`MatrixReadTxt`
([`utils/matrix.cpp:991-1034`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L991-L1034))
produces a column vector (`rows=N`, `cols=1`) when
the input file has one number per line. With
contiguous flat-data layout (FreeSurfer's MATRIX
allocates `rows*cols` floats with
`rptr[r] = data + (r-1)*cols`), `rptr[1][n]` for
`n > cols` reads into the next row's data; for
`cols=1` this exactly matches `rptr[n][1]`. The
intended access pattern.

For a row-vector input (`rows=1`, `cols=N`):
- loop: `n=1..1` — only one iteration,
- `rptr[1][1]` — first label processed correctly,
- remaining labels (`rptr[1][2..N]`) never visited.

For a 2D N×M matrix:
- loop: `n=1..N`,
- `rptr[1][n]` for `n=1..M` reads row 1's columns;
  for `n=M+1..N` walks into subsequent rows.

The behaviour is unintentionally column-major-only.

## Root Cause

The author confused row/column indexing. The
contiguous-memory layout of FreeSurfer's MATRIX
structures masks the defect for the natural
one-number-per-line column-vector input format.

## Impact

- **Latent for typical input.** If the user
  supplies the swap files as one-number-per-line
  (the documented format), the bug is fully
  masked.
- **Active for row-vector input.** If the user
  supplies a single-line-with-spaces file, only the
  first label is processed.
- **Active for 2D input.** If the user supplies a
  rectangular matrix, only the first M labels are
  processed and the rest are missed or read OOB
  depending on dimensions.

the bug is silent.
