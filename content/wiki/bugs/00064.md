# [severity-2] [bug-00064] `MRIScompute(Total)VertexSpacingStats` — `dist_scale = 1.0f;` overrides the patch-vs-area branch

> [!bug] Synopsis
> Two paired functions
> `MRIScomputeVertexSpacingStats`
> ([`utils/mrisurf_metricProperties.cpp:4091-…`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_metricProperties.cpp#L4091))
> and
> `MRIScomputeTotalVertexSpacingStats`
> ([`:4179-…`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_metricProperties.cpp#L4179))
> select a `dist_scale` based on whether the surface
> is a patch or a closed sphere/inflated surface. The
> patch branch sets `dist_scale = 1.0`; the closed
> branch sets `dist_scale = sqrt(orig_area /
> total_area)` (so that distances measured on an
> inflated surface are scaled back to original units).
> Immediately after the if/else, both functions
> contain:
>
> ```cpp
> if (mris->patch) {
>   dist_scale = 1.0;
> }
> else {
>   dist_scale = sqrt(mris->orig_area / mris->total_area);
> }
> dist_scale = 1.0f;     /* (!) unconditional override */
> ```
>
> The unconditional `dist_scale = 1.0f;` makes the
> entire if/else dead code. The closed-surface branch
> never takes effect.

## Affected Artefacts

- **Tool / consumers:** internal helpers used by
  surface-integration and SSE-cost code paths during
  recon-all surface stages.
  - `utils/mrisurf_timeStep.cpp:2328`
    (`mrisurf_timeStep` — surface-integration driver)
  - `utils/mrisurf_sseTerms.cpp:2947`
    (energy-functional helpers used by
    `mris_inflate`, `mris_smooth`, etc.)
  - `utils/mrisurf_metricProperties.cpp:10446`
    (other metric-property summaries)
- **Pipeline stage(s):** `recon-all` surface stages
  reach this code, but the call is *diagnostic*: the
  returned `vmean`/`vsigma` are used for printf-only
  reporting and as inputs to soft penalty terms.
- **Triggering configuration:** any consumer that
  asks for vertex-spacing stats on a non-patch
  surface (i.e. an inflated, sphere, or sphere.reg
  surface).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* MRIScomputeVertexSpacingStats — :4097-4104 */
MRIScomputeMetricProperties(mris);
if (mris->patch) {
  dist_scale = 1.0;
}
else {
  dist_scale = sqrt(mris->orig_area / mris->total_area);
}
dist_scale = 1.0f;                                    /* :4104 — kills the else */
```

```cpp
/* MRIScomputeTotalVertexSpacingStats — :4185-4192 */
MRIScomputeMetricProperties(mris);
if (mris->patch) {
  dist_scale = 1.0;
}
else {
  dist_scale = sqrt(mris->orig_area / mris->total_area);
}
dist_scale = 1.0f;                                    /* :4192 — kills the else */
```

Effect: on an inflated surface (`total_area >>
orig_area`), the area-rescale `sqrt(orig_area /
total_area)` would shrink reported distances. Without
the rescale, distances are reported in inflated-
surface units. The downstream consumers
(`mrisurf_sseTerms.cpp:2947`,
`mrisurf_timeStep.cpp:2328`) compare this `vmean`
against threshold parameters that were tuned
expecting original-area-scaled distances; the
mismatch is small but real.

## Root Cause

Looks like a debug / diagnostic override that was
left in. The override sets `dist_scale = 1.0f` —
identical to the patch branch's value — so the
visible behaviour matches what the patch branch
would produce regardless of `mris->patch`.

## Impact

- **Latent for patch surfaces:** override matches
  the patch branch's value; no behaviour change.
- **Active for closed / inflated surfaces:**
  reported `vmean`/`vsigma` are off by the
  `sqrt(orig_area / total_area)` factor relative to
  the documented intent.
- **Consequence in callers:** the SSE / timestep
  consumers use `vmean` as a soft penalty input.
  Effects bias the integration step size by the same
  factor; for a typical inflated surface the
  area ratio is ~1.0–2.0, so the impact is small.
- **Severity:** low. Affects surface-integration
  cost diagnostics, not final geometry output
  directly.

## Recommended Fix

Either:

1. Delete the override:
   ```diff
   -  dist_scale = 1.0f;
   ```

   Restores the documented patch-vs-area-rescale
   logic.

2. Delete the if/else and keep the override:
   ```diff
   -  if (mris->patch) {
   -    dist_scale = 1.0;
   -  }
   -  else {
   -    dist_scale = sqrt(mris->orig_area / mris->total_area);
   -  }
   -  dist_scale = 1.0f;
   +  /* always 1.0 — see <reason> */
   +  dist_scale = 1.0;
   ```

   Documents that the area-rescale was deliberately
   removed.

The first option is the natural reading; pick (2)
only if there is a documented reason the rescale was
disabled.
