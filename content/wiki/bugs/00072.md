# [severity-5] [bug-00072] `JHISTOfindBin` — bin-index formula misses the `- min` shift

> [!bug] Synopsis
> `JHISTOfindBin`
> ([`utils/joint_histo.cpp:156-168`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/joint_histo.cpp#L156-L168))
> maps an input pair `(val1, val2)` to a joint
> histogram bin index. The arithmetic at
> [`:161-162`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/joint_histo.cpp#L161-L162):
>
> ```cpp
> int i = (int)((val1 * bins1) / (jhisto->max - jhisto->min));
> int j = (int)((val2 * bins2) / (jhisto->max - jhisto->min));
> ```
>
> uses `val * nbins / range` instead of the correct
> `(val - min) * nbins / range`. The denominator is
> `max - min` (correct) but the numerator omits the
> `- min` shift. For inputs with non-zero (especially
> negative) `min`, the bin assignment is biased.
>
> Consumers (`JHISTOfill` →
> `JHISTOgetEntropy` → mutual-information
> computation in [[mri_mi]]) see a distorted joint
> distribution. Latent for inputs with
> `min == 0` (T1 intensities, FA maps in
> [0, 1], label volumes); active for any input
> with non-zero minimum.

- **Sole tool caller:**

## Detailed Description

Standard histogram binning maps a value in `[min,
max]` to a bin index in `[0, nbins-1]` via:

```
bin = (val - min) * nbins / (max - min)
```

The implementation:

```cpp
int bins1 = jhisto->nbins_1;
int bins2 = jhisto->nbins_2;

int i = (int)((val1 * bins1) / (jhisto->max - jhisto->min));   /* missing - jhisto->min */
int j = (int)((val2 * bins2) / (jhisto->max - jhisto->min));   /* missing - jhisto->min */
i = max(min(i, bins1 - 1), 0);
j = max(min(j, bins2 - 1), 0);
return (i * bins2 + j);
```

Concrete examples (assuming `bins = 64`):
- T1 in [0, 255]: bin for val=128 → intended `(128-0)*64/255 ≈ 32`; actual `128*64/255 ≈ 32`. ✓ same when min=0.
- Residuals in [-100, 100]: bin for val=0 → intended `(0-(-100))*64/200 = 32` (middle); actual `0*64/200 = 0` (first bin). ✗
- Residuals in [-100, 100]: bin for val=50 → intended `(50+100)*64/200 = 48`; actual `50*64/200 = 16`. ✗

The clamp at `:164-165` saves the histogram from
out-of-bounds writes but masks the underlying
mis-binning.

## Root Cause

The `- min` shift was omitted from the numerator,
likely by an author who tested only with
non-negative inputs. The formula degrades to the
correct one when `min == 0`.

## Impact

- **Inputs with `min ≥ 0`:** unaffected. T1, FA,
  label volumes are typically all-non-negative.
- **Inputs with `min < 0`:** the bin assignment is
  biased toward the lower-numbered bins, often
  collapsing the entire negative half of the
  distribution into bin 0 (after the clamp). The
  joint histogram's marginals are wrong, and so is
  the resulting entropy / MI score.
- **Practical impact:** `mri_mi` between two
  detrended / residual volumes (e.g. for
  registration of bias-corrected vs. raw data)
  produces wrong MI scores — though typically
  comparable across calls, so a *relative* MI sweep
  may still find the right transform. Absolute MI
  values are wrong.
- **Severity:** medium. Latent for typical inputs;
  active and silently wrong for residual-domain
  inputs.

## Recommended Fix

```diff
--- a/utils/joint_histo.cpp
+++ b/utils/joint_histo.cpp
@@ -158,8 +158,9 @@ int JHISTOfindBin(JOINT_HISTOGRAM *jhisto, double val1, double val2)
   int bins1 = jhisto->nbins_1;
   int bins2 = jhisto->nbins_2;

-  int i = (int)((val1 * bins1) / (jhisto->max - jhisto->min));
-  int j = (int)((val2 * bins2) / (jhisto->max - jhisto->min));
+  double range = jhisto->max - jhisto->min;
+  int i = (range > 0) ? (int)(((val1 - jhisto->min) * bins1) / range) : 0;
+  int j = (range > 0) ? (int)(((val2 - jhisto->min) * bins2) / range) : 0;
   // insure they are in range
   i = max(min(i, bins1 - 1), 0);
   j = max(min(j, bins2 - 1), 0);
```

The `range > 0` guard handles the (admittedly
pathological) case of constant volumes where
`max == min`.

## Workarounds

Pre-shift the input volumes to have `min == 0`
before passing to `mri_mi` (e.g. `mri_concat in.nii
--add-const <-min> --o shifted.nii`).
