# [severity-3] [bug-00184] trac-preproc — missing `set` keyword breaks the multi-field-map DWI concatenation (aborts with parse error)

> [!bug] Synopsis
> In `trac-preproc`'s multiple-field-map branch (`if ($nmap > 1)`), the three
> lines that build the `mri_concat` command which merges the per-field-map
> dewarped DWI volumes into `dwi.nii.gz` are missing the leading `set`
> keyword: they read `cmd = mri_concat`, `cmd = ($cmd --i $flist)`,
> `cmd = ($cmd --o ...)` instead of `set cmd = ...`. In `tcsh`, a bare
> `cmd = mri_concat` is not an assignment — `tcsh` tries to execute a
> command named `cmd` ("cmd: Command not found."), leaves `$cmd` undefined,
> and the next line `cmd = ($cmd ...)` then fails with "Badly placed ()'s.",
> aborting the script. As a result, when more than one B0 field map is
> supplied, the per-map DWI volumes are never concatenated and `trac-preproc`
> dies instead of producing the merged `dwi.nii.gz`.

## Affected Artefacts

- **Tool(s):** [[trac-preproc]] — the TRACULA preprocessing script, invoked
  by [[wiki/pipelines/trac-all|trac-all]] during `-prep`.
- **Pipeline stage(s):** [[wiki/pipelines/trac-all|trac-all]] preprocessing.
  Reached only when B0-inhomogeneity correction is requested with **more
  than one** field map (`$nmap = $#b0mfile > 1`, i.e. multiple `--b0-mag` /
  `--b0-pha` inputs, typically one field map per DWI run).
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — the script is `#!/bin/tcsh -f`; the defect is in tcsh
  parsing and is platform-independent.
- **Triggering configuration:** multiple field maps. A single field map
  (`$nmap == 1`) skips this block entirely (`if ($nmap > 1)` is false), so
  the common single-field-map case is unaffected.

## Detailed Description

When B0 distortion correction is enabled, `trac-preproc` loops over each
input field map, runs `epidewarp.fsl` per map to produce a dewarped DWI
volume `$outbase.nii.gz`, and accumulates those outputs in `$flist`
([`scripts/trac-preproc:898`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-preproc#L898)).
After the loop, if there was more than one field map, the per-map results
must be concatenated back into a single 4-D `dwi.nii.gz` with `mri_concat`.

That concatenation is exactly the block that is broken.

### Expected Behaviour

The three lines should build and run `mri_concat`:

```tcsh
set cmd = mri_concat
set cmd = ($cmd --i $flist)
set cmd = ($cmd --o $dwidir/dwi.nii.gz)
...
$fs_time $cmd
```

producing `$dwidir/dwi.nii.gz` as the merged DWI of all per-field-map
segments, which the rest of the script then masks, eddy/B0-corrects, and
hands to `bedpostx`.

### Observed Behaviour

The lines lack `set`:

```tcsh
cmd = mri_concat
cmd = ($cmd --i $flist)
cmd = ($cmd --o $dwidir/dwi.nii.gz)
```

In `tcsh`, `=` is only an assignment operator inside `set`, `setenv`, or `@`.
A bare `cmd = mri_concat` is parsed as the command `cmd` with arguments `=`
and `mri_concat`. There is no `cmd` executable, so:

1. Line `cmd = mri_concat` → **"cmd: Command not found."**, `$status` = 1,
   and the variable `cmd` is left **undefined**.
2. Line `cmd = ($cmd --i $flist)` → `$cmd` is undefined; under `tcsh -f`
   this produces **"Badly placed ()'s."** (a parse error) and the script
   aborts at this point. The `mri_concat` command is never assembled or run.

A faithful reproduction in this environment (a minimal `tcsh -f` script that
replicates the exact three lines inside `if ($nmap > 1)`) prints:

```
cmd: Command not found.
Badly placed ()'s.
```

and exits non-zero before reaching any later line — confirming both the
command-not-found and the abort.

The net effect: with multiple field maps, the dewarped per-map DWIs are
never merged into `dwi.nii.gz`, and `trac-preproc` terminates with an error
instead of producing its primary preprocessing output.

### Reproducer

```bash
# Minimal tcsh -f reproduction of the broken block (no FreeSurfer needed):
cat > /tmp/repro.csh <<'EOF'
#!/bin/tcsh -f
set flist  = (a.nii.gz b.nii.gz)
set dwidir = /tmp/foo
set nmap   = 2
if ($nmap > 1) then
  cmd = mri_concat
  cmd = ($cmd --i $flist)
  cmd = ($cmd --o $dwidir/dwi.nii.gz)
  echo "BUILT CMD: $cmd"
endif
echo "REACHED END"
EOF
chmod +x /tmp/repro.csh
/tmp/repro.csh
# Output:
#   cmd: Command not found.
#   Badly placed ()'s.
# (never prints "BUILT CMD" or "REACHED END"; exits 1)
```

To trigger it through TRACULA itself: run `trac-preproc` (via `trac-all
-prep`) with B0 correction enabled and **two or more** field maps configured
(`set b0mlist` / `set b0plist` with >1 entry in `dmrirc`).

## Code Reference (Unambiguous)

- **File:** `scripts/trac-preproc`
- **Function:** multiple-field-map post-loop concatenation, `if ($nmap > 1)`
- **Lines:** `1005–1014` (defect at `1006–1008`)
- **Commit:** `d932c45`

```tcsh
    if ($nmap > 1) then
      cmd = mri_concat                       # ← missing `set`
      cmd = ($cmd --i $flist)                # ← missing `set`
      cmd = ($cmd --o $dwidir/dwi.nii.gz)    # ← missing `set`
      echo $cmd |& tee -a $LF |& tee -a $CF
      if ($RunIt) then
        $fs_time $cmd |& tee -a $LF
        if ($status) goto error_exit
      endif
    endif
```

These are the **only** three `cmd =` assignments in the entire script that
omit `set`; every other one of the ~60 assignments uses `set cmd = ...`
(e.g. the structurally identical single-field-map concatenation at
[`scripts/trac-preproc:491-495`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-preproc#L491-L495)),
confirming the omission is accidental. The script shebang is
[`scripts/trac-preproc:1`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-preproc#L1)
`#!/bin/tcsh -f`.

## Root Cause

A typo: the `set` keyword was dropped on all three lines of this one block.
In `tcsh`, variable assignment **requires** `set` (or `@`); `cmd = value`
without it is a command invocation, not an assignment. The first line then
fails to define `$cmd`, and the second line's `($cmd ...)` becomes a syntax
error because `$cmd` is undefined. The block is only reachable when
`$nmap > 1`, which is why the typo survived — single-field-map runs (the
usual case) never execute it.

## Impact

- **Multi-field-map TRACULA preprocessing fails.** Users who supply more
  than one B0 field map (e.g. one per DWI run) hit a hard abort:
  `trac-preproc` errors out at the concatenation step and never produces the
  merged `dwi.nii.gz`, blocking the rest of `trac-all` (mask creation,
  eddy/B0 correction, `bedpostx`, path reconstruction).
- **Loud, not silent.** The failure manifests as "cmd: Command not found."
  followed by "Badly placed ()'s." in the log, then an error exit — so it is
  observable, but the messages are cryptic (they name `cmd`, not
  `mri_concat`).
- **Scope.** Gated behind a specific input profile (>1 field map), so
  medium (3): the default single-field-map and no-field-map paths are
  unaffected. It is not critical (5) because it does not silently corrupt
  output — it aborts before producing any.

## Recommended Fix

Add the missing `set` keyword to all three lines:

```diff
     if ($nmap > 1) then
-      cmd = mri_concat
-      cmd = ($cmd --i $flist)
-      cmd = ($cmd --o $dwidir/dwi.nii.gz)
+      set cmd = mri_concat
+      set cmd = ($cmd --i $flist)
+      set cmd = ($cmd --o $dwidir/dwi.nii.gz)
       echo $cmd |& tee -a $LF |& tee -a $CF
       if ($RunIt) then
         $fs_time $cmd |& tee -a $LF
         if ($status) goto error_exit
       endif
     endif
```

After the change, the block matches the rest of the script and assembles
`mri_concat --i <per-map DWIs> --o $dwidir/dwi.nii.gz` correctly.

### Alternative Fixes Considered

The three lines could be collapsed into a single
`set cmd = (mri_concat --i $flist --o $dwidir/dwi.nii.gz)`, matching the
single-field-map style. Equivalent in effect; the three-line `set` fix is the
smaller, more faithful edit.

## Workarounds (If Any)

Users with multiple field maps can run the concatenation manually after the
per-map dewarping completes:
`mri_concat --i <dwidir>/dwi.<1..N>.nii.gz --o <dwidir>/dwi.nii.gz`, then
re-invoke `trac-preproc` to continue. Alternatively, supply a single combined
field map so `$nmap == 1` and the broken block is skipped.
