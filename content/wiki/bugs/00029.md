# mri_vol2vol --crop passes exclusive bounding-box end as inclusive end to MRIcrop

> [!bug] Synopsis
> The `--crop` code path of `mri_vol2vol` calls `MRIboundingBox` to
> find the foreground extent, then calls `MRIcrop(mov, box.x,
> box.y, box.z, box.x + box.dx, box.y + box.dy, box.z + box.dz)`.
> `MRIcrop` documents both endpoints as **inclusive**, but
> `MRIboundingBox` populates `box.dx` as the **count** of in-range
> voxels (`max_x - min_x + 1`), so `box.x + box.dx` is one **past**
> the last voxel inside the bounding box. Two consequences:
> (1) when the bounding box does not reach the volume edge, the
> crop is silently inflated by one voxel on each of the +x, +y,
> +z faces; (2) when the bounding box does reach the edge, `c2 ==
> mri->width` trips the validation check inside `MRIcrop`,
> `MRIcrop` returns `NULL`, and the very next line dereferences
> `crop->width` → SIGSEGV.

## Affected Artefacts

- **Tool(s):** [[mri_vol2vol]] when invoked with the `--crop`
  flag.
- **Pipeline stage(s):** _N/A_ for default [[recon-all]]
  (`recon-all` does not pass `--crop`); the bug is a user-facing
  defect of `mri_vol2vol --crop SCALE`.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_.
- **Platforms:** all
- **Triggering configuration:**
  - `mri_vol2vol --crop SCALE --mov INPUT [...]`
  - When `INPUT`'s foreground (any voxel ≠ 0) reaches column
    `width − 1`, row `height − 1`, or slice `depth − 1`, the
    program crashes with a NULL-pointer dereference.
  - When the foreground does **not** reach the edge, the program
    succeeds but the cropped output is one voxel wider in each of
    width, height, depth than the bounding box reported by
    `MRIboundingBox`.

## Detailed Description

### Expected Behaviour

`MRIboundingBox` populates the `MRI_REGION` struct with
`(box.x, box.y, box.z)` set to the **first** in-bounds voxel and
`(box.dx, box.dy, box.dz)` set to the **count** of in-bounds
voxels along each axis ([`utils/mri.cpp:3121-3123`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L3121-L3123)):

```cpp
box->dx = x1 - box->x + 1;
box->dy = y1 - box->y + 1;
box->dz = z1 - box->z + 1;
```

so the **last** in-bounds voxel along x is `box.x + box.dx − 1`.

`MRIcrop`'s public contract documents both endpoints as
**inclusive** ([`utils/mri2.cpp:2637-2642`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L2637-L2642)):

```cpp
/*!
  \fn MRI *MRIcrop(MRI *mri, int c1, int r1, int s1, int c2, int r2, int s2)
  \brief Crop volume, keep correct goemetry.
  \param mri - volume to be cropped
  \param crs1 - col, row, slice to start cropping (inclusive)
  \param crs2 - col, row, slice to end cropping (inclusive)
 */
```

The correct call therefore passes `box.x + box.dx − 1` as the
inclusive `c2`, matching the inclusive-end convention.

### Observed Behaviour

The `--crop` block at
[`mri_vol2vol/mri_vol2vol.cpp:668-699`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_vol2vol/mri_vol2vol.cpp#L668-L699)
calls:

```cpp
err = MRIboundingBox(mov, 0, &box);
if(err) exit(1);
crop  = MRIcrop(mov,
                box.x,            box.y,            box.z,
                box.x + box.dx,   box.y + box.dy,   box.z + box.dz);   /* ← off by one */
/* ... */
cropnew = MRIalloc(nint(crop->width*CropScale),    /* ← NULL-deref when crop is NULL */
                   nint(crop->height*CropScale),
                   nint(crop->depth*CropScale),
                   mov->type);
```

The `c2` argument is `box.x + box.dx = max_x + 1`. `MRIcrop` then
runs the validation at
[`utils/mri2.cpp:2655-2658`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L2655-L2658):

```cpp
if (c2 < 0 || c2 >= mri->width || r2 < 0 || r2 >= mri->height || s2 < 0 || s2 >= mri->depth) {
  printf("MRIcrop(): end point %d %d %d out of range\n", c2, r2, s2);
  return (NULL);
}
```

— and refuses any input whose foreground reaches the last column,
row, or slice (`max_x = width − 1` ⇒ `c2 = width` ⇒ rejected).

When the foreground **does not** reach the edge, `MRIcrop`
succeeds but the returned `crop` has one extra voxel on each of
the +x, +y, +z faces (since `c2 = max_x + 1` is taken as
inclusive). Those extra voxels are filled with whatever was at
column `max_x + 1` in `mov` — typically `0` for a volume with
background padding, but in general arbitrary content from outside
the bounding box.

### Reproducer

```bash
# 1. Crash on a tightly-cropped volume:
#    Construct a volume whose foreground extends to the last column.
fscalc INPUT.mgz mul 0 -o zero.mgz
mri_convert -ic 0 -jc 0 -kc 0 zero.mgz extends_to_edge.mgz   # write 1's at the edge
# (use any tool that produces a volume with non-zero voxels at column width-1)
mri_vol2vol --mov extends_to_edge.mgz --crop 1.0 \
            --targ TEMPLATE.mgz --o out.mgz
# Expected: cropped output written to out.mgz.
# Observed: "MRIcrop(): end point 256 ... out of range"
#           followed by SIGSEGV at mri_vol2vol.cpp:680
#           when nint(crop->width * CropScale) dereferences crop = NULL.

# 2. Off-by-one on a typical T1-with-padding input:
mri_vol2vol --mov T1.mgz --crop 1.0 --targ T1.mgz --o cropped.mgz
mri_info cropped.mgz   # observe width/height/depth one voxel wider than
                       # the bounding box reported by mri_boundingbox.
```

## Root Cause

`MRIboundingBox` returns `dx` as a **count** (inclusive end is
`x + dx − 1`), but the call site treats `x + dx` as the
inclusive end. The error is consistent with a programmer mental
model where `dx` is "one past the end" (a half-open count). The
two conventions disagree, and the code does not subtract one
when crossing the boundary between them.

Compounding factor: `MRIcrop` validates `c2 < mri->width` and
returns `NULL` on failure, but the caller does not check for
`NULL` before dereferencing — so the validation (which would
prevent silent corruption) instead becomes a crash trigger.

## Impact

- **Crashes on tightly-cropped or edge-touching inputs.** Any
  `mri_vol2vol --crop SCALE` invocation where the foreground
  reaches `width − 1`, `height − 1`, or `depth − 1` along any
  axis crashes with a NULL-pointer dereference at
  [`mri_vol2vol.cpp:680`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_vol2vol/mri_vol2vol.cpp#L680).
  Realistic for binary masks, already-cropped volumes, or
  segmentations whose foreground occupies the full FoV.
- **Silently inflated output on typical inputs.** When the
  foreground does not touch the edge, the cropped volume is one
  voxel wider in each of width, height, depth than the bounding
  box. The extra voxels are typically zero (if the background
  outside the bbox is uniformly zero), so the data values are
  unchanged, but the **header geometry** is wrong: the
  reported `c_r`, `c_a`, `c_s` (computed by
  `MRIp0ToCRAS` from the cropped first voxel's RAS) plus the
  one-extra-voxel-each-face dimension shift the volume's centre
  by half a voxel.
- **Subtle downstream consequence.** Any tool that reads the
  cropped output and relies on `width/height/depth × xsize ×
  ysize × zsize = bounding-box volume` over-estimates the
  bounded region by `(W·H + W·D + H·D + W + H + D + 1)·voxvol`
  worth of background.
- **Latent for default [[recon-all]].** `recon-all` does not
  invoke `mri_vol2vol --crop`.

## Recommended Fix

```diff
   err = MRIboundingBox(mov, 0, &box);
   if(err) exit(1);
-  crop  = MRIcrop(mov,box.x, box.y, box.z,
-                  box.x+box.dx, box.y+box.dy, box.z+box.dz);
+  crop  = MRIcrop(mov, box.x,           box.y,           box.z,
+                       box.x+box.dx-1,  box.y+box.dy-1,  box.z+box.dz-1);
+  if (crop == NULL) {
+    printf("ERROR: MRIcrop failed for bbox (%d,%d,%d)–(%d,%d,%d) in %dx%dx%d volume\n",
+           box.x, box.y, box.z,
+           box.x+box.dx-1, box.y+box.dy-1, box.z+box.dz-1,
+           mov->width, mov->height, mov->depth);
+    exit(1);
+  }
```

Two changes: subtract `1` from each upper endpoint to match the
inclusive-end contract, and add a `NULL`-check on `crop` to
convert the latent SIGSEGV into a clean error message even if a
future regression reintroduces the off-by-one.

### Alternative Fixes Considered

- **Change `MRIcrop`'s contract to half-open.** Possible but
  invasive — there are multiple callers (`mri_convert`, two
  other `mri_vol2vol` paths) that follow the inclusive
  convention correctly today. Rejected.
- **Convert `MRIboundingBox.dx` to a half-open count.** Same
  surface-area issue: many call sites depend on the
  count-with-inclusive-min semantics. Rejected.

## Workarounds (If Any)

- For a non-tightly-cropped input where the off-by-one only
  inflates the output, the cropped volume is usually still
  usable — the extra voxels are typically zero and the geometry
  shift is within ½ voxel.
- For an edge-touching input that crashes: pad the input with
  one slice of zero voxels before invoking `mri_vol2vol --crop`,
  e.g., via `mri_convert --conform_min` or a manual `MRIalloc`
  + `MRIextract` round-trip with a larger destination.

## Confidence and Gaps

> [!gap] Header-geometry shift quantification
> The recommended fix is mathematically clear, but the magnitude
> of the cropped output's centre-of-volume shift under the
> current buggy form has not been measured on a real input. For
> a 256³ volume with bbox at `(10,10,10)-(245,245,245)`, the
> shift in `c_r`, `c_a`, `c_s` is `±½ × xsize` along each axis
> — sub-millimetre at the conformed 1 mm voxel size, but
> potentially significant for downstream tools that align two
> cropped outputs of subjects with different bboxes.
