# [severity-2] [bug-00094] `MRIcomplement` allocates 1 frame but iterates `nframes` — multi-frame OOB write

> [!bug] Synopsis
> `MRIcomplement`
> ([`utils/mriset.cpp:171-195`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L171-L195))
> binarises a source volume by complementing
> each voxel (`!val`). When `mri_dst == NULL`,
> the destination is allocated with
>
> ```cpp
> if (!mri_dst) {
>   mri_dst = MRIalloc(width, height, depth, mri_src->type);   /* :182 */
>   MRIcopyHeader(mri_src, mri_dst);
> }
> ```
>
> `MRIalloc(w, h, d, type)` defaults the
> `nframes` argument to **1**
> ([`utils/mri.cpp:515-518`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L515-L518)
> — the constructor uses
> `MRI({width, height, depth}, type)` which is
> 1-frame). The loop then iterates over
> `mri_src->nframes`:
>
> ```cpp
> for (f = 0; f < mri_src->nframes; f++)
>   for (z = 0; z < depth; z++)
>     for (y = 0; y < height; y++)
>       for (x = 0; x < width; x++) {
>         val = (int)MRIgetVoxVal(mri_src, x, y, z, f);
>         MRIsetVoxVal(mri_dst, x, y, z, f, !val);     /* :191 — OOB for f >= 1 */
>       }
> ```
>
> For a multi-frame source, every write at
> `f >= 1` is past the end of the destination's
> voxel buffer.

## Affected Artefacts

- **Tools (in-tree callers):**
  - [`utils/mriflood.cpp:132`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriflood.cpp#L132)
    — passes `MRIcomplement(mri_inter, mri_inter)`
    (in-place; alloc branch not taken).
  - [`mri_segment/mri_segment.cpp:1158`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segment/mri_segment.cpp#L1158)
    — passes `MRIcomplement(mri_filled,
    mri_filled)` (in-place; alloc branch not
    taken).
- **Pipeline stage(s):** none directly affected
  in default `recon-all` (both callers pre-
  allocate). Latent for any future caller that
  passes `mri_dst == NULL` on a multi-frame
  source.
- **Triggering configuration:** any call with
  `mri_dst == NULL` and `mri_src->nframes > 1`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mriset.cpp:171-195 */
MRI *MRIcomplement(MRI *mri_src, MRI *mri_dst)
{
  int width, height, depth, x, y, z, val, f;

  MRIcheckVolDims(mri_src, mri_dst);

  width  = mri_src->width;
  height = mri_src->height;
  depth  = mri_src->depth;

  if (!mri_dst) {
    mri_dst = MRIalloc(width, height, depth, mri_src->type);   /* :182 — 1 frame */
    MRIcopyHeader(mri_src, mri_dst);
  }

  for (f = 0; f < mri_src->nframes; f++)
    for (z = 0; z < depth; z++)
      for (y = 0; y < height; y++)
        for (x = 0; x < width; x++) {
          val = (int)MRIgetVoxVal(mri_src, x, y, z, f);
          MRIsetVoxVal(mri_dst, x, y, z, f, !val);
        }

  return (mri_dst);
}
```

`MRIalloc` is the legacy single-frame
allocator
([`utils/mri.cpp:515-518`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L515-L518)):

```cpp
MRI *MRIalloc(int width, int height, int depth, int type)
{
  return new MRI({width, height, depth}, type);
}
```

The constructor's `Shape` initializer
`{width, height, depth}` defaults `nframes` to
1
([`utils/mri.cpp:108-110`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L108-L110)).
For multi-frame sources, the resulting
`mri_dst` has only the f=0 slot allocated; the
write at `f=1` lands either in an adjacent
heap allocation (heap corruption) or in the
overflow part of `mri_dst`'s contiguous buffer
(undefined behaviour).

Compare with `MRIand` / `MRIor` / `MRIxor` /
`MRIintersect` in the same file, which all use
`MRIclone(mri1, NULL)` — `MRIclone` correctly
preserves the source's frame count.

## Root Cause

`MRIalloc` is the legacy single-frame
allocator that predates the move to multi-
frame defaults. The complement function was
written when input was always single-frame,
or copy-pasted from a similar single-frame
helper. The `for (f = 0; f < mri_src->nframes;
...)` loop was added later (or always there)
without updating the alloc to
`MRIallocSequence(..., mri_src->nframes)` or
`MRIclone(mri_src, NULL)`.

## Impact

- **In-tree callers:** unaffected — both
  `mriflood.cpp:132` and
  `mri_segment.cpp:1158` pass `mri_dst ==
  mri_src` (in-place), so the alloc branch is
  never executed.
- **External callers:** any external code that
  invokes `MRIcomplement(mri_src, NULL)` on a
  multi-frame `mri_src` writes past the
  destination buffer. Symptom: heap
  corruption, segfault, or silently wrong
  values in adjacent allocations.
- **Severity:** 2 — latent under typical
  conditions; conceptual mismatch between
  alloc shape and loop iteration extent.

## Recommended Fix

```diff
--- a/utils/mriset.cpp
+++ b/utils/mriset.cpp
@@ -179,7 +179,7 @@ MRI *MRIcomplement(MRI *mri_src, MRI *mri_dst)
   depth = mri_src->depth;
 
   if (!mri_dst) {
-    mri_dst = MRIalloc(width, height, depth, mri_src->type);
-    MRIcopyHeader(mri_src, mri_dst);
+    mri_dst = MRIclone(mri_src, NULL);
   }
```

`MRIclone` correctly allocates with the
source's frame count, header, and pulse
parameters — and matches the pattern used by
the other set-op functions in the same file.

## Workarounds

Always pass a pre-allocated `mri_dst` (or
`mri_src` itself for in-place complement) to
ensure the dst frame count is correct.
