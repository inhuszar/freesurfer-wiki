# [severity-5] [bug-00004] MRIsampleVolumeGradient — boundary denominator not adjusted when one side is clipped

> [!bug] Synopsis
> `MRIsampleVolumeGradient` in `utils/mri.cpp` degrades to a one-sided
> forward (or backward) difference when either `x+1` or `x−1` falls
> outside the volume, yet always divides by `2·xsize` as if it were a
> central difference. For voxels near the edge of the FoV, this
> under-reports the gradient magnitude by a factor of two along the
> axes where clipping occurred. The companion `MRIsampleVolumeGradientFrame`
> has a related defect: it does not attempt the one-sided fallback at
> all, so it takes `mri->outside_val` as the out-of-bounds sample,
> further corrupting the gradient at the edge. The routine is called
> from the surface-deformation gradient term and from many atlas-morph
> entry points inside [[wiki/pipelines/recon-all|recon-all]].

## Affected Artefacts

- **Tool(s):** Every tool that calls `MRIsampleVolumeGradient` —
  [[mris_place_surface]], [[mris_make_surfaces]], [[mri_ca_register]],
  [[mri_em_register]], [[mris_fix_topology]] (topology fixer),
  `mri_extract_fcd_features`, `mri_distance_transform`,
  `mri_dct_align`, `mris_shrinkwrap`, and internal helpers in
  `mrisurf_compute_dxyz.cpp`, `mrisurf_sseTerms.cpp`,
  `mrisurf_mri.cpp`, `mrisurf_defect.cpp`, and `mrimorph.cpp`.
- **Pipeline stage(s):** `autorecon2` and `autorecon3` surface
  placement (gradient-driven deformation against intensity volumes);
  the affine/nonlinear atlas-registration stages in `autorecon1` and
  `autorecon2`.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit
  `d932c45b79`.
- **Platforms:** all.
- **Triggering configuration:** any sampling point whose `x±1`,
  `y±1`, or `z±1` neighbour lies outside the source volume. In
  conformed `256³` volumes the brain is typically well inside the FoV,
  so the artefact is confined to voxels within one step of a face of
  the bounding box. In cropped or aggressively defaced volumes, or in
  the late stages of inward gradient walks, a vertex can reach within
  a voxel of the boundary.

## Detailed Description

`MRIsampleVolumeGradient` estimates `∂I/∂x`, `∂I/∂y`, `∂I/∂z` by a
three-point central difference. It explicitly guards each ±1 lookup
against being outside the volume: when `x+1` is out of bounds the code
substitutes `I(x)` for `I(x+1)`, and likewise on the lower side. That
substitution turns the central difference into a one-sided difference
over a spacing of **one** voxel, not two. However, the final division
is still `(xp1 − xm1) / (2·xsize)`, which is correct only when both
sides were actually available.

The companion function `MRIsampleVolumeGradientFrame` dispenses with
the guard entirely and calls `MRIsampleVolumeFrame(mri, x±1, y, z, …)`
directly. Because `MRIsampleVolumeFrame` returns `mri->outside_val`
when its coordinate is out of bounds, any boundary evaluation of
`MRIsampleVolumeGradientFrame` mixes the (usually zero)
`outside_val` into the numerator, producing a biased gradient rather
than a halved one.

### Expected Behaviour

A central-difference sampler should either:

- detect a boundary clip and switch to `(I(x) − I(x−1)) / xsize` (or
  `(I(x+1) − I(x)) / xsize`), using the correct denominator for the
  step actually taken; or
- explicitly document the one-sided, half-magnitude result and have
  callers compensate.

Neither is done in `MRIsampleVolumeGradient`.

### Observed Behaviour

When `x+1` is out of bounds and `x−1` is in bounds (or vice-versa):

- `MRIsampleVolumeGradient` returns `(I(x) − I(x−1)) / (2·xsize)`.
  The true one-sided gradient is `(I(x) − I(x−1)) / xsize`. The
  returned value is half the correct magnitude.
- `MRIsampleVolumeGradientFrame` returns
  `(outside_val − I(x−1)) / (2·xsize)`. For the default
  `outside_val = 0` this is `−I(x−1)/(2·xsize)` — wrong in both
  magnitude and (likely) sign relative to the local trend.

When both `x+1` and `x−1` are out of bounds (a 1-voxel slab), both
variants return zero, which is reasonable.

```cpp
int MRIsampleVolumeGradient(MRI *mri, double x, double y, double z, double *pdx, double *pdy, double *pdz)
{
  // int width, height, depth;
  double xp1, xm1, yp1, ym1, zp1, zm1;

  if (MRIindexNotInVolume(mri, x + 1, y, z))
    MRIsampleVolume(mri, x, y, z, &xp1);
  else
    MRIsampleVolume(mri, x + 1.0, y, z, &xp1);
  if (MRIindexNotInVolume(mri, x - 1, y, z))
    MRIsampleVolume(mri, x, y, z, &xm1);
  else
    MRIsampleVolume(mri, x - 1.0, y, z, &xm1);

  if (MRIindexNotInVolume(mri, x, y + 1, z))
    MRIsampleVolume(mri, x, y, z, &yp1);
  else
    MRIsampleVolume(mri, x, y + 1.0, z, &yp1);
  if (MRIindexNotInVolume(mri, x, y - 1.0, z))
    MRIsampleVolume(mri, x, y, z, &ym1);
  else
    MRIsampleVolume(mri, x, y - 1.0, z, &ym1);

  if (MRIindexNotInVolume(mri, x, y, z + 1.0))
    MRIsampleVolume(mri, x, y, z, &zp1);
  else
    MRIsampleVolume(mri, x, y, z + 1.0, &zp1);
  if (MRIindexNotInVolume(mri, x, y, z - 1.0))
    MRIsampleVolume(mri, x, y, z, &zm1);
  else
    MRIsampleVolume(mri, x, y, z - 1.0, &zm1);

  *pdx = (xp1 - xm1) / (2.0 * mri->xsize);
  *pdy = (yp1 - ym1) / (2.0 * mri->ysize);
  *pdz = (zp1 - zm1) / (2.0 * mri->zsize);
  return (NO_ERROR);
}
```

int MRIsampleVolumeGradientFrame(
    const MRI *mri, double x, double y, double z, double *pdx, double *pdy, double *pdz, int frame)

  double xp1, xm1, yp1, ym1, zp1, zm1;

  *pdy = (yp1 - ym1) / (2.0 * mri->ysize);
  *pdz = (zp1 - zm1) / (2.0 * mri->zsize);

  return (NO_ERROR);
}

## Root Cause

The boundary guard substitutes the central sample `I(x)` for the
missing one-sided sample `I(x±1)`, which effectively halves the
interval between the two numerator samples (from 2 voxels to 1). The
denominator `2·xsize` was not adjusted to reflect that the
`(xp1 − xm1)` difference is now across a one-voxel step, not a
two-voxel step. As a result, the returned gradient is half of the true
forward (or backward) difference at edge voxels.

For `MRIsampleVolumeGradientFrame`, no guard was added in the first
place, and `MRIsampleVolumeFrame`'s out-of-bounds return value
(`mri->outside_val`) enters the numerator as if it were a real sample.

## Impact

- **Surface placement (`mris_place_surface` / `mris_make_surfaces`,
  inside `autorecon2`).** The gradient term in `mrisComputeIntensityTerm`
  and similar routines multiplies the image gradient by the outward
  surface normal to decide how to advance each vertex. Near the FoV
  boundary the driving force is reduced by half, biasing the surface
  toward its current position. In conformed `256³` volumes most of
  the cortex is far from the FoV so the population-level effect is
  small, but local artefacts can appear when a surface is initialised
  close to the volume boundary (e.g., after aggressive defacing or
  head placement at the edge of the gantry).
- **Atlas registration (`mri_em_register`, `mri_ca_register`,
  `mri_robust_register` downstream).** The gradient is consumed by
  the optimiser in the gradient-descent/line-search step; halved
  magnitudes at boundary voxels slightly distort the search direction
  and can slow convergence, though the objective minimum is still
  reached in typical cases.
- **Topology fixing and defect detection (`mrisurf_defect.cpp`).**
  Gradient magnitudes are used as features for candidate defect
  regions; misreporting at the boundary biases those features but
  rarely affects the high-curvature defects of interest.
- `MRIsampleVolumeGradientFrame` is called in comparatively few
  places; its worse boundary behaviour (mixing in `outside_val`) is
  likely to be more destructive per-call but hits fewer users.

## Recommended Fix

Track whether each side was clipped, and scale accordingly. A
minimal, self-contained rewrite of the x component:

```diff
-  if (MRIindexNotInVolume(mri, x + 1, y, z))
-    MRIsampleVolume(mri, x, y, z, &xp1);
-  else
-    MRIsampleVolume(mri, x + 1.0, y, z, &xp1);
-  if (MRIindexNotInVolume(mri, x - 1, y, z))
-    MRIsampleVolume(mri, x, y, z, &xm1);
-  else
-    MRIsampleVolume(mri, x - 1.0, y, z, &xm1);
-  ...
-  *pdx = (xp1 - xm1) / (2.0 * mri->xsize);
+  int xp_clipped = MRIindexNotInVolume(mri, x + 1, y, z);
+  int xm_clipped = MRIindexNotInVolume(mri, x - 1, y, z);
+  MRIsampleVolume(mri, xp_clipped ? x : x + 1.0, y, z, &xp1);
+  MRIsampleVolume(mri, xm_clipped ? x : x - 1.0, y, z, &xm1);
+  /* span is (1 - xp_clipped) + (1 - xm_clipped) voxels, so avoid
+   * dividing by zero when both are clipped (1-voxel-wide volume). */
+  {
+    double span = (2 - xp_clipped - xm_clipped) * mri->xsize;
+    *pdx = (span > 0.0) ? (xp1 - xm1) / span : 0.0;
+  }
```

Apply the same pattern to the y and z components. For
`MRIsampleVolumeGradientFrame`, add equivalent guards so that
`outside_val` never enters the numerator.

### Alternative Fixes Considered

Fall back to `MRIsampleVolumeFrame` (or `MRIsampleVolume`) at
sub-voxel offsets like `±0.5` to keep a symmetric, half-step central
difference at the boundary; the gradient would then be
`(I(x+0.5) − I(x−0.5)) / xsize`. This preserves a consistent
denominator but requires trusting `MRIsampleVolume`'s behaviour just
inside the boundary on each side. The explicit clip-and-rescale above
is clearer and does not change the behaviour of interior voxels.

## Workarounds (If Any)

Callers that care about accurate boundary gradients can either
(a) pad the source volume before sampling, or (b) skip gradient
queries when `MRIindexNotInVolume(mri, x±1, y, z)` is true for any
axis.
