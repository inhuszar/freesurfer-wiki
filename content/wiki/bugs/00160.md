# [severity-2] [bug-00160] stim_polar — leftover debug block reads one stdin char and exit(0)s before any argument or GLUT code

> [!bug] Synopsis
> `main()` in `stim_polar.cpp` opens with a leftover debug block that
> reads a single character from stdin with `fgetc(stdin)`, prints
> `c = <char>`, and immediately calls `exit(0)` — before any version
> handling, argument parsing, GLUT initialisation, or rendering runs. The
> shipped binary is therefore non-functional as a polar-angle retinotopy
> stimulus: it prints `c = ` and quits regardless of the command line.
> Everything from `handleVersionOption` onward (the entire usable program,
> ~50 lines) is unreachable dead code.

## Affected Artefacts

- **Tool(s):** [[stim_polar]]
- **Pipeline stage(s):** _N/A_ — `stim_polar` is an interactive OpenGL/GLUT
  visual-stimulus generator for retinotopic-mapping experiments, run by
  hand at an experimental display; it is not part of
  [[wiki/pipelines/recon-all|recon-all]] or any batch pipeline.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — the early `exit(0)` is unconditional and
  platform-independent.
- **Triggering configuration:** every invocation. No flag combination
  reaches past the debug block; even `--help` / `--version` are shadowed
  because the block precedes `handleVersionOption`.

## Detailed Description

The first statement in `main()` after declaring `nargs` is an unnamed
block that:

1. Loops `while (feof(stdin)) printf(".")` — a no-op in practice, since
   `feof` only returns non-zero **after** a read hits end-of-file, so on
   entry it is `0` and the body never executes.
2. Calls `c = fgetc(stdin)` — blocks for and consumes one character of
   standard input.
3. Prints `c = %c`.
4. Calls `exit(0)`.

Because step 4 terminates the process, none of the real program runs:
`handleVersionOption`, `Progname`/`ErrorInit`/`DiagInit` setup,
`glutInit`, the 7-argument usage check, the `atof`/`atoi` parsing of
`flickerFreq`/`stimPeriod`/`minEcc`/`maxEcc`/`numRings`/`numSpokes`/
`OUTWARD`, the `minEcc` validation, `glutCreateWindow`, `init()`, the
display/reshape/idle callbacks, and `glutMainLoop()` are all dead code.
The block has the hallmarks of a hand-debugging stub (read a keystroke,
echo it, bail) that was committed by mistake.

### Expected Behaviour

`stim_polar <flickerFreq> <stimPeriod> <minEcc> <maxEcc> <numRings>
<numSpokes> <OUTWARD>` should parse its seven arguments, open a GLUT
window, and animate the rotating polar-angle checkerboard wedge stimulus
until the window is closed. `stim_polar --version` should print the
version and exit.

### Observed Behaviour

The program prints `c = ` (followed by whatever single character it read
from stdin, or a blank/newline if stdin is empty or closed) and exits 0,
having drawn nothing and ignored all arguments. Confirmed on the installed
`8.2.0` binary:

```text
$ echo "x" | stim_polar 1 2 3 4 5 6 7
c = x
$ echo "" | stim_polar --help
c =
```

Both invocations exit 0 immediately; no window is created, no usage is
printed, `--help`/`--version` are not honoured.

### Reproducer

```bash
# Any invocation quits after echoing one stdin char:
echo "x" | stim_polar 8 32000 1 40 8 24 1
#   -> "c = x"  (then exit 0; no GLUT window, args ignored)

# --version is also shadowed by the debug block:
echo "" | stim_polar --version
#   -> "c = "   (version string never printed)
```

Reproduced on `/usr/local/freesurfer/8.2.0/bin/stim_polar`.

## Code Reference (Unambiguous)

- **File:** `stim_polar/stim_polar.cpp`
- **Function:** `main()`
- **Lines:** `457–522` (whole function); defect at `460–468`
- **Commit:** `d932c45`

```cpp
int main(int argc, char** argv) {
  int     nargs ;

  {
    char c ;

    while (feof(stdin))
      printf(".") ;
    c = fgetc(stdin) ;
    printf("c = %c\n", c) ;
    exit(0) ;                       // ← unconditional early exit: everything below is dead
  }

  nargs = handleVersionOption(argc, argv, "stim_polar");
  if (nargs && argc - nargs == 1)
    exit (0);
  argc -= nargs;
  /* ... Progname/ErrorInit/DiagInit, glutInit, arg parsing, glutMainLoop ... */
```

## Root Cause

A debugging stub — "wait for / read a keystroke, echo it, exit" — was left
at the very top of `main()`. The trailing `exit(0)` makes it terminal,
and because it is placed before `handleVersionOption` and every other
statement, it pre-empts the entire program. The companion
`while (feof(stdin)) printf(".")` is also debug scaffolding (and is itself
logically inert, since `feof` is false until a read fails).

## Impact

- `stim_polar` is completely non-functional as shipped: it cannot present
  the retinotopic stimulus it exists to present. Any experimenter invoking
  it gets `c = ` and an immediate exit.
- The failure is **loud and immediate** (the program obviously does
  nothing and prints a stray `c =`), so there is no risk of silently
  corrupting data or analysis — a user notices at once that no stimulus
  appears. The tool is an interactive, standalone visual-stimulus
  generator with **no in-tree callers** and no place in
  [[wiki/pipelines/recon-all|recon-all]]. Per the severity rubric, an
  always-broken-but-obvious standalone interactive tool with no pipeline
  reach and no silent-output risk sits at **2 (low)**: the entire usable
  program is dead code behind the stub, but nothing downstream depends on
  it and no result is silently wrong.

## Recommended Fix

Delete the leftover debug block so `main()` begins with version handling:

```diff
 int main(int argc, char** argv) {
   int     nargs ;

-  {
-    char c ;
-
-    while (feof(stdin))
-      printf(".") ;
-    c = fgetc(stdin) ;
-    printf("c = %c\n", c) ;
-    exit(0) ;
-  }
-
   nargs = handleVersionOption(argc, argv, "stim_polar");
   if (nargs && argc - nargs == 1)
     exit (0);
   argc -= nargs;
```

After removal the program proceeds to parse arguments and enter the GLUT
main loop as intended.

### Alternative Fixes Considered

None — the block has no legitimate runtime purpose; the only correct
action is to remove it. (Guarding it behind a never-set debug flag would
leave the same dead code in place; deletion is cleaner.)

## Workarounds (If Any)

None as shipped — no command-line input bypasses the early `exit(0)`.
The tool must be rebuilt with the debug block removed (or the offending
lines commented out) to function.
