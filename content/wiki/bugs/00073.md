# [severity-3] [bug-00073] `mri_glmfit --split` last-split adjustment drops the final frame

> [!bug] Synopsis
> `mri_glmfit` with `--split <NSplits> <SplitNo>`
> partitions the input frames into `NSplits` blocks
> and runs the GLM on the `SplitNo`-th block,
> excluding all other frames. The block boundaries
> are computed at
> [`mri_glmfit/mri_glmfit.cpp:1075-1083`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L1075-L1083):
>
> ```cpp
> nPerSplit = floor((double)mriglm->y->nframes/NSplits);
> SplitMin = SplitNo*nPerSplit;
> SplitMax = SplitMin + nPerSplit;
> if((SplitNo==NSplits-1) && (SplitMax<mriglm->y->nframes-1))
>   SplitMax = mriglm->y->nframes-1;                          /* :1079 */
> nExclude = mriglm->y->nframes-(SplitMax-SplitMin);
> ```
>
> The last-split adjustment uses
> `mriglm->y->nframes - 1` (one less than the total
> frame count). Combined with the inclusion check at
> `:1099` (`if(n < SplitMin || n >= SplitMax)`
> excludes frames outside the half-open interval
> `[SplitMin, SplitMax)`), the last frame
> (index `nframes - 1`) is silently dropped from
> the last split whenever the adjustment fires.

## Affected Artefacts

- **Tool:** [[mri_glmfit]] with `--split <NSplits>
  <SplitNo>`.
- **Pipeline stage(s):** none in default
  `recon-all`. Affects user split-half analyses.
- **Triggering configuration:**
  `nframes > NSplits * floor(nframes/NSplits) + 1`
  AND `SplitNo == NSplits - 1`. Examples that
  trigger the bug:
  - `nframes=11, NSplits=3` → last frame dropped
  - `nframes=14, NSplits=3` → last frame dropped
  - `nframes=10, NSplits=3` → no adjustment fires
    (different bug: frames 9 silently dropped via
    the floor-division anyway)
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

Walk-through with `nframes=11, NSplits=3`:

| SplitNo | nPerSplit | SplitMin | SplitMax (before) | adj | SplitMax (after) | Frames in split |
|--------:|----------:|---------:|------------------:|:---:|-----------------:|:---------------:|
| 0       | 3         | 0        | 3                 | —   | 3                | 0,1,2           |
| 1       | 3         | 3        | 6                 | —   | 6                | 3,4,5           |
| **2**   | 3         | 6        | 9                 | yes | **10**           | **6,7,8,9**     |

The check `(SplitMax < nframes-1)` = `(9 < 10)` =
true, so `SplitMax = nframes - 1 = 10`. Wait, that
gives `SplitMax = 10` — let me re-check.

Hmm, `nframes - 1 = 10`. So `SplitMax = 10`. Then the
inclusion check is `n < 10`, which includes frames
0..9 = all 10 of frames 0..nframes-1. That covers
the 11-frame volume up to frame 9 inclusive but not
frame 10 (the 11th frame).

Wait, frame indices 0..10 (11 frames). After
adjustment SplitMax=10. Check `n < 10` excludes
frame 10. So frame 10 (last) is dropped.

Concretely: with `nframes=11, NSplits=3`, the last
split `[6, 10)` covers frames 6, 7, 8, 9 — but
frame 10 (the last frame) is not included.

The fix is `SplitMax = nframes` and the condition
becomes `SplitMax < nframes`:

```cpp
if ((SplitNo == NSplits - 1) && (SplitMax < mriglm->y->nframes))
  SplitMax = mriglm->y->nframes;
```

After this fix, the last split covers frames
6, 7, 8, 9, 10 — all of the trailing block.

## Root Cause

Standard off-by-one: the author treated `SplitMax`
as inclusive instead of exclusive (or vice-versa)
when applying the last-split fence. The inclusion
check at `:1099` uses half-open semantics `[SplitMin,
SplitMax)`, which means `SplitMax` should be `nframes`
to cover all `nframes` frames.

## Impact

- **Latent for evenly-divisible split counts.** If
  `nframes % NSplits == 0`, the adjustment doesn't
  fire and no frames are dropped.
- **Active for unevenly-divisible split counts.**
  The last frame of the volume is silently excluded
  from the last split, reducing that split's
  effective sample size by one. The number of
  excluded frames is reported by the printf at
  `:1081` but the user has no way to know that the
  *last* split is one frame short of intended.
- **Severity:** low. One frame of 11+ for typical
  fMRI / split analyses. The bias is small but
  reproducible.

## Recommended Fix

```diff
--- a/mri_glmfit/mri_glmfit.cpp
+++ b/mri_glmfit/mri_glmfit.cpp
@@ -1077,7 +1077,7 @@ int main(int argc, char *argv[])
     SplitMin = SplitNo*nPerSplit;
     SplitMax = SplitMin + nPerSplit;
-    if((SplitNo==NSplits-1) && (SplitMax<mriglm->y->nframes-1)) SplitMax = mriglm->y->nframes-1;
+    if((SplitNo==NSplits-1) && (SplitMax<mriglm->y->nframes)) SplitMax = mriglm->y->nframes;
     nExclude = mriglm->y->nframes-(SplitMax-SplitMin);
```

After the fix the last frame is included in the
last split when the adjustment fires.

## Workarounds

For users who want all frames included in their
splits: pad or pre-trim the input volume so that
`nframes` is exactly divisible by `NSplits`.
