# [severity-2] [bug-00077] `mri_dct_align` — three diagnostic basis-matrix writes all dump the X basis

> [!bug] Synopsis
> `find_optimal_dct`
> ([`mri_dct_align/mri_dct_align.cpp:582-596`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_dct_align/mri_dct_align.cpp#L582-L596))
> dumps the freshly-allocated DCT basis matrices for
> diagnostics:
>
> ```cpp
> MatrixWrite(dct->m_x_basis, "xdct.mat", "xdct") ;     /* :589 */
> MatrixWrite(dct->m_x_basis, "ydct.mat", "ydct") ;     /* :590 — wrong source */
> MatrixWrite(dct->m_x_basis, "zdct.mat", "zdct") ;     /* :591 — wrong source */
> ```
>
> The first call correctly dumps the X basis. The
> second and third dump the same X basis under
> filenames `ydct.mat` / `zdct.mat`. The `dct->m_y_basis`
> and `dct->m_z_basis` fields exist
> ([`include/dct.h:48-50`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/dct.h#L48-L50))
> and would have been the correct sources.
>
> The actual registration uses the correct
> in-memory matrices (the fields are populated by
> `DCTalloc`); only the diagnostic dump files are
> mislabelled. Anyone reading the dumped `.mat`
> files for debugging will see three identical
> X-basis matrices.

## Affected Artefacts

- **Tool:** [[mri_dct_align]] (`mri_dct_align.cpp`)
  on the diagnostic dump path.
- **Pipeline stage(s):** none in default `recon-all`.
- **Triggering configuration:** any
  `mri_dct_align` run that allocates a fresh DCT —
  the dump fires unconditionally inside
  `find_optimal_dct`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
static DCT *
find_optimal_dct(DCT *dct, MRI *mri_source, MRI *mri_target, int ncoef, int skip)
{
  Gmri_source = mri_source ; Gmri_target = mri_target ;
  if (dct == NULL)
  {
    dct = DCTalloc(ncoef, mri_source) ;
    MatrixWrite(dct->m_x_basis, "xdct.mat", "xdct") ;     /* :589 */
    MatrixWrite(dct->m_x_basis, "ydct.mat", "ydct") ;     /* :590 — should be m_y_basis */
    MatrixWrite(dct->m_x_basis, "zdct.mat", "zdct") ;     /* :591 — should be m_z_basis */
    //    write_snapshot(dct, mri_source, mri_target, "test.mgz") ;
  }
  return(dct) ;
}
```

## Root Cause

Copy-paste typo. The three lines are visually
parallel, and the source matrix wasn't updated when
the lines were duplicated.

## Impact

- **Functional:** none — the actual registration
  uses the correct in-memory matrices populated by
  `DCTalloc`. Only the diagnostic dump files
  written next to the working directory are
  mislabelled.
- **Debugging:** reading `ydct.mat` or `zdct.mat`
  to inspect the Y/Z basis will surface the X
  basis instead, potentially confusing a developer
  diagnosing an alignment issue.
- **Severity:** low.

through the dumped `.mat` files.
