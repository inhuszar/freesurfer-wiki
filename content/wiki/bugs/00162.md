# [severity-3] [bug-00162] rbbr — --rh-only handler is a copy of --lh-only, so it registers the LEFT hemisphere

> [!bug] Synopsis
> In `scripts/rbbr`, the command-line handler for `--rh-only` is a verbatim
> copy of the handler for `--lh-only`: it sets `LHOnly = 1; RHOnly = 0;`
> instead of `LHOnly = 0; RHOnly = 1;`. Because `RHOnly` never becomes 1,
> passing `--rh-only` causes `rbbr` to forward `--lh-only` (not `--rh-only`)
> to every `bbregister` call. The user asks to restrict the registration to
> the **right** hemisphere and silently gets the **left** hemisphere instead.

## Affected Artefacts

- **Tool(s):** [[rbbr]] — robust wrapper around `bbregister`.
- **Pipeline stage(s):** _N/A_ — `rbbr` is a standalone registration helper;
  it is not invoked on the default
  [[wiki/pipelines/recon-all|recon-all]] path.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — pure tcsh control flow.
- **Triggering configuration:** any invocation that includes `--rh-only`.
  The defect fires every time that flag is used.

## Detailed Description

`rbbr` exposes `--lh-only` and `--rh-only` to restrict the boundary-based
registration to a single hemisphere. These two flags drive two mutually
exclusive boolean variables, `LHOnly` and `RHOnly` (both initialised to 0 at
[`scripts/rbbr:29-30`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L29-L30)).
Downstream, the script appends the matching `bbregister` flag based on which
variable is set, at two sites: the initial-registration call
([`scripts/rbbr:115-116`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L115-L116))
and the per-iteration BBR call
([`scripts/rbbr:191-192`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L191-L192)):

```tcsh
if($LHOnly) set cmd = ($cmd --lh-only)
if($RHOnly) set cmd = ($cmd --rh-only)
```

The intent is clear: `--lh-only` should set `LHOnly`, and `--rh-only` should
set `RHOnly`. But the `--rh-only` case body was copy-pasted from `--lh-only`
and never edited, so it assigns the left-hemisphere variables.

### Expected Behaviour

`rbbr --rh-only ...` should set `RHOnly = 1` (and `LHOnly = 0`), causing the
script to pass `--rh-only` to `bbregister` and restrict the registration to
the right hemisphere.

### Observed Behaviour

`rbbr --rh-only ...` sets `LHOnly = 1; RHOnly = 0;`. The two `if` guards then
add `--lh-only` to the `bbregister` command line. The registration is
restricted to the **left** hemisphere — the opposite of what was requested.
`RHOnly` is dead: no code path can ever set it to 1, so `--rh-only` is never
forwarded to `bbregister` from anywhere in `rbbr`. There is no warning or
error; the run completes normally with the wrong hemisphere.

### Reproducer

```bash
# Isolated demonstration of the parser defect (verbatim case bodies from rbbr):
cat > /tmp/repro.csh <<'CSH'
#!/bin/tcsh -f
set LHOnly = 0
set RHOnly = 0
set flag = "--rh-only"
switch($flag)
  case "--lh-only":
    set LHOnly = 1;
    set RHOnly = 0;
    breaksw
  case "--rh-only":
    set LHOnly = 1;
    set RHOnly = 0;
    breaksw
endsw
echo "LHOnly=$LHOnly RHOnly=$RHOnly"
CSH
tcsh -f /tmp/repro.csh
# prints: LHOnly=1 RHOnly=0   (--rh-only set the LEFT-hemi variables)
```

A full end-to-end run (`rbbr --s <subj> --mov bold.nii.gz --t2 --init-reg
init.dat --rh-only --reg out.dat`) would echo the constructed `bbregister`
command into the log file, where the `--lh-only` flag would be visible on the
line written by
[`scripts/rbbr:120`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L120)
/ [`scripts/rbbr:196`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L196).

## Code Reference (Unambiguous)

- **File:** `scripts/rbbr`
- **Function:** `parse_args` (tcsh `switch` on `$flag`)
- **Lines:** `384-392` (the two case bodies)
- **Commit:** `d932c45`

```tcsh
    case "--lh-only":
      set LHOnly = 1;
      set RHOnly = 0;
      breaksw

    case "--rh-only":
      set LHOnly = 1;
      set RHOnly = 0;
      breaksw
```

The two case bodies are byte-for-byte identical
([`scripts/rbbr:384-387`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L384-L387)
and
[`scripts/rbbr:389-392`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L389-L392)),
which is the signature of an un-edited copy-paste. Compare with the
consumer sites at
[`scripts/rbbr:116`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L116)
and
[`scripts/rbbr:192`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L192),
which correctly distinguish `LHOnly` from `RHOnly`.

## Root Cause

Copy-paste error. The `--rh-only` case was duplicated from `--lh-only` and
the variable assignments were not swapped. The correct body should set
`LHOnly = 0; RHOnly = 1;`.

## Impact

- A user who passes `--rh-only` to restrict registration to the right
  hemisphere silently gets a left-hemisphere registration. The output
  registration (`--reg` / `--lta`) is computed from the wrong cortical
  surface, producing a subtly or grossly wrong transform depending on how
  asymmetric the subject's anatomy is.
- The defect is **silent**: no error, no warning. The only trace is the
  `--lh-only` token in the logged `bbregister` command line, which a user
  would have to notice.
- Severity is **3 (medium)**, not 4: the defect is gated behind a specific
  opt-in flag (`--rh-only`). The default `rbbr` path (both hemispheres) is
  unaffected, and `rbbr` is a standalone auxiliary tool, not part of a
  default user-facing pipeline. It does not reach
  [[wiki/pipelines/recon-all|recon-all]].

## Recommended Fix

Swap the two assignments in the `--rh-only` case so it sets the
right-hemisphere variables:

```diff
     case "--rh-only":
-      set LHOnly = 1;
-      set RHOnly = 0;
+      set LHOnly = 0;
+      set RHOnly = 1;
       breaksw
```

After the change, `--rh-only` sets `RHOnly = 1`, the guard at
[`scripts/rbbr:116`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L116)
and
[`scripts/rbbr:192`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/rbbr#L192)
fires, and `--rh-only` is forwarded to `bbregister`.

### Alternative Fixes Considered

None needed; the two-line swap is unambiguous and matches the existing
`--lh-only` pattern and the consumer logic.

## Workarounds (If Any)

There is no way to restrict `rbbr` to the right hemisphere with the current
code. As a workaround, a user can run `bbregister` directly with `--rh-only`
(forgoing the `rbbr` robustness loop), or patch the one-line case body
locally.
