# [severity-4] [bug-00046] `fMRItemporalAR1`: zero-variance guard misses a `continue` — every zero-variance voxel still divides by zero, writing NaN/Inf into `tar1.mgh`

> [!bug] Synopsis
> `fMRItemporalAR1`
> ([`utils/fmriutils.cpp:193-229`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fmriutils.cpp#L193-L229))
> divides voxelwise temporal covariance by voxelwise
> temporal variance to compute the AR(1) coefficient. The
> body explicitly guards against `voxvar == 0`:
>
> ```cpp
> voxvar = MRIFseq_vox(var, c, r, s, 0);
> if (voxvar == 0) MRIFseq_vox(ar1, c, r, s, 0) = 0;     // intent: handle zero variance
> voxcovar = MRIFseq_vox(covar, c, r, s, 0);
> MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;       // ALWAYS executes, even when voxvar==0
> ```
>
> The `if (voxvar == 0)` clause is missing a `continue;`
> (or an `else`). The very next statement at line 223
> *unconditionally* divides `voxcovar` by `voxvar` and
> overwrites the freshly-zeroed `ar1` slot with the
> result of `voxcovar / 0`. For mask voxels (the only ones
> that reach the body — line 215 already `continue`s on
> non-mask voxels) where the residual time-series is flat
> (e.g. dropout, constant artefact, or a frame mask that
> leaves only one frame after weighting), the published
> output `tar1.mgh` carries `NaN` or `±Inf` instead of
> the intended `0`. When `mask == NULL` (the case in
> [`mri_concat.cpp:546`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_concat/mri_concat.cpp#L546)),
> *every* zero-variance voxel — typically the entire
> background outside the brain — receives NaN/Inf, which
> then poisons any downstream summary that ingests
> `tar1.mgh` (mean, histogram, fwhm, registration cost,
> …).

## Detailed Description

### Expected Behaviour

The temporal AR(1) coefficient at a voxel is
`AR1 = E[(x[t] - μ)(x[t+1] - μ)] / Var[x]`. When
`Var[x] == 0` (the time-series is flat), AR1 is not
defined; the de-facto FreeSurfer convention — visible
from the explicit `if (voxvar == 0)` guard — is to set
those voxels to `0` and skip the division.

### Observed Behaviour

[`utils/fmriutils.cpp:211-226`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fmriutils.cpp#L211-L226):

```cpp
for (c = 0; c < fmri->width; c++) {
    for (r = 0; r < fmri->height; r++) {
      for (s = 0; s < fmri->depth; s++) {
        if (mask) {
          if (MRIgetVoxVal(mask, c, r, s, 0) < 0.5) {
            MRIFseq_vox(ar1, c, r, s, 0) = 0;
            continue;                                       /* (a) correct: continue on mask-out */
          }
        }
        voxvar = MRIFseq_vox(var, c, r, s, 0);
        if (voxvar == 0) MRIFseq_vox(ar1, c, r, s, 0) = 0;  /* (b) intended guard, no continue */
        voxcovar = MRIFseq_vox(covar, c, r, s, 0);
        MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;   /* (c) always runs; overwrites (b) */
      }
    }
  }
```

Block (a) — the mask check — has a proper `continue`.
Block (b) — the zero-variance guard — does **not**, and
is followed unconditionally by block (c). The semantic
of (b) ("if `voxvar == 0`, write 0 and stop") is
silently dropped. The output is whatever
`voxcovar / 0` produces in IEEE 754:

- `voxcovar > 0` → `+Inf`,
- `voxcovar < 0` → `−Inf`,
- `voxcovar == 0` → `NaN` (`0/0`).

In a typical fMRI residual volume:
- the background outside the brain has zero variance
  (or near-zero — stricter `voxvar == 0` is the only
  trigger for the buggy guard, but `voxvar < FLT_EPSILON`
  voxels also produce massively-amplified random
  values); these voxels were *meant* to be zeroed,
- mask voxels rarely have exactly zero variance, but a
  frame-mask configuration that leaves a single
  surviving frame, or a dropout voxel inside the brain,
  will trip the guard exactly as designed —
  except the guard is broken.

Compare with the sister function `fMRIcomputeT`
([`utils/fmriutils.cpp:332-337`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fmriutils.cpp#L332-L337))
which gets the structure right:

```cpp
std = sqrt(MRIgetVoxVal(var, c, r, s, 0));
if (std == 0)
  MRIFseq_vox(t, c, r, s, 0) = 0;
else {
  cesval = MRIgetVoxVal(ces, c, r, s, 0);
  MRIFseq_vox(t, c, r, s, 0) = cesval / (srf * std);
}
```

The `else` is the mechanical fix for the AR1 site.

### Reproducer

```bash

```

## Root Cause

A control-flow defect introduced when the
zero-variance guard was bolted on as a single line. The
author wrote `if (voxvar == 0) MRIFseq_vox(ar1, …) = 0;`
in place of an `if/else` block but did not add the
`continue;` (or `else { … }`) needed to actually skip
the division. The sister function `fMRIcomputeT`
illustrates the intended pattern.

## Impact

- **`tar1.mgh` (and `tar1.nii.gz` etc.):** voxels with
  exactly-zero temporal variance — overwhelmingly the
  background outside the brain when `mask == NULL` (as
  `mri_concat --tar1` does), and any flat-line dropout
  voxel inside the brain — receive `NaN`, `+Inf`, or
  `-Inf` instead of the intended `0`.
- **Downstream consumers:** any summary built from
  `tar1.mgh` that does not strip NaN/Inf is corrupted.
  Examples: `mri_concat tar1.mgh --mean`, histogram of
  `tar1.mgh`, FWHM-of-AR1 metrics, registration cost
  surfaces that ingest the residual AR(1) map.
- **`--qa` reports:** `mri_glmfit --qa` enables `--tar1`
  ([`mri_glmfit.cpp:2738-2741`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L2738-L2741)).
  QA scripts that ingest `tar1.mgh` and compute brain-wise
  summaries (mean, max) without an `isfinite` filter will
  see NaN/Inf-driven readouts.
- **Severity:** medium. The bug is opt-in (no default
  `recon-all` invocation runs `--tar1`) but the
  user-facing artefact is published with a documented
  filename and is consumed by analysis pipelines. The
  guard's *intent* is captured in code, just not its
  semantics.

## Recommended Fix

```diff
--- a/utils/fmriutils.cpp
+++ b/utils/fmriutils.cpp
@@ -218,9 +218,12 @@ MRI *fMRItemporalAR1(MRI *fmri, float DOFAdjust, MRI *mask, MRI *ar1)
           }
         }
         voxvar = MRIFseq_vox(var, c, r, s, 0);
-        if (voxvar == 0) MRIFseq_vox(ar1, c, r, s, 0) = 0;
-        voxcovar = MRIFseq_vox(covar, c, r, s, 0);
-        MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;
+        if (voxvar == 0) {
+          MRIFseq_vox(ar1, c, r, s, 0) = 0;
+        } else {
+          voxcovar = MRIFseq_vox(covar, c, r, s, 0);
+          MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;
+        }
       }
     }
   }
```

The `if/else` pattern matches `fMRIcomputeT` and makes
the zero-variance branch actually short-circuit the
division.

### Alternative Fixes Considered

- **`if (voxvar == 0) { ar1 = 0; continue; }`** — also
  correct, slightly less symmetric with the sister
  function.
- **Use `FZERO(voxvar)` instead of `voxvar == 0`** —
  catches near-zero variances that produce huge but
  finite spurious values. Worth a separate change but not
  necessary to fix the immediate NaN/Inf defect.

## Workarounds (If Any)

- Strip non-finite values from `tar1.mgh` before
  downstream summary:
  ```bash
  fscalc tar1.mgh masked-replace -inf 0 inf 0 nan 0 \
      --o tar1.cleaned.mgh
  ```
  (Or apply a brain mask.)
- Always pass an explicit `--mask` to `mri_glmfit
  --tar1` so non-brain voxels never reach the buggy
  branch.

## Provenance and Discovery

- **Discovered:** 2026-04-30 by agent (high-severity
  audit; identified by grepping for the pattern
  `if (X == 0) <single-line>` on subsequent unconditional
  use of `X` as a divisor).
- **Evidence:** `fMRItemporalAR1` body at `:221` reads
  the documented "if zero, write 0" guard but is
  immediately followed by an unconditional `voxcovar /
  voxvar` at `:223`. The sister `fMRIcomputeT` at
  `:332-337` shows the correct `if/else` pattern, which
  rules out "intended fall-through" as a benign reading.
