# [severity-2] [bug-00146] Unconditional debug `MRIwrite("t.mgz")` calls in `mri_convert`, `mri_dct_align`, and `mri_hires_register` pollute the user's current working directory on every invocation

> [!bug] Synopsis
> Five tools contain unconditional `MRIwrite(..., "t.mgz")` calls — left over from development debugging and never guarded by `Gdiag & DIAG_WRITE`. On every invocation that reaches the surrounding code, the program writes a multi-MB intermediate volume named `t.mgz` to the current working directory.
>
> ```cpp
> /* mri_convert/mri_convert.cpp:3277 (inverse-morph branch) */
> printf("morphing from atlas with resample type %d\n", resample_type_val);
> mri_transformed = GCAMmorphFromAtlas(mri, gcam, mri_transformed, resample_type_val);
> MRIwrite(mri_transformed, "t.mgz");           /* :3277 — unconditional */
>
> /* mri_dct_align/mri_dct_align.cpp:179 */
> MRIwrite(mri_target, "t.mgz");                /* unconditional */
>
> /* mri_dct_align/mri_dct_align_binary.cpp:304 */
> MRIwrite(mri_target, "t.mgz");                /* unconditional */
>
> /* mri_hires_register/mri_linear_align.cpp:221 */
> MRIwrite(mri_target, "t.mgz");                /* unconditional */
>
> /* mri_hires_register/mri_nl_align.cpp:281 */
> MRIwrite(mri_tmp, "t.mgz");                   /* unconditional */
> ```
>
> Compare with the project convention for diagnostic outputs (used elsewhere in each of these files):
>
> ```cpp
> if (Gdiag & DIAG_WRITE && DIAG_VERBOSE_ON) {
>   MRIwrite(mri_dst, "dc.mgz");
> }
> ```
>
> The `Gdiag` flag is set only by `-v` / `--debug` style options. Every other intermediate-volume write in these files is properly gated. The five `"t.mgz"` writes are not.

## Affected Artefacts

- **Tool(s):** [[mri_convert]], [[mri_dct_align]], [[mri_hires_register]]
- **Pipeline stage(s):** _not on default `recon-all`_, but:
  - `mri_convert --apply_inverse_morph` / `-ait` is used by hippocampal-subfield and exvivo workflows to apply inverse m3z transforms.
  - `mri_dct_align` and `mri_dct_align_binary` are alignment helpers used by hires registration scripts.
  - `mri_hires_register` is the high-resolution registration tool used by hippo-subfield pipelines.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`; earliest known: _unknown_.
- **Platforms:** all.
- **Triggering configuration:** every invocation that reaches the surrounding code path. For `mri_convert`, this is `--apply_inverse_morph` / `-ait` with an m3z transform. For `mri_dct_align`, `mri_dct_align_binary`, `mri_hires_register`, this is the default code path.

## Detailed Description

These are classic "leftover from debugging" writes — the developer added `MRIwrite(intermediate, "t.mgz")` to dump a working volume, then forgot to remove or guard it before committing. The five sites all use the same basename `"t.mgz"`, suggesting one developer adopted a personal convention.

### Expected Behaviour

Intermediate / diagnostic volumes should be written **only** when the user explicitly opts in via a debug flag, and the filename should be either user-controllable or namespaced (e.g., into a debug directory). The convention used elsewhere in each of these files is `if (Gdiag & DIAG_WRITE && DIAG_VERBOSE_ON) MRIwrite(...)`.

### Observed Behaviour

On every invocation that reaches the code path, a file named `t.mgz` is created in the user's current working directory. If the user already has a file named `t.mgz` (working file, prior debug output, intermediate from another tool), it is overwritten without warning.

### Reproducer

```bash
# (mri_convert): apply any inverse m3z transform
mri_convert --apply_inverse_morph some.m3z input.mgz output.mgz
ls -la t.mgz
#   -rw-r--r-- 1 user user 17829942 May 23 10:00 t.mgz   ← stray file

# (mri_hires_register): default invocation
mri_hires_register source.mgz target.mgz out.lta
ls -la t.mgz
#   -rw-r--r-- 1 user user 17829942 May 23 10:00 t.mgz   ← stray file

# (mri_dct_align): default invocation
mri_dct_align source.mgz target.mgz out.lta
ls -la t.mgz
#   -rw-r--r-- 1 user user 17829942 May 23 10:00 t.mgz   ← stray file
```

If the user's CWD is read-only:

```bash
cd /readonly/path
mri_hires_register source.mgz target.mgz out.lta
# ... MRIwrite fails with "permission denied" — and depending on the
# tool's error handling, may either crash, exit non-zero, or print a
# warning and continue.
```

> [!gap] Live reproducer not executed
> The static read is unambiguous: each cited line is at the indentation level of the surrounding code path with no `if (Gdiag...)` guard. A trivial `strace`-based check would confirm the file is created.

## Root Cause

Five separate development-time debug writes left in the source tree without `Gdiag` guards. Each is at the indentation of the surrounding code, not bracketed by any `if`. The same basename `"t.mgz"` across all five sites suggests they were added by the same developer using a personal convention.

## Impact

- **Stray file in CWD.** Every invocation that reaches the code path creates a multi-MB `t.mgz` file in `$PWD`. For a typical conformed volume that's ~17 MB; for hi-res it can be hundreds of MB.
- **Silently overwrites a user's `t.mgz`.** Any user who has a file named `t.mgz` (working file, prior tool output, scratch) sees it clobbered. Real risk in busy directories.
- **Read-only CWD failure mode.** If `$PWD` is read-only (containerised pipelines, network-mounted read-only paths, `sudo`-d test runs), the `MRIwrite` may either fail silently (most error paths just print and continue) or cause the tool to exit non-zero, breaking pipelines for no functional reason.
- **CI / test-suite breakage.** Test fixtures that diff CWD contents will flag the stray file. Reproducibility tests that hash directory state see the file appear/disappear depending on whether the tool ran.
- **No `recon-all` impact** because the affected tools are not on the default `recon-all` path, but hippo-subfield, exvivo, and hi-res registration pipelines do invoke them.

## Recommended Fix

Either delete each line, or guard it with the project convention. Recommend guarding rather than deleting to preserve the debug capability for future developers — but with a directory-aware filename so the file doesn't land in `$PWD`.

```diff
   mri_transformed = GCAMmorphFromAtlas(mri, gcam, mri_transformed, resample_type_val);
-  MRIwrite(mri_transformed, "t.mgz") ;
+  if (Gdiag & DIAG_WRITE && DIAG_VERBOSE_ON) {
+    MRIwrite(mri_transformed, "t.mgz") ;
+  }
```

Repeat for all five sites. If the project has a convention for diagnostic-output directories (e.g., `$SUBJECTS_DIR/tmp/`), prefer that over a CWD-relative basename.

## Workarounds (If Any)

- **Run from a scratch directory** (e.g., `cd /tmp/scratch && mri_convert …`) so the stray `t.mgz` lands somewhere disposable and doesn't overwrite a user file.
- **`rm -f t.mgz`** after every invocation. Annoying but effective.
- **Don't use these tools from a read-only CWD.** For containerised pipelines, `cd /tmp` before invoking.
