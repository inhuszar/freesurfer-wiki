# [severity-2] [bug-00085] `MRIgetEqualizeHisto` writes bin centres to the wrong histogram

> [!bug] Synopsis
> Inside the equalisation loop, the line that
> initialises bin centres targets the **source**
> histogram (which is about to be freed) instead
> of the **destination**:
>
> ```cpp
> /* utils/mrihisto.cpp:585-592 */
> for (total = 0, i = low; i <= high; i++) {
>   total += histo->counts[i];
>   if (norm)
>     histo_eq->counts[i] = nint(255.0f * (float)total / (float)total_pix);
>   else
>     histo_eq->counts[i] = total;
>   histo->bins[i] = i;                             /* :591 — wrong target */
> }
> ```
>
> The two surrounding loops both write to
> `histo_eq->bins[i] = i;`
> ([`:582`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrihisto.cpp#L582),
> [`:595`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrihisto.cpp#L595));
> the middle loop writes to `histo->bins[i]`. The
> source histogram `histo` is freed two lines
> after the loops
> ([`:599`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrihisto.cpp#L599)),
> so the corruption never escapes — but
> `histo_eq->bins[low..high]` is never written and
> remains at calloc-initialised `0.0` instead of
> the bin-index `i` the surrounding code clearly
> intended.

## Affected Artefacts

- **Tool:** none currently observable. Callers
  reachable in v$FREESURFER_VERSION:
  - [[mri_ca_label]] (default `recon-all`,
    [`mri_ca_label/mri_ca_label.cpp:793`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_ca_label/mri_ca_label.cpp#L793))
  - [[mri_ca_train]]
  - [[mri_nlfilter]]
  - `mrinorm.cpp` (`MRIhistogramNormalize` /
    `MRInormalize`)
  All read `histo_eq->counts` and not
  `histo_eq->bins[low..high]`, so the defect is
  latent.
- **Pipeline stage(s):** none affected today.
- **Triggering configuration:** any future
  caller that consumes `histo_eq->bins[i]` for
  `low <= i <= high` would observe `0` instead
  of `i`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mrihisto.cpp:568-601 */
HISTOGRAM *MRIgetEqualizeHisto(MRI *mri, HISTOGRAM *histo_eq, int low, int high, int norm)
{
  int i, total, total_pix;
  HISTOGRAM *histo;

  histo = MRIhistogram(mri, 0);                          /* :573 — local */
  if (!histo_eq) histo_eq = HISTOalloc(histo->nbins);    /* :574 — caller's dest */
  ...
  for (i = 0; i < low; i++) {
    histo_eq->counts[i] = 0;
    histo_eq->bins[i]   = i;                             /* :582 — correct target */
  }

  for (total = 0, i = low; i <= high; i++) {
    total += histo->counts[i];
    if (norm)
      histo_eq->counts[i] = nint(255.0f * (float)total / (float)total_pix);
    else
      histo_eq->counts[i] = total;
    histo->bins[i] = i;                                  /* :591 — wrong target */
  }
  for (i = high + 1; i < histo->nbins; i++) {
    histo_eq->counts[i] = histo_eq->counts[high] + i;
    histo_eq->bins[i]   = i;                             /* :595 — correct target */
  }

  histo_eq->nbins = histo->nbins;
  HISTOfree(&histo);                                     /* :599 — corruption discarded */
  return (histo_eq);
}
```

`histo` (allocated via `MRIhistogram` at `:573`)
goes out of scope at `:599`. The intermediate
write at `:591` therefore has no externally
visible effect — but neither does it accomplish
its purpose. `HISTOalloc` calloc-allocates the
`bins` array
([`utils/histo.cpp:124`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/histo.cpp#L124)),
so `histo_eq->bins[low..high]` returns to the
caller as a region of zeros bordered by
correctly-indexed bin centres on either side.

## Root Cause

Copy-paste / typo. The author wrote three
parallel index-assignment blocks (for
`i < low`, `low <= i <= high`, `high < i <
nbins`); the first and third correctly target
`histo_eq->bins[i]`, the middle one was typed
`histo->bins[i]`. Once typed, the middle write
is silent (the target is freed) and would only
surface when a caller starts reading bin centres
from the equalised histogram.

## Impact

- **Today:** none. No in-tree caller reads
  `histo_eq->bins` from a `MRIgetEqualizeHisto`
  return.
- **Future:** any code that adds a `bins`-aware
  consumer (e.g., a histogram plotter that
  expects bin centres on the X axis, or a
  composer that interpolates by bin centre)
  would silently see zeros for the equalised
  range. Plots would have a flat-zero spike at
  the X axis between `low` and `high`;
  composers would map every input value in
  that range to bin 0.
- **Severity:** 2 (latent under typical
  conditions; current callers happen not to
  read the corrupted field).

Single-character fix.

## Workarounds

Callers that need correct bin centres on
`histo_eq->bins[low..high]` should write them
themselves after the call until the patch
lands.
