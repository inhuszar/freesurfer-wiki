# [severity-4] [bug-00193] `mri_edit_wm_with_aseg` — fourth MTL diagonal-fill block fills `(x−1, y+1, z)` instead of `(x+1, y+1, z)`

> [!bug] Synopsis
> In [[mri_edit_wm_with_aseg]]'s medial-temporal-lobe "spackle" loop, four
> sibling blocks each detect a non-white-matter diagonal neighbour of a
> hippocampus / amygdala / inferior-lateral-ventricle voxel that sits over
> inferior WM, and fill the brighter of `{current voxel, that diagonal
> neighbour}` to break a diagonal-only WM connection. The fourth block
> tests the neighbour `(x+1, y+1, z)`, but its `else` branch writes to
> `(x−1, y+1, z)` — a verbatim copy of the third block that was never
> updated. As a result the intended `+x` diagonal break is **not** made,
> and a spurious WM voxel is deposited on the opposite (`−x`) side. The bug
> fires unconditionally on the default [[wiki/pipelines/recon-all|recon-all]]
> WM-editing stage (`mri_edit_wm_with_aseg … wm.seg.mgz brain.mgz
> aseg.presurf.mgz wm.asegedit.mgz`), so the corrupted voxels propagate
> through `wm.asegedit.mgz` → [[mri_pretess]] → `wm.mgz` → white-surface
> placement near the hippocampus and amygdala.

## Affected Artefacts

- **Tool(s):** [[mri_edit_wm_with_aseg]]
- **Pipeline stage(s):** `autorecon2` WM editing (default, gated by `$UseAseg`,
  which is on by default) — [`scripts/recon-all:3356-3362`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/scripts/recon-all#L3356-L3362)
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`; introduced
  2006-12-29 (commit `426a336eeed`), the `else` body has never been corrected.
- **Platforms:** all
- **Triggering configuration:** always-on. `edit_segmentation()` is called
  unconditionally from `main()`; the enclosing anatomical guards
  (hippocampus / amygdala / inf-lat-vent at the inferior WM border) are
  ordinary medial-temporal anatomy present in every brain. No flag gates it.

## Detailed Description

`edit_segmentation()` contains a "more spackling" pass over the medial
temporal lobe. For each non-WM voxel `(x, y, z)` whose `aseg` label is
`Left/Right_Inf_Lat_Vent`, `Left/Right_Hippocampus`, or
`Left/Right_Amygdala`, and which passes a series of anatomical guards
(WM directly inferior, not on top of thick WM, close to cortex/unknown
below, no WM close above, not on the medial edge of hippocampus, …), the
code fills WM to break diagonal-only connections to the inferior white
matter. It does this with **four sibling blocks**, one per diagonal
neighbour in the `y+1` (inferior) plane:

| Block | Neighbour tested (`if` condition) | T1 comparison neighbour | `else` fill target |
|-------|-----------------------------------|-------------------------|--------------------|
| 1 (`:1278`) | `(x,   y+1, z−1)` | `(x,   y+1, z−1)` | `(x,   y+1, z−1)` ✔ |
| 2 (`:1299`) | `(x,   y+1, z+1)` | `(x,   y+1, z+1)` | `(x,   y+1, z+1)` ✔ |
| 3 (`:1320`) | `(x−1, y+1, z)`   | `(x−1, y+1, z)`   | `(x−1, y+1, z)`   ✔ |
| 4 (`:1341`) | `(x+1, y+1, z)`   | `(x+1, y+1, z)`   | **`(x−1, y+1, z)`** �’ |

In every block the rule is the same: if the diagonal neighbour is not
already WM, fill whichever of `{(x,y,z), neighbour}` is brighter in the
T1 (`brain.mgz`). Blocks 1–3 fill the same voxel they tested. Block 4's
`if` condition and T1 comparison both correctly reference `(x+1, y+1, z)`,
but its `else` branch sets `xi = x−1; yi = y+1`, copied from block 3 and
never updated when block 4 was specialised to the `+x` direction.

### Expected Behaviour

When `(x, y, z)` is **not** brighter than `(x+1, y+1, z)`, block 4 should
fill the tested neighbour `(x+1, y+1, z)` — closing the `+x` diagonal gap
between the MTL voxel and the inferior WM, exactly as blocks 1–3 close
their respective diagonals.

### Observed Behaviour

The `else` branch fills `(x−1, y+1, z)` instead. Two distinct wrong
outcomes follow, both silent (no warning, no crash):

1. **The intended repair is skipped.** `(x+1, y+1, z)` is left non-WM, so
   the `+x` diagonal-only connection this block exists to eliminate
   survives into `wm.asegedit.mgz`. A topology defect that the spackle was
   meant to pre-empt is left for [[mri_pretess]] / topology correction to
   handle (or to perturb the surface).
2. **A spurious WM voxel is added.** `(x−1, y+1, z)` is set to `AUTO_FILL`.
   Block 3 immediately above may have *deliberately* left that voxel
   non-WM (when `(x, y, z)` was the brighter choice it fills `(x, y, z)`,
   not `(x−1, y+1, z)`); block 4 then overrides that decision and forces
   `(x−1, y+1, z)` to WM. When block 3 had already made `(x−1, y+1, z)` WM,
   block 4's write is idempotent; otherwise it injects WM the heuristic
   never intended.

> while the block-4 `if`/T1 lines were corrected to `x+1` in 2011). A
> minimal input that drives a specific voxel through block 4's `else`
> branch and a before/after diff of `wm.asegedit.mgz` has not yet been
> constructed. The triggering geometry is a hippocampus/amygdala/inf-lat-vent
> voxel at the inferior WM border whose `(x+1, y+1, z)` neighbour is
> non-WM and is brighter than the voxel itself in `brain.mgz`.


## Root Cause

Block 4 was created by copy-pasting block 3 and editing the neighbour
direction from `−x` to `+x`. The `if` guard (`:1341`) was updated in the
original 2006 commit, and the T1-intensity comparison (`:1343`) was
corrected to `x+1` in a later 2011 commit (`099093b78c4`), but the
`else`-branch coordinate assignment (`xi = x-1`, `:1350`) was never
changed. The function therefore tests one voxel (`x+1`) and writes a
different one (`x−1`) whenever the current voxel is not the brighter of
the pair. This is an unmodified remnant of the block-3 copy, confirmed by
`git blame`:

```
426a336eeed (2006-12-29) 1341  if (MRIvox(mri_wm, x+1, y+1, z) < MIN_WM_VAL)
099093b78c4 (2011-02-07) 1343    if (MRIvox(mri_T1, x, y, z) > MRIvox(mri_T1, x+1, y+1, z))
426a336eeed (2006-12-29) 1350      xi = x-1 ;    ← never updated to x+1
```

## Impact

- **Output corrupted:** `wm.asegedit.mgz`, the edited white-matter volume,
  is the direct output. The error is silent — no warning, no non-zero exit.
- **Propagation:** `wm.asegedit.mgz` becomes `WM_vol` for the immediately
  following [[mri_pretess]] step
  ([`scripts/recon-all:3367-3371`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/scripts/recon-all#L3367-L3371)),
  producing `wm.mgz`, which drives white-surface tessellation and
  placement. The affected voxels lie at the hippocampus/amygdala WM
  boundary, so the perturbation lands in medial-temporal-lobe surface
  geometry — a region used heavily for morphometry.
- **Bounded magnitude.** Each qualifying voxel mislabels at most one extra
  voxel (and skips one intended fill). It does not corrupt a hemisphere or
  crash. The `−x` write stays in-bounds because the loop bounds `x` to
  `2 … width−3` ([`:1160`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_edit_wm_with_aseg/mri_edit_wm_with_aseg.cpp#L1160)),
  so there is no out-of-bounds access.

> [!note] Severity 4 vs 5 (why this is scored 4)
> The bug straddles the schema's two top tiers. By **reach** it matches the
> severity-5 criterion — it fires silently on the default `recon-all`
> pipeline path that users run end-to-end. By **magnitude** it is far
> milder than a typical severity-5: a handful of single-voxel WM
> perturbations in a localized MTL cleanup heuristic, not a wholesale
> mis-segmentation or a result-invalidating error across the volume.
> Per the schema's tiebreaker ("default to the lowest score that fits;
> when a bug straddles two levels, pick the lower and explain"), it is
> recorded as **4**. A reviewer who weights the medial-temporal
> morphometry exposure more heavily could reasonably argue for 5; the
> systematic-bias-near-hippocampus angle is the strongest case for it.

## Recommended Fix

Change the `else` branch of block 4 to fill the neighbour it actually
tested:

```diff
               else
               {
-                xi = x-1 ;
+                xi = x+1 ;
                 yi = y+1 ;
               }
```

After the fix, block 4 mirrors blocks 1–3: it fills the brighter of
`{(x, y, z), (x+1, y+1, z)}`, closing the `+x` diagonal break as intended.

A regression test should construct a small synthetic `wm`/`brain`/`aseg`
trio that places a hippocampus voxel with a non-WM, brighter
`(x+1, y+1, z)` neighbour over inferior WM, run `mri_edit_wm_with_aseg`,
and assert that `(x+1, y+1, z)` becomes `AUTO_FILL` and `(x−1, y+1, z)` is
left unchanged.

## Workarounds (If Any)

No user-facing workaround avoids the code path — it is unconditional on
the default `recon-all` WM-edit stage. Manual WM edits in FreeView can
correct the resulting surface locally after the fact, but cannot prevent
the mis-fill during the automated run.
