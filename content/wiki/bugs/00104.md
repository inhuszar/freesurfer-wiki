# [severity-3] [bug-00104] `MRIdivide` UCHAR fast-path drops the `p1`/`pdst` advance when divisor is zero

> [!bug] Synopsis
> `MRIdivide`
> ([`utils/mri.cpp:5664-5717`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L5664-L5717))
> has two code paths: a general
> `MRIgetVoxVal`/`MRIsetVoxVal`-based path
> (`:5681-5695`) and an optimised UCHAR/UCHAR/
> UCHAR pointer-walk fast-path (`:5697-5716`).
>
> The fast-path advances three pointers (`p1`,
> `p2`, `pdst`) per voxel using `*pdst++ =
> *p1++ / *p2++`. When the divisor `*p2 == 0`
> the function takes a separate "divide by
> zero" branch, but **only `p2` is advanced**:
>
> ```cpp
> for (x = 0; x < width; x++) {
>   if (!*p2) {
>     *pdst = FZERO(*p1) ? 0 : 255;
>     p2++;                             /* :5707 — only p2 advances */
>   }
>   else {
>     *pdst++ = *p1++ / *p2++;          /* :5710 — all three advance */
>   }
> }
> ```
>
> After a zero-divisor voxel:
>
> - `pdst` still points at the slot just
>   written → next iteration overwrites it.
> - `p1` still points at the same source slot
>   → next iteration reads the wrong dividend.
>
> Every voxel in the row after the first
> zero-divisor is misaligned in the output.

## Detailed Description

```cpp
/* utils/mri.cpp:5697-5716 — UCHAR fast-path */
else /* both UCHAR volumes */
{
  for (z = 0; z < depth; z++) {
    for (y = 0; y < height; y++) {
      p1 = mri1->slices[z][y];
      p2 = mri2->slices[z][y];
      pdst = mri_dst->slices[z][y];
      for (x = 0; x < width; x++) {
        if (!*p2) {
          *pdst = FZERO(*p1) ? 0 : 255;        /* writes pdst[0] */
          p2++;                                /* p1 and pdst NOT advanced */
        }
        else {
          *pdst++ = *p1++ / *p2++;             /* all three advance */
        }
      }
    }
  }
}
```

### Worked example

Consider a row of width 5 with values:

| x          | 0 | 1 | 2 | 3 | 4 |
|------------|---|---|---|---|---|
| `p1[x]`    | 100 | 200 | 50 | 80 | 60 |
| `p2[x]`    | 4 | 0 | 5 | 2 | 0 |

Iteration 0 (`*p2=4`, non-zero): `pdst[0] =
100 / 4 = 25`. p1, p2, pdst advance to x=1.

Iteration 1 (`*p2=0`, zero): `pdst[1] = (FZERO(200)? ...) = 255`. **Only p2** advances to x=2.

Iteration 2 (`*p2=5`, non-zero): reads `*p1`
which still points at p1[1] (`200`); writes
to `*pdst` which still points at pdst[1] (`255`,
just written). Result: `pdst[1] = 200 / 5 =
40`, overwriting the just-written `255`. After
this, p1 advances to x=2, p2 advances to x=3,
pdst advances to x=2.

So after iter 2, the output's pdst[1] holds
40 (which should have been 255 for the
zero-divisor case). And we're now reading p1
at x=2 with p2 at x=3 — misaligned by 1.

Iteration 3 (`*p2 = p2[3] = 2`, non-zero):
`pdst[2] = p1[2] / p2[3] = 50 / 2 = 25`.
Wrong dividend.

Iteration 4 (`*p2 = p2[4] = 0`, zero):
`pdst[3] = (FZERO(p1[3])? ...) = 255`. Only
p2 advances.

End of row. Output row:

| x          | 0  | 1  | 2  | 3   | 4 |
|------------|----|----|----|-----|---|
| `pdst[x]`  | 25 | 40 | 25 | 255 | ? |

Position 4 was never written; it retains
whatever was there before. Position 1 was
overwritten by an aligned-against-wrong-divisor
quotient.

### Comparison with float path

The general path at `:5681-5695` uses
`MRIgetVoxVal(mri1, x, y, z, 0)` and
`MRIsetVoxVal(mri_dst, x, y, z, 0, dst)` —
explicitly indexed, no advancing pointers, so
the divide-by-zero branch handling is
trivially correct.

## Root Cause

When the author wrote the divide-by-zero
short-circuit, they correctly added the
"clamp to 255 or 0" logic but forgot the
matching pointer advances. The pattern
`*pdst++ = *p1++ / *p2++` advances all three
pointers atomically; the special-case branch
needs to do the same explicitly.

## Impact

- **UCHAR/UCHAR/UCHAR path with zero
  divisors:** every output voxel after the
  first zero-divisor in a row is wrong.
  Specifically, the divide-by-zero result is
  overwritten by the next legitimate quotient
  (computed against an off-by-one divisor),
  and the row's last voxel is left
  uninitialised in `pdst`.
- **FLOAT path:** unaffected.
- **Severity:** 3 — flag-gated on UCHAR
  inputs containing any zero divisor; not
  default `recon-all` but reachable in
  `mris_make_surfaces`'s multi-echo path and
  in `mri_volsynth`.

## Recommended Fix

```diff
--- a/utils/mri.cpp
+++ b/utils/mri.cpp
@@ -5703,8 +5703,9 @@ MRI *MRIdivide(MRI *mri1, MRI *mri2, MRI *mri_dst)
         pdst = mri_dst->slices[z][y];
         for (x = 0; x < width; x++) {
           if (!*p2) {
-            *pdst = FZERO(*p1) ? 0 : 255;
-            p2++;
+            *pdst++ = FZERO(*p1) ? 0 : 255;
+            p1++;
+            p2++;
           }
           else {
             *pdst++ = *p1++ / *p2++;
```

The fix advances all three pointers
consistently in the divide-by-zero branch.

## Workarounds

For UCHAR inputs that may contain zero in
the divisor, convert to FLOAT first (e.g.
`MRIchangeType(mri, MRI_FLOAT, 0, 1, 0)`) to
take the safe path.
