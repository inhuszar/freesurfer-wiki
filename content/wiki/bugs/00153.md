# [severity-1] [bug-00153] fsfirst.fsl / longmc — elapsed run-time minutes computed as seconds/50 instead of seconds/60, inflating the logged minute figure by 20%

> [!bug] Synopsis
> Both `fsfirst.fsl` and `longmc` compute the elapsed run time in minutes
> for the end-of-run log summary as `tSecRun / 50` when it should be
> `tSecRun / 60` (there are 60 seconds in a minute). The adjacent hours
> computation in the same block correctly divides by 3600, confirming the
> `/50` is an error, not a unit choice. The reported "Run-Time-Min" line
> is therefore inflated by a factor of 60/50 = 1.2 (a 10-minute run is
> logged as 12 minutes). This is cosmetic, log-only output; no
> computation or scientific result depends on it.

## Affected Artefacts

- **Tool(s):** [[fsfirst.fsl]] (FSL-FIRST subcortical segmentation
  wrapper) and [[longmc]] (longitudinal make-conform helper).
- **Pipeline stage(s):** _N/A_ — affects only the end-of-run timing
  summary printed/tee'd to the log; not part of any computation.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all.
- **Triggering configuration:** always-on — both scripts print the
  timing summary at the end of every run.

## Detailed Description

At the end of each script the elapsed wall-clock seconds
(`tSecRun = tSecEnd - tSecStart`) are converted to minutes and hours for
a human-readable summary:

```tcsh
@ tSecRun = $tSecEnd - $tSecStart;
set tRunMin   = `echo $tSecRun/50|bc -l`      # ← should be /60
set tRunMin   = `printf %5.2f $tRunMin`
set tRunHours = `echo $tSecRun/3600|bc -l`    # correct
set tRunHours = `printf %5.2f $tRunHours`
```

There are 60 seconds in a minute, so minutes = seconds / 60. Dividing by
50 overstates the minute count by 60/50 = 1.2×. The hours line divides by
the correct 3600, so within the same summary the "minutes" and "hours"
figures are mutually inconsistent (`tRunMin` ≠ 60 × `tRunHours`),
which is itself evidence the `/50` is a typo for `/60`.

### Expected Behaviour

`Run-Time-Min` should equal the elapsed seconds divided by 60 (and equal
`Run-Time-Hours × 60`). A 600-second run should log `10.00` minutes.

### Observed Behaviour

`Run-Time-Min` equals elapsed seconds divided by 50. A 600-second run
logs `12.00` minutes (and `0.17` hours, which is correct — so the two
lines disagree).

### Reproducer

```bash
# The exact computation the scripts perform, for a 600 s (10 min) run:
echo "600/50" | bc -l    # -> 12.00000...  (buggy minutes, as logged)
echo "600/60" | bc -l    # -> 10.00000...  (correct minutes)
echo "600/3600" | bc -l  # ->  0.16666...  (hours line, correct)
```

Running either tool to completion and inspecting the
`Fsfirst.Fsl-Run-Time-Min` / `Longmc-Run-Time-Min` log line shows the
inflated value, while the `*-Run-Time-Hours` line on the next row is
correct.

## Root Cause

A typo: `50` written where `60` was meant in the seconds-to-minutes
conversion. The correct divisor is visible one line later in the
seconds-to-hours conversion (`/3600 = /60/60`).

## Impact

- **Cosmetic, log-only.** The only artefact affected is the
  `*-Run-Time-Min` line in the end-of-run summary. No file content, no
  numeric result, and no downstream tool consumes this value.
- A user reading the log sees a run time about 20% longer than the true
  elapsed minutes; the seconds line (`*-Run-Time-Sec`) and the hours line
  (`*-Run-Time-Hours`) are both correct, so the discrepancy is easy to
  cross-check. Rated **trivial (1)** accordingly.

## Recommended Fix

Change the divisor from 50 to 60 in both scripts:

```diff
-set tRunMin = `echo $tSecRun/50|bc -l`
+set tRunMin = `echo $tSecRun/60|bc -l`
```

## Workarounds (If Any)

Read the `*-Run-Time-Sec` (or `*-Run-Time-Hours`) line instead, or
multiply the logged `*-Run-Time-Min` value by 50/60 ≈ 0.833 to recover
true minutes.
