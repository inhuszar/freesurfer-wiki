# [severity-4] [bug-00195] `surf2vol` — the `-aparc` medial-wall exclusion is a no-op with FreeSurfer ≥5 annotations: unlabeled (annotation 0) vertices never get `ripflag`, so the medial wall stays in the boundary-condition set

> [!bug] Synopsis
> [[surf2vol]] (the elastic stage of [[mri_cvs_register]]) is designed to drop
> vertices labelled `unknown` or `corpuscallosum` in the `-aparc` annotation
> from the boundary conditions (BCs) that drive the elastic deformation. The
> exclusion works by looking up the colour-table *indices* of those two
> names and testing each vertex's annotation-derived index against them. In
> the `?h.aparc.annot` files shipped with FreeSurfer 8.2.0 (including the
> default CVS template `cvs_avg35`) the medial wall carries annotation value
> `0`, which is **not an entry in the colour table**: its index is `-1` and
> neither "unknown" (index 0, RGB 25 5 25) nor "corpuscallosum" (index 4) is
> ever matched. No vertex is ripped (`create BC container - ripCounter = 0`),
> so about 6 % of the vertices of every surface — the medial wall, where
> spherical-registration correspondences are not anatomically meaningful —
> are used as BCs on every [[mri_cvs_register]] run.

## Detailed Description

`surf2vol` fits an elastic deformation to point correspondences between the
fixed (template) surfaces and the moving (subject) surfaces that were
resampled onto the template mesh through the spherical registration
(`?h.resample.white` / `?h.resample.pial`). Every non-ripped fixed vertex and
its moving counterpart becomes one boundary condition
([`create_bc_container`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L947-L1006)).
Medial-wall vertices have no cortical anatomy to register on, so their
correspondence comes only from the smooth interpolation of the sphere
registration across the corpus-callosum / thalamic cut. The `-aparc` option
exists to keep these vertices out: `SurfaceMarker` sets `ripflag = 1` on
fixed-surface vertices whose label is in an ignore list, and the BC and mesher
containers skip ripped vertices.

The ignore list is built **by name**: the constructor looks up the colour
table index of `"unknown"` and `"corpuscallosum"`
([`fem_elastic/fsurf2vol.cpp:1544-1546`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1544-L1546),
[`:1575-1582`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1575-L1582)),
and the per-vertex functor converts the vertex annotation to a colour-table
index with `CTABfindAnnotation` and binary-searches the list
([`:1558-1567`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1558-L1567)).
`CTABfindAnnotation` decodes the annotation integer into (r, g, b) and returns
the index of the colour-table entry with exactly that RGB, or `-1` when no
entry matches ([`utils/colortab.cpp:1492-1508`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/colortab.cpp#L1492-L1508),
[`:1611-1632`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/colortab.cpp#L1611-L1632)).

In the aparc annotations used since FreeSurfer 5 the medial wall is simply
**unlabeled**: the raw annotation of those vertices is `0` (RGB 0,0,0), and
the colour table has no entry with RGB (0,0,0). The lookup therefore yields
`-1`, which is not in the ignore list `{0, 4}`. The label names "unknown" and
"corpuscallosum" exist in the colour table but are assigned to **no vertex**
of the shipped annotations, so the ignore list matches nothing at all.

> [!gotcha] The log looks healthy
> `surf2vol` prints `label = unknown -> value = 0`,
> `label = corpuscallosum -> value = 4` and `ignored labels = 0 4` for every
> annotation. Those lines show that the *names* were resolved, not that any
> vertex was excluded. The only run-time symptom is the counter
> `create BC container - ripCounter = 0` ([`fem_elastic/fsurf2vol.cpp:1002`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1002)).

### Expected Behaviour

The medial-wall vertices of the fixed surfaces are flagged (`ripflag = 1`) by
`SurfaceMarker` and skipped by `create_bc_container`
([`fem_elastic/fsurf2vol.cpp:983-987`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L983-L987))
and `create_surf_container`
([`:1039`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1039)).
For `cvs_avg35` that is 8108 of 139336 `lh` vertices and 8391 of 134980 `rh`
vertices per surface, i.e. `ripCounter` should be 8108 (`lh`) / 8391 (`rh`)
for each surface paired with its own hemisphere annotation. The intent is
visible in the comment of the companion affine fit
([`fem_elastic/fsurf2vol.cpp:916`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L916),
"don't use medial or unknown regions in linear fit") and in the label list
itself; the exact developer intent for the elastic stage is inferred, not
documented.

### Observed Behaviour

`ripCounter` is 0 for every surface, so every vertex of every fixed surface —
including all medial-wall vertices — is a BC. With the 8 pinned box corners
the solver reports `Total BCs = 278680` for `lh.white` + `lh.pial`
(2 × 139336 + 8), i.e. nothing was removed.

Colour-table facts, read with `nibabel` from the annotation files shipped in
`$FREESURFER_HOME/subjects`:

| Subject / annotation | Vertices with raw annotation 0 | Vertices with colour-table index 0 (`unknown`) or 4 (`corpuscallosum`) |
|---|---|---|
| `cvs_avg35` `lh.aparc.annot` / `rh.aparc.annot` | 8108 of 139336 / 8391 of 134980 | 0 / 0 |
| `cvs_avg35_inMNI152` `lh` / `rh` | 9012 / 9556 | 0 / 0 |
| `bert` `lh` / `rh` | 9452 / 9447 | 0 / 0 |

In all cases the annotation-0 vertices are exactly the complement of the
corresponding `?h.cortex.label`. For the `-aparc` files given by the default
`mri_cvs_register` call, that is 5.8 % (`lh`) and 6.2 % (`rh`) of the vertices
of each surface; with four surfaces (`lh/rh` white and pial)
(8108 + 8391) × 2 = 32 998 medial-wall BCs participate in every default CVS
run.

> [!gotcha] The exclusion works by coincidence for `aparc.a2009s`
> The Destrieux annotation `?h.aparc.a2009s.annot` has no `corpuscallosum`
> entry (`CTABfindName` returns `-1`, which is pushed into the ignore list),
> and its entry 0 is named `Unknown` with RGB (0,0,0) — the same value that
> an unlabeled vertex decodes to. The medial wall is therefore ripped
> (annotation 0 → index 0 ∈ ignore list), but only because of that colour
> table. For the Desikan–Killiany and DKT tables
> (`unknown` = 25 5 25, `corpuscallosum` = index 4) it never happens.
> (`bert`, 36 entries for `aparc` and `DKTatlas`, 76 for `a2009s`.)

### Reproducer

Fixed = moving = the `cvs_avg35` template, identity cached affine, two FEM
steps; the BC counters are printed before the first FEM step:

```bash

         -fixed_surf   $T/surf/lh.white -moving_surf   $T/surf/lh.white \
         -fixed_surf_2 $T/surf/lh.pial  -moving_surf_2 $T/surf/lh.pial \
         -aparc $T/label/lh.aparc.annot -aparc_2 $T/label/lh.aparc.annot \
         -cache_transform identity.txt -fem_steps 2 -penalty_weight 1000 \
         -topology_old -compress -pc_type jacobi -ksp_type preonly \
         -out out.mgz
```

Observed (installed 8.2.0 binary), abridged:

```

 label = corpuscallosum -> value = 4

 ...

 create BC container - ripCounter = 0
 ...

```

The same `ripCounter = 0` appears with the rigidly shifted and synthetic
sinusoidally deformed moving surfaces used for the other [[surf2vol]]

check the premise independently of `surf2vol`, read the annotation with
`nibabel.freesurfer.read_annot(..., orig_ids=True)` and count the vertices

## Root Cause

`SurfaceMarker` assumes that every vertex to be excluded carries a colour-table
entry named `unknown` or `corpuscallosum`, which is how pre-FreeSurfer-5
annotations marked the medial wall. In current annotations those vertices have
no label at all: annotation value 0, which `CTABfindRGBi` maps to index `-1`
([`utils/colortab.cpp:1629-1631`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/colortab.cpp#L1629-L1631)).
The functor tests only for membership in `{index("unknown"), index("corpuscallosum")}`
and never treats "no colour-table entry" (`ctIndex < 0`) as excludable. The
return codes of `CTABfindAnnotation` and `CTABfindName` are not checked and
`ctIndex` is uninitialised when the call fails.

## Impact

- **Silent:** the output is a valid transform; only the `ripCounter = 0` line
  reveals the problem. No warning, no non-zero exit.
- **Where it matters:** the elastic deformation is the volumetric first stage
  of CVS. About 6 % of the BCs (≈33 000 for the default four-surface call)
  come from the medial wall, where the moving-subject positions are produced
  by spherical-registration interpolation across the corpus callosum and
  thalamic cut. They pull the elastic field in a region that contains no
  cortical features, contradicting the stated purpose of `-aparc`.
- **Magnitude not quantified:** the effect on the final CVS warp has not been
  measured. The later [[mri_nl_align]] stages of [[mri_cvs_register]] refine the
  warp volumetrically and may attenuate it. Note also that, because of
  [[00200]], the elastic solve with the CVS options only moves nodes inside
  elements that contain a BC, so the medial-wall BCs affect the field mainly
  near the midline.
- **Severity 4, not 5:** the defect fires on every [[mri_cvs_register]] run, but
  [[mri_cvs_register]] is not one of the pipelines listed in the severity-5
  criterion (it is reached from [[trac-all]] only for the CVS inter-subject
  space and from [[post-recon-all]] only with `--cvs`), the magnitude is
  unquantified, and the later volumetric stages refine the result.
- **Fixing changes CVS output:** removing ≈33 000 BCs changes every warp the
  stage produces; the fix needs validation against a reference CVS data set
  before release.

## Recommended Fix

Treat "no colour-table entry" as excluded, and keep names absent from the
table out of the ignore list:

```diff
   void operator()(VERTEX* pvtx)
   {
-    int ctIndex;
+    int ctIndex = -1;
     CTABfindAnnotation( m_psurf->ct, pvtx->annotation, &ctIndex );
-    if ( std::binary_search( m_vecAparcIgnored.begin(),
-                             m_vecAparcIgnored.end(),
-                             ctIndex )
-       )
+    if ( ctIndex < 0 ||     // unlabeled (FS >= 5 medial wall)
+         std::binary_search( m_vecAparcIgnored.begin(),
+                             m_vecAparcIgnored.end(),
+                             ctIndex )
+       )
       pvtx->ripflag = 1;
   }
 ...
     CTABfindName( m_psurf->ct, const_cast<char*>(name), &aparcVal );
     std::cout << " label = " << name << " -> value = " << aparcVal << std::endl;
-    m_vecAparcIgnored.push_back(aparcVal);
+    if ( aparcVal >= 0 )   // name absent (e.g. a2009s has no corpuscallosum)
+      m_vecAparcIgnored.push_back(aparcVal);
```

(initialise `aparcVal = -1` in `addLabelToIgnored` likewise). A regression
test is the counter itself: for `cvs_avg35` the call in the Reproducer must
print `ripCounter = 8108` for each `lh` surface (8391 for `rh`) and
`Total BCs = 2 × (139336 − 8108) + 8 = 262 464`.

### Alternative Fixes Considered

- Keep the name-based list but also add the `cortex.label` complement from a
  `?h.cortex.label` argument. More invasive (new option, new file dependency)
  and does not help annotations given without a cortex label.
- Re-label the medial wall as `unknown` in the template's annotation files.
  Works without touching the code but only for that template; any other
  template or user annotation remains affected.

## Workarounds (If Any)

None verified. Untested suggestion derived from the code: supply an annotation
in which the medial-wall vertices carry the `unknown` colour
(25, 5, 25), i.e. annotation value `25 + 5·256 + 25·65536 = 1639705`, so that
`CTABfindAnnotation` returns index 0. `mri_cvs_register` hard-codes
`$tlabel/?h.aparc.annot`
([`mri_cvs_register/mri_cvs_register:400-401`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_cvs_register/mri_cvs_register#L400-L401)),
so this would require editing the template's label files or the script. Calling
`surf2vol` directly with `-aparc none` does not help (it skips the exclusion
altogether).

## Confidence and Gaps

> [!gap] Developer intent and when the annotation format changed
> The purpose (exclude the medial wall) is inferred from the label list and the
> "don't use medial or unknown regions" comment; no document states it for the
> elastic stage. It was not established in which FreeSurfer release the aparc
> medial wall stopped carrying `unknown` / `corpuscallosum` labels, so
> `first_seen_commit` records only the commit that introduced the code.
> Annotations produced by `recon-all` 8.2.0 for individual subjects were not
> inspected; the shipped `cvs_avg35`, `cvs_avg35_inMNI152` and `bert` files
> all show the behaviour.

> [!gap] Effect on the final CVS warp unquantified
> The change in the elastic field, and in the final `.m3z` after the later
> [[mri_nl_align]] steps, when the ≈33 000 medial-wall BCs are removed has not
> been measured.
