# [severity-2] [bug-00152] register_subject_flash / label_subject_flash pass the tissue-parms file to `-flash` (a no-argument boolean) instead of `-flash_parms`, halting option parsing

> [!bug] Synopsis
> `register_subject_flash` and `label_subject_flash` invoke their
> binaries as `mri_em_register -flash <tissue_parms.txt> ...` and
> `mri_ca_label -flash <tissue_parms.txt> ...`. In both binaries `-flash`
> is a **no-argument** boolean (it only sets `map_to_flash = 1`); the
> tissue-parameters filename belongs to the separate `-flash_parms`
> option. Because `-flash` consumes nothing, the next token
> (`tissue_parms.txt`) is left in `argv`; it does not begin with `-`, so
> the `ISOPTION` option loop terminates immediately. Every following flag
> (`-fsamples`, `-norm`) and all positional arguments are then mis-read,
> the GCA/output filenames are mis-assigned, and the FLASH-model
> renormalisation the scripts intend (the tissue-parms file) is never
> wired in. The runs abort on a misread filename rather than producing a
> registration / labelling.

## Affected Artefacts

- **Tool(s):** [[register_subject_flash]] (drives `mri_em_register`) and
  [[label_subject_flash]] (drives `mri_ca_label`).
- **Pipeline stage(s):** _N/A_ — these are standalone legacy FLASH
  (multi-flip-angle) helper scripts, not part of the default
  [[wiki/pipelines/recon-all|recon-all]] chain.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — pure argument-parsing logic.
- **Triggering configuration:** always-on — both scripts unconditionally
  pass the tissue-parms file positionally after `-flash`.

## Detailed Description

Both binaries dispatch options in `main()` with the canonical FreeSurfer
loop

```c
for ( ; argc > 1 && ISOPTION(*argv[1]) ; argc--, argv++)
{
  nargs = get_option(argc, argv) ;
  argc -= nargs ;
  argv += nargs ;
}
```

where `ISOPTION(c)` is `((c) == '-')` (`include/macros.h`). An option
handler signals how many extra tokens it consumed by setting `nargs`.

In `get_option`:

- The `FLASH` handler sets `map_to_flash = 1` and **does not** set
  `nargs` — so `nargs` stays `0` and no argument is consumed. `-flash`
  is a pure boolean.
- The `FLASH_PARMS` handler does `tissue_parms_fname = argv[2]; nargs = 1;`
  — this is the option that actually reads the tissue-parameters file.

The scripts call:

```tcsh
mri_em_register -flash $FREESURFER_HOME/average/tissue_parms.txt -fsamples ... -norm ... <orig> <GCA> <LTA>
mri_ca_label    -flash $FREESURFER_HOME/average/tissue_parms.txt <norm> <talairach.lta> <GCA> <ASEG>
```

After `-flash` consumes nothing, `argv[1]` is `tissue_parms.txt`. That
token does not start with `-`, so `ISOPTION` is false and the option
loop **exits before parsing `-fsamples` / `-norm`**. Control falls to the
positional-argument block, which computes `ninputs = argc-3` and assigns
`gca_fname = argv[ninputs+1]`, `out_fname = argv[ninputs+2]`. Because the
leftover token stream still contains `tissue_parms.txt`, `-fsamples`,
their paths, `-norm`, etc., the input count and the GCA/output filenames
are all shifted. The renormalisation filename (`tissue_parms_fname`) that
`-flash_parms` would have set is never assigned, so the FLASH forward
model has no tissue parameters even though `map_to_flash` is on.

### Expected Behaviour

The scripts intend "use the FLASH forward model, with tissue parameters
from `tissue_parms.txt`." That is expressed as **two** options:
`-flash` (turn the model on) **and** `-flash_parms <file>` (supply the
parameters) — or simply `-flash_parms <file>` alone, since several code
paths key the FLASH model off a non-NULL `tissue_parms_fname`.

### Observed Behaviour

`mri_em_register` (mimicking `register_subject_flash`) prints:

```
using FLASH forward model to predict intensity values...
...
reading 6 input volumes...
reading '/path/to/GCA'...
error: No such file or directory
error: GCAread(...): could not open file
```

`reading 6 input volumes...` is the tell: with the options loop halted at
`tissue_parms.txt`, the parser treated the leftover `tissue_parms.txt`,
`-fsamples`, its path, `-norm`, its path, and `orig` as six "input
volumes" and mis-assigned the GCA path. `mri_ca_label` (mimicking
`label_subject_flash`) likewise prints `using FLASH forward model...`
then `reading 2 input volumes` (consuming `tissue_parms.txt` and the
norm volume as inputs) before failing to read the classifier array from
the mis-assigned path.

### Reproducer

```bash
PARMS=/usr/local/freesurfer/8.2.0/average/tissue_parms.txt

# register_subject_flash's binary call shape:
/usr/local/freesurfer/8.2.0/bin/mri_em_register \
    -flash $PARMS -fsamples /tmp/fs -norm /tmp/norm /tmp/orig /tmp/gca /tmp/out.lta
#   -> "using FLASH forward model..." ; "reading 6 input volumes..." ; GCAread fails

# label_subject_flash's binary call shape:
/usr/local/freesurfer/8.2.0/bin/mri_ca_label \
    -flash $PARMS /tmp/norm /tmp/talairach.m3z /tmp/gca /tmp/aseg.mgz
#   -> "using FLASH forward model..." ; "reading 2 input volumes" ; classifier read fails
```

Both were executed against the installed 8.2.0 binaries. The
`-fsamples` / `-norm` options were silently ignored and the positional
filenames mis-assigned, confirming the option loop halts at the stray
filename. (The FLASH GCA atlases the scripts reference —
`average/mixed.gca`, `average/n7.gca` — are not shipped, so the
end-to-end workflow cannot complete anyway; see Impact.)

## Root Cause

The driver scripts confuse the two FLASH options: `-flash` is the
on/off boolean (`map_to_flash = 1`, no argument), while `-flash_parms` is
the file-taking option (`tissue_parms_fname = argv[2]; nargs = 1`). The
scripts hand the tissue-parameters filename to `-flash`. Since `-flash`
does not advance `nargs`, the filename stays in `argv`, fails the
leading-`-` `ISOPTION` test, and ends the option loop — cascading into a
positional-argument mis-assignment.

## Impact

- **Both FLASH driver scripts are broken on their default (only)
  invocation.** `-fsamples` and `-norm` are silently dropped, the
  positional GCA/output filenames are shifted, and the FLASH tissue
  parameters are never supplied. The binaries crash on a misread file
  rather than registering / labelling.
- **Severity rated low (2), not high.** The rubric would put a
  default-path crash in a standalone tool at 4, but these are
  specialised **legacy** FLASH helpers that are not part of `recon-all`
  and whose required GCA atlases (`$FREESURFER_HOME/average/mixed.gca`
  for register, `.../n7.gca` for label) are **not shipped** in the 8.2.0
  distribution. The workflow therefore cannot run to completion
  regardless of this defect, so the bug is latent for essentially all
  users. It is recorded for cleanup and because the same fix is trivial.

## Recommended Fix

Pass the tissue-parameters file to `-flash_parms` (which both turns on
the FLASH model and stores the filename). The redundant bare `-flash`
may be kept or dropped:

```diff
# scripts/register_subject_flash
-mri_em_register -flash $FREESURFER_HOME/average/tissue_parms.txt -fsamples $sdir/fsamples -norm $sdir/norm $sdir/orig $GCA $sdir/transforms/$LTA
+mri_em_register -flash_parms $FREESURFER_HOME/average/tissue_parms.txt -fsamples $sdir/fsamples -norm $sdir/norm $sdir/orig $GCA $sdir/transforms/$LTA
```

```diff
# scripts/label_subject_flash
-mri_ca_label  -flash $FREESURFER_HOME/average/tissue_parms.txt  $sdir/norm $sdir/transforms/$LTA $GCA $sdir/$ASEG
+mri_ca_label  -flash_parms $FREESURFER_HOME/average/tissue_parms.txt  $sdir/norm $sdir/transforms/$LTA $GCA $sdir/$ASEG
```

### Alternative Fixes Considered

Keep `-flash` and add `-flash_parms <file>` as a separate option
(`... -flash -flash_parms <file> ...`). Functionally equivalent for these
tools, since `-flash_parms` already implies the FLASH model; the
single-flag form above is simpler.

## Workarounds (If Any)

Invoke the binaries directly with the correct option, e.g.
`mri_em_register -flash_parms <tissue_parms> -fsamples ... -norm ... <orig> <GCA> <LTA>`,
rather than through the broken driver scripts — and supply a FLASH GCA
atlas, which is not part of the standard distribution.
