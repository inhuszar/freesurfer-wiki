# [severity-3] [bug-00201] `surf2vol` — the FEM domain (`cmax = 256`) and the `-compress` delta grid (256³) are hard-coded: template volumes larger than 256 voxels lose everything beyond index 255 (zeros in `-out`, invalid GCAM nodes, dropped surface constraints)

> [!bug] Synopsis
> [[surf2vol]] builds its FEM mesh in voxel coordinates of the fixed volume
> with the upper corner hard-coded to `(256, 256, 256)`, and
> `FemTransform3d::convert_to_delta()` (used by `-compress`, which
> [[mri_cvs_register]] always passes) samples the displacement field on a
> hard-coded `256 × 256 × 256` grid. For a fixed (template) volume with more
> than 256 voxels along any axis, e.g. a 0.8 mm, 320³ volume, every voxel with
> an index ≥ 256 is outside the mesh and outside the delta grid: it is
> written as 0 in `-out`, becomes a `GCAM_POSITION_INVALID` node in the
> exported `.m3z`, and fixed-surface constraints beyond 256 are dropped
> (`failed to find elt`). The shipped templates (`cvs_avg35`,
> `cvs_avg35_inMNI152`) are 256³, so the default CVS run is unaffected.

## Affected Artefacts

- **Tool(s):** [[surf2vol]]; [[mri_cvs_register]] when run with a larger template; [[exportGcam]] (consumes the delta morph)
- **Pipeline stage(s):** [[mri_cvs_register]] step 2 (elastic registration) with
  `--template <subject>` where the template's `norm.mgz` has more than 256
  voxels along any axis
- **FreeSurfer version(s):** confirmed in 8.2.0. The 256³ delta grid dates from the
  2008 import (`4b881dc775f`); the fixed `cmax = 256` replaced `cmax + 10` on
  2014-01-30 (`bcd095b9436`, verified with `git blame` / `git show`).
- **Platforms:** all
- **Triggering configuration:** `-compress` (always in [[mri_cvs_register]]) and a
  fixed volume wider than 256 voxels in any dimension. Conformed volumes exceed
  256 voxels when the field of view is large or the voxel size is below 1 mm
  (`MRIfindRightSize`,
  [`utils/mriio.cpp:368-401`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/mriio.cpp#L368-L401):
  256 mm / 0.8 mm = 320).

## Detailed Description

`surf2vol` converts all surfaces to voxel coordinates of the fixed volume
(`convert_surf_to_vox`) and does all FEM work in that space. The mesh
bounding box is derived from the fixed surfaces but the upper corner is not:

```cpp
cmin = max( cmin - tDblCoords(10.0), tDblCoords(0.0) );   // lower corner: bbox - 20 voxels
cmax = tDblCoords(256.0);                                  // upper corner: always 256
```

([`fem_elastic/fsurf2vol.cpp:393-398`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L393-L398);
note the lower corner is padded twice, by 10 at `:393` and again by 10 at `:396`,
i.e. 20 voxels). The box is used for the Delaunay mesh
([`:490`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L490))
and for the pinned corners
([`:507`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L507),
[`:805-817`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L805-L817)).
A boundary-condition point outside the box has no containing element and is
discarded with a message
([`fem_elastic/solver.h:579-584`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/solver.h#L579-L584)).

After every step the FEM transform is converted to a delta (displacement)
volume, which is what `-compress` stores in the `.tm3d` file and what
[[exportGcam]] reads: `convert_to_delta()` allocates a field and a validity
mask of a fixed 256 × 256 × 256 voxels and evaluates the mesh at each of
them ([`fem_elastic/morph.cpp:603-644`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L603-L644)).
The delta transform keeps no information about the grid it was built on.
When the morph is applied, voxels outside that grid sample the mask out of
bounds, which returns the volume's `outside_val` (0), so they are treated as
invalid
([`fem_elastic/morph.cpp:421-430`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L421-L430)).
`VolumeMorph::apply_transforms` loops over the full template volume
([`:795-799`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L795-L799))
and leaves invalid voxels at 0, and `exportGcam` marks them
`GCAM_POSITION_INVALID`
([`:1581-1590`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L1581-L1590)).

> [!note] Not a separate defect: single-hemisphere meshes start at `bbox − 20`
> The lower corner follows the fixed surfaces' bounding box, so a one-hemisphere
> run only covers that hemisphere: for `cvs_avg35` with `lh.white` + `lh.pial`
> the log prints `min = 103.611 25.1985 17.8614`, `max = 256 256 256`, and fixed
> voxels with i < 104 (the other hemisphere) are outside the mesh. This is by
> design for the hemisphere-wise run; it is mentioned because the box is
> asymmetric and the 256 on the upper side is *not* derived from the data.

### Expected Behaviour

The FEM domain and the delta grid cover the whole fixed volume, whatever its
dimensions: `cmax` follows the fixed volume (or the surfaces' bounding box plus
padding, as before 2014) and the delta field has the fixed volume's size.

### Observed Behaviour

Experiment with the installed 8.2.0 `surf2vol`: fixed volume = moving volume =
`cvs_avg35` `norm.mgz` resampled to 0.8 mm (`mri_convert -vs 0.8 0.8 0.8`;
320 × 320 × 320, same `c_ras`), `lh.white` + `lh.pial` as fixed and (identical)
moving surfaces so that the correct morph is the identity, identity cached
affine, `-fem_steps 1 -fem_end_step 0 -elt_vol 10 -penalty_weight 1000
-topology_old -compress -poisson .3 -young 1000 -pc_type jacobi -ksp_type
preonly -out out.mgz -gcam out.m3z`:

- The fixed surfaces extend to voxel index 269.4 in z
  (`direct max = 244.864 199.897 269.394`) but the mesh box is
  `max = 256 256 256`. The log contains 2919 lines
  `TSolver::done_bc_mfc -> failed to find elt for coords ... 256.154` (one per
  dropped constraint, coordinates beyond 256).
- Of the 2 300 534 voxels of the head (voxels with intensity > 0) that lie
  in the lower-corner box of the mesh (`i ≥ 134.5`, `j ≥ 36.5`, `k ≥ 27.3`),
  2 255 606 have all indices below 256: `out.mgz` equals the input there
  exactly (mean absolute difference 0.0). The remaining **44 928** head voxels
  have a z index ≥ 256 and are **all 0** in `out.mgz`. No voxel with an index ≥ 256
  is non-zero in the output.
- In `out.m3z` (exported by the same run) the same 44 928 head voxels are
  `GCAM_POSITION_INVALID` nodes (position 0), and no node with an index ≥ 256
  is valid. The log prints `gcam export invalid voxels = 26698640` (of 32 768 000;
  the count also contains everything outside the one-hemisphere mesh box).
- The run took 47 seconds.

With the same options and the unmodified 256³ `norm.mgz` (the default) the log
contains no `failed to find elt` lines.

### Reproducer

```bash
T=$FREESURFER_HOME/subjects/cvs_avg35
mri_convert $T/mri/norm.mgz norm08.mgz -vs 0.8 0.8 0.8        # 320^3, 0.8 mm

         -fixed_surf   $T/surf/lh.white -moving_surf   $T/surf/lh.white \
         -fixed_surf_2 $T/surf/lh.pial  -moving_surf_2 $T/surf/lh.pial \
         -aparc $T/label/lh.aparc.annot -aparc_2 $T/label/lh.aparc.annot \
         -cache_transform identity.txt -fem_steps 1 -fem_end_step 0 -elt_vol 10 \
         -penalty_weight 1000 -topology_old -compress -poisson .3 -young 1000 \
         -pc_type jacobi -ksp_type preonly -out out.mgz -gcam out.m3z
grep -c "failed to find elt" <log>
# out.mgz == norm08.mgz for all voxels with all indices < 256 inside the mesh box,
# and 0 wherever an index is >= 256 (here: 44 928 head voxels with z >= 256)
```

## Root Cause

Two literals encode the assumption "the fixed volume is 256³": `cmax = 256`
replaced the data-driven `cmax + 10` in 2014 (the line above it is left
commented out, [`fem_elastic/fsurf2vol.cpp:397`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L397)),
and `convert_to_delta()` takes no dimensions and uses `256` for all three axes
since the 2008 import. Neither takes the fixed volume's `width/height/depth`.

## Impact

- **Silent for larger templates:** no error. The outputs (`-out`, `.tm3d`,
  `.m3z`) simply have no valid warp for voxels beyond index 255; in the test
  44 928 head voxels (1.4 % of the head; all at the end of the third voxel axis,
  the anterior end in this `LIA`-oriented volume) were lost.
- **Default path unaffected:** `cvs_avg35` and `cvs_avg35_inMNI152` are 256³;
  [[mri_cvs_register]] accepts any FreeSurfer subject as template
  (`--template`, described in `mri_cvs_register.help.xml`), so a template
  conformed at sub-millimetre resolution or with a large field of view hits the
  limit. Subject volumes
  that are *moving* (not fixed) can be any size: the limit applies to the fixed
  (template) volume.
- **Severity 3:** wrong output gated by a specific input profile (fixed
  volume > 256 along any axis); the default path is unaffected.
- **Interplay:** the invalid nodes are carried into the combined warp that
  [[mri_cvs_register]] feeds to [[mri_nl_align]] and [[mri_concatenate_gcam]];
  how those tools treat `GCAM_POSITION_INVALID` regions was not tested here.

## Recommended Fix

Derive both limits from the fixed volume:

```diff
-  cmax = tDblCoords(256.0);
+  cmax(0) = mri_fixed->width;
+  cmax(1) = mri_fixed->height;
+  cmax(2) = mri_fixed->depth;
```

```diff
-FemTransform3d::convert_to_delta() const
+FemTransform3d::convert_to_delta(int width, int height, int depth) const
 {
   MRI* field = NULL;
   MRI* mask = NULL;
-  int width(256), height(256), depth(256);
 ...
-        Transform3SPointer pBufTransform(pTmpTransform->convert_to_delta());
+        Transform3SPointer pBufTransform(
+            pTmpTransform->convert_to_delta(mri_fixed->width,
+                                            mri_fixed->height,
+                                            mri_fixed->depth));
```

(plus the matching change of the declaration at [`morph.h:313`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.h#L313); `cmax(i)` is
assignable because `TCoords::operator()(int)` returns a reference). For a
256³ fixed volume the new `cmax` equals the old constant, so the default CVS
path is bit-for-bit unchanged. A regression test is the experiment above:
for a 320³ fixed volume, `out.mgz` must equal the input for the identity
morph over the whole head and no `failed to find elt` lines may appear for
surface vertices.

### Alternative Fixes Considered

- Restore `cmax = cmax + 10` (bounding box + padding) as before 2014 and
  size the delta grid from the mesh bounding box; this makes the grid
  independent of the volume but needs the delta transform to store its origin.
- Refuse fixed volumes larger than 256³ with an explicit error until the code
  is generalised.

## Workarounds (If Any)

Use a template subject whose `norm.mgz` has at most 256 voxels along every
axis (for example a standard 1 mm conformed subject). Untested on a full CVS
run.
