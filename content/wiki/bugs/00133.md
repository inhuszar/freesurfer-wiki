# [severity-3] [bug-00133] `MRIcomputeFlairRatio` samples FLAIR at integer y but float x/z, and overrides T1=1 making the "ratio" just FLAIR

> [!bug] Synopsis
> ```cpp
> /* mri_extract_fcd_features/mri_extract_fcd_features.cpp:603-680 (excerpt) */
> static MRI *MRIcomputeFlairRatio(MRI_SURFACE *mris, MRI *mri_ribbon,
>                                  MRI *mri_aparc, MRI *mri,
>                                  MRI *mri_flair, MRI *mri_aseg, int whalf)
> {
>   ...
>   for (vno = 0; vno < mris->nvertices; vno++) {
>     v = &mris->vertices[vno];
>     ...
>     xs = v->whitex - v->nx * SAMPLE_DIST;
>     ys = v->whitey - v->ny * SAMPLE_DIST;
>     zs = v->whitez - v->nz * SAMPLE_DIST;
>     MRISsurfaceRASToVoxelCached(mris, mri_aseg, xs, ys, zs, &xf, &yf, &zf);  /* :633 */
>     xv = nint(xf); yv = nint(yf); zv = nint(zf);                              /* :634 */
>     label = MRIgetVoxVal(mri_aseg, xv, yv, zv, 0);
>     if (IS_WHITE_MATTER(label) == 0) continue;
>     ...
>     MRISsurfaceRASToVoxelCached(mris, mri_aseg, xs, ys, zs, &xf, &yf, &zf);   /* :664 — recomputes xf, yf, zf */
>     MRIsampleVolume(mri_flair, xf, yv, zf, &flair);                          /* :665 — bug: yv not yf */
>     MRIsampleVolume(mri,        xf, yv, zf, &T1);  T1 = 1;                    /* :666 — bug: yv not yf, and T1 overridden */
>     if (FZERO(T1)) continue;
>
>     v->marked = 1;
>     MRIsetVoxVal(mri_features, vno, 0, 0, 0, flair/T1);                       /* :671 — flair/1 == flair */
>   }
>   ...
> }
> ```

## Detailed Description

### Bug 1: `yv`
instead of `yf`

`yv` is the integer
nearest-voxel index
from the surface
sample point
`(xs, ys, zs)`,
computed at `:634`:
```c
xv = nint(xf); yv = nint(yf); zv = nint(zf);
```

`yf` is the float
voxel coordinate
freshly recomputed
at `:664`:
```c
MRISsurfaceRASToVoxelCached(mris, mri_aseg, xs, ys, zs, &xf, &yf, &zf);
```

(This recomputation
is itself
redundant with the
`:633` call since
`(xs, ys, zs)` is
unchanged.)

The `MRIsampleVolume`
function does
trilinear
interpolation
based on the
float voxel
coordinates. With
`yv` integer and
`xf, zf` float,
the sample uses
y = nearest-slice
and x,z = full
trilinear. The
y-direction
quantization is
up to 0.5 voxels
(= 0.5 mm for 1 mm
isotropic FLAIR
volume).

The FCD
feature-extraction
walk uses
half-voxel
spacing
(`step_size = mri->xsize/2`),
so half-voxel
quantization on
one axis is
non-negligible.

### Bug 2: T1
override

```c
MRIsampleVolume(mri, xf, yv, zf, &T1); T1 = 1;
```

The function reads
T1 from the
anatomical volume,
then immediately
sets T1 = 1. The
sampling at `:666`
is wasted compute,
and the "ratio"
`flair / T1` at
`:671` evaluates
to `flair / 1 =
flair`.

The function name
`MRIcomputeFlairRatio`
and the comment at
the top of the
file suggest it
should compute
FLAIR / T1 ratio.
This is a common
contrast used in
FCD detection
since FCD lesions
typically have
elevated FLAIR
relative to T1.
With the override,
the feature is
just FLAIR
intensity at the
sample point —
useful but
different from
what the function
purports to
compute.

### Combined effect

The FCD FLAIR
feature is:
- Sampled with a
  half-pixel y-axis
  quantization
  (bug 1).
- Computed as raw
  FLAIR instead of
  FLAIR/T1 ratio
  (bug 2).

Downstream FCD
detection models
trained on these
buggy features
will continue to
work with
similarly-buggy
test data, but
the features
don't represent
what the function
name advertises.

## Root Cause

**Bug 1**:
copy-paste typo
between two
co-existing y
variables (`yv`
the integer at
line 634, `yf`
the float at line
664). The author
likely intended
`yf` but typed
`yv`.

**Bug 2**: `T1 = 1`
looks like a
test-mode override
or a debugging
hack that was
committed. The
function name
strongly suggests
it was meant to
compute a ratio.

Two changes:
1. Replace `yv`
   with `yf` so
   trilinear
   interpolation
   is consistent
   across axes.
2. Remove the
   `T1 = 1`
   override so
   the function
   actually
   computes the
   FLAIR/T1
   ratio its
   name implies.

If the override
was intentional
(i.e., the
author found

worked better

rename the
function to
`MRIcomputeFlairFeature`
and remove the
sampling-of-T1
