# [severity-3] [bug-00223] surf2vol -topology_old — TPbMeshCrop::bfs is a depth-first search with global visited sets: untangler crop patches are smaller and more lopsided than the requested radius

> [!bug] Synopsis
> The old untangler (`-topology_old`, used by every [[mri_cvs_register]] run) crops a neighbourhood of radius 3 around each inverted tetrahedron and relaxes it. The function that
> collects the neighbourhood, `TPbMeshCrop::bfs`, is named "bfs" but is a recursive depth-first search that marks elements and nodes as visited globally. An element first reached with a small
> remaining radius is never re-expanded from a shorter path, so the patch is truncated in directions that depend on element id order. In a harness on a regular tetrahedral mesh, radius 3 keeps 782–884 of the 1,007
> elements within graph distance 3 and has 77–90 free nodes instead of 108; radius 4 loses 34–44 % of the elements. The effect on real CVS data has not been measured.

## Affected Artefacts

- **Tool(s):** [[surf2vol]] with `-topology_old`; therefore every [[mri_cvs_register]] run (the script always passes it)
- **Pipeline stage(s):** `mri_cvs_register` elastic registration (`surf2vol` per hemisphere, `-fem_steps 17`), in each FEM step whose log prints `solving topology problems`
- **FreeSurfer version(s):** confirmed in `8.2.0`; present since the surf2vol import, 2008-04-18 (`9761aeb9b6`)
- **Platforms:** all
- **Triggering configuration:** any FEM step with at least one inverted element and `-topology_old` (radius `3`, [`fem_elastic/fsurf2vol.cpp:557`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L557)). Radius 2 is unaffected in the harness; radius 3 and 4 are.

## Detailed Description

The module header states the intent: "Problems Mesh Crop Filter - crops a certain radius around problem elements; DFS with given radius - the radius is reinitialized at each problem encountered"
([`fem_elastic/pbmesh_crop.h:5-7`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/pbmesh_crop.h#L5-L7)), and the comment on `bfs` defines the neighbour relation: "2 tetrahedra are considered neighbors if they share a node"
([`fem_elastic/pbmesh_crop.h:185-189`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/pbmesh_crop.h#L185-L189)). The untangler calls it with the seed element and `neighborhood = 3`:

```cpp
    crop.Crop( &cropMesh,
               nodeMap,
               elementMap,
               boundaryNodes,
               vecContainer.front(),
               neighborhood
             );
```

The collection routine:

```cpp
template<class Cstr, int n>
void
TPbMeshCrop<Cstr,n>::bfs(unsigned int seed,
                         unsigned int radius,
                         unsigned int maxRadius,
                         IndexSetType& eltVisited,
                         IndexSetType& nodeVisited)
{
  IndexSetType tetSet; // used to populate the neighbor list
  NodeType* pnode = NULL;
  const ElementType* cpseed = NULL;
  //unused: const ElementType* cpelt = NULL;

  typename IndexSetType::const_iterator cit;
  typename NodeType::tElt_citer eltBegin, eltEnd;

  // if element was already visited, return
  if ( eltVisited.find(seed) != eltVisited.end() )
  {
    // if not a leaf, truly visited
    if ( m_leafElements.find(seed) == m_leafElements.end() )
      return;
  }

  cpseed = m_pmesh->get_elt(seed);
  if ( !cpseed  )
  {
    std::cerr << " Failed to extract element with seed " << seed << std::endl;
    exit(1);
  }

  // criterium for seed-reinit
  if ( cpseed->orientation_pb( dst ) )
    radius = maxRadius;

  eltVisited.insert( seed );

  if ( !radius )
  {
    m_leafElements.insert( seed );
    return;
  }
  else
  {
    // if previously a leaf, erase it
    cit = m_leafElements.find( seed );
    if ( cit != m_leafElements.end() )
      m_leafElements.erase( cit );
  }
  radius -= 1;

  // populate the set of neighbors
  for (unsigned int ui(0), nnodes(cpseed->no_nodes());
       ui < nnodes; ++ui)
  {
    if ( !cpseed->get_node(ui, &pnode))
    {
      std::cerr << " Failed to get node for element " << seed << std::endl;
      exit(1);
    }
    // continue if node was already visited
    // no backward propagation
    if ( nodeVisited.find( pnode->get_id() ) != nodeVisited.end() ) continue;

    nodeVisited.insert( pnode->get_id() );

    for ( pnode->get_elt_citer(eltBegin, eltEnd);
          eltBegin != eltEnd;
          ++eltBegin )
      tetSet.insert( *eltBegin );
  }

  for ( typename IndexSetType::const_iterator tetCiter = tetSet.begin();
        tetCiter != tetSet.end(); ++tetCiter)
    this->bfs( *tetCiter,
               radius,
               maxRadius,
               eltVisited,
               nodeVisited );

}
```

Two global-state mechanisms break the radius semantics:

1. **Element visited check** ([`fem_elastic/pbmesh_crop.h:206-212`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/pbmesh_crop.h#L206-L212)): an element that has already been expanded is never expanded again, even if it is now reached with a larger remaining `radius` through a shorter path. (Elements that were reached at `radius == 0`
   are remembered as "leaves" and can be re-expanded; elements reached with remaining radius 1 or more cannot.)
2. **Node visited check** ([`fem_elastic/pbmesh_crop.h:250-254`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/pbmesh_crop.h#L250-L254)): the first element that touches a node claims it and queues that node's incident elements with *its own* remaining radius; every later element
   sharing that node skips it ("no backward propagation"). The neighbours queued from that node therefore inherit the radius of whichever element happened to arrive first.

Because the recursion goes depth-first through the id-sorted `tetSet`, "first" is determined by element numbering, not by distance from the seed. Elements within graph distance 3 can end up at remaining radius 0 along a long path and are never revisited via the short path.

### Expected Behaviour

All elements within `radius` node-sharing hops of the seed (and of every other inverted element encountered, with the radius reinitialised) are in the patch, and the patch interior (the "visited" nodes that become free unknowns) is the set of nodes of elements at distance ≤ radius − 1.

### Observed Behaviour

The patch is a subset of that ball whose shape depends on element ids. Because the interior is smaller, the local solve has fewer free degrees of freedom and a thinner relaxation zone around the fold.

### Reproducer

A standalone harness holds a verbatim transcription of `TPbMeshCrop::bfs` (including the leaf bookkeeping) over minimal stand-ins for `Node`, `Elt` and `Mesh`. Test mesh: a 14 × 14 × 14 grid of cubes, each split into 6 tetrahedra (Freudenthal/Kuhn subdivision, 16,464 tetrahedra); the six tetrahedra of the central cube are used in turn as the sole
"problem" seed. The reference is a true breadth-first search over the element graph (two tetrahedra adjacent if they share a node). Counts of elements within graph distance ≤ radius, and of interior (free) nodes, across the six seeds:

| radius | elements expected | elements cropped (6 seeds) | free nodes expected | free nodes (6 seeds) |
|--------|-------------------|----------------------------|---------------------|----------------------|
| 2 | 359 | 359 (all) | 32 | 32 |
| 3 | 1,007 | 782 – 884 | 108 | 77 – 90 |
| 4 | 2,159 | 1,218 – 1,422 | 256 | 128 – 153 |

So radius 3 (the value used by `surf2vol`) loses 12–22 % of the elements and 17–29 % of the free nodes; radius 4 loses 34–44 % of the elements. A 2-D variant (a 21 × 21 grid of quads, neighbours = shared corner) shows the same: radius 1–3 complete, radius 4 yields 63 of 81 elements.
A corrected version (remember the best remaining radius per element, re-expand only when reached with a larger radius, drop the node-visited skip; see Recommended Fix) reproduces the reference exactly in every case (1,007 elements, 108 nodes at radius 3; 2,159 and 256 at radius 4).

> [!gap] Not measured on real CVS meshes
> The harness uses a regular mesh and a single seed. How much smaller the patches are on the Delaunay meshes of `surf2vol`, and how that changes the number of
> remaining inverted elements ("Still having pbs after untangling", [`fem_elastic/untangler.cpp:148-149`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/untangler.cpp#L148-L149)), was not measured.

## Root Cause

A radius-limited neighbourhood is computed with a depth-first traversal that uses global visited flags for both elements and nodes. For a distance-limited ball a visited flag is only valid in a breadth-first order (the first visit is at minimum distance) or if the traversal remembers the best remaining radius per element.
The function name, the header comment ("DFS") and the code disagree, but the contract ("crops a certain radius around problem elements") is what callers rely on.

## Impact

- **Default CVS path:** `-topology_old` → `solve_topology_problems(*pmesh, 3)` → `TPbMeshCrop::Crop(..., 3)` ([`fem_elastic/untangler.cpp:88-94`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/untangler.cpp#L88-L94)), in every FEM step that has inverted elements.
- **Probable effect:** untangling relaxes a smaller, lopsided region than intended; folds that need a larger relaxation zone survive more often ("Still having pbs after untangling"). Residual inverted elements are then treated by `TMesh::dir_img` as invalid ([[00224]]), which turns them into masked voxels in the compressed morph.
  This causal chain is a hypothesis, not a measurement.
- **Severity 3 (medium):** on the default path of [[mri_cvs_register]] (which argues for 4–5), but the defect degrades the quality of an iterative repair step rather than demonstrably producing wrong output, its magnitude on real data is unquantified, and the later volumetric stages (`mri_nl_align`) refine the result. Scored 3; a reviewer who weights the default-path reach could argue for 4.

## Recommended Fix

Track the best remaining radius per element and re-expand an element only when it is reached with a larger radius; always register the nodes of expanded elements as interior (no node skip). This is the variant validated in the harness:

```diff

+  std::map<unsigned int, unsigned int> m_bestRadius; // best remaining radius seen per element
@@ TPbMeshCrop::Crop
-  m_leafElements.clear();
+  m_bestRadius.clear();
@@ TPbMeshCrop::bfs
-  // if element was already visited, return
-  if ( eltVisited.find(seed) != eltVisited.end() )
-  {
-    // if not a leaf, truly visited
-    if ( m_leafElements.find(seed) == m_leafElements.end() )
-      return;
-  }
-
   cpseed = m_pmesh->get_elt(seed);
@@
   // criterium for seed-reinit
   if ( cpseed->orientation_pb( dst ) )
     radius = maxRadius;

+  // (re)visit only if reached with a larger remaining radius than before
+  typename std::map<unsigned int,unsigned int>::iterator bit = m_bestRadius.find( seed );
+  if ( bit != m_bestRadius.end() && bit->second >= radius ) return;
+  m_bestRadius[seed] = radius;
+

   if ( !radius )
-  {
-    m_leafElements.insert( seed );
-    return;
-  }
-  else
-  {

-    cit = m_leafElements.find( seed );
-    if ( cit != m_leafElements.end() )
-      m_leafElements.erase( cit );
-  }
+    return;

-    // continue if node was already visited
-    // no backward propagation
-    if ( nodeVisited.find( pnode->get_id() ) != nodeVisited.end() ) continue;
```

Each element can now be expanded at most `maxRadius` times, so the cost stays bounded. Tests: the harness above (expect 1,007 / 108 for radius 3, 2,159 / 256 for radius 4) plus a regression on a real `surf2vol` problem comparing the number of elements left inverted before and after. Because this changes the untangling result of the CVS default path, validate on several subjects before adopting.

### Alternative Fixes Considered

Replace the recursion with an explicit queue-based BFS over the element graph and handle the "radius reinitialised at each problem" rule by seeding the queue with all problem elements found so far; simpler to reason about, but the reinitialisation rule makes the best-radius formulation the closer match to the existing semantics.

## Workarounds (If Any)

None short of changing the code. The neighbourhood radius is hard-coded to 3 ([`fem_elastic/fsurf2vol.cpp:557`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L557)); the new solver (no `-topology_old`) has its own defect ([[00222]]).

## Confidence and Gaps

> [!gap] Is a truncated ball intended?
> The header calls the algorithm "DFS with given radius", which suggests the authors knew it was not a breadth-first search. Whether they accepted order-dependent truncation, or did not realise the visited flags break the radius, is not known; the contract text ("crops a certain radius") says the latter.
> Behaviour is established (high confidence); real-data impact is not (medium).
