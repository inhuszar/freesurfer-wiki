# [severity-3] [bug-00128] `REGIONgetBoundingBox` / `REGIONgetBoundingBoxM` are off-by-one: `dx = cmax - cmin + 2·npad` missing the `+ 1`

> [!bug] Synopsis
> ```cpp
> /* utils/region.cpp:344-379 */
> MRI_REGION *REGIONgetBoundingBox(MRI *mask, int npad)
> {
>   ...
>   cmin = rmin = smin = 1000000;
>   cmax = rmax = smax = 0;
>
>   for (c = 0; c < mask->width; c++) {
>     for (r = 0; r < mask->height; r++) {
>       for (s = 0; s < mask->depth; s++) {
>         v = MRIgetVoxVal(mask, c, r, s, 0);
>         if (iszero(v)) continue;
>         if (cmin > c) cmin = c;
>         ...
>         if (cmax < c) cmax = c;
>         ...
>       }
>     }
>   }
>   region = REGIONalloc();
>   region->x = MAX(cmin - npad, 0);
>   region->y = MAX(rmin - npad, 0);
>   region->z = MAX(smin - npad, 0);
>   /* :374-376 — bug */
>   region->dx = MIN(cmax - cmin + 2 * npad, mask->width  - region->x);
>   region->dy = MIN(rmax - rmin + 2 * npad, mask->height - region->y);
>   region->dz = MIN(smax - smin + 2 * npad, mask->depth  - region->z);
>
>   return (region);
> }
> ```
>
> The bounding box should
> span columns `cmin-npad`
> through `cmax+npad`
> **inclusive**. The count of
> voxels in that span is
> `(cmax + npad) - (cmin -
> npad) + 1 = cmax - cmin +
> 2·npad + 1`.
>
> The code writes
> `cmax - cmin + 2 * npad`
> — **missing the `+1`**.
>
> Same defect in
> `REGIONgetBoundingBoxM`
> ([`:327-329`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/region.cpp#L327-L329)):
>
> ```cpp
> region->dx = MIN(cmax - cmin + npad[0] + npad[1], mask->width  - region->x);
> region->dy = MIN(rmax - rmin + npad[2] + npad[3], mask->height - region->y);
> region->dz = MIN(smax - smin + npad[4] + npad[5], mask->depth  - region->z);
> ```

## Detailed Description

### Concrete numerical example

For a brain mask in a
256³ volume with
non-zero voxels in
`c ∈ [50, 200]` (151
voxels along width),
`npad = 2`:

| quantity     | correct | buggy code |
|--------------|---------|-----------|
| region->x    | `max(50 - 2, 0) = 48` | same |
| region->dx   | `(200 - 50) + 1 + 2·2 = 155` | `(200 - 50) + 2·2 = 154` |
| span        | `c ∈ [48, 48+155) = [48, 203)` (voxels 48..202) | `c ∈ [48, 48+154) = [48, 202)` (voxels 48..201) |
| missing | none | **voxel 202 is excluded** — the last padding voxel |

Consumers do:
```cpp
for (c = region->x; c < region->x + region->dx; c++) {
  ...
}
```

So the bug drops one
voxel column at the far
edge of the bounding box
in every dimension. For
a 3D bounding box of
size ~D³, the lost
voxels form a thin L-
shaped shell:
~3·D² voxels missing
out of D³ total
(~3/D ≈ 1.5 % for D=200).

### When the MIN clamp
masks the bug

The `MIN(..., mask->width
- region->x)` clamp at
the end of each line
limits dx to the
remaining volume. If
`cmax + npad >=
mask->width - 1` (mask
extends to or near the
high edge), the MIN
clamp may produce the
correct value despite
the buggy expression.

Specifically, for
`cmin = 0` and
`cmax = mask->width - 1`
(mask touches both edges):
- region->x = 0.
- region->dx (buggy) =
  (width-1) + 2·npad =
  width + 2npad - 1.
- mask->width -
  region->x = width.
- MIN = width.

So when the mask
touches both edges, the
MIN clamp produces dx
= width (which spans
the full volume) and
the off-by-one is
masked. The bug only
manifests when the
bounding box is
strictly interior to
the volume — typical
for brain masks in
neuroimaging volumes
that include neck/
shoulders.

### Single-voxel case

For a single non-zero
voxel at `c == 50` with
`npad == 0`:
- cmin = cmax = 50.
- region->x = 50.
- region->dx (buggy) =
  50 - 50 + 0 = **0**.
- Correct dx = 1.

The consumer loop
`for(c=50; c < 50+0; c++)`
runs zero iterations —
the lone voxel is
silently dropped.

### Downstream impact

For `mri_gtmpvc
--auto-mask`:
- The PET-cropping
  region misses the
  last padding voxel
  in each dimension.
- All subsequent
  output volumes
  (`gtm.nii.gz` etc.)
  are cropped to this
  one-voxel-short
  bounding box.

For `MRIvol2VolFill`
(used by various
upsample workflows):
- The mask-and-
  upsample region
  drops the last voxel
  slab.
- The output upsampled
  volume is missing
  voxel data in that
  slab.

For
`GTMrbv` with
`mask_rbv_to_brain`:
- The RBV output
  volume cropping
  excludes the last
  brain-edge voxel.

### Why this is severity 3

- **Silent and
  reachable**: triggered
  on every call to
  `REGIONgetBoundingBox`
  / `REGIONgetBoundingBoxM`.
- **Bounded effect**:
  ~1 voxel slab lost
  per axis, not entire
  output volumes.
- **MIN-clamp
  masking**: when the
  mask touches the
  volume boundary in
  the relevant
  direction, the bug
  is invisible.
- **Not severity 4**:
  the rest of the
  bounding box is
  correctly computed;
  the lost shell is
  typically thin and
  at the brain
  periphery (e.g.,
  the outermost
  CSF/skull-edge
  voxels). No
  CATASTROPHIC wrong
  output.
- **Severity 3
  threshold**:
  reachable from
  production tools
  (`mri_gtmpvc`,
  `mri_vol2vol`),
  silent, output
  data is missing
  voxels at a known
  location.

## Root Cause

The formula for the
size of an inclusive
interval `[a, b]` is
`b - a + 1`. The
bounding-box code
forgot the `+ 1` when
combining cmin/cmax
with the padding:

```c
region->dx = MIN(cmax - cmin + 2 * npad, ...);  /* missing + 1 */
```

The matching field
naming (`dx` is "delta
x" / size) and consumer
loops `for(c = x; c < x
+ dx; c++)` confirm
that `dx` is intended
as a count, not an
exclusive endpoint.

  values at the
  brain periphery
  (outermost gyral

  are missing from
  the output PVC
  volumes.

  one fewer voxel

  upsampled side

  one fewer voxel
  slab when
  `--mask-rbv-to-brain`
  is enabled.
- **Severity:** 3 —
  reachable, silent,

  to a thin edge
  shell.

## Workarounds

For users running
`mri_gtmpvc` with
`--auto-mask`: pad the
input brain mask by an
additional 1 voxel
(via `mri_binarize
--dilate 1` or
`MRIdilate`) before
feeding to
`mri_gtmpvc`. This
shifts cmin down /
cmax up by 1, working
around the off-by-one.

For `MRImaskAndUpsample`
callers: post-process
the output to add a
zero-valued voxel slab
on the trailing edge,
or just accept the
one-voxel loss
(typically benign).
