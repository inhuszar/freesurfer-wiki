# [severity-3] [bug-00069] `mri_diff --diffpct` divides by zero when `val1 + val2 == 0`

> [!bug] Synopsis
> `mri_diff` with `--diffpct`
> ([`mri_diff/mri_diff.cpp:494`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_diff/mri_diff.cpp#L494))
> computes per-voxel percent difference:
>
> ```cpp
> if (DiffPct) diff = 100*(val1-val2)/((val1+val2)/2.0);
> ```
>
> When `val1 + val2 == 0`, the divisor is zero. IEEE
> 754:
> - `val1 == val2 == 0` → `0/0 = NaN`,
> - `val1 == -val2 ≠ 0` → `±x/0 = ±Inf`.
>
> The resulting `diff` is then:
> - tracked as `maxdiff` if larger;
> - written to the `--diffvol` output if requested
>   ([`:495`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_diff/mri_diff.cpp#L495));
> - accumulated into `SumDiff` for `--avgdiff`
>   ([`:496`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_diff/mri_diff.cpp#L496)).
>
> Any NaN/Inf in those summaries propagates and
> dominates downstream readers.

## Affected Artefacts

- **Tool:** [[mri_diff]] with `--diffpct`.
- **Pipeline stage(s):** none in default
  `recon-all`. Affects QA pipelines that compute
  percent-difference metrics.
- **Triggering configuration:** any voxel where the
  two inputs sum to zero (background outside brain
  in float volumes; equal-magnitude opposite-signed
  values in residual volumes).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

```cpp
double diff = val1-val2;
if (fabs(diff) > pixthresh) ndiff++;
...
SumSqDiff += (diff*diff);
SumSqErr  += (diff*diff);
if (AbsDiff)  diff = fabs(diff);
if (DiffAbs)  diff = fabs(fabs(val1)-fabs(val2));
if (DiffPct)  diff = 100*(val1-val2)/((val1+val2)/2.0);   /* :494 */
if (DiffVolFile && !DoRSS)  MRIsetVoxVal(DiffVol,c,r,s,f,diff, mode);
if (AvgDiffFile && !DoRSS)  SumDiff += diff;
...
if (maxdiff < diff) {
  maxdiff = diff;
  ...
}
```

The percent-difference formula is otherwise correct
(symmetric, scale-invariant). The missing guard is
the only defect.

## Root Cause

Missing zero-divisor guard. The
percent-difference computation does not consider
the `val1 + val2 == 0` corner case.

## Impact

- **Background voxels:** for two volumes whose
  outside-brain regions are exactly zero, every
  background voxel triggers `0/0 = NaN`. The
  `maxdiff` reader sees `NaN < anything = false`, so
  the maxdiff doesn't get clobbered, but the
  per-voxel `--diffvol` output and the `--avgdiff`
  summary do.
- **Inside-brain voxels:** uncommon to hit
  `val1 + val2 == 0`, but possible for residual /
  zero-mean fMRI data.
- **Severity:** low. The percent-difference metric
  is scale-relative and undefined at zero anyway;
  users typically restrict computation to a mask.

## Recommended Fix

```diff
--- a/mri_diff/mri_diff.cpp
+++ b/mri_diff/mri_diff.cpp
@@ -491,7 +491,11 @@ int main(int argc, char *argv[])
             SumSqErr  += (diff*diff);
             if(AbsDiff)   diff = fabs(diff);
             if(DiffAbs)   diff = fabs(fabs(val1)-fabs(val2));
-            if(DiffPct)   diff = 100*(val1-val2)/((val1+val2)/2.0);
+            if(DiffPct) {
+              double sum = val1 + val2;
+              if (sum == 0) diff = 0;
+              else          diff = 100*(val1-val2) / (sum/2.0);
+            }
             if(DiffVolFile && !DoRSS)  MRIsetVoxVal(DiffVol,c,r,s,f,diff, mode);
```

Or use `FZERO(sum)` for an epsilon-tolerant guard.

## Workarounds

Pass `--mask <brainmask>` to restrict computation
to in-brain voxels, where `val1 + val2 == 0` is
extremely unlikely.
