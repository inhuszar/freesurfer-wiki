# [severity-3] [bug-00170] map_central_sulcus — calls `recon-all -avglabels`, a flag removed in v8.2.0 (fails as shipped)

> [!bug] Synopsis
> `scripts/map_central_sulcus` is a two-step wrapper whose only active
> command is `recon-all -s $1 -hemi $2 -avglabels`. The `-avglabels`
> flag has been **removed from `recon-all` in v8.2.0**, so the script
> fails immediately with `ERROR: Flag -avglabels unrecognized.` The
> original, intended call (`mris_spherical_average ... label
> $2-central_sulc ...`) survives only as a commented-out line at the top
> of the script. As shipped in 8.2.0, `map_central_sulcus` cannot do
> anything useful — it always errors out.

## Affected Artefacts

- **Tool(s):** [[map_central_sulcus]] — a tiny tcsh wrapper
  (`$1` = subject, `$2` = hemisphere) intended to map a central-sulcus
  label onto a subject via spherical-average label transfer.
- **Pipeline stage(s):** _N/A_ — run by hand. (It *invokes*
  [[wiki/pipelines/recon-all|recon-all]], but with a flag recon-all no longer accepts.)
- **FreeSurfer version(s):** confirmed broken in `8.2.0` at commit
  `d932c45`; `-avglabels` is absent from `scripts/recon-all` at this
  commit.
- **Platforms:** all — control flow / obsolete CLI.
- **Triggering configuration:** **every** invocation. The single active
  command unconditionally passes `-avglabels` to `recon-all`.

## Detailed Description

The script body is essentially three lines: a commented-out
`mris_spherical_average` invocation, then the active `recon-all` call,
then `exit $status`.

The active command
([`scripts/map_central_sulcus:26`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/map_central_sulcus#L26))
is:

```
recon-all -s $1 -hemi $2 -avglabels
```

`recon-all` in v8.2.0 no longer recognises `-avglabels`. A search of
`scripts/recon-all` at commit `d932c45` finds **no** occurrence of
`avglabels` (the flag and its handler have been removed). recon-all's
argument parser therefore falls through to its "unrecognized flag" error
and exits non-zero. Because `-avglabels` is the only directive given,
there is no surviving useful behaviour.

The commented block at the top
([`scripts/map_central_sulcus:23-24`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/map_central_sulcus#L23-L24))
shows the historical intent:

```
#mris_spherical_average -o $1 label $2-central_sulc $2 \
#  sphere.reg margaret $SUBJECTS_DIR/$1/label/$2-central_sulc_margaret.label
```

i.e. the tool was originally meant to run `mris_spherical_average` in
`label` mode to transfer a central-sulcus label from a template subject
("margaret") onto subject `$1`. That call was replaced by a `recon-all
-avglabels` shortcut, and when `-avglabels` was later dropped from
recon-all, this wrapper was left calling a flag that no longer exists.

### Expected Behaviour

`map_central_sulcus <subj> <hemi>` should map the central-sulcus label
onto `<subj>` and exit zero on success.

### Observed Behaviour

The wrapper invokes `recon-all -s <subj> -hemi <hemi> -avglabels`,
recon-all prints `ERROR: Flag -avglabels unrecognized.` and exits with an
error, and the wrapper propagates that via `exit $status`. No label
mapping occurs.

### Reproducer

```bash
map_central_sulcus somesubject lh
```

Observed (v8.2.0):

```
Adding options -fix-ento-wm -transfer-base-bfs -fix-vsinus -fix-mca-dura ...
ERROR: Flag -avglabels unrecognized.
-s somesubject -hemi lh -avglabels
...
recon-all -s somesubject exited with ERRORS at <date>
```

Verified 2026-06-09 against `/usr/local/freesurfer/8.2.0/bin/map_central_sulcus`
and confirmed directly with `recon-all -s somesubject -hemi lh
-avglabels`, which produces the identical `Flag -avglabels unrecognized`
error. (The error appears before any subject lookup, so it does not
require a real subject to reproduce.)

## Root Cause

Obsolete interface. The tool delegates to a `recon-all` sub-command
(`-avglabels`) that has been removed from `recon-all` in v8.2.0. The
script was not updated to either (a) restore the direct
`mris_spherical_average` call it used to make, or (b) use a still-supported
recon-all flag. The historical `mris_spherical_average` invocation is
present but commented out, so the wrapper has no working code path.

## Impact

- **Broken as shipped.** Any user running `map_central_sulcus` on v8.2.0
  gets an immediate `Flag -avglabels unrecognized` failure and no output.
- **Loud, not silent.** The failure is an explicit error with non-zero
  exit, so there is no risk of wrong-but-plausible output — the user
  simply cannot use the tool.
- **Severity 3 (medium).** This is a standalone auxiliary tool, not a
  default user-facing pipeline, and the failure is loud. It is not a 4/5
  (those require wrong output or a crash in a default/auxiliary path that
  users routinely run); `map_central_sulcus` is a niche, label-transfer
  helper. It is firmly broken, but only when explicitly invoked — hence
  medium.

## Recommended Fix

Restore the direct `mris_spherical_average` call (the script's original
behaviour), updating the template-subject and label names as appropriate:

```diff
-#mris_spherical_average -o $1 label $2-central_sulc $2 \
-#  sphere.reg margaret $SUBJECTS_DIR/$1/label/$2-central_sulc_margaret.label
-
-recon-all -s $1 -hemi $2 -avglabels
-
-
+mris_spherical_average -o $1 label $2-central_sulc $2 \
+  sphere.reg margaret $SUBJECTS_DIR/$1/label/$2-central_sulc_margaret.label
+
 exit $status
```

A test should confirm the wrapper exits zero and writes the expected
`label/$2-central_sulc.label` for a known subject.

### Alternative Fixes Considered

- If a current recon-all directive provides equivalent label-averaging,
  re-point the wrapper at that flag instead. (No such replacement flag
  was identified at commit `d932c45`; `-avglabels` simply no longer
  exists, so this requires developer knowledge of its successor.)
- Retire the script if the central-sulcus label-mapping workflow is
  obsolete.

> [!gap] Which fix is correct depends on developer intent
> Whether the intended replacement is "restore `mris_spherical_average`"
> or "use a new recon-all directive" cannot be determined from the code
> alone. The commented-out `mris_spherical_average` line is the only
> evidence of the original behaviour, and it references a template
> subject ("margaret") and label paths that may no longer ship.

## Workarounds (If Any)

Run the underlying `mris_spherical_average` command by hand (the
commented-out line at
[`scripts/map_central_sulcus:23-24`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/map_central_sulcus#L23-L24)),
supplying a valid template subject and the central-sulcus label file. Do
not rely on `map_central_sulcus` as shipped.
