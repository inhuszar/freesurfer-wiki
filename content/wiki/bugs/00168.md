# [severity-2] [bug-00168] mksurfatlas — overlay existence check tests the registration surface (`$sr`) instead of the overlay (`$sv`)

> [!bug] Synopsis
> In `scripts/mksurfatlas`, `check_params` validates, for each subject,
> that both the registration surface (`$sr =
> $SUBJECTS_DIR/$subject/surf/$hemi.$regsurf`) and the overlay file (`$sv
> = $SUBJECTS_DIR/$subject/$surfvaldir/$hemi.$surfval`, the `--v`
> argument) exist. The overlay test is a copy-paste error: it re-tests
> `! -e $sr` instead of `! -e $sv`, while the error message still prints
> `$sv`. A subject that has the registration surface but is **missing the
> `--v` overlay** therefore passes validation, and the script proceeds to
> `mris_make_template`, which fails later (or, with a present-but-wrong
> surface, in a confusing way) instead of being caught early with a clear
> "cannot find …" message.

## Affected Artefacts

- **Tool(s):** [[mksurfatlas]] — a standalone csh wrapper around
  `mris_make_template` that builds a surface registration atlas from a
  set of subjects' per-vertex overlays.
- **Pipeline stage(s):** _N/A_ — not part of [[wiki/pipelines/recon-all|recon-all]]; run by hand
  when building a custom surface atlas.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — purely a shell-level input-validation check.
- **Triggering configuration:** any invocation where at least one
  subject has the registration surface (`$hemi.$regsurf`, default
  `sphere.reg`) present but the requested overlay
  (`$surfvaldir/$hemi.$surfval`, from `--v`/`--d`) absent. The early
  guard that should catch this is bypassed.

## Detailed Description

The `check_params` loop iterates over each subject and builds two paths:

- `$sr` — the registration surface, `surf/$hemi.$regsurf`
  ([`scripts/mksurfatlas:185`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mksurfatlas#L185)).
- `$sv` — the overlay, `$surfvaldir/$hemi.$surfval`
  ([`scripts/mksurfatlas:190`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mksurfatlas#L190)).

The first guard correctly tests `$sr`
([`scripts/mksurfatlas:186-189`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mksurfatlas#L186-L189)).
The second guard is meant to test `$sv`, and its error message indeed
says `"ERROR: cannot find $sv"`, but its `if` condition re-uses `$sr`
([`scripts/mksurfatlas:191-194`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mksurfatlas#L191-L194)).
Because `$sr` was already proven to exist by the immediately preceding
guard, the overlay test can never fire on its own: a missing overlay
slips through.

### Expected Behaviour

If the `--v` overlay file `$SUBJECTS_DIR/$subject/$surfvaldir/$hemi.$surfval`
does not exist for some subject, `mksurfatlas` should abort during
`check_params` with `ERROR: cannot find <overlay path>`, before
attempting to build the atlas.

### Observed Behaviour

A subject with the registration surface present but the overlay absent
passes `check_params`. The script proceeds to run

```
mris_make_template -norot -annot aparc -overlay $surfval $nsmooth \
  -overlay-dir $surfvaldir $hemi $regsurf $subjects $atlas
```

so the missing-overlay condition surfaces as a downstream
`mris_make_template` failure (or, with a malformed surface, a confusing
read error) rather than the intended early, clearly-labelled validation
error.

### Reproducer

```bash
# Create a subject with the registration surface present but NO overlay.
export SUBJECTS_DIR=/tmp/msa_repro_sd
rm -rf $SUBJECTS_DIR
mkdir -p $SUBJECTS_DIR/subjX/surf $SUBJECTS_DIR/subjX/label
: > $SUBJECTS_DIR/subjX/surf/lh.sphere.reg     # $sr exists
# (no $SUBJECTS_DIR/subjX/label/lh.func.mgh — the overlay is absent)

mksurfatlas --a /tmp/out.tif --h lh --v func.mgh --r sphere.reg --s subjX
```

Observed (v8.2.0): `check_params` does **not** print
`ERROR: cannot find .../label/lh.func.mgh`; instead the script proceeds
to invoke `mris_make_template`, which then fails reading the surface.
This confirms the early overlay check was skipped. (Verified
2026-06-09 against `/usr/local/freesurfer/8.2.0/bin/mksurfatlas`.)

## Code Reference (Unambiguous)

- **File:** `scripts/mksurfatlas`
- **Function/symbol:** `check_params` (per-subject existence loop)
- **Lines:** `180-195`
- **Commit:** `d932c45`

```csh
  foreach subject ($subjects $target)
    if(! -e $SUBJECTS_DIR/$subject) then
      echo "ERROR: cannot find $SUBJECTS_DIR/$subject"
      exit 1;
    endif
    set sr = $SUBJECTS_DIR/$subject/surf/$hemi.$regsurf
    if(! -e $sr) then
      echo "ERROR: cannot find $sr"
      exit 1;
    endif
    set sv = $SUBJECTS_DIR/$subject/$surfvaldir/$hemi.$surfval
    if(! -e $sr) then                       # ← BUG: should test $sv
      echo "ERROR: cannot find $sv"
      exit 1;
    endif
  end
```

The mismatch is self-evident: the condition tests `$sr` but the error
message names `$sv`. The two were copy-pasted from the preceding guard
and only the message was updated.

## Root Cause

Copy-paste error. The overlay-existence guard was duplicated from the
registration-surface guard directly above it; the author updated the
`set sv = …` line and the `echo` message but forgot to change the `if(!
-e $sr)` test to `if(! -e $sv)`.

## Impact

- **Latent input-validation defect.** The intended early "missing
  overlay" diagnostic never fires. The failure is not silent — the run
  still aborts downstream when `mris_make_template` cannot use the
  missing overlay — but the error is later and less clear than the
  guard was designed to produce. No incorrect atlas is produced from a
  truly missing overlay.
- **Severity 2 (low).** `mksurfatlas` is a standalone, explicitly
  unsupported helper (its own help says "This program has not been
  tested, is not supported, and you should not use it."), and the defect
  only degrades an error message rather than corrupting output. Per the
  rubric this is a low-severity, QA/diagnostic-only defect.

## Recommended Fix

Test the overlay path in the overlay guard:

```diff
     set sv = $SUBJECTS_DIR/$subject/$surfvaldir/$hemi.$surfval
-    if(! -e $sr) then
+    if(! -e $sv) then
       echo "ERROR: cannot find $sv"
       exit 1;
     endif
```

### Alternative Fixes Considered

None needed — the one-character/one-variable correction fully restores
the intended check.

## Workarounds (If Any)

Before running `mksurfatlas`, verify by hand that every subject has the
overlay file `$SUBJECTS_DIR/$subject/<surfvaldir>/<hemi>.<surfval>` (for
the default `--d label`, that is `subject/label/<hemi>.<surfval>`). The
script will not catch a missing overlay for you.
