# [severity-5] [bug-00070] `mri_segstats` SNR computation lacks zero-std guard

> [!bug] Synopsis
> `mri_segstats`
> ([`mri_segstats/mri_segstats.cpp:910-921`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segstats/mri_segstats.cpp#L910-L921))
> computes per-segment SNR as
>
> ```cpp
> if (InVolFile != NULL && !dontrun) {
>   if (nhits > 0) {
>     ...
>     MRIsegStats(seg, StatSumTable[n].id, invol, frame,
>                 &min, &max, &range, &mean, &std);
>     ...
>     snr = mean/std;                                    /* :921 */
>   }
>   else { snr = 0; ... }
>   ...
>   StatSumTable[n].snr = snr;
> }
> ```
>
> The `nhits > 0` branch protects against zero
> voxels but not against `std == 0` (which can
> occur when all voxels in the segment have the
> same intensity). The unguarded division yields
> `±Inf` (mean ≠ 0) or `NaN` (mean == 0) and is
> written to the SNR column of the produced
> `.stats` file.

## Affected Artefacts

- **Tool:** [[mri_segstats]] with `--in <volume>` and
  `--snr` enabled (the SNR column appears in the
  default `.stats` output produced by recon-all's
  `mri_segstats` invocations).
- **Pipeline stage(s):** invoked by `recon-all` to
  produce `aseg.stats`, `wmparc.stats`, etc.
- **Triggering configuration:** any segment whose
  intensity values are all identical. In practice:
  - `--in` a binary mask (all 1's),
  - `--in` a constant-value volume,
  - segments small enough that every member has the
    same rounded intensity (rare but possible for
    integer-valued inputs).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

```cpp
if (InVolFile != NULL && !dontrun) {
  if (nhits > 0) {
    if (UseRobust == 0)
      MRIsegStats(seg, StatSumTable[n].id, invol, frame,
                  &min, &max, &range, &mean, &std);
    else
      MRIsegStatsRobust(seg, StatSumTable[n].id, invol, frame,
                        &min, &max, &range, &mean, &std, RobustPct);

    snr = mean/std;     /* (!) divide by zero if std == 0 */
  }
  else { ... snr = 0; ... }
  ...
  StatSumTable[n].snr = snr;
}
```

The branch around `nhits > 0` correctly guards
the empty-segment case but not the constant-segment
case. The output SNR column carries `Inf`/`NaN`
text for any constant segment.

## Code Reference

- **File:** [`mri_segstats/mri_segstats.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segstats/mri_segstats.cpp)
- **Defect:**
  [`:921`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segstats/mri_segstats.cpp#L921)
- **Commit:** `d932c45b79`

## Root Cause

Missing zero-std guard. The author guarded against
empty segments (the more common case) but not
against constant-value segments.

## Impact

- **Standard recon-all `aseg.stats`:** unaffected
  in practice — the input is `norm.mgz` (T1
  intensity, no constant-value labels).
- **User pipelines with binary or
  constant-intensity inputs:** the SNR column
  carries `Inf`/`NaN` for the constant segments.
  Downstream parsers (Excel, R, Python) may
  silently propagate the sentinel.
- **Severity:** low. Niche but reproducible.

## Recommended Fix

```diff
--- a/mri_segstats/mri_segstats.cpp
+++ b/mri_segstats/mri_segstats.cpp
@@ -918,7 +918,7 @@ int main(int argc, char **argv)
           MRIsegStatsRobust(seg, StatSumTable[n].id, invol, frame,
             &min, &max, &range, &mean, &std, RobustPct);

-        snr = mean/std;
+        snr = (std > 0) ? (mean / std) : 0;
       }
```

A more defensive choice is to write the literal
string `n/a` when `std == 0` so downstream parsers
can tell apart "constant segment" from "noisy
segment with mean = 0".

## Workarounds

Filter out constant segments from `--in` before
running.
