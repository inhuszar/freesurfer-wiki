# [severity-2] [bug-00156] stat_normalize — advertised -f (field-of-view) option is unreachable (case 'f' under toupper)

> [!bug] Synopsis
> `stat_normalize` advertises a `-f <field of view>` option in its usage
> text, but the option dispatcher switches on `toupper(*option)` while the
> handler is written as `case 'f':`. Because `toupper('f')` is `'F'`, the
> lowercase `case 'f'` can never match; every `-f` invocation falls
> through to the `default:` arm, prints `unknown option -f`, and calls
> `exit(1)`. The field-of-view setting is therefore impossible to change
> from the command line — the tool always uses the compiled-in default
> `fov = 256.0`.

## Affected Artefacts

- **Tool(s):** [[stat_normalize]]
- **Pipeline stage(s):** _N/A_ — `stat_normalize` is a standalone
  group-averaging utility; it is not invoked by
  [[wiki/pipelines/recon-all|recon-all]].
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — purely CLI dispatch logic; `toupper` is
  locale-independent for ASCII `'f'` in the C locale.
- **Triggering configuration:** any command line that passes `-f`
  (e.g. `stat_normalize -f 200 in out`). The bug always fires when `-f`
  is used; the option simply cannot be reached.

## Detailed Description

`get_option()` first handles the long options `--help` and `--version`,
then dispatches the single-letter options with
`switch (toupper(*option))`. Every other case is written as an
**uppercase** letter (`'E'`, `'S'`, `'U'`, `'R'`, `'X'`, `'I'`, `'C'`),
which is consistent with switching on the upper-cased first character —
so `-r`, `-s`, `-x`, etc. all work because, e.g., `toupper('r') == 'R'`
matches `case 'R'`.

The field-of-view handler breaks this pattern: it is written as
`case 'f':` (lowercase). Since the switch expression is always upper-cased,
the controlling value for a `-f` argument is `toupper('f') == 'F'`, and
there is no `case 'F'`. Control therefore reaches the `default:` arm,
which prints `unknown option %s` and exits with status 1.

### Expected Behaviour

`stat_normalize -f <value>` should parse `<value>` as a float and store
it in the static `fov`, exactly as the usage text promises
(`-f <field of view> - set output field of view (def=256)`), so that the
output structural volume is allocated at the requested field of view via
`StatAllocStructuralVolume(sv, fov, resolution, coord_name)`.

### Observed Behaviour

`stat_normalize -f 200 in out` prints `unknown option -f` and exits 1.
The `sscanf(argv[2], "%f", &fov)` body under `case 'f'` is unreachable
dead code. `fov` cannot be changed and retains its default of `256.0`.
By contrast, the resolution option `-r` (handled by `case 'R'`) works
correctly, demonstrating that the uppercase cases are the reachable ones.

### Reproducer

```bash
# -f is rejected as unknown:
SUBJECTS_DIR=/tmp stat_normalize -f 200 /tmp/in /tmp/out
#   -> "unknown option -f", exit 1

# Control: -r (case 'R') is accepted and proceeds past option parsing:
SUBJECTS_DIR=/tmp stat_normalize -r 8 /tmp/in /tmp/out
#   -> "INFO: settting resolution to 8.000000", then reads the volume
```

Observed on the installed `8.2.0` binary
(`/usr/local/freesurfer/8.2.0/bin/stat_normalize`): the first command
prints `unknown option -f`; the second accepts the flag and advances to
the stat-volume read stage.

## Root Cause

The switch is keyed on the upper-cased first option character
(`toupper(*option)`), but the field-of-view arm is labelled with the
**lowercase** literal `'f'`. `toupper('f')` is `'F'`, so the arm is
permanently unreachable. Every other arm uses an uppercase literal and
therefore works regardless of the case the user types. The `'f'` label is
the sole inconsistency, almost certainly a transcription slip when the
option was added (note the usage text and the `fov` global are otherwise
fully wired up).

## Impact

- The documented `-f` field-of-view override does not work; users cannot
  set the output FOV and silently get the 256 mm default.
- The failure is loud (the program exits with `unknown option -f`), so
  there is no risk of a wrong-but-silent result — a user who tries `-f`
  immediately sees it rejected. This caps the severity at **2 (low)**:
  a single auxiliary tool's option is inoperative, the default path
  (no `-f`) is unaffected, and there is no silent corruption.
- `stat_normalize` is a standalone group-averaging tool and is not part
  of [[wiki/pipelines/recon-all|recon-all]], so no default pipeline is
  affected.

## Recommended Fix

Relabel the arm with the uppercase literal so it matches the upper-cased
switch value, consistent with every other case:

```diff
-    case 'f':
+    case 'F':
       sscanf(argv[2], "%f", &fov) ;
       nargs = 1 ;
       break ;
```

After the change, `toupper('f') == 'F'` matches `case 'F'` and the FOV
override works for both `-f` and `-F`.

### Alternative Fixes Considered

Switch on the raw `*option` instead of `toupper(*option)` and spell every
case with its intended literal. This is a larger change (it would make the
options case-sensitive, altering current behaviour where `-R` and `-r`
are both accepted) and is unnecessary; the one-character fix above is
minimal and preserves the existing case-insensitive convention for the
other flags.

## Workarounds (If Any)

None from the command line — the option cannot be reached as shipped.
To use a non-default field of view, edit the static initialiser
`static float fov = 256.0f;` and rebuild, or apply the one-line fix above.
