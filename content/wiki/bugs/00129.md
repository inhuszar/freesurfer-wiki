# [severity-3] [bug-00129] `MRIerodeSegmentation` infinite-loops when called with `nErodes <= 0`

> [!bug] Synopsis
> ```cpp
> /* utils/mriset.cpp:1002-1057 */
> MRI *MRIerodeSegmentation(MRI *seg, MRI *out, int nErodes, int nDiffThresh)
> {
>   ...
>   if (!out) out = MRIallocSequence(seg->width, seg->height, seg->depth, seg->type, 1);
>   ...
>   out = MRIcopy(seg, out);
>
>   n = nErodes;
>   seg2 = MRIcopy(seg, seg2);
>   while (n != 1) {                          /* :1020 — bug */
>     out = MRIerodeSegmentation(seg2, out, 1, nDiffThresh);
>     seg2 = MRIcopy(out, seg2);
>     n--;
>   }
>
>   /* single-step erode below */
>   for (c = 0; c < seg->width; c++) {
>     ...
>   }
>   ...
>   return (out);
> }
> ```
>
> The driver `n = nErodes;
> while (n != 1) { ...; n--; }`
> is meant to do `nErodes-1`
> recursive single-step
> erodes, then fall through
> to the final single step
> at the bottom — for a
> total of `nErodes`
> erodes.
>
> | nErodes | behaviour |
> |---------|-----------|
> | 1       | skip while, do final step → 1 erode ✓ |
> | 2       | 1 recursive step + final step → 2 erodes ✓ |
> | k ≥ 1   | (k-1) recursive steps + final → k erodes ✓ |
> | **0**   | enter loop with n=0; decrement to -1, -2, …; `n != 1` is always true → **infinite loop** |
> | **k < 0** | same: n decreases monotonically, never reaches 1 |
>
> Each loop iteration
> performs a full erosion
> over the volume
> (O(width·height·depth)
> work) and copies the
> result back. CPU stays
> at 100 %; memory is
> bounded (seg2/out
> reused). The process
> only stops when the user
> kills it.

## Detailed Description

### Driver-loop trace

```cpp
n = nErodes;
seg2 = MRIcopy(seg, seg2);
while (n != 1) {
    out = MRIerodeSegmentation(seg2, out, 1, nDiffThresh);
    seg2 = MRIcopy(out, seg2);
    n--;
}
```

For `nErodes = 0`:

| iter | n entering | `n != 1`? | action      | n after |
|------|------------|-----------|-------------|---------|
| 1    | 0          | true      | erode+copy  | -1      |
| 2    | -1         | true      | erode+copy  | -2      |
| 3    | -2         | true      | erode+copy  | -3      |
| …    | …          | true      | …           | …       |

`n` monotonically
decreases, the
`!= 1` predicate stays
true forever. Each
iteration is an
O(volume) erosion +
copy, so the process
spins at 100 % CPU and
never terminates.

For `nErodes < 0`:
identical trajectory,
starting from a lower
value.

### CLI exposure

All three tools that
call this function
accept the erode-count
as a plain
`sscanf("%d", &n)`
integer from the
command line and pass
it through unchecked.

A user typing
`mri_convert --erode-seg 0
in.mgz out.mgz`
expecting "0 means no
erosion" instead gets
an indefinite hang.

A user typing
`--erode-seg -1` (e.g.,
by accident, or
following a convention
where -1 means "all the
way") hangs.

### Why this is severity 3

- **Triggered by
  documented CLI
  flags** with
  out-of-range
  user-supplied
  integers.
- **Silent hang
  (no error message)**:
  the tool prints
  `Eroding seg 0 times`
  / similar, then
  enters the loop. No
  output until manual
  kill.
- **No data
  corruption**: the
  volume isn't
  modified; the
  process just spins.
- **Below severity 4**:
  the bad behaviour
  only fires for
  non-positive
  inputs, not for the
  normal `N >= 1`
  use case.

## Root Cause

`while (n != 1)` with
`n--` is only safe
when `n` starts at
`>= 1`. For `n <= 0`,
the predicate is
never satisfied
(`n` moves away from
1, not toward it).

The author likely
intended
`while (n > 1)` —
"while we need more
than one recursive
step, do another."
That predicate
correctly handles
`n = 0` (skip loop)
and `n = 1` (skip
loop, fall through to
final step), giving
zero erosions for
`n = 0` and one for
`n = 1`.

Alternatively, the
function should
early-return when
`nErodes <= 0` (skip
all work and either
return `seg` or
return an empty
output volume,
depending on the
desired semantics).

## Recommended Fix

```diff
--- a/utils/mriset.cpp
+++ b/utils/mriset.cpp
@@ -1014,12 +1014,15 @@ MRI *MRIerodeSegmentation(MRI *seg, MRI *out, int nErodes, int nDiffThresh)
   if (MRIdimMismatch(seg, out, 0)) {
     printf("ERROR: MRIerodeSegmentation(): seg/out dim mismatch\n");
     return (NULL);
   }
+  if (nErodes <= 0) {
+    printf("ERROR: MRIerodeSegmentation(): nErodes=%d must be >= 1\n", nErodes);
+    return (NULL);
+  }
   out = MRIcopy(seg, out);

   n = nErodes;
   seg2 = MRIcopy(seg, seg2);
-  while (n != 1) {
+  while (n > 1) {
     out = MRIerodeSegmentation(seg2, out, 1, nDiffThresh);
     seg2 = MRIcopy(out, seg2);
     n--;
   }
```

Two parts:
1. Early return on
   `nErodes <= 0`
   with an explicit
   error.
2. `while (n != 1)`
   → `while (n > 1)`
   so that the loop
   terminates
   correctly for any
   non-negative
   `nErodes`.

Apply the same fix
to `MRIdilateSegmentation`
at `:1107` (also
uses `while (n !=
1)` with `n--`).

## Workarounds

For users: don't pass
`0` or negative
values to
`--erode-seg` /
`--erode`. If you
want no erosion,
just omit the flag.

For pipelines that
might programmatically
compute the erode
count: clamp to a
minimum of 1 before
invoking the tool,
e.g.:
```sh
nerode=$(( nerode > 0 ? nerode : 1 ))
```
