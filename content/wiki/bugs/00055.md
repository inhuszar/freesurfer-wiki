# [severity-3] [bug-00055] `GetSurfCosts` — divisions by `nhits` precede the `nhits == 0` guard

> [!bug] Synopsis
> `GetSurfCosts`
> ([`mri_segreg/mri_segreg.cpp:2113-2320`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segreg/mri_segreg.cpp#L2113-L2320))
> computes the BBR (boundary-based registration) cost
> by sampling intensities just inside (`vwm`) and just
> outside (`vctx`) the white surface and accumulating
> per-vertex contrast-vs-cost statistics. After the
> per-vertex loop, the function divides four sums by
> `nhits` to compute means and stds, then writes the
> optimisation cost into `costs[7]`. The early-exit
> for the "no valid vertex was visited" case is at
> [`:2283`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segreg/mri_segreg.cpp#L2283):
>
> ```cpp
> dmean = dsum/nhits;                                         // :2268 — /0 if nhits==0
> dstd  = sum2stddev(dsum,dsum2,nhits);                       // :2269
> cmean = csum/nhits;                                         // :2271 — /0 if nhits==0
> cstd  = sum2stddev(csum,csum2,nhits);                       // :2272
>
> costs[0] = nhits;
> costs[2] = sum2stddev(costs[1],costs[2],nhits);             // :2276
> costs[1] = costs[1]/nhits;                                  // :2277 — /0
> costs[3] = dstd;
> costs[5] = sum2stddev(costs[4],costs[5],nhits);             // :2279
> costs[4] = costs[4]/nhits;                                  // :2280 — /0
> costs[6] = dmean;
> costs[7] = cmean;
> if(nhits == 0) costs[7] = 10.0;                             // :2283 — patches only [7]
> ```
>
> When `nhits == 0` (no surface vertex passed all the
> ripflag / mask / cortex-label / `ExcludeZeroVoxels`
> checks), four divisions by zero already executed. The
> only term salvaged is `costs[7]`, which is the
> optimiser's cost. The remaining `costs[1..6]` (WM
> mean/std, ctx mean/std, percent-contrast mean/std)
> stay as `NaN`.

## Affected Artefacts

- **Tool:** [[mri_segreg]] (BBR registration of fMRI /
  diffusion to anatomical).
- **Pipeline stage(s):** none in default `recon-all`.
  Called from `bbregister` and any direct user
  invocation of `mri_segreg`.
- **Triggering configuration:** any cost evaluation
  during Powell optimisation that produces zero
  qualifying vertices on both hemispheres. This
  happens when:
  - the candidate transform places the surfaces fully
    outside the moving volume's field of view;
  - all qualifying vertices were ripped, masked, or had
    zero intensity in either WM or CTX with
    `ExcludeZeroVoxels` (default).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

Optimiser-facing impact:

- The Powell optimiser (`MinPowell` /
  `compute_powell_cost`) reads only `costs[7]`. When
  `nhits == 0`, that value is patched to `10.0`
  *after* the divisions, so the optimiser sees a sane
  finite cost and never observes the NaN.
- Diagnostic outputs (printed cost summary, `costs[1..6]`
  written to logs) carry NaN values whenever the cost
  evaluator sees zero hits. Operators reading the log
  may misinterpret these as "registration broke" when
  they merely indicate "the trial transform happens to
  put all vertices out of bounds".
- Per-hemisphere cost MRIs (`lhcost`, `rhcost`,
  `lhcon`, `rhcon`) are zero-filled per call
  ([`MRIclone(...)` at `:2184`, `:2185`, `:2190`,
  `:2191`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segreg/mri_segreg.cpp#L2184-L2191)),
  so they are unaffected by the `nhits == 0` divisions.

A symmetric concern: when `nhits` is *small but
nonzero*, `dstd` / `cstd` / `costs[2]` / `costs[5]`
divide by `nhits` or `nhits-1` inside `sum2stddev`,
which can produce inflated noise estimates. That's a
statistical consideration, not a defect.

## Root Cause

The `if (nhits == 0) costs[7] = 10.0;` was added as a
narrow patch for the optimiser-facing cost without
relocating the upstream divisions. The author likely
recognised that the optimiser was the only consumer
that mattered and skipped the rest.

## Impact

- **Optimiser convergence:** unaffected — Powell sees
  `costs[7] = 10.0` (a deliberate large fallback).
- **Operator-facing log values:** when a trial
  transform sees no vertices, `costs[1..6]`,
  `dmean/dstd`, `cmean/cstd` are NaN. The printed
  cost line in the optimiser log reads
  `dmean=nan dstd=nan cmean=nan cstd=nan
  cost=10.0`. This is alarming but operationally
  benign.
- **No effect on registration outputs.** The final
  registration is computed from the optimised
  parameters, not the diagnostic costs.

## Recommended Fix

```diff
--- a/mri_segreg/mri_segreg.cpp
+++ b/mri_segreg/mri_segreg.cpp
@@ -2265,6 +2265,15 @@ double *GetSurfCosts(...)
   //fclose(fp);
   }

+  if (nhits == 0) {
+    /* No qualifying vertices — fill diagnostic costs with sentinels
+       so the log is interpretable, then set the optimisation cost. */
+    for (n = 0; n < 8; n++) costs[n] = 0;
+    costs[7] = 10.0;
+    return (costs);
+  }
+
   dmean = dsum/nhits;
   dstd  = sum2stddev(dsum,dsum2,nhits);
```

This short-circuits the divisions and produces clean
zeros (or any chosen sentinel) for `costs[0..6]` while
preserving the existing optimiser behaviour at
`costs[7] = 10.0`.

## Workarounds

None needed for the optimiser. For diagnostic
post-processing of the cost log, treat `nan` entries
as "no qualifying vertices" rather than as a numerical
failure.
