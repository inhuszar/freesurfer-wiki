# VectorAngle — acos input clamped on the positive side only

> [!bug] Synopsis
> `VectorAngle` in `utils/matrix.cpp` computes `acos(dot / norm)` for
> two n-dimensional vectors, clamping the ratio to `1.0` when it exceeds
> `1` due to floating-point roundoff, but failing to clamp the symmetric
> case on the negative side. Nearly-antiparallel inputs whose dot
> product rounds to a value slightly less than `-norm` therefore yield
> `acos(x)` with `x < −1`, which returns `NaN`. The sister routine
> `Vector3Angle` — immediately below in the same file — is written with
> a different, symmetric clamp and is unaffected.

## Affected Artefacts

- **Tool(s):** None today (the only in-tree caller is the function's
  own declaration in [`include/matrix.h:227`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/include/matrix.h#L227)). The function is exported
  as part of the FreeSurfer utility library and is available to any
  downstream consumer that links against it.
- **Pipeline stage(s):** _N/A_ — not reached by [[recon-all]] at the
  audited commit; catalogued as a latent defect so future callers do
  not re-discover it.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit
  `d932c45b79`.
- **Platforms:** all — purely numerical.
- **Triggering configuration:** any pair of n-dimensional vectors whose
  true angle is `≈ π` and whose dot product rounds to a value strictly
  less than `−|v₁||v₂|`.

## Detailed Description

The function computes the angle between two general `VECTOR`s by the
standard identity `θ = acos(v₁·v₂ / (|v₁| |v₂|))`. To defend against
floating-point overshoot on the upper side, it clamps the ratio to `1`
when `dot > norm`. The analogous overshoot on the lower side — `dot <
−norm`, giving an acos input below `−1` — is not handled, and `acos`
returns `NaN`.

### Expected Behaviour

`VectorAngle` should return a value in `[0, π]` for any finite, non-zero
input vectors, exactly as `Vector3Angle` does for the three-dimensional
case.

### Observed Behaviour

For nearly antiparallel vectors where numerical error rounds
`v₁·v₂` to a value less than `−|v₁||v₂|` (for example, when `dot`
and `norm` are computed in single precision and their magnitudes are
large), `acos(dot / norm)` is evaluated at an input `< −1` and returns
`NaN`.

## Code Reference (Unambiguous)

- **File:** `utils/matrix.cpp`
- **Function:** `VectorAngle()`
- **Lines:** `2622–2636`
- **Commit:** `d932c45b79`

```cpp
float VectorAngle(const VECTOR *v1, const VECTOR *v2)
{
  float angle, l1, l2, dot, norm;

  l1 = VectorLen(v1);
  l2 = VectorLen(v2);
  norm = fabs(l1 * l2);
  if (FZERO(norm)) return (0.0f);
  dot = VectorDot(v1, v2);
  if (dot > norm)
    angle = acos(1.0);
  else
    angle = acos(dot / norm);
  return (angle);
}
```

Compare with the symmetric clamp in the neighbouring `Vector3Angle`:

- **File:** `utils/matrix.cpp`
- **Function:** `Vector3Angle()`
- **Lines:** `2638–2659`
- **Commit:** `d932c45b79`

```cpp
double Vector3Angle(VECTOR *v1, VECTOR *v2)
{
  double angle, l1, l2, dot, norm, x, y, z;

  ...
  norm = l1 * l2;
  if (FZERO(norm)) return (0.0f);
  dot = V3_DOT(v1, v2);
  if (fabs(dot) > fabs(norm)) norm = fabs(dot);   // symmetric clamp
  if (dot > norm)
    angle = acos(1.0);
  else
    angle = acos(dot / norm);
  return (angle);
}
```

`Vector3Angle` inflates `norm` to `|dot|` whenever `|dot| > |norm|`, so
`dot / norm` lies in `[−1, +1]` in both directions. `VectorAngle` is
missing that line.

## Root Cause

Defensive clamping against floating-point overshoot was applied only to
the upper bound of `acos`'s valid domain when `VectorAngle` was written.
The symmetric fix used in `Vector3Angle` was not mirrored.

## Impact

The function has no active in-tree callers, so the defect does not
change any current FreeSurfer output. It is nevertheless exported in
`include/matrix.h` and compiled into `libutils`; any new caller — or
any tool that picks it up while refactoring `Vector3Angle`-using code
to higher dimensions — can hit a silent `NaN` on nearly antiparallel
vectors.

## Recommended Fix

Mirror the symmetric clamp from `Vector3Angle`:

```diff
 float VectorAngle(const VECTOR *v1, const VECTOR *v2)
 {
   float angle, l1, l2, dot, norm;

   l1 = VectorLen(v1);
   l2 = VectorLen(v2);
   norm = fabs(l1 * l2);
   if (FZERO(norm)) return (0.0f);
   dot = VectorDot(v1, v2);
-  if (dot > norm)
-    angle = acos(1.0);
-  else
-    angle = acos(dot / norm);
+  if (fabs(dot) > norm) norm = fabs(dot);   // defend both ends of acos domain
+  angle = acos(dot / norm);
   return (angle);
 }
```

### Alternative Fixes Considered

Alternatively, clamp the acos input directly:
`float r = dot / norm; if (r >  1.0f) r =  1.0f; if (r < -1.0f) r = -1.0f; angle = acos(r);`.
Trade-off: one extra compare, but semantically the clearest form and
the same pattern many numerics codebases use.

## Workarounds (If Any)

Prefer `Vector3Angle` for 3-D work. For higher-dimensional inputs, clamp
the acos argument at the call site until the helper is fixed.
