# [severity-2] [bug-00118] `readBrukerVolume` hardcodes `sizeof(short)` element size; non-16-bit Bruker data is read with wrong byte counts

> [!bug] Synopsis
> ```cpp
> /* utils/Bruker.cpp:790-813 */
> switch (mri->type) {
>   case MRI_UCHAR:
>     //  size = sizeof(unsigned char);   <-- commented out
>     break;
>   case MRI_SHORT:
>     //   size = sizeof(short);          <-- commented out
>     break;
>   case MRI_FLOAT:
>     //   size = sizeof(float);          <-- commented out
>     break;
>   case MRI_INT:
>     //   size = sizeof(int);            <-- commented out
>     break;
>   case MRI_LONG:
>     //   size = sizeof(long);           <-- commented out
>     break;
>   default:
>     fprintf(stderr, "INFO: unknown size.  bail out\n");
>     return (0);
> }
>
> for (k = 0; k < mri->depth; ++k) {
>   for (j = 0; j < mri->height; ++j) {
>     nread = fread(mri->slices[k][j], sizeof(short), mri->width, fp);  /* :813 */
>     ...
> ```
>
> The switch dispatches on `mri->type`
> but each branch's only action (setting
> `size`) is commented out, leaving
> `size` unused. The subsequent
> `fread` at `:813` hardcodes the
> element size as `sizeof(short)` (2
> bytes) regardless of the actual
> volume type.
>
> Effect on the various types:
>
> | mri->type   | expected element bytes | bytes read | result |
> |-------------|------------------------|------------|--------|
> | MRI_UCHAR   | 1                      | 2          | reads twice as many bytes; row's worth of data gets squashed into mri->width shorts (= 2·mri->width bytes), overflowing the uchar buffer by mri->width bytes |
> | MRI_SHORT   | 2                      | 2          | correct ✓ |
> | MRI_FLOAT   | 4                      | 2          | reads half the bytes; the rest of the float buffer stays uninitialised, and the bytes read are mis-interpreted as float |
> | MRI_INT     | 4                      | 2          | reads half the bytes; reinterprets adjacent pairs of shorts as ints |
> | MRI_LONG    | 8                      | 2          | reads 1/4 of the bytes; rest uninitialised |
>
> Only `MRI_SHORT` (2 bytes) is correct
> by coincidence.

## Detailed Description

### Concrete corruption for 32-bit Bruker

Suppose a Bruker volume has
`RECO_wordtype = _32BIT_SGN_INT` and
`RECO_size = (64, 64, 32)`. Each
voxel on disk is 4 bytes (int32).
The on-disk row for one slice is
64*4 = 256 bytes.

`mri->type = MRI_INT`,
`mri->slices[k][j]` is a buffer
sized 64*4 = 256 bytes (one int per
voxel × 64 voxels).

The fread call:
```cpp
nread = fread(mri->slices[k][j], sizeof(short), mri->width, fp);
```
reads `mri->width = 64` shorts =
128 bytes. So only the first half
of the buffer gets data; the second
half is uninitialised.

Furthermore, those 128 bytes are
interpreted as 32 ints (since the
buffer is typed as `int *`). Adjacent
pairs of shorts get mis-read as a
single int. The file pointer advances
by 128 bytes instead of 256, so the
NEXT row's read starts at the wrong
file offset — the entire volume gets
misaligned data.

### Why 16-bit Bruker works

For `_16BIT_SGN_INT` →
`MRI_SHORT`, each voxel is 2 bytes
both on disk and in memory. The
hardcoded `sizeof(short)` matches.
This is the most common Bruker
case, so the bug evades casual
testing.

### Why the bug exists

The commented-out `size = sizeof(...)`
lines show that this used to be
dynamically sized, but at some
point the lines were commented out
(perhaps for debugging) and the
fread was not updated. The
unused `size` variable declaration
at `:777` (`// int size;`) confirms
this.

## Root Cause

The switch was likely intended to
set `size` per-type for the fread.
At some point the size assignments
were commented out (perhaps a
temporary debugging change), and
the fread was hardcoded to
`sizeof(short)` — but only the
debugging change was reverted (the
commented-out lines remain).

The `int size;` declaration is also
commented out at `:777`, confirming
the variable is never used in the
current build.

## Impact

- **16-bit Bruker (`_16BIT_SGN_INT`):**
  correct by coincidence (most
  common case).
- **32-bit Bruker (`_32BIT_SGN_INT`):**
  data corruption — half the bytes
  read, misaligned, reinterpreted.
- **Other types (UCHAR / FLOAT / LONG):**
  not produced by Bruker
  `readBrukerReco` but if forced
  via other paths, also broken.
- **Severity:** 2 — niche format,
  affects a subset of Bruker data
  files.

-      //   size = sizeof(long);

Uncomment the size assignments
and use the resulting `size` in
fread.

The `swap_bytes_flag` path
([`:821-825`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/Bruker.cpp#L821-L825))
should also be updated to swap
according to the element size
rather than hardcoded short
(currently it uses
`swab(...mri->width*sizeof(short))`).
