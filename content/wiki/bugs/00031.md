# [severity-5] [bug-00031] MostHitsInVolVox tissue-type tiebreaker tests last-segid count instead of winner's count

> [!bug] Synopsis
> `MostHitsInVolVox` decides each output voxel's segid by majority
> vote over the source-aseg voxels mapped into that output voxel.
> When a tissue-type color table is supplied, the function falls
> back to a tissue-type tiebreaker if the winning segid has fewer
> than half of the total hits. The check is written
> `if (ct && (float)nhits / N < 0.5)` — but `nhits` at that point
> holds the count of the **last segid encountered in the loop**,
> not the winner's count `nmost`. Whenever a voxel has three or
> more competing segids, the last one's count is almost always
> < 50%, so the tiebreaker fires regardless of whether the actual
> winner already has a clear majority. The output is the
> tissue-type-mode label, not the majority-vote label.

## Affected Artefacts

- **Tool(s):** [[mri_label2vol]] when invoked with the `--ttype`
  or `--ttype+head` flag (which sets `ctTissueType` non-NULL,
  enabling the tiebreaker), and [[mri_rbvpvc]] (which
  unconditionally passes `gtm->ctGTMSeg` to
  `MRIaseg2volMU`).
- **Pipeline stage(s):** _N/A_ for default [[wiki/pipelines/recon-all|recon-all]]; the
  bug fires under documented user-facing flags.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_.
- **Platforms:** all
- **Triggering configuration:**
  - `mri_label2vol --seg ASEG.mgz --ttype --temp T.mgz --o O.mgz
     ...`
  - any `mri_rbvpvc` run (always passes `ct ≠ NULL`).
  - More precisely: any output voxel whose footprint covers
    three or more distinct source-aseg labels — i.e., almost
    every voxel along an ROI boundary in the aseg.

## Detailed Description

### Expected Behaviour

The tiebreaker is documented in the function as:

```cpp
if (ct && (float)nhits / N < 0.5) {
  // no clear winner, choose one from tissue type with most representation
  ...
}
```

The intent is "if the winning segid has < 50% of the total hits,
fall back to tissue-type voting". The semantically correct test
is therefore `(float)nmost / N < 0.5`, where `nmost` is the
running maximum updated inside the main loop:

```cpp
if (nmost < nhits) {
  *segidmost = segid;
  nmost = nhits;
}
```

### Observed Behaviour

The actual test uses `nhits` rather than `nmost`. After the
outer `while (n < N)` loop terminates, `nhits` holds the count
of the **last segid encountered** in the segid-sorted iteration
order — not the maximum. For voxels with three or more
competing segids the last segid is rarely the winner, so the
fraction `nhits / N` drops below 0.5 even when the actual
winner has a clear majority.

Concrete example for one output voxel with `N = 50` source-aseg
hits:

| segid | hits | running `nmost` | running `*segidmost` |
|-------|------|-----------------|----------------------|
| 2     | 30   | 30              | 2                    |
| 41    | 15   | 30              | 2                    |
| 17    | 5    | 30              | 2                    |

After the loop, `nhits = 5`, `nmost = 30`, `*segidmost = 2`.
- Intended check: `30 / 50 = 0.6 ≥ 0.5` → no tiebreaker → return
  segid 2.
- Actual check: `5 / 50 = 0.1 < 0.5` → tiebreaker fires →
  `*segidmost` is overwritten by the most-hit segid in the
  most-represented tissue type, which may not be 2.

The "no clear winner" path therefore activates whenever the
last segid in segid-sorted order is itself a minority, which is
the typical case at any ROI boundary.

```cpp
static int MostHitsInVolVox(ASEGVOLINDEX *avindsorted, int N, int *segidmost, COLOR_TABLE *ct)
{
  int n, nhits = 0, nmost = 0, segid, nsegs;
  static int segidlist[1000], ttypelist[1000], nhitslist[1000];
  static int nPerTType[100], nPerTTypeMax, TTypeMax;

  bzero(nPerTType, sizeof(int) * 100);

  n = 0;
  nsegs = 0;
  while (n < N) {
    segid = avindsorted[n].segid;
    nhits = 0;
    while ((n + nhits < N) && (segid == avindsorted[n + nhits].segid)) nhits++;
    if (n == 0) { *segidmost = segid; nmost = nhits; }
    if (nmost < nhits) { *segidmost = segid; nmost = nhits; }
    n += nhits;
    if (ct) {
      segidlist[nsegs] = segid;
      nhitslist[nsegs] = nhits;
      ttypelist[nsegs] = ct->entries[segid]->TissueType;
      if (ct->entries[segid]->TissueType >= 0)
        nPerTType[ct->entries[segid]->TissueType] += nhits;
      /* ... */
    }
    nsegs++;
  }

  if (ct && (float)nhits / N < 0.5) {     /* ← uses last-segid `nhits`, not `nmost` */
    /* ... tissue-type tiebreaker overwrites *segidmost ... */
  }

  return (nmost);
}
```

The function's only caller — `MRIaseg2vol`'s inner loop at
[`utils/resample.cpp:2617`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/resample.cpp#L2617) —
uses the returned `nmost` and the out-parameter `*segidmost` to
decide each output voxel's label.

## Root Cause

`nhits` is the inner loop's per-segid counter. It is reset to 0
at the start of each new segid (line 2790). After the outer
`while` terminates, `nhits` retains the value from the final
inner iteration — i.e., the count of whichever segid happened
to come last in the segid-sorted order. The maximum is tracked
separately as `nmost`, but the tiebreaker condition reads
`nhits` instead.

The likely origin is a copy-rename slip: in an earlier draft
the tiebreaker may have lived inside the loop (where `nhits`
referred to the current segid's count). When it was moved to
after the loop, the variable was not renamed to `nmost`.

## Impact

- **`mri_label2vol --ttype`.** The tiebreaker's purpose is to
  resolve "ambiguous" voxels using tissue-type majority. With
  the bug, the tiebreaker fires not just for ambiguous voxels
  but for almost every boundary voxel — overriding clean
  majority decisions with tissue-type-mode decisions. The
  resulting volume's ROI labels disagree with the source aseg's
  majority in regions where the source has a clear local
  winner.
- **`mri_rbvpvc`.** The PET PVC tool builds its working
  segmentation by `MRIaseg2volMU` with `ct = gtm->ctGTMSeg`.
  Every output voxel passes through `MostHitsInVolVox` with
  `ct ≠ NULL`. The PVC matrix construction then weights the
  resampled (and biased) segmentation, propagating the
  tiebreaker bias into the partial-volume-corrected PET
  intensities.
- **Silent.** No error or warning. Output looks plausible but
  diverges from the older `--no-new-aseg2vol` voting scheme,
  which does not use the tiebreaker.
- **Latent for default [[wiki/pipelines/recon-all|recon-all]].** Recon-all does not
  invoke `mri_label2vol --ttype` or `mri_rbvpvc`.

## Recommended Fix

```diff
   nsegs++;  // keep count of number of segs
 }

-if (ct && (float)nhits / N < 0.5) {
+if (ct && (float)nmost / N < 0.5) {
   // no clear winner, choose one from tissue type with most representation
   nPerTTypeMax = 0;
   for (n = 0; n < ct->ctabTissueType->nentries; n++) {
     if (nPerTTypeMax < nPerTType[n]) {
       nPerTTypeMax = nPerTType[n];
       TTypeMax = n;
     }
   }
   *segidmost = segidlist[0];
   nmost = 0;
   for (n = 0; n < nsegs; n++) {
     if (ttypelist[n] != TTypeMax) continue;
     if (nmost > nhitslist[n]) continue;
     nmost = nhitslist[n];
     *segidmost = segidlist[n];
   }
 }
```

Single-token change: `nhits` → `nmost`.

### Alternative Fixes Considered

- **Track `nmost` and the corresponding segid as
  `nhits_winner` separately.** Functionally equivalent to
  the `nmost` rename; loses no information.
- **Document the current behaviour as "tissue-type mode" and
  rename the function to reflect that.** Rejected — the
  function's docstring and the tiebreaker comment both name
  "majority vote with tissue-type fallback for ties", which is
  the intended semantics.

## Workarounds (If Any)

- For `mri_label2vol`: drop the `--ttype` / `--ttype+head` flag
  to disable the tissue-type code path. The fallback voting
  scheme without `ct` works correctly.
- For `mri_rbvpvc`: there is no flag to disable the tissue-type
  ct, so no in-flag workaround. Patching the source is
  required.

## Confidence and Gaps

> [!gap] Latent thread-safety
> The `static int segidlist[1000]` / `nhitslist[1000]` /
> `ttypelist[1000]` / `nPerTType[100]` and uninitialised
> `static int TTypeMax` at
> [`utils/resample.cpp:2780-2781`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/resample.cpp#L2780-L2781)
> make this function non-reentrant. Current callers iterate
> single-threaded (no OpenMP wraps the loop at
> [`:2604`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/resample.cpp#L2604)),
> so this is latent. If a future refactor parallelises the
> outer loop, the static arrays will race and `TTypeMax` may
> retain a stale value from a previous call.

> [!gap] Empirical magnitude on `mri_rbvpvc`
> The PVC literature is sensitive to small per-voxel label
> changes; quantifying the divergence on a real phantom or
> patient PET dataset would set the severity tighter.
