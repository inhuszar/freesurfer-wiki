# [severity-1] [bug-00071] `CTABcountRepeats` early-termination flag breaks the wrong loop

> [!bug] Synopsis
> `CTABcountRepeats`
> ([`utils/colortab.cpp:527-546`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/colortab.cpp#L527-L546))
> documents an `int break_after_found` parameter as
> "will stop after finding the first repeat (as in
> call from `CTABunique` to prevent N^2 search)".
> The body:
>
> ```cpp
> for (i = 0; i < ct->nentries; i++) {
>   for (j = i+1; j < ct->nentries; j++) {
>     if (i == j) continue;                            /* dead — j > i */
>     if (ct->entries[i]->rf == ct->entries[j]->rf &&
>         ct->entries[i]->gf == ct->entries[j]->gf &&
>         ct->entries[i]->bf == ct->entries[j]->bf) {
>       nrepeats++;
>       if (break_after_found)
>         break;                                       /* (!) only inner */
>     }
>   }
> }
> ```
>
> The `break` exits the inner `j` loop but the
> outer `i` loop continues. So per-call cost is
> still O(nentries²) when the caller passes
> `break_after_found = 1`; the only saving is one
> inner-loop iteration per outer iteration after a
> repeat is found.
>
> Caller `CTABunique`
> ([`:502`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/colortab.cpp#L502))
> uses the return value as `if(CTABcountRepeats(ct,1)
> == 0) break;`, which still works correctly because
> the function does return the actual count — the
> only consequence is the missed early-exit
> optimisation.

## Affected Artefacts

- **Sole caller:** `CTABunique`
  ([`utils/colortab.cpp:502`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/colortab.cpp#L502))
  in a colour-table uniqueness loop. `CTABunique`
  is itself called rarely (when generating random
  unique colour tables, e.g.
  `mris_anatomical_stats`-style tools).
- **Pipeline stage(s):** none in default `recon-all`.
- **Triggering configuration:** any call to
  `CTABcountRepeats(ct, 1)` (`break_after_found ==
  1`).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

To exit the outer loop as the doc claims, a flag or
double-break is needed:

```cpp
int found = 0;
for (i = 0; i < ct->nentries && !found; i++) {
  for (j = i+1; j < ct->nentries; j++) {
    if (rgb-equal) {
      nrepeats++;
      if (break_after_found) { found = 1; break; }
    }
  }
}
```

In practice, the existing code is functionally
correct (it returns the right count, just slowly)
and the caller only checks for `==0`. The issue is
documentation-vs-implementation drift.

The redundant `if (i == j) continue;` at the start
of the inner loop is dead code — the inner loop
starts at `j = i+1`, so `j > i` always. Innocuous.

## Root Cause

`break` only exits the innermost loop. The author
intended to exit the outer scan but didn't add a
`found` flag or use a `goto`.

## Impact

- **Functional:** none. The function returns the
  correct count.
- **Performance:** O(n²) per call when caller
  passes `break_after_found = 1`. For a typical
  256-entry colour table, ~32 K comparisons per
  call. `CTABunique` calls in a retry loop until
  zero repeats; each retry is O(n²) regardless of
  the flag.
- **Severity:** very low.
