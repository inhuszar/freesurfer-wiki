# [severity-2] [bug-00074] `MRInonzeroValRange` ignores the loop's frame index

> [!bug] Synopsis
> `MRInonzeroValRange`
> ([`utils/mri.cpp:2278-2305`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L2278-L2305))
> computes the min/max of nonzero voxel values across
> all frames of the input volume. The body iterates
> `frame = 0..nframes-1` but the inner `MRIgetVoxVal`
> call hard-codes the frame index to 0:
>
> ```cpp
> for (frame = 0; frame < mri->nframes; frame++) {
>   for (z = 0; z < depth; z++) {
>     for (y = 0; y < height; y++) {
>       for (x = 0; x < width; x++) {
>         val = MRIgetVoxVal(mri, x, y, z, 0);    /* :2293 — should be `frame` */
>         if (FZERO(val)) continue;
>         if (val < fmin) fmin = val;
>         if (val > fmax) fmax = val;
>       }
>     }
>   }
> }
> ```
>
> For multi-frame inputs, frames 1..nframes-1 are
> never read; the same frame-0 voxel grid is rescanned
> `nframes` times, returning the min/max of frame 0
> alone. Latent for typical single-frame callers
> (binary masks, segmentations, paths volumes) where
> `nframes == 1` and the bug doesn't change behaviour.

## Detailed Description

Compare with the parallel `MRIvalRangeFrame`
([`utils/mri.cpp:2308`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L2308))
which takes an explicit `frame` parameter and reads
`MRIgetVoxVal(mri, x, y, z, frame)` correctly, and
with `MRIvalRange`
([`:2179`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L2179))
which iterates frames and reads
`MRIFseq_vox(mri, …, frame)` correctly per type
branch.

`MRInonzeroValRange` is the only one of the three that
hard-codes the frame index to 0.

## Root Cause

Copy-paste / typo. The author copied the iteration
shell from `MRIvalRange` but didn't update the
`MRIgetVoxVal` call to use the loop variable.

## Impact

- **Latent for single-frame inputs.** All in-tree
  callers pass binary masks (typically single-frame).
- **Active for multi-frame inputs.** Returns
  frame-0 min/max instead of across-frame
  min/max. Affects MI / DCT-alignment cost
  computations on multi-frame inputs (rare but
  possible).
- **Severity:** low.

Single-character fix.

## Workarounds

For multi-frame inputs, call `MRIvalRangeFrame` per
frame and aggregate.
