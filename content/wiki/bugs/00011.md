# [severity-3] [bug-00011] MRIvote — final-run handler forgets Exclude0; returns 0 at all-zero voxels with 100% confidence

> [!bug] Synopsis
> `MRIvote` in `utils/mri2.cpp` picks the most frequent value across
> frames at each voxel. Its in-loop run-length tracker correctly skips
> runs of value `0` when the caller passes `Exclude0 = 1`, but the
> post-loop "last run" handler (lines 2129–2135) does not repeat that
> check. At any voxel whose final sorted run is a run of zeros —
> which includes every voxel where all frames are `0` — the handler
> sets `vmax = 0` and records a confidence fraction of up to `1.0`,
> silently overriding the `Exclude0` contract. The `mri_concat
> --vote-ex0` command line exposes this path directly.

## Affected Artefacts

- **Tool(s):** [[mri_concat]] — the `--vote-ex0` flag routes through
  [`mri_concat/mri_concat.cpp:642`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_concat/mri_concat.cpp#L642),
  which calls `MRIvote(mri_in, mask, NULL, VoteExclude0=1)`.
- **Pipeline stage(s):** _N/A_ — `mri_concat --vote` is not part of
  [[recon-all]] itself. Commonly used in downstream group pipelines
  that aggregate per-subject segmentation frames (e.g., majority
  voting for multi-atlas label fusion).
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit
  `d932c45b79`.
- **Platforms:** all — purely logical.
- **Triggering configuration:** `mri_concat ... --vote-ex0 ...` on
  any input with voxels where every frame is 0, or where the sorted
  run of zeros happens to be the last run (i.e., the voxel has no
  non-zero values, or in any input type where zero sorts to the end).
  For the standard integer/float sort used here (ascending), zeros
  sort to the start, so the bug manifests primarily at voxels that
  are zero in every frame.

## Detailed Description

`MRIvote` sorts the frames at each voxel and walks through the sorted
sequence tracking run lengths. When a new value is encountered
(`v0 != v`), the in-loop code records the just-finished run of `v0`
as a candidate for the longest run, guarded by an `Exclude0` check:

```cpp
if (v0 != v) {
  runlen = f - f0;
  int skip = 0;
  if (v0 == 0 && Exclude0) skip = 1;
  if (runlenmax < runlen && !skip) {
    runlenmax = runlen;
    vmax = v0;
  }
  v0 = v;
  f0 = f;
}
```

The last run in the sequence never triggers a `v0 != v` transition
(it ends at the loop boundary, not because a new value appears), so a
separate post-loop block records it:

```cpp
// Need to do this one more time in case last value
// has the longest run
runlen = f - f0;
if (runlenmax < runlen) {
  runlenmax = runlen;
  vmax = v0;
  v0 = v;
  f0 = f;
}
```

The post-loop block is missing the `if (v0 == 0 && Exclude0) skip = 1`
guard. Whenever the final run's value is `0` and `Exclude0` is set,
the handler still updates `runlenmax` and `vmax`.

### Expected Behaviour

With `Exclude0 = 1`, `MRIvote` should return, at each voxel, the most
frequent **non-zero** value across frames. For voxels where every
frame is zero, the function should either leave the output untouched
(default-initialised to 0 with confidence 0) or explicitly report
`vmax = 0` with confidence `0.0` — never a positive confidence that
would be interpreted downstream as "the vote decided".

### Observed Behaviour

For a voxel with sorted frames `[0, 0, 0, 0]` and `Exclude0 = 1`:

- The in-loop transitions never occur (`v0 == v` every iteration).
- The post-loop block evaluates `runlen = f - f0 = nframes - 0 =
  nframes`. Since `runlenmax` is still `0`, the block fires: it sets
  `runlenmax = nframes`, `vmax = v0 = 0`.
- The voxel's first output frame is `0`.
- The voxel's second output frame — the "fraction of occurrences" —
  is `runlenmax / nframes = 1.0`.

Downstream consumers reading the vote volume will see a
full-confidence "the vote decided on label 0" at every voxel that
happened to be zero in every input, defeating the caller's
intent to exclude zeros.

The same defect also affects voxels with any sort order that leaves
a zero-valued run as the final run. For the standard ascending sort
over non-negative integer labels this is limited to all-zero voxels,
but the defect is structurally present regardless of sort
orientation.

### Reproducer

> [!gap] Reproducer not yet constructed
> A minimal demonstration:
>
> 1. Build a synthetic 3D multi-frame volume `all_zero.mgz` whose
>    every frame is identically zero at every voxel.
> 2. `mri_concat all_zero.mgz --vote-ex0 vote.mgz`
> 3. Inspect `vote.mgz`: frame 0 will read `0` everywhere, frame 1
>    will read `1.0` everywhere — "100% confidence that the vote is
>    zero", contradicting `Exclude0 = 1`.

## Code Reference (Unambiguous)

- **File:** `utils/mri2.cpp`
- **Function:** `MRIvote()`
- **Lines:** `2063–2144` (full function); defect at `2129–2135`
- **Commit:** `d932c45b79`

```cpp
MRI *MRIvote(MRI *in, MRI *mask, MRI *vote, int Exclude0)
{
  /* ... sort, allocate output ... */
  for (c = 0; c < ncols; c++) {
    for (r = 0; r < nrows; r++) {
      for (s = 0; s < nslices; s++) {
        if (mask) {
          m = MRIgetVoxVal(mask, c, r, s, 0);
          if (m < 0.5) continue;
        }
        vmax = 0;
        runlenmax = 0;
        v0 = MRIgetVoxVal(sorted, c, r, s, 0);
        f0 = 0;
        f = 1;
        while (f < nframes) {
          v = MRIgetVoxVal(sorted, c, r, s, f);
          if (v0 != v) {
            runlen = f - f0;
            int skip = 0;
            if (v0 == 0 && Exclude0) skip = 1;     // in-loop guard
            if (runlenmax < runlen && !skip) {
              runlenmax = runlen;
              vmax = v0;
            }
            v0 = v;
            f0 = f;
          }
          f++;
        }
        // Need to do this one more time in case last value
        // has the longest run
        runlen = f - f0;
        if (runlenmax < runlen) {                  // ← no Exclude0 check
          runlenmax = runlen;
          vmax = v0;
          v0 = v;
          f0 = f;
        }
        MRIsetVoxVal(vote, c, r, s, 0, vmax);
        MRIsetVoxVal(vote, c, r, s, 1, (double)runlenmax / nframes);
      }
    }
  }
  return (vote);
}
```

The asymmetry between the in-loop `skip` guard (inside the
`if (v0 != v)` branch) and the post-loop block is the defect.

## Root Cause

The post-loop block was added to close an off-by-one in the run-length
enumerator (the last run has no trailing transition). The author
correctly copied the body of the in-loop branch but dropped the
`Exclude0` guard. Because the guard is only relevant for runs of
zero, and the sorted-ascending input puts all-zero voxels into the
post-loop path, the defect's footprint is confined to the exact
case the `Exclude0` flag was designed to handle.

## Impact

- **`mri_concat --vote-ex0`.** Every all-zero voxel in the input
  gets `vmax = 0` with frequency `1.0` in the output vote volume,
  defeating the caller's `--vote-ex0` intent. Downstream tools that
  treat the "fraction" frame as a confidence measure cannot
  distinguish an all-zero voxel from a unanimous nonzero vote.
- **Downstream pipelines.** Any multi-atlas label-fusion or
  group-level majority-vote workflow that uses
  `mri_concat --vote-ex0` and thresholds on the frequency frame will
  admit all-zero voxels at full confidence, biasing the labelled
  region outward into background.
- **`mri_concat --vote` (Exclude0 = 0).** Unaffected — when
  Exclude0 is off the defective branch is reachable but produces
  the same value it would have anyway.
- [[recon-all]] does not call `mri_concat --vote-ex0` directly, so
  the recon-all pipeline is not affected. The defect is
  recon-all-adjacent: it lives in `libutils` code used by several
  recon-all helper binaries, but its specific manifestation is
  confined to `mri_concat`.

## Recommended Fix

Mirror the in-loop guard inside the post-loop block:

```diff
   // Need to do this one more time in case last value
   // has the longest run
   runlen = f - f0;
-  if (runlenmax < runlen) {
+  int skip = 0;
+  if (v0 == 0 && Exclude0) skip = 1;
+  if (runlenmax < runlen && !skip) {
     runlenmax = runlen;
     vmax = v0;
     v0 = v;
     f0 = f;
   }
```

After the fix, an all-zero voxel with `Exclude0 = 1` leaves
`runlenmax = 0` and `vmax = 0`, so the output is `(0, 0.0)` —
unambiguously "no vote" rather than "unanimously zero".

### Alternative Fixes Considered

Factoring the run-close bookkeeping into a helper used by both the
in-loop transition and the post-loop block. The helper avoids
diverging branches and would structurally prevent this class of
defect in future edits; cost is one additional small function.

## Workarounds (If Any)

For callers of `mri_concat --vote-ex0` that only want to act on
voxels with at least one non-zero frame, post-mask the output vote
volume: compute a max-across-frames mask of the input
(`mri_concat in.mgz --max nz_mask.mgz`) and zero out the vote volume
wherever `nz_mask == 0`.
