# MatrixSVDInverse allocates m_Ut as (cols × cols) instead of (cols × rows); rectangular inputs corrupt memory

> [!bug] Synopsis
> `MatrixSVDInverse` is documented (in its own inline comment) to
> compute the Moore–Penrose pseudoinverse via `V · Σ⁺ · Uᵀ`. The
> required dimensions are `m_Ut: (cols × rows)`, `m_w: (cols × cols)`,
> `m_V: (cols × cols)`. The code's comment at
> [`utils/matrix.cpp:1893`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1893)
> states `m_Ut is (cols x rows)` but the allocation at line 1898
> uses `MatrixAlloc2(cols, cols, ...)`. For any input matrix `m`
> with `rows > cols`, the subsequent `MatrixTranspose(m_U, m_Ut)`
> writes `m_Ut->rptr[col][row]` for `row` up to `rows` — past the
> per-row `cols + 1` floats actually allocated — corrupting
> adjacent rows of `m_Ut`. The diagonal-fill loop at lines
> 1881-1886 has the symmetric overrun on `m_w` and reads `v_w`
> (allocated `1 × cols`) at indices up to `rows`. **Latent in
> v$FREESURFER_VERSION** — every in-tree caller passes a square
> matrix.

## Detailed Description

### Expected Behaviour

For input `m` of size `(rows × cols)` with `rows ≥ cols`, the
Moore–Penrose pseudoinverse is

```
m⁺  =  V · Σ⁺ · Uᵀ        of size (cols × rows)
```

where the thin-SVD components are

```
U : (rows × cols)
Σ : (cols × cols)  diagonal
V : (cols × cols)
```

so the temporaries needed by the implementation are

```
m_U  : (rows × cols)        copy of m
m_w  : (cols × cols)        diagonal of inverted singular values
m_Ut : (cols × rows)        Uᵀ
m_V  : (cols × cols)        right singular vectors
```

The function's own inline comment at
[`utils/matrix.cpp:1888-1894`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1888-L1894)
reproduces this layout:

```
// m_w  is (cols x cols)
// m_U  is (rows x cols)
// m_Ut is (cols x rows)
// (cols x cols) * (cols x rows) is (cols, rows) which is what m_tmp needs to be
```

### Observed Behaviour

The actual allocations at
[`utils/matrix.cpp:1898`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1898)
allocate `m_Ut` as `(cols × cols)` — not `(cols × rows)`:

```cpp
MATRIX *m_Ut  = MatrixAlloc2(cols, cols, MATRIX_REAL, &m_Ut_buffer);
m_Ut = MatrixTranspose(m_U, m_Ut);
```

`MatrixTranspose` does **not** reallocate when its destination is
non-NULL (see
[`utils/matrix.cpp:1086-1106`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1086-L1106));
it writes `mOut->rptr[col][row] = mIn->rptr[row][col]` for
`col ∈ [1, cols]` and `row ∈ [1, rows]`. For `m_U` of size
`(rows × cols)` with `rows > cols`, the inner index `row` exceeds
`cols`. Because each row pointer in a `(cols × cols)` matrix only
addresses `cols + 1` floats, writing `m_Ut->rptr[col][row]` for
`row > cols` writes into the data of subsequent row pointers —
silent in-place corruption.

The diagonal-fill loop at
[`utils/matrix.cpp:1881-1886`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1881-L1886)
exhibits the same shape mismatch:

```cpp
float wmin = TOO_SMALL * wmax;
for (row = 1; row <= rows; row++) {
  if (fabs(RVECTOR_ELT(v_w, row)) < wmin)
    m_w->rptr[row][row] = 0.0f;
  else
    m_w->rptr[row][row] = 1.0f / RVECTOR_ELT(v_w, row);
}
```

`v_w` is allocated `(1 × cols)` at line 1863; reading
`RVECTOR_ELT(v_w, row)` for `row > cols` reads past the row
vector. `m_w` is `(cols × cols)`; writing `m_w->rptr[row][row]`
for `row > cols` writes past the row-pointer array.

For square (`rows == cols`) inputs everything is in bounds and
the routine produces a numerically correct inverse — which is
why the defect has not been observed.

### Reproducer

```c
/* Pseudoinverse of a tall (5 × 3) matrix that should succeed. */
MATRIX *m = MatrixAlloc(5, 3, MATRIX_REAL);
/* fill m with arbitrary non-singular content */
MATRIX *m_pinv = MatrixSVDInverse(m, NULL);   /* expects (3 × 5) result */
/* Expected: m_pinv well-defined; m_pinv * m ≈ I_3.
 * Observed: m_Ut overrun corrupts internal state during transpose;
 *           result matrix contents are silently wrong, possibly
 *           with adjacent allocations corrupted depending on the
 *           memory allocator's slop. */
```

- **File:** [`utils/matrix.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp)
- **Function:** `MatrixSVDInverse()`
- **Lines:** [`1844-1919`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1844-L1919)
  (defects at `:1873`, `:1881-1885`, `:1898`)
- **Commit:** `d932c45b79`

```cpp
MATRIX *MatrixSVDInverse(MATRIX *m, MATRIX *m_inverse)
{
  int const rows = m->rows;
  int const cols = m->cols;

  m_U = MatrixAlloc2(rows, cols, MATRIX_REAL, &m_U_buffer);
  m_U = MatrixCopy(m, m_U);
  m_V = MatrixAlloc2(cols, cols, MATRIX_REAL, &m_V_buffer);
  v_w = MatrixAlloc2(1, cols, MATRIX_REAL, &v_w_buffer);          /* (1 × cols) */

  if (OpenSvdcmp(m_U, v_w, m_V) != NO_ERROR) { ... }

  m_w = MatrixAlloc2(cols, cols, MATRIX_REAL, &m_w_buffer);       /* (cols × cols) */

  float wmax = 0.0f;
  for (row = 1; row <= rows; row++)                               /* ← `rows`, not `cols` */
    if (fabs(RVECTOR_ELT(v_w, row)) > wmax)                       /* OOB read on v_w
                                                                     when rows > cols */
      wmax = fabs(RVECTOR_ELT(v_w, row));

  float wmin = TOO_SMALL * wmax;
  for (row = 1; row <= rows; row++) {                             /* same overrun */
    if (fabs(RVECTOR_ELT(v_w, row)) < wmin)
      m_w->rptr[row][row] = 0.0f;                                 /* OOB write on m_w
                                                                     when rows > cols */
    else
      m_w->rptr[row][row] = 1.0f / RVECTOR_ELT(v_w, row);
  }

  // m_w  is (cols x cols)
  // m_U  is (rows x cols)
  // m_Ut is (cols x rows)                                        /* ← intent */
  // (cols x cols) * (cols x rows) is (cols, rows) which is what m_tmp needs to be

  MATRIX *m_Ut  = MatrixAlloc2(cols, cols, MATRIX_REAL, &m_Ut_buffer);   /* ← (cols × cols),
                                                                            not (cols × rows) */
  m_Ut = MatrixTranspose(m_U, m_Ut);                              /* writes
                                                                     m_Ut->rptr[col][row]
                                                                     for row ∈ [1, rows];
                                                                     overflows row buffer
                                                                     when rows > cols */

  MATRIX *m_tmp = MatrixAlloc2(cols, rows, MATRIX_REAL, &m_tmp_buffer);  /* correctly sized */
  m_tmp         = MatrixMultiply(m_w, m_Ut, m_tmp);
  m_inverse     = MatrixMultiply(m_V, m_tmp, m_inverse);
  /* ... cleanup ... */
}
```

`MatrixTranspose` for reference at
[`utils/matrix.cpp:1086-1106`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1086-L1106)
shows that the destination dimensions are not validated when a
non-NULL `mOut` is passed:

```cpp
MATRIX *MatrixTranspose(MATRIX *mIn, MATRIX *mOut)
{
  if (!mOut) {
    mOut = MatrixAlloc(mIn->cols, mIn->rows, mIn->type);
    /* ... */
  }
  /* (no dimension check on caller-provided mOut) */
  for (row = 1; row <= rows; row++)
    for (col = 1; col <= cols; col++)
      mOut->rptr[col][row] = mIn->rptr[row][col];
  return (mOut);
}
```

## Root Cause

The author wrote the dimension comment correctly — `m_Ut is (cols
x rows)` at line 1893 — but typed `cols, cols` instead of
`cols, rows` in the `MatrixAlloc2` call at line 1898. The same
mental shortcut leaked into the loop bound (`row <= rows` when
the storage is sized for `cols`) at lines 1877 and 1881.
`MatrixTranspose` does not validate caller-supplied destination
dimensions, so the bug stays silent — corrupting memory rather
than crashing on a size check.

## Impact

- **Latent in v$FREESURFER_VERSION.** Every in-tree caller listed
  above passes a square matrix (covariance / scatter / Gram
  forms). With `rows == cols` the loop bound and the `(cols ×
  cols)` allocation coincide and no overrun occurs.
- **Heap corruption when triggered.** A future caller that
  invokes `MatrixSVDInverse` on a tall matrix (the documented
  Moore–Penrose use case) will, depending on the allocator's
  slop and the buffered `MatrixBuffer` layout, either corrupt
  adjacent stack data (since `MatrixBuffer` is stack-resident)
  or corrupt subsequent rows of `m_Ut`. Result: silently wrong
  pseudoinverse, possibly downstream crashes.
- **Correctness regression on a function whose name documents
  rectangular support.** "SVD pseudoinverse" implies non-square
  capability; the function will appear to work, then drift on
  validation matrices.
- **No memory error reported.** No bounds check, no allocator
  guard, no error return — the silent corruption continues to the
  end of the routine.

## Recommended Fix

```diff
-  MATRIX *m_Ut  = MatrixAlloc2(cols, cols, MATRIX_REAL, &m_Ut_buffer);
+  MATRIX *m_Ut  = MatrixAlloc2(cols, rows, MATRIX_REAL, &m_Ut_buffer);
   m_Ut = MatrixTranspose(m_U, m_Ut);
```

Combined with cap'ing the loop bound to `cols` (the actual
dimension of `v_w` and the diagonal of `m_w`):

```diff
-  for (row = 1; row <= rows; row++)
+  for (row = 1; row <= cols; row++)
     if (fabs(RVECTOR_ELT(v_w, row)) > wmax) wmax = fabs(RVECTOR_ELT(v_w, row));

   float wmin = TOO_SMALL * wmax;
-  for (row = 1; row <= rows; row++) {
+  for (row = 1; row <= cols; row++) {
     if (fabs(RVECTOR_ELT(v_w, row)) < wmin)
       m_w->rptr[row][row] = 0.0f;
     else
       m_w->rptr[row][row] = 1.0f / RVECTOR_ELT(v_w, row);
   }
```

Optionally also harden `MatrixTranspose` at
[`utils/matrix.cpp:1086-1106`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L1086-L1106)
to verify caller-supplied destination dimensions:

```diff
   if (!mOut) {
     mOut = MatrixAlloc(mIn->cols, mIn->rows, mIn->type);
     if (!mOut) return (NULL);
   }
+  else if (mOut->rows != mIn->cols || mOut->cols != mIn->rows) {
+    ErrorReturn(NULL, (ERROR_BADPARM,
+      "MatrixTranspose: dst (%d x %d) wrong shape for transpose of (%d x %d)",
+      mOut->rows, mOut->cols, mIn->rows, mIn->cols));
+  }
```

Without this hardening, future callers that miscompute output
dimensions will encounter the same class of silent corruption.

### Alternative Fixes Considered

- **Restrict to square inputs explicitly.** Add an
  `if (rows != cols) ErrorReturn(...)` at the top of
  `MatrixSVDInverse`. Loses the Moore–Penrose contract that the
  function name implies; rejected.
- **Use SVD utility from a numerical library.** Replace the
  ad-hoc loop with a call to a vetted pseudoinverse routine.
  Larger refactor; not necessary for the immediate fix.

## Workarounds (If Any)

- Callers needing the pseudoinverse of a tall matrix can compute
  the normal-equations form `(MᵀM)⁻¹ Mᵀ` by hand: form `MᵀM`
  (square), invert with `MatrixSVDInverse` (currently safe for
  square), and post-multiply by `Mᵀ`. Loses numerical
  conditioning advantages of direct SVD-pinv but stays inside
  the safe envelope.

## Confidence and Gaps

> [!gap] Heap-corruption blast radius
> The `MatrixBuffer` argument allows `m_Ut` to be allocated on
> the stack (when the buffer is large enough) or on the heap (via
> `posix_memalign`). The blast radius — adjacent locals on the
> stack vs. the next allocation on the heap — depends on which
> path is taken at the time of the call. This has not been
> measured.

> [!gap] OpenSvdcmp guarantees
> The analysis assumes `OpenSvdcmp` returns singular values in
> `v_w[1..cols]` and only writes within that range. If
> `OpenSvdcmp` itself writes past `cols` (e.g., for `rows < cols`
> degenerate cases), there could be an _additional_ overrun
> earlier in the function. The OpenSvdcmp implementation has not
> been independently audited.
