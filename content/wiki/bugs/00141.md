# [severity-3] [bug-00141] `mri_fuse_intensity_images` Parzen-window intensity-coherence loop writes back into the same buffer it reads from — output is order-dependent and silently biased

> [!bug] Synopsis
> ```cpp
> /* mri_fuse_intensity_images/mri_fuse_intensity_images.cpp:425-454 */
> static int
> normalize_timepoints_with_parzen_window(MRI *mri, double cross_time_sigma)
> {
>   int   frame1, frame2, x, y, z ;
>   double val0, val, total, g, norm, total_norm ;
>
>   norm = 1 / sqrt(2 * M_PI * SQR(cross_time_sigma)) ;
>   for (x = 0 ; x < mri->width ; x++)
>     for (y = 0 ; y < mri->height ; y++)
>       for (z = 0 ; z < mri->depth ; z++)
>       {
>         if (x == Gx && y == Gy && z == Gz)
>           DiagBreak() ;
>         for (frame1 = 0 ; frame1 < mri->nframes ; frame1++)
>         {
>           val0 = MRIgetVoxVal(mri, x, y, z, frame1) ;
>           for (total = total_norm = 0.0, frame2 = 0 ; frame2 < mri->nframes ; frame2++)
>           {
>             val = MRIgetVoxVal(mri, x, y, z, frame2) ;
>             g = norm * exp( - SQR(val-val0) / (2 * SQR(cross_time_sigma))) ;
>             total += g*val ;
>             total_norm += g ;
>           }
>           total /= total_norm ;
>           MRIsetVoxVal(mri, x, y, z, frame1, total) ;       /* writes back into the same volume the next iter reads */
>         }
>       }
>
>   return(NO_ERROR) ;
> }
> ```
>
> The intent is a per-voxel adaptive (Parzen-window-weighted) average across time points, with the kernel centred on each `frame1`'s *original* value. Because every iteration of the outer `frame1` loop overwrites the result at `(x,y,z,frame1)` before the loop moves on, the next iteration reads a mixture of original and already-smoothed neighbour values:
>
> - `frame1 = 0`: kernel weights are computed against `val0 = original[0]`; neighbour `val[k]` for `k = 0..N-1` are all the originals. Output is the correct Parzen-weighted mean.
> - `frame1 = 1`: kernel is centred on `val0 = original[1]`. But `val[0]` is now the *smoothed* output from the previous iteration, not the original. So weight `g(|original[1] − smoothed[0]|)` is wrong by however far the smoothing pulled `[0]` toward `[1]`.
> - `frame1 = k > 0`: all frames `< k` are read in their smoothed form; only frames `≥ k` are still original. The output mixes pre-smoothed and post-smoothed neighbour intensities, and the kernel weights are computed against the wrong differences.
>
> Two user-visible consequences:
>
> 1. **Order-dependent output.** The result depends on the order of the input time points listed in the longitudinal TP file (`argv[1]`). Permuting two rows of the time-point file (which is just a roster) changes the per-frame outputs.
> 2. **Asymmetric coupling.** Late frames are pulled toward early frames more strongly than the reverse, because early frames are smoothed first and then act as the (now-shrunk) neighbours for late frames. The longer the time-point list, the worse the asymmetry: with `N ≥ 3` frames, the last frame is smoothed against `N−1` *already smoothed* neighbours.
>
> Effect on the RMS diagnostic printed at [`:198`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_fuse_intensity_images/mri_fuse_intensity_images.cpp#L198) / [`:209`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_fuse_intensity_images/mri_fuse_intensity_images.cpp#L209) (`MRIrmsDiff(mri_frame1, mri_frame2)` before/after intensity cohering): the RMS still decreases — pulling early frames toward late ones and then late toward (already-pulled) early ones is a net contraction — so the printout misleadingly looks like the function is working.

## Detailed Description

`mri_fuse_intensity_images` is the FreeSurfer command-line wrapper that pre-normalises the per-time-point intensities of a longitudinal MR dataset so that downstream tools (`mri_concat`, `mri_robust_template`, `mri_average`, segmentations on the long. base) see a coherent intensity scale at each anatomical voxel. The chosen mechanism (per the function name and the published longitudinal pipeline rationale) is a *per-voxel adaptive average*: at each `(x,y,z)`, replace each frame's value with a Parzen-window-weighted mean of all frames' values at the same voxel, where the kernel weights down frames whose value is far from the current frame's value (i.e., the frames most likely to be from a different tissue / partial volume).

### Expected Behaviour

For each `(x,y,z)`, compute the smoothed time series in one pass using only the **original** input values:

```
out[k] = ( Σ_j  g(|orig[k] − orig[j]|) · orig[j] )
       / ( Σ_j  g(|orig[k] − orig[j]|) )
```

In particular `out[k]` should depend only on `orig[0..N−1]`, never on any `out[j]`. Permuting the input frames should permute the output frames in the same way (`out` should be a *frame-permutation-equivariant* function of `orig`).

### Observed Behaviour

`out[k]` depends on `out[0..k−1]` (the previously-written outputs), not `orig[0..k−1]`. Concretely:

```
out[0] = ( Σ_j  g(|orig[0] − orig[j]|) · orig[j] )
       / ( Σ_j  g(|orig[0] − orig[j]|) )                          (correct)

out[1] = ( g(|orig[1] − out[0]|) · out[0]                          (wrong term)
         + Σ_{j≥1} g(|orig[1] − orig[j]|) · orig[j] )
       / ( g(|orig[1] − out[0]|)
         + Σ_{j≥1} g(|orig[1] − orig[j]|) )
```

— and so on. The kernel is being evaluated against `(x,y,z,frame2)` values that may be from a *different* row of the Parzen-smoothed output, not from the original input. Equivalently: the function performs one Gauss–Seidel sweep of an iterated smoother instead of one Jacobi sweep of the documented Parzen-window estimator.

### Reproducer

```bash

# at one voxel, in two different orderings of the time points; run the
# tool and observe that the outputs differ.

# Step 1: synthesise two TP files containing the same three subjects in
# different orders (the file is a list of timepoint subject IDs).
cat > tp.A.txt <<EOF
subj_t0
subj_t1
subj_t2
EOF
cat > tp.B.txt <<EOF
subj_t2
subj_t1
subj_t0
EOF

# Step 2: run twice with the same transform / input volume / mask.
mri_fuse_intensity_images \
    tp.A.txt nu.mgz noxform fused.A.mgz
mri_fuse_intensity_images \
    tp.B.txt nu.mgz noxform fused.B.mgz

# Step 3: compare. For a frame-permutation-equivariant normaliser, the
# A output and the (reverse-permuted) B output should match. They do not.
mri_diff --abs --thresh 0.001 fused.A.mgz fused.B.mgz
```

```cpp
static int
normalize_timepoints_with_parzen_window(MRI *mri, double cross_time_sigma)
{
  int   frame1, frame2, x, y, z ;
  double val0, val, total, g, norm, total_norm ;

  norm = 1 / sqrt(2 * M_PI * SQR(cross_time_sigma)) ;
  for (x = 0 ; x < mri->width ; x++)
    for (y = 0 ; y < mri->height ; y++)
      for (z = 0 ; z < mri->depth ; z++)
      {
        if (x == Gx && y == Gy && z == Gz)
          DiagBreak() ;
        for (frame1 = 0 ; frame1 < mri->nframes ; frame1++)
        {
          val0 = MRIgetVoxVal(mri, x, y, z, frame1) ;
          for (total = total_norm = 0.0, frame2 = 0 ; frame2 < mri->nframes ; frame2++)
          {
            val = MRIgetVoxVal(mri, x, y, z, frame2) ;        /* :442  ← reads the buffer being mutated */
            g = norm * exp( - SQR(val-val0) / (2 * SQR(cross_time_sigma))) ;
            total += g*val ;
            total_norm += g ;
          }
          total /= total_norm ;
          MRIsetVoxVal(mri, x, y, z, frame1, total) ;        /* :448  ← writes back; corrupts read at the next frame1 */
        }
      }


  return(NO_ERROR) ;
}
```

## Root Cause

The outer `frame1` loop both reads from and writes to the same `mri` volume on the same voxel. The author appears to have written a Jacobi-style smoother (each output frame is a function of all input frames) but implemented it Gauss–Seidel-style (each output frame is a function of the previously-written output frames and the not-yet-overwritten input frames). The fix needed is a one-extra-volume (or one-extra-row) scratch buffer: collect the smoothed values for all `frame1 ∈ [0, nframes)` at each voxel before writing any of them back.

Note that the sister function [`normalize_timepoints`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_fuse_intensity_images/mri_fuse_intensity_images.cpp#L346-L420) (the `if (0)`-gated alternative) does *not* have this bug — it uses a separate `mri_bias` volume and a separate `mri_target` volume, then applies the bias correction once per frame via `MRImultiply` at [`:405`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_fuse_intensity_images/mri_fuse_intensity_images.cpp#L405). The Parzen-window variant was added later (post-import; the file header credits Bruce Fischl but the function looks like a quick rewrite) and the scratch-volume discipline was dropped.

## Impact

- **Output silently wrong.** Every invocation of `mri_fuse_intensity_images` returns intensity-cohered volumes that depend on time-point ordering. The fact that they look smoother than the inputs (RMS reported drops) is misleading — they are smoother in a frame-asymmetric way.
- **Downstream contamination is real but narrow.** `mri_fuse_intensity_images` is invoked manually (no in-tree script calls it on a default path — confirmed by `grep -rn mri_fuse_intensity_images scripts/ distribution/` returning zero hits). Users who do invoke it (longitudinal cross-time intensity normalisation, multi-spectral / multi-modal cohering, longitudinal SAMSEG pre-processing) get biased outputs; downstream `mri_robust_template`, `mri_average`, and segmentation steps will use the biased frames as if they were correctly cohered, but the bias is per-voxel-small (kernel-bounded by `cross_time_sigma`) so the downstream effects are subtle, not catastrophic.
- **Reproducibility hazard.** Studies that re-run `mri_fuse_intensity_images` after reordering the time-point file (a routine bookkeeping operation) get different fused volumes — a silent reproducibility failure that does not flag itself.
- **Not on `recon-all`.** This is severity 3, not 4, because the tool requires explicit standalone invocation; `recon-all`/`recon-all -long` does not invoke it.

## Recommended Fix

Allocate a scratch row of `nframes` doubles (or a scratch volume the size of `mri`) and write into the scratch on the inner loop; copy back to `mri` only after the inner `frame1` loop finishes for the current voxel.

Minimal in-place fix (per-voxel temporary row, no extra volume allocation):

```diff
 static int
 normalize_timepoints_with_parzen_window(MRI *mri, double cross_time_sigma)
 {
   int   frame1, frame2, x, y, z ;
-  double val0, val, total, g, norm, total_norm ;
+  double val0, val, total, g, norm, total_norm ;
+  double *out ;
+
+  out = (double *)calloc(mri->nframes, sizeof(double)) ;
+  if (!out) ErrorExit(ERROR_NOMEMORY,
+                      "normalize_timepoints_with_parzen_window: failed to alloc %d doubles",
+                      mri->nframes) ;

   norm = 1 / sqrt(2 * M_PI * SQR(cross_time_sigma)) ;
   for (x = 0 ; x < mri->width ; x++)
     for (y = 0 ; y < mri->height ; y++)
       for (z = 0 ; z < mri->depth ; z++)
       {
         if (x == Gx && y == Gy && z == Gz)
           DiagBreak() ;
         for (frame1 = 0 ; frame1 < mri->nframes ; frame1++)
         {
           val0 = MRIgetVoxVal(mri, x, y, z, frame1) ;
           for (total = total_norm = 0.0, frame2 = 0 ; frame2 < mri->nframes ; frame2++)
           {
             val = MRIgetVoxVal(mri, x, y, z, frame2) ;
             g = norm * exp( - SQR(val-val0) / (2 * SQR(cross_time_sigma))) ;
             total += g*val ;
             total_norm += g ;
           }
-          total /= total_norm ;
-          MRIsetVoxVal(mri, x, y, z, frame1, total) ;
+          out[frame1] = total / total_norm ;
         }
+        for (frame1 = 0 ; frame1 < mri->nframes ; frame1++)
+          MRIsetVoxVal(mri, x, y, z, frame1, out[frame1]) ;
       }

+  free(out) ;
   return(NO_ERROR) ;
 }
```

This adds `nframes * sizeof(double)` of allocation (≪ 1 KB for typical longitudinal cohort sizes), and re-uses the buffer across all voxels. It restores the documented Jacobi-style semantics: each output frame depends only on the original input frames.

### Alternative Fixes Considered

- **Whole-volume scratch.** `MRI *mri_out = MRIclone(mri, NULL); ... MRIsetVoxVal(mri_out, ...); MRIcopy(mri_out, mri); MRIfree(&mri_out);` — clearer but doubles peak memory.
- **Cache `val[frame2]` into a row once per voxel** and reuse for both `frame1 = 0` and `frame1 > 0`. This is a separate optimisation; the correctness fix above is independent.

## Workarounds (If Any)

- **Pin time-point ordering across re-runs.** Always pass the time-point list in the same canonical order (e.g., chronological) so that the (silently biased) output at least matches between runs.
- **Skip the tool.** The longitudinal pipeline (`recon-all -base`, `recon-all -long`) does not require `mri_fuse_intensity_images` — it is an opt-in preprocessing step. Most users do not invoke it.

## Confidence and Gaps

> [!gap] Order of magnitude of the bias
> The in-place mutation is unambiguous. What is not quantified is the *magnitude* of the resulting bias under typical `cross_time_sigma` values (the tool default is `0.0` — meaning the function would short-circuit because `norm` is undefined; in practice users pass `-cross_time_sigma N` to set it). A small `σ` produces near-identity weights (kernel concentrates on frames with similar intensity) and the bias is small; a large `σ` flattens the kernel and the bias is large. A grid sweep over `σ ∈ {1, 5, 10, 25}` on a 3-time-point cohort would put a number on it.

> [!gap] Author intent
> An alternative reading is that the author *intended* a Gauss–Seidel-style iterative refinement, not a Parzen-window estimate. Under that reading the function would still be buggy in three ways: (a) it does only one Gauss–Seidel pass, not until convergence; (b) the function name and the `g = norm * exp(-…)` formulation say "Parzen window" not "iterated smoother"; (c) the per-voxel result depends on the (arbitrary) input ordering of frames. So even on that interpretation, the function is wrong; the fix is still the scratch-buffer rewrite.
