# [severity-3] [bug-00163] epidewarp.fsl — --unwarpdir parses into a misspelled variable, so the unwarp axis is always y

> [!bug] Synopsis
> In `scripts/epidewarp.fsl`, the `--unwarpdir` command-line handler stores
> its argument in a **misspelled** variable, `undwarpdir` (note the extra
> `d`), which is never read anywhere else. The value that FUGUE actually
> uses is `$unwarpdir`, which is only ever assigned its hard-coded default
> `y`. As a result, `--unwarpdir x` (or any other axis) is silently ignored,
> and B0 unwarping is always performed along the `y` axis. A user with a
> non-`y` phase-encode direction gets a geometrically wrong voxel-shift map
> with no error.

## Affected Artefacts

- **Tool(s):** [[epidewarp.fsl]] — B0 fieldmap-based EPI distortion
  correction (front end for FSL's PRELUDE/FUGUE).
- **Pipeline stage(s):** _N/A_ — `epidewarp.fsl` is a standalone tool; it is
  not on the default [[wiki/pipelines/recon-all|recon-all]] path.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — pure tcsh variable handling.
- **Triggering configuration:** any invocation that passes `--unwarpdir`
  with a value other than `y` (e.g. `--unwarpdir x`, `--unwarpdir y-`).
  The default `y` masks the defect because the intended and actual axes
  coincide.

## Detailed Description

`epidewarp.fsl` lets the user choose the unwarp (phase-encode) axis with
`--unwarpdir`, documented as taking `x/y/z/x-/y-/z-`
([`scripts/epidewarp.fsl:885`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/epidewarp.fsl#L885)).
The variable is declared with default `y` at
[`scripts/epidewarp.fsl:37`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/epidewarp.fsl#L37)
and is consumed by the FUGUE call that builds the voxel-shift map at
[`scripts/epidewarp.fsl:392-393`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/epidewarp.fsl#L392-L393):

```tcsh
set cmd = (fugue -i $mag -u $magdw -p $ph2 --unwarpdir=$unwarpdir\
    --dwell=$esp --asym=$tediff --mask=$mask --saveshift=$vsmmag);
```

The argument parser, however, writes the user's value into a different,
misspelled variable:

```tcsh
    case "--unwarpdir":
      if ( $#argv == 0) goto arg1err;
      set undwarpdir = $argv[1]; shift;
      breaksw
```

`undwarpdir` (with the transposed `dw` → `dwa` typo producing `undwarp...`)
is set and then never referenced again anywhere in the script. The
correctly-spelled `unwarpdir` that FUGUE reads keeps its default `y`.

### Expected Behaviour

`epidewarp.fsl --unwarpdir x ...` should run FUGUE with `--unwarpdir=x`, so
the voxel shifts are computed along the x axis (matching an x phase-encode
acquisition).

### Observed Behaviour

`--unwarpdir x` sets `undwarpdir = x`. `unwarpdir` remains `y`. The FUGUE
command emitted at
[`scripts/epidewarp.fsl:392`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/epidewarp.fsl#L392)
contains `--unwarpdir=y` regardless of the requested axis. The unwarp axis
is silently wrong; there is no error or warning.

### Reproducer

```bash
# Isolated demonstration of the parser defect (verbatim case body):
cat > /tmp/repro.csh <<'CSH'
#!/bin/tcsh -f
set unwarpdir = y
set flag = "--unwarpdir"
set argv = (x)
switch($flag)
  case "--unwarpdir":
    set undwarpdir = $argv[1]; shift;
    breaksw
endsw
echo "undwarpdir (typo, unused) = $undwarpdir"
echo "unwarpdir  (used by fugue) = $unwarpdir"
CSH
tcsh -f /tmp/repro.csh
# prints:
#   undwarpdir (typo, unused) = x
#   unwarpdir  (used by fugue) = y     <-- user value ignored
```

A full run with `--unwarpdir x --debug` would echo the FUGUE command line
(via the `echo $cmd` at
[`scripts/epidewarp.fsl:395`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/epidewarp.fsl#L395))
showing `--unwarpdir=y`.

A whole-file search confirms `undwarpdir` occurs exactly once (the parser
line); `unwarpdir` occurs at the default, the FUGUE call, and the usage
string only.

## Root Cause

Single-character typo in the parser: the case body assigns `undwarpdir`
instead of `unwarpdir`. Because tcsh creates variables on first assignment
and does not warn about an unread variable, the misspelling is silent.

## Impact

- For any acquisition whose phase-encode direction is not the FUGUE default
  `y`, the voxel-shift map is computed along the wrong axis, so the dewarped
  EPI/exf is distorted incorrectly. The output is **silently wrong** — no
  error, no warning.
- For the (common) case where the data really is y phase-encoded, the
  default `y` happens to be correct, so the defect is invisible. This is why
  it has gone unnoticed.
- Severity is **3 (medium)**: the defect only manifests when the user opts
  into a non-`y` axis via `--unwarpdir`; the default path produces correct
  output. `epidewarp.fsl` is a standalone auxiliary tool and is not on a
  default user-facing pipeline.

## Recommended Fix

Fix the variable name in the parser so it matches the consumer:

```diff
     case "--unwarpdir":
       if ( $#argv == 0) goto arg1err;
-      set undwarpdir = $argv[1]; shift;
+      set unwarpdir = $argv[1]; shift;
       breaksw
```

After the change, the user's axis flows into the FUGUE `--unwarpdir=` option.

### Alternative Fixes Considered

None needed; the one-character correction is unambiguous.

## Workarounds (If Any)

There is no command-line way to change the unwarp axis with the current
code. A user whose data is not y phase-encoded must either patch the parser
line locally or call FUGUE directly with the correct `--unwarpdir`.
