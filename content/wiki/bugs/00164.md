# [severity-2] [bug-00164] fsl_rigid_register — -nocleanup/-cleanup set an unread variable, so temp files are always deleted

> [!bug] Synopsis
> In `scripts/fsl_rigid_register`, the `-nocleanup` and `-cleanup` flags
> assign to a variable named `nocleanup`, but the cleanup decision at the end
> of the script tests a **different** variable, `$cleanup`. Nothing ever
> reads `nocleanup`, and nothing in the flag handlers writes `cleanup`. As a
> result, `-nocleanup` is non-functional: `$cleanup` keeps its default value
> `1`, so the temporary directory (and the init transform) are deleted
> regardless of the flag. The user cannot preserve the intermediate files
> via `-nocleanup`.

## Affected Artefacts

- **Tool(s):** [[fsl_rigid_register]] — wrapper around FSL's `flirt`.
- **Pipeline stage(s):** _N/A_ — standalone registration helper, not on the
  default [[wiki/pipelines/recon-all|recon-all]] path.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — pure tcsh control flow.
- **Triggering configuration:** any invocation that passes `-nocleanup`
  expecting the temp directory to survive. (`-cleanup` is also a no-op, but
  its intended effect — deletion — coincides with the default, so it is
  harmless.)

## Detailed Description

`fsl_rigid_register` creates a temporary working directory and, when
`-initgeom` is on, an init FSL matrix
([`scripts/fsl_rigid_register:87-90`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsl_rigid_register#L87-L90),
[`scripts/fsl_rigid_register:132-133`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsl_rigid_register#L132-L133)).
At the end it conditionally deletes them based on `$cleanup`, which is
initialised to `1` at
[`scripts/fsl_rigid_register:35`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsl_rigid_register#L35):

```tcsh
# Cleanup
if($cleanup) then
  echo "Cleaning up"
  if($initgeom) rm $initxfm
  rm -rf $tmpdir
endif
```

The `-nocleanup` and `-cleanup` flag handlers, however, write a variable
named `nocleanup`, not `cleanup`:

```tcsh
    case "-nocleanup":
      set nocleanup = 0;
      breaksw

    case "-cleanup":
      set nocleanup = 1;
      breaksw
```

`nocleanup` is created here and never read anywhere in the script. The
`$cleanup` that actually governs deletion is only ever changed by the
`-tmp`/`-tmpdir` handler (which sets `cleanup = 0` at
[`scripts/fsl_rigid_register:372`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsl_rigid_register#L372)).
So `-nocleanup` on its own leaves `cleanup = 1` and the temp files are
removed.

(As a secondary oddity, the handler mapping is itself inverted —
`-nocleanup` sets `nocleanup = 0` and `-cleanup` sets `nocleanup = 1` —
but this is moot because the variable is never consulted.)

### Expected Behaviour

`fsl_rigid_register ... -nocleanup` should preserve `$tmpdir` and the init
matrix after the run, exactly as the usage text promises
("`-nocleanup` : do not delete temporary files",
[`scripts/fsl_rigid_register:533`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsl_rigid_register#L533)).

### Observed Behaviour

`-nocleanup` sets `nocleanup = 0`, which nothing reads. `$cleanup` stays `1`,
so the `if($cleanup)` block runs and `rm -rf $tmpdir` deletes the temporary
directory. The flag has no effect.

### Reproducer

```bash
# Isolated demonstration of the parser/consumer mismatch:
cat > /tmp/repro.csh <<'CSH'
#!/bin/tcsh -f
set cleanup = 1
set flag = "-nocleanup"
switch($flag)
  case "-nocleanup":
    set nocleanup = 0;
    breaksw
endsw
echo "nocleanup (set, unused) = $nocleanup"
echo "cleanup   (governs rm)  = $cleanup"
if($cleanup) echo "  => tmpdir WILL be deleted despite -nocleanup"
CSH
tcsh -f /tmp/repro.csh
# prints: cleanup=1 and "tmpdir WILL be deleted despite -nocleanup"
```

[`scripts/fsl_rigid_register:35`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsl_rigid_register#L35)

line 261 and written only at lines 35 and 372; `nocleanup` is written only
at lines 422 and 426 and read nowhere.

## Root Cause

Variable-name mismatch between the flag handlers (`nocleanup`) and the
cleanup decision (`cleanup`). The handlers should assign `cleanup` directly,
with the correct polarity.

## Impact

- `-nocleanup` is silently ignored: a user who wants to inspect the
  intermediate FSL matrices or the converted ANALYZE/NIFTI volumes finds the
  temp directory already deleted. This is a debugging/QA inconvenience, not a
  corruption of the registration output.
- The script's primary outputs (the resampled volume, `.fslmat`, and any
  requested `register.dat`/`xfm`/`lta`) are written outside `$tmpdir` and are
  unaffected.
- Severity is **2 (low)**: the defect is latent under normal use (it only
  affects a diagnostic option that controls retention of temporary files);
  it does not change the registration result. `-cleanup` is also a no-op but
  its intended behaviour matches the default, so it is harmless.

## Recommended Fix

Make the handlers assign the variable that is actually tested, with correct
polarity (`-nocleanup` ⇒ do not clean up ⇒ `cleanup = 0`):

```diff
     case "-nocleanup":
-      set nocleanup = 0;
+      set cleanup = 0;
       breaksw

     case "-cleanup":
-      set nocleanup = 1;
+      set cleanup = 1;
       breaksw
```

### Alternative Fixes Considered

Alternatively, introduce a real `nocleanup` variable and test `if(!
$nocleanup)` at the cleanup site. This is more invasive and inconsistent
with `-tmp`/`-tmpdir`, which already manipulate `cleanup` directly; the
two-site fix above is preferred.

## Workarounds (If Any)

To retain the temporary files, pass `-tmp <dir>` (or `-tmpdir <dir>`), which
sets `cleanup = 0` as a side effect
([`scripts/fsl_rigid_register:368-373`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsl_rigid_register#L368-L373))
and so does preserve the directory. This is the documented behaviour of
`-tmp` and works today.
