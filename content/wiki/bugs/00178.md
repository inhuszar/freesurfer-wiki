# [severity-2] [bug-00178] mkheadsurf — dilation test reads undefined `$dilate` instead of `$ndilate`, aborting the `-ndilate`/`-nerode` post-processing block

> [!bug] Synopsis
> In `mkheadsurf`, the optional post-segmentation dilate/erode block is
> entered when the user passes `-ndilate N` or `-nerode N`. Inside that
> block the dilation is gated by `if($dilate > 0)`, but the variable is
> spelled `$dilate` — a name that is **never set anywhere in the
> script**. Every other reference (the default, the `-ndilate` parser,
> the `--dilate` argument, the usage text) uses `$ndilate`. Under the
> script's `tcsh -f` shebang, referencing the undefined `$dilate`
> raises `dilate: Undefined variable.` and **aborts the script with
> non-zero status** the moment the dilate/erode block runs — so not
> only does `-ndilate` fail to add the dilation, the whole run dies
> before tessellation whenever `-ndilate` or `-nerode` is used.

## Affected Artefacts

- **Tool(s):** [[mkheadsurf]] — head-surface generation wrapper.
- **Pipeline stage(s):** _N/A_ — `mkheadsurf` is run manually to build
  `seghead` surfaces; it is not on the default
  [[wiki/pipelines/recon-all|recon-all]] path.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — tcsh variable-name typo.
- **Triggering configuration:** the defective line is reached only when
  the enclosing `if($ndilate != 0 || $nerode != 0)` is true, i.e. when
  the user passes `-ndilate N` (N ≠ 0) **or** `-nerode N` (N ≠ 0). The
  default invocation (no dilation/erosion) never enters the block and is
  unaffected.

## Detailed Description

After segmenting the head with `mri_seghead`, `mkheadsurf` optionally
post-processes the binary head mask with `mri_binarize`, dilating it by
`$ndilate` voxels and/or eroding it by `$nerode` voxels. The block is:

```tcsh
if($ndilate != 0 || $nerode != 0) then
  set cmd = (mri_binarize --i $OutputVol --min 0.5 \
    --o $OutputVol --binval $fillval)
  if($dilate > 0) set cmd = ($cmd --dilate $ndilate)
  if($nerode > 0) set cmd = ($cmd --erode $nerode)
  ...
endif
```

The guard `if($dilate > 0)` is supposed to read the same counter used
both for the enclosing test and for the `--dilate` argument value,
namely `$ndilate`. Instead it reads `$dilate`, which the script never
defines.

### Expected Behaviour

When the user runs `mkheadsurf ... -ndilate 2`, the head mask should be
dilated by 2 voxels: the block should evaluate `if($ndilate > 0)` as
true and append `--dilate 2` to the `mri_binarize` command.

### Observed Behaviour

The block evaluates `if($dilate > 0)` where `$dilate` is undefined.
Under `tcsh -f`, an undefined-variable reference is a fatal error, not
an empty expansion:

```
dilate: Undefined variable.
```

The script terminates immediately with non-zero exit status at that
line. Because the dilate/erode block sits **before** tessellation,
smoothing and inflation, the entire `mkheadsurf` run fails whenever
`-ndilate` or `-nerode` is requested — the surface is never produced.
(If `-nerode N` is given without `-ndilate`, the block is still entered
via the `|| $nerode != 0` clause, and the very next line —
`if($dilate > 0)` — dies before the erode line is ever reached.)

Even if `tcsh` were configured to treat the undefined variable as
empty (it is not, under `-f`), the dilation would simply never be
added: the option would be a silent no-op. Either way the `-ndilate`
control does not take effect as written.

### Reproducer

```bash
# The undefined-variable abort, reproduced in isolation:
tcsh -f -c 'set ndilate = 2; set nerode = 0
set cmd = (mri_binarize --foo)
if($ndilate != 0 || $nerode != 0) then
  if($dilate > 0) set cmd = ($cmd --dilate $ndilate)
  echo "reached: $cmd"
endif'
# → prints: dilate: Undefined variable.   (and exits non-zero;
#   "reached:" is never printed)
```

A full reproducer:

```bash
mkheadsurf -i /path/T1.mgz -o /tmp/seghead.mgz \
           -surf /tmp/lh.seghead -ndilate 2
# → aborts with "dilate: Undefined variable." before tessellation
```

- **Function:** top-level script body (post-`mri_seghead` block)

```tcsh

      --o $OutputVol --binval $fillval)

    echo $cmd |& tee -a $LF

```

The variable is declared as `$ndilate` (default `0`) at
[`scripts/mkheadsurf:42`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mkheadsurf#L42),
set by the parser at
[`scripts/mkheadsurf:246`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mkheadsurf#L246)
(`case "-ndilate":`), used in the enclosing guard at
[`scripts/mkheadsurf:126`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mkheadsurf#L126),
and used as the `--dilate` value at
[`scripts/mkheadsurf:129`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mkheadsurf#L129)
— but the **test** on that same line 129 reads the never-set
`$dilate`. A `grep` for `set dilate` in the script returns nothing.

## Root Cause

A variable-name typo: `$dilate` was written where `$ndilate` was meant.
The mismatch is on a single line —
[`scripts/mkheadsurf:129`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/mkheadsurf#L129)
— which simultaneously reads the wrong name in the test (`$dilate`) and
the right name in the argument value (`$ndilate`), making the typo easy
to miss. Under `tcsh -f`, an undefined variable in a conditional is a
hard error, so the consequence is an abort rather than a silent skip.

## Impact

- **`-ndilate` / `-nerode` are unusable.** Any `mkheadsurf` invocation
  that passes a non-zero `-ndilate` or `-nerode` aborts with
  `dilate: Undefined variable.` before the head surface is tessellated.
  The intended dilation/erosion of the head mask never happens.
- **Default path unaffected.** The defaults are `ndilate = 0` and
  `nerode = 0`, so the enclosing block is skipped on a standard
  `mkheadsurf` run and the surface is produced normally. This is why the
  defect is gated/latent (severity 2) rather than a default-path failure.
- **No silent wrong output.** The failure is loud (script exits
  non-zero); it does not corrupt an otherwise-successful surface.

## Recommended Fix

Spell the variable consistently as `$ndilate`:

```diff
-    if($dilate > 0) set cmd = ($cmd --dilate $ndilate)
+    if($ndilate > 0) set cmd = ($cmd --dilate $ndilate)
     if($nerode > 0) set cmd = ($cmd --erode $nerode)
```

After the change, `-ndilate N` (N > 0) correctly appends `--dilate N`
to the `mri_binarize` command, and `-nerode N` alone no longer aborts
on the preceding dilation test.

### Alternative Fixes Considered

None needed — a single-token rename resolves the defect. (One could
also pre-declare `set dilate = $ndilate`, but that adds a redundant
variable; renaming the reference is cleaner.)

## Workarounds (If Any)

Until patched, do not pass `-ndilate`/`-nerode` to `mkheadsurf`. To
dilate or erode the head mask, run `mri_binarize --i seghead.mgz
--min 0.5 --o seghead.mgz --binval 1 --dilate N` (and/or `--erode N`)
manually, then re-run `mkheadsurf -noseghead` to tessellate the edited
mask.
