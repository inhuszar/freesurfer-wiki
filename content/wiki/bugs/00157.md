# [severity-2] [bug-00157] oct_register_mosaic — registration/refinement paths are unreachable dead code (unconditional exit(0), && 0 guard, hard-disabled unwarp)

> [!bug] Synopsis
> Large parts of `oct_register_mosaic`'s advertised registration pipeline
> never run. `main()` writes a header-positioned averaged mosaic and then
> calls an **unconditional `exit(0)`**, so the per-tile Powell translation
> search, the final optical-distortion–corrected mosaic, and the
> brute-force energy-minimisation translation search that follow it are
> all unreachable dead code (two further `exit(0)`s sit inside that dead
> region). Separately, the mosaic-list-file input mode (usage 2) is gated
> behind `if (argc == 3 && 0)` — permanently false — so the program never
> reads a list file, and the optical-distortion **unwarp** is hard-disabled
> inside `undistort_and_mosaic_images` (`xu = xf ; yu = yf ; //disable
> unwarping for now`) while the `-unwarp` option handler is compiled out
> under `#if 0`. The shipped binary therefore only ever produces a
> header-positioned average (optionally a Powell-translation-refined
> average when `-U` is given), never a distortion-corrected one and never
> from a list file.

## Affected Artefacts

- **Tool(s):** [[oct_register_mosaic]]
- **Pipeline stage(s):** _N/A_ — a specialised OCT (optical coherence
  tomography) tile-mosaicking utility, not part of
  [[wiki/pipelines/recon-all|recon-all]] and with no in-tree callers.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — the dead code, the `&& 0` guard, and the disabled
  unwarp are unconditional source constructs.
- **Triggering configuration:** always on. The unconditional `exit(0)`,
  the `&& 0` list-file guard, and the hard-disabled unwarp fire on every
  invocation regardless of flags.

## Detailed Description

`oct_register_mosaic` advertises (usage strings, comment banner) optical
distortion correction and registration of OCT tiles into a mosaic. In the
shipped code, three large regions of `main()` that implement the
registration/refinement are unreachable, and two further capabilities are
disabled:

1. **Unconditional `exit(0)` truncates `main()`.** After building the
   header-positioned averaged mosaic with `mosaic_images_with_xforms`
   (and, when `-U` is set, the Powell-translation-refined
   `build_best_mosaic`), `main()` writes the result and calls `exit(0)`.
   Everything after that point is dead:
   - the `insert_image_into_mosaic` + `powell_minimize` **per-tile**
     translation/refinement loop,
   - the final `undistort_and_mosaic_images` call that would apply the
     optical-distortion model,
   - the brute-force **energy-minimisation** translation search
     (`compute_mosaic_energy` over a `±max_trans` grid),
   - and two more `exit(0)` statements that can never be reached.

2. **Mosaic-list-file input disabled by `&& 0`.** The branch that opens a
   list file and reads `x0 y0 filename` per line is guarded by
   `if (argc == 3 && 0)  // disable for now`. The `&& 0` makes the
   condition permanently false, so `fp` is always `NULL`, `nimages` is
   always `argc - 2`, and "usage 2: … `<mosaic list file>` … " never works
   — tiles can only be passed individually on the command line.

3. **Optical-distortion unwarp hard-disabled.** Even on the `-U` path that
   does run (`build_best_mosaic` → `undistort_and_mosaic_images`), the
   actual distortion resampling is bypassed: the inner loop sets
   `xu = xf ; yu = yf ; //disable unwarping for now`, with the
   `undistorted_coords(...)` call commented out and the Jacobian block
   under `#if 0`. The `-unwarp` option handler and a `hough` handler in
   `get_option` are likewise inside `#if 0`. So no optical-distortion
   correction is ever applied; `-U` performs only a Powell **translation**
   refinement of the tile offsets.

### Expected Behaviour

Per the tool's banner and usage, `oct_register_mosaic` should: (a) accept
either a list of tiles or a mosaic list file; (b) register/refine tile
placement (Powell and/or energy minimisation); and (c) optionally apply
optical-distortion unwarping to produce a corrected mosaic.

### Observed Behaviour

The binary always emits a header-positioned **averaged** mosaic (from
`mosaic_images_with_xforms`). With `-U` it instead emits a Powell-
**translation**-refined average (via `build_best_mosaic`), but still with
no distortion unwarping. The per-tile Powell loop, the distortion-corrected
final mosaic, and the energy-minimisation search never execute, and a list
file is never read. There is no error or warning — the unreachable
features simply do nothing.

### Reproducer

> [!gap] Reproducer not executed end-to-end

> dominates the trailing statements; `&& 0` is a constant-false guard;
> the unwarp assignment overrides the coordinate transform). A behavioural
> check:

> 1. Run `oct_register_mosaic tile1.mgz tile2.mgz out.mgz` and confirm the

## Root Cause

The file is mid-development scaffolding that was shipped with its
work-in-progress guards left in place: a debugging `exit(0)` was inserted
after the averaged-mosaic write to short-circuit `main()` (leaving the
later refinement/energy code stranded), the list-file path was switched
off with `&& 0  // disable for now`, and the distortion unwarp was stubbed
with `xu = xf ; yu = yf ; //disable unwarping for now`. The comments
("disable for now", "disable unwarping for now") confirm these were
intended as temporary toggles, not the final behaviour.

## Impact

- The binary does far less than its banner/usage advertise: it produces a
  header-positioned averaged (or, with `-U`, Powell-translation-refined)
  mosaic only — never a distortion-corrected mosaic, never from a list
  file, and never via the per-tile Powell loop or the energy-minimisation
  search.
- The shortfall is **silent**: the disabled features emit no warning, so a
  user who passes a list file or expects distortion correction gets a
  plausible-looking but unrefined/uncorrected mosaic.
- Severity is **2 (low)**: `oct_register_mosaic` is a niche OCT-specific
  tool with **no in-tree callers** and no place in
  [[wiki/pipelines/recon-all|recon-all]]; the default code path
  (averaged mosaic) does run and produces a usable output, and the
  affected features are advanced/optional. There is no silent corruption
  of a default pipeline result, which would be needed for a higher score.

## Recommended Fix

This is unfinished code; the correct remediation is a developer decision,
but the minimal steps to make the advertised behaviour reachable are:

```diff
@@ main() @@
   printf("writing final mosaic to %s\n", out_fname) ;
   MRIwrite(mri_mosaic, out_fname) ;
-  exit(0) ;
-
-  insert_image_into_mosaic(mri_mosaic, mri[0], x0d[0], y0d[0]) ;
+  /* fall through to the intended refinement, or gate it behind a flag */
@@ list-file guard @@
-  if (argc == 3 && 0)  // disable for now
+  if (argc == 3)       // mosaic list file (usage 2)
@@ undistort_and_mosaic_images() @@
-//	undistorted_coords(mri[i], xf, yf, ax[i], ay[i], a, b, c, d, &xu, &yu) ;
-	xu = xf ; yu = yf ;  //disable unwarping for now
+	undistorted_coords(mri[i], xf, yf, ax[i], ay[i], a, b, c, d, &xu, &yu) ;
```

and re-enable the `#if 0`-guarded `-unwarp`/`hough` handlers. Each
re-enabled path needs validation (the distortion model and per-tile Powell
loop were disabled presumably because they were not yet working), so a test
on representative OCT tiles should accompany the change.

### Alternative Fixes Considered

If the refinement/distortion paths are genuinely abandoned, the honest
alternative is to **delete** the dead code after the first `exit(0)`,
remove the `&& 0` branch, and update the usage/banner so the tool no longer
advertises list-file input or distortion correction. That removes the
silent-no-op surprise at the cost of dropping the (non-functional)
features. Choosing between re-enabling and removing is a developer call —
flagged here, not assumed.

## Workarounds (If Any)

Pass tiles individually on the command line (the list-file mode does not
work). Accept that no optical-distortion correction is applied; if
distortion correction is required, it must be done with another tool. There
is no flag that re-enables the disabled paths at runtime.

## Confidence and Gaps

> [!gap] Flag-inertness is narrower than it first appears — verified
> A loose reading suggests `-N/-S/-U/-P` are all "silently inert". That is
> only partly true and was checked against the code: the **`-U` path does
> run** — `main()` reaches
> [`build_best_mosaic`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/oct_register_mosaic/oct_register_mosaic.cpp#L312)
> at line 312, *before* the `exit(0)` at line 316, and that function does
> perform a Powell **global energy minimisation** that consumes `niters`
> (`-N`,
> [`:1223`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/oct_register_mosaic/oct_register_mosaic.cpp#L1223)),
> the blurred copies `mri_smooth` (`-S`), and `pad` (`-P`). So with `-U`,
> `-N/-S/-P` are **live** and the output is a translation-refined mosaic.
> What is genuinely dead is the **per-tile** `powell_minimize` loop, the
> **distortion-corrected** final mosaic, and the **brute-force energy
> search** after the `exit(0)`, plus the list-file input and the
> optical-distortion unwarp. Without `-U`, `-N/-S/-P` indeed have no
> effect. The tool page's gotcha that "`build_best_mosaic` sits after the
> first `exit(0)`" is inaccurate on the line ordering; this page reflects
> the verified control flow.
