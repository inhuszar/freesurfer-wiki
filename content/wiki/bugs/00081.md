# [severity-4] [bug-00081] `soap_bubble` reads one element past the end of `tmp_vals`

> [!bug] Synopsis
> `soap_bubble`
> ([`utils/dct.cpp:412-458`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/dct.cpp#L412-L458))
> smooths a 1-D array by averaging each non-control
> element with its two neighbours. The neighbour
> window is built as
>
> ```cpp
> for (out_val = 0.0, num = 0,
>      j = MAX(i - 1, 0);
>      j <= MIN(i + 1, N);            /* :447 — wrong upper bound */
>      j++, num++)
>   out_val += tmp_vals[j];
> ```
>
> `tmp_vals` is allocated with `N` elements
> ([`:417`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/dct.cpp#L417)),
> so valid indices are `0..N-1`. When the outer
> loop variable reaches `i == N - 1`, the inner
> bound `MIN(i + 1, N)` evaluates to `N`, and the
> body reads `tmp_vals[N]` — one past the buffer.
> The correct upper bound is `MIN(i + 1, N - 1)`.

## Affected Artefacts

- **Tool:** the only caller is
  `DCTinverseTransformVoxlist` /
  `inverse_dct`-style helper at
  [`utils/dct.cpp:404`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/dct.cpp#L404),
  reachable via [[mri_dct_align]] and
  [[mri_dct_align_binary]] when running the inverse
  transform for resampling.
- **Pipeline stage(s):** none in default
  `recon-all`.
- **Triggering configuration:** any
  `mri_dct_align*` invocation that calls the
  inverse-transform path (i.e. resamples the moving
  image through the inverse DCT).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/dct.cpp:412-458 */
static int soap_bubble(double *in_vals, double *ctrl, double *out_vals,
                       int N, double max_change_allowed)
{
  double *tmp_vals, max_change, change, out_val, min_val, max_val;
  int iter, i, j, num;

  tmp_vals = (double *)calloc(N, sizeof(double));    /* :417 — N elements */
  memmove(out_vals, in_vals, N * sizeof(double));
  ...
  do {
    max_change = 0;
    memmove(tmp_vals, out_vals, N * sizeof(double));
    for (i = 0; i < N; i++) {
      if (ctrl[i] > 0) { out_vals[i] = tmp_vals[i]; continue; }
      for (out_val = 0.0, num = 0,
           j = MAX(i - 1, 0); j <= MIN(i + 1, N);    /* :447 — overread */
           j++, num++)
        out_val += tmp_vals[j];
      out_vals[i] = out_val / num;
      ...
    }
    ...
  } while (max_change > 0.001);
  free(tmp_vals);
  return (NO_ERROR);
}
```

Per ASan / heap-checker, this is an
out-of-bounds read of 8 bytes per outer-loop
iteration whenever `ctrl[N-1] == 0`. Because
`calloc` initialises the buffer's pages but the
read goes one element past the *requested* size,
the value at `tmp_vals[N]` is whatever happened to
sit there in the malloc payload (frequently zero,
sometimes a metadata byte, sometimes another
allocation's tail). The averaged value at index
`N-1` is therefore mildly biased by this stray
read; `num` is also one too large for that
iteration, dividing by 4 rather than 3 and
attenuating the boundary value.

For `N == 1` the outer loop runs once with `i == 0`
and the inner loop walks `j ∈ {0, 1}` — same OOB
read.

## Root Cause

Half/half-open interval confusion. The author
treated `N` as an inclusive upper bound on the
neighbour window when in fact the array is indexed
`0..N-1`. The same pattern done correctly elsewhere
in the file uses `< N` rather than `<= N` (e.g.
the `for (i = 0; i < N; i++)` outer loop on the
preceding line).

## Impact

- **Memory safety:** consistent 8-byte
  out-of-bounds heap read on every
  `soap_bubble` iteration.
- **Numerical:** the boundary-element output
  carries a small bias from the stray read and is
  attenuated by averaging over four samples
  instead of three; with hundreds of relaxation
  iterations the effect propagates inward by the
  bias's diffusion length.
- **Severity:** low (memory-safety issue with a
  numerical effect that's small relative to the
  smoothing being performed; not in a
  default-`recon-all` path).
