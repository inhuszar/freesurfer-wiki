# [severity-3] [bug-00041] MRIresample SAMPLE_VOTE clamps every label to [0, 255] — silently corrupts aparc+aseg-style label volumes resampled with `mri_convert -rt vote`

> [!bug] Synopsis
> `MRIresampleFill` documents `SAMPLE_VOTE` as the
> recommended resampling for label volumes (see also
> `mri_convert -rt vote`). The implementation allocates a
> per-destination-voxel vote map sized
> `width × height × depth × 256` of MRI_UCHAR (one frame per
> possible label value), reads the source label as
> `val = nint(MRIgetVoxVal(src, …))` and unconditionally
> clamps `val` into `[0, 255]` before incrementing the
> count. The label-pick loop then iterates `label = 0..255`
> and writes the winner to the destination. For any label
> volume that uses identifiers above 255 — which includes
> *every* aparc/aparc-aseg volume produced by the FreeSurfer
> pipeline (cortical labels in the 1000s and 2000s, hippo
> subfields in the 200s-500s, etc.) — every high-value label
> collapses to label 255 and the destination loses the
> ability to encode any label in the 256+ range. The result
> is a near-uniform "label 255" output across most of the
> brain when a user runs `mri_convert -rt vote
> aparc+aseg.mgz -rl <template> aparc_resampled.mgz`.

- **Pipeline stage(s):** _N/A_ for default [[wiki/pipelines/recon-all|recon-all]];
  user-facing.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_ (the 256-frame vote map is the

- **Platforms:** all

  <input.mgz> -rl <template.mgz> <output.mgz>` for any

  - `aparc+aseg.mgz` (cortical IDs 1000-1035 and 2000-2035),
  - `aparc.a2009s+aseg.mgz` (IDs in 11100-12175),
  - `aparc.DKTatlas+aseg.mgz` (1000s and 2000s),

    the 200s-500s),
  - `aseg.mgz` (most labels are below 255, but `Right-Vessel`,
    `Right-Choroid-Plexus`, etc. are exactly at 60/63 — fine
    — except `WM-hypointensities` = 77, also fine; the volume
    is *not* affected unless the user has applied a custom
    LUT with high IDs).

## Detailed Description

### Expected Behaviour

`MRIresampleFill(src, template_vol, SAMPLE_VOTE, …)` should
produce a destination volume in which each voxel takes the
*most frequent label among the source voxels that fall into
its template-space cell*. The natural reader expectation —
and the documented purpose of `-rt vote` — is that *every*
distinct label in the source is preserved as a candidate
winner, regardless of its numeric ID. Sister sampling modes
(`SAMPLE_NEAREST`, `SAMPLE_TRILINEAR`) operate on the raw
voxel values via `MRIgetVoxVal` / `MRIsetVoxVal` and are not
range-restricted.

### Observed Behaviour

The vote map and accumulation loop
([`utils/mri.cpp:12140-12206`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L12140-L12206)):

```cpp
if (resample_type == SAMPLE_VOTE) {
  MRI *mri_votes;
  int count;
  MATRIX *minv;

  printf("resampling using voting...\n");
  // iterate over source voxels and vote to create dest one
  mri_votes = MRIallocSequence(template_vol->width,
                                template_vol->height,
                                template_vol->depth,
                                MRI_UCHAR, 256);                /* (a) 256 label-frames, UCHAR count */
  /* … minv / sp / dp setup … */

  for (nframe = 0; nframe < src->nframes; nframe++) {
    for (si = 0; si < src->width; si++) {
      for (sj = 0; sj < src->height; sj++) {
        for (sk = 0; sk < src->depth; sk++) {
          /* … project (si,sj,sk) → (di,dj,dk) … */
          val = nint(MRIgetVoxVal(src, si, sj, sk, nframe));
          if (val < 0)
            val = 0;
          else if (val > 255)
            val = 255;                                            /* (b) clamp [0,255] */
          count = MRIgetVoxVal(mri_votes, di, dj, dk, val);
          MRIsetVoxVal(mri_votes, di, dj, dk, val, count + 1);    /* (c) count saturates at 255 — UCHAR_MAX */
        }
      }
    }
  }
  for (nframe = 0; nframe < template_vol->nframes; nframe++) {
    int max_label, max_count, label;
    for (di = 0; di < template_vol->width; di++) {
      for (dj = 0; dj < template_vol->height; dj++) {
        for (dk = 0; dk < template_vol->depth; dk++) {
          max_label = max_count = -1;
          for (label = 0; label < 256; label++) {                  /* (d) label range [0,255] only */
            count = MRIgetVoxVal(mri_votes, di, dj, dk, label);
            if (count > max_count) {
              max_count = count;
              max_label = label;
            }
          }
          MRIsetVoxVal(dest, di, dj, dk, nframe, max_label);       /* (e) destination value ≤ 255 */
        }
      }
    }
  }
  MRIfree(&mri_votes);
}
```

Three independent pathologies:

**(b)** The `val > 255` branch *silently* maps every label
above 255 to label 255. There is no warning printed, no
error returned. For an aparc+aseg input where every voxel
has a label of either 0, an aseg ID (mostly < 255), or a
cortical ID (1000-2035), the cortical voxels all collapse
to "label 255" — which in FreeSurfer's LUT is `unknown_177`
or simply unmapped depending on the colortable.

**(d)** Even if the user works around (b) by hand-mapping
labels, the winner-selection loop `for (label = 0; label <
256; label++)` cannot select a winner above 255.

**(c)** The vote count is stored as MRI_UCHAR and saturates
at 255 (`MRIsetVoxVal` clips to `UCHAR_MAX`). When the
upsample factor (or the number of source voxels per
destination voxel) exceeds 255, the count for the most
common label saturates and ties with any other label that
also saturates can be broken arbitrarily by the
linear-scan tie-breaker (first-seen wins, since the loop is
strict `>`, not `>=`).

The combined effect: pass any of the standard FreeSurfer
parcellation volumes through `mri_convert -rt vote` and the
output is a binary "0 vs 255" near-mask — a complete
information loss.

### Reproducer

```bash
# Produce a low-resolution aparc+aseg via vote-based
# resampling. The template can be any sub-mm or supra-mm grid
# in the same RAS space.
mri_convert -rt vote \
    $SUBJECTS_DIR/$SUBJ/mri/aparc+aseg.mgz \
    -rl <some_template.mgz> \
    aparc_resampled.mgz

# Inspect the output's label range:
mri_segstats --seg aparc_resampled.mgz --sum aparc.txt --excludeid 0
# The .txt file will only contain label-255 (and possibly
# the un-clamped sub-255 aseg labels). Cortical labels in
# the 1000-2035 range are absent entirely.
```

## Root Cause

The vote-map storage was hand-sized for `MRI_UCHAR` source
volumes (e.g. raw `aseg.mgz` whose labels were originally
under 255 in older FreeSurfer versions). When the cortical
parcellation labels were extended into the 1000s/2000s, the
`SAMPLE_VOTE` path was not updated to track wider labels.

## Impact

- **`mri_convert -rt vote aparc+aseg.mgz`**: the output
  collapses every cortical label (1000-2035) into label 255,
  and the wm parcellation labels (3000-5002) similarly.
  Every column of any group analysis or volume-of-interest
  report built from the resampled output is wrong.
- **`mri_convert -rt vote aparc.a2009s+aseg.mgz`**: same as
  above but worse — Destrieux IDs are in 11100-12175 so
  even the *non-cortical* labels above 255 (CC posterior
  segments at 251-255 are at the boundary; thalamic atlas
  IDs at 8001+) collapse.
- **`mri_convert -rt vote wmparc.mgz`**: WM parcellation
  IDs (3000-5002) all collapse.
- **High-resolution → low-resolution resampling of any
  label volume with > 255 source voxels per destination
  voxel**: count saturation at 255 makes the winner
  selection arbitrary even for in-range labels.
- **Latent for default [[wiki/pipelines/recon-all|recon-all]]**: standard pipeline
  does not use `mri_convert -rt vote`.
- **Active for users who use vote-resampling** to bring
  parcellations into fMRI/PET/DTI native space, or to
  downsample for visualisation. This is a documented
  recommended workflow on the FreeSurfer FAQ for label
  volume resampling.

## Recommended Fix

The minimum fix is to size the vote map by the *actual* set
of distinct labels in the source, and to use a wide-enough
count storage to avoid saturation.

```diff
   if (resample_type == SAMPLE_VOTE) {
-    MRI *mri_votes;
-    int count;
+    MRI *mri_votes;
+    int count;
+    int *segidlist, nsegs, label2frame_max = 0;
     MATRIX *minv;
 
     printf("resampling using voting...\n");
-    mri_votes = MRIallocSequence(template_vol->width,
-                                  template_vol->height,
-                                  template_vol->depth,
-                                  MRI_UCHAR, 256);
+    /* Build the actual label list from the source so the
+       vote map covers every label that actually occurs.
+       Pre-compute a label→frame index for O(1) lookup. */
+    segidlist = MRIsegIdList(src, &nsegs, 0);
+    int max_label = 0;
+    for (int n = 0; n < nsegs; n++)
+      if (segidlist[n] > max_label) max_label = segidlist[n];
+    int *label2frame = (int *)calloc(max_label + 1, sizeof(int));
+    for (int n = 0; n < nsegs; n++) label2frame[segidlist[n]] = n;
+    /* MRI_INT count storage so we don't saturate at 255 */
+    mri_votes = MRIallocSequence(template_vol->width,
+                                  template_vol->height,
+                                  template_vol->depth,
+                                  MRI_INT, nsegs);
     /* … */
     for (nframe = 0; nframe < src->nframes; nframe++) {
       for (si = 0; si < src->width; si++) {
         for (sj = 0; sj < src->height; sj++) {
           for (sk = 0; sk < src->depth; sk++) {
             /* … project src→dst … */
             val = nint(MRIgetVoxVal(src, si, sj, sk, nframe));
-            if (val < 0)
-              val = 0;
-            else if (val > 255)
-              val = 255;
-            count = MRIgetVoxVal(mri_votes, di, dj, dk, val);
-            MRIsetVoxVal(mri_votes, di, dj, dk, val, count + 1);
+            if (val < 0 || val > max_label) continue;     /* skip OOB */
+            int fr = label2frame[val];
+            count = MRIgetVoxVal(mri_votes, di, dj, dk, fr);
+            MRIsetVoxVal(mri_votes, di, dj, dk, fr, count + 1);
           }
         }
       }
     }
     for (nframe = 0; nframe < template_vol->nframes; nframe++) {
       int max_label, max_count, label;
       for (di = 0; di < template_vol->width; di++) {
         for (dj = 0; dj < template_vol->height; dj++) {
           for (dk = 0; dk < template_vol->depth; dk++) {
             max_label = max_count = -1;
-            for (label = 0; label < 256; label++) {
+            for (int fr = 0; fr < nsegs; fr++) {
-              count = MRIgetVoxVal(mri_votes, di, dj, dk, label);
+              count = MRIgetVoxVal(mri_votes, di, dj, dk, fr);
               if (count > max_count) {
                 max_count = count;
-                max_label = label;
+                max_label = segidlist[fr];
               }
             }
-            MRIsetVoxVal(dest, di, dj, dk, nframe, max_label);
+            MRIsetVoxVal(dest, di, dj, dk, nframe, max_label > 0 ? max_label : 0);

         }
       }
     }
     MRIfree(&mri_votes);
+    free(segidlist);
+    free(label2frame);
   }
```

The fix uses `MRIsegIdList` (already in the codebase, used
by `MRIseg2SegPVF` and others) to enumerate the source's
actual labels, sizes the vote map accordingly, and stores
the count in `MRI_INT` to avoid the 255-saturation. Output
labels keep their original IDs.

### Alternative Fixes Considered

- **Refuse to vote-resample volumes with labels > 255.**
  Print an error and require the user to explicitly handle
  it. Less helpful than a correct implementation but at
  least non-silent.
- **Use a `std::map<int,int>`-per-voxel** instead of an
  MRI vote map. Cleaner code but memory- and
  cache-unfriendly for whole-brain volumes.
- **Restrict the function to MRI_UCHAR sources.** Would
  break the `mri_convert -rt vote` advertised support for
  arbitrary label volumes.

## Workarounds (If Any)

- For aparc+aseg-style label volumes, use
  `mri_label2vol --regheader` or `mri_vol2vol --interp
  nearest` followed by careful neighbourhood-mode
  smoothing — *not* `mri_convert -rt vote`.
- A two-step workaround: split the source into a stack of
  binary masks (one per label), `mri_convert -rt nearest`
  each, and reassemble — but this loses the
  partial-volume voting that is the entire point of
  `-rt vote`.
- Use `mri_label2vol --hits` + the high-resolution
  segmentation pipeline (USF=2 or 3) which uses
  `MRIseg2SegPVF` instead. That path is correct.

## Confidence and Gaps

> [!gap] Memory cost of the fixed vote map
> An aparc+aseg has roughly 200 distinct labels; sized as
> MRI_INT, the vote map is ~200 frames × 256³ × 4 bytes ≈
> 13 GB for a 1mm³ destination. That is impractical for a
> per-voxel dense map. The right fix is probably the
> std::map-per-voxel form (or the `MRIseg2SegPVF`
> sub-sampling form) for any label volume with more than a
> handful of distinct labels. The diff above demonstrates
> the *minimum* fix; production code should adopt the
> sparse-map approach.

> [!gap] Other in-tree callers of MRIresample(SAMPLE_VOTE)
> A grep finds no other in-tree caller besides
> `mri_convert`. If a user-supplied tool propagates
> `SAMPLE_VOTE` through the FreeSurfer libraries, the same
> defect applies.
