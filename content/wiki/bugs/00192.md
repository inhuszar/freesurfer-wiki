# [severity-2] [bug-00192] exvivo-hemi-proc — --rotreg checks $reg instead of $rotreg (undefined-variable error), and advertised --force has no parser case

> [!bug] Synopsis
> `exvivo-hemi-proc` has two command-line parsing defects. (1) The
> `--rotreg <file>` handler stores the argument in `$rotreg` but then
> existence-checks `$reg` — a different variable that is not defined
> until much later in the script. In tcsh, referencing the unset `$reg`
> at parse time aborts the script with `reg: Undefined variable.`, so
> `--rotreg` cannot be used at all. (2) `--force` is listed in the usage
> text (and the corresponding `ForceUpdate` flag is wired throughout),
> but there is no `case "--force"` in the parser, so passing `--force`
> hits the `default` case and exits with
> `ERROR: Flag --force unrecognized.` Both were reproduced against the
> installed 8.2.0 binary.

## Affected Artefacts

- **Tool(s):** [[exvivo-hemi-proc]]
- **Pipeline stage(s):** _N/A_ — a standalone whole-hemisphere ex-vivo
  FLASH processing driver (parameter-map fitting → masking → samseg →
  surfaces).
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — tcsh argument parsing.
- **Triggering configuration:**
  - Defect 1: any command line containing `--rotreg <file>`.
  - Defect 2: any command line containing `--force`.
  Both abort during argument parsing, before any processing.

## Detailed Description

### Defect 1 — `--rotreg` checks the wrong variable

The handler
([`scripts/exvivo-hemi-proc:483-491`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L483-L491)):

```tcsh
case "--rotreg":
  if($#argv < 1) goto arg1err;
  set rotreg = $argv[1]; shift;   # stores into $rotreg
  if(! -e $reg) then              # ← checks $reg, not $rotreg
    echo "ERROR: cannot find $reg"
    exit 1
  endif
  set DoRotate = 1
  breaksw
```

The user-supplied path is assigned to `rotreg`, but the existence test
and error message both reference `$reg`. `$reg` is not set anywhere in
the parser; it is first assigned far later, at
[`scripts/exvivo-hemi-proc:329`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L329)
(`set reg = $outdir/reg.samseg.lta`), which runs in the main body after
`parse_args` returns. Under tcsh, dereferencing an undefined variable is
a fatal error, so `if(! -e $reg)` aborts immediately with
`reg: Undefined variable.` — the script never even reaches its own
parameter checks. `--rotreg` is therefore completely unusable. (As a
secondary consequence, `$rotreg` is set but never subsequently read, so
even if the check were fixed the supplied registration is not wired into
the rotation step — but the observable, blocking bug is the undefined
`$reg` reference.)

### Defect 2 — `--force` advertised but unimplemented

The usage text lists `--force`
([`scripts/exvivo-hemi-proc:680`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L680)),
and the `ForceUpdate` variable it would set is initialised
([`scripts/exvivo-hemi-proc:10`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L10))
and consulted throughout the body (every `if($ud || $ForceUpdate)`
gate, e.g.
[`scripts/exvivo-hemi-proc:136`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L136),
[`:199`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L199),
[`:331`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L331)).
But the parser has no `case "--force":`, so `--force` falls through to
the `default` case
([`scripts/exvivo-hemi-proc:552-556`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/exvivo-hemi-proc#L552-L556))
and the script exits with `ERROR: Flag --force unrecognized.`
`ForceUpdate` can never be turned on; there is no way to force stale
steps to recompute.

### Expected Behaviour

- `--rotreg <file>` should validate that `<file>` (the supplied
  rotation registration) exists and use it for the rotation step.
- `--force` should set `ForceUpdate = 1`, causing the `$ud ||
  $ForceUpdate` gates to recompute outputs regardless of timestamps.

### Observed Behaviour

Reproduced against `/usr/local/freesurfer/8.2.0/bin/exvivo-hemi-proc`:

```text
$ exvivo-hemi-proc --rotreg /tmp/somefile.lta --o /tmp/out
reg: Undefined variable.

$ exvivo-hemi-proc --o /tmp/out --force
ERROR: Flag --force unrecognized.
--o /tmp/out --force
```

Both abort during parsing.

### Reproducer

```bash
# Defect 1: --rotreg aborts with an undefined-variable error
/usr/local/freesurfer/8.2.0/bin/exvivo-hemi-proc --rotreg /tmp/somefile.lta --o /tmp/out

/usr/local/freesurfer/8.2.0/bin/exvivo-hemi-proc --o /tmp/out --force

```

Both were run on the target system; neither requires input data because
the failure occurs in `parse_args`.

## Root Cause

- Defect 1: a variable-name slip — the handler assigns `rotreg` but the
  copied-from existence check still names `reg`. Because `reg` is unset
  during parsing (it is created later), tcsh aborts on the dereference.
- Defect 2: the `--force` option was documented and its target variable
  (`ForceUpdate`) wired into the body, but the parser `case` was never
  added.

## Impact

- Both defects are CLI-parsing failures that abort before any data
  processing, so they cannot corrupt output — hence severity 2. The tool
  is a specialised, opt-in ex-vivo driver (not part of any default
  pipeline), which also caps the reach.
- `--rotreg` is entirely unusable: any user trying to supply a
  precomputed rotation registration is stopped with a cryptic
  `reg: Undefined variable.` message.
- `--force` is unusable: a user who has partially-completed outputs and
  wants to force a recompute cannot, despite the option being advertised.
  Their only recourse is to delete intermediate files so the `UpdateNeeded`
  timestamp logic re-triggers.

## Recommended Fix

Fix the variable name in the `--rotreg` handler, and add the missing
`--force` case:

```diff
     case "--rotreg":
       if($#argv < 1) goto arg1err;
       set rotreg = $argv[1]; shift;
-      if(! -e $reg) then
-        echo "ERROR: cannot find $reg"
+      if(! -e $rotreg) then
+        echo "ERROR: cannot find $rotreg"
         exit 1
       endif
       set DoRotate = 1
       breaksw
+
+    case "--force":
+      set ForceUpdate = 1
+      breaksw
```

A natural place for the new `case "--force":` is alongside the other
0-argument flags (e.g. near `--no-rotate` / `--prep-only`).

### Alternative Fixes Considered

For `--rotreg`, beyond fixing the existence check, the handler should
also actually *use* `$rotreg` for the rotation step (it is currently set
but never read, so the rotation continues to expect the interactive
freeview-produced `log/raw-to-rotate.lta`). Wiring `$rotreg` into the
rotation LTA would complete the option's intent, but that is a feature
gap beyond the blocking parse error; the minimal fix above at least makes
`--rotreg <existing-file>` no longer abort. A maintainer should confirm
how `$rotreg` is meant to feed the rotation.

## Workarounds (If Any)

- `--rotreg`: do not pass it. Supply the rotation registration through
  the interactive path the script expects (`log/raw-to-rotate.lta` plus
  `log/rotate.template.mgz`), or `--no-rotate` if no rotation is needed.
- `--force`: do not pass it. Delete the relevant intermediate output
  files so the built-in `UpdateNeeded` timestamp checks recompute them.
