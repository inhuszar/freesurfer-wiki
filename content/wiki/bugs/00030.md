# [severity-3] [bug-00030] MRIdownsampleN reads past source boundary when dimensions are not multiples of the factor

> [!bug] Synopsis
> `MRIdownsampleN(src, dst, Fc, Fr, Fs, KeepType)` averages
> `Fc × Fr × Fs` source voxels into each destination voxel. The
> destination size is computed with `ceil()`, so when a source
> dimension is not a multiple of the corresponding factor, the
> last destination voxel's averaging window extends past the
> source boundary. The triple loop iterates `c0` from `Fc * c` up
> to (but not including) `Fc * (c + 1)` without bounds-checking
> against `src->width`/`src->height`/`src->depth`, so the
> innermost `MRIgetVoxVal(src, c0, r0, s0, f)` reads voxels that
> live in the next row, next slice, or in unrelated memory beyond
> the volume buffer. The output's last edge voxels are silently
> averaged with **wrong-row** content; the divisor is always the
> nominal `Fc * Fr * Fs`, so partial-window voxels are also
> mis-normalised.

## Affected Artefacts

- **Tool(s):** [[wiki/tools/mri_convert|mri_convert]] `--downsample DSx DSy DSz` (the
  primary user-facing entry point) and [[mri_gtmpvc]]
  ([`mri_gtmpvc.cpp:2038`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_gtmpvc/mri_gtmpvc.cpp#L2038)).
- **Pipeline stage(s):** _N/A_ for default [[wiki/pipelines/recon-all|recon-all]] (which
  does not invoke `mri_convert --downsample` on non-conformed
  inputs); the bug is a user-facing defect.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_.
- **Platforms:** all
- **Triggering configuration:** any `mri_convert --downsample F1
  F2 F3` invocation where at least one of:
  - `src->width % F1 != 0` (e.g., a `192×256×192` T1 with `F1 =
    F2 = F3 = 3`)
  - `src->height % F2 != 0`
  - `src->depth % F3 != 0`
  - `F1`, `F2`, `F3` non-integer (the function accepts `float`
    factors per its actual signature, even though the docstring
    says `int`).

  Realistic triggers: `mri_convert --downsample 3 3 3 input.mgz
  output.mgz` on most fMRI volumes (typical 64×64×30 to
  96×96×80, none of which are multiples of 3); any
  non-conformed T1; any non-power-of-two factor.

## Detailed Description

### Expected Behaviour

`MRIdownsampleN` should average over a window of source voxels
that **lies within the source volume**. For a destination voxel
`(c, r, s)` produced by integer downsample factor `F`, the
correct window is

```
c0 ∈ [F·c, min(F·(c+1), src->width))
r0 ∈ [F·r, min(F·(r+1), src->height))
s0 ∈ [F·s, min(F·(s+1), src->depth))
```

and the divisor should be the **actual** in-bounds count, not
the nominal `F³`. For non-integer factors, the window placement
is itself ambiguous; the function should either reject
non-integer factors or document the precise rounding rule.

### Observed Behaviour

The averaging block at
[`utils/mri.cpp:7856-7872`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L7856-L7872):

```cpp
for (f = 0; f < dst->nframes; f++) {
  for (c = 0; c < dst->width; c++) {
    for (r = 0; r < dst->height; r++) {
      for (s = 0; s < dst->depth; s++) {
        val = 0;
        for (c0 = Fc * c; c0 < Fc * (c + 1); c0++) {
          for (r0 = Fr * r; r0 < Fr * (r + 1); r0++) {
            for (s0 = Fs * s; s0 < Fs * (s + 1); s0++) {
              val += MRIgetVoxVal(src, c0, r0, s0, f);   /* ← OOB on edge */
            }
          }
        }
        MRIsetVoxVal(dst, c, r, s, f, val / (Fc * Fr * Fs));
      }
    }
  }
}
```

`dst->width = ceil(src->width / Fc)` (line 7814). For
`src->width = 256, Fc = 3`, `dst->width = 86`, and the last
`c = 85` gives `c0 ∈ [255, 258)` — `c0 = 256, 257` are out of
bounds. `MRIgetVoxVal` does not bounds-check positive
coordinates (cf. its bounds-check block at
[`utils/mri.cpp:1628-1632`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L1628-L1632),
which only guards `< 0`), so the read goes through the access
macro
([`include/mri.h:1480`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mri.h#L1480))
to `((BUFTYPE *)mri->slices[s + f*depth][r])[c0]`, indexing
past the row's allocated `width` elements into either the
adjacent row's storage (chunked allocations are contiguous) or
unrelated memory.

For typical chunked layouts the read returns the **first
voxels of the next row**, so the averaging silently mixes
columns from one row with columns of the next row of the source
volume. The output is biased on the +x face of the destination;
analogous biases occur on the +y and +z faces when `height` and
`depth` are not multiples.

The divisor `Fc * Fr * Fs` in the final
`MRIsetVoxVal(dst, ..., val / (Fc * Fr * Fs))` is the **nominal**
window size — independent of how many in-bounds voxels were
actually read. Even if the OOB reads were silenced (e.g., by
clamping with `MRIgetVoxValSafe` or `if (c0 >= src->width)
continue`), the divisor would still be wrong for partial
windows, biasing the edge voxels by the missing contribution.

### Reproducer

```bash
# Trigger 1: non-divisible source dimension with integer factor
mri_convert --downsample 3 3 3 \
    /usr/local/freesurfer/subjects/bert/mri/orig.mgz \
    out.mgz                # orig.mgz is 256³; 256 % 3 = 1
# Inspect last-row voxels of out.mgz against a reference
# computed manually with the in-bounds-only window.

# Trigger 2: non-integer downsample factors
mri_convert --downsample 1.5 1.5 1.5 input.mgz out.mgz
# Window placement is non-uniform and bounds-violating from the
# very first destination voxel (c=1, c0 ∈ [1.5, 3.0) → c0 = 1, 2;
# c=0, c0 ∈ [0, 1.5) → c0 = 0, 1; voxel 1 contributes to both
# output voxels — overlapping windows).
```

the de facto contract.

## Root Cause

Two independent issues, both affecting the same edge of the
output:

1. **No bounds clamp on the inner-loop indices.** When
   `src->width % Fc != 0` (or analogously for height/depth), the
   `ceil()` rounding at the destination side guarantees that
   `Fc * (c + 1) > src->width` for `c = dst->width − 1`. The
   inner loop reads `c0 = src->width, src->width + 1, …` past
   the source boundary.
2. **Nominal divisor for partial windows.** The final
   `val / (Fc * Fr * Fs)` is the average over the
   nominal-size window. Even if (1) were patched (e.g., by
   clamping `c0 < min(Fc * (c + 1), src->width)`), the divisor
   would still be wrong: a partial window of `2` voxels divided
   by `3` under-weights the edge voxels by 33%.

For non-integer factors, the float-to-int truncation in
`c0 = Fc * c` produces non-uniform window placement and
overlapping windows (e.g., `Fc = 1.5` gives windows `[0, 1.5)`,
`[1.5, 3.0)`, `[3.0, 4.5)` → integer windows `{0,1}`, `{1,2}`,
`{3,4}` — voxel 1 belongs to two output voxels). This is a
separate semantics issue regardless of bounds.

## Impact

- **`mri_convert --downsample F1 F2 F3` on any non-conformed
  input.** Conformed FreeSurfer volumes are 256³ (or
  256×256×256), and `F = 2` divides cleanly. Any other source
  shape — typical for fMRI (e.g., 64×64×40), DTI (e.g., 96³),
  high-resolution structural (e.g., 320×320×224), or any
  user-supplied volume that does not match the conformed shape
  — is at risk. Edge voxels of the output are biased by
  wrong-row content from the source.
- **`mri_gtmpvc`.** The PET partial-volume correction tool
  invokes `MRIdownsampleN(src, NULL, Fc, Fr, Fs, 0)` to build
  its low-resolution working volume. PET volumes are typically
  smaller and rarely match the downsample factor exactly, so
  the bug fires routinely. The downsampled PET data has biased
  edge voxels, propagating into the PVC correction.
- **Silent.** No error, no warning, no `NULL` return — just
  wrong values at the boundary.
- **Latent for default [[wiki/pipelines/recon-all|recon-all]].** Recon-all does not
  exercise `MRIdownsampleN` on its conformed 256³ volumes with
  any factor that doesn't divide 256.

```diff
         for (s = 0; s < dst->depth; s++) {

-              for (s0 = Fs * s; s0 < Fs * (s + 1); s0++) {
-                val += MRIgetVoxVal(src, c0, r0, s0, f);
-              }
-            }
-          }
-          MRIsetVoxVal(dst, c, r, s, f, val / (Fc * Fr * Fs));
+          val = 0;
+          int n = 0;
+          int c0_lo = (int)(Fc * c),       c0_hi = (int)(Fc * (c + 1));
+          int r0_lo = (int)(Fr * r),       r0_hi = (int)(Fr * (r + 1));
+          int s0_lo = (int)(Fs * s),       s0_hi = (int)(Fs * (s + 1));
+          if (c0_hi > src->width)  c0_hi = src->width;
+          if (r0_hi > src->height) r0_hi = src->height;
+          if (s0_hi > src->depth)  s0_hi = src->depth;
+          for (c0 = c0_lo; c0 < c0_hi; c0++) {
+            for (r0 = r0_lo; r0 < r0_hi; r0++) {
+              for (s0 = s0_lo; s0 < s0_hi; s0++) {
+                val += MRIgetVoxVal(src, c0, r0, s0, f);
+                n++;
+              }
+            }
+          }
+          MRIsetVoxVal(dst, c, r, s, f, n > 0 ? val / n : 0);
         }
       }
     }
   }
```

Two changes: clamp each inner loop's upper bound to the actual
source extent, and divide by the **actual** count of voxels read
rather than the nominal `Fc * Fr * Fs`. Also fix the docstring at
`:7778` to reflect the `float` signature.

### Alternative Fixes Considered

- **Reject non-divisible inputs.** Add `if (src->width % (int)Fc
  != 0 || ...) return ErrorReturn(NULL, ...)` and require integer
  factors. Cleaner contract but breaks `mri_gtmpvc` and any
  user that already accepts edge biasing. Rejected as too
  restrictive.
- **Pad the source before downsampling.** Pad with zeros to a
  multiple of the factor, then downsample. Mathematically clean
  but allocates a copy of the source.

## Workarounds (If Any)

- Pre-pad or pre-crop the source so its dimensions are exact
  multiples of the desired factor before invoking
  `mri_convert --downsample`.
- For an exact integer factor, ensure the source is conformed
  to a multiple of that factor first via `mri_convert
  --conform_min` or an equivalent reshape.

## Confidence and Gaps

> [!gap] Empirical magnitude
> The numerical magnitude of edge-voxel divergence has not been
> measured. For a row-major chunked allocation, the OOB read
> picks up the first columns of the next row in the source —
> intensities that for a typical anatomical or PET volume can
> be very different from the nominal-window content (e.g.,
> background voxels at the start of the next row vs. brain
> voxels at the end of the current row). End-to-end measurement
> on a 192³ T1 with `--downsample 3 3 3` would quantify the
> bias.

> [!gap] Non-integer factor semantics
> The float-factor case is also problematic (overlapping
> windows, non-uniform placement) but is more a design issue
> than an OOB bug. A separate fix or a hard
> `assert(Fc == (int)Fc)` would clarify the contract.
