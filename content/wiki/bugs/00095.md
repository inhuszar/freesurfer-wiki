# [severity-2] [bug-00095] `LabelVoxelToSurfaceRAS` calls the **inverse** transform when `lsrc->mris` is set

> [!bug] Synopsis
> `LabelVoxelToSurfaceRAS`
> ([`utils/label.cpp:3285-3306`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/label.cpp#L3285-L3306))
> is supposed to convert label vertex coordinates
> from **voxel** to **surface RAS**. Its body
> branches on whether the label has an attached
> surface:
>
> ```cpp
> if (lsrc->mris)
>   MRISsurfaceRASToVoxel((MRIS *)lsrc->mris, mri,
>                         lsrc->lv[i].x, lsrc->lv[i].y, lsrc->lv[i].z,
>                         &xs, &ys, &zs);                       /* :3295 — WRONG DIRECTION */
> else
>   MRIvoxelToSurfaceRAS(mri,
>                        lsrc->lv[i].x, lsrc->lv[i].y, lsrc->lv[i].z,
>                        &xs, &ys, &zs);                        /* :3297 — correct */
> ```
>
> `MRISsurfaceRASToVoxel`
> ([`utils/mrisurf_mri.cpp:7199`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_mri.cpp#L7199))
> converts **surface RAS → voxel** — the inverse
> of what the function name and contract require.
> When `lsrc->mris != NULL`, the input voxel
> coordinates are silently treated as if they
> were surface RAS, mapped through the inverse
> matrix, and stored back into `ldst->lv[i]`
> tagged as `LABEL_COORDS_TKREG_RAS`. The
> coordinates are now meaningless (a double
> reverse-transform).

## Affected Artefacts

- **Tool:** [[mri_compute_bias]] is the single
  in-tree caller
  ([`mri_bias/mri_compute_bias.cpp:117`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_bias/mri_compute_bias.cpp#L117)).
  The label is constructed by `LabelApplyMatrix`
  on the previous line, which leaves
  `mris == NULL`, so the function takes the
  correct `else` branch.
- **Pipeline stage(s):** none in default
  `recon-all`.
- **Triggering configuration:** any caller
  whose label has `lsrc->mris != NULL`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/label.cpp:3285-3306 */
LABEL *LabelVoxelToSurfaceRAS(LABEL *lsrc, MRI *mri, LABEL *ldst)
{
  int i;
  double xs, ys, zs;

  if (ldst != lsrc)
    ldst = LabelCopy(lsrc, ldst) ;

  for (i = 0; i < lsrc->n_points; i++) {
    if (lsrc->mris)
      MRISsurfaceRASToVoxel((MRIS *)lsrc->mris, mri,
                            lsrc->lv[i].x, lsrc->lv[i].y, lsrc->lv[i].z,
                            &xs, &ys, &zs);                     /* WRONG: surfaceRAS→voxel */
    else
      MRIvoxelToSurfaceRAS(mri,
                           lsrc->lv[i].x, lsrc->lv[i].y, lsrc->lv[i].z,
                           &xs, &ys, &zs);                      /* CORRECT: voxel→surfaceRAS */
    ldst->lv[i].x = xs;
    ldst->lv[i].y = ys;
    ldst->lv[i].z = zs;
  }

  ldst->coords = LABEL_COORDS_TKREG_RAS;
  strcpy(ldst->space, "TkReg");
  return (ldst);
}
```

For both branches the values returned in
`xs/ys/zs` are stored back into
`ldst->lv[i].{x,y,z}` and the label is tagged
as `LABEL_COORDS_TKREG_RAS`. In the buggy
branch the values are voxel coords (because
`MRISsurfaceRASToVoxel` produces voxel coords
from a surface RAS input), so the resulting
label is mislabelled.

The likely intent was a surface-aware
voxel-to-surfaceRAS path (using
`mris->vg.x_r`, `mris->vg.c_r`, etc., as in
`MRISsurfaceRASToVoxel`'s vg-aware branch), but
the function name was inverted in the call.

A correct surface-aware voxel→surfaceRAS would
use `RASFromSurfaceRAS_(mri_tmp, NULL)`'s
inverse multiplied by `inv(mri_tmp's vox2RAS)`,
or equivalently `MatrixInverse` of
`MRISsurfaceRASToVoxel`'s composed matrix.

## Root Cause

Wrong-function-name typo. The author probably
meant a hypothetical `MRISvoxelToSurfaceRAS`
that uses the surface's `vol_geom` as the
reference grid; that function does not exist
in the tree. The closest function with a
similar name is `MRISsurfaceRASToVoxel`, which
implements the inverse transform; it was
plugged in as a substitute and the direction
mistake was never caught.

## Impact

- **In-tree:** none. `mri_compute_bias`'s
  label has `mris == NULL` so the `else`
  branch handles every call correctly.
- **External callers** (or future callers)
  with `lsrc->mris` populated would receive a
  label whose coordinates are voxels labelled
  as TkReg surface RAS — silently wrong by an
  `inv(M_surface_to_vox) ∘ M_surface_to_vox`
  composition (i.e., the values are roughly
  the original voxel coords, *not* surface
  RAS).
- **Severity:** 2 — latent under typical
  conditions; conceptual reverse-direction
  defect.

## Recommended Fix

Either delete the `mris != NULL` branch and
always use the `mri`-only path (the function
already takes an `mri` argument), or implement
a vol-geom-aware voxel→surfaceRAS using the
surface's geometry:

```diff
--- a/utils/label.cpp
+++ b/utils/label.cpp
@@ -3290,11 +3290,9 @@ LABEL *LabelVoxelToSurfaceRAS(LABEL *lsrc, MRI *mri, LABEL *ldst)

-    if (lsrc->mris)
-      MRISsurfaceRASToVoxel((MRIS *)lsrc->mris, mri, lsrc->lv[i].x, lsrc->lv[i].y, lsrc->lv[i].z, &xs, &ys, &zs);
-    else
-      MRIvoxelToSurfaceRAS(mri, lsrc->lv[i].x, lsrc->lv[i].y, lsrc->lv[i].z, &xs, &ys, &zs);
+    /* Use the volume's voxel→surfaceRAS regardless of whether a surface is
+       attached; the surface's vol_geom is expected to share the volume's grid. */
+    MRIvoxelToSurfaceRAS(mri, lsrc->lv[i].x, lsrc->lv[i].y, lsrc->lv[i].z, &xs, &ys, &zs);
     ldst->lv[i].x = xs;
```

If a true surface-aware path is ever needed, a
new helper `MRISvoxelToSurfaceRAS` should be
written and used here.

## Workarounds

External callers should set `label->mris =
NULL` before calling `LabelVoxelToSurfaceRAS`
to force the correct branch.
