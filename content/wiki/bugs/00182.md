# [severity-3] [bug-00182] sfa2fieldsign — analysis mask squares the eccentricity mask instead of intersecting it with polar significance

> [!bug] Synopsis
> `sfa2fieldsign` builds its retinotopy analysis mask by intersecting the
> thresholded eccentricity significance map with the thresholded polar-angle
> significance map. The `fslmaths` call that is supposed to perform the
> intersection multiplies the **eccentricity** binary mask by **itself**
> (`fslmaths eccen/.../fsig.bin.nii -mul eccen/.../fsig.bin.nii`) instead of
> by the **polar** mask. Squaring a 0/1 mask is a no-op, so the polar-angle
> significance threshold is silently dropped: the combined mask equals the
> eccentricity mask alone. Voxels significant for eccentricity but **not**
> for polar angle are wrongly retained in the field-sign analysis, and the
> resulting masked angle/field-sign overlays cover the wrong region. This
> contradicts both the in-code comment ("Take intersection of thresholded
> fsigs") and the help text ("`fsig.bin.nii` - intersection of polar and
> eccen thresholded fsigs").

## Affected Artefacts

- **Tool(s):** [[sfa2fieldsign]] — the field-sign computation script for
  self-organising-map / retinotopy analyses. The defect is on the script's
  single, default code path (no flag is required to reach it).
- **Pipeline stage(s):** _N/A_ — `sfa2fieldsign` is a standalone retinotopy
  post-processing script, not a stage of [[wiki/pipelines/recon-all|recon-all]].
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — pure shell logic; depends on the external FSL
  `fslmaths` binary, which behaves identically across platforms.
- **Triggering configuration:** every invocation. The mask is always built
  this way; the user-visible error appears whenever the eccentricity and
  polar significance maps differ (i.e., essentially always for real data,
  since the two contrasts rarely have identical suprathreshold support).

## Detailed Description

`sfa2fieldsign` first binarises the omnibus significance volume for each of
the two retinotopy contrasts — `eccen` and `polar` — at the user threshold
(`mri_binarize --abs --min $thresh`), producing
`eccen/omnibus/fsig.bin.nii` and `polar/omnibus/fsig.bin.nii`. It then
forms a single combined mask `fsig.bin.nii` that is supposed to be the
logical AND of the two, and uses that combined mask to (a) mask the complex
`h` volumes that feed the field-sign calculation and (b) mask the eccen and
polar angle volumes that are sampled onto the surface.

The combining step is intended to be an intersection of the two thresholded
maps. Because each input is already a 0/1 mask, `eccen -mul polar` yields 1
exactly where **both** contrasts are significant — the desired AND.

### Expected Behaviour

The combined mask `$outdir/fsig.bin.nii` should equal the voxelwise product
(intersection) of the eccentricity and polar binary masks:

```
fsig.bin = eccen/omnibus/fsig.bin  ×  polar/omnibus/fsig.bin
```

so that only voxels significant in **both** the eccentricity and the
polar-angle omnibus tests participate in the field-sign analysis.

### Observed Behaviour

The `fslmaths` call multiplies the eccentricity mask by **itself**:

```
fslmaths eccen/omnibus/fsig.bin.nii -mul eccen/omnibus/fsig.bin.nii  fsig.bin.nii
```

For a 0/1 mask, `x · x = x`, so the result is identical to
`eccen/omnibus/fsig.bin.nii`. The polar mask is never referenced. The
combined "intersection" therefore equals the eccentricity mask alone:

- Voxels that are significant for eccentricity but **not** for polar angle
  remain in the mask (they should have been excluded).
- The constraint that field-sign be computed only where polar angle is
  reliably estimated is silently lost.

Every downstream product that uses `$fsigbin` — the masked `h` volumes
(`h.masked.nii`), the masked angle volumes (`eccen.masked.nii`,
`polar.masked.nii`), the surface-sampled overlays, and ultimately
`?h.fieldsign.masked.mgh` — inherits the wrong support region. The error is
**silent**: `fslmaths` succeeds, `$status` is 0, and no warning is printed.

### Reproducer

> [!gap] Reproducer requires a prepared SFA directory and FSL
> The defect is established by static reading of the script; a full
> end-to-end run needs a self-organising-map retinotopy dataset
> (`$sfadir/{eccen,polar}/omnibus/fsig.nii`) and a flattened occipital
> patch, which are not shipped with FreeSurfer. The squaring no-op is
> directly demonstrable in isolation:
>
> ```bash
> # Two distinct 0/1 masks
> fslmaths eccen_fsig.bin.nii -mul eccen_fsig.bin.nii out_buggy.nii   # == eccen
> fslmaths eccen_fsig.bin.nii -mul polar_fsig.bin.nii out_fixed.nii   # == AND
> # out_buggy equals eccen_fsig.bin; out_fixed is the true intersection.
> # Wherever polar==0 but eccen==1, the two outputs differ.
> ```

## Code Reference (Unambiguous)

- **File:** `scripts/sfa2fieldsign`
- **Function:** main body — "Take intersection of thresholded fsigs" block
- **Lines:** `77–83` (defect at `79–80`); intent stated by the comment at
  `77` and the help text at `351`
- **Commit:** `d932c45`

```tcsh
# Take intersection of thresholded fsigs
set fsigbin = $outdir/fsig.bin.nii
set cmd = (fslmaths $sfadir/eccen/omnibus/fsig.bin.nii \
  -mul $sfadir/eccen/omnibus/fsig.bin.nii $fsigbin -odt float)   # ← second operand should be polar
echo $cmd | tee -a $LF
$cmd | tee -a $LF
if($status) exit 1;
```

The self-documenting help text confirms the intended semantics
([`scripts/sfa2fieldsign:351`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/sfa2fieldsign#L351)):

```tcsh
  fsig.bin.nii - intersection of polar and eccen thresholded fsigs
```

The two per-contrast masks the intersection is meant to combine are produced
just above, at
[`scripts/sfa2fieldsign:63-75`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/sfa2fieldsign#L63-L75)
(the `foreach type (eccen polar)` binarisation loop), so
`$sfadir/polar/omnibus/fsig.bin.nii` exists and is simply not used.

## Root Cause

Copy-paste error. The line builds the first operand from the `eccen`
path, and the second `-mul` operand was duplicated from the first instead of
being edited to the `polar` path. Because the operands are 0/1 masks,
`eccen · eccen = eccen`, so the mistake is mathematically invisible (no
crash, no NaN) and survives as a silent logic error. The comment at
[`scripts/sfa2fieldsign:77`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/sfa2fieldsign#L77)
and the help text both say "intersection", confirming the second operand was
meant to be the polar mask.

## Impact

- **Wrong analysis mask.** The field-sign analysis and every masked
  overlay (`?h.fieldsign.masked.mgh`, `?h.eccen.masked.mgh`,
  `?h.polar.masked.mgh`) include voxels where polar angle was not
  significant. The eccentricity threshold is effectively the only one
  applied.
- **Silent.** There is no error, warning, or non-zero exit; the masked
  outputs look plausible. A user inspecting the field-sign map has no
  signal that the polar significance constraint was dropped.
- **Scope.** `sfa2fieldsign` is a specialised retinotopy script, not a
  default user-facing pipeline, so this is medium (3) rather than critical:
  it fires only for users who run this script, but when they do, it always
  fires on the default path and corrupts the analysis region. The downstream
  field-sign maps may be used for visual-area delineation; an over-inclusive
  mask can shift area borders and contaminate the sign estimate with
  voxels whose polar angle is unreliable.

## Recommended Fix

Replace the duplicated eccentricity operand with the polar mask so the call
computes the intended intersection:

```diff
 # Take intersection of thresholded fsigs
 set fsigbin = $outdir/fsig.bin.nii
 set cmd = (fslmaths $sfadir/eccen/omnibus/fsig.bin.nii \
-  -mul $sfadir/eccen/omnibus/fsig.bin.nii $fsigbin -odt float)
+  -mul $sfadir/polar/omnibus/fsig.bin.nii $fsigbin -odt float)
 echo $cmd | tee -a $LF
 $cmd | tee -a $LF
 if($status) exit 1;
```

After the change, `fsig.bin.nii` is 1 only where both the eccentricity and
the polar omnibus tests survive `$thresh`, matching the comment and help
text. No other code path changes: the downstream consumers already read
`$fsigbin` and simply receive the correct (smaller) mask.

### Alternative Fixes Considered

`fslmaths eccen -mas polar` (mask-with) would produce the same result for
0/1 inputs and reads more clearly as "restrict eccen to where polar is
non-zero". The `-mul` form above is the smallest edit and is symmetric, so
it is preferred.

## Workarounds (If Any)

Until patched, a user can build the intersection by hand and substitute it
for `$outdir/fsig.bin.nii` before the masking steps run, e.g.
`fslmaths .../eccen/omnibus/fsig.bin.nii -mul .../polar/omnibus/fsig.bin.nii
.../fsig.bin.nii`, then re-run the surface-sampling portion. There is no
flag that selects the correct behaviour.
