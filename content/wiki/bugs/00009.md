# fMRItemporalAR1 — zero-variance guard is dead; still divides by zero

> [!bug] Synopsis
> `fMRItemporalAR1` in `utils/fmriutils.cpp` contains a
> guard "`if (voxvar == 0) MRIFseq_vox(ar1, …) = 0;`" that is
> immediately followed by the unconditional statement
> `MRIFseq_vox(ar1, …) = voxcovar / voxvar;`, which divides by
> `voxvar` for every voxel — including zero-variance ones. The guard
> sets the output to zero and then the next line overwrites it with
> `voxcovar / 0 = NaN` (or `±Inf`). The guard is missing a
> `continue;` (or an `else`) and therefore has no effect at all.

## Affected Artefacts

- **Tool(s):** [[mri_glmfit]] via
  [`mri_glmfit/mri_glmfit.cpp:2102`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_glmfit/mri_glmfit.cpp#L2102)
  (computes the residual-map temporal AR1 when the user requests
  AR1 whitening or diagnostics) and [[mri_concat]] via
  [`mri_concat/mri_concat.cpp:546`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_concat/mri_concat.cpp#L546)
  (exposes temporal AR1 through the `--temporal-ar1` switch).
- **Pipeline stage(s):** _N/A_ — not part of [[recon-all]]. Relevant
  to any fMRI/DTI analysis pipeline that passes through
  [[mri_glmfit]] or [[mri_concat]] with the AR1 options enabled.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit
  `d932c45b79`.
- **Platforms:** all.
- **Triggering configuration:** any volume with at least one voxel
  whose temporal variance is exactly zero — typically unmasked
  background voxels whose time series is constant. When the caller
  passes a `mask`, masked-out voxels are explicitly zeroed and
  `continue`d, so the defect only fires for unmasked voxels that
  happen to be constant in time. Calling with `mask == NULL` (as
  `mri_concat`'s `--temporal-ar1` path does) exposes every constant
  voxel in the volume.

## Detailed Description

The AR1 coefficient at a voxel is the lag-1 autocovariance divided
by the variance:

$$
\rho_{1} = \frac{\mathrm{cov}(x_{t}, x_{t-1})}{\mathrm{var}(x_{t})}.
$$

When the variance is zero the coefficient is undefined. The function
attempts to handle this with a guard, but the guard does not break
out of the computation:

```cpp
voxvar = MRIFseq_vox(var, c, r, s, 0);
if (voxvar == 0) MRIFseq_vox(ar1, c, r, s, 0) = 0;  // intended to skip
voxcovar = MRIFseq_vox(covar, c, r, s, 0);
MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;   // ← always runs
```

There is no `continue` after the guard and no `else` wrapping the
division, so every iteration reaches the division. For zero-variance
voxels the `ar1[c,r,s,0] = 0` write is silently overwritten by
`voxcovar / voxvar = 0/0 = NaN` (or a non-zero `voxcovar` divided
by zero, giving `±Inf`).

### Expected Behaviour

For zero-variance voxels the AR1 map should carry a sentinel value
— the existing code's intent was zero — and the division should be
skipped.

### Observed Behaviour

Zero-variance voxels carry `NaN` (`0.0 / 0.0`) or `±Inf`
(`voxcovar / 0` with non-zero numerator) in the returned AR1 map,
depending on whether the lag-1 covariance is exactly zero or
floating-point noise. Either output is a silent departure from the
guard's declared behaviour and can poison downstream statistics that
aggregate over the volume (e.g., spatial summaries of AR1 printed
diagnostically by `mri_concat --temporal-ar1`).

### Reproducer

> [!gap] Reproducer not yet constructed
> A direct demonstration:
>
> 1. Build a small synthetic 4D volume with a masked brain region
>    carrying realistic fMRI timeseries and a background region of
>    constant zero voxels (no mask passed).
> 2. Call `fMRItemporalAR1(fmri, 1.0, NULL, NULL)`, or equivalently
>    `mri_concat fmri.mgz --temporal-ar1 out.mgz` without a mask.
> 3. Inspect `out.mgz` at any background voxel: the value will be
>    `NaN` (or `±Inf`) instead of the intended zero.

## Code Reference (Unambiguous)

- **File:** `utils/fmriutils.cpp`
- **Function:** `fMRItemporalAR1()`
- **Lines:** `193–229` (full function); defect at `220–223`
- **Commit:** `d932c45b79`

```cpp
MRI *fMRItemporalAR1(MRI *fmri, float DOFAdjust, MRI *mask, MRI *ar1)
{
  int c, r, s;
  double voxvar, voxcovar;
  MRI *var, *covar;

  var = fMRIcovariance(fmri, 0, DOFAdjust, mask, NULL);
  covar = fMRIcovariance(fmri, 1, DOFAdjust, mask, NULL);

  if (ar1 == NULL) {
    ar1 = MRIallocSequence(fmri->width, fmri->height, fmri->depth, MRI_FLOAT, 1);
    /* ... */
    MRIcopyHeader(fmri, ar1);
  }

  for (c = 0; c < fmri->width; c++) {
    for (r = 0; r < fmri->height; r++) {
      for (s = 0; s < fmri->depth; s++) {
        if (mask) {
          if (MRIgetVoxVal(mask, c, r, s, 0) < 0.5) {
            MRIFseq_vox(ar1, c, r, s, 0) = 0;
            continue;                                          // mask branch does continue
          }
        }
        voxvar = MRIFseq_vox(var, c, r, s, 0);
        if (voxvar == 0) MRIFseq_vox(ar1, c, r, s, 0) = 0;      // ← no continue
        voxcovar = MRIFseq_vox(covar, c, r, s, 0);
        MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;       // ← overwrites with NaN when voxvar==0
      }
    }
  }

  return (ar1);
}
```

Note how the mask branch correctly uses `continue` after the
zero-assign (line 217), but the zero-variance branch (line 221) does
not.

## Root Cause

The guard was written as a single statement without braces and the
author forgot to include the accompanying `continue` (or to wrap the
division in an `else`). C's "dangling else / missing brace" hazard:
a quick read makes it look like the guard handles the degenerate
case, but the unconditional division that follows silently
overrides it.

## Impact

- For users who pass a `mask` that excludes background and
  constant-value voxels, the defect is masked: the earlier
  mask-branch `continue` handles those voxels first.
- For callers that do not pass a mask — notably
  `mri_concat --temporal-ar1`, which calls
  `fMRItemporalAR1(mriout, TAR1DOFAdjust, NULL, NULL)` — every
  constant-time-series voxel in the output carries `NaN` or `±Inf`.
- `mri_glmfit` passes the residual-error volume through
  `fMRItemporalAR1`; its residual masks usually exclude background,
  but any unmasked constant residual (e.g., frozen voxels outside
  the ROI) produces poisoned AR1 values that propagate into the
  diagnostic `eres.tar1.mgh` output.

## Recommended Fix

Add the missing `continue` (or wrap the following two statements in
an `else`). The minimal diff:

```diff
   voxvar = MRIFseq_vox(var, c, r, s, 0);
-  if (voxvar == 0) MRIFseq_vox(ar1, c, r, s, 0) = 0;
+  if (voxvar == 0) {
+    MRIFseq_vox(ar1, c, r, s, 0) = 0;
+    continue;
+  }
   voxcovar = MRIFseq_vox(covar, c, r, s, 0);
   MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;
```

### Alternative Fixes Considered

Replacing the zero test with `FZERO(voxvar)` (the codebase's
standard epsilon comparison) is more robust for floating-point
near-zeros, and is how the equivalent test is written in several
other routines in `utils/fmriutils.cpp`. Either change should be
applied together with the `continue`.

## Workarounds (If Any)

Always pass a proper brain mask to `fMRItemporalAR1`. The mask
branch at
[`utils/fmriutils.cpp:215–219`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/fmriutils.cpp#L215-L219)
correctly skips masked-out voxels with a `continue`, so
zero-variance voxels are unreachable through that path.

For `mri_concat --temporal-ar1` users who need a clean AR1 map,
pass `--mask` or post-process the output with
`mri_binarize --i out.mgz --abs --min 0 --max 2 --o out.bin.mgz`
followed by `mri_mask` to zero out `NaN`/`Inf` entries.
