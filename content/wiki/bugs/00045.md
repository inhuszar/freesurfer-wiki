# `mri_normalize`: `remove_surface_outliers` and `remove_outliers_near_surface` are silent no-ops — `return(0);` at the top of each function makes the entire body unreachable

> [!bug] Synopsis
> The surface-driven branch of [[mri_normalize]]
> (entered with `-surface`) is the workhorse used by
> [[recon-all]]'s T2/FLAIR pial-refinement stages
> ([`scripts/recon-all:4662-4669`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/scripts/recon-all#L4662-L4669)).
> In that branch, after the surface-distance map has been
> binarised into a control-point mask, two cleanup helpers
> are supposed to remove control points that look like
> outliers. The non-aseg path calls
> `remove_surface_outliers` at
> [`mri_normalize.cpp:455`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L455);
> the `-aseg` path skips it. Then **unconditionally**, the
> code calls `remove_outliers_near_surface` at
> [`:469`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L469).
> Both helpers have a bare `return(0);` placed at the very
> first executable line of the function body
> ([`:1809`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1809)
> and
> [`:1962`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1962)
> respectively). Every line of cleanup logic underneath —
> histogram-based outlier detection in
> `remove_surface_outliers`, and the local-mean / `nsigma`
> outlier rejection in `remove_outliers_near_surface` — is
> unreachable dead code. The user sees
> `"Removing surface outliers"` in the log but the action
> does not run. The control-point set used to fit the bias
> field includes the very outliers these helpers were
> written to remove, biasing the bias-corrected output
> volume (`brain.finalsurfs.T2.mgz` /
> `brain.finalsurfs.FLAIR.mgz` in T2pial / FLAIRpial
> recon-all) and, through it, the refined pial surface
> placement.

## Affected Artefacts

- **Tool:** [[mri_normalize]] when invoked with one or more
  `-surface` flags. Both early-return defects sit in
  helpers reached only from the surface-driven branch
  ([`mri_normalize.cpp:281`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L281)
  `if(nsurfs > 0)`).
- **Pipeline stage:** [[recon-all]] T2/FLAIR pial
  refinement
  ([`scripts/recon-all:4662-4669`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/scripts/recon-all#L4662-L4669)),
  triggered by `-T2pial` or `-FLAIRpial`. The output
  `brain.finalsurfs.T2.mgz` (or `.FLAIR.mgz`) is the
  intensity volume used by `mris_make_surfaces` /
  `mris_place_surface` to refine the pial surface against
  T2 / FLAIR contrast. Plain T1-only default recon-all
  does not invoke `mri_normalize -surface` and is
  therefore unaffected.
- **Other callers:** standalone `mri_normalize -surface
  <surf> <xform> <in> <out>` invocations by users.
  Inspection found no other callers of either helper in
  the FreeSurfer 8.2.0 tree (header-private static
  functions; their only callers are at `:455` and
  `:469`).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`); earliest
  known: _unknown_.
- **Triggering configuration:** any `mri_normalize -surface`
  invocation reaches the unconditional
  `remove_outliers_near_surface` call. The
  `remove_surface_outliers` no-op only fires when no
  `-aseg` is supplied (recon-all's T2/FLAIR step does
  pass `-aseg aseg.presurf.mgz` and therefore takes the
  `remove_nonwm_voxels` branch instead, which works
  correctly).

## Detailed Description

### Expected Behaviour

`mri_normalize` with `-surface` builds an "interior"
control-point set by computing a signed distance to the
surface, binarising it (control points = voxels at least
`min_dist` mm inside the surface), and using those control
points to fit `MRIbuildBiasImage`. Before fitting, two
cleanup helpers are documented to:

1. `remove_surface_outliers` — for each control point,
   pull a `wsize`-mm histogram of nearby voxel
   intensities, robust-Gaussian-fit it, and drop the
   control point if its intensity is more than 1 σ from
   the local mean
   ([`:1843-1858`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1843-L1858)).
2. `remove_outliers_near_surface` — for control points
   within `min_dist+1` mm of the surface, recompute a
   local mean over the rest of the control points in a
   9-vox neighbourhood and drop the candidate if it
   deviates by more than `nsigma=2.5` σ from that local
   mean
   ([`:1969-1979`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1969-L1979).

Both are intentional sanity guards on the control-point
set that drives `MRIbuildBiasImage`. Outliers in that
set propagate as ringing / bias in the corrected output.

([`scripts/recon-all:4662-4669`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/scripts/recon-all#L4662-L4669)):


`-aseg` is set, so the non-aseg branch (which contains
the `remove_surface_outliers` no-op) is *not* taken; that
defect is dormant for recon-all but live for users who
run `mri_normalize -surface` without `-aseg`. The
unconditional `remove_outliers_near_surface` no-op fires
on every recon-all T2/FLAIR run, leaving the control-point
set un-pruned of near-surface outliers.

### Side Effects of the Early Return

- **Memory leak** — line
  [`:1807`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1807)
  allocates `mri_outlier = MRIclone(mri_ctrl_src, NULL);`
  before the `return(0);` at
  [`:1809`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1809).
  The `MRIfree(&mri_outlier);` at
  [`:1872`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1872)
  is unreachable. Each call leaks one cloned MRI volume
  (~the size of the control-point grid). Small per call,
  but it does fire on every standalone `mri_normalize
  -surface` without `-aseg`.
- **Misleading log output** —
  `printf("Removing surface outliers\n");` at
  [`:454`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L454)
  prints regardless of whether the helper actually does
  anything. Operators reading the recon-all log will
  reasonably conclude that outlier removal happened.

## Root Cause

Both `return(0);` lines sit immediately after the local
variable declarations, before any work of the function.
The shape — `return(0);` followed by ~70 lines of
ostensibly-active code — is the canonical pattern of a
*temporary* dev-time disablement (e.g., to A/B-test
whether the helper was the cause of a regression) that
was committed and never reverted. The sister helper
`remove_surface_outliers_T2`
([`:2017-2117`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L2017-L2117))
does *not* have an early-return — it runs as written —
which corroborates the "left-in disablement" reading: the
disablement was applied selectively to two specific
helpers and forgotten.

## Impact

- **Recon-all T2/FLAIR pial refinement
  (`-T2pial` / `-FLAIRpial`):** the
  `remove_outliers_near_surface` call is unconditional,
  so on every T2/FLAIR run the control-point set used to
  fit the bias field includes voxels that the algorithm
  was written to drop. The bias-corrected output —
  `brain.finalsurfs.T2.mgz` /
  `brain.finalsurfs.FLAIR.mgz` — is the intensity volume
  that drives the pial-surface refinement step in
  `mris_make_surfaces` / `mris_place_surface`. Errors in
  it propagate to the final pial surfaces.
- **Standalone `mri_normalize -surface` without `-aseg`:**
  both helpers fire (and both are no-ops). This is the
  worst case — both cleanup steps disabled silently.
- **Standalone `mri_normalize -surface` with `-aseg`:**
  only `remove_outliers_near_surface` fires (no-op);
  `remove_nonwm_voxels` works correctly.
- **Plain T1-only default recon-all:** **not affected**.
  The non-surface invocation of `mri_normalize` at
  [`scripts/recon-all:3131`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/scripts/recon-all#L3131)
  does not pass `-surface` and therefore does not enter
  the `nsurfs > 0` branch.
- **Magnitude:** depends on how many voxels the helpers
  would have dropped. For a well-stripped, well-registered
  T1, the count is small. For T2/FLAIR data with
  partial-volume / artifact outliers near the surface
  (the case the helpers were written for), the count is
  larger — exactly when the helper would have been most
  useful.

## Recommended Fix

Remove the two stray `return(0);` statements:

```diff
--- a/mri_normalize/mri_normalize.cpp
+++ b/mri_normalize/mri_normalize.cpp
@@ -1806,7 +1806,6 @@ remove_surface_outliers(MRI *mri_ctrl_src, MRI *mri_dist, MRI *mri_src,
   double    mean, sigma, val ;
   MRI       *mri_outlier = MRIclone(mri_ctrl_src, NULL) ;
 
-  return(0) ;
   mri_ctrl_dst = MRIcopy(mri_ctrl_src, mri_ctrl_dst) ;
   wsize = nint(WSIZE_MM/mri_src->xsize) ;
@@ -1959,7 +1958,6 @@ remove_outliers_near_surface(MRI *mri_ctrl, MRI *mri_dist, MRI *mri_dst, MRI *mr
   int x, y, z, c, nremoved ;
   double mean, sigma, val ;
 
-  return(0) ;
   for (nremoved = x = 0 ; x < mri_ctrl->width ; x++)
     for (y = 0 ; y < mri_ctrl->height ; y++)
       for (z = 0 ; z < mri_ctrl->depth ; z++)
```

That re-enables both helpers as written. Each is
self-contained and has a documented `nremoved` /
diagnostic write-out at the bottom, so the consequence of
re-enabling is observable in the recon-all log.

### Alternative Fixes Considered

- **Delete both functions and their call sites entirely.**
  If the code was disabled because the helpers were
  causing bad classifications, the right fix is to delete
  both bodies and the calls (no silent dead code, no
  misleading log line). This is the conservative
  alternative if a future audit shows the helpers are
  empirically harmful.
- **Wrap each call in a CLI flag (`--remove-outliers`).**
  Lets the user opt in/out and makes the disablement
  explicit. More work, but documents the design choice.
- **Just suppress the misleading
  `printf("Removing surface outliers\n");`** — leaves the
  semantic bug (no-op cleanup) in place; not recommended.

## Workarounds (If Any)

- Source-patch `mri_normalize.cpp` per the diff above and
  rebuild.
- For T2/FLAIR pial-refinement users who suspect outlier
  contamination, manually edit the control-point volume
  with `mri_binarize` / `mri_mask` against an aseg mask
  before re-running the bias correction step.

## Confidence and Gaps

> [!gap] Empirical magnitude of the bias on T2/FLAIR pial
> placement
> The defect is structural and the no-op behaviour is
> certain. The downstream effect on bias-corrected
> intensity (and through it, the refined pial surface) is
> bounded by the number and severity of outlier control
> points the helpers would have dropped. A patched-vs-
> unpatched run on a few subjects with T2/FLAIR data would
> quantify it.

> [!gap] Was the disablement intentional?
> The `return(0);` lines look like temporary dev-time
> toggles. Without git history beyond the audit
> snapshot, we cannot distinguish "left in by accident"
> from "deliberately disabled because the helper was
> producing bad classifications." Either reading is bad
> for users: an accidentally-left-in disablement is a
> bug; a deliberate-but-undocumented disablement is dead
> code that misleads operators reading the log.
