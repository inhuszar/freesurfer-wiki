# [severity-3] [bug-00148] `mri_label2vol --pvf` and `mri_ca_label -F` exit with status 1 after writing their output successfully

> [!bug] Synopsis
> Two flag-gated CLI branches end with `exit(1)` immediately after writing successful output:
>
> ```cpp
> /* mri_label2vol/mri_label2vol.cpp:492-500 */
> if(HitVolId != NULL) MRIwrite(HitVol,HitVolId);
> printf("PVF %s\n",PVFVolId);
> if(PVFVolId != NULL) {
>   voxvol = TempVol->xsize * TempVol->ysize * TempVol->zsize;
>   printf("Computing PVF %g\n",voxvol);
>   PVFVol = MRImultiplyConst(HitVol, 1/voxvol, NULL);
>   MRIwrite(PVFVol,PVFVolId);          /* writes user-supplied filename */
>   exit(1);                              /* :499 — WRONG: should exit(0) or fall through */
> }
> ```
>
> ```cpp
> /* mri_ca_label/mri_ca_label.cpp:474-495 */
> if (filter)                              /* set by `-F` CLI flag at :2112 */
> {
>   MRI *mri_dir, *mri_kernel, *mri_smooth;
>   mri_kernel = MRIgaussian1d(1, 15);
>   mri_smooth = MRIconvolveGaussian(mri_tmp, NULL, mri_kernel);
>   MRIfree(&mri_kernel);
>   …
>   mri_dir = MRIgradientDir2ndDerivative(mri_tmp, NULL, 5);
>   MRIscaleAndMultiply(mri_tmp, 128.0, mri_dir, mri_tmp);
>   MRIwrite(mri_dir, "lap.mgz");          /* :489 — hardcoded CWD-relative */
>   MRIwrite(mri_tmp, "filtered.mgz");     /* :490 — hardcoded CWD-relative */
>   MRIfree(&mri_dir);
>   MRIfree(&mri_smooth);
>   exit(1);                                /* :494 — WRONG: should exit(0) or fall through */
> }
> ```
>
> Two distinct problems compounded in each branch:
>
> 1. **Wrong exit code.** POSIX `exit(1)` signals failure to the shell. Shell wrappers, `make`, Snakemake, Nextflow, Slurm-array dispatchers, GitHub Actions, and any CI / test pipeline that gates on `$?` will see these successful operations as failures. The output files have been written to disk correctly, but the calling pipeline aborts, retries, or marks the task failed.
>
> 2. **Hardcoded CWD-relative filenames in the `mri_ca_label -F` branch** (the `mri_label2vol --pvf` branch uses the user-supplied `PVFVolId`, so that one is OK on filenames — only the exit code is wrong). The `mri_ca_label -F` `MRIwrite(mri_dir, "lap.mgz")` and `MRIwrite(mri_tmp, "filtered.mgz")` writes hit the user's CWD and silently overwrite any pre-existing files with those names — the same class of CWD-pollution defect as [[00146]]'s unconditional `MRIwrite(..., "t.mgz")` calls.

## Affected Artefacts

- **Tool(s):** [[mri_label2vol]], [[mri_ca_label]]
- **Pipeline stage(s):** _not on default `recon-all`_:
  - `mri_label2vol --pvf` is opt-in for partial-volume-fraction computation; used in PET PVC workflows and label-volume-fraction analyses.
  - `mri_ca_label -F` enables the gradient-direction filter mode; used for diagnostic / visualisation purposes during CA atlas development.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`; earliest known: _unknown_.
- **Platforms:** all.
- **Triggering configuration:** every invocation with the respective flag.

## Detailed Description

POSIX exit codes follow the convention: `0` = success, non-zero = failure. Both `mri_label2vol` and `mri_ca_label` are auxiliary tools that get invoked from shell wrappers, recon-all-like scripts, Make-based test rules, CI pipelines, and modern workflow managers (Snakemake, Nextflow). All of these gate task success / retry / continuation on the exit code; an `exit(1)` after a *successful* write is a hard failure for the caller even though the user-visible output is correct.

### Expected Behaviour

After successfully writing the requested output (the user-supplied `PVFVolId` in `mri_label2vol`, or the `lap.mgz` / `filtered.mgz` debug volumes in `mri_ca_label`), the program should fall through to the normal end-of-main exit path or call `exit(0)` to signal success.

### Observed Behaviour

Both branches call `exit(1)` immediately after the successful `MRIwrite`. The shell sees status 1; pipelines abort or mark the task failed.

### Reproducer

## Root Cause

Both branches read like developer-time "do this preprocessing step, dump the result for inspection, then bail out of the rest of `main` because there's nothing more to do" — implemented with `exit(1)` instead of `exit(0)`. The `1` was likely picked because it's the typical "non-zero exit" sentinel the developer types reflexively, without thinking about the semantic of "1 = failure". The `mri_ca_label -F` site additionally hardcodes the basenames `lap.mgz` and `filtered.mgz` in the CWD (the same anti-pattern as [[00146]]).

## Impact

- **Pipeline aborts on success.** Any shell wrapper that does `if mri_label2vol --pvf … ; then …` or `set -e` followed by an invocation sees `$? == 1` and treats it as failure. Snakemake / Nextflow / Slurm task definitions mark the task failed and may retry indefinitely.
- **`mri_label2vol --pvf` impact narrows once.** Only the `--pvf` branch is affected; the normal `--o` output path falls through to a proper `MRIwrite` + return.
- **`mri_ca_label -F` impact compounds:**
  - **Single-input only.** The `if (filter)` branch is inside the per-input-volume loop. With `-F`, the program processes only the *first* input volume, then exits — multi-input invocations get truncated.
  - **CWD pollution.** Writes `lap.mgz` and `filtered.mgz` to the CWD, overwriting any pre-existing files with those names.
  - **Read-only CWD failure mode.** Same as [[00146]] — if CWD is read-only (containerised pipelines, network-mounted read-only paths), the `MRIwrite` may fail with permission-denied.
- **Not on `recon-all` default.** Neither flag is set by `scripts/recon-all` on any default code path. Affects users who invoke the tools directly.

## Recommended Fix

For `mri_label2vol --pvf`: change `exit(1)` to `exit(0)` (or remove the early exit and let `main` fall through to the normal terminal `MRIwrite(OutVol, OutVolId)` + return). The latter is cleaner since `--pvf` and `--o` are not mutually exclusive in spirit.

```diff
   if(PVFVolId != NULL) {
     voxvol = TempVol->xsize * TempVol->ysize * TempVol->zsize;
     printf("Computing PVF %g\n",voxvol);
     PVFVol = MRImultiplyConst(HitVol, 1/voxvol, NULL);
     MRIwrite(PVFVol,PVFVolId);
-    exit(1);
+    /* fall through to write OutVol below, or:
+       exit(0); */
   }
```

For `mri_ca_label -F`: change `exit(1)` to `exit(0)`. Additionally, replace the hardcoded `"lap.mgz"` / `"filtered.mgz"` basenames with user-supplied filenames (add `--lap-out` and `--filtered-out` CLI flags) or guard them with `Gdiag & DIAG_WRITE && DIAG_VERBOSE_ON`.

```diff
   if (filter)
   {
     …
-    MRIwrite(mri_dir, "lap.mgz");
-    MRIwrite(mri_tmp, "filtered.mgz");
+    if (Gdiag & DIAG_WRITE && DIAG_VERBOSE_ON) {
+      MRIwrite(mri_dir, "lap.mgz");
+      MRIwrite(mri_tmp, "filtered.mgz");
+    }
     MRIfree(&mri_dir);
     MRIfree(&mri_smooth);
-    exit(1);
+    exit(0);
   }
```

## Workarounds (If Any)

- **`mri_label2vol --pvf`:** wrap the invocation in `mri_label2vol … || true` to ignore the exit code, then verify the output via `ls` or `mri_info`.
- **`mri_ca_label -F`:** same `|| true` workaround; run from a scratch CWD (`cd /tmp/scratch && mri_ca_label -F …`) to avoid overwriting user files.
- **Don't use `-F` for multi-input invocations**; the program exits after processing only the first input.
