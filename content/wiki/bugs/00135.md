title: "[severity-3] [bug-00135] GLMcMatrices (`utils/fsglm.cpp:414-452`) has a backwards null-check at `:426` that silently disables Partial Correlation Coefficient (PCC) computation. The function enters the PCC setup block when `glm->C[n]->rows == 1 && glm->DoPCC`, allocates `D = MatrixColNullSpace(glm->Ct[n], &err)`, then checks `if (glm->Dt[n] == NULL) continue;`. The `D` allocation at `:425` is leaked (no MatrixFree before `continue`), and `glm->Dt[n]` stays NULL — which means the subsequent `MatrixCopy`, `MatrixMultiplyD` calls, and the PCC-output gate at `:641` (`if (glm->Dt[n] != NULL)`) in `GLMtest` all skip the PCC pipeline. # [severity-3] [bug-00135] `GLMcMatrices` backwards null-check at `:426` silently disables PCC computation in `mri_glmfit --pcc`

> [!bug] Synopsis
> ```cpp
> /* utils/fsglm.cpp:414-452 (excerpt) */
> int GLMcMatrices(GLMMAT *glm)
> {
>   int n, err;
>
>   for (n = 0; n < glm->ncontrasts; n++) {
>     glm->Ct[n] = MatrixTranspose(glm->C[n], glm->Ct[n]);
>     glm->Mpmf[n] = GLMpmfMatrix(glm->C[n], &glm->Ccond[n], glm->Mpmf[n]);
>
>     if (glm->C[n]->rows == 1 && glm->DoPCC) {
>       // These are for the computation of partial correlation coef
>       // null space of contrast space
>       MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);  /* :425 — alloc D */
>       if (glm->Dt[n] == NULL) continue;                  /* :426 — BUG: should check D, not Dt[n] */
>       glm->Dt[n] = MatrixCopy(D, glm->Dt[n]);            /* :427 — never reached */
>       MatrixFree(&D);                                    /* :428 — never reached → D leaks */
>       // design matrix projected onto contrast space
>       glm->XCt[n] = MatrixMultiplyD(glm->X, glm->Ct[n], glm->XCt[n]);
>       // design matrix projected onto contrast null space (nuisance reg space)
>       glm->XDt[n] = MatrixMultiplyD(glm->X, glm->Dt[n], glm->XDt[n]);
>       glm->RD[n] = MatrixResidualForming(glm->XDt[n], glm->RD[n]);
>       ...
>     }
>     else
>       glm->Dt[n] = NULL;
>   }
>   return (0);
> }
> ```
>
> `glm->Dt[n]` is initialised
> to `NULL` in `GLMalloc`
> at `:213`. The first time
> `GLMcMatrices` runs, the
> check `glm->Dt[n] == NULL`
> is **true**, so the
> function `continue`s,
> skipping the PCC setup
> for that contrast.
> Subsequent contrasts in
> the same call hit the
> same condition and also
> skip.
>
> Three immediate
> consequences:
>
> 1. `D` allocated at `:425`
>    is leaked (no
>    `MatrixFree` before
>    the `continue`).
> 2. `glm->Dt[n]` is never
>    assigned a non-NULL
>    value.
> 3. The downstream gate
>    in `GLMtest` at
>    [`utils/fsglm.cpp:641`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L641)
>    (`if (glm->Dt[n] !=
>    NULL) { ... pcc … }`)
>    is permanently false,
>    so PCC values
>    (`glm->pcc[n]`) are
>    never computed.
>
> The corresponding mri_glmfit
> output gate at
> [`mri_glmfit/mri_glmfit.cpp:2219-2221`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L2219-L2221):
>
> ```c
> if(mriglm->glm->Dt[n] != NULL){
>   // Write out the pcc
>   sprintf(tmpstr,"%s/%s/pcc.%s",GLMDir,mriglm->glm->Cname[n],format);
>   MRIwrite(mriglm->pcc[n],tmpstr);
> }
> ```
>
> is also permanently false,
> so `pcc.*` output files
> are **never written**
> despite the user enabling
> `--pcc`.

## Detailed Description

### Trace

Initial state after
`GLMalloc`:
- `glm->Dt[0..ncontrasts-1] = NULL`
  (line 213).
- `glm->DoPCC` set by
  caller, e.g.
  `mri_glmfit.cpp:817`:
  `mriglm->glm->DoPCC =
  DoPCC;` (default
  `DoPCC = 1`).

First call to
`GLMcMatrices`:
- For `n = 0`:
  - Line 425: `D =
    MatrixColNullSpace(Ct[0],
    &err)` — alloc.
  - Line 426: `if
    (glm->Dt[0] == NULL)
    continue;` → TRUE
    (it's NULL) →
    `continue`.
  - **`D` is leaked.**
- For `n = 1, 2, ...`:
  same trace. All
  `Dt[n]` stay NULL.

Subsequent call (e.g.,
per-voxel mode):
- `glm->Dt[n]` is still
  NULL (no path
  populates it).
- Same trace. PCC is
  never set up.

### What the
correct code should be

```c
MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
if (D == NULL) continue;             // defensive check
glm->Dt[n] = MatrixCopy(D, glm->Dt[n]);
MatrixFree(&D);
```

Or simply remove the
check (since
`MatrixCopy(D, NULL)`
allocates fresh and
`MatrixCopy(D, Dt[n])`
reuses the existing
buffer):

```c
MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
glm->Dt[n] = MatrixCopy(D, glm->Dt[n]);
MatrixFree(&D);
```

### Memory-leak
quantification

The leak is per
`(contrast, GLMcMatrices
call)`. For typical
mri_glmfit:
- One contrast per
  command, one
  `GLMcMatrices` call
  per analysis: 1 leak
  (small, ~1-row
  matrix).
- Per-voxel mode
  (e.g.,
  `mriglm->pervoxflag
  == 1` path at
  `:1017`): one
  `GLMcMatrices` call
  per voxel.
  256³ ~16 M voxels →
  16 M `D` leaks.
  Each `D` is a small
  matrix (typically a
  few rows ×
  C->cols).
  Cumulative leak:
  100s of MB on a
  brain-sized
  analysis.

### Why this is severity 3

- **Silent**: tool
  reports
  successful
  completion; no
  warning that PCC
  was disabled.
- **Reachable**:
  `DoPCC = 1` is the
  default in
  `mri_glmfit`. Any
  user running it
  without `--no-pcc`
  is affected.
- **Documented
  feature broken**:
  `--pcc` is a
  documented option;
  expected
  `pcc.<contrast>.<format>`
  output files
  silently don't
  appear.
- **Memory leak**:
  per-voxel mode
  leaks accumulate
  to 100s of MB.
- **Below severity 4**:
  the primary
  outputs (beta,
  gamma, F, sig)
  are not affected;
  only the PCC
  output is. And a
  user noticing the
  missing `pcc.*`
  file can work
  around it.

## Root Cause

Refactoring residue.
The docstring at
`:404-413` mentions a
5/10/22 change "to
use already alloced
matrices so no
memory leak so
accomodate per-voxel
apps." The intent
was: for the
per-voxel mode where
`GLMcMatrices` is
called once per
voxel, reuse the
pre-allocated `Dt[n]`
buffer.

The check at `:426`
appears to have been
inserted to support
this — but it's
backwards:

| state         | intent          | actual         |
|---------------|-----------------|----------------|
| Dt[n] == NULL | alloc fresh     | **continue (skip)** |
| Dt[n] != NULL | reuse buffer    | proceed to MatrixCopy |

The check should be
`if (D == NULL) continue;`
(safety against
`MatrixColNullSpace`
failure), not
`if (glm->Dt[n] ==
NULL) continue;`.

`MatrixCopy(D, dst)`
correctly handles
both NULL and
non-NULL `dst`, so
no special-casing
is needed.

## Recommended Fix

```diff
--- a/utils/fsglm.cpp
+++ b/utils/fsglm.cpp
@@ -422,8 +422,10 @@ int GLMcMatrices(GLMMAT *glm)
     if (glm->C[n]->rows == 1 && glm->DoPCC) {
       // These are for the computation of partial correlation coef
       // null space of contrast space
       MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
-      if (glm->Dt[n] == NULL) continue;
+      if (D == NULL) {
+        glm->Dt[n] = NULL;  // explicit
+        continue;
+      }
       glm->Dt[n] = MatrixCopy(D,glm->Dt[n]);
       MatrixFree(&D);
       // design matrix projected onto contrast space
```

Change the
null-check to test
the new `D`
allocation (the
defensive intent),
not the existing
`Dt[n]`. Also
explicitly NULL
`Dt[n]` when
skipping so
downstream
`Dt[n] != NULL`
gates work
correctly.

## Workarounds

For users who need
PCC output: there
is no clean
workaround short of
patching the source.
The PCC output is
not produced
regardless of the
`--pcc` flag.

For users who don't
need PCC and want
to avoid the memory
leak: pass
`--no-pcc` to
`mri_glmfit`.
