# [severity-3] [bug-00136] FFT helper trio leaks GB-scale memory per call — top-level `free()` does not free the underlying `float**`/`float*` allocations

> [!bug] Synopsis
> ```cpp
> /* utils/fftutils.cpp:510-532 */
> void FFTswitch_with_z(float ***vect, int dimension, int is_y)
> {
>   float ***res;
>   int x, y, z;
>   res = (float ***)malloc(dimension * sizeof(float **));
>
>   for (z = 0; z < dimension; z++) {
>     res[z] = (float **)malloc(dimension * sizeof(float *));
>     for (y = 0; y < dimension; y++)
>       res[z][y] = (float *)malloc(dimension * sizeof(float));   /* dim^3 floats alloc */
>   }
>   for (z, y, x) {
>     ...res[x][y][z] = vect[x][z][y] or vect[z][y][x] ...
>   }
>   for (z, y, x) vect[x][y][z] = res[x][y][z];                    /* copy back */
>   free(res);                                                      /* :531 — leaks the inner arrays */
> }
> ```
>
> `res` is a 3-level
> indirection: top-level
> `float ***` array of
> `dimension` pointers,
> mid-level `float **`
> arrays of `dimension`
> pointers each, and
> bottom-level `float *`
> arrays of `dimension`
> floats each. The cleanup
> at `:531` only frees the
> top-level. The mid-level
> and bottom-level
> allocations are leaked:
>
> | level    | count    | bytes per object | total bytes (dim=256) |
> |----------|----------|------------------|------------------------|
> | top      | 1        | 256 × 8 = 2 KB   | 2 KB |
> | mid      | 256      | 256 × 8 = 2 KB   | 512 KB |
> | bottom   | 256²     | 256 × 4 = 1 KB   | 64 MB |
>
> Per `FFTswitch_with_z`
> call on a 256-cube,
> ~64.5 MB leaks.
>
> The same incomplete-free
> pattern repeats in
> `MRI_fft` itself:
>
> ```cpp
> /* utils/mrifilter.cpp:6126-6138 — alloc */
> src   = (float ***)malloc(dimension * sizeof(float **));
> dst_r = (float ***)malloc(dimension * sizeof(float **));
> dst_i = (float ***)malloc(dimension * sizeof(float **));
> for (k = 0; k < dimension; k++) {
>   src[k]   = (float **)malloc(dimension * sizeof(float *));
>   dst_r[k] = (float **)malloc(dimension * sizeof(float *));
>   dst_i[k] = (float **)malloc(dimension * sizeof(float *));
>   for (j = 0; j < dimension; j++) {
>     src[k][j]   = (float *)malloc(dimension * sizeof(float));
>     dst_r[k][j] = (float *)malloc(dimension * sizeof(float));
>     dst_i[k][j] = (float *)malloc(dimension * sizeof(float));
>   }
> }
> ...
> /* :6181 — overwrites dst_r without freeing the old buffer */
> dst_r = FFTinv_quarter(dst_r, dimension);
> ...
> free(src);                /* :6190 — top-level only */
> free(dst_r);              /* :6191 — top-level only */
> free(dst_i);              /* :6192 — top-level only */
> return (dst);
> ```
>
> All three multi-level
> allocations leak at
> the end of `MRI_fft`,
> and `dst_r` is also
> overwritten mid-function
> by `FFTinv_quarter`
> (which allocates a
> fresh array and returns
> it).

## Detailed Description

### Per-call leak budget

For a 256-cube
volume with 1 frame:

| location | leak per call | count | subtotal |
|----------|---------------|-------|----------|
| `FFTswitch_with_z` inner arrays | ~64.5 MB | 8 per frame | 516 MB |
| `FFTinv_quarter` overwrites old `dst_r` | ~64.5 MB | 1 per frame | 64.5 MB |
| `MRI_fft` end cleanup for `src`, `dst_r`, `dst_i` (mid/low not freed) | ~64.5 MB | 3 | 194 MB |

**Total per `MRI_fft`
call on a 256-cube:
~774 MB.**

`MRI_fft_gaussian`
calls `MRI_fft` twice
(once for the source
volume, once for the
Gaussian kernel),
yielding ~1.55 GB
leaked per
`mri_volsynth
--pdf gaussianfft`
invocation.

For a 128-cube
volume the leaks
scale by 1/8 →
~97 MB per
`MRI_fft` /
~194 MB per
`MRI_fft_gaussian`.

### The pattern

For each 3D array
`X` allocated as

```c
X = malloc(D * sizeof(float**));
for (i = 0; i < D; i++) {
  X[i] = malloc(D * sizeof(float*));
  for (j = 0; j < D; j++)
    X[i][j] = malloc(D * sizeof(float));
}
```

the cleanup must be

```c
for (i = 0; i < D; i++) {
  for (j = 0; j < D; j++)
    free(X[i][j]);
  free(X[i]);
}
free(X);
```

Both functions
(`FFTswitch_with_z`
and `MRI_fft`)
use only the
single `free(X)`
form, leaking the
inner allocations.

### Comparison with
`FFTinv_quarter`

`FFTinv_quarter` at
`fftutils.cpp:534-567`
allocates a fresh
3D array and
returns it without
freeing anything —
which is fine (the
caller owns the
return value). But
its callers don't
free the old
buffer they
overwrite:

```c
/* utils/mrifilter.cpp:6181 — bug */
dst_r = FFTinv_quarter(dst_r, dimension);
/* The old dst_r is now leaked because the caller didn't
 * MRIfree it before the reassignment, and FFTinv_quarter
 * doesn't free its first argument. */
```

### Why this is severity 3

- **Reachable**:
  `mri_volsynth
  --pdf gaussianfft`
  is a documented
  option.
- **Silent**: tool
  reports
  successful
  completion;
  output is
  correct.
- **GB-scale leak
  per call** on a
  256-cube volume.
- **Bounded
  cumulative**:
  process exit
  reclaims; long-
  lived scripts
  that call
  MRI_fft_gaussian
  multiple times
  can OOM.
- **Below severity 4**
  because output is
  correct.

## Root Cause

The author wrote
single-`free(X)`
cleanups for
multi-level
heap-allocated 3D
arrays, perhaps
expecting that
`free` would
recursively
deallocate. C's
`free` only
deallocates the
exact pointer you
pass it; for
multi-level
arrays each level
must be freed
explicitly.

This is a common
C beginner mistake
that survived
into a production
file. It appears
consistently in
`FFTswitch_with_z`,
in `MRI_fft`'s
cleanup block,
and in the
overwrite pattern
at the `FFTinv_quarter`
call site.

## Impact

- **`mri_volsynth
  --pdf gaussianfft`
  on 256-cube
  volumes**: ~1.5 GB
  leaked per
  invocation.
- **Long-lived
  pipelines** that
  iterate over
  many FFT-Gaussian
  smoothings can
  OOM.
- **Severity:** 3 —
  silent, large
  leak; output
  correctness is
  not affected.

## Recommended Fix

Replace the
single-level
`free` calls
with proper
recursive
cleanup:

```diff
--- a/utils/fftutils.cpp
+++ b/utils/fftutils.cpp
@@ -528,7 +528,12 @@ void FFTswitch_with_z(float ***vect, int dimension, int is_y)
   for (z = 0; z < dimension; z++)
     for (y = 0; y < dimension; y++)
       for (x = 0; x < dimension; x++) vect[x][y][z] = res[x][y][z];
-  free(res);
+  for (z = 0; z < dimension; z++) {
+    for (y = 0; y < dimension; y++)
+      free(res[z][y]);
+    free(res[z]);
+  }
+  free(res);
 }
```

```diff
--- a/utils/mrifilter.cpp
+++ b/utils/mrifilter.cpp
```

a helper
`alloc3DFloat(dim)`
and
`free3DFloat(arr,

the
allocation /
deallocation
pattern.
