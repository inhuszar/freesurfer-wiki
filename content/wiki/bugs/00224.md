# [severity-2] [bug-00224] fem_elastic — TMesh::dir_img ignores its signalTopology argument: points inside inverted elements are always returned invalid

> [!bug] Synopsis
> `TMesh::dir_img(point, bool signalTopology = false)` is documented as returning an invalid point for an element with a topological defect only *if `signalTopology` is true*.
> The implementation never reads the argument: it invalidates the point whenever the element is inverted (`orientation_pb()`), for every caller. `FemTransform3d` defaults its flag to
> `false`, so on the default [[mri_cvs_register]] path, voxels that fall in tetrahedra still folded after untangling get an invalid image and mask 0 in each compressed step, contrary to the documented contract.
> Whether the contract or the code is the intended behaviour is a developer question.

## Affected Artefacts

- **Tool(s):** [[surf2vol]] (`convert_to_delta`, BC-error checks); results reach [[exportGcam]] and [[mri_cvs_register]]
- **Pipeline stage(s):** `mri_cvs_register` elastic step, each compressed FEM step
- **FreeSurfer version(s):** confirmed in `8.2.0`; the unused argument and the unconditional test have been there since the 2008-03-14 import (`4b881dc775`)
- **Platforms:** all
- **Triggering configuration:** any `TMesh::dir_img` call that lands in an element for which `orientation_pb()` is true, i.e. when inverted elements remain after (or before) untangling.

## Detailed Description

The declaration documents the flag:

```cpp
  // Mapping functionality
  // if signalTopology is true and the element has a topological defect,
  //    an invalid point will be returned
  tCoords        dir_img(const tCoords&,
                         bool signalTopology = false) const /*throw(gmpErr) */;
```

The definition:

```cpp
template<class Cstr, int n>
TCoords<double,n>
TMesh<Cstr,n>::dir_img(const tCoords& c_src,
                       bool signalTopology) const /*throw(gmpErr) */
{
  tCoords img;
  const tElement* pelt = this->element_at_point( c_src );

  if ( !pelt )
    img.status() = cOutOfBounds;
  else if ( pelt->orientation_pb() )
    img.invalidate();
  else
    img = pelt->dir_img( c_src );

  return img;
}
```

`signalTopology` is not referenced. `pelt->orientation_pb()` (default `Frame both`, comparing the sign of the reference volume with that of the deformed volume, [`fem_elastic/fem_3d.cpp:516-536`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fem_3d.cpp#L516-L536)) is evaluated for every point.

The flag is carried by `FemTransform3d`, which initialises it to `false` and forwards it:

```cpp
FemTransform3d::FemTransform3d()
    : Transform<3>()
{
  m_bdbg=false;
  m_signalTopology=false;
}

FemTransform3d::tCoords
FemTransform3d::doOwnImg(const tCoords& pt) const
{
  if (!m_sharedMesh)
    throw std::logic_error("FemTransform3d img -> NULL mesh");

  return m_sharedMesh->dir_img(pt, m_signalTopology);

}
```

The only place that sets it to `true` is inside a block that is not compiled (`#ifdef USE_SURF_FORWARD_MORPH`, [`fem_elastic/fsurf2vol.cpp:1763-1835`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1763-L1835); the assignment is [`fem_elastic/fsurf2vol.cpp:1780`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1780)). So in compiled code `signalTopology` is always `false`.

### Expected Behaviour

Per the contract: with `signalTopology == false` (the only value used) a point in an inverted element is mapped by that element's interpolation like any other point; only with `true` is it reported as invalid.

### Observed Behaviour

A point in an inverted element is invalid for every caller. On the CVS default path this occurs in `FemTransform3d::convert_to_delta`, which samples the mesh through `img()` → `doOwnImg()` → `dir_img(pt, false)` on a 256³ grid and records invalid points as `mask = 0` with no displacement
([`fem_elastic/morph.cpp:604-653`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L604-L653), test at [`fem_elastic/morph.cpp:633-643`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L633-L643)), and in `TSolver::check_bc_error`, which skips boundary-condition points whose image is invalid ("countInvalid", [`fem_elastic/solver.h:1152-1160`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/solver.h#L1152-L1160)).

### Reproducer

> [!gap] Reproducer not yet constructed
> The behaviour follows directly from the code (the argument is unused). No mesh with an inverted element was pushed through `dir_img` in a harness, and no CVS run was inspected for the number of voxels masked by this path.

## Root Cause

The parameter was added to the signature and documented but its use was never implemented (or was removed), leaving an unconditional `else if ( pelt->orientation_pb() ) img.invalidate();`. The code and the interface comment have disagreed since the 2008 import.

## Impact

- **Behaviour versus contract:** the documented way to obtain "valid but folded" images (flag `false`) does not exist; folded regions are always masked. In the compressed morphs of the CVS path, voxels inside residual folds receive no displacement and mask 0, so they depend on how [[exportGcam]] and the later stages treat masked voxels (not analysed here).
- **Possibly intentional:** invalidating inverted elements may be the behaviour the maintainers want (a folded map is not a valid map). The code has run this way for years; the parameter may simply be dead.
- **Severity 2 (low):** at worst a documentation/contract mismatch affecting only voxels in the (few) folded elements; the primary result is otherwise unaffected. If the flag was meant to protect those voxels it would be 3.

> [!gap] Is invalidation desired?
> If the intent is "always invalidate inverted elements", the fix is to remove the parameter and correct the comment, and the `m_signalTopology` member and `USE_SURF_FORWARD_MORPH` code are redundant. If the intent is the commented contract, honouring it changes the CVS default output (voxels in residual folds become valid and receive the folded element's interpolation,
> probably interacting with the cache issue in [[00199]]) and needs validation on real data.

## Recommended Fix

Needs a developer decision. Honouring the documented contract:

```diff
--- a/fem_elastic/mesh.h
+++ b/fem_elastic/mesh.h
   if ( !pelt )
     img.status() = cOutOfBounds;
-  else if ( pelt->orientation_pb() )
+  else if ( signalTopology && pelt->orientation_pb() )
     img.invalidate();
   else
     img = pelt->dir_img( c_src );
```

Alternatively remove the parameter, `FemTransform3d::m_signalTopology` and the dead `USE_SURF_FORWARD_MORPH` block, and change the comment at [`fem_elastic/mesh.h:182-183`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/mesh.h#L182-L183) to "an invalid point is returned for elements with a topological defect". A regression test should map a point inside a deliberately inverted tetrahedron with both flag values.

### Alternative Fixes Considered

Keep the behaviour, fix only the comment (zero risk, no output change). This is the safe choice until the maintainers confirm which behaviour is intended.

## Workarounds (If Any)

None needed to avoid wrong output; none to obtain "valid but folded" images.
