# ScaleStatTableByETIV — break instead of continue leaves all columns after eTIV un-normalized

> [!bug] Synopsis
> `ScaleStatTableByETIV` divides every numeric column of a stat
> table by the per-row eTIV value (and multiplies by a constant
> factor) so that downstream group analyses are intracranial-
> volume-normalised. It first scans the column names for
> `EstimatedTotalIntraCranialVol` or `eTIV` and stores the
> matched column index in `matched_column`. The scaling loop
> then iterates columns and uses `if (matched_column == c)
> break;` to "skip" the eTIV column itself — but `break`
> *terminates the outer loop*, not just the current iteration.
> Result: every column with index *strictly less than*
> `matched_column` is normalised; every column at or after
> `matched_column` is left untouched. `asegstats2table`
> documents (and emits) eTIV as the *second-to-last* column,
> with `BrainSegVol` as the last column, so the standard input
> to `mri_glmfit --scale-by-etiv` leaves `BrainSegVol` (and any
> column the user has appended after eTIV) silently
> un-normalised while every other measure *is* normalised.
> Group analyses then fit a GLM on a mixture of
> eTIV-normalised and raw-volume measures.

## Detailed Description

### Expected Behaviour

`ScaleStatTableByETIV` is documented (by name) as scaling the
non-eTIV measures so that they are expressed as a fraction of
each subject's intracranial volume (then multiplied by a
constant factor — `1e5` from the only call site at
[`mri_glmfit.cpp:929`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L929)).
The natural reading is: "for every column that is *not* the
eTIV column, replace `data[r][c]` with
`factor * data[r][c] / data[r][eTIV_col]`". The eTIV column
itself is exempt (it would always be `factor`).

### Observed Behaviour

The scaling loop
([`utils/stats.cpp:1800-1807`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/stats.cpp#L1800-L1807)):

```cpp
// scale values in table
for (int c = 0; c < table->ncols; c++) {
  if (matched_column == c) break;                     /* ← exits OUTER loop */
  for (int r = 0; r < table->nrows; r++) {
    table->data[r][c] /= table->data[r][matched_column];
    table->data[r][c] *= factor;
    MRIsetVoxVal(table->mri, c, 0, 0, r, table->data[r][c]);
  }
}
```

`break` terminates the *innermost enclosing* loop, which is
the outer `for (int c = …)` (the `if` is a sibling of the
inner `for`, not nested inside it). On reaching
`c == matched_column`, the function returns. Columns with
`c > matched_column` are *never* visited.

Worked example — typical `asegstats2table` row layout:

| col index | column name                |
|----------:|----------------------------|
|         0 | Left-Lateral-Ventricle     |
|         1 | Left-Inf-Lat-Vent          |
|       ... | …                          |
|     N − 3 | (last segmentation volume) |
|     N − 2 | **EstimatedTotalIntraCranialVol** (= matched_column) |
|     N − 1 | BrainSegVol                |

After the buggy loop:
- columns `0 … N−3` are normalised by eTIV (correct),
- column `N−2` (eTIV itself) is unchanged (correct),
- column `N−1` (BrainSegVol) is **unchanged** (silently wrong).

The `MRIsetVoxVal` line means the `StatTable->mri` that
`mri_glmfit` then assigns to `mriglm->y`
([`mri_glmfit.cpp:930`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L930))
contains a mixture of eTIV-normalised columns and raw
columns, with the un-normalised columns appearing as the last
columns of the design `y`.

  // search for eTIV measurement
  int matched_column = -1;
  for (int c = 0; c < table->ncols; c++) {
    std::string colname = table->colnames[c];
    if (("EstimatedTotalIntraCranialVol" == colname) or ("eTIV" == colname)) {
      matched_column = c;
      break;

  // couldn't find eTIV in table

## Root Cause

`break` and `continue` look identical at a glance and the
indentation here invites the misread. The author meant "skip
the eTIV column itself"; `continue` would do that, `break`
exits the loop.

## Impact

- **`mri_glmfit --scale-by-etiv` on `asegstats2table` output:**
  `BrainSegVol` (the last column) is left in raw mm³ while
  every other measurement is rescaled to `(mm³/mm³)·1e5`. A
  GLM fit on this `y` matrix mixes two unit systems; group
  contrasts that average across measures (or that touch the
  last column directly) give numerically wrong results
  without warning.
- **`mri_glmfit --scale-by-etiv` on any user-prepared table
  where eTIV is not the last column:** every column at or
  after eTIV is left un-normalised. Worst case: a user
  appends measurements after eTIV expecting the function to
  normalise them too — none are normalised.
- **Tables where eTIV happens to be the last column:** no
  observable defect (the `break` and the natural end-of-loop
  coincide).
- **`mri_segstats --etiv` direct usage:** unaffected — the
  bug is in the stat-table scaler, not in eTIV computation.

## Recommended Fix

```diff
   // scale values in table
   for (int c = 0; c < table->ncols; c++) {
-    if (matched_column == c) break;
+    if (matched_column == c) continue;
     for (int r = 0; r < table->nrows; r++) {
       table->data[r][c] /= table->data[r][matched_column];
       table->data[r][c] *= factor;
       MRIsetVoxVal(table->mri, c, 0, 0, r, table->data[r][c]);
     }
   }
```

A one-token change. With `continue`, the eTIV column itself
is the only one skipped, and every other column is scaled
regardless of its position relative to the eTIV column.

### Alternative Fixes Considered

- **Pre-snapshot the eTIV per row, then unconditionally scale
  every column.** Same observable behaviour as the
  `continue` fix; would slightly simplify the read pattern
  but adds a per-row buffer. Marginally less invasive
  diff-wise to use `continue`.
- **Reorder columns so eTIV is last in `LoadStatTable`.**
  Side-effects on every consumer of `STAT_TABLE`. Strongly
  not recommended.

## Workarounds (If Any)

- Hand-edit the input table so eTIV is the *last* numeric
  column before passing to `mri_glmfit --scale-by-etiv`. With
  eTIV last, the bug coincides with end-of-loop and the
  observable behaviour is correct.
- Pre-scale the table outside FreeSurfer (`awk` / pandas) and
  pass an already-normalised table without `--scale-by-etiv`.
