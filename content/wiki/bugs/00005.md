# [severity-3] [bug-00005] MRISaverageMarkedCurvatures — neighbour filter drops marked check

> [!bug] Synopsis
> The neighbour loop in `MRISaverageMarkedCurvatures` skips only
> ripped neighbours, not unmarked ones, so curvatures from outside the
> selected (marked) region bleed into the running average of vertices
> inside it. The sister function `MRISaverageMarkedVals` — written on
> the same template a few lines below — correctly skips both ripped
> and unmarked neighbours. The outer loop still only writes back into
> marked vertices, so the two functions only diverge in which
> neighbours contribute to the mean.

## Affected Artefacts

- **Tool(s):** [[mris_ms_refine]] — the only in-tree caller of
  `MRISaverageMarkedCurvatures`.
- **Pipeline stage(s):** _N/A_ — `mris_ms_refine` is a specialised
  multi-spectral surface-refinement driver and is not part of the
  standard [[wiki/pipelines/recon-all|recon-all]] flow. Catalogued because the function is a
  generic library helper and the inconsistency with its sister
  `MRISaverageMarkedVals` is exactly the kind of latent trap that
  bites a future caller.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit
  `d932c45b79`.
- **Platforms:** all.
- **Triggering configuration:** any call where the surface has both
  marked and unmarked live vertices adjacent to one another. If
  every live vertex is marked, the two functions are equivalent.

## Detailed Description

`MRISaverageMarkedCurvatures` and `MRISaverageMarkedVals` are
parallel: they both perform `navgs` iterations of one-ring smoothing
over a restricted region defined by `v->marked`. They differ only in
the scalar field being smoothed (`curv` vs. `val`). One would expect
them to skip the same neighbours when computing the mean.

They do not. The curvature variant only tests `vn->ripflag`; the val
variant tests both `vn->ripflag` and `vn->marked == 0`.

### Expected Behaviour

To restrict smoothing to the marked region, the neighbour loop should
include only live, marked neighbours of a live, marked central vertex
— matching the behaviour of `MRISaverageMarkedVals`. Unmarked
neighbours (which typically sit just outside the selected region)
carry curvatures from a different context and should not contribute
to the average of the marked region.

### Observed Behaviour

At boundary vertices of the marked region (marked vertices whose
first-ring includes unmarked live vertices), the average pulls in
curvature values from just outside the region. Over repeated
iterations the boundary is drifted toward the outside-region mean.
Vertices strictly inside the marked region — whose whole first-ring
is marked — are unaffected.

### Reproducer

> [!gap] Reproducer not yet constructed
> A unit-style exercise: take any cortical surface, mark a contiguous
> patch of vertices, write distinctive curvature values into the
> marked patch and a contrasting value outside, call
> `MRISaverageMarkedCurvatures(mris, 10)`, and compare to a hand-rolled
> smoother that only averages marked-to-marked. The divergence
> localises to a one-ring-thick band along the patch boundary and
> grows with `navgs`.

Defective body:

```cpp
int MRISaverageMarkedCurvatures(MRI_SURFACE *mris, int navgs)
{
  int i, vno, vnb, vnum;
  float curv, num;

  for (i = 0; i < navgs; i++) {
    for (vno = 0; vno < mris->nvertices; vno++) {
      VERTEX_TOPOLOGY const * const vt = &mris->vertices_topology[vno];
      VERTEX                * const v  = &mris->vertices         [vno];
      if (v->ripflag || !v->marked) {
        continue;
      }
      curv = v->curv;
      int const * pnb  = vt->v;
      vnum = vt->vnum;
      for (num = 0.0f, vnb = 0; vnb < vnum; vnb++) {
        VERTEX const * const vn = &mris->vertices[*pnb++]; /* neighboring vertex pointer */
        if (vn->ripflag) {        // ← missing: || vn->marked == 0
          continue;
        }
        num++;
        curv += vn->curv;
      }
      num++; /*  account for central vertex */
      v->tdx = curv / num;
    }
    for (vno = 0; vno < mris->nvertices; vno++) {
      VERTEX * const v = &mris->vertices[vno];
      if (v->ripflag || v->marked == 0) {
        continue;
      }
      v->curv = v->tdx;
    }
  }
  mrisComputeCurvatureMinMax(mris);
  return (NO_ERROR);
}
```

## Root Cause

A copy-paste elision: when `MRISaverageMarkedCurvatures` was derived
from the curvature-agnostic `MRISaverageCurvatures`, the outer-loop
`marked` check was added but the inner loop's `marked` check was not
mirrored. The val variant, authored (or edited) independently, got
the additional inner check.

## Impact

- The only in-tree caller at the audited commit is
  [`mris_ms_refine/mris_ms_refine.cpp:2260`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mris_ms_refine/mris_ms_refine.cpp#L2260). That tool is not part of
  [[wiki/pipelines/recon-all|recon-all]] and is used only for multi-spectral refinement
  experiments.
- Wherever the defect fires, curvatures at the boundary of the
  marked region drift toward the surrounding (unmarked) curvature
  distribution. Over multiple smoothing iterations the effect
  accumulates, broadening the marked boundary by approximately one
  vertex-ring per iteration in curvature-space.

## Recommended Fix

```diff
       for (num = 0.0f, vnb = 0; vnb < vnum; vnb++) {
         VERTEX const * const vn = &mris->vertices[*pnb++]; /* neighboring vertex pointer */
-        if (vn->ripflag) {
+        if (vn->ripflag || vn->marked == 0) {
           continue;
         }
         num++;
         curv += vn->curv;
       }
```

## Workarounds (If Any)

Callers that need region-restricted curvature smoothing today can
call `MRISaverageCurvatures` on a mris copy whose unmarked vertices
have been temporarily ripped, then restore the ripflags. Alternatively,
use `MRISaverageMarkedVals` on a scratch `val` field populated from
`curv`, then copy back.
