# [severity-4] [bug-00108] `GLMcMatrices` PCC branch is permanently skipped — `mri_glmfit` partial-correlation output is silently all zero

> [!bug] Synopsis
> `GLMcMatrices`
> ([`utils/fsglm.cpp:414-452`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L414-L452))
> sets up per-contrast matrices used by
> `GLMtest` to compute the partial
> correlation coefficient (PCC). The
> per-contrast block is gated on
> `glm->C[n]->rows == 1 && glm->DoPCC` and
> reads:
>
> ```cpp
> if (glm->C[n]->rows == 1 && glm->DoPCC) {
>   MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
>   if (glm->Dt[n] == NULL) continue;        /* :426 — bug */
>   glm->Dt[n] = MatrixCopy(D, glm->Dt[n]);  /* :427 — never reached */
>   MatrixFree(&D);
>   glm->XCt[n] = MatrixMultiplyD(glm->X, glm->Ct[n], glm->XCt[n]);
>   ...
> }
> ```
>
> The check `if (glm->Dt[n] == NULL)
> continue;` reads the **destination
> buffer**, which is initialised to NULL by
> `GLMalloc`
> ([`:213`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L213)),
> and never set non-NULL because the
> assignment at `:427` is the only writer
> and is unreachable.
>
> The pre-refactor code wrote
>
> ```cpp
> glm->Dt[n] = MatrixColNullSpace(glm->Ct[n], &err);
> if (glm->Dt[n] == NULL) continue;
> ```
>
> where the null check defensively tested
> the just-computed null-space matrix. The
> 2022-06-24 refactor (commit `709169895b`,
> "Made glm stuff more amenable to per-voxel
> analysis") moved the assignment to a local
> `D`, then planned to copy `D` into
> `glm->Dt[n]` afterwards — but left the null
> check on `glm->Dt[n]`, inverting its
> meaning.
>
> Effect: on every call, `Dt[n]` stays NULL,
> the rest of the PCC setup
> (`XCt`/`XDt`/`RD`/`Xcd`/`Xcdt`/`sumXcd`/
> `sumXcd2`) is skipped, and `GLMtest`'s PCC
> consumer at
> [`:641`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L641)
> falls into the `else glm->pcc[n] = 0;`
> branch at
> [`:654`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L654).
>
> `mri_glmfit` defaults `DoPCC = 1`
> ([`:767`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L767))
> and writes a `pcc.<contrast>.mgh` map per
> contrast
> ([`:2220`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L2220))
> — that map is silently all zero for
> single-row contrasts.

## Affected Artefacts

- **Tool:** [[mri_glmfit]] — the canonical
  GLM analysis tool. `DoPCC = 1` is the
  default and only suppressed by `--no-pcc`,
  `--osgm`, or specific design-matrix flags.
- **Output file:** `pcc.<contrast>.mgh`
  written to each contrast's output
  subdirectory.
- **Pipeline stage(s):** any group analysis
  using `mri_glmfit` with single-row
  contrasts (the typical case for t-tests
  and regression slopes).
- **Triggering configuration:** any
  `mri_glmfit` invocation that doesn't pass
  `--no-pcc` and uses a 1-row contrast.
- **FreeSurfer version(s):** introduced by
  commit
  [`709169895b`](https://github.com/freesurfer/freesurfer/commit/709169895b)
  on 2022-06-24 (FreeSurfer 7.4.x development
  cycle). Confirmed in `$FREESURFER_VERSION`
  (commit `d932c45b79`).

## Detailed Description

### What the refactor was meant to do

The pre-refactor pattern allocated a fresh
matrix per call by passing `NULL` as the
destination of `MatrixColNullSpace`. The
refactor's stated goal (commit message:
"Made glm stuff more amenable to per-voxel
analysis") was to reuse pre-allocated
storage so per-voxel calls don't allocate
inside the inner loop. The intended pattern
is:

```cpp
MATRIX *D = MatrixColNullSpace(...);
glm->Dt[n] = MatrixCopy(D, glm->Dt[n]);  /* alloc-or-reuse */
MatrixFree(&D);
```

`MatrixCopy(D, glm->Dt[n])` allocates a new
matrix when `glm->Dt[n] == NULL` and reuses
the existing one otherwise — that's the
intended idempotent allocation. The early
`continue` was retained as a defensive guard
for the case where `MatrixColNullSpace`
itself returned NULL (e.g. ill-conditioned
contrast).

But the guard now tests the **wrong
variable**: `glm->Dt[n]` (the destination,
NULL on first call) instead of `D` (the
local from `MatrixColNullSpace`).

### What actually happens

| call | `glm->Dt[n]` before check | `continue` taken? | `Dt[n]` after call |
|------|---------------------------|-------------------|--------------------|
| 1st  | NULL (from `GLMalloc`)    | yes               | NULL               |
| 2nd  | NULL (still — never set)  | yes               | NULL               |
| ...  | NULL                      | yes               | NULL               |

Because `Dt[n]` is never assigned, all
subsequent PCC consumers gate on
`Dt[n] != NULL` and fall back to zero:

- [`fsglm.cpp:641`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L641)
  — `if (glm->Dt[n] != NULL)` skipped.
- [`fsglm.cpp:654`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L654)
  — `glm->pcc[n] = 0;` taken.

### Memory side-effect

`MATRIX *D` is allocated by
`MatrixColNullSpace` *before* the check, so
the early `continue` also leaks `D`.
Per-voxel call frequency × number of
contrasts × volume size = many MB / GB
leaked over a typical analysis. (Out of
scope for this report — user excluded memory
leaks — but listed for completeness.)

### Output the user sees

The contrast-output directory contains the
following files, of which only `pcc.mgh` is
affected:

```
gamma.mgh    — correct
F.mgh        — correct
sig.mgh      — correct (–log10 p)
z.mgh        — correct
pcc.mgh      — silently all zero
```

A user running `freeview pcc.mgh` sees a
uniformly black volume with no diagnostic.
There is no console warning that PCC was not
computed.

## Root Cause

A copy-paste / refactor oversight. The
diff for the introducing commit shows the
intended change:

```diff
-    glm->Dt[n] = MatrixColNullSpace(glm->Ct[n], &err);
+    MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
      if (glm->Dt[n] == NULL) continue;
+    glm->Dt[n] = MatrixCopy(D,glm->Dt[n]);
+    MatrixFree(&D);
```

The author moved the assignment to a local
`D`, but the existing null check was
literally retained character-for-character
— including its reference to `glm->Dt[n]`.
The intended semantic (test the just-
computed null space) was lost.

The bug evades unit-style testing because
PCC is a derived statistic — F, p, z all
work fine — and `mri_glmfit` produces
"sensible" output overall. Visual inspection
of the `pcc.mgh` map is the only way to
notice.

## Impact

- **Default `mri_glmfit` analyses with
  single-row contrasts:** `pcc.<contrast>.mgh`
  output map is uniformly zero.
- **No console warning, no error:** the
  failure mode is silent.
- **Severity:** 4 — high. Standard analysis
  tool, default flag setting, externally
  visible result, but only one of several
  output statistics is affected.

## Recommended Fix

```diff
--- a/utils/fsglm.cpp
+++ b/utils/fsglm.cpp
@@ -422,9 +422,9 @@ int GLMcMatrices(GLMMAT *glm)
   if (glm->C[n]->rows == 1 && glm->DoPCC) {
     // These are for the computation of partial correlation coef
     // null space of contrast space
     MATRIX *D = MatrixColNullSpace(glm->Ct[n], &err);
-    if (glm->Dt[n] == NULL) continue;
+    if (D == NULL) continue;
     glm->Dt[n] = MatrixCopy(D,glm->Dt[n]);
     MatrixFree(&D);
     // design matrix projected onto contrast space
```

A single-character variable change. The
fixed version tests `D` (the just-computed
null space) instead of `glm->Dt[n]` (the
unwritten destination). After the patch:

- `Dt[n]` is allocated on first call and
  reused on subsequent calls.
- `GLMtest`'s `if (glm->Dt[n] != NULL)`
  branch fires and PCC is computed.

## Workarounds

For users who need PCC values now: there is
no flag-level workaround inside
`mri_glmfit`. Options:

1. Apply the one-line patch and rebuild.
2. Compute PCC externally from `gamma.mgh`,
   `eres.mgh` and the design matrix (the
   formula at
   [`fsglm.cpp:648-651`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L648-L651)
   is straightforward to reimplement in
   numpy / R).
