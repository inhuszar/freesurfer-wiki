# [severity-3] [bug-00098] `MRIzeroMean` / `MRIzeroMeanTimecourse` / `MRImeanTimecourse` — z-loop iterates over `height` instead of `depth`

> [!bug] Synopsis
> Four sites in three adjacent functions in
> [`utils/mri.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp)
> bound the slice (`z`) loop with
> `mri_src->height` rather than `mri_src->depth`:
>
> ```cpp
> /* MRIzeroMean :16008, accumulator */
> for (z = 0; z < mri_src->height; z++) { ... mean += MRIgetVoxVal(...,x,y,z,f); }
>
> /* MRIzeroMean :16017, writer */
> for (z = 0; z < mri_src->height; z++) { ... MRIsetVoxVal(...,x,y,z,f, val − mean); }
>
> /* MRIzeroMeanTimecourse :16036 */
> for (z = 0; z < mri_src->height; z++) { ... }
>
> /* MRImeanTimecourse :16063 */
> for (z = 0; z < mri_src->height; z++) { ... }
> ```
>
> The other ~10 functions in the same file
> ([`:8772`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L8772),
> [`:8779`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L8779),
> [`:14056`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L14056),
> [`:14088`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L14088),
> etc.) correctly use `mri_src->depth` for the
> `z`-loop bound, confirming the typo.

## Affected Artefacts

- **Tools (in-tree callers):**
  - [[mris_make_face_parcellation]]
    ([`:1758`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_make_face_parcellation/mris_make_face_parcellation.cpp#L1758))
    calls `MRImeanTimecourse(mri_cmatrix,
    NULL)`. `mri_cmatrix` is a face-by-face
    connectivity matrix shaped roughly
    `(width=N, height=N, depth=1, nframes=K)`.
    The buggy loop iterates `z = 0..N-1` while
    the actual `depth` is 1 — every iteration
    with `z >= 1` reads/writes voxels outside
    the allocated slice buffer.
  - [[mris_intensity_profile]]
    ([`:713`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_thickness/mris_intensity_profile.cpp#L713),
    [`:725`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_thickness/mris_intensity_profile.cpp#L725))
    calls `MRIzeroMeanTimecourse` on
    `mri_profiles` (per-vertex intensity
    profiles, typically `(nvertices, 1, 1,
    nlayers)`). Here `height == depth == 1`, so
    the typo is invisible by coincidence.
  - [[mri_jacobian]]
    ([`:158`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_jacobian/mri_jacobian.cpp#L158))
    calls `MRIzeroMean` on a jacobian volume.
    Typical conformed input is 256³ cubic, so
    `height == depth` and the typo is
    invisible.
- **Pipeline stage(s):** none in default
  `recon-all`. Affects connectivity / intensity
  profile / jacobian post-processing.
- **Triggering configuration:** any non-cubic
  input. Most severe for inputs where
  `height >> depth` (OOB access) — exemplified
  by the connectivity matrix in
  `mris_make_face_parcellation`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mri.cpp:15998-16023 — MRIzeroMean */
MRI *MRIzeroMean(MRI *mri_src, MRI *mri_dst)
{
  ...
  for (mean = 0.0, f = 0; f < mri_src->nframes; f++)
    for (x = 0; x < mri_src->width; x++) {
      for (y = 0; y < mri_src->height; y++) {
        for (z = 0; z < mri_src->height; z++) {            /* :16008 — should be ->depth */
          mean += MRIgetVoxVal(mri_src, x, y, z, f);
        }
      }
    }
  mean /= (mri_src->width * mri_src->height *
           mri_src->depth * mri_src->nframes);             /* normaliser uses correct depth */
  for (f = 0; f < mri_src->nframes; f++)
    for (x = 0; x < mri_src->width; x++) {
      for (y = 0; y < mri_src->height; y++) {
        for (z = 0; z < mri_src->height; z++) {            /* :16017 — should be ->depth */
          MRIsetVoxVal(mri_dst, x, y, z, f,
                       MRIgetVoxVal(mri_src, x, y, z, f) - mean);
        }
      }
    }
  return (mri_dst);
}
```

`MRIzeroMean` has a compounding bug: the
accumulator loop covers `height` slices but the
divisor `(width * height * depth * nframes)`
treats the sum as if it covered all `depth`
slices. The computed mean is therefore biased
by a factor of `height/depth` (or worse, with
OOB-read contamination).


```cpp
/* utils/mri.cpp:16051-16071 — MRImeanTimecourse */
MRI *MRImeanTimecourse(MRI *mri_src, MRI *mri_dst)
{
  ...
  for (x = 0; x < mri_src->width; x++) {
    for (y = 0; y < mri_src->height; y++) {
      for (z = 0; z < mri_src->height; z++) {              /* :16063 — should be ->depth */
        for (mean = 0.0, f = 0; f < mri_src->nframes; f++)
          mean += MRIgetVoxVal(mri_src, x, y, z, f);
        mean /= mri_src->nframes;
        MRIsetVoxVal(mri_dst, x, y, z, 0, mean);
      }
    }
  }
  ...
}
```

For both timecourse functions, only the slice
range `z = 0..height-1` is touched. If
`depth > height`, slices `[height, depth)` are
**never written** in `mri_dst` — they retain
whatever was in `mri_dst` before (likely zeros
if freshly allocated, but stale data if caller-
provided). If `depth < height`, the loop
accesses voxels at `z >= depth` which lie
outside the slice array — undefined behaviour.

### Concrete impact on `mris_make_face_parcellation`

`mri_cmatrix` for an `nfaces × nfaces × 1`
connectivity matrix triggers `depth = 1, height
= N`. The buggy loop iterates `z = 0..N-1`,
with `MRIgetVoxVal(mri_src, x, y, z, f)` for
`z >= 1` reading past the single allocated
slice. The mean per `(x, y)` is therefore
contaminated with whatever heap memory follows
the slice buffer.

`mri_jacobian` and `mris_intensity_profile`
inputs happen to satisfy `height == depth` (256³
cubic / 1×1×1 profile slabs), so the typo is
silent for them.

## Root Cause

Copy-paste typo. The y-loop bound
`mri_src->height` was duplicated into the z-loop
slot, four times in three closely-grouped
functions, without updating to `mri_src->depth`.

## Impact

- **Cubic / `height == depth` inputs:** none
  (typo invisible).
- **`mris_make_face_parcellation`** with non-
  trivial face count (`height = depth = ` `nfaces`?
  actually need to verify shape): if `mri_cmatrix`
  has `depth = 1, height = N`, the loop reads
  past the allocated slice buffer for `z >= 1`,
  producing meaningless mean values.
- **`MRIzeroMean` global mean:** biased by
  `height/depth` ratio whenever the input is
  non-cubic.
- **Severity:** 3 — flag-gated / specific
  input-shape conditions; can produce
  out-of-bounds memory access in realistic
  use cases.
