# [severity-2] [bug-00173] csvprint — off-by-one row-length guard (len(row)<i) crashes with IndexError; --tsv overridden by file extension

> [!bug] Synopsis
> `csvprint` extracts named columns from a CSV/TSV file. The guard that
> is supposed to skip rows missing a requested column uses
> `if(len(row) < i)` where `i` is a **0-based** column index. The correct
> bound for a valid `row[i]` access is `len(row) <= i`. As written, a row
> that is short by **exactly one** column (`len(row) == i`) is *not*
> skipped, and the subsequent `row[i]` access raises an uncaught
> `IndexError`, aborting the program. Separately, the `--tsv` flag sets
> the delimiter to a tab, but a later block unconditionally re-derives the
> delimiter from the file extension, so `--tsv` is silently overridden for
> any file whose name ends in `.csv` (or that lacks a `.tsv` extension).

## Affected Artefacts

- **Tool(s):** [[csvprint]].
- **Pipeline stage(s):** _N/A_ — `csvprint` is a standalone CSV/TSV
  field-extraction utility (ADNI/GSP table parsing); it is not part of
  [[wiki/pipelines/recon-all|recon-all]].
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — pure Python.
- **Triggering configuration:**
  - **IndexError:** any input whose data rows are short by exactly one
    column relative to the highest requested field index (e.g. a
    trailing field omitted on some rows). Always reachable, no flag
    required.
  - **--tsv override:** `--tsv` on any file whose name ends in `.csv`,
    or any tab-delimited file that does not end in `.tsv`.

## Detailed Description

`csvprint` reads the header row, resolves each requested `--f` field to
a column index via `row.index(field)` (producing **0-based** indices
stored in `ind`), then for every data row it (a) skips rows with missing
data and (b) prints the requested columns.

### Defect 1 — off-by-one row-length guard

The "skip missing data" guard at
[`scripts/csvprint:200-207`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/csvprint#L200-L207)
is:

```python
  for i in ind:
    if(len(row)<i):
      skip=1
      break
    if(len(row[i])==0):
      skip=1
      break
```

`i` is a 0-based index. A `row[i]` access is valid iff `i < len(row)`,
i.e. iff `len(row) > i`. The guard should therefore set `skip` when
`len(row) <= i`. The code uses the strict `len(row) < i`, which is `True`
only when the row is short by **two or more** columns. When the row is
short by exactly one — `len(row) == i` — the guard is `False`, control
falls through to `if(len(row[i])==0)`, and `row[i]` indexes one past the
end of the list → `IndexError: list index out of range`. The same off-by-one
guard is duplicated at
[`scripts/csvprint:211-213`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/csvprint#L211-L213)
in the print loop, so even if the first guard were corrected the second
would need the same fix.

There is no `try/except` anywhere in the script, so the `IndexError`
propagates to the top level and terminates the program with a traceback
and a non-zero exit — one malformed row aborts the entire extraction
instead of being skipped.

### Defect 2 — --tsv overridden by file extension

`--tsv` sets `delimiter="\t"` during argument parsing
([`scripts/csvprint:79-80`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/csvprint#L79-L80)).
After parsing, the script re-derives the delimiter purely from the file
extension
([`scripts/csvprint:133-135`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/csvprint#L133-L135)):

```python
filename, file_extension = os.path.splitext(csvfile);
if(file_extension == ".csv"): delimiter=",";
if(file_extension == ".tsv"): delimiter="\t";
```

This block runs unconditionally and *after* argument parsing, so for a
tab-delimited file named `foo.csv`, the `.csv` branch resets
`delimiter=","`, discarding the `--tsv` request. The entire tab-delimited
header is then parsed as a single field and field lookup fails with
`ERROR: cannot find field ...`. `--tsv` only survives when the file
extension is neither `.csv` nor `.tsv` (e.g. `.txt`, `.dat`, or no
extension).

### Expected Behaviour

- A data row missing one (or more) of the requested columns should be
  **skipped** (the script's stated intent: "Skip missing data"), not
  crash the program.
- `--tsv` should force tab-delimited parsing regardless of the file's
  name.

### Observed Behaviour

- A row short by exactly one column raises
  `IndexError: list index out of range` and aborts (traceback, exit 1).
- `--tsv` on a `.csv`-named tab file is ignored; the file is parsed with
  commas and every field lookup fails.

### Reproducer

```bash
# Defect 1: row short by exactly one column -> IndexError
printf 'A,B,C\n1,2,3\n4,5\n' > t.csv
csvprint --csv t.csv --f C
#   3
#   Traceback (most recent call last):
#     File ".../csvprint", line 204, in <module>
#       if(len(row[i])==0):
#   IndexError: list index out of range

# Defect 2: --tsv overridden by .csv extension
printf 'A\tB\tC\n1\t2\t3\n' > t2.csv
csvprint --csv t2.csv --f B --tsv
#   ERROR: cannot find field B in ['A\tB\tC']    <- comma delimiter used despite --tsv
# Same content named .txt works, because the extension override does not fire:
printf 'A\tB\tC\n1\t2\t3\n' > t2.txt
csvprint --csv t2.txt --f B --tsv
#   2
```

Both reproducers were executed against the installed
`/usr/local/freesurfer/8.2.0/bin/csvprint` and produced the output shown.

## Root Cause

1. **Off-by-one:** the guard treats the 0-based index `i` as if a row of
   length `i` could be safely indexed at `[i]`. The bound for a valid
   access is `i <= len(row) - 1`, i.e. `len(row) > i`; the skip condition
   must be its negation `len(row) <= i`. The strict `<` leaves the
   boundary case `len(row) == i` unguarded, where the very next line
   dereferences `row[i]` out of range.
2. **--tsv override:** the delimiter is set twice — once from the flag,
   once from the extension — and the extension block runs last and
   unconditionally, so it wins. The two mechanisms are not reconciled
   (no "only infer from extension if the user did not specify").

## Impact

- **Latent, low severity.** Most ADNI/GSP tables that `csvprint` is used
  on are rectangular (every row has every column), so the off-by-one is
  not exercised in routine use. When it *is* hit (a table with a missing
  trailing field on some rows), the tool aborts mid-extraction with a
  traceback rather than skipping the offending row — a hard failure of a
  diagnostic/QA helper, not corruption of pipeline output.
- The `--tsv` override silently changes the parse for `.csv`-named tab
  files, yielding "cannot find field" errors that look like a bad field
  name rather than a delimiter problem — confusing but loud (the tool
  errors out, it does not produce wrong values silently).
- `csvprint` is not part of any default neuroimaging pipeline, so no
  recon-all / trac-all result is affected — hence severity 2.

## Recommended Fix

Correct both copies of the off-by-one guard, and make the extension
inference defer to an explicitly requested delimiter:

```diff
   # Skip missing data
   skip = 0
   for i in ind:
-    if(len(row)<i):
+    if(len(row)<=i):
       skip=1
       break
     if(len(row[i])==0):
       skip=1
       break
   # endfor
   if(skip): continue
 
   # Print out each field in field list
   for i in ind:
-    if(len(row)<i): print("len(row)=%d, i=%d" % (len(row),i))
+    if(len(row)<=i): continue
     sys.stdout.write ("%s " % (row[i]))
```

For the `--tsv` precedence, only infer the delimiter from the extension
when the user did not request one explicitly — e.g. track whether
`--tsv` was given and guard the extension block:

```diff
-filename, file_extension = os.path.splitext(csvfile);
-if(file_extension == ".csv"): delimiter=",";
-if(file_extension == ".tsv"): delimiter="\t";
+filename, file_extension = os.path.splitext(csvfile);
+if(delimiter == ","):   # only auto-detect if --tsv was not passed
+  if(file_extension == ".csv"): delimiter=",";
+  if(file_extension == ".tsv"): delimiter="\t";
```

(or, more explicitly, set a `tsv_flag` in `parse_args` and skip the
extension block when it is set).

### Alternative Fixes Considered

The print-loop guard (Site B) could simply be deleted now that the
upstream skip guard (Site A) handles short rows — but keeping a defensive
`continue` there is harmless and protects against future regressions.

## Workarounds (If Any)

- **IndexError:** ensure every requested field is present (and non-short)
  on every row before running, or request only columns guaranteed to be
  populated. Pre-cleaning the file (padding short rows with empty
  trailing fields) avoids the crash.
- **--tsv override:** rename a tab-delimited input to a `.tsv` extension
  (or to a non-`.csv` name) so the extension inference selects (or does
  not clobber) the tab delimiter.
