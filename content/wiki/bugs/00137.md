# [severity-3] [bug-00137] `DTIeigvals2RA` uses wrong Relative Anisotropy formula — missing one factor of `λmean` in denominator

> [!bug] Synopsis
> ```cpp
> /* utils/dti.cpp:587-625 */
> MRI *DTIeigvals2RA(MRI *evals, MRI *mask, MRI *RA)
> {
>   ...
>   for (c = 0; c < evals->width; c++) {
>     for (r = 0; r < evals->height; r++) {
>       for (s = 0; s < evals->depth; s++) {
>         ...
>         v1 = MRIgetVoxVal(evals, c, r, s, 0);
>         v2 = MRIgetVoxVal(evals, c, r, s, 1);
>         v3 = MRIgetVoxVal(evals, c, r, s, 2);
>         vmean = (v1 + v2 + v3) / 3.0;
>         if (vmean != 0) {
>           vsse = pow(v1 - vmean, 2.0) + pow(v2 - vmean, 2.0) + pow(v3 - vmean, 2.0);
>           v = sqrt(vsse / (3.0 * vmean));        /* :615 — bug, missing vmean² */
>         }
>         else
>           v = 0;
>         MRIsetVoxVal(RA, c, r, s, 0, v);
>       }
>     }
>   }
>   return (RA);
> }
> ```
>
> The standard Basser & Pierpaoli (1996) definition of Relative Anisotropy is:
>
> $$\mathrm{RA} = \frac{1}{\sqrt{3}\,\lambda_{\text{mean}}} \sqrt{\sum_i (\lambda_i - \lambda_{\text{mean}})^2}$$
>
> Squaring:
>
> $$\mathrm{RA}^2 = \frac{\sum_i (\lambda_i - \lambda_{\text{mean}})^2}{3\,\lambda_{\text{mean}}^2} = \frac{v_{\text{sse}}}{3\,\lambda_{\text{mean}}^2}$$
>
> The code's `v = sqrt(vsse / (3.0 * vmean));` computes `v² = vsse / (3·λmean)`, missing one factor of `λmean` in the denominator. The ratio between code and correct value:
>
> $$\frac{v_{\text{code}}}{\mathrm{RA}_{\text{correct}}} = \sqrt{\lambda_{\text{mean}}}$$
>
> For typical white-matter DTI eigenvalues with `λmean ≈ 1e−3 mm²/s`, `sqrt(λmean) ≈ 0.032`, so the reported RA is ~3.2 % of the true value — a silent ~30× under-report. Dimensionally, the code produces units of `[mm²/s]^0.5` (square root of diffusivity) instead of a unitless ratio.

## Detailed Description

### What the standard formula says

Relative Anisotropy (Basser & Pierpaoli 1996, equation 50 in J Magn Reson B; also Westin et al. 2002; and reproduced in essentially every DTI textbook) is:

$$\mathrm{RA} = \frac{\sigma(\lambda)}{\lambda_{\text{mean}}} = \frac{1}{\sqrt{3}\,\lambda_{\text{mean}}} \sqrt{\sum_{i=1}^{3} (\lambda_i - \lambda_{\text{mean}})^2}$$

— the **standard deviation of the eigenvalues divided by their mean**, with a factor of 1/sqrt(3) so that for an isotropic tensor RA = 0 and for a perfectly linear tensor (`λ1 ≫ λ2 = λ3 = 0`) RA → 1 (some conventions normalise to sqrt(2)/sqrt(3); the code's `1/sqrt(3)` factor lines up with the dominant convention).

Squaring both sides:

$$\mathrm{RA}^2 = \frac{1}{3\,\lambda_{\text{mean}}^2} \sum_i (\lambda_i - \lambda_{\text{mean}})^2 = \frac{v_{\text{sse}}}{3\,\lambda_{\text{mean}}^2}$$

So the **correct** code is one of:

```cpp
v = sqrt(vsse / 3.0) / vmean;
// or equivalently
v = sqrt(vsse / (3.0 * vmean * vmean));
```

### What the code computes

```cpp
v = sqrt(vsse / (3.0 * vmean));
```

Squaring: `v² = vsse / (3 · vmean)`. Missing one factor of `vmean` in the denominator.

### Magnitude of the error

The ratio between the buggy result and the correct value is `sqrt(vmean)` (with the right dimensional reading: the buggy `v` carries an extra `sqrt(λmean)` factor that the correct RA doesn't).

For typical brain tissue diffusion eigenvalues:

| Tissue | `λmean` (mm²/s) | `sqrt(λmean)` | Code result vs. true RA |
|---|---|---|---|
| White-matter (anisotropic) | ~7e−4 | ~0.026 | ~2.6 % of true RA |
| Grey matter (isotropic) | ~8e−4 | ~0.028 | ~2.8 % of true RA |
| CSF | ~3e−3 | ~0.055 | ~5.5 % of true RA |

So the `ra.<format>` file written by `mri_glmfit --dti` has values roughly **30×–40× smaller** than the textbook RA. The voxel-wise *ranking* is preserved (RA and `code_v` are both monotonic in vsse for fixed vmean), so cluster locations are unchanged, but the absolute values are nonsense, comparison with other DTI packages (FSL `dtifit`, MRtrix `tensor2metric`, dipy) is meaningless, and group-level effect sizes reported in mm²/s-derived units are wrong.

### Dimensional check

- `vsse = Σ(λi − λmean)²` has units `[mm²/s]²`.
- `vmean` has units `[mm²/s]`.
- Correct: `RA² = vsse / (3·vmean²) → dimensionless`. ✓
- Code: `v² = vsse / (3·vmean) → [mm²/s]`. ⇒ `v` has units `[mm²/s]^0.5`, i.e. `mm/s^0.5`. Dimensionally wrong.

This is the strongest hint that something is off: a ratio metric should be dimensionless, but the code's output isn't.

### Why this is severity 3

- **Wrong numerical output on a documented CLI option** (`mri_glmfit --dti`). The `ra.<format>` file is produced silently with wrong values.
- **Not on the default `recon-all` path** (DTI processing is a separate workflow), so most users aren't exposed.
- **Voxel-wise statistics on the RA volume are still internally consistent** (monotone transform of vsse at fixed vmean), so cluster maps and ranks are preserved — but absolute values and cross-tool comparison are broken.
- **Not severity 4+** because (a) the GLM output also includes FA, ADC, VR, MD, axial/radial diffusivity which are all correct, and (b) DTI users rarely report RA as the primary measure (FA dominates), so the silent-wrong RA tends to be a secondary indicator most users skim past.
- **Above severity 2** because the formula is unambiguously wrong (dimensionally inconsistent) and the file is a user-visible deliverable from a documented option.

## Root Cause

A simple algebra slip in the squared form. The author likely worked from the form:

$$\mathrm{RA} = \frac{1}{\lambda_{\text{mean}}} \sqrt{\frac{v_{\text{sse}}}{3}}$$

and tried to combine the two terms under one sqrt, writing `sqrt((1/vmean²) · vsse/3)`. While simplifying, they kept only one factor of `vmean` instead of two:

```text
correct:   sqrt(vsse / (3 * vmean * vmean))
written:   sqrt(vsse / (3 * vmean))           ← lost one vmean
```

That this is *probably* an algebra slip rather than a deliberate formula choice is supported by:
1. The dimensional inconsistency (output isn't unitless).
2. The neighbouring FA computation at `:576` correctly handles its analogous `1/Σλi²` denominator inside the sqrt.
3. The VR computation at `:657` correctly cubes `vmean` (it doesn't write `pow(vmean, 1.0)` or `pow(vmean, 2.0)`).

So the author understood the standard family of definitions — RA is the outlier.

## Impact

- **`mri_glmfit --dti` users writing `ra.<format>`:** the absolute RA values are wrong by a factor of `sqrt(λmean)` — ~30× too small for typical brain tissue diffusivities. Cluster locations are correct, but absolute values are nonsense.
- **Comparison with other DTI tools** (FSL `dtifit -ra`, MRtrix `tensor2metric -ra`, dipy `tensor_RA`): values disagree by ~30×.
- **Group-level GLM statistics on the RA volume:** t-statistics are still meaningful internally (it's a monotone transform of vsse at fixed vmean), but effect sizes and reported betas in physical units are wrong.
- **`fa.<format>`, `vr.<format>`, `adc.<format>`, `radialdiff.<format>`, axialdiff:** unaffected — the bug is isolated to the RA computation.
- **`recon-all`:** not affected (DTI is not part of the standard pipeline).
- **Severity 3** — wrong numerical output on a documented CLI option; silent and easily missed because the cluster maps look plausible.

## Recommended Fix

```diff
--- a/utils/dti.cpp
+++ b/utils/dti.cpp
@@ -612,7 +612,7 @@ MRI *DTIeigvals2RA(MRI *evals, MRI *mask, MRI *RA)
         vmean = (v1 + v2 + v3) / 3.0;
         if (vmean != 0) {
           vsse = pow(v1 - vmean, 2.0) + pow(v2 - vmean, 2.0) + pow(v3 - vmean, 2.0);
-          v = sqrt(vsse / (3.0 * vmean));
+          v = sqrt(vsse / 3.0) / vmean;
         }
         else
           v = 0;
```

One-token fix: lift `vmean` out of the sqrt's denominator and divide instead. The equivalent inside-sqrt form `v = sqrt(vsse / (3.0 * vmean * vmean));` is also correct but slightly less readable. The `if (vmean != 0)` guard above is unchanged and still prevents a divide-by-zero.

## Workarounds

For users who need correct RA values from `mri_glmfit --dti` outputs: post-process the `ra.<format>` file by multiplying by `sqrt(λmean)`, where `λmean = (evals[0]+evals[1]+evals[2])/3` from the eigenvalue volume (or, equivalently, recompute from the eigenvalue volume directly):

```sh
# evals = 3-frame eigenvalue volume produced by mri_glmfit --dti
mri_concat --i evals.<format> --mean --o lambda_mean.<format>
mri_concat --i ra.<format> --mul lambda_mean.<format> --sqrt --o ra_corrected.<format>
# Wait: that gives ra_corrected = ra · sqrt(lambda_mean). Correct relation is ra_correct = ra · sqrt(lambda_mean).
```

(The exact `mri_concat` recipe depends on the version; the math is `ra_corrected = ra_buggy * sqrt(λmean)`.) Better: recompute RA from the eigenvalue volume directly with a short script, since RA is a one-line function of `evals`.
