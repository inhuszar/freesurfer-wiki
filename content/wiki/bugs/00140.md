# [severity-3] [bug-00140] `mris_apply_reg --randn` / `--ones` NULL-deref `SrcVal` immediately — segfault on documented CLI flags

> [!bug] Synopsis
> ```cpp
> /* mris_apply_reg/mris_apply_reg.cpp:170-236, abridged */
> // Load in source data
> SrcVal = NULL;                                              /* :171 */
>
> if (DoSynthRand) {
>   ...
>   MRIrandn(SrcVal->width, SrcVal->height, SrcVal->depth,    /* :176-177 — NULL deref */
>            SrcVal->nframes, 0, 1, SrcVal);
> }
> else if (DoSynthOnes != 0) {
>   ...
>   MRIconst(SrcVal->width, SrcVal->height, SrcVal->depth,    /* :181-182 — NULL deref */
>            SrcVal->nframes, 1, SrcVal);
> }
> else if (AnnotFile) {
>   ...                                                       /* populates SrcVal */
> }
> else if (SurfXYZFile) {
>   ...
>   SrcVal = MRIcopyMRIS(NULL, SurfSrc, 2, "z");               /* populates SrcVal */
> }
> else if (nLabelFiles > 0) {
>   SrcVal = MRIallocSequence(...);                          /* populates SrcVal */
>   ...
> }
> else {
>   ...
>   SrcVal = MRIread(SrcValFile);                            /* populates SrcVal */
> }
> ```
>
> The if/else chain is mutually exclusive: only one branch runs. The first two branches (the synth-rand and synth-ones paths) dereference `SrcVal` while it is still NULL from line 171; the four loading branches all populate `SrcVal` before use. The natural reading of the help text — `--randn : replace input with WGN`, `--ones : replace input with ones` — is that synth overwrites the loaded source. But the if/else order means that whenever `DoSynthRand` (or `DoSynthOnes`) is set, the loader branches never run, and the synth branch immediately reads `SrcVal->width` from a NULL pointer.

## Detailed Description

### What the code does

`SrcVal = NULL;` at line 171, immediately followed by:

```cpp
if (DoSynthRand) {
  if (SynthSeed < 0) SynthSeed = PDFtodSeed();
  printf("INFO: synthesizing, seed = %d\n", SynthSeed);
  srand48(SynthSeed);
  MRIrandn(SrcVal->width, SrcVal->height, SrcVal->depth,
           SrcVal->nframes, 0, 1, SrcVal);
}
else if (DoSynthOnes != 0) {
  printf("INFO: filling input with all 1s\n");
  MRIconst(SrcVal->width, SrcVal->height, SrcVal->depth,
           SrcVal->nframes, 1, SrcVal);
}
else if (AnnotFile) { … populates SrcVal via MRISannotIndex2Seg … }
else if (SurfXYZFile) { … populates SrcVal via MRIcopyMRIS … }
else if (nLabelFiles > 0) { … populates SrcVal via MRIallocSequence + MRISlabel2Mask … }
else { SrcVal = MRIread(SrcValFile); … }
```

The chain is mutually exclusive — exactly one branch runs. The synth branches do not load any source first; they read `SrcVal->width / height / depth / nframes` from the still-NULL pointer.

### Why the help-text intent doesn't match the implementation

The CLI help at `:664-665` reads:

```
--randn : replace input with WGN
--ones  : replace input with ones
```

The word "replace" implies a sequence of (1) load input, (2) overwrite with synth. A correct implementation would be:

```cpp
// (1) Load source as usual
if (AnnotFile) { … }
else if (SurfXYZFile) { … }
else if (nLabelFiles > 0) { … }
else { SrcVal = MRIread(SrcValFile); … }

// (2) Overwrite with synth if requested (non-exclusive)
if (DoSynthRand) {
  if (SynthSeed < 0) SynthSeed = PDFtodSeed();
  srand48(SynthSeed);
  MRIrandn(SrcVal->width, SrcVal->height, SrcVal->depth,
           SrcVal->nframes, 0, 1, SrcVal);
}
if (DoSynthOnes) {
  MRIconst(SrcVal->width, SrcVal->height, SrcVal->depth,
           SrcVal->nframes, 1, SrcVal);
}
```

The current code has the synth branches *as the first two clauses* of the same if/else, making them not "replacements" but exclusive alternatives. And since `SrcVal = NULL;` is the only state set before the chain starts, those two clauses always crash.

### Trace for `mris_apply_reg --src brain.mgh --randn --streg ...`

1. `parse_commandline` parses `--randn`, setting `DoSynthRand = 1` and (at `:340`) leaving `SrcValFile = "brain.mgh"`.
2. `check_options` at `:702-753` runs:
   - `:704` checks `SrcValFile == NULL && AnnotFile == NULL && …` — `SrcValFile = "brain.mgh"` is non-NULL, so the check passes.
   - All other guards are satisfied (assuming a valid command line otherwise).
   - Returns cleanly.
3. In `main`, `SrcVal = NULL;` at `:171`.
4. `if (DoSynthRand)` at `:172` — true. Enter branch.
5. `:176-177`: `MRIrandn(SrcVal->width, SrcVal->height, SrcVal->depth, SrcVal->nframes, 0, 1, SrcVal);` — `SrcVal->width` dereferences NULL. **SEGFAULT**.

The user never sees the source data they passed — the program crashes before any load.

### Why this is severity 3

- **Triggered by two documented CLI flags** (`--randn`, `--ones`) on `mris_apply_reg`.
- **SEGFAULT, not a hang or wrong output** — the program dies before doing any work.
- **Not on the default `recon-all` path**; the affected flags are diagnostic / synthesis utilities.
- **Above severity 2** because the crash happens on every invocation of the documented flag, with no useful diagnostic; the user has no obvious workaround (passing `--src foo.mgh` doesn't help because the synth branch runs first regardless).
- **Below severity 4** because the affected flags are opt-in QA / testing options rather than primary functionality.

## Root Cause

The if/else chain is structured as "pick one source of input data" — six mutually-exclusive sources, of which two (`--randn`, `--ones`) are *generators* and four are *loaders*. The generators were placed at the top of the chain, presumably so they could short-circuit the loaders. But the generators read `SrcVal->{width,height,depth,nframes}` to know how big to synthesise — and `SrcVal` has not been populated at that point.

The correct mental model — and the one the help text describes — is "load, then optionally synth-overwrite." The implementation conflated "generator" with "loader" and put them in the same exclusive chain.

## Impact

- **`mris_apply_reg --randn` (with or without `--src`):** segfault on every invocation.
- **`mris_apply_reg --ones` (with or without `--src`):** segfault on every invocation.
- **All other `mris_apply_reg` modes** (`--src`, `--src-annot`, `--src-label`, `--src-xyz`, `--lta`, `--m3z`): unaffected — the four loader branches all populate `SrcVal` before use.
- **`recon-all`:** unaffected. `recon-all` does not pass `--randn` or `--ones`.
- **Severity 3** — every invocation of two documented CLI flags crashes; opt-in diagnostic option, not a primary pipeline path.

The fix:
1. Remove the `if (DoSynthRand) … else if (DoSynthOnes) …` heads of the if/else chain.
2. Promote what was previously `else if (AnnotFile)` to the chain's head.
3. Re-add the synth-rand and synth-ones overwrites *after* the loader chain, as non-exclusive `if` blocks (not `else if`).

This matches the help-text intent ("replace input with WGN") and the four already-correct loader branches now run unconditionally before any synth.

## Workarounds

Until the fix lands, callers who need synth-WGN or synth-ones output from `mris_apply_reg` must do the synthesis themselves before invocation:

```sh
# Synthesize random source upstream, then resample as normal
mri_volsynth --pdf gaussian --gausmean 0 --gausstd 1 \
             --dim <nverts> 1 1 1 --o /tmp/randn.mgh
mris_apply_reg --src /tmp/randn.mgh --streg src.reg trg.reg --trg out.mgh
```

(Replace `mri_volsynth` with `mri_const` for `--ones` equivalent.) Avoid `--randn` / `--ones` entirely until the segfault is fixed.
