# [severity-3] [bug-00063] `mri_morphology` — the `mode` argument silently runs morphological *open* instead of mode-filter

> [!bug] Synopsis
> `mri_morphology`
> ([`mri_morphology/mri_morphology.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_morphology/mri_morphology.cpp))
> defines a `MODE_FILTER` operation constant at
> [`:51`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_morphology/mri_morphology.cpp#L51)
> alongside the other morphological operations
> (`ERODE`, `DILATE`, `CLOSE`, `OPEN`, `ERODE_THRESH`,
> `DILATE_THRESH`, `ERODE_BOTTOM`, `FILL_HOLES`, etc.).
> The CLI parser at
> [`:113-114`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_morphology/mri_morphology.cpp#L113-L114)
> handles the user-facing string `"mode"`:
>
> ```cpp
> else  if (!stricmp(argv[2], "mode"))
>     operation = OPEN ;     /* (!) should be MODE_FILTER */
> ```
>
> It maps to `OPEN`, not `MODE_FILTER`. Worse, the
> downstream `switch (operation)` statement has no
> `case MODE_FILTER:` clause at all — even if the
> mapping were correct, the operation would fall to
> `default: break;` and emit no output of value.
>
> Users running `mri_morphology <in> mode <niter>
> <out>` get a morphological-open result (erode then
> dilate) instead of a mode-filter. Same intermediate
> output type (label volume), so the substitution is
> silent.

## Affected Artefacts

- **Tool:** [[mri_morphology]] with the `mode` op
  (e.g. `mri_morphology in.mgz mode 1 out.mgz`).
- **Pipeline stage(s):** none in default `recon-all`.
  Affects user pipelines that explicitly invoke
  `mri_morphology mode`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
#define ERODE          1
#define DILATE         2
#define CLOSE          3
#define OPEN           4
#define DILATE_LABEL   5
#define MODE_FILTER    6                            /* :51 — defined */
#define ERODE_THRESH   7
#define DILATE_THRESH  8
#define ERODE_BOTTOM   9
#define FILL_HOLES     10
...
else  if (!stricmp(argv[2], "mode"))
    operation = OPEN ;                              /* :114 — wrong destination */
```

Switch in `main`:

```cpp
switch (operation) {
  case FILL_HOLES: ...
  case ERODE_BOTTOM: ...
  case DILATE: ...
  case CLOSE: ...
  case OPEN:                                         /* :191 — what "mode" lands in */
    mri_dst = NULL ;
    for (i = 0 ; i < niter ; i++) {
      mri_dst = MRIerode(mri_src, mri_dst) ;
      MRIcopy(mri_dst, mri_src) ;
    }
    for (i = 0 ; i < niter ; i++) {
      mri_dst = MRIdilate(mri_src, mri_dst) ;
      MRIcopy(mri_dst, mri_src) ;
    }
    break ;
  case ERODE: ...
  case ERODE_THRESH: ...
  case DILATE_THRESH: ...
  /* (no case MODE_FILTER) */
  default: break ;                                   /* :252 — would land here if mapped correctly */
}
```

So today `mri_morphology … mode …` produces
morphological-open output. If the CLI mapping is fixed
without also adding the `case MODE_FILTER:` body, the
user would see an unmodified copy of the input (the
`default: break` falls through, mri_dst is whatever
was last assigned — `nullptr` from
[`:69`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_morphology/mri_morphology.cpp#L69)).

## Root Cause

A two-step omission:
1. The CLI handler was written or copy-pasted with
   `OPEN` instead of `MODE_FILTER`.
2. The implementation case was never added to the
   switch.

`MRImostFreqNeighbor` exists in `utils/mri2.cpp:2153`
and could implement the operation per-voxel, but no
caller of it exists in `mri_morphology.cpp`.

## Impact

- **User-facing:** any caller of
  `mri_morphology <in> mode <niter> <out>` gets a
  morphological-open output (erode N times then
  dilate N times) silently labelled "mode". For label
  volumes, mode-filter and open produce visibly
  different segmentations.
- **Severity:** medium. The wrong output is silent —
  the file is created and looks plausible. Pipelines
  relying on `mri_morphology mode` get wrong results.

## Recommended Fix

Two-part fix:

```diff
--- a/mri_morphology/mri_morphology.cpp
+++ b/mri_morphology/mri_morphology.cpp
@@ -111,8 +111,8 @@ int main(int argc, char *argv[]) {
   else  if (!stricmp(argv[2], "dilate_thresh"))
     operation = DILATE_THRESH ;
   else  if (!stricmp(argv[2], "mode"))
-    operation = OPEN ;
+    operation = MODE_FILTER ;
   else  if (!stricmp(argv[2], "erode_bottom"))
     operation = ERODE_BOTTOM ;
   else  if (!stricmp(argv[2], "fill_holes"))
@@ -207,6 +207,17 @@ int main(int argc, char *argv[]) {
       MRIcopy(mri_dst, mri_src) ;
     }
     break ;
+  case MODE_FILTER:
+    mri_dst = MRIclone(mri_src, NULL) ;
+    for (i = 0 ; i < niter ; i++) {
+      for (int z = 0 ; z < mri_src->depth ; z++)
+        for (int y = 0 ; y < mri_src->height ; y++)
+          for (int x = 0 ; x < mri_src->width ; x++)
+            MRIsetVoxVal(mri_dst, x, y, z, 0,
+                         MRImostFreqNeighbor(mri_src, x, y, z, 0, 1)) ;
+      MRIcopy(mri_dst, mri_src) ;
+    }
+    break ;
   case ERODE_THRESH:
```

The `MRImostFreqNeighbor` helper is defined at
[`utils/mri2.cpp:2153`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L2153)
and returns the most-frequent label in a local
neighbourhood — exactly what a label-volume mode
filter wants.

Alternative: drop the `mode` CLI keyword entirely
and remove the `MODE_FILTER` `#define`. That option
is cleaner if the design decision is "mode filter is
out of scope for `mri_morphology`."

## Workarounds

For users who need a label-volume mode filter, use
[[mri_threshold]] / [[mri_concat]] pipelines or a
custom Python wrapper around
`MRImostFreqNeighbor`. Avoid `mri_morphology mode`.

- **Discovered:** 2026-05-01 by agent (CLI

- **Evidence:**
  - `MODE_FILTER` defined at `:51` but never used —

    matching `MODE_FILTER`. Pattern-match against
    sibling cases (`"dilate" → DILATE`, etc.)
    confirms the typo.
