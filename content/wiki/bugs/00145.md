# [severity-3] [bug-00145] `mri_diff --no-absdiff` silently misses bulk negative-direction differences and reports the wrong `maxdiff`

> [!bug] Synopsis
> ```cpp
> /* mri_diff/mri_diff.cpp:471-509 (abridged) */
> val1 = MRIgetVoxVal(InVol1, 0, 0, 0, 0, mode);
> val2 = MRIgetVoxVal(InVol2, 0, 0, 0, 0, mode);
> double maxdiff = fabs(val1 - val2);          /* :473 — typically 0 for background */
> int ndiff = 0;
> for (c=...; r=...; s=...; f=...) {
>   val1 = MRIgetVoxVal(InVol1, c, r, s, f, mode);
>   val2 = MRIgetVoxVal(InVol2, c, r, s, f, mode);
>   double diff = val1 - val2;                  /* :485 — signed */
>   if (fabs(diff) > pixthresh) ndiff++;        /* :486 — correctly abs */
>   …
>   if (AbsDiff)  diff = fabs(diff);            /* :492 — DEFAULT (AbsDiff=1) */
>   if (DiffAbs)  diff = fabs(fabs(val1)-fabs(val2));
>   if (DiffPct)  diff = 100*(val1-val2)/((val1+val2)/2.0);
>   …
>   if (maxdiff < diff) {                       /* :503 — signed comparison */
>     maxdiff = diff;
>     cmax=c; rmax=r; smax=s; fmax=f;
>   }
> }
>
> if (maxdiff > pixthresh) {                    /* :535 — gates the diff branch */
>   printf("Volumes differ in pixel data\n");
>   …
>   if (ndiff > diffcountthresh) {              /* :551 — only reached if maxdiff > pixthresh */
>     ExitStatus = 106;
>     if (ExitOnDiff) exit(106);
>   }
> }
> ```
>
> Default invocation is **correct**: `AbsDiff = 1` (defined at [`:193`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_diff/mri_diff.cpp#L193)), so `:492` applies `fabs()` and `:503` compares non-negative values. The bug fires under `--no-absdiff` ([`:726`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_diff/mri_diff.cpp#L726): `AbsDiff = 0`) when also `DiffAbs=0` and `DiffPct=0` (both default).
>
> Under that flag combination:
>
> 1. `diff = val1 - val2` stays signed.
> 2. `maxdiff` is seeded from `fabs(val1[0,0,0,0] - val2[0,0,0,0])` — usually `0` because the corner voxel is background in both volumes.
> 3. The comparison `maxdiff < diff` updates only when `diff > maxdiff`. With `maxdiff = 0` and all `diff ≤ 0`, no update ever happens.
> 4. At `:535`, `if (0 > pixthresh)` is false (default `pixthresh = 0`). The "Volumes differ" branch is **skipped entirely**.
> 5. `ndiff` is checked **inside** that branch ([`:551`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_diff/mri_diff.cpp#L551)), so even though `ndiff` (correctly using `fabs(diff)`) is non-zero, the exit-on-diff code path is unreachable. Program exits 0.
>
> Two consequences:
>
> - **Silent miss of bulk negative-direction diffs.** Any volume pair where `val2[i] ≥ val1[i]` everywhere — a uniformly scaled-up version of the same data, an fMRI baseline vs activation map, a normalisation regression — is reported as "no difference" under `--no-absdiff` even when every voxel differs.
> - **Misleading `maxdiff` printout.** When some diffs are positive and some negative, `maxdiff` reports the maximum positive value only; a larger-magnitude negative diff is not reflected. A user looking at the printed `maxdiff` is told the worst-case discrepancy is the positive direction's max, which can be wildly smaller than the true `max |diff|`.

## Affected Artefacts

- **Tool(s):** [[mri_diff]]
- **Pipeline stage(s):** _not on default `recon-all`_; widely used as a regression-test / CI tool to compare expected vs actual volume outputs.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`; earliest known: _unknown_.
- **Platforms:** all.
- **Triggering configuration:** `mri_diff --no-absdiff … vol1 vol2` (or any invocation that sets `AbsDiff=0` without also setting `DiffAbs` or `DiffPct`). Default invocation (no `--no-absdiff`) is correct.

## Detailed Description

`mri_diff` is the FreeSurfer regression-test tool used by `make check`, internal CI pipelines, and user-side test suites to compare a reference volume against a candidate volume. The pixel-comparison loop tracks the maximum per-voxel difference and the count of voxels that differ beyond a threshold; the program then exits with a non-zero status (`106`) if any difference is found.

The default invocation (`AbsDiff = 1`) applies `fabs()` to the per-voxel `diff` before the max-tracking comparison and is correct. The `--no-absdiff` option exists to give users access to the signed difference (e.g., for inspecting the `--diffvol` output, for `--avgdiff` signed-mean, or for pure "is val1 always ≤ val2" tests). When that option is set, the rest of the pipeline — which assumes `maxdiff` is the maximum |diff| — breaks: `maxdiff` becomes "maximum positive diff", with a floor of `fabs(val1[0,0,0,0] - val2[0,0,0,0])`.

### Expected Behaviour

`maxdiff` should track the maximum absolute difference regardless of the `AbsDiff`/`DiffAbs`/`DiffPct` flag, because the threshold check at [`:535`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_diff/mri_diff.cpp#L535) (`if (maxdiff > pixthresh)`) is the gate for the entire diff-reporting branch and the `ExitOnDiff` exit. The transformations applied at `:492-494` are intended for the `--diffvol`, `--diffabsvol`, and `--diffpct` *outputs*, not for the threshold gate.

### Observed Behaviour

Under `--no-absdiff`, `maxdiff` tracks "maximum *signed* diff with a floor of `fabs(initial)`". For all-negative-diff inputs, this is constant at the initial value (usually `0`) and never updates. The diff-reporting branch and the `ndiff > diffcountthresh` exit are then unreachable.

### Reproducer

```bash
# Two volumes that differ everywhere in the foreground, all in
# the negative direction (val2 > val1).
mri_volsynth --dim 64 64 64 1 --pdf const --val 100 --o vol1.mgz
mri_volsynth --dim 64 64 64 1 --pdf const --val 200 --o vol2.mgz

# Default (AbsDiff=1) — correctly reports the difference and exits 106:
mri_diff vol1.mgz vol2.mgz
echo "exit: $?"   # expected: 106

# With --no-absdiff — silently exits 0:
mri_diff --no-absdiff vol1.mgz vol2.mgz
echo "exit: $?"   # observed: 0  (BUG — should be 106)
```

## Root Cause

`maxdiff` is overloaded with two responsibilities: (1) the threshold gate at `:535`, (2) the reported "worst voxel" coordinate / value for the diagnostic printout and `--diff` file. The transformations at `:492-494` are output-shaping (for `--diffvol`/`--avgdiff`) and should not influence `:503`. The fix is to track `maxabsdiff = max(fabs(val1-val2))` separately for the threshold gate, while letting `diff` (possibly signed under `--no-absdiff`) drive only the per-voxel output writes.

## Impact

- **`--no-absdiff` invocations missing diffs.** Anyone using `--no-absdiff` to inspect signed differences gets exit 0 when val2 is uniformly larger than val1 (or vice versa with a different first-voxel seed). For regression-test CI pipelines that exercise `--no-absdiff`, this silently masks one entire failure mode.
- **`maxdiff` printout wrong under mixed-sign diffs.** Even when the diff is detected, the reported worst-case is the max positive direction only.
- **Default-path is correct.** This bug does *not* fire when `--no-absdiff` is absent; the default `AbsDiff=1` saves the default invocation.

## Recommended Fix

Track a separate `max_abs_diff` for the threshold gate.

```diff
   val1 = MRIgetVoxVal(InVol1,c,r,s,f, mode);
   val2 = MRIgetVoxVal(InVol2,c,r,s,f, mode);
-  double maxdiff = fabs(val1-val2);
+  double maxdiff = fabs(val1-val2);
+  double max_abs_diff = maxdiff;
   …
   for (c=0; c < InVol1->width; c++) { … {
     double diff = val1-val2;
+    double abs_diff_here = fabs(diff);
+    if (max_abs_diff < abs_diff_here) {
+      max_abs_diff = abs_diff_here;
+    }
     if (fabs(diff) > pixthresh) ndiff++;
     …
     if (AbsDiff)  diff = fabs(diff);
     if (DiffAbs)  diff = fabs(fabs(val1)-fabs(val2));
     if (DiffPct)  diff = 100*(val1-val2)/((val1+val2)/2.0);
     …
     if (maxdiff < diff) {                  /* keep existing — drives the printout */
       maxdiff = diff;
       cmax = c; rmax = r; smax = s; fmax = f;
     }
   }
-  if (maxdiff > pixthresh) {               /* :535 */
+  if (max_abs_diff > pixthresh) {          /* gate on the true abs max */
     printf("Volumes differ in pixel data\n");
-    printf("maxdiff %12.8f at %d %d %d %d\n", maxdiff,cmax,rmax,smax,fmax);
+    printf("maxabsdiff %12.8f, signed maxdiff %12.8f at %d %d %d %d\n",
+           max_abs_diff, maxdiff, cmax, rmax, smax, fmax);
     …
```

### Alternative Fix

Simplest one-line fix: change `:503` from `if (maxdiff < diff)` to `if (maxdiff < fabs(val1-val2))` — uses the always-positive abs-diff for the gate, lets the cmax/rmax/smax/fmax fields still update on the absolute worst voxel. But this loses the "signed maxdiff" semantics that `--no-absdiff` users might want for the printout. The diff above keeps both pieces of information.

## Workarounds (If Any)

- **Don't pass `--no-absdiff`.** The default invocation works correctly.
- **Inspect `ndiff` separately.** Use `--count` to print `ndiff`; if ndiff > 0 but exit code is 0, the maxdiff gate missed the diff.
- **Use `--ssd` or `--rms`** to compute sum-of-squares / RMS differences — both are non-negative and unaffected by this bug.
