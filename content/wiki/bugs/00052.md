# [severity-3] [bug-00052] `HISTOseg` — bin index uses wrong operator precedence

> [!bug] Synopsis
> `HISTOseg`
> ([`utils/mri2.cpp:5717-5739`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L5717-L5739))
> builds a histogram of intensities from voxels in a
> given segmentation. The bin index for each voxel is
> computed at line 5731 as:
>
> ```cpp
> binno = round(v-bmin)/bdelta;
> ```
>
> Operator precedence parses this as
> `round(v - bmin) / bdelta`, not
> `round((v - bmin) / bdelta)`. The two expressions
> differ whenever `bdelta != 1`. Concretely, with
> `v=2.5`, `bmin=0`, `bdelta=0.5`:
>
> - intended `round((2.5-0)/0.5) = round(5) = 5`
> - actual `round(2.5-0)/0.5 = round(2.5)/0.5 = 2/0.5 = 4`
>
> The defect is **latent**: every in-tree caller passes
> `bdelta = 1` (an integer literal), which collapses
> both forms to the same value.

## Detailed Description

```cpp
HISTOGRAM *HISTOseg(MRI *seg, int segid, MRI *vol, double bmin, double bmax, double bdelta)
{
  ...
  nbins = round((bmax-bmin)/bdelta) + 1;
  h = HISTOinit(NULL, nbins, bmin, bmax);
  for(c=0; c < seg->width; c++){
    for(r=0; r < seg->height; r++){
      for(s=0; s < seg->depth; s++){
        vsegid  = MRIgetVoxVal(seg,c,r,s,0);
        if(vsegid != segid) continue;
        v = MRIgetVoxVal(vol,c,r,s,0);
        binno = round(v-bmin)/bdelta;                     /* (!) precedence */
        if(binno < 0)      binno=0;
        if(binno >= nbins) binno=nbins-1;
        h->counts[binno] ++;
      }
    }
  }
  return(h);
}
```

The `nbins` computation at the function head
`round((bmax-bmin)/bdelta) + 1` correctly parenthesises
the division before `round`. The voxel-mapping
expression at `:5731` is missing the same
parentheses.

For `bdelta = 1`, `round(x)/1 == round(x) ==
round(x/1)`, so the bug is dormant. For any other
`bdelta`, the binning is wrong (incorrect bin index,
clipped by the final `binno < 0` / `binno >= nbins`
guards but biased toward small bins for `bdelta < 1`
and toward large bins for `bdelta > 1`).

## Root Cause

Missing pair of parentheses. The function head got the
parenthesisation right; the per-voxel use did not.

## Impact

- **Currently latent.** All four in-tree callers pass
  `bdelta = 1`.
- **If a caller passes `bdelta != 1`:** voxels are
  binned incorrectly. Specifically, two voxels with
  values `v1` and `v2 = v1 + ε` for any non-integer
  `ε ∈ [0, bdelta)` may map to different bins (if
  `round(v1-bmin) != round(v2-bmin)`), even though the
  intended binning would put them in the same bin.
