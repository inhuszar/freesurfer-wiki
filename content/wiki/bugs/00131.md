# [severity-3] [bug-00131] `MRIerodeAndReplaceLabel` uses signed sum instead of L1 norm for neighborhood-topology test, over-eroding for topo ∈ {1, 2}

> [!bug] Synopsis
> ```cpp
> /* utils/mriset.cpp:692-714 */
> for (int dc = -1; dc < 2 && !stop; dc++) {
>     int c = c0 + dc;
>     if (c < 0 || c >= seg->width) continue;
>     for (int dr = -1; dr < 2 && !stop; dr++) {
>         int r = r0 + dr;
>         if (r < 0 || r >= seg->height) continue;
>         for (int ds = -1; ds < 2 && !stop; ds++) {
>             int s = s0 + ds;
>             if (s < 0 || s >= seg->depth) continue;
>             // topo 1=face, 2=face+edge, 3=face+edge+corner
>             if (abs(dc+dr+ds) > topo) continue;     /* :702 — bug */
>             int vsegid = MRIgetVoxVal(seg,c,r,s,0);
>             if (vsegid == segid) continue;
>             // …mark center as edge voxel and replace…
>         }
>     }
> }
> ```
>
> The Manhattan / L1 norm
> `|dc| + |dr| + |ds|` is
> the correct way to
> classify 3D
> neighborhood offsets
> into face / edge /
> corner:
>
> | offset type | example | `|dc|+|dr|+|ds|` |
> |-------------|---------|-----------------|
> | center | (0,0,0) | 0 |
> | face | (±1,0,0), (0,±1,0), (0,0,±1) | 1 |
> | edge | (±1,±1,0), (±1,0,±1), (0,±1,±1) | 2 |
> | corner | (±1,±1,±1) | 3 |
>
> But the code uses
> `abs(dc+dr+ds)` — the
> absolute value of the
> **signed** sum, which
> is NOT the L1 norm
> when offsets can have
> different signs.
>
> | offset | L1 norm | signed-sum-abs | bug effect (topo=1) |
> |--------|---------|----------------|---------------------|
> | (1,0,0) | 1 | 1 | included ✓ |
> | (1,1,0) | 2 | 2 | excluded ✓ |
> | (1,-1,0) | 2 | 0 | **included ✗** (should be edge, excluded for topo=1) |
> | (1,1,1) | 3 | 3 | excluded ✓ |
> | (1,1,-1) | 3 | 1 | **included ✗** (corner, should be excluded for topo<3) |
> | (1,-1,-1) | 3 | 1 | **included ✗** |
> | (-1,1,-1) | 3 | 1 | **included ✗** |
>
> For **topo = 1**
> (intended: face only,
> 6 neighbors): the
> buggy check admits 6
> face + 6 edges (the
> signed-sum-0 ones) +
> 6 corners (the
> signed-sum-±1 ones) =
> **18 neighbors**
> instead of 6.
>
> For **topo = 2**
> (intended: face +
> edge, 18 neighbors):
> the buggy check
> admits face + edge +
> some corners.
>
> For **topo = 3** (all
> 26): the predicate
> `abs(...) > 3` is
> false for every
> dc,dr,ds ∈ {-1,0,1},
> so all 27 cells are
> visited (the center
> is skipped earlier
> via `vsegid == segid`).
> Topo=3 happens to
> work.

## Detailed Description

### Enumeration of all 27 (dc,dr,ds) cells

For each `dc, dr, ds
∈ {-1, 0, 1}`, the L1
norm and signed-sum-abs:

```
(dc, dr, ds)  L1  |sum|   topo=1 (correct)  topo=1 (bug)
(-1,-1,-1)    3   3        skip               skip
(-1,-1, 0)    2   2        skip               skip
(-1,-1, 1)    3   1        skip               INCLUDED ✗
(-1, 0,-1)    2   2        skip               skip
(-1, 0, 0)    1   1        include            include ✓
(-1, 0, 1)    2   0        skip               INCLUDED ✗
(-1, 1,-1)    3   1        skip               INCLUDED ✗
(-1, 1, 0)    2   0        skip               INCLUDED ✗
(-1, 1, 1)    3   1        skip               INCLUDED ✗
( 0,-1,-1)    2   2        skip               skip
( 0,-1, 0)    1   1        include            include ✓
( 0,-1, 1)    2   0        skip               INCLUDED ✗
( 0, 0,-1)    1   1        include            include ✓
( 0, 0, 0)    0   0        center             center
( 0, 0, 1)    1   1        include            include ✓
( 0, 1,-1)    2   0        skip               INCLUDED ✗
( 0, 1, 0)    1   1        include            include ✓
( 0, 1, 1)    2   2        skip               skip
( 1,-1,-1)    3   1        skip               INCLUDED ✗
( 1,-1, 0)    2   0        skip               INCLUDED ✗
( 1,-1, 1)    3   1        skip               INCLUDED ✗
( 1, 0,-1)    2   0        skip               INCLUDED ✗
( 1, 0, 0)    1   1        include            include ✓
( 1, 0, 1)    2   2        skip               skip
( 1, 1,-1)    3   1        skip               INCLUDED ✗
( 1, 1, 0)    2   2        skip               skip
( 1, 1, 1)    3   3        skip               skip
```

For topo=1, **12 extra
neighbors** are
incorrectly admitted
(6 sign-mismatched
edges and 6
sign-mismatched
corners). Effective
neighborhood is 18
voxels instead of 6
(plus center).

For topo=2:
- All 6 face neighbors
  (correct): L1=1, |sum|=1.
- All 12 edge
  neighbors: L1=2,
  |sum| ∈ {0, 2}.
  Buggy check
  `|sum| > 2` is false
  for both → all 12
  included correctly.
- 8 corners: L1=3,
  |sum| ∈ {1, 3}.
  Buggy check
  `|sum| > 2` is true
  for |sum|=3 (skip)
  but false for
  |sum|=1 (include).
  6 corners
  incorrectly
  included.

So topo=2 effectively
becomes 6 face + 12
edge + 6 corner = 24
neighbors instead of
18. Still bias, less
than topo=1.

For topo=3: `|sum| > 3`
is false for all
27 cells. All
neighbors visited.
Topo=3 happens to be
correct by accident.

### Consequence for erosion

The function marks
the center voxel as
an "edge" if any
neighbor (per the
buggy filter) has a
different segid.
Over-broad
neighborhoods → more
voxels marked as
edges → more
aggressive erosion.

For a typical WM
segmentation:
- WM voxels at the
  WM-cortex boundary
  have face neighbors
  in cortex (different
  segid). These
  correctly trigger
  "edge" status under
  any topo.
- WM voxels one
  voxel inside from
  the boundary have
  face neighbors in
  WM and edge/corner
  neighbors in cortex.
  Under correct
  topo=1, these
  should NOT be
  marked as edges
  (all face neighbors
  are WM).
- Under buggy topo=1,
  some of these
  one-step-inside
  voxels get checked
  against
  diagonal-corner
  neighbors and
  triggered if any
  of those is
  cortex.

So the erosion
penetrates deeper
into the WM body than
the user-specified
"erode by N face-
adjacency steps."

### Why this is severity 3

- **Reachable**: default
  configuration of
  `mri_gtmseg
  --wm-erode N`.
- **Silent**: tool
  prints
  "topo=1" and
  proceeds; no error.
- **Systematic bias**:
  affects all PVC
  output volumes
  downstream of the
  gtmseg.
- **Bounded**: only
  affects WM edge
  shell; not whole-
  volume corruption.
- **Topo=3
  unaffected**: users
  who happened to
  pass `--wm-erode-topo
  3` get correct
  behavior.

## Root Cause

The author confused
the **signed sum**
`dc + dr + ds` with
the **L1 norm**
`|dc| + |dr| + |ds|`.
For 3D offsets with
all non-negative
components (or all
non-positive), these
are equal. But when
components have mixed
signs, the signed
sum collapses
(e.g., `(1, -1, 0)`
has L1 = 2 but
signed sum = 0).

The correct test:
```c
if (abs(dc) + abs(dr) + abs(ds) > topo) continue;
```

## Impact

- **`mri_gtmseg --wm-erode N`
  (default topo=1)**:
  WM is over-eroded.
  More voxels labeled
  5001/5002 (eroded
  WM) than expected;
  fewer voxels labeled
  2/41 (cerebral WM).
  GTM matrix rows
  shift accordingly.
- **PET PVC output
  values** for the
  WM-cortex boundary
  region are biased.
- **`mri_gtmseg --wm-erode N
  --wm-erode-topo 2`**:
  6 extra corner
  voxels included
  per WM voxel
  checked.
- **`--wm-erode-topo 3`**:
  unaffected.
- **Severity:** 3 —
  silent, systematic
  bias in a niche
  PVC tool with a
  documented
  user-facing flag.

## Recommended Fix

```diff
--- a/utils/mriset.cpp
+++ b/utils/mriset.cpp
@@ -699,7 +699,7 @@ MRI *MRIerodeAndReplaceLabel(MRI *seg, int segid, int replaceid, int topo, int i
               int s = s0 + ds;

               // topo 1=face, 2=face+edge, 3=face+edge+corner
-              if(abs(dc+dr+ds) > topo) continue;
+              if(abs(dc) + abs(dr) + abs(ds) > topo) continue;

```

One-character fix to
the predicate. After
the fix:
- topo=1: only 6 face
  neighbors.
- topo=2: 6 face + 12
  edge = 18.
- topo=3: all 26
  (unchanged).

For users of
`mri_gtmseg`: pass
`--wm-erode-topo 3`
to get the correct

it's the only safe
topo value before

Or: post-process
the eroded
`gtmseg.mgz` to
restore over-eroded
voxels back to
