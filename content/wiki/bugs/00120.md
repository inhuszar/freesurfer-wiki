# [severity-2] [bug-00120] `RandPerm` uses the naive shuffle (not Fisher-Yates); permutations are non-uniform

> [!bug] Synopsis
> ```cpp
> /* utils/evschutils.cpp:505-520 */
> int *RandPerm(int N, int *v)
> {
>   int tmp, n, n2;
>
>   if (v == NULL) v = (int *)calloc(sizeof(int), N);
>   for (n = 0; n < N; n++) v[n] = n;
>
>   for (n = 0; n < N; n++) {
>     n2 = (int)floor(drand48() * N);   /* :513 — bug: full range [0,N) */
>     tmp = v[n];
>     v[n] = v[n2];
>     v[n2] = tmp;
>   }
>
>   return (v);
> }
> ```
>
> Each iteration draws `n2` uniformly
> from `[0, N)` and swaps `v[n]` with
> `v[n2]`. This is the "naive shuffle"
> — known to produce a NON-uniform
> distribution over the `N!`
> permutations.
>
> The correct Fisher-Yates shuffle picks
> `n2` uniformly from `[n, N)` (the
> unshuffled tail):
>
> ```cpp
> for (n = 0; n < N; n++) {
>   n2 = n + (int)floor(drand48() * (N - n));
>   tmp = v[n]; v[n] = v[n2]; v[n2] = tmp;
> }
> ```
>
> Fisher-Yates produces each of the `N!`
> permutations with exact probability
> `1/N!`. The naive shuffle does
> `N^N` random choices but only `N!`
> outcomes, so some are more likely
> than others (because `N^N` is not
> divisible by `N!` for `N ≥ 3`).
>
> ### Concrete bias for `N = 3`
>
> Trace all 27 paths
> (`3 × 3 × 3` iterations):
>
> | resulting permutation | paths | probability |
> |------------------------|-------|-------------|
> | (0, 1, 2)             | 4     | 4/27 ≈ 0.148 |
> | (0, 2, 1)             | 5     | 5/27 ≈ 0.185 |
> | (1, 0, 2)             | 5     | 5/27 ≈ 0.185 |
> | (1, 2, 0)             | 5     | 5/27 ≈ 0.185 |
> | (2, 0, 1)             | 4     | 4/27 ≈ 0.148 |
> | (2, 1, 0)             | 4     | 4/27 ≈ 0.148 |
>
> Uniform would be `1/6 ≈ 0.167`. The
> bias factor between the most- and
> least-likely permutations is `5/4 =
> 1.25`.
>
> The bias diminishes for larger N but
> does not vanish.

## Detailed Description

### Why this matters for permutation tests

Permutation testing for statistical
significance:

1. Compute the observed statistic
   on the data.
2. Shuffle the data and recompute
   the statistic `K` times.
3. The p-value is the fraction of
   shuffled statistics that exceed
   the observed.

This requires the shuffles to be
drawn from the uniform distribution
over all `N!` permutations.
Otherwise, the empirical null
distribution is biased, and the
p-value is also biased (typically
slightly too liberal or
conservative depending on the
bias direction).

The bias here is small for
moderate N (the marginal
distribution of each element's
position converges to uniform as
`N → ∞`), but it's a known
correctness issue.

### Why the bug is hard to notice

For `N = 50` (typical study cohort
size), 50^50 ≫ 50!, so the bias
per permutation is tiny. Tools
that average over many runs
(`mri_glmfit-sim` typically uses
1000+ permutations) further dilute
the effect. Statistical sims
comparing biased-shuffle to
uniform-shuffle would need 10000+
runs to detect a difference.

But: the bug is real, and the fix
is trivial.

## Root Cause

The author wrote the obvious
"swap each element with a random
element" loop. This is a common
beginner mistake — it looks like
it should work but doesn't
produce a uniform distribution.
The standard Fisher-Yates fix is
to restrict the random pick to
the unshuffled tail.

## Impact

- **`mri_glmfit --perm` Type-I
  error control:** subtly biased.
  In practice, the bias is small
  enough that the impact on
  reported p-values is likely
  within the noise floor of typical
  studies (1000-permutation runs,
  N=50 subjects).
- **Severity:** 2 — known
  statistical correctness issue,
  but real-world impact is small
  and easily compensated by larger
  permutation counts.

## Recommended Fix

```diff
--- a/utils/evschutils.cpp
+++ b/utils/evschutils.cpp
@@ -510,8 +510,8 @@ int *RandPerm(int N, int *v)
   for (n = 0; n < N; n++) v[n] = n;

   for (n = 0; n < N; n++) {
-    n2 = (int)floor(drand48() * N);
+    n2 = n + (int)floor(drand48() * (N - n));
     tmp = v[n];
     v[n] = v[n2];
     v[n2] = tmp;
   }
```

Single-line change implementing
Fisher-Yates.

## Workarounds

For users running rigorous
permutation tests: use a larger
number of permutations to dilute
the bias; or use external
permutation tools (e.g., FSL's
`randomise`) with verified
uniform shuffling.
