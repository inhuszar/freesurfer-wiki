# [severity-2] [bug-00059] `gdfReadV1` — Input-count bounds check off by one

> [!bug] Synopsis
> `gdfReadV1`
> ([`utils/fsgdf.cpp:257`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsgdf.cpp#L257)
> et seq.) parses an FSGD file. The `Input` keyword
> handler at
> [`:651-664`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsgdf.cpp#L651-L664)
> guards against overrun:
>
> ```cpp
> if (gd->ninputs > FSGDF_NINPUTS_MAX) {                   /* :652 */
>   printf("ERROR: gdfReadV1: the number of inputs in FSGD file "
>          "exceeds the maximum allowed %d\n", FSGDF_NINPUTS_MAX);
>   return(NULL);
> }
> ...
> n = gd->ninputs; /* current input number */               /* :663 */
> r = fscanf(fp,"%s %s",gd->subjid[n],class_name);          /* :664 */
> ```
>
> `subjid` is declared as `char subjid[FSGDF_NINPUTS_MAX][100]`
> in
> [`include/fsgdf.h:92`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/fsgdf.h#L92)
> with `FSGDF_NINPUTS_MAX = 40000`
> ([`include/fsgdf.h:39`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/fsgdf.h#L39)).
> Valid indices are `0..39999`. The check uses strict
> `>`, so it accepts `ninputs == 40000` and falls
> through to `fscanf(fp, "%s %s", gd->subjid[40000], …)`
> — a write past the end of the array. The check
> only fires on the 40 002-nd Input line; the 40 001-st
> already corrupted memory.

## Affected Artefacts

- **Tool:** any consumer of `gdfRead` /
  `gdfReadV1`. Most prominently [[wiki/tools/mri_glmfit|mri_glmfit]] reads
  FSGD files when the user passes `--fsgd <file>`. Also
  used by `mri_concat`, `glmfit-sim`, and various
  group-analysis scripts.
- **Pipeline stage(s):** none in default `recon-all`.
- **Triggering configuration:** an FSGD file with
  more than 40 000 `Input` lines. The 40 001-st Input
  line writes one past the array; the check on the
  40 002-nd Input line stops parsing.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/fsgdf.cpp:651-680 */
if (!strcasecmp(tag,"Input")) {
  if (gd->ninputs > FSGDF_NINPUTS_MAX) {              /* (!) strict > */
    printf("ERROR: gdfReadV1: the number of inputs in FSGD file "
           "exceeds the maximum allowed %d\n", FSGDF_NINPUTS_MAX);
    return(NULL);
  }
  if (gd->nclasses == 0) { ... }
  n = gd->ninputs; /* current input number */
  r = fscanf(fp,"%s %s",gd->subjid[n],class_name);    /* OOB write when n == MAX */
  ...
  gd->subjclassno[n] = r;
  ...
  /* gd->ninputs is incremented to track count */
}
```

Walk-through with `MAX = 40000`:

| Input line # | `gd->ninputs` at check | Check passes? | Index written |
|-------------:|-----------------------:|:-------------:|--------------:|
| 1            | 0                       | yes           | `subjid[0]` ✓ |
| ...          | ...                     | yes           | ...           |
| 40 000       | 39 999                  | yes           | `subjid[39999]` ✓ |
| **40 001**   | **40 000**              | **yes (40000 > 40000 is false)** | **`subjid[40000]`** ✗ OOB |
| 40 002       | 40 001                  | no (errors)   | (not written) |

The single OOB write on the 40 001-st input is the
defect.

A symmetric check elsewhere in the same file (the
`Class` keyword, etc.) uses the same `>` pattern; only
the Input handler is reviewed here, but the same
fix-and-audit pattern applies vault-wide.

## Code Reference

- **File:** [`utils/fsgdf.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsgdf.cpp)

- **Commit:** `d932c45b79`

## Root Cause

Standard off-by-one: when validating "current count is
about to exceed the array's capacity," the correct test
is `count >= MAX` (not `count > MAX`), because the
write uses `array[count]` with valid indices
`0..MAX-1`.

## Impact

- **Files with ≤ 40 000 Inputs:** unaffected. This is
  the overwhelming majority of FSGD use cases (group
  studies rarely exceed a few thousand subjects).
- **Files with 40 001+ Inputs:** the 40 001-st input
  corrupts memory adjacent to the FSGD struct's
  `subjid` array. Subsequent fields in the struct
  (whichever follow `subjid` in
  `include/fsgdf.h`) are clobbered. The check on the
  40 002-nd input fires too late.
- **Severity:** low — requires a 40 K-input FSGD,
  which is uncommon. UK Biobank-scale group analyses
  could approach this.

## Recommended Fix

```diff
--- a/utils/fsgdf.cpp
+++ b/utils/fsgdf.cpp
@@ -649,7 +649,7 @@ FSGD *gdfRead(const char *gdfname, const char *gd2mtx_method, int LoadData)
     /*----------------- Input Line ---------------------*/
     if (!strcasecmp(tag,"Input")) {
-      if (gd->ninputs > FSGDF_NINPUTS_MAX) {
+      if (gd->ninputs >= FSGDF_NINPUTS_MAX) {
         printf("ERROR: gdfReadV1: the number of inputs in FSGD file "
                "exceeds the maximum allowed %d\n",
                FSGDF_NINPUTS_MAX);
```

A more thorough fix would also dynamically allocate
`subjid` (and the parallel arrays
`subjclassno`, `tablefile`, etc.) so that group-study
size is bounded by available memory rather than by
`FSGDF_NINPUTS_MAX`. That is a larger refactor; the
single-character fix is sufficient to plug the OOB.

## Workarounds

For datasets approaching the 40 K limit: split the FSGD
into multiple files and analyse separately, or patch
and rebuild.

## Provenance and Discovery

- **Discovered:** 2026-05-01 by agent (greylist of
  `> MAX` patterns followed by array writes).
- **Evidence:** `subjid` declaration at
  `include/fsgdf.h:92` is fixed-size
  `[FSGDF_NINPUTS_MAX][100]`; the write at
  `:664` uses `gd->subjid[gd->ninputs]` with a strict
  `>` check at `:652` that allows
  `ninputs == FSGDF_NINPUTS_MAX`.
