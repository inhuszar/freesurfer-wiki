# [severity-1] [bug-00210] fem_elastic — Material3d::get_matrix never sets D(2,1), so the 6x6 elasticity matrix is asymmetric (dead code: no caller)

> [!bug] Synopsis
> `Material3d::get_matrix()` fills the 6×6 isotropic elasticity matrix but writes `m(2,0)` and `m(2,2)` and forgets `m(2,1) = dnu`, so `D(1,2) = λ` while `D(2,1) = 0`.
> No code calls `VMaterial::get_matrix()`: `Element3d::get_matrix()` computes the stiffness terms inline, so the defect is currently dead code and affects no output.

## Affected Artefacts

- **Tool(s):** [[surf2vol]] (the only tool that links the class; no execution path reaches the function)
- **Pipeline stage(s):** _N/A_
- **FreeSurfer version(s):** confirmed in `8.2.0`; present since the 2008-03-14 import (`4b881dc775`)
- **Platforms:** all
- **Triggering configuration:** none today. It would fire for any future caller of `VMaterial::get_matrix()` / `Material3d::get_matrix()`.

## Detailed Description

For an isotropic material in Voigt notation the upper-left 3×3 block of the elasticity matrix is symmetric:
`D = [[α, λ, λ], [λ, α, λ], [λ, λ, α]]`. The code builds it row by row and misses one entry in the third row:

```cpp
SmallMatrix
Material3d::get_matrix() const
{
  SmallMatrix m(6,6);
  m.set(0);

  double dfactor = (get_E()/(1+get_nu()))/(1-2.0*get_nu());
  double alpha = (1.0-get_nu())*dfactor;
  double beta  = (1-2*get_nu())/2 * dfactor;
  double dnu   = dfactor * get_nu();

  m(0,0) = alpha;
  m(0,1) = dnu;
  m(0,2) = dnu;
  m(1,0) = dnu;
  m(1,1) = alpha;
  m(1,2) = dnu;
  m(2,0) = dnu;
  m(2,2) = alpha;

  m(3,3) = beta;
  m(4,4) = beta;
  m(5,5) = beta;

  return m;
}
```

Rows 0 and 1 set all three entries; row 2 sets `m(2,0)` and `m(2,2)` only (`m.set(0)` on the previous line zero-initialises the matrix), leaving `m(2,1) = 0`.

### Expected Behaviour

`m(2,1) = dnu;` (D symmetric), as `m(1,2) = dnu;` on [`fem_elastic/fem_3d.cpp:77`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fem_3d.cpp#L77).

### Observed Behaviour

`D(1,2) ≠ D(2,1)`. With the harness described below and `E = 1000`, `ν = 0.3`: `dfactor = E/(1+ν)/(1−2ν) = 1923.08`, `dnu = 576.923`; the program prints `Material3d D(1,2)=576.923 D(2,1)=0`.

### Reproducer

A small program compiled against the unmodified `fem_elastic/fem_3d.cpp`, `small_matrix.cpp` and the bundled tetgen sources constructs `Constructor::material("default", 1000.0, 0.3)`, calls
`mat->get_matrix()` and prints entries `(1,2)` and `(2,1)`: `D(1,2)=576.923 D(2,1)=0`. (The matrix is not reachable from the tools; the harness calls the virtual directly.)

## Root Cause

A single omitted assignment, most likely a typo when the symmetric block was typed out. The Lamé-constant terms (`alpha`, `beta`, `dnu`) are otherwise correct.

## Impact

- **No effect on any output:** a repository-wide `grep` finds no call of `get_matrix()` on a material; the only call ([`fem_elastic/solver.h:708`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/solver.h#L708)) is on an element and resolves to `Element3d::get_matrix()`.
- **Severity 1 (trivial):** dead code with no in-tree callers (schema tier 1). It would become a correctness bug if the stiffness assembly were ever refactored to use the material matrix (`Bᵀ D B`).

## Recommended Fix

```diff
--- a/fem_elastic/fem_3d.cpp
+++ b/fem_elastic/fem_3d.cpp
   m(2,0) = dnu;
+  m(2,1) = dnu;
   m(2,2) = alpha;
```

Alternatively delete `VMaterial::get_matrix()` and `Material3d::get_matrix()` as unused. A one-line unit test asserting `D == Dᵀ` guards the fix.
