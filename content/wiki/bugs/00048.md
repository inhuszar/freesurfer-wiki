# [severity-2] [bug-00048] `MRIuncrop` — slice-end bounds check uses `r2` instead of `s2`

> [!bug] Synopsis
> `MRIuncrop`
> ([`utils/mri2.cpp:2710-2741`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L2710-L2741))
> validates the end coordinate of the cropped region
> against the destination volume's dimensions. The check
> at
> [`:2721`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L2721)
> is:
>
> ```cpp
> if (c2 < 0 || c2 >= mri->width || r2 < 0 || r2 >= mri->height || s2 < 0 || r2 >= mri->depth) {
> ```
>
> The last term is `r2 >= mri->depth` and is intended to
> be `s2 >= mri->depth`. The slice-end coordinate is
> never validated against the volume depth. If a caller
> passes `s2 ≥ mri->depth`, the function happily proceeds
> and the loop body at `:2734` writes
> `MRIsetVoxVal(uncrop, c+c1, r+r1, s+s1, f, v)` past the
> end of `uncrop`'s slice axis — out-of-bounds write.
>
> The defect is **latent**: no in-tree caller invokes
> `MRIuncrop`. The header
> ([`include/mri2.h:101`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mri2.h#L101))
> exposes the function for external consumers, so a
> third-party caller could trip it.

## Affected Artefacts

- **Tool:** none — `MRIuncrop` has no callers in
  FreeSurfer 8.2.0.
- **Header export:**
  [`include/mri2.h:101`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mri2.h#L101)
  — externally visible.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).
- **Triggering configuration:** any caller passing
  `s2 ≥ mri->depth`. Symmetric typo would also fire if
  `r2 ≥ mri->depth` and the volume's `height < depth`,
  in which case the function rejects an actually-valid
  request.

## Detailed Description

```cpp
MRI *MRIuncrop(MRI *mri, MRI *crop, int c1, int r1, int s1, int c2, int r2, int s2)
{
  ...
  if (c1 < 0 || c1 >= mri->width || r1 < 0 || r1 >= mri->height || s1 < 0 || s1 >= mri->depth) {
    printf("MRIuncrop(): start point %d %d %d out of range\n", c1, r1, s1);
    return (NULL);
  }
  if (c2 < 0 || c2 >= mri->width || r2 < 0 || r2 >= mri->height || s2 < 0 || r2 >= mri->depth) {  /* (!) */
    printf("MRIuncrop(): end point %d %d %d out of range\n", c2, r2, s2);
    return (NULL);
  }
  ...
  for (s = 0; s < crop->depth; s++) {
    ...
    MRIsetVoxVal(uncrop, c + c1, r + r1, s + s1, f, v);
  }
}
```

Compare with the sister start-point check at
`:2716`, which correctly uses `s1 >= mri->depth`. The
typo is on the end-point check only.

## Code Reference

- **File:** [`utils/mri2.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp)
- **Function:** `MRIuncrop`
- **Defect:**
  [`:2721`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L2721)
  (`r2 >= mri->depth` should be `s2 >= mri->depth`)
- **Commit:** `d932c45b79`

## Root Cause

Copy-paste typo: the end-point bounds check copied the
`s2` term from the start-point check at `:2716` but a
keystroke replaced `s2` with `r2`.

## Impact

- **Currently:** none — no in-tree caller. The function
  exists but is not exercised by any FreeSurfer tool.
- **If exercised** by a third-party tool with
  `s2 ≥ depth`: silent OOB write, undefined behaviour
  (potential corruption of an unrelated heap allocation,
  segfault, or — under MRI's slice-pointer layout — a
  jump into another struct's data).
- **Symmetric mis-rejection:** if a tool calls with
  `r2 ≥ depth` (possible when `height < depth` for a
  non-conformed volume), the function returns NULL even
  though `r2` may be valid in the height axis.
