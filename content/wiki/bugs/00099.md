# [severity-3] [bug-00099] `MRIfindNearestNonzero` max-distance gate tests `dist` instead of `min_dist`

> [!bug] Synopsis
> `MRIfindNearestNonzero`
> ([`utils/mri.cpp:13229-13265`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L13229-L13265))
> searches a `wsize × wsize × wsize`
> neighbourhood around `(xr, yr, zr)` for a
> non-zero voxel and returns the value at the
> closest hit. `min_dist` and `min_val` track
> the closest hit; the loop variable `dist`
> only gets updated **inside** the
> hit-detection branch and therefore retains
> whatever distance was computed for the **last
> visited hit**.
>
> The post-loop range check is:
>
> ```cpp
> if (max_dist > 0 && dist > max_dist) return (0);   /* :13263 — wrong variable */
> return (min_val);
> ```
>
> The intended test is "did we find any hit
> within `max_dist`?" but the implementation
> reads the last hit's distance — which can be
> the **farthest** hit if the loop visits the
> close hit early and a far hit later. In that
> case the function returns `0` even when a
> close hit exists, because the code mistook
> the last-iteration distance for the
> closest-hit distance.

## Affected Artefacts

- **Tool:** [[mris_sample_parc]]
  ([`mris_sample_parc/mris_sample_parc.cpp:219`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_sample_parc/mris_sample_parc.cpp#L219),
  [`:835`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_sample_parc/mris_sample_parc.cpp#L835),
  [`:848`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mris_sample_parc/mris_sample_parc.cpp#L848)).
  Vertices in the surface-to-volume parcel
  sampling step may be assigned label `0`
  ("unknown") instead of their actual nearest
  parcel label whenever the parcel boundary
  geometry triggers the bug.
- **Pipeline stage(s):** none in default
  `recon-all` directly. `mris_sample_parc` is
  used by some downstream parcellation flows.
- **Triggering configuration:** the bug fires
  when the search cube around the query point
  contains at least two hits, and the loop's
  last-visited hit is farther than `max_dist`
  while a closer hit exists.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mri.cpp:13229-13265 */
float MRIfindNearestNonzero(MRI *mri, int wsize, double xr, double yr, double zr, float max_dist)
{
  int xk, yk, zk, xi, yi, zi, whalf, x, y, z;
  float dist, min_dist, min_val, dx, dy, dz;
  dist = 0.0;                                                /* :13233 */

  x = mri->xi[nint(xr)]; y = mri->yi[nint(yr)]; z = mri->zi[nint(zr)];
  min_val = MRIgetVoxVal(mri, x, y, z, 0);
  if (min_val > 0) return (min_val);

  min_dist = 100000;
  min_val = 0;
  whalf = (wsize - 1) / 2;
  for (zk = -whalf; zk <= whalf; zk++) {
    zi = mri->zi[z + zk]; dz = zi - zr;
    for (yk = -whalf; yk <= whalf; yk++) {
      yi = mri->yi[y + yk]; dy = yi - yr;
      for (xk = -whalf; xk <= whalf; xk++) {
        xi = mri->xi[x + xk]; dx = xi - xr;
        if (MRIgetVoxVal(mri, xi, yi, zi, 0) > 0) {
          dist = sqrt(dx * dx + dy * dy + dz * dz);          /* updated only on hits */
          if (dist < min_dist) {
            min_dist = dist;
            min_val = MRIgetVoxVal(mri, xi, yi, zi, 0);
          }
        }
      }
    }
  }
  if (max_dist > 0 && dist > max_dist) return (0);           /* :13263 — uses 'dist', not 'min_dist' */
  return (min_val);
}
```

After the loop:

- `min_dist` and `min_val` correctly reflect
  the closest hit (or `min_dist == 100000` and
  `min_val == 0` if no hit was found).
- `dist` reflects the **last-iteration**
  hit's distance. If no hit was found, `dist`
  retains its initial value `0.0`.

The post-loop test reads `dist`, not
`min_dist`. Three failure modes:

1. **Multiple hits, last one is far.** Loop
   visits voxels in z–y–x raster order. If the
   only hit at `dist > max_dist` happens to be
   the last visited hit, the test fires and
   returns `0` — discarding the close hit.
2. **No hits.** `dist == 0.0` from the
   initialiser, `0 > max_dist` is false, so
   the test does not fire and the function
   returns `min_val == 0`. Coincidentally
   correct.
3. **Single hit within range.** `dist ==
   min_dist <= max_dist`, test does not fire,
   `min_val` returned. Correct.

Failure mode 1 is the actual bug.

### Worked example

Suppose `wsize = 5` and the search cube
contains hits at distances `(2.0, 4.5)` from
the query, in raster order. With `max_dist =
3.0`:

- Hit 1 (`dist=2.0`): updates `min_dist=2,
  min_val=Hit1.value`.
- Hit 2 (`dist=4.5`): does not update
  `min_dist` (4.5 > 2). But `dist` is now 4.5.
- Post-loop: `4.5 > 3.0` is true → return 0.

The correct return is `Hit1.value` — `min_dist
(2.0) <= max_dist (3.0)`.

## Root Cause

Variable confusion. Both `dist` and `min_dist`
are in scope at the post-loop test site;
`min_dist` is the value the test should read
("did the search find any hit at distance
≤ max_dist"). The author wrote `dist` —
plausibly because `dist` was the most recently
written distance value at the time the test
runs. Because the test is on the *bound*, not
the *closest hit*, this conflation is benign
for queries with one hit (where `dist ==
min_dist`) but fails for queries with
multiple hits.

## Impact

- **`mris_sample_parc`:** vertices may be
  assigned label 0 instead of their actual
  nearest parcel whenever the search cube
  contains a close hit and a farther hit
  whose distance exceeds `max_dist`. The
  parcellation map will have spurious
  "unknown" patches near parcel boundaries.
- **Severity:** 3 — auxiliary tool's default
  output is wrong on a specific (but common)
  geometric pattern.

## Recommended Fix

```diff
--- a/utils/mri.cpp
+++ b/utils/mri.cpp
@@ -13260,7 +13260,7 @@ float MRIfindNearestNonzero(MRI *mri, int wsize, double xr, double yr, double zr,
       }
     }
   }
-  if (max_dist > 0 && dist > max_dist) return (0);
+  if (max_dist > 0 && min_dist > max_dist) return (0);
   return (min_val);
 }
```

Single-character variable substitution. After
the fix:

- No hit: `min_dist == 100000`, test fires for
  any positive `max_dist` → returns 0.
  (Correct semantics; the previous code also
  returned 0 in this case via `min_val == 0`.)
- Hit within range: `min_dist <= max_dist`,
  test does not fire → returns `min_val`.
- Hit outside range: `min_dist > max_dist`,
  test fires → returns 0.

## Workarounds

Pass `max_dist <= 0` to disable the gate (the
function will then return the nearest hit
regardless of distance). Set `min_val == 0`
guard at the call site instead.
