# [severity-2] [bug-00093] `MRImaxInLabelInRegion` returns `0` instead of the true max for all-negative regions

> [!bug] Synopsis
> `MRImaxInLabelInRegion`
> ([`utils/mri.cpp:14220-14245`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L14220-L14245))
> finds the maximum source intensity over voxels
> in a `(2*whalf+1)^3` neighbourhood whose label
> matches `label`:
>
> ```cpp
> int    nvox = 0;
> double max  = 0.0;                                        /* :14226 — wrong sentinel */
>
> for (x = x0 - whalf; x <= x0 + whalf; x++) {
>   ...
>   l = nint(MRIgetVoxVal(mri_labeled, x, y, z, 0));
>   if (l == label) {
>     val = MRIgetVoxVal(mri_src, x, y, z, 0);
>     if (val > max) max = val;                             /* :14237 */
>     nvox++;
>   }
>   ...
> }
> if (!nvox) nvox = 1;                                      /* :14243 — dead store */
> return (max);
> ```
>
> Two issues:
>
> 1. **`max` initialises to `0.0`.** For a region
>    where all matching voxels have **negative**
>    `mri_src` values, the comparison `val > max`
>    is never true and the function returns
>    `0.0`. The correct sentinel is `-DBL_MAX`
>    (or "first-value" lazy initialisation).
> 2. **`if (!nvox) nvox = 1;`** at `:14243`
>    writes to `nvox`, which is never read after
>    the loop. The function returns `max` only.
>    Pure dead store — likely copied from
>    `MRImeanAndStdInLabel` or similar where the
>    division `mean / nvox` requires the
>    sentinel.

## Affected Artefacts

- **Tool:** [[mri_normalize]] — three call sites
  ([`mri_normalize.cpp:1441`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1441),
  [`:1525`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1525),
  [`:1698`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_normalize/mri_normalize.cpp#L1698))
  feed in the T1 volume (`mri_src`) for control-
  point intensity selection.
- **Pipeline stage(s):** default `recon-all` —
  `mri_normalize` runs in autorecon1 to scale
  T1 intensities to a standard range. T1
  volumes are non-negative, so the bug does not
  fire in the default flow.
- **Triggering configuration:** any caller that
  passes a signed-valued `mri_src` (residual
  maps, demeaned signals, log-density images,
  derivative-based features) to
  `MRImaxInLabelInRegion` would receive `0`
  instead of the true (negative) maximum.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mri.cpp:14220-14245 */
double MRImaxInLabelInRegion(MRI *mri_src, MRI *mri_labeled, int label,
                             int x0, int y0, int z0, int whalf)
{
  int    x, y, z, l;
  float  val;
  int    nvox = 0;
  double max  = 0.0;                              /* :14226 */

  for (x = x0 - whalf; x <= x0 + whalf; x++) {
    if (x < 0 || x >= mri_src->width) continue;
    for (y = y0 - whalf; y <= y0 + whalf; y++) {
      if (y < 0 || y >= mri_src->height) continue;
      for (z = z0 - whalf; z <= z0 + whalf; z++) {
        if (z < 0 || z >= mri_src->depth) continue;
        l = nint(MRIgetVoxVal(mri_labeled, x, y, z, 0));
        if (l == label) {
          val = MRIgetVoxVal(mri_src, x, y, z, 0);
          if (val > max) max = val;               /* :14237 */
          nvox++;
        }
      }
    }
  }
  if (!nvox) nvox = 1;                            /* :14243 — dead */
  return (max);
}
```

For a region of all-negative `val` (or empty
matching set), `max` stays at `0.0` and is
returned as the "max." A caller that uses the
return value to thread-place control points,
threshold, or compare against another region
will silently get the wrong answer.

The sister function `MRImeanAndStdInLabel`
([`:14160`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L14160))
has the same `if (!nvox) nvox = 1;` pattern,
but **uses** `nvox` for a division afterwards —
so the sentinel is meaningful there. In
`MRImaxInLabelInRegion` the same line was
copy-pasted but the corresponding division
does not exist.

## Root Cause

Pattern transplanted from a "mean" function
without adjusting the initial value. A "mean"
starts at 0 and accumulates; that's correct.
A "max" needs a `-∞`-equivalent sentinel — `0`
is only correct if the input is guaranteed
non-negative. The `nvox = 1` sentinel was
copied along with the rest of the boilerplate
even though there is no division to protect.

## Impact

- **`mri_normalize` (default recon-all):** none
  observable — T1 intensities are non-negative.
- **Other potential callers:** any future
  caller passing a signed-valued `mri_src`
  receives `0` instead of the true maximum
  whenever all matching voxels are negative.
- **Severity:** 2 — latent under typical
  conditions; conceptual defect waiting for a
  caller that exercises the failing input
  range.

The `-DBL_MAX` sentinel ensures any real value
updates `max`. The post-loop check returns `0`
(or any chosen sentinel) for an empty-label
region — preserving the existing behaviour for
the common no-match case while fixing the
all-negative case.

## Workarounds

Callers that need this function on signed-
valued data should bias the input by adding a
known constant first, then subtract from the
returned max.

    has no consumer).
  - Sister `MRImeanAndStdInLabel` has the
    matching `nvox = 1` sentinel and **uses**
    `nvox` to divide `mean` and `var`.
