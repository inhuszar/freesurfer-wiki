# [severity-2] [bug-00196] `surf2vol` — the Powell affine fit tests `ripflag` on the moving surfaces, which are never annotated, so its medial/unknown-region exclusion can never take effect

> [!bug] Synopsis
> The linear (Powell) stage of [[surf2vol]] is meant to skip medial-wall and
> unknown-label vertices when fitting the 12-parameter affine
> ("don't use medial or unknown regions in linear fit"). It tests
> `pvtx_x->ripflag` where `x` is the **moving** surface, but the `-aparc`
> annotation, and hence `ripflag`, is only ever applied to the **fixed**
> surfaces. The test is therefore always false. Today this changes nothing,
> because [[00195]] already prevents any vertex from being flagged; once
> [[00195]] is fixed the affine would still be fitted on the medial wall
> while the elastic stage excludes it.

## Affected Artefacts

- **Tool(s):** [[surf2vol]]; reached on every [[mri_cvs_register]] run whose
  `transform.txt` cache does not exist yet
- **Pipeline stage(s):** [[mri_cvs_register]] step 2 (elastic registration)
- **FreeSurfer version(s):** confirmed in 8.2.0; the lines are unchanged since the 2008-04-18 import (`9761aeb9b6`, verified with `git log -L`)
- **Platforms:** all
- **Triggering configuration:** `-aparc` given and no readable `-cache_transform`
  file (first run). The affine is then computed by Powell minimisation
  ([`fem_elastic/fsurf2vol.cpp:349-367`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L349-L367)).

## Detailed Description

`powell_lin(vmris_x, vmris_fx)` collects, for every `-lin_res`-th vertex index
of every surface pair, the point pair (moving vertex, fixed vertex) and
minimises the mean Euclidean distance with Powell's method. A comment at the
exclusion test states the design intent: "don't use medial or unknown regions
in linear fit". The first argument is the **moving** surface vector and the
loop variable `pvtx_x` walks the moving surface
([`fem_elastic/fsurf2vol.cpp:880-917`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L880-L917)).

The annotation is read only for the **fixed** surfaces and `SurfaceMarker` is
only run on them
([`fem_elastic/fsurf2vol.cpp:1643-1675`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1643-L1675));
the moving surfaces are read by `MRISread` and never touched by the marker
([`:1677-1692`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1677-L1692)).
The only assignment of `ripflag` anywhere in `fsurf2vol.cpp` is
[`:1566`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1566),
inside `SurfaceMarker::operator()`. A regular surface file read with `MRISread`
starts with `ripflag = 0` (the `ripflag` assignments in
`utils/mrisurf_io.cpp` belong to the patch readers, `MRISreadPatchNoRemove`).
So `if ( pvtx_x->ripflag ) continue;` can never execute
`continue`.

Moving and fixed surfaces have identical vertex counts and vertex-wise
correspondence (checked at
[`fem_elastic/fsurf2vol.cpp:333-339`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L333-L339)),
and `powell_lin` advances `pvtx_x` and `pvtx_fx` in lockstep, so the flag of
the fixed vertex `pvtx_fx` is the right one to test.

### Expected Behaviour

Vertices flagged by `-aparc` on the fixed surface (medial wall / `unknown`) are
excluded from the point pairs used for the affine fit, as the comment states.

### Observed Behaviour

No vertex is excluded from the affine fit, whatever the annotation contains.
Currently this is indistinguishable from the intended behaviour, because
[[00195]] leaves every fixed vertex unflagged anyway (`ripCounter = 0`). The
affine reported by `surf2vol` ("energy before/after calling Powell") therefore
always includes the medial-wall pairs; after [[00195]] is fixed it would be
the only place where the medial wall is still used.

### Reproducer

> [!gap] Reproducer not yet constructed
> The defect is established by static reading of the code (the single
> assignment of `ripflag`, the argument order of the `powell_lin` calls, and
> the absence of any annotation processing for the moving surfaces). With the
> 8.2.0 binary no observable difference exists, because [[00195]] masks it; a
> demonstration requires first applying the [[00195]] fix (or an annotation
> that does label the medial wall as `unknown`, see the Workarounds of
> [[00195]]) and comparing the printed Powell energies and the resulting
> `transform.txt` with the test changed to `pvtx_fx->ripflag`.

## Root Cause

`powell_lin` was written with the moving surface as its first (`x`) argument,
and the exclusion test copied the naming (`pvtx_x`) without considering that
`ripflag` is set only on the fixed surfaces (the surfaces that carry the
`-aparc` annotation). The flag has to be read from `pvtx_fx`.

## Impact

- **Today: none relative to current behaviour.** Because [[00195]] leaves all
  vertices unflagged, excluding by `pvtx_fx->ripflag` would not change the fit
  either. The affine fit uses every `-lin_res`-th pair including medial wall
  (about 6 % of the sampled pairs for `cvs_avg35`).
- **Latent:** once [[00195]] is fixed, the elastic BCs would exclude the medial
  wall but the 12-parameter affine that precedes it, and that defines
  the starting point of the elastic stage and the `-out_affine` result, would
  not. The affine is computed once per cache file and reused
  (see [[00203]]), so a fix would also have to invalidate old caches.
- **Severity 2 (low):** latent under current conditions; the primary results are
  unaffected today. If it were reachable independently of [[00195]] it would
  affect the default [[mri_cvs_register]] path (every run without a cache),
  which is why it is recorded; per the schema's tiebreaker the lower score
  is used.

## Recommended Fix

```diff
     for (unsigned int ui=0;
          ui < nvertices;
          ui+=linInc, pvtx_x+=linInc, pvtx_fx+=linInc )
     {
       // don't use medial or unknown regions in linear fit
-      if ( pvtx_x->ripflag ) continue;
+      if ( pvtx_fx->ripflag ) continue;   // ripflag is only set on the fixed surfaces
```

Apply together with the fix of [[00195]]; the fix changes the fitted affine and
therefore every CVS result, so it needs the same validation. A regression test:
with the [[00195]] fix applied and `cvs_avg35` as fixed surface, the container
passed to `powell_minimize` must contain no pair whose fixed vertex has
annotation 0 (8108 of the 139336 `lh` vertices are excluded before the
`-lin_res` stride is applied).

## Workarounds (If Any)

None needed today (no behavioural effect). After [[00195]] is fixed, none
exists short of fixing this test; `-lin_res` only changes the sampling stride.
