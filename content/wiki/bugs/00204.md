# [severity-2] [bug-00204] `fem_elastic` — `read_transform` accepts a truncated 11-value file: the 12th number (the z translation) is silently set to 0

> [!bug] Synopsis
> `read_transform()` reads the 12 floats of an affine (3×3 matrix followed by
> the translation) with a loop whose counter is incremented **after** each
> extraction, whether or not the extraction succeeded. If the file contains
> only 11 numbers — or a non-numeric 12th token — the failing 12th extraction
> still advances the counter to 12, the length check `ui < 12` passes, and the
> function returns a transform whose last element (the z translation) is `0`.
> [[surf2vol]] (`-cache_transform`, hence [[mri_cvs_register]] reruns) and
> [[createMorph]] (`affine` inputs) then use it without any message. Files with 10
> or fewer numbers are correctly rejected.

## Affected Artefacts

- **Tool(s):** [[surf2vol]] (`-cache_transform`), [[createMorph]] (`affine` transform items); [[mri_cvs_register]] indirectly via its `transform.txt` cache ([[00203]])
- **Pipeline stage(s):** _N/A_
- **FreeSurfer version(s):** confirmed in 8.2.0; present since the 2008-03-14 import (`4b881dc775f`).
- **Platforms:** all (a failed `operator>>` stores 0 from C++11 on, verified here with g++ 8.5 in its default `gnu++14` mode; under C++98 semantics the 12th value would be left uninitialised instead)
- **Triggering configuration:** an affine text file with exactly 11 readable
  numbers, or with a non-numeric 12th token (for example a hand-edited,
  truncated or partially written cache file).

## Detailed Description

```cpp
float* read_transform(const char* fname)
{
  std::ifstream ifs(fname);

  if ( !ifs )
  {
    std::cerr << " Error opening file " << fname
    << " to read transform\n";
    return NULL;
  }

  float* fp = new float[12];
  unsigned int ui=0;
  for ( float *pbuf = fp; ui<12 && ifs; ++ui, ++pbuf)
    ifs >> *pbuf;


  if ( ui<12 )
  {
    delete[] fp;
    return NULL;
  }

  return fp;
}
```

The loop `for ( float *pbuf = fp; ui<12 && ifs; ++ui, ++pbuf) ifs >> *pbuf;`
([`fem_elastic/transformUtils.cpp:21-22`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/transformUtils.cpp#L21-L22)) tests `ifs` *before* each extraction but
increments `ui` *after* it. If the extraction at index `k` fails, the stream is
in the failed state, `ui` becomes `k+1` and the loop stops. The rejection test
([`fem_elastic/transformUtils.cpp:25-29`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/transformUtils.cpp#L25-L29)) is `ui < 12`, i.e. `k+1 < 12`, so it triggers
for `k ≤ 10` but not for `k = 11`: a failure at the twelfth (last) number is
indistinguishable from success. Since C++11, a failed `operator>>` into a
`float` stores `0`, so `fp[11]` (the z translation, `m_pdata[j+9]` with `j = 2`,
[`fem_elastic/morph.cpp:39-50`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L39-L50)) becomes exactly `0` and no diagnostic is printed.

### Expected Behaviour

A file that does not contain 12 readable numbers should be rejected
(`NULL` return), so that surf2vol falls back to the Powell fit
([`fem_elastic/fsurf2vol.cpp:358-366`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L358-L366)) and createMorph prints `failed to read
transform` and exits ([`fem_elastic/fcreateMorph.cpp:113-118`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L113-L118)).

### Observed Behaviour

An 11-number file is accepted and the returned transform has a z translation of 0; nothing is printed (see the table below).

### Reproducer

`read_transform` compiled on its own (`g++ 8.5`, default `gnu++14`) against a
three-line driver that prints the returned values:

| file contents | result |
|---|---|
| `1 0 0 0 1 0 0 0 1 2 3 4` | `1 0 0 0 1 0 0 0 1 2 3 4` (correct) |
| `1 0 0 0 1 0 0 0 1 2 3` (11 numbers) | `1 0 0 0 1 0 0 0 1 2 3 0` — accepted, z translation 0 |
| `1 0 0 0 1 0 0 0 1 2 3 x` (non-numeric 12th token) | `1 0 0 0 1 0 0 0 1 2 3 0` — accepted |
| `1 0 0 0 1 0 0 0 1 2` (10 numbers) | `NULL (rejected)` |

```bash
printf '1 0 0 0 1 0 0 0 1 2 3 \n' > a11.txt        # 11 numbers: translation (2, 3, <missing>)
g++ -I fem_elastic driver.cpp fem_elastic/transformUtils.cpp -o rt && ./rt a11.txt
# -> 1 0 0 0 1 0 0 0 1 2 3 0
```

(`driver.cpp`: `float* f = read_transform(argv[1]); if (!f) puts("NULL"); else for (i<12) printf("%g ", f[i]);`.)

## Root Cause

The loop condition `ui<12 && ifs` guards the *next* iteration, but the
post-increment `++ui` is evaluated even when the extraction that just ran
failed. After the loop, `ui == 12` is taken as "all 12 values were read",
which is false when the last read failed. The success test should be on the
stream state (or the counter should only advance on successful reads).

## Impact

- **Output affected (rarely):** a malformed affine file silently becomes a
  valid transform with the z translation (the last value) dropped. For
  surf2vol this is the cache file written by surf2vol itself
  ([`fem_elastic/transformUtils.cpp:34-50`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/transformUtils.cpp#L34-L50),
  always 12 values), so it needs a truncated or hand-edited file; for
  createMorph it is a user-supplied file.
- **Why 2:** latent under typical conditions — surf2vol-written cache files are
  complete, `mri_cvs_register` never edits them, and the failure only occurs
  for a file whose last value is missing or unreadable. The user's primary
  results are unaffected otherwise.

## Recommended Fix

Test the stream state, not the counter. Verified on the stand-alone driver
(the 11-number and non-numeric-12th files are rejected, the 12-number file
is read):

```diff
--- a/fem_elastic/transformUtils.cpp
+++ b/fem_elastic/transformUtils.cpp
@@ float* read_transform(const char* fname)
   float* fp = new float[12];
   unsigned int ui=0;
-  for ( float *pbuf = fp; ui<12 && ifs; ++ui, ++pbuf)
-    ifs >> *pbuf;
+  while ( ui<12 && (ifs >> fp[ui]) )
+    ++ui;
 
 
   if ( ui<12 )
```

A regression test should feed 10-, 11-, 12-value and non-numeric-12th-token
files to `read_transform`.

## Workarounds (If Any)

Make sure affine files contain exactly 12 numbers; surf2vol-written cache files do.
