# [severity-2] [bug-00181] fix_subject_corrected-lh — `mris_curvature` reads `../subjects/lh.smoothwm*` instead of `../surf/lh.smoothwm*`, inconsistent with its own `cp` target and the rh worker

> [!bug] Synopsis
> `fix_subject_corrected-lh` computes mean curvature on the smoothed
> white-matter surface with two `mris_curvature` calls, then copies the
> resulting `.H` files into `lh.curv` / `lh.curv_corrected`. But both
> `mris_curvature` calls read their input surface from
> `../subjects/lh.smoothwm` and `../subjects/lh.smoothwm_corrected`,
> whereas the surfaces are actually produced in, and copied back from,
> `../surf/` (`mris_smooth ... ../surf/lh.smoothwm_corrected`;
> `cp ../surf/lh.smoothwm.H ../surf/lh.curv`). The right-hemisphere
> twin, `fix_subject_corrected-rh`, correctly reads `../surf/rh.smoothwm*`.
> The `../subjects/` path does not exist in the subject tree, so each
> `mris_curvature` call fails to find its input, no `.H` file is written,
> and the following `cp` copies a stale or missing file — leaving
> `lh.curv` / `lh.curv_corrected` wrong or absent.

## Affected Artefacts

- **Tool(s):** [[fix_subject_corrected-lh]] — the left-hemisphere
  topology-correction wrapper. Its right-hemisphere counterpart
  [[fix_subject_corrected-rh]] does **not** have the defect (it reads
  `../surf/`).
- **Pipeline stage(s):** _N/A_ — `fix_subject_corrected-lh` is a manual
  per-hemisphere correction wrapper, not a stage of the default
  [[wiki/pipelines/recon-all|recon-all]] run.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all.
- **Triggering configuration:** always — both `mris_curvature` lines
  unconditionally use the `../subjects/` path on every invocation.

## Detailed Description

The script runs from `$SUBJECTS_DIR/$1/scripts` (via `pushd`), so
relative paths are resolved against that directory; `../surf` is the
subject's `surf` directory and `../subjects` is a sibling that is not a
standard FreeSurfer subject-tree directory. The relevant sequence is:

```tcsh
mris_smooth ../surf/lh.orig_corrected ../surf/lh.smoothwm_corrected
mris_inflate ../surf/lh.smoothwm_corrected ../surf/lh.inflated_corrected
mris_curvature -w -a 10 ../subjects/lh.smoothwm
cp ../surf/lh.smoothwm.H ../surf/lh.curv
mris_curvature -w -a 10 ../subjects/lh.smoothwm_corrected
cp ../surf/lh.smoothwm_corrected.H ../surf/lh.curv_corrected
```

`mris_curvature -w` writes its mean-curvature output next to the input
surface, as `<input>.H`. The script then expects that `.H` to be at
`../surf/lh.smoothwm.H` (the `cp` source). For that expectation to hold,
the input surface must be `../surf/lh.smoothwm` — but the call reads
`../subjects/lh.smoothwm`.

### Expected Behaviour

`mris_curvature` should read the smoothed surface from `../surf/`, the
same directory `mris_smooth` wrote it to and the same directory the `cp`
reads the `.H` file from. With `-w`, it writes `../surf/lh.smoothwm.H`,
which `cp` then renames to `../surf/lh.curv`. The corrected variant
should likewise read `../surf/lh.smoothwm_corrected` and write
`../surf/lh.smoothwm_corrected.H`. This is exactly what the rh worker
does:

```tcsh
mris_curvature -a 10 -w ../surf/rh.smoothwm
cp ../surf/rh.smoothwm.H ../surf/rh.curv
mris_curvature -a 10 -w ../surf/rh.smoothwm_corrected
cp ../surf/rh.smoothwm_corrected.H ../surf/rh.curv_corrected
```

### Observed Behaviour

The lh worker reads `../subjects/lh.smoothwm` and
`../subjects/lh.smoothwm_corrected`. The `../subjects` directory is not
part of a standard subject tree and the smoothed surfaces are not
written there, so `mris_curvature` cannot open its input surface and
errors out (no `.H` is produced under `../surf/`). Because the script's
shebang is `#!/bin/tcsh -f` (no `-e`), the failed `mris_curvature` does
**not** abort the script: execution continues to the `cp`, which then
copies a **stale** `../surf/lh.smoothwm.H` from a previous run if one
exists, or fails (no such file) if it does not. The end result is that
`lh.curv` and `lh.curv_corrected` are either stale (carried over from an
earlier run) or missing — not the curvature of the freshly smoothed
surfaces this run produced.

The asymmetry with `fix_subject_corrected-rh`, which reads the correct
`../surf/` path, confirms the `../subjects/` spelling is a mistake
rather than an intended location.

## Root Cause

A wrong directory component: `../subjects/` was written where `../surf/`
was meant. The mistake is isolated to the two `mris_curvature` input
arguments; every neighbouring command in the same script — the
`mris_smooth` that produces `lh.smoothwm_corrected`, and both `cp`
commands that consume `lh.smoothwm.H` / `lh.smoothwm_corrected.H` — uses
`../surf/`. The rh sibling script uses `../surf/` throughout, so the lh
worker is the outlier.

## Impact

- **`lh.curv` / `lh.curv_corrected` wrong or missing.** Each
  `mris_curvature` call fails to read its input, writes no `.H` under
  `../surf/`, and the subsequent `cp` propagates a stale file (from an
  earlier successful run) or fails outright. The left-hemisphere mean
  curvature this script is supposed to (re)generate is not the curvature
  of the current corrected surfaces.
- **Loud but non-fatal.** `mris_curvature` errors are visible on stderr,
  but because the script runs under `tcsh -f` (no `-e`) the run
  continues, so the bad/stale `cp` happens anyway and
  `mris_make_surfaces` still runs. The damage is to the curvature
  overlays specifically.
- **Manual, single-hemisphere wrapper.** This is an opt-in
  topology-correction helper outside the default
  [[wiki/pipelines/recon-all|recon-all]] chain, and only the lh curv
  outputs are affected — bounded scope, hence severity 2 rather than a
  default-pipeline score.

## Recommended Fix

Read the smoothed surfaces from `../surf/`, matching the `cp` sources
and the rh worker:

```diff
-mris_curvature -w -a 10 ../subjects/lh.smoothwm
+mris_curvature -w -a 10 ../surf/lh.smoothwm
 cp ../surf/lh.smoothwm.H ../surf/lh.curv
-mris_curvature -w -a 10 ../subjects/lh.smoothwm_corrected
+mris_curvature -w -a 10 ../surf/lh.smoothwm_corrected
 cp ../surf/lh.smoothwm_corrected.H ../surf/lh.curv_corrected
```

After the change, each `mris_curvature -w` writes `../surf/lh.smoothwm.H`
(resp. `..._corrected.H`), which the following `cp` then installs as
`../surf/lh.curv` (resp. `lh.curv_corrected`).

### Alternative Fixes Considered

None warranted — the two-token path correction is the minimal,
unambiguous fix and brings the lh worker into line with the rh worker.

## Workarounds (If Any)

script finishes:
