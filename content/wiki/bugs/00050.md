# [severity-2] [bug-00050] `MatrixSum` — non-NULL caller matrix is silently leaked when zeroing

> [!bug] Synopsis
> `MatrixSum`
> ([`utils/matrix.cpp:3070-3112`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L3070-L3112))
> takes an optional `msum` destination matrix. When
> `msum == NULL` it correctly allocates a new matrix.
> When `msum != NULL` and dimensions match, it should
> zero the caller's matrix *in-place* and accumulate
> into it. Instead, the existing-buffer branch reads:
>
> ```cpp
> msum = MatrixZero(outrows, outcols, NULL);             // :3091
> ```
>
> `MatrixZero(rows, cols, NULL)` allocates a fresh
> matrix; the assignment overwrites the local `msum`
> pointer, abandoning the caller's matrix as a leak.
> The newly-allocated matrix is what gets accumulated
> into and returned. The sister
> `MatrixSumSquare`
> ([`:3139`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L3139))
> has the same shape but the correct in-place form:
> `msumsq = MatrixZero(outrows, outcols, msumsq);`.

## Affected Artefacts

- **Tool:** [[wiki/tools/mri_glmfit|mri_glmfit]] PCC code path
  ([`utils/fsglm.cpp:445`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fsglm.cpp#L445)
  and

  [`utils/gtm.cpp:2805`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gtm.cpp#L2805)
  passes `NULL`, so this caller is unaffected.
- **Pipeline stage(s):** none in default `recon-all`.
- **Triggering configuration:** any `mri_glmfit` run

  is currently **gated** by bug [[00043]]: the buggy

  the `MatrixSum` call) to be skipped. Once 00043 is

  active.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

```cpp
MATRIX *MatrixSum(MATRIX *m, int dim, MATRIX *msum)
{
  ...
  if (msum == NULL)
    msum = MatrixZero(outrows, outcols, NULL);            // :3085 — correct
  else {
    if (msum->rows != outrows || msum->cols != outcols) {
      printf("ERROR: MatrixSum: dimension mismatch\n");
      return (NULL);
    }
    msum = MatrixZero(outrows, outcols, NULL);            // :3091 — leaks caller's msum
  }
  ...
  return (msum);
}
```

The else-branch's `MatrixZero(..., NULL)` allocates a
new matrix, so the caller's `msum` is never re-used and
is leaked. The caller does receive the new matrix as the
return value, so the function "works" — just leaks one
matrix per non-NULL call.

Compare with the immediately-following `MatrixSumSquare`
([`:3139`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L3139)):

```cpp
msumsq = MatrixZero(outrows, outcols, msumsq);            // :3139 — in-place, correct
```

`MatrixZero` zeros in-place when its third argument is
non-NULL, so this is the leak-free pattern. The two
functions are otherwise structurally identical.

## Root Cause

Copy-paste typo. `MatrixSumSquare` was written or
edited later with the correct `MatrixZero(..., msumsq)`
pattern; `MatrixSum` retained an earlier, incorrect
`MatrixZero(..., NULL)` form.

## Impact

- **Currently latent:** bug [[00043]] (`Dt[n] == NULL`
  null-check typo in `GLMcMatrices`) suppresses the PCC
  branches that would call `MatrixSum` with a non-NULL
  `msum`, so this leak does not fire in practice.
- **Once 00043 is fixed:**
  - `fsglm.cpp:445` is in `GLMcMatrices`, called once
    per contrast — small one-time leak.
  - `fsglm.cpp:645` is in `GLMtest`, called *once per
    voxel per contrast* during
    `MRIglmFitAndTest`. For an fMRI grid (~200 K
    in-mask voxels) and 1–4 contrasts, that's
    200 K – 800 K leaked matrices per analysis run.
    Each is a 1-row × N-col `MATRIX_REAL` (~tens of
    bytes plus header) — tens to hundreds of MB total.
- **No correctness defect** in the values written: the
  function returns the freshly-allocated and properly
  accumulated matrix, so `glm->sumXcd[n]` /
  `glm->sumyhatd[n]` get the right numbers. The
  *previous* matrix in those slots is dropped on the
  floor instead of re-used.

## Recommended Fix

```diff
--- a/utils/matrix.cpp
+++ b/utils/matrix.cpp
@@ -3088,7 +3088,7 @@ MATRIX *MatrixSum(MATRIX *m, int dim, MATRIX *msum)
       printf("ERROR: MatrixSum: dimension mismatch\n");
       return (NULL);
     }
-    msum = MatrixZero(outrows, outcols, NULL);
+    msum = MatrixZero(outrows, outcols, msum);
   }
```

This matches `MatrixSumSquare` and is the documented
in-place semantics of `MatrixZero`.

## Workarounds

None — caller would have to track the previous matrix
and free it manually, but the function's interface
already promises to re-use it.
