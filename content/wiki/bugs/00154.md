# [severity-2] [bug-00154] post-recon-all — `--no-qa-stats`/`--no-qastats` set DoQAStats=1, so QA-stats cannot be disabled (negating flag enables it)

> [!bug] Synopsis
> In `post-recon-all`, the `--no-qa-stats` and `--no-qastats` options are
> meant to suppress the QA-stats step (`mri_segstats --qa-stats`). Their
> handler sets `DoQAStats = 1` — the *enabling* value, identical to the
> `--qa-stats` handler. Since `DoQAStats` already defaults to `1`, passing
> `--no-qa-stats` is a no-op: QA-stats always runs and cannot be turned
> off from the command line. The `--no-qa-stats` usage text even says
> "do not run qastats", confirming the intent.

## Affected Artefacts

- **Tool(s):** [[post-recon-all]] (post-`recon-all` add-on steps:
  samseg, GTM seg, QA-stats, QCache, CVS, etc.).
- **Pipeline stage(s):** the QA-stats step inside `post-recon-all`
  (`mri_segstats --qa-stats <subject> <statsdir>/qa.stats`). Not part of
  the core [[wiki/pipelines/recon-all|recon-all]] chain itself.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all.
- **Triggering configuration:** passing `--no-qa-stats` or `--no-qastats`
  to suppress QA-stats. The defect manifests as the absence of any effect.

## Detailed Description

`DoQAStats` defaults to `1` near the top of the script
(`set DoQAStats = 1`). The argument parser then defines:

```tcsh
    case "--qa-stats":
      set DoQAStats = 1
      breaksw
    case "--no-qa-stats":
    case "--no-qastats":
      set DoQAStats = 1          # ← should be 0
      breaksw
```

The negating cases assign `1`, identical to the affirmative case. Because
the default is already `1`, neither the affirmative nor the negating flag
changes anything — but critically, the user's explicit request to
*disable* QA-stats is ignored. Later, `if($DoQAStats)` is always true, so
`mri_segstats --qa-stats ...` always runs.

The immediately-following option pair in the same parser is written
correctly and shows the intended pattern:

```tcsh
    case "--qcache":
      set DoQCache = 1
      breaksw
    case "--no-qcache":
      set DoQCache = 0
      breaksw
```

so the QA-stats negation block should likewise set `0`. The usage text
`--no-qa-stats : do not run qastats` confirms the design intent.

### Expected Behaviour

`post-recon-all --no-qa-stats` (or `--no-qastats`) sets `DoQAStats = 0`,
so the `if($DoQAStats)` block is skipped and `mri_segstats --qa-stats`
does not run.

### Observed Behaviour

`--no-qa-stats` / `--no-qastats` leave `DoQAStats = 1`; the QA-stats step
runs regardless. The flag has no effect.

### Reproducer

```bash
# Parse-loop equivalent (the bug is in option handling):
cat > /tmp/qa.csh <<'EOF'
#!/bin/tcsh -f
set DoQAStats = 1
set argv = (--no-qa-stats)
while( $#argv != 0 )
  set flag = $argv[1]; shift
  switch($flag)
    case "--qa-stats":
      set DoQAStats = 1
      breaksw
    case "--no-qa-stats":
    case "--no-qastats":
      set DoQAStats = 1
      breaksw
    default:
      breaksw
  endsw
end
echo "DoQAStats=$DoQAStats (expect 0 if --no-qa-stats worked)"
EOF
tcsh -f /tmp/qa.csh
#   -> DoQAStats=1   (QA-stats would still run)
```

Executed: prints `DoQAStats=1`, i.e. the disabling flag does not disable.

## Root Cause

Copy-paste error: the `--no-qa-stats` / `--no-qastats` block was cloned
from the `--qa-stats` block and the assignment value was not changed from
`1` to `0`. Compare the correctly-written `--qcache` / `--no-qcache` pair
in the same parser.

## Impact

- **`--no-qa-stats` is a silent no-op.** A user who passes it to skip the
  QA-stats step still gets `mri_segstats --qa-stats` executed, costing the
  extra runtime and writing `qa.stats` they asked to avoid. There is no
  command-line way to disable QA-stats in this version.
- QA-stats is a diagnostic/QC product, not a primary scientific output,
  and the default already runs it — so the only harm is the inability to
  opt out (wasted time / an unwanted file), never wrong results. Rated
  **low (2)**.

## Recommended Fix

Set the negating cases to `0`:

```diff
     case "--no-qa-stats":
     case "--no-qastats":
-      set DoQAStats = 1
+      set DoQAStats = 0
       breaksw
```

## Workarounds (If Any)

There is no command-line workaround in 8.2.0 — the flag cannot disable
QA-stats. Users who must avoid the QA-stats step have to edit the script
locally (set `DoQAStats = 0`) or remove/patch the `if($DoQAStats)` block.
