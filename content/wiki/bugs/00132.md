# [severity-3] [bug-00132] `MRIcomputeSurfaceDistanceIntensities` walk-path label check samples the fixed target voxel instead of the walk position, making the safeguard dead code

> [!bug] Synopsis
> ```cpp
> /* mri_extract_fcd_features/mri_extract_fcd_features.cpp:476-600 (excerpt) */
> for (xk = -whalf; xk <= whalf; xk++) {
>     xi = mri_aseg->xi[x0+xk];
>     for (yk = -whalf; yk <= whalf; yk++) {
>         yi = mri_aseg->yi[y0+yk];
>         for (zk = -whalf; zk <= whalf; zk++) {
>             zi = mri_aseg->zi[z0+zk];
>             label = MRIgetVoxVal(mri_aseg, xi, yi, zi, 0);  /* :543 */
>             if (label != hemi_label) continue;               /* :546-547 — filter */
>             label = MRIgetVoxVal(mri_aparc, xi, yi, zi, 0);
>             if (label && label != label0) continue;          /* parcel filter */
>
>             // search along vector connecting x0 to this point …
>             nx = xi - x0; ny = yi - y0; nz = zi - z0;
>             thickness = sqrt(nx*nx + ny*ny + nz*nz);
>             assignable = 1;
>             if (thickness > 0) {
>                 nx /= thickness; ny /= thickness; nz /= thickness;
>                 ...
>                 for (dist = 0; assignable && dist <= thickness; dist += step_size) {
>                     xv = x0 + nx*dist;
>                     yv = y0 + ny*dist;
>                     zv = z0 + nz*dist;
>                     ...
>                     MRIsampleVolume(mri_pial_dist,  xv, yv, zv, &pdist);  /* :568 — correct */
>                     MRIsampleVolume(mri_white_dist, xv, yv, zv, &wdist);  /* :569 — correct */
>                     label = MRIgetVoxVal(mri_aseg, xi, yi, zi, 0);        /* :570 — bug */
>                     if (SKIP_LABEL(label) || label == ohemi_label)
>                         assignable = 0;
>                     if (wdist < 0) assignable = 0;
>                     ...
>                 }
>             }
>             if (assignable) ngm++;
>         }
>     }
> }
> ```
>
> `xv, yv, zv` is the
> floating-point walk
> position along the
> straight line from the
> cortex-center voxel
> `(x0, y0, z0)` to the
> neighborhood target
> `(xi, yi, zi)`. Inside
> the walk:
>
> | sample at `:568-569` | sampled at `(xv, yv, zv)` — the walk position ✓ |
> | sample at `:570`     | sampled at `(xi, yi, zi)` — the **fixed target** ✗ |
>
> The target voxel has
> already been filtered
> at `:546-547` to be
> `hemi_label` (the
> home-hemisphere
> cerebral cortex
> label). So:
>
> - `SKIP_LABEL(hemi_label)`
>   is `false`.
> - `hemi_label ==
>   ohemi_label` is
>   `false`.
>
> The whole condition
> `SKIP_LABEL(label) ||
> label == ohemi_label`
> is always `false`. The
> `assignable = 0`
> assignment never
> fires. The check is
> structurally dead.

## Detailed Description

### Intent vs implementation

The function counts,
for each cortical
vertex, how many
voxels in its
neighborhood
(a `(2*whalf+1)³`
cube centered at
the cortex midline)
are reachable via a
straight-line walk
without:

1. Entering white
   matter (caught by
   `wdist < 0` —
   white-matter
   distance-transform
   crosses 0).
2. Leaving the pial
   surface and
   re-entering (caught
   by `pdist > 0` and
   the
   `outside_of_ribbon`
   re-entry flag).
3. Passing through a
   SKIP_LABEL voxel
   (caudate, ventricle,
   etc.) or into the
   other hemisphere
   (intended: `label
   == ohemi_label`).

Checks (1) and (2)
use the
distance-transform
sampled at the walk
position
`(xv, yv, zv)` —
correct.

Check (3) uses the
**target voxel's
aseg label**, not
the walk position's
aseg label. Since
the target is
already constrained
to be `hemi_label`,
this check never
fires.

### What the code
should have been

```diff
-            label = MRIgetVoxVal(mri_aseg, xi, yi, zi, 0);
+            label = MRIgetVoxVal(mri_aseg, nint(xv), nint(yv), nint(zv), 0);
             if (SKIP_LABEL(label) || label == ohemi_label)
                 assignable = 0;
```

Sample at the walk
position so the
check actually
inspects each step
of the path.

### Downstream impact

For a typical
neighborhood walk:
- The walk goes from
  the cortex midline
  toward a neighbor
  cortex voxel.
- If the path
  briefly clips
  through a
  subcortical
  structure (e.g.,
  caudate near the
  ventricle) before
  reaching the
  target cortex
  voxel, the
  intended check
  (3) should mark
  the target as
  not-assignable.
- With the bug,
  check (3) is
  dead, so the
  target IS counted
  even though the
  path is bad.

The
distance-transform
checks (1) and (2)
do catch the most
common bad-path
cases (entering
WM, leaving pial),
but they don't
catch subcortical
GM clip-through or
other-hemisphere
clip-through.

### Why this is severity 3

- **Silent**: the
  tool runs
  normally;
  feature counts
  are slightly
  inflated for
  vertices where
  the bad walk-
  path-tissue cases
  would have caught
  the target.
- **Reachable**:
  every invocation
  of the function.
- **Clinical
  workflow**: FCD
  detection for
  epilepsy
  surgical
  planning.
- **Bounded
  impact**: the
  primary
  distance-based
  checks still
  catch most bad
  paths; only the
  SKIP_LABEL /
  cross-hemisphere
  edge cases slip
  through.
- **Below severity
  4** because the
  feature itself
  (count of
  reachable GM
  voxels) is still
  computed for
  most cases; only
  edge-case
  failures leak
  through.

## Root Cause

Typo / copy-paste
error. The function
samples
`mri_pial_dist` and
`mri_white_dist` at
the walk position
`xv, yv, zv` (lines
568-569), but the
adjacent aseg
sample at line 570
uses the fixed
target `xi, yi,
zi` instead of the
walk position. The
author likely
copied from the
outer-loop pattern
(where `xi, yi, zi`
is the
neighborhood-iteration
target) without
updating the
indices to the
walk position.

## Impact

- **FCD feature
  output for
  vertices near
  subcortical
  structures or
  near the
  hemisphere
  midline**: the
  count of
  reachable GM
  voxels (ngm)
  is slightly
  inflated.
  Vertices that
  should have
  fewer
  reachable GM
  voxels (due to
  paths
  intersecting
  caudate /
  thalamus /
  contralateral
  hemisphere)
  get higher
  counts.
- **Severity:** 3
  — silent
  feature
  inflation in a
  clinical
  feature-
  extraction
  tool. The
  primary
  distance-based
  walk safety
  checks still
  fire.

## Recommended Fix

```diff
--- a/mri_extract_fcd_features/mri_extract_fcd_features.cpp
+++ b/mri_extract_fcd_features/mri_extract_fcd_features.cpp
@@ -567,7 +567,7 @@ MRIcomputeSurfaceDistanceIntensities(...)
                       DiagBreak() ;
                     MRIsampleVolume(mri_pial_dist, xv, yv, zv, &pdist) ;
                     MRIsampleVolume(mri_white_dist, xv, yv, zv, &wdist) ;
-                    label = MRIgetVoxVal(mri_aseg, xi, yi, zi,0) ;
+                    label = MRIgetVoxVal(mri_aseg, nint(xv), nint(yv), nint(zv), 0) ;
                     if (SKIP_LABEL(label) || label == ohemi_label)
                       assignable = 0 ;
                     if (wdist < 0)  // entered wm - not assignable
```

Sample the aseg
at the walk
position rather
than the fixed
target. Use
`nint()` to round
to integer
coordinates,
matching the
typical pattern
of sampling
voxel labels.
