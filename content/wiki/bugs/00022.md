# [severity-5] [bug-00022] HISTOaddSample drops samples at integer bin positions and mis-guards underflow

> [!bug] Synopsis
> `HISTOaddSample` distributes each sample between the floor and ceil
> bins with weights `dp = dbin − floor(dbin)` and
> `dn = ceil(dbin) − dbin`. For any sample whose normalised position
> `dbin` is integer-valued (e.g., _all_ integer intensities when
> `bin_size = 1`), **both** weights are zero and the sample is silently
> discarded — the histogram has fewer samples than calls. A second
> defect in the else-branch compares the integer bin index to the
> float value-range minimum (`bin_no < bmin`), so underflow counts are
> lost when `bmin < 0`. Multiple callers in the `recon-all` surface
> pipeline build histograms with `bin_size = 1` and feed them integer
> or near-integer intensities, so this is not a latent defect.

## Affected Artefacts

- **Tool(s):** any caller of `HISTOaddSample`. Confirmed bin_size ≡ 1
  configurations:
  - [[mris_make_surfaces]] surface-placement likelihood histograms
    (`mrisurf_sseTerms.cpp:2613–2615`, three histograms
    `h_wm` / `h_gm` / `h_nonbrain` each `(256, 0, 255)`)
  - GCA label-statistics histograms (`gca.cpp:14758–14765`,
    `(256, 0, 255)` per-label)
  - Ventricle / caudate intensity histograms in GCAM label-term code
    (`gcamorph.cpp:16940,16942`, `(nbins, 0, nbins − 1)`)
  - RBM hidden-unit activation histograms (`rbm.cpp:1160`,
    `(nhidden + 1, 0, nhidden)`)
- **Pipeline stage(s):** [[recon-all]] `autorecon2` and `autorecon3`
  (surface placement, GCA build, GCAM optimisation)
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_
- **Platforms:** all
- **Triggering configuration:** always-on for callers listed above;
  affects any future caller that picks `bin_size = 1` or feeds
  integer-valued samples.

## Detailed Description

### Expected Behaviour

Given the signature

```c
int HISTOaddSample(HISTOGRAM *histo, float val, float bmin, float bmax);
```

and a sample `val ∈ [bmin, bmax]`, the function should add **one unit**
of mass to `histo`, distributed between the two adjacent bins via
linear interpolation. For a sample that lies exactly on a bin centre,
the full unit of mass should land in that single bin. Total mass added
over N in-range calls should equal `N` regardless of where the samples
fall.

### Observed Behaviour

For every sample whose normalised bin position
`dbin = (val − bmin) / bin_size` is integer-valued, the weights are:

```
dp = dbin − floor(dbin) = 0
dn = ceil(dbin) − dbin  = 0        (because ceil(k) = k for integer k)
```

The two `counts[]` updates therefore add `0 + 0 = 0` to the histogram.
The call still returns `bin_no` successfully and the caller has no
signal that the sample was dropped.

When `bin_size = 1.0` and `val` is integer-valued — e.g., a histogram
allocated as `HISTOinit(h, 256, 0, 255)` fed raw `MRI_UCHAR` voxel
intensities — this applies to **every single sample**. The
likelihood histograms in
[`utils/mrisurf_sseTerms.cpp:2613-2615`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_sseTerms.cpp#L2613-L2615)
are populated from
[`MRIsampleVolume`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp)
on a T1 volume; many interpolated values are integer-valued whenever
the sample coincides with a voxel centre or falls inside a locally
constant region, so a substantial fraction of samples silently vanish
in `h_wm`, `h_gm`, `h_nonbrain` — the histograms that drive the
[[MRIS_make_surfaces]] likelihood SSE term.

In addition, the else-branch guard

```c
else {
  if (bin_no < bmin)                    // ← comparing bin index to value
    histo->counts[0]++;
  else if (bin_no >= histo->nbins)
    histo->counts[histo->nbins - 1]++;
}
```

compares `bin_no` (integer bin index, out-of-range) to `bmin` (the
value-range minimum, a `float`). The intent is `if (bin_no < 0)`. When
`bmin < 0` and the sample is below range, `bin_no` is negative but
`bin_no < bmin` can evaluate false (e.g., `bin_no = −99`, `bmin =
−2000`), so the underflow count is dropped and neither the `counts[0]`
nor `counts[nbins − 1]` bin is incremented — the left tail is
silently truncated. Four callers use negative `bmin`
(`gcamorph.cpp:16955–16956` uses the `bmin = bmax = −1` "not
specified" sentinel, but `rbm.cpp:1199,1771` also use `−1, −1`, so in
practice the defect fires only when a caller passes a genuine
negative bmin that is less than the integer bin index it computes —
still a real correctness hole for future callers).

### Reproducer

```c
// Minimal C demonstration:
HISTOGRAM *h = HISTOinit(NULL, 256, 0, 255);   // bin_size = 1
for (int v = 0; v <= 255; v++) HISTOaddSample(h, (float)v, 0, 255);
// Expected: every h->counts[b] == 1, total mass 256
// Observed: every h->counts[b] == 0, total mass 0
```

## Root Cause

Two independent defects in the same function:

1. **Integer-dbin dropout (lines 983–992).** The code implements linear
   interpolation between bins `bp = floor(dbin)` and `bn = ceil(dbin)`
   with weights `dn = ceil(dbin) − dbin` (toward lower bin) and
   `dp = dbin − floor(dbin)` (toward upper bin). This formulation
   implicitly assumes `bn = bp + 1`, but when `dbin` is integer,
   `ceil(dbin) = floor(dbin) = dbin`, so `bn = bp` and both weights
   collapse to zero. The total mass added per call is
   `dp + dn = (dbin − floor(dbin)) + (ceil(dbin) − dbin)`, which is
   `1` only for non-integer `dbin` and `0` for integer `dbin`.

   The correct formulation uses a fixed upper bin: `bn = bp + 1` and
   weights `1 − t` to `bp`, `t` to `bn`, where `t = dbin − floor(dbin)`
   is always in `[0, 1)` and the total mass is always `1`.

2. **Index-vs-value comparison (line 995).** The else-branch guard
   `if (bin_no < bmin)` compares an `int` bin index (known to be
   negative or ≥ `nbins` by the outer-else) against a `float`
   value-range minimum. The intent (from symmetry with the adjacent
   `bin_no >= histo->nbins`) is `if (bin_no < 0)`. When `bmin < 0` and
   the sample underflows, the condition can be false and the
   left-tail underflow count is lost.

## Impact

- **Surface placement.** `mris_make_surfaces` (invoked by
  `autorecon2` / `autorecon3`) builds
  `h_wm` / `h_gm` / `h_nonbrain` at
  [`mrisurf_sseTerms.cpp:2613-2615`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_sseTerms.cpp#L2613-L2615)
  with `bin_size = 1` and feeds them values from `MRIsampleVolume`.
  Values that happen to land on an integer (voxel-centre samples, or
  locally constant regions) contribute zero mass. The histograms are
  then normalised to PDFs via
  [`HISTOmakePDF`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/histo.cpp#L1451-L1472)
  and consulted via `HISTOgetCount` inside the likelihood SSE term
  ([`mrisurf_sseTerms.cpp:1150-1156`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_sseTerms.cpp#L1150-L1156)).
  The PDFs are therefore biased away from integer-valued intensities.
  This feeds into the cost that drives pial surface placement.
- **GCA label histograms.**
  [`gca.cpp:14758-14765`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gca.cpp#L14758-L14765)
  builds per-label intensity histograms (used during GCA training) in
  `(256, 0, 255)` bins. Label intensities from UCHAR inputs are
  integers. The resulting histograms systematically under-count
  integer intensities, biasing Gaussian-fit parameters derived from
  them.
- **GCAM label term.**
  [`gcamorph.cpp:16940-16956`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gcamorph.cpp#L16940-L16956)
  builds `hv` / `hc` (ventricle/caudate intensity histograms) the same
  way; these drive the GCAM label energy term during
  `mri_ca_register`.
- **Silent.** There is no warning; the histograms simply have less
  mass than expected. Downstream `HISTOmakePDF` will scale whatever
  mass remains to sum to 1, so the shape distortion is not
  signalled.
- **Magnitude.** For integer-valued inputs at bin_size = 1, 100% of
  samples are dropped. For floating-point inputs, only the fraction
  that lands exactly on integer `dbin` is dropped — non-zero but
  typically small. For non-unity `bin_size` with integer inputs, the
  drop rate depends on whether `(val − bmin) / bin_size` is integer
  for the sampled values.

## Recommended Fix

```diff
   bin_no = nint((val - bmin) / bin_size);
   if (bin_no < histo->nbins && bin_no >= 0)
   {
-    double dp, dn, dbin ;
-    int    bp, bn ;
-    dbin = ((val - bmin) / bin_size) ;
-    dp = dbin-floor(dbin) ;
-    dn = ceil(dbin)-dbin ;
-    bp = (int)floor(dbin) ;
-    bn = (int)ceil(dbin) ;
-    if (bp < 0)
-      bp = 0 ;
-    if (bn >= histo->nbins)
-      bn = histo->nbins-1 ;
-    histo->counts[bn] += dp ;
-    histo->counts[bp]  += dn ;
+    double dbin = (val - bmin) / bin_size;
+    int    bp   = (int)floor(dbin);
+    int    bn   = bp + 1;
+    double t    = dbin - bp;           // fractional part in [0, 1)
+    if (bp < 0) bp = 0;
+    if (bn >= histo->nbins) bn = histo->nbins - 1;
+    histo->counts[bp] += 1.0 - t;
+    histo->counts[bn] += t;            // t == 0 when dbin is integer → all mass in bp
   }
   else {
-    if (bin_no < bmin)
+    if (bin_no < 0)
       histo->counts[0]++;
     else if (bin_no >= histo->nbins)
       histo->counts[histo->nbins - 1]++;
   }
```

Key property of the fix: `weight(bp) + weight(bn) = (1 − t) + t = 1`
for all `t ∈ [0, 1)`, so the total mass per in-range call is exactly
`1` regardless of sample position. For integer `dbin`, `t = 0`, `bp =
dbin`, `bn = dbin + 1` (clamped), and the full unit of mass goes into
`counts[bp]`.

### Alternative Fixes Considered

- Keep the `floor/ceil` formulation and special-case integer `dbin`
  with `if (bp == bn) counts[bp] += 1.0; else { ... }`. Works but is
  uglier than the fixed-upper-bin form.
- Fix only the main branch and leave the else-branch alone. Rejected
  because the else-branch bug is in the same few-line block and the
  diff is trivial.

## Workarounds (If Any)

- Callers that want exact integer-bin placement can bypass
  `HISTOaddSample` by indexing `histo->counts[]` directly, as
  [`utils/mideface.cpp:303-310`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mideface.cpp#L303-L310)
  does. This is the existing in-tree workaround.
- Pre-shift samples by a fraction of `bin_size` (e.g., `val + 0.5 *
  bin_size`) to avoid integer `dbin`. Brittle and not recommended.

## Confidence and Gaps

> [!gap] Caller downstream sensitivity
> The severity rating of `high` assumes the biased PDFs in
> `h_wm` / `h_gm` / `h_nonbrain` measurably shift pial-surface
> placement. End-to-end confirmation on a test subject (compare
> surfaces with and without the fix) has not been performed.

> [!gap] Author intent
> The formulation `dn = ceil(dbin) − dbin` may have been intended as
> "weight toward lower bin" with an implicit assumption that `dbin` is
> never integer (e.g., for continuous image intensities after
> trilinear interpolation). This is inconsistent with the explicit
> `nint(...)` on the same `dbin` on the preceding line, which assumes
> integer `dbin` is common. The fix does not depend on which intent
> was correct because it produces identical output on all non-integer
> `dbin` inputs.
