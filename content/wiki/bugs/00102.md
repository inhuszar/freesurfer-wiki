# [severity-1] [bug-00102] `MRISwriteIntoVolume` auto-allocates a shape its own writer cannot use

> [!bug] Synopsis
> `MRISwriteIntoVolume`
> ([`utils/mrisurf_io.cpp:412-470`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_io.cpp#L412-L470))
> writes a per-vertex scalar (or vector
> component) into an MRI volume. When the
> caller passes `mri == NULL`, the function
> auto-allocates:
>
> ```cpp
> if (mri == NULL) {
>   mri = MRIalloc(1, 1, mris->nvertices, MRI_FLOAT);   /* :419 — width=1, depth=nvertices */
> }
> ```
>
> The writer then dispatches based on `mri`'s
> shape:
>
> ```cpp
> if (mri->width == mris->nvertices)
>   MRIsetVoxVal(mri, vno, 0, 0, 0, val);             /* :454-455 — needs width = N */
> else if (mri->nframes == mris->nvertices)
>   MRIsetVoxVal(mri, 0, 0, 0, vno, val);             /* :456-457 — needs nframes = N */
> else
>   ErrorReturn(NULL, ...);                           /* :459-466 */
> ```
>
> The auto-allocated shape `(width=1,
> height=1, depth=N, nframes=1)` matches
> neither branch (assuming `N > 1`); the very
> first iteration falls into the
> dimension-mismatch error path and returns
> NULL without writing a single voxel.

## Affected Artefacts

- **Tool:** none currently observable in normal
  workflows. Reachable via:
  - [`utils/mrisurf_integrate.cpp:569`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_integrate.cpp#L569),
    [`:608`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_integrate.cpp#L608)
    — debug write blocks gated by `DIAG_WRITE
    && parms->write_iterations > 0 &&
    DIAG_VERBOSE_ON`. The blocks call
    `MRISwriteIntoVolume(mris, NULL, ...)` to
    save per-iteration `dist_dx####.mgz` files
    for inspection.
  - [`mri_extract_fcd_features/mri_extract_fcd_features.cpp:676`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_extract_fcd_features/mri_extract_fcd_features.cpp#L676)
    — passes a non-NULL `mri_features` whose
    `width == nvertices`, so the auto-alloc
    branch is not exercised.
- **Pipeline stage(s):** none in default
  `recon-all` (debug-only path).
- **Triggering configuration:** any caller
  with `mri == NULL` and `mris->nvertices > 1`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mrisurf_io.cpp:412-470 */
MRI *MRISwriteIntoVolume(MRI_SURFACE *mris, MRI *mri, int which)
{
  int vno;
  VERTEX *v;
  float val = 0;

  if (mri == NULL) {
    mri = MRIalloc(1, 1, mris->nvertices, MRI_FLOAT);    /* :419 */
  }

  for (vno = 0; vno < mris->nvertices; vno++) {
    v = &mris->vertices[vno];
    if (v->ripflag) continue;
    switch (which) { ... val = ... }

    if (mri->width == mris->nvertices)
      MRIsetVoxVal(mri, vno, 0, 0, 0, val);
    else if (mri->nframes == mris->nvertices)
      MRIsetVoxVal(mri, 0, 0, 0, vno, val);
    else
      ErrorReturn(NULL, (...));                         /* :459 */
  }
  return (mri);
}
```

Auto-allocated shape:

| Field    | Value         |
|----------|---------------|
| width    | 1             |
| height   | 1             |
| depth    | `nvertices`   |
| nframes  | 1             |

Writer's per-iteration check:

| Test                              | Result for auto-alloc |
|-----------------------------------|----------------------|
| `mri->width == mris->nvertices`   | `1 == N`             |
| `mri->nframes == mris->nvertices` | `1 == N`             |

For `N > 1`, both checks fail and the function
returns `NULL` on the first iteration of the
loop, without writing any vertex. Caller code
like `mrisurf_integrate.cpp:569`:

```cpp
mri = MRISwriteIntoVolume(mris, NULL, VERTEX_DX);
MRIwrite(mri, fname);                              /* :570 — passes NULL to MRIwrite */
```

then passes the NULL return to `MRIwrite`,
which is undefined behaviour (typically a
crash).

The companion reader `MRISreadFromVolume`
([`:478-526`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_io.cpp#L478-L526))
requires `mri->width == nvertices`
([`:484`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_io.cpp#L484)),
confirming that the canonical shape for a
"per-vertex MRI" in this file is `(N, 1, 1, 1)`.
The auto-alloc places `N` in the wrong axis
(`depth` instead of `width`).

## Root Cause

The auto-alloc was probably written before the
shape-dispatch logic was added. The writer
later grew the two `mri->width == N` /
`mri->nframes == N` branches and an error
fallback, but the auto-alloc was not updated to
match either branch. The reader's hard-coded
`mri->width == N` requirement points to
`(N, 1, 1, 1)` as the canonical layout.

## Impact

- **Debug-write paths:** the `dist_dx####.mgz`
  / `dist_dy####.mgz` /
  `dist_dz####.mgz` snapshots produced by
  `mrisurf_integrate.cpp:569` and `:608`
  cannot be saved when `DIAG_VERBOSE_ON` is
  set.
- **External callers:** any user who reads
  the docstring and calls
  `MRISwriteIntoVolume(mris, NULL, …)` will
  receive a NULL return.
- **Severity:** 1 — debug-only impact in the
  current tree; future callers writing new
  code from the documented signature will hit
  the same issue.

## Recommended Fix

```diff
--- a/utils/mrisurf_io.cpp
+++ b/utils/mrisurf_io.cpp
@@ -416,7 +416,7 @@ MRI *MRISwriteIntoVolume(MRI_SURFACE *mris, MRI *mri, int which)
   float val = 0;
 
   if (mri == NULL) {
-    mri = MRIalloc(1, 1, mris->nvertices, MRI_FLOAT);
+    mri = MRIalloc(mris->nvertices, 1, 1, MRI_FLOAT);
   }
```

Single-character-rearrangement fix. The
reader at `:484` already expects this shape.

## Workarounds

Pre-allocate the destination via
`MRIalloc(mris->nvertices, 1, 1, MRI_FLOAT)`
and pass it as the `mri` argument.
