# [severity-2] [bug-00012] mrisComputeOptimalPlane — centroid never divided, reset to zero before covariance; returned plane is centered at origin

> [!bug] Synopsis
> `mrisComputeOptimalPlane` in `utils/mrisurf_metricProperties.cpp` is a
> helper that fits a best-fit plane to a set of vertices via PCA on the
> 3×3 covariance matrix of their positions. It has three compounding
> defects in close succession: (1) it accumulates the centroid
> components `xc, yc, zc` as sums but never divides by the vertex
> count; (2) the second `for`-loop init statement resets `xc = yc =
> zc = 0.0`, discarding the already-incorrect centroid; (3) the
> covariance loop therefore computes the matrix of second moments
> around the origin rather than around the centroid, and the loop also
> silently ignores `ripflag`. As a bonus, the returned centroid
> `(*pxc, *pyc, *pzc)` is always `(0, 0, 0)`, because those
> out-parameters are assigned from the reset variables after the
> covariance loop. The function has no in-tree callers at this commit,
> so the defects are latent — but any downstream consumer that wires
> it up will get a plane fit through the origin with the wrong normal
> direction.

## Affected Artefacts

- **Tool(s):** None today — `mrisComputeOptimalPlane` is a static
  helper in `utils/mrisurf_metricProperties.cpp` and has no in-tree
  callers. It is catalogued as a latent trap because its four-line
  interface (`pxn, pyn, pzn, pxc, pyc, pzc`) advertises a complete
  plane fit that it cannot deliver.
- **Pipeline stage(s):** _N/A_ — not reached by [[recon-all]].
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit
  `d932c45b79`.
- **Platforms:** all — purely arithmetic.
- **Triggering configuration:** every call would fire the defects;
  the practical impact depends on how close the input vertices are
  to the origin (the error on the normal direction grows with the
  distance of the centroid from the origin).

## Detailed Description

PCA-based plane fitting has a canonical form: compute the centroid
$\mu$ of the input points, build the covariance matrix
$M = \sum_i (x_i - \mu)(x_i - \mu)^\top$, take the eigenvector
corresponding to the smallest eigenvalue as the plane normal, and
report $\mu$ as a point on the plane.

`mrisComputeOptimalPlane` attempts this in two loops but loses the
centroid between them. The relevant sequence:

1. **First loop** (centroid pass): accumulates sums of `v->x`,
   `v->y`, `v->z` into `xc`, `yc`, `zc`, and counts live vertices
   in `vnum`. The loop never performs `xc /= vnum`; after it runs,
   `xc` is the sum, not the mean.
2. **`if (vnum < 4)`** early-return guard.
3. **Second loop** (covariance pass): the `for` initialisation is
   `for (xc = yc = zc = 0.0, n = 0; …)`, which resets the three
   accumulators to zero. The inner body then computes
   `SQR(v->x - xc)` etc., but `xc == yc == zc == 0`, so the matrix
   accumulates `v->x²`, `v->x v->y`, … — second moments around the
   origin, not around the centroid.
4. **Eigendecomposition and output**: the eigenvector of the
   smallest eigenvalue is taken as the plane normal, and
   `*pxc, *pyc, *pzc` are assigned from the post-reset
   `xc, yc, zc`, which are all `0`.

### Expected Behaviour

Given N ≥ 4 non-ripped vertices, the function should return a unit
normal `(pxn, pyn, pzn)` pointing along the smallest-variance axis
of the centred point cloud, and a centroid `(pxc, pyc, pzc)` at the
mean of the point cloud.

### Observed Behaviour

- `(pxc, pyc, pzc) = (0, 0, 0)` unconditionally.
- `(pxn, pyn, pzn)` is the eigenvector of the smallest eigenvalue
  of $\sum_i x_i x_i^\top$ — the second-moment matrix around the
  origin. This agrees with the true plane normal **only when the
  centroid happens to coincide with the origin**. Otherwise the
  normal is biased by the positional offset. For a brain surface
  centred in MNI305 or scanner RAS (hundreds of millimetres from
  origin), the "optimal plane" normal is dominated by the centroid
  vector direction.
- Ripped vertices are included in the covariance accumulation
  (second loop) even though the centroid pass (first loop) skips
  them; the two passes disagree about which vertices count.

- **File:** `utils/mrisurf_metricProperties.cpp`
- **Function:** `mrisComputeOptimalPlane()`
- **Lines:** `3579–3656` (full function); defect at `3597–3635` and
  `3650–3652`
- **Commit:** `d932c45b79`

```cpp
int mrisComputeOptimalPlane(MRIS *mris,
                            int *vertices,
                            int nvertices,
                            double *pxn,
                            double *pyn,
                            double *pzn,
                            double *pxc,
                            double *pyc,
                            double *pzc)
{
  int vno, n, vnum;
  MATRIX *M, *m_evectors;
  VERTEX *v;
  double a, b, c, xc, yc, zc, norm;
  float evalues[3];

  M = MatrixAlloc(3, 3, MATRIX_REAL);
  m_evectors = MatrixAlloc(3, 3, MATRIX_REAL);
  for (vnum = 0, xc = yc = zc = 0.0, n = 0; n < nvertices; n++) {
    vno = vertices[n];
    v = &mris->vertices[vno];
    if (vno == Gdiag_no) {
      DiagBreak();
    }
    if (v->ripflag) {
      continue;
    }

    xc += v->x;
    yc += v->y;
    zc += v->z;
    vnum++;
  }
  if (vnum < 4) {
    ErrorReturn(ERROR_BADPARM,
                (ERROR_BADPARM, "mrisComputeOptimalPlane: must specify at least 4 non-ripped verices\n"));
  }

  for (xc = yc = zc = 0.0, n = 0; n < nvertices; n++) {   // ← resets xc/yc/zc
    vno = vertices[n];
    v = &mris->vertices[vno];
    if (vno == Gdiag_no) {
      DiagBreak();
    }
    *MATRIX_RELT(M, 1, 1) += SQR(v->x - xc);              // xc == 0 here
    *MATRIX_RELT(M, 2, 2) += SQR(v->y - yc);
    *MATRIX_RELT(M, 3, 3) += SQR(v->z - zc);

    *MATRIX_RELT(M, 2, 1) += (v->x - xc) * (v->y - yc);
    *MATRIX_RELT(M, 1, 2) += (v->x - xc) * (v->y - yc);

    *MATRIX_RELT(M, 3, 1) += (v->x - xc) * (v->z - zc);
    *MATRIX_RELT(M, 1, 3) += (v->x - xc) * (v->z - zc);

    *MATRIX_RELT(M, 3, 2) += (v->y - yc) * (v->z - zc);
    *MATRIX_RELT(M, 2, 3) += (v->y - yc) * (v->z - zc);
  }
  MatrixEigenSystem(M, evalues, m_evectors);

  // evalues are distance squared to plane, so use smallest one, which is in 3rd col
  a = *MATRIX_RELT(m_evectors, 1, 3);
  b = *MATRIX_RELT(m_evectors, 2, 3);
  c = *MATRIX_RELT(m_evectors, 3, 3);
  norm = sqrt(a * a + b * b + c * c);
  a /= norm;
  b /= norm;
  c /= norm;

  *pxn = a;
  *pyn = b;
  *pzn = c;
  *pxc = xc;    // ← always 0
  *pyc = yc;    // ← always 0
  *pzc = zc;    // ← always 0
  MatrixFree(&m_evectors);
  MatrixFree(&M);
  return (NO_ERROR);
}
```

## Root Cause

Three distinct mistakes that compound:

1. The first loop computes the sum of coordinates but is missing
   the post-loop `xc /= vnum; yc /= vnum; zc /= vnum;` step to
   convert the sum to a mean.
2. The second `for` statement's init `for (xc = yc = zc = 0.0, …)`
   unintentionally resets the (incorrect) sum. The author probably
   intended to reset only `n`, using a comma-expression of
   convenience, but accidentally collapsed both resets onto the
   same statement.
3. The second loop omits the `v->ripflag` guard that the first
   loop uses. Even if the centroid were correct, ripped vertices
   would still leak into the covariance.

The compound result is that the function silently degrades to
"eigenvector of the second-moment matrix around origin", and the
returned centroid is always `(0, 0, 0)`.

## Impact

- Currently **latent**: the function is static to its translation
  unit and has no in-tree caller at `d932c45b79`.
- If any downstream pipeline code (inside or outside the FreeSurfer
  tree) wires the helper up as "fit a plane to this vertex set",
  the returned normal will be biased by the centroid's offset from
  origin. For cortical vertices expressed in surface-RAS (centered
  near origin by `MRIScenter`), the error is small; for vertices
  expressed in scanner RAS or Talairach with typical offsets of
  ~100 mm, the error can flip the normal direction entirely.
- The (0, 0, 0) centroid output is wrong in every case where the
  true centroid is non-zero — any consumer that uses `(pxc, pyc,
  pzc)` as a plane anchor will misplace the plane.

## Recommended Fix

Add the centroid division at the end of the first loop, keep the
reset out of the second loop's init, and add the `ripflag` guard:

```diff

   }

+  yc /= vnum;
+  zc /= vnum;
```

After the patch, `xc, yc, zc` hold the centroid, the covariance is
centred, ripped vertices are excluded consistently, and the
`(*pxc, *pyc, *pzc)` out-parameters report the centroid position.

### Alternative Fixes Considered

Factor the centroid computation into a separate small helper that
takes the vertex list and returns a three-double struct. Less error-
prone to future edits but slightly heavier patch; the minimal
three-hunk diff above is sufficient to correct the arithmetic.

## Workarounds (If Any)

None at the user level — the function has no in-tree caller. A
downstream consumer can reimplement the PCA-plane fit inline.
