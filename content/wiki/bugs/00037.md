# [severity-5] [bug-00037] removeRippedVertices does not compact vertices_topology in lock-step with vertices

> [!bug] Synopsis
> `removeRippedVertices` is the second half of
> `MRISrenumberRemovingRippedFacesAndVertices`. It walks
> `mris->vertices[]`, drops entries whose `ripflag` is set, and
> compacts the remaining `VERTEX` records into the low end of
> the array via `memcpy(sizeof(VERTEX))`. The parallel
> `mris->vertices_topology[]` array — a *separately allocated*
> buffer under `SEPARATE_VERTEX_TOPOLOGY` (which is unconditionally
> defined in this build) — is never touched. After the first
> loop, `vertices[i]` describes the *new* compacted vertex while
> `vertices_topology[i]` still describes the *original* vertex
> that was at index `i` (which may itself have been ripped). The
> second loop then iterates `i = 0..nvertices_new−1`, treats the
> mismatched topology as the new vertex's neighbour list, and
> rewrites it through `out_vnos[]`. For any neighbour that was
> ripped, `out_vnos[…] == −1` is written back into the neighbour
> list, leaving `−1` as a valid-looking vertex index. The
> ripped-neighbour guard
> `mris->vertices[vno2].ripflag == 1` is also unreliable after
> the compaction (every position `< nvertices_new` was
> overwritten with non-ripped data). Fires when
> `mris_inflate -explode <thresh>` actually rips at least one
> vertex.

## Detailed Description

### Expected Behaviour

After `MRISrenumberRemovingRippedFacesAndVertices(mris)`
returns, the surface should be a coherent compact mesh:
- `mris->nvertices` reflects the count of surviving vertices,
- `vertices[i]` and `vertices_topology[i]` jointly describe the
  same surviving vertex `i`,
- every `vertices_topology[i].v[*]` index points to a surviving
  vertex (no `−1`s),
- every `faces[fno].v[*]` index points to a surviving vertex.

The function calls `mrisCheckVertexFaceTopology(mris)` at exit,
which is supposed to enforce this invariant.

### Observed Behaviour

`removeRippedVertices`
([`utils/mrisurf_topology.cpp:2780-2854`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_topology.cpp#L2780-L2854))
compacts only `vertices[]`:

```cpp
for (out_vno = vno = 0; vno < mris->nvertices; vno++)
{
  VERTEX const * const v = &mris->vertices[vno];
  if (v->ripflag) {
    nvertices--;
    out_vnos[vno] = -1;
  } else {
    out_vnos[vno] = out_vno;
    if (vno != out_vno)                                       /* in-place compact */
      memcpy(mris->vertices+out_vno, mris->vertices+vno, sizeof(VERTEX)); /* GROSS HACK */
    out_vno++;
  }
}
```

`sizeof(VERTEX)` does **not** include the topology fields,
because `SEPARATE_VERTEX_TOPOLOGY` is unconditionally defined
in
[`include/mrisurf_FACE_VERTEX_MRIS_generated.h:7`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mrisurf_FACE_VERTEX_MRIS_generated.h#L7),
and `MRISreallocVertices`
([`utils/mrisurf_base.cpp:514-555`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_base.cpp#L514-L555))
allocates `mris->vertices_topology` as an independent buffer.
Nothing in this function — and nothing in
`MRISremovedVertices`
([`utils/mrisurf_base.cpp:570-574`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_base.cpp#L570-L574),
which only updates `nvertices`) — compacts that buffer.

The next loop
([`:2808-2842`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_topology.cpp#L2808-L2842))
then walks the *new* index range:

```cpp
for (vno = 0; vno < nvertices; vno++)
{
  VERTEX_TOPOLOGY * const v = &mris->vertices_topology[vno];   /* WRONG ENTRY */
  /* … reads v->v[n], v->vnum, v->v2num, v->v3num … */
  for (n = 0; n < v->vtotal; n++)
  {
    int vno2 = v->v[n];
    if (vno2 < 0 || mris->vertices[vno2].ripflag == 1)         /* see (a) */
      continue;
    v->v[v->v3num++] = out_vnos[v->v[n]];                      /* see (b) */
    /* … */
  }
}
```

Two consequences:

**(a)** The neighbour-skip predicate
`mris->vertices[vno2].ripflag == 1` looks up `vno2` (an
*original* index) in the *post-compaction* `vertices[]` array.
For every `vno2 < nvertices`, position `vno2` was overwritten
with a non-ripped vertex's data, so `ripflag == 0` and the
predicate fails to skip ripped originals. For
`vno2 >= nvertices`, the slot still holds whichever vertex was
last memcpy'd from there (or the ripped vertex's stale data),
so the predicate is non-deterministic.

**(b)** `out_vnos[ripped_vno] == −1`. When the predicate in (a)
fails to filter out a ripped neighbour, `−1` is written into
`v->v[]`. Downstream consumers of the topology — face
look-ups, distance computations, neighbour averaging — index
`mris->vertices[-1]`, which is one element before the buffer
and reads stale memory.

A small worked example. Original surface with four vertices,
V1 ripped, all others surviving:

| original vno | ripflag | out_vnos[orig] | post-compaction vertices[] | post-compaction vertices_topology[] |
|-------------:|:-------:|:--------------:|:---------------------------|:------------------------------------|
|            0 |    0    |        0       | V0 (correct)               | topology of V0 (correct)            |
|            1 |    1    |       −1       | V2 (compacted in)          | topology of V1 (wrong vertex!)       |
|            2 |    0    |        1       | V3 (compacted in)          | topology of V2 (wrong vertex!)       |
|            3 |    0    |        2       | stale V3                   | topology of V3 (unused, vno=3 ≥ nvertices=3) |

When the second loop runs on `vno = 1`, it reads V1's
topology (V1 was ripped) and rewrites it through `out_vnos[]`,
storing the result back at `vertices_topology[1]`. The new
vertex at position 1 is V2, but its topology is now V1's
remapped neighbour list. The face loop at
[`:2844-2849`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_topology.cpp#L2844-L2849)
is correct (faces store original vnos, are remapped via
`out_vnos[]`), but face↔vertex consistency is then broken.

## Root Cause

The compaction logic was written under the assumption that
`mris->vertices_topology` aliases `mris->vertices` (the
`#ifndef SEPARATE_VERTEX_TOPOLOGY` branch in
`MRISreallocVertices`). When that aliasing held, a single
`memcpy(sizeof(VERTEX))` would have moved both records in
lock-step. The unconditional `#define SEPARATE_VERTEX_TOPOLOGY`
in
[`mrisurf_FACE_VERTEX_MRIS_generated.h:7`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mrisurf_FACE_VERTEX_MRIS_generated.h#L7)
broke the assumption, and `removeRippedVertices` was not
updated.

## Impact

- **`mris_inflate -explode <thresh>`**: any iteration in which
  `mrisTearStressedRegions` rips at least one vertex (printed
  as `nrip = N` with `N > 0`) leaves the surface with
  mismatched `vertices` / `vertices_topology` pairing.
  Subsequent integration steps read garbage neighbour
  positions, neighbour distances, and ripflag bits. Most
  likely outcome: a `cheapAssert` fires inside
  `mrisCheckVertexFaceTopology` immediately on return, which
  aborts the program (an explicit, non-silent failure).
  Worse outcome: `−1` survives in `v->v[]` and a later
  consumer dereferences `mris->vertices[-1]`.
- **Internal callers in default [[recon-all]]**: none —
  `MRISrenumberRemovingRippedFacesAndVertices` is only invoked
  from the explode-mode integration loop.
- **Latent for non-explode inflation**: `parms->explode_flag`
  is the only gate. Standard `mris_inflate` (no `-explode`)
  does not call this function and is unaffected.

## Recommended Fix

Compact `vertices_topology[]` in the same pass as
`vertices[]`, then strengthen the ripped-neighbour guard so
the loop does not depend on `vertices[]` having been
overwritten.

```diff
   for (out_vno = vno = 0; vno < mris->nvertices; vno++)
   {
     VERTEX const * const v = &mris->vertices[vno];
     if (vno == Gdiag_no) DiagBreak();
     if (v->ripflag) {
       nvertices--;
       out_vnos[vno] = -1;
     } else {
       if (out_vno == Gdiag_no) DiagBreak();
       out_vnos[vno] = out_vno;
       if (vno != out_vno) {
         memcpy(mris->vertices+out_vno, mris->vertices+vno, sizeof(VERTEX));
+        /* Move topology in lock-step. SEPARATE_VERTEX_TOPOLOGY is
+           unconditionally defined: vertices_topology is its own
+           buffer. The pointer fields (f, n, e, v) are owned by
+           this slot — moving the struct moves their ownership too,
+           and we leave nothing aliased at the source slot
+           (out_vno < vno is the strict invariant of this loop). */
+        memcpy(mris->vertices_topology + out_vno,
+               mris->vertices_topology + vno,
+               sizeof(VERTEX_TOPOLOGY));
       }
       out_vno++;
     }
   }

   for (vno = 0; vno < nvertices; vno++) {
     VERTEX_TOPOLOGY * const v = &mris->vertices_topology[vno];
     int vnum, v2num, v3num;
     vnum = v->vnum; v2num = v->v2num; v3num = v->v3num;
     v->v3num = v->v2num = 0; clearVnum(mris,vno);
     for (n = 0; n < v->vtotal; n++) {
       int vno2 = v->v[n];
-      if (vno2 < 0 || mris->vertices[vno2].ripflag == 1)
+      /* vertices[] was just compacted; ripflag in-place is unreliable
+         for original indices. Use out_vnos[] (built from the original
+         ripflags) as the authoritative survivor map. */
+      if (vno2 < 0 || out_vnos[vno2] < 0)
         continue;
       v->v[v->v3num++] = out_vnos[v->v[n]];
       if (n < v2num) v->v2num++;
       if (n < vnum)  addVnum(mris, vno, 1);
     }
     /* … */
   }
```

The first hunk fixes the topology/vertex pairing. The second
hunk uses `out_vnos[]` as the ground-truth survivor map (it
was built from the original `ripflag` bits before any
compaction), so the predicate is independent of the
overwritten `vertices[].ripflag` and is also robust if the
first hunk is applied (since after compaction the topology in
slot `i` describes the surviving vertex, but `v->v[n]` still
holds *original* indices until rewritten).

### Alternative Fixes Considered

- **Allocate a fresh `VERTEX_TOPOLOGY *new_vt` of size
  `nvertices` and copy survivors in.** Cleaner ownership story
  for the embedded `f`, `n`, `e`, `v` pointers, but requires
  freeing the old buffer and updating `mris->vertices_topology`
  via the same `(VERTEX_TOPOLOGY *)`-cast trick used elsewhere.
  Functionally equivalent.
- **Disable `SEPARATE_VERTEX_TOPOLOGY` in this build.** The
  generated header `#define`s it unconditionally, so doing
  this would require regenerating the header and likely
  breaks unrelated invariants. Not recommended.

## Workarounds (If Any)

- Avoid `mris_inflate -explode <thresh>`. The non-explode
  inflation path does not exercise this function.
- If `-explode` is required, use a stress threshold high
  enough that `nrip` is always reported as `0` in the
  per-iteration log line (no vertices actually ripped → no
  compaction → no observable defect).

## Confidence and Gaps

> [!gap] Whether `mrisCheckVertexFaceTopology` always catches it
> The function asserts a number of invariants that the
> mismatched topology would violate (e.g., neighbour-count
> consistency between `vnum` and `v->v[]`). In practice this
> tends to assert-and-abort rather than silently corrupt, but
> the precise observable depends on which invariant trips
> first.

> [!gap] Memory ownership of the moved pointers
> Each `VERTEX_TOPOLOGY` owns its `f`, `n`, `e`, `v` arrays via
> heap pointers. The recommended `memcpy` of the struct copies
> the *pointer values*, transferring ownership from slot `vno`
> to slot `out_vno` (and leaving the source slot with stale
> pointers, which is fine because the loop never reads slot
> `vno > out_vno` again). This matches the existing handling
> for `VERTEX` (which also has heap members like `dist`,
> `dist_orig`).
