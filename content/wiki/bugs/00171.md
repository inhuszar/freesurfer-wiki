# [severity-3] [bug-00171] label_child — references unset `$GCA_TL`, aborting under `tcsh -ef` before mri_ca_label runs

> [!bug] Synopsis
> `scripts/label_child` builds its `mri_ca_label` command line as
> `mri_ca_label -tl $GCA_TL ...`, but `GCA_TL` is **never set** anywhere
> in the script — only `GCA` is defined (twice). The script's shebang is
> `#!/bin/tcsh -ef`, under which referencing an undefined variable is a
> fatal error. So `label_child <subject>` aborts immediately with
> `GCA_TL: Undefined variable.` before `mri_ca_label` is ever launched.
> The tool is broken as shipped — it cannot label a single subject.

## Affected Artefacts

- **Tool(s):** [[label_child]] — a tcsh wrapper that runs `mri_ca_label`
  with the children GCA atlases to produce an `aseg` for a paediatric
  subject (`$1` = subject).
- **Pipeline stage(s):** _N/A_ — run by hand; not part of
  [[wiki/pipelines/recon-all|recon-all]].
- **FreeSurfer version(s):** confirmed broken in `8.2.0` at commit
  `d932c45`.
- **Platforms:** all — the `-ef` undefined-variable abort is a tcsh
  language behaviour, not platform-specific.
- **Triggering configuration:** **every** invocation. The `mri_ca_label`
  line unconditionally interpolates `$GCA_TL`.

## Detailed Description

`label_child` sets several variables at the top:

```tcsh
setenv LTA   talairach.lta
setenv ASEG  aseg
setenv GCA $FREESURFER_HOME/average/talairach_children_b.gca
setenv GCA $FREESURFER_HOME/average/talairach_children_tl_b.gca
setenv s $1
```

Note `GCA` is set twice (the second assignment wins, pointing at the
`_tl_` atlas), but **`GCA_TL` is never set**. The final command line
([`scripts/label_child:30`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/label_child#L30))
is:

```tcsh
mri_ca_label -tl $GCA_TL -mask $sdir/brain  $sdir/norm $sdir/transforms/$LTA $GCA $sdir/$ASEG
```

It references both `$GCA` (defined) and `$GCA_TL` (undefined). A grep of
the whole script confirms `GCA_TL` occurs exactly once — here, on the
usage line — and is never assigned.

The shebang is `#!/bin/tcsh -ef`
([`scripts/label_child:1`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/label_child#L1)).
The `-e` option makes the shell exit on the first error, and tcsh treats
the expansion of an **unset** variable as a fatal error ("Undefined
variable."). So the moment the shell tries to expand `$GCA_TL` while
building the command line, the script dies — `mri_ca_label` is never
exec'd.

### Expected Behaviour

`label_child <subject>` should run `mri_ca_label` with both the main
children atlas (`$GCA`) and a temporal-lobe atlas passed via `-tl`,
writing `$SUBJECTS_DIR/<subject>/mri/aseg`.

### Observed Behaviour

The script aborts with `GCA_TL: Undefined variable.` before
`mri_ca_label` runs. No segmentation is produced.

### Reproducer

```bash
export SUBJECTS_DIR=/tmp/lc_repro_sd
rm -rf $SUBJECTS_DIR
mkdir -p $SUBJECTS_DIR/testsubj/mri

label_child testsubj
# → GCA_TL: Undefined variable.
```

Observed (v8.2.0): the script prints `GCA_TL: Undefined variable.` and
stops; `mri_ca_label` is never invoked. Verified 2026-06-09 against
`/usr/local/freesurfer/8.2.0/bin/label_child`.

## Code Reference (Unambiguous)

- **File:** `scripts/label_child`
- **Function/symbol:** top-level script body
- **Lines:** `1` (shebang), `21-30` (variable setup + command line)
- **Commit:** `d932c45`

```tcsh
#!/bin/tcsh -ef
...
setenv LTA   talairach.lta
setenv ASEG  aseg
setenv GCA $FREESURFER_HOME/average/talairach_children_b.gca
setenv GCA $FREESURFER_HOME/average/talairach_children_tl_b.gca

setenv s $1

set sdir = $SUBJECTS_DIR/$s/mri
mkdir -p $sdir/$ASEG
mri_ca_label -tl $GCA_TL -mask $sdir/brain  $sdir/norm $sdir/transforms/$LTA $GCA $sdir/$ASEG
```

`GCA` is assigned at lines 23-24; `GCA_TL` is referenced at line 30 and
assigned nowhere. Under the `-ef` shebang at line 1, the unset `$GCA_TL`
expansion is fatal.

## Root Cause

Undefined variable under `tcsh -ef`. The `-tl` (temporal-lobe atlas)
argument is supposed to be a distinct GCA file from the main `$GCA`, but
the variable that should hold it (`GCA_TL`) was never given a value. The
two `setenv GCA …` lines suggest the author intended the **first** to be
the main atlas and the **second** (the `_tl_` one) to be the temporal-lobe
atlas — i.e. the second `setenv GCA` was probably meant to be `setenv
GCA_TL`. As written, the second assignment merely overwrites `GCA`, and
`GCA_TL` stays unset.

## Impact

- **Broken as shipped.** Every `label_child` run aborts before doing any
  work. The tool cannot segment a paediatric subject in v8.2.0.
- **Loud, not silent.** The `-ef` abort is an explicit error with a clear
  message and non-zero exit; there is no risk of wrong-but-plausible
  output.
- **Severity 3 (medium).** Standalone auxiliary tool (children-atlas
  labelling), not a default pipeline, and the failure is loud. It is
  broken whenever invoked, but only when explicitly invoked — hence
  medium, not high.

## Recommended Fix

Define `GCA_TL` to the temporal-lobe children atlas (the `_tl_` file the
second `setenv GCA` currently points at), and let `GCA` be the main
children atlas:

```diff
 setenv LTA   talairach.lta
 setenv ASEG  aseg
 setenv GCA $FREESURFER_HOME/average/talairach_children_b.gca
-setenv GCA $FREESURFER_HOME/average/talairach_children_tl_b.gca
+setenv GCA_TL $FREESURFER_HOME/average/talairach_children_tl_b.gca
```

After this, line 30 interpolates a defined `$GCA_TL`
(`talairach_children_tl_b.gca`) and `$GCA`
(`talairach_children_b.gca`), and `mri_ca_label -tl $GCA_TL … $GCA …`
runs. A test should confirm the script reaches `mri_ca_label` and exits
zero for a subject that has `norm`, `brain`, and
`transforms/talairach.lta`.

### Alternative Fixes Considered

- If `mri_ca_label` should **not** use a separate `-tl` atlas at all,
  drop `-tl $GCA_TL` from the command line entirely. This avoids
  introducing `GCA_TL` but changes the labelling (no temporal-lobe
  atlas). The diff above is preferred because the presence of the `_tl_`
  GCA filename indicates a temporal-lobe atlas was intended.

> [!gap] Which atlas belongs where
> The fix assumes the `_tl_b.gca` file is the temporal-lobe atlas (for
> `-tl`) and the plain `_b.gca` is the main atlas. This is the natural
> reading of the two filenames, but should be confirmed against the
> intended children-segmentation recipe before shipping.

## Workarounds (If Any)

Run `mri_ca_label` by hand with both atlases explicitly, e.g.

```bash
mri_ca_label -tl $FREESURFER_HOME/average/talairach_children_tl_b.gca \
  -mask $sdir/brain $sdir/norm $sdir/transforms/talairach.lta \
  $FREESURFER_HOME/average/talairach_children_b.gca $sdir/aseg
```

substituting the subject's `mri` directory for `$sdir`. Do not rely on
`label_child` as shipped.
