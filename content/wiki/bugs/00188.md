# [severity-2] [bug-00188] fsr-longpreproc — modename consistency check diffs 'unique.modenames.txt' but fsr-import writes 'fsr-import.unique.modenames.txt'

> [!bug] Synopsis
> `fsr-longpreproc` cross-checks that every input time point shares the
> same set of unique modenames by `diff`-ing each time point's
> per-timepoint unique-modenames file against the reference time point's.
> The reference side correctly uses `log/fsr-import.unique.modenames.txt`
> (the name [[fsr-import]] actually writes), but the per-time-point side
> of the `diff` points at `log/unique.modenames.txt` — without the
> `fsr-import.` prefix. That file does not exist, so `diff` errors to
> stderr and emits nothing on stdout; the line-count guard sees zero
> lines and the consistency check silently passes. The check that is
> supposed to reject time points with mismatched modes never actually
> compares the intended file.

## Affected Artefacts

- **Tool(s):** [[fsr-longpreproc]] (the broken check); [[fsr-import]]
  (the writer whose filename the check fails to match).
- **Pipeline stage(s):** longitudinal preprocessing — building a base
  from multiple per-timepoint import+coreg directories, upstream of
  `samseg-long` / `run_samseg_long`.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — purely shell/IO.
- **Triggering configuration:** any
  `fsr-longpreproc --o out --tp tp1 --tp tp2 ...` run with newly
  specified inputs reaches the time-point consistency loop in
  `check_params`. The faulty `diff` runs for every time point.

## Detailed Description

In its `check_params` block `fsr-longpreproc` validates that all time
points are mutually consistent. It reads the reference time point's
unique-modenames file into `$uumodenames` from
`$tplist[1]/log/fsr-import.unique.modenames.txt`
([`scripts/fsr-longpreproc:575-576`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-longpreproc#L575-L576)),
then loops over every time point and `diff`s the two files
([`scripts/fsr-longpreproc:585`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-longpreproc#L585)).

The first operand, `$uumodenamesfile`, is correct. The second operand is
spelled `$tpdir/log/unique.modenames.txt`, omitting the `fsr-import.`
prefix that [[fsr-import]] uses when it writes the file
([`scripts/fsr-import:281`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-import#L281)
sets `umodenamefile = $outdir/log/fsr-import.unique.modenames.txt`, and
[`scripts/fsr-import:77`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-import#L77)
writes `$umodenames` into it). The error-message body of the same `if`
block even references the correctly-named file
([`scripts/fsr-longpreproc:588-589`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-longpreproc#L588-L589)),
confirming the intended target is `fsr-import.unique.modenames.txt`.

### Expected Behaviour

For each time point, the script should compare that time point's
`log/fsr-import.unique.modenames.txt` against the reference time point's
copy of the same file, and abort with
`"ERROR: time points differ in unique modenames"` if they differ.

### Observed Behaviour

`diff $uumodenamesfile $tpdir/log/unique.modenames.txt` is run with a
non-existent second file. `diff` writes
`diff: .../log/unique.modenames.txt: No such file or directory` to
**stderr** and produces **no stdout**. The command substitution
`` `... | wc -l` `` therefore captures `0`, so `$nd` is `0`, the guard
`if($nd > 0)` is false, and the check is skipped for every time point —
including the reference time point compared against itself. Time points
with genuinely different modenames are not detected.

### Reproducer

> [!gap] Reproducer not yet constructed
> A direct demonstration requires two fully-populated time-point
> directories (each produced by [[fsr-import]] + [[fsr-coreg]]) with
> deliberately mismatched modenames. The defect is, however, immediate
> from the filenames:
>
> 1. `ls tp1/log/` shows `fsr-import.unique.modenames.txt` (written by
>    fsr-import), and **no** `unique.modenames.txt`.
> 2. The `diff` at line 585 reads `tp1/log/unique.modenames.txt`, which
>    is absent, so `diff` fails and `$nd == 0`.
> 3. Even when two time points have different modes, the
>    `"time points differ in unique modenames"` error never fires.

## Code Reference (Unambiguous)

- **File:** `scripts/fsr-longpreproc`
- **Function:** `check_params` (consistency loop over `$tplist`)
- **Lines:** `575-591`; defect at `585`
- **Commit:** `d932c45`

```tcsh
set uumodenamesfile = $tplist[1]/log/fsr-import.unique.modenames.txt   # correct ref name
set uumodenames = (`cat $uumodenamesfile`)
foreach tpdir ($tplist)
  set nd = `diff $coregparfile $tpdir/log/fsr-coreg.par.txt | wc -l`
  if($nd > 0) then
    echo "ERROR: time points differ in coreg par file"
    echo $coregparfile $tpdir/log/fsr-coreg.par.txt
    cat  $coregparfile $tpdir/log/fsr-coreg.par.txt
    exit 1
  endif
  set nd = `diff $uumodenamesfile $tpdir/log/unique.modenames.txt | wc -l`   # ← wrong file: missing 'fsr-import.' prefix
  if($nd > 0) then
    echo "ERROR: time points differ in unique modenames"
    echo $uumodenamesfile $tpdir/log/fsr-import.unique.modenames.txt          # message uses the CORRECT name
    cat $uumodenamesfile $tpdir/log/fsr-import.unique.modenames.txt
    exit 1
  endif
  ...
end
```

Companion site in the writer (proves the canonical filename):

```tcsh

echo $umodenames > $umodenamefile                                 # :77
```

## Root Cause

A filename typo in `fsr-longpreproc`: the second `diff` operand was
written as `unique.modenames.txt` instead of
`fsr-import.unique.modenames.txt`. Because `diff` against a missing file
returns no stdout (its complaint goes to stderr), the `| wc -l == 0`
makes the guard a no-op rather than a failure, so the mistake is silent.
The surrounding code — the reference-side variable
(`$uumodenamesfile`) and the two `echo`/`cat` lines in the error body —
all use the correct `fsr-import.`-prefixed name, isolating the defect to
this one operand.

## Impact

- This is a QA/consistency check, not a data-producing step, so a wrong
  result does not directly corrupt output — hence severity 2. Its job is
  to fail fast when a user assembles time points with inconsistent
  modenames; that safety net is disabled.
- A user who accidentally points `--tp` at time points with different
  modes (e.g. one timepoint imported without FLAIR) will *not* be
  stopped here. The run proceeds and may fail later in a more confusing
  place, or silently build a base over an inconsistent mode set.
- The neighbouring coreg-parameter check on the line above
  ([`scripts/fsr-longpreproc:578`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-longpreproc#L578))
  is correct and still fires, so some inconsistencies are still caught;
  only the modename comparison is defeated.

## Recommended Fix

Add the missing `fsr-import.` prefix to the second `diff` operand so it
matches the file [[fsr-import]] writes:

```diff
-  set nd = `diff $uumodenamesfile $tpdir/log/unique.modenames.txt | wc -l`
+  set nd = `diff $uumodenamesfile $tpdir/log/fsr-import.unique.modenames.txt | wc -l`
```

### Alternative Fixes Considered

Capture stderr too (`diff ... |& wc -l`) so a missing file would inflate
`$nd` and surface as a (misleading) "modes differ" error — this would at
least stop the run, but it reports the wrong reason and still doesn't
compare the right file. The one-line filename fix above is the correct
remedy. Optionally also guard with an explicit existence check
(`if(! -e $tpdir/log/fsr-import.unique.modenames.txt) ... exit 1`) to
make a missing file a loud, specific error.

## Workarounds (If Any)

Until patched, verify by hand that every time point's
`log/fsr-import.unique.modenames.txt` is identical before running
`fsr-longpreproc` (e.g. `diff tp1/log/fsr-import.unique.modenames.txt
tp2/log/fsr-import.unique.modenames.txt`). There is no flag that
re-enables the built-in check.
