# [severity-2] [bug-00167] gca-apply — `--no-segstats` is a no-op and the `--force-update` overwrite guards can never refuse

> [!bug] Synopsis
> In `scripts/gca-apply`, the `--no-segstats` flag sets the variable
> `DoSegStats = 0`, but `DoSegStats` is never read anywhere else in the
> script. The `mri_segstats` block is gated only on the
> update-needed/`--force-update` test, so segstats **always runs** and
> `--no-segstats` silently does nothing. Separately, the four (five with
> `--m3z`) "file already exists" overwrite guards live entirely inside an
> `if($ForceUpdate)` block, and each guard refuses only when
> `! $Overwrite`; but `--force-update` is the only thing that sets
> `ForceUpdate = 1`, and it sets `Overwrite = 1` in the same case, so
> inside that block `! $Overwrite` is always false. The overwrite-refusal
> logic is therefore unreachable — there is effectively no overwrite
> protection.

## Affected Artefacts

- **Tool(s):** [[gca-apply]] — a standalone tcsh wrapper that replays the
  recon-all GCA stages (`mri_em_register`, `mri_ca_normalize`,
  `mri_ca_register`, `mri_ca_label`, then `mri_segstats`).
- **Pipeline stage(s):** _N/A_ — `gca-apply` is run by hand (e.g. for GCA
  atlas evaluation / `gcatrain` workflows); it is not invoked by
  [[wiki/pipelines/recon-all|recon-all]].
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — purely control flow in a shell script.
- **Triggering configuration:**
  - The `--no-segstats` no-op fires on **every** invocation that passes
    `--no-segstats` expecting to skip segstats.
  - The dead overwrite guards fire on **every** `--force-update` run that
    has pre-existing outputs: the user is silently allowed to overwrite,
    never refused.

## Detailed Description

`gca-apply` declares `Overwrite = 0` and `ForceUpdate = 0` at the top
([`scripts/gca-apply:23`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L23),
[`:25`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L25)).
The `--no-segstats` case introduces a third variable, `DoSegStats`, but
no default for it is ever declared and nothing ever tests it.

### Defect 1 — `--no-segstats` is a no-op

The argument parser handles `--no-segstats` by setting `DoSegStats = 0`
([`scripts/gca-apply:299-301`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L299-L301)),
and the usage text advertises it as "do not compute segstats"
([`scripts/gca-apply:504`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L504)).
But the segstats block
([`scripts/gca-apply:172-188`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L172-L188))
is guarded only by `if($ud || $ForceUpdate)`
([`scripts/gca-apply:175`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L175)),
where `$ud` is the result of `UpdateNeeded $statsfile $aseg $norm`. There
is no reference to `DoSegStats` anywhere outside the assignment in the
parser. A grep of the entire script confirms `DoSegStats` occurs exactly
once. The flag is dead: `mri_segstats` runs whenever the stats file is
out of date (which it always is on a fresh run, because `$aseg` is
regenerated immediately beforehand).

### Defect 2 — the overwrite guards can never refuse

The "check whether the outputs already exist" section
([`scripts/gca-apply:453-477`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L453-L477))
is wrapped in `if($ForceUpdate)`
([`scripts/gca-apply:454`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L454)).
Each inner test is of the form `if(-e $lta && ! $Overwrite)` → `ERROR:
$lta already exists`. The only place `ForceUpdate` is set to `1` is the
`--force-update` case
([`scripts/gca-apply:294-297`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L294-L297)),
and that same case sets `Overwrite = 1`. No other flag sets `Overwrite`.
Therefore:

- If `--force-update` was **not** given, `ForceUpdate == 0`, the entire
  guard block is skipped — no existence check runs at all.
- If `--force-update` **was** given, `Overwrite == 1`, so `! $Overwrite`
  is `0` (false) in every inner test — every guard is skipped.

There is no reachable code path on which any of these `ERROR: ... already
exists` messages can be printed. The guards are dead, and `gca-apply`
never refuses to overwrite an existing output.

### Expected Behaviour

- `--no-segstats` should skip the `mri_segstats` step entirely.
- The "already exists" guards read as an intent to refuse clobbering
  pre-existing outputs unless an explicit overwrite is requested. (As
  written, the only flag in the script is `--force-update`, which is
  precisely the "go ahead and overwrite" intent, so the guard block as
  placed cannot express a refusal.)

### Observed Behaviour

- `mri_segstats` runs regardless of `--no-segstats`.
- No output-existence refusal ever occurs.

### Reproducer

> [!gap] Reproducer not executed end-to-end
> A full `gca-apply` run requires a recon-all subject with `nu.mgz` and
> `brainmask.mgz` and takes hours (it performs `mri_ca_register`). The
> defects are confirmed by static reading: `DoSegStats` is assigned at
> [`scripts/gca-apply:300`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L300)
> and never read; the segstats block at
> [`:175`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/gca-apply#L175)
> tests only `$ud || $ForceUpdate`. The following two greps demonstrate
> the dead variable and the always-true `Overwrite` inside the guard:
>
> ```bash
> # DoSegStats appears exactly once (the no-op assignment):
> grep -n DoSegStats /usr/local/freesurfer/8.2.0/bin/gca-apply
> # Overwrite is set to 1 only inside --force-update, alongside ForceUpdate=1:
> grep -n 'set Overwrite = 1\|set ForceUpdate = 1\|if($ForceUpdate)\|! $Overwrite' \
>   /usr/local/freesurfer/8.2.0/bin/gca-apply
> ```

## Root Cause

Two independent variable-wiring mistakes:

1. **Dead variable.** `DoSegStats` was added to the parser but the
   author never added the corresponding `if($DoSegStats)` guard around
   the segstats block. There is no default initialisation for
   `DoSegStats` either, so even a hand-added test would need one.
2. **Coupled flags + misplaced guard.** The overwrite-refusal block was
   placed under `if($ForceUpdate)` and keyed on `! $Overwrite`, but the
   single flag that turns on `ForceUpdate` also turns on `Overwrite`.
   The two booleans are never set independently, so the
   `ForceUpdate && !Overwrite` state the guards depend on is
   unreachable. (The guards also logically belong **outside** the
   `--force-update` branch — one would expect a normal run to refuse to
   clobber outputs, and `--force-update` to be the override.)

## Impact

- **`--no-segstats` silently ignored.** A user who passes `--no-segstats`
  to save the (non-trivial) `mri_segstats` time still pays it, and still
  gets a `.stats` file written. No error or warning is emitted. This is a
  wasted-work / surprising-behaviour defect, not a data-corruption one —
  the segstats output itself is correct.
- **No overwrite protection.** The help text and the guard block imply
  `gca-apply` will refuse to clobber existing `lta`/`norm`/`aseg`/`stats`/
  `m3z` outputs, but it never does. In practice the script's normal mode
  already relies on `UpdateNeeded` (timestamp comparison) to skip
  up-to-date files, so accidental clobbering is partially mitigated by
  that mechanism; the dedicated guard, however, is inert.
- **Severity 2 (low).** `gca-apply` is a standalone, manually-run
  auxiliary tool (its own help says runs "may take 8 hours or so"), not
  part of a default pipeline. Both defects are option/guard-only: they do
  not corrupt the scientific output. Per the rubric, an option that is
  silently a no-op is a low-severity defect.

## Recommended Fix

Add a default for `DoSegStats`, gate the segstats block on it, and
decouple the overwrite guards from `--force-update` (move them out of the
`if($ForceUpdate)` wrapper and let `--force-update` be the override):

```diff
@@ variable defaults @@
 set EMRegAseg = 1;
 set ctab = $FREESURFER_HOME/ASegStatsLUT.txt
 set ForceUpdate = 0
+set DoSegStats = 1
@@ segstats block @@
-# Compute segstats
-set statsfile = $outdir/stats/$gcabase.stats
-set ud = `UpdateNeeded $statsfile $aseg $norm`
-if($ud || $ForceUpdate) then
+# Compute segstats
+set statsfile = $outdir/stats/$gcabase.stats
+set ud = `UpdateNeeded $statsfile $aseg $norm`
+if($DoSegStats && ($ud || $ForceUpdate)) then
@@ overwrite guards @@
-# Check whether the outputs already exist
-if($ForceUpdate) then
+# Refuse to clobber existing outputs unless --force-update was given
+if(! $Overwrite) then
   if(-e $lta && ! $Overwrite) then
     echo "ERROR: $lta already exists"
     exit 1;
   endif
   ...
 endif
```

(With `Overwrite` set only by `--force-update`, the simplest correct
guard is `if(! $Overwrite)` around the block; the redundant inner
`&& ! $Overwrite` tests can then be dropped or left as-is.)

### Alternative Fixes Considered

Keep the guards under `if($ForceUpdate)` but invert their intent (warn
that outputs will be overwritten) instead of refusing. This documents
behaviour rather than preventing it. The minimal change above is
preferable because it makes the advertised refusal actually work.

## Workarounds (If Any)

- To genuinely skip segstats, comment out or guard the segstats block
  locally, or run only up to `mri_ca_label` — `--no-segstats` cannot be
  relied on.
- To avoid clobbering existing outputs, run `gca-apply` into a fresh
  `--o outdir`, or rely on the `UpdateNeeded` timestamp logic (do not
  pass `--force-update`, and ensure inputs are older than outputs).

> [!gap] Intended placement of the overwrite guards
> The guards may have been intended to live outside `if($ForceUpdate)`
> (so a normal run refuses to clobber and `--force-update` overrides),

> from `--force-update`. Either way the current code cannot refuse. A
> developer should confirm which semantics were intended before applying
> the fix. The `--no-segstats` no-op is unambiguous.
