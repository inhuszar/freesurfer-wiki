# [severity-2] [bug-00216] `createMorph` — bad input is accepted silently or crashes: missing `--template` with a `gcam` segfaults, unknown keywords and unreadable `--template`/`--subject` are skipped with exit 0, nested morphs lose their geometry, a missing mesh aborts

> [!bug] Synopsis
> [[createMorph]] does almost no input validation. (1) A `gcam` pair without `--template` dereferences a NULL `MRI*` and segfaults (exit 139). (2) An unrecognised or miscased transform keyword (for example `Affine`) only prints `unhandled transform type` and the program still writes an output and exits 0, possibly with an empty transform chain that [[applyMorph]] then evaluates as an uninitialised point flagged valid. (3) An unreadable `--template` or `--subject` is non-fatal and leaves a default, invalid 256-cubed geometry in the output. (4) A `morph` pair copies the nested file's transforms but not its fixed/moving geometries, so the default geometry silently changes the morph's meaning. (5) A missing `mesh` file throws an uncaught `const char*` (abort, exit 134). Each is a scripting hazard rather than a wrong result on correct input, hence severity 2.

## Affected Artefacts

- **Tool(s):** [[createMorph]]; the damaged `.tm3d` files are then consumed by [[applyMorph]] and [[exportGcam]].
- **Pipeline stage(s):** _N/A_ — the in-tree caller ([[trac-preproc]], [`scripts/trac-preproc:1763-1768`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-preproc#L1763-L1768)) passes a well-formed `--template`, `--subject`, `gcam` and `morph` and does not trigger any of the five cases.
- **FreeSurfer version(s):** confirmed in `8.2.0`; all five behaviours are present in the original 2008 import (commit `4b881dc775`, 2008-03-14, "source for createMorph and applyMorph").
- **Platforms:** all
- **Triggering configuration:** user or script errors: wrong or missing arguments, miscased keywords, missing files.

## Detailed Description

`main()` reads each `--in KEYWORD FILE` pair and dispatches on the keyword. The error handling is inconsistent:

| # | Input error | What the code does | Observed |
|---|-------------|--------------------|----------|
| 1 | `gcam` pair, no `--template` | `MRIread("")` returns NULL; `mri_template->width` is dereferenced ([`fem_elastic/fcreateMorph.cpp:149-150`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L149-L150), [`fem_elastic/fcreateMorph.cpp:167-169`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L167-L169)) | segfault, exit 139, no output |

| 3 | `--template`/`--subject` file unreadable | prints a message and continues ([`fem_elastic/fcreateMorph.cpp:83-102`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L83-L102)) | output written, exit 0, geometry = default (`valid = 0`, 256^3, 1 mm, LIA) |
| 4 | `morph` pair | copies only the transform list ([`fem_elastic/fcreateMorph.cpp:204-209`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L204-L209)) | nested file's fixed/moving geometries dropped |
| 5 | `mesh` pair, file missing | `TMesh::load` throws `const char*` ([`fem_elastic/mesh.h:342-343`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/mesh.h#L342-L343)); the `mesh` branch has no `catch` ([`fem_elastic/fcreateMorph.cpp:211-218`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L211-L218)) | `terminate called after throwing an instance of 'char const*'`, exit 134 |

Cases 2 to 4 are *silent*: they leave a well-formed `.tm3d` that downstream tools evaluate without complaint.

**Case 2, empty chain.** When the only keyword was unrecognised, the `.tm3d` contains the two geometry tags and no transform (176 bytes). `VolumeMorph::image` loops over an empty list and returns its local `ret` ([`fem_elastic/morph.cpp:1110-1127`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L1110-L1127)), a default-constructed `tCoords`, whose constructor sets the status to `cValid` and leaves the three coordinates uninitialised ([`fem_elastic/coords.h:167-172`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/coords.h#L167-L172)). `apply_transforms` therefore treats it as a valid point and goes on to use its undefined coordinates ([`fem_elastic/morph.cpp:817-848`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L817-L848)).

**Case 4, lost geometry.** `apply_transforms` builds its voxel-to-voxel matrices from the morph's stored fixed and moving geometries ([`fem_elastic/morph.cpp:729-758`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L729-L758)) without checking their `valid` flag. A `morph` pair drops the nested file's real geometries, so those matrices come from the constructor default. Because the transforms inside the nested chain were computed on the real grids, the output is silently shifted or rescaled.

### Expected Behaviour

Each case should end with a message on stderr and `exit(1)` before any output file is written, as already happens for a missing `affine`/`volume`/`gcam`/`morph` file and for an odd token count ([`fem_elastic/fcreateMorph.cpp:114-118`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L114-L118), [`fem_elastic/fcreateMorph.cpp:129-133`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L129-L133), [`fem_elastic/fcreateMorph.cpp:143-147`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fcreateMorph.cpp#L143-L147)). A `morph` pair should preserve the nested file's geometries unless `--template`/`--subject` override them.

### Observed Behaviour

All experiments used the installed 8.2.0 binaries on a synthetic 32x32x32, 8 mm template `tmpl.mgz` and an identity `ident.m3z` made with `mri_warp_convert --invox` (see [[00215]]).

1. `createMorph --out nt.tm3d --in gcam ident.m3z` printed `error: mri_read(): empty fname!`, the GCAM atlas/image sizes, and died with `Segmentation fault`, exit status 139; no `nt.tm3d` was written.
2. `createMorph --out unk.tm3d --template tmpl.mgz --subject tmpl.mgz --in Affine aff.txt` printed ` unhandled transform type Affine`, exit status 0, and wrote a 176-byte `unk.tm3d` (two 76-byte geometry tags, no transform record). `applyMorph --template tmpl.mgz --transform unk.tm3d vol tmpl.mgz out.mgz linear` then exited 0 and reported `Invalid voxels = 0`, `Valid = 32768`; the output volume was identically 0 in three repeated runs (the template has non-zero values everywhere), so a mistyped keyword yields a plausible-looking but empty result.
3. `createMorph --out ft.tm3d --template nonexist.mgz --subject tmpl.mgz --in affine aff.txt` printed ` Failed to open template mri nonexist.mgz` (plus an `MRIfree: null pointer` message), exit 0; the fixed-geometry tag of `ft.tm3d` has `valid = 0` and 256x256x256 at 1 mm, while the moving tag holds the real 32^3, 8 mm geometry.
4. Nested morph (see Reproducer): applying a morph that was re-wrapped without `--template`/`--subject` returned an image that is practically unshifted instead of shifted by 2 voxels.
5. `createMorph --out m.tm3d --template tmpl.mgz --subject tmpl.mgz --in mesh nonexist.mesh` printed `terminate called after throwing an instance of 'char const*'` and aborted with exit 134 (core dump); no output.

### Reproducer

Case 4 is the one that changes numerical results without any message. Files: `tmpl.mgz` (32^3, 8 mm, random intensities), `shiftvol.mgz` (same geometry, 3 frames; frame 0 is 2.0 everywhere, frames 1 and 2 are 0).

```bash
# A: morph with its real geometry (a +2 voxel shift in x)
createMorph --out A.tm3d --template tmpl.mgz --subject tmpl.mgz --in volume shiftvol.mgz
# B: re-wrap A by splicing it in, without repeating --template/--subject
createMorph --out B.tm3d --in morph A.tm3d
# C: same as B but repeating the geometry
createMorph --out C.tm3d --template tmpl.mgz --subject tmpl.mgz --in morph A.tm3d

for m in A B C; do
  applyMorph --template tmpl.mgz --transform $m.tm3d vol tmpl.mgz ${m}_applied.mgz linear
done
```

Observed: all three `createMorph` calls exit 0 with no warning. The fixed and moving geometry tags of `B.tm3d` have `valid = 0`, 256^3, 1 mm (those of `A.tm3d` and `C.tm3d` are the real 32^3, 8 mm geometry). `applyMorph` output for `A` and `C` equals `tmpl[i+2,j,k]` at 100 % of the voxels with `i < 30` (and reports `Valid = 30720`); the output for `B` equals the **unshifted** template at 99.8 % of voxels and reports `Valid = 32768`. (The default 1 mm geometry maps template voxel indices to default-grid indices eight times smaller than the field's own grid, so the 32-voxel field is looked up only near the origin of the default grid and gives zero displacement elsewhere.) Splicing a zero-field morph (a pure identity) hides the problem because both default geometries cancel; the shift field makes it visible.

## Root Cause

`createMorph` was written with a mix of `exit(1)` on I/O errors and "print and continue" on the rest. There is no final validation step: nothing verifies that the transform list is non-empty, that every keyword was understood, that `--template` is present when a `gcam` needs it, that a requested geometry could be read, or that the nested morph's geometries survive a splice. The error-handling paths for `mesh` rely on a `throw const char*` from the library that no handler in `main` catches.

## Impact

- **Wrong or empty morphs without a diagnostic** (cases 2-4): scripts that check only the exit status proceed with an empty or mis-geometried `.tm3d`. In the observed empty-chain case the result is an all-zero volume that `applyMorph` reports as fully valid.
- **Crashes** (cases 1 and 5) are loud but unhelpful (`Segmentation fault`, `terminate called ...`).
- **Reach.** The only in-tree caller supplies well-formed arguments, so the shipped TRACULA path does not trigger any case. The defects bite manual users and new scripts. Severity 2 (latent under typical, correct usage; user-input paths only).
- **Not a regression:** present since the initial 2008 import.

## Workarounds (If Any)

Check `createMorph`'s stderr for `unhandled transform type`, `Failed to open`, and verify the output with a quick `applyMorph` on a test volume. Always give `--template` and `--subject` explicitly, including when splicing a `morph`. Use lower-case keywords exactly as documented. Treat exit status 0 as insufficient.
