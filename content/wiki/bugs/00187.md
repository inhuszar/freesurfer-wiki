# [severity-3] [bug-00187] fsr-mergexopts — non-recon-all merge loop greps the literal 'recon-all' instead of the current command

> [!bug] Synopsis
> `fsr-mergexopts` merges expert-option (xopts) files into a single
> file, one line per command. It does this in two passes: a first loop
> that gathers options for the `recon-all` command, and a second loop
> that is supposed to gather options for every *other* command. Through
> a copy-paste error the second loop greps each input file for the
> literal string `recon-all` (exactly as the first loop does) instead of
> for the current command `$cmd`. As a result, expert options for any
> non-`recon-all` command (e.g. `mri_segment`, `mri_normalize`,
> `mris_make_surfaces`) are never picked up: the merged line for such a
> command is emitted with the wrong options (whatever was on the
> `recon-all` line, possibly empty) rather than that command's own
> options.

## Affected Artefacts

- **Tool(s):** [[fsr-mergexopts]]
- **Pipeline stage(s):** _N/A_ — utility for assembling expert-options
  files consumed by samseg-based recon-all runs via [[fsr-getxopts]].
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — purely shell control flow.
- **Triggering configuration:** any invocation
  (`fsr-mergexopts --x A.xopts --x B.xopts --o merged.xopts`) in which at
  least one input xopts file contains a line for a command other than
  `recon-all`. The first (recon-all) line is merged correctly; every
  non-`recon-all` line is merged from the wrong source.

## Detailed Description

An xopts file is a plain-text file with one line per command; the first
whitespace token is the command name and the remaining tokens are the
expert options to append for that command. `fsr-mergexopts` first builds
a sorted unique list of command names seen across all the input files
([`scripts/fsr-mergexopts:84`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-mergexopts#L84)),
then walks that list twice:

1. **recon-all first** ([`scripts/fsr-mergexopts:87-98`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-mergexopts#L87-L98)):
   skip every `$cmd` that is not `recon-all`, then for each input file
   grep the `recon-all` line and append tokens 2..N.
2. **everything else** ([`scripts/fsr-mergexopts:101-112`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-mergexopts#L101-L112)):
   skip `$cmd == recon-all`, then for each input file grep — and this is
   the defect — the **`recon-all`** line again, instead of the `$cmd`
   line.

The two inner `set tmp = ...` statements (file line 93 and file line
107) are byte-for-byte identical. The first is correct; the second
should reference `$cmd`.

### Expected Behaviour

For a command `C` other than `recon-all`, the merged output line should
be `C` followed by the concatenation, across all input xopts files, of
the options that each file lists for `C`. Example: if `A.xopts` contains
`mri_segment -wsizemm 5` and `B.xopts` contains `mri_segment -mprage`,
the merged file should contain `mri_segment -wsizemm 5 -mprage`.

### Observed Behaviour

The second loop greps `recon-all` in every input file regardless of
`$cmd`:

- If the input files contain a `recon-all` line, the non-`recon-all`
  command inherits `recon-all`'s options — e.g. the merged file gets
  `mri_segment <recon-all-options>`, which is wrong and may even be
  rejected downstream.
- If the input files contain no `recon-all` line, `$tmp` has fewer than
  2 tokens, the `if($#tmp < 2) continue` guard fires for every file, and
  the command is emitted with **no** options at all
  (`echo $cmd` with empty `$opts`), silently dropping the user's expert
  options for that command.

In both cases the per-command expert options the user supplied for any
non-`recon-all` command are lost.

### Reproducer

> [!gap] Reproducer not yet constructed
> A direct demonstration (not executed here because it requires building
> two valid xopts files that pass [[fsr-checkxopts]]):
>
> 1. `printf 'mri_segment -wsizemm 5\n' > A.xopts`
> 2. `printf 'mri_segment -mprage\n'    > B.xopts`
> 3. `fsr-mergexopts --x A.xopts --x B.xopts --o merged.xopts`
> 4. Inspect `merged.xopts`: the `mri_segment` line is emitted with no
>    options (because neither file has a `recon-all` line, so the grep
>    matches nothing and the `$#tmp < 2` guard skips both files),
>    instead of `mri_segment -wsizemm 5 -mprage`.

## Code Reference (Unambiguous)

- **File:** `scripts/fsr-mergexopts`
- **Function:** the two merge loops (no enclosing function — top-level
  script body)
- **Lines:** correct site `93`; defect site `107`
- **Commit:** `d932c45`

First loop (recon-all) — **correct**, greps `recon-all` because `$cmd`
is `recon-all` here:

```tcsh
# If recon-all exists as a command, do that first
foreach cmd ($cmdlist)
  if($cmd != recon-all) continue
  set opts = ()
  # Go through each xopts file and append the options in the order 
  # that the xopt files were given on the command line
  foreach xopts ($xoptslist)
    set tmp = `cat $xopts | grep recon-all | awk '{print $0}'`
    if($#tmp < 2) continue
    set opts = ($opts $tmp[2-$#tmp])
  end
  echo $cmd $opts | tee -a $outxopts
end
```

Second loop (non-recon-all) — **defect** at line 107: still greps the
literal `recon-all` instead of `$cmd`:

```tcsh
# Now do the non-recon-all commands
foreach cmd ($cmdlist)
  if($cmd == recon-all) continue
  set opts = ()
  # Go through each xopts file and append the options in the order 
  # that the xopt files were given on the command line
  foreach xopts ($xoptslist)
    set tmp = `cat $xopts | grep recon-all | awk '{print $0}'`   # ← should grep $cmd
    if($#tmp < 2) continue
    set opts = ($opts $tmp[2-$#tmp])
  end
  echo $cmd $opts | tee -a $outxopts
end
```

## Root Cause

Copy-paste. The non-`recon-all` loop was clearly cloned from the
recon-all loop, and the hard-coded `grep recon-all` was not changed to
`grep $cmd`. The two loops are otherwise identical apart from their
`if(... continue)` guard (`!=` vs `==`), which makes the unchanged grep
easy to miss on review.

## Impact

- The bug only fires when the user opts into building a merged
  expert-options file (a specific, non-default action), and only affects
  the non-`recon-all` lines — hence severity 3 rather than 4/5.
- When triggered it is silent: no error is printed, the merged file is
  written, and [[fsr-checkxopts]] passes (the emitted lines are
  well-formed). The user's expert options for the affected commands are
  quietly dropped (or replaced by recon-all's), so a downstream
  samseg-based recon-all run does not receive the customisation the user
  intended.
- The final [`fsr-checkxopts`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/fsr-mergexopts#L116)
  guard does not catch this because key-uniqueness is preserved; the
  values are simply wrong/empty.

## Recommended Fix

Change the grep target in the second loop from the literal `recon-all`
to the loop variable `$cmd`:

```diff
   foreach xopts ($xoptslist)
-    set tmp = `cat $xopts | grep recon-all | awk '{print $0}'`
+    set tmp = `cat $xopts | grep $cmd | awk '{print $0}'`
     if($#tmp < 2) continue
     set opts = ($opts $tmp[2-$#tmp])
   end
```

(The same change cannot be applied to the first loop — there it is
correct because `$cmd` is always `recon-all` in that branch — but using
`$cmd` there too would make the two loops identical and remove the trap.)

### Alternative Fixes Considered

Collapse the two loops into a single loop over `$cmdlist` that greps
`$cmd` and emits each command (recon-all naturally sorts among the
others; the "recon-all first" ordering is cosmetic for an expert-options
file). This removes the duplicated code that caused the bug, at the cost
of losing the deliberate recon-all-first ordering. The minimal one-token
fix above is sufficient.

> [!gap] Anchoring of the grep
> Both loops use an unanchored `grep $cmd` / `grep recon-all`, which can
> match a command name appearing as a substring of another command or
> inside an option value. The fix above preserves the existing
> (unanchored) behaviour; tightening to `grep "^$cmd "` would be a
> separate hardening change and is not required to resolve this defect.

## Workarounds (If Any)

Until patched, only merge xopts files whose sole command is `recon-all`,
or assemble the merged expert-options file by hand for any non-recon-all
command. There is no flag that changes the grep target.
