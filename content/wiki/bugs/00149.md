# [severity-3] [bug-00149] `mri_segment -min-wm-mask <vol>` is non-functional — both compounded defects (no-op binarization + swapped function args) silently nullify the feature

> [!bug] Synopsis
> Two compounded defects render the `-min-wm-mask <vol>` option a no-op:
>
> **Defect A — no-op binarization at `:629-630`** (post-load):
>
> ```cpp
> /* mri_segment/mri_segment.cpp:621-635 */
> else if (strcmp(option, "min-wm-mask")==0){
>   // -min-wm-mask pathtomri
>   MinWMMask = MRIread(argv[2]);
>   if(MinWMMask == NULL) exit(1);
>   for(int c=0; c < MinWMMask->width; c++){
>     for(int r=0; r < MinWMMask->height; r++){
>       for(int s=0; s < MinWMMask->depth; s++){
>         int m = MRIgetVoxVal(MinWMMask,c,r,s,0);
>         if(IS_WM(m) || IS_HYPO(m)) MRIsetVoxVal(MinWMMask,c,r,s,0, 1);
>         else                       MRIsetVoxVal(MinWMMask,c,r,s,0, 1);  /* :630 — should be 0 */
>       }
>     }
>   }
>   nargs = 1 ;
> }
> ```
>
> Both `if` and `else` branches set the voxel to `1`. The intent (per the surrounding loop and the option name) is to **binarize**: WM-class / Hypo voxels → 1, all others → 0. As written, every voxel is set to 1 regardless of its label — the binarization is a no-op and the resulting "mask" is uniformly 1 everywhere.
>
> **Defect B — swapped function arguments at `:217, :286`**:
>
> ```cpp
> /* mri_segment/mri_segment.cpp:217 */
> mri_tmp = MRIintensitySegmentation(mri_src, NULL, MinWMMask, wm_low, wm_hi, gray_hi);
> /* mri_segment/mri_segment.cpp:286 */
> mri_tmp = MRIintensitySegmentation(mri_src, NULL, MinWMMask, wm_low, wm_hi, gray_hi);
> ```
>
> The callee's signature ([`utils/mripolv.cpp:3603`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mripolv.cpp#L3603)):
>
> ```cpp
> MRI *MRIintensitySegmentation(MRI *mri_src, MRI *MinWMMask, MRI *mri_labeled, float wm_low, float wm_hi, float gray_hi)
> {
>   …
>   for (z = 0; z < depth; z++) {
>     for (y = 0; y < height; y++) {
>       for (x = 0; x < width; x++) {
>         if(MinWMMask){                                /* :3619 — protect WM voxels */
>           double m = MRIgetVoxVal(MinWMMask,x,y,z,0);
>           if(m>0.5){
>             MRIsetVoxVal(mri_labeled, x, y, z, 0, MRI_WHITE);
>             nmask++;
>             nwhite++;
>           }
>           continue;                                    /* skip the val-threshold path */
>         }
>         val = MRIgetVoxVal(mri_src, x, y, z, 0);
>         …
>       }
>     }
>   }
>   …
>   return (mri_labeled);
> }
> ```
>
> The intended call is `MRIintensitySegmentation(mri_src, MinWMMask /* arg 2 */, NULL /* arg 3 = labeled */, …)` — pass the user's `MinWMMask` to **arg 2** (the `MinWMMask` parameter), let the function allocate a fresh `mri_labeled`. The actual call passes `NULL` to arg 2 and `MinWMMask` to arg 3, which means:
>
> 1. The `if(MinWMMask)` branch at the callee's `:3619` is **never** entered (the parameter is NULL).
> 2. The user's `MinWMMask` volume is **used as the output** `mri_labeled` — it is overwritten by the intensity-threshold segmentation (`MRI_NOT_WHITE`, `MRI_AMBIGUOUS`, `MRI_WHITE` codes) at `:3641`. The user's mask is destroyed.
>
> Combined, the option is fully silent and does nothing of what it promises. The `MRIintensitySegmentation` function's protect-WM behaviour is bypassed, and `mri_tmp` is assigned the trashed `MinWMMask` pointer (which still contains valid intensity-segmentation data, so downstream code keeps working — just without the `MinWMMask` protection the user asked for).

## Affected Artefacts

- **Tool(s):** [[mri_segment]]
- **Pipeline stage(s):** _not on default `recon-all`_; `mri_segment` is invoked by `recon-all` at `scripts/recon-all:3322` but without `-min-wm-mask` (the recon-all default invocation is `mri_segment -wsizemm $MriSegWsizemm`). The `-min-wm-mask` flag is documented in the option parser at `:621` but does not appear in any in-tree script or recon-all configuration.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`; earliest known: _unknown_.
- **Platforms:** all.
- **Triggering configuration:** every `mri_segment -min-wm-mask <vol>` invocation.

## Detailed Description

`mri_segment` is the FreeSurfer tool that produces `wm.seg.mgz` from the bias-corrected T1 (`norm.mgz`). The `-min-wm-mask <vol>` option was added to let the user supply a "minimal WM mask" — a binary volume marking voxels that must be classified as white matter in the output, overriding the intensity-threshold logic. This is useful for fixing systematic mis-classifications (e.g., subcortical-WM hypointensities that the histogram-based segmentation misses).

Two compounded defects make the option a complete no-op:

### Defect A — Binarization is a no-op

The option handler at `:621-635` reads the supplied volume, then loops over all voxels with the apparent intent of binarizing: WM and HYPO labels → 1, everything else → 0. But both `if` and `else` branches set the voxel to `1`:

```cpp
if(IS_WM(m) || IS_HYPO(m)) MRIsetVoxVal(MinWMMask,c,r,s,0, 1);
else                       MRIsetVoxVal(MinWMMask,c,r,s,0, 1);
```

After this loop, `MinWMMask` is uniformly `1` everywhere, regardless of what label was in the input. The mask carries no information.

This is a textbook copy-paste-and-edit bug: the developer wrote the `if` branch, copied it to the `else`, then forgot to change `1` to `0`.

### Defect B — Swapped function arguments

`MRIintensitySegmentation` ([`utils/mripolv.cpp:3603`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mripolv.cpp#L3603)) has the signature `(mri_src, MinWMMask, mri_labeled, wm_low, wm_hi, gray_hi)`. The caller at `:217` and `:286` passes:

| Caller arg position | Caller value | Callee param |
|---|---|---|
| 1 | `mri_src` | `mri_src` ✓ |
| 2 | `NULL` | `MinWMMask` ✗ (should be the loaded `MinWMMask`) |
| 3 | `MinWMMask` (the local var) | `mri_labeled` ✗ (should be `NULL`, so the callee allocates a fresh output) |

Consequences:

1. `if(MinWMMask)` at the callee's `:3619` is never entered (parameter is `NULL`); the WM-protection branch is dead.
2. The user's `MinWMMask` is used as `mri_labeled` — overwritten with `MRI_NOT_WHITE` / `MRI_AMBIGUOUS` / `MRI_WHITE` codes. The original mask data is destroyed.
3. `mri_tmp` (the return value) ends up pointing to the same memory as `MinWMMask`. From this point on, the variable `MinWMMask` no longer holds the user's mask.

### Expected Behaviour

Two separate fixes are needed:

1. **Binarize correctly** at `:629-630`: `if (IS_WM(m) || IS_HYPO(m)) → 1; else → 0`.
2. **Pass `MinWMMask` to the correct argument** at `:217, :286`: `MRIintensitySegmentation(mri_src, MinWMMask, NULL, wm_low, wm_hi, gray_hi)`.

With both fixes, the `if (MinWMMask)` branch at `MRIintensitySegmentation:3619` would fire, setting every mask=1 voxel to `MRI_WHITE` in the output segmentation, achieving the documented behaviour.

### Observed Behaviour

The `-min-wm-mask <vol>` option silently does nothing. `mri_segment` runs as if the flag were never passed, except that:
- The user's supplied volume is read, its contents trashed in memory (defect A), and then used as scratch storage for the intensity segmentation (defect B).
- The expected WM protection never happens; mis-classifications that the user hoped to fix remain mis-classified.

### Reproducer

```bash

# Take an aseg.mgz where some hippocampus voxels are mis-labelled as WM
```

## Root Cause

Two independent developer errors:

- **Defect A** is a classic copy-paste-and-edit slip: the developer wrote the `if` branch with `1`, copied it to the `else` to handle the negative case, but forgot to change the value to `0`. Editor auto-completion / autocorrect can easily introduce this kind of typo.
- **Defect B** is a swapped-args bug. The developer added the `MinWMMask` argument to `MRIintensitySegmentation`'s signature at some point but did not update the two existing call sites consistently. The compiler accepts the call because all three argument positions are `MRI *` — no type-system protection against the swap.

The fact that both defects exist in the same option-handling code path suggests that `-min-wm-mask` was added but never actually run through a regression test that would have caught either bug.

## Impact

- **`-min-wm-mask` does nothing.** Every user who has ever invoked `mri_segment -min-wm-mask <vol>` got the same `wm.seg.mgz` they would have gotten without the flag.
- **The user's supplied mask is destroyed in memory.** The `MinWMMask` variable ends up holding the intensity-segmentation output, not the user's mask. (The on-disk file is not touched.)
- **No `recon-all` impact.** `recon-all` does not pass `-min-wm-mask` on any code path.
- **Confidence-shaking.** Anyone who has used `-min-wm-mask` to "fix" a mis-classification has been silently misled into believing the fix took effect.

## Recommended Fix

Two-part patch.

### Fix A — Defect A (binarization)


### Fix B — Defect B (swapped args at `:217` and `:286`)


Both call sites at `:217` and `:286` need the same change.

After both fixes:

- The user's mask is correctly binarized at load time.
- The mask is passed as the `MinWMMask` parameter to `MRIintensitySegmentation`.
- Inside the callee, the `if(MinWMMask)` branch at `:3619` fires and sets the corresponding output voxels to `MRI_WHITE`.
- The user's mask volume is no longer overwritten (the callee allocates fresh `mri_labeled` via `MRIclone(mri_src, NULL)` when arg 3 is NULL).

## Workarounds (If Any)

- **Don't rely on `-min-wm-mask`.** Until both defects are patched, the option is a no-op; nothing it claims to do happens.
- **Manual post-edit.** Run `mri_segment` without the flag, then patch the output `wm.seg.mgz` with `mri_mask` / `mri_binarize` to manually set WM voxels in the desired region.
