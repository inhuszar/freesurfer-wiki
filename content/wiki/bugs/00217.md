# [severity-2] [bug-00217] `DeltaTransform3d::doOwnImg` — validity mask is sampled trilinearly although the comment says nearest neighbour; any point with one valid neighbour is accepted and its displacement is blended with the zeros stored at invalid voxels

> [!bug] Synopsis
> `gmp::DeltaTransform3d` (the dense `field|` transform of a `.tm3d`) decides whether a point is valid by sampling its `uchar` validity mask with `m_interpolation`, which defaults to `SAMPLE_TRILINEAR`, although the code comment says "do this on a nearest neighbor method". A fractional point is accepted as long as **any** of the eight surrounding mask voxels is non-zero, and the displacement is then interpolated between valid voxels and the zeros that [[surf2vol]] stores at invalid ones. Along the boundary of the valid region the morph is therefore not marked invalid where it should be, and the displacement is pulled toward the identity over a one-voxel rim.

## Affected Artefacts

- **Tool(s):** [[surf2vol]] (its `-compress` mode evaluates a masked delta transform at every FEM step), [[exportGcam]] and [[applyMorph]] (both evaluate the saved `.tm3d`), hence the CVS registration of [[mri_cvs_register]], which calls `surf2vol -compress` ([`mri_cvs_register/mri_cvs_register:391`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_cvs_register/mri_cvs_register#L391)) and then `exportGcam`.
- **Pipeline stage(s):** _N/A_ (the effect lies in a one-voxel boundary rim, mostly outside the brain).
- **FreeSurfer version(s):** confirmed in `8.2.0`; present in the original 2008 import (commit `4b881dc775`, 2008-03-14).
- **Platforms:** all
- **Triggering configuration:** any `field|` transform that carries a mask, evaluated at a non-integer point. Masks are written by [[surf2vol]] `-compress` ([`fem_elastic/fsurf2vol.cpp:568-573`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L568-L573)); [[createMorph]] never attaches one (see [[00215]]), so `createMorph`-built delta fields are not affected.

## Detailed Description

`FemTransform3d::convert_to_delta()` rasterises a FEM mesh into a 256^3 3-frame float field plus a `uchar` mask: for every voxel the mesh map is evaluated, and if it is invalid the mask is 0 and the field is left at its zero initialisation; otherwise the mask is 1 and the field holds the displacement ([`fem_elastic/morph.cpp:603-653`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L603-L653)). `DeltaTransform3d::doOwnImg()` is the evaluator. It first samples the mask, returning an invalid point when the mask value is 0, and then samples the three displacement frames and adds them to the point ([`fem_elastic/morph.cpp:414-442`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L414-L442)).

The comment says the mask is sampled with a nearest-neighbour method, but the call passes the member `m_interpolation`, which the constructor sets to `SAMPLE_TRILINEAR` ([`fem_elastic/morph.cpp:403-406`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L403-L406)). The member is public ([`fem_elastic/morph.h:199`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.h#L199)) but never assigned anywhere else, not serialised, and no tool exposes it, so every transform loaded from disk uses trilinear sampling too. (The sibling class `DenseDisplacementField` does it the intended way: it rounds the interpolated mask, `floor(value + .5) != 1`, [`fem_elastic/morph.cpp:385-389`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L385-L389).)

For a 0/1 mask, trilinear interpolation returns the weighted fraction of valid corner voxels: it is non-zero as soon as one of the eight corners is valid. The test `if ( !val )` therefore accepts a point whose nearest voxel is invalid, whenever it lies within one voxel of a valid one. Two effects follow:

1. **Validity region too large by one voxel.** Points that should be invalid (outside the mesh, or inside an inverted element that the untangler could not repair) are reported valid.
2. **Displacement shrunk on the rim.** The three displacement frames are then trilinearly interpolated using the same corners, including the invalid ones, whose stored value is 0 (nothing was written there). At the rim the displacement is `w · d_valid + (1 − w) · 0`, a partial displacement, not the displacement of any real node.

### Expected Behaviour

The mask should be sampled by nearest neighbour (as the comment says): a point is valid if and only if the nearest voxel's mask is 1, as `DenseDisplacementField` does.

### Observed Behaviour

Silent; no warning. Points in the boundary rim are returned as valid with a damped displacement instead of being flagged invalid.

### Reproducer

`createMorph` cannot attach a mask, so a masked field is built by patching one record of a `.tm3d`. All files are synthetic (32x32x32, 8 mm, same geometry as `tmpl.mgz`; `ramp.mgz` holds the value `100 + i` at voxel `i` along the first axis; `maskfield.mgz` has 3 frames with frame 0 equal to 5.0 for `i <= 3` and 0 elsewhere, mimicking the zeros that `convert_to_delta` leaves at invalid voxels).

```bash
echo "1 0 0 0 1 0 0 0 1 0.7 0 0" > shift07.txt        # affine: x' = x + 0.7
createMorph --out mk0.tm3d --template tmpl.mgz --subject tmpl.mgz \
            --in affine shift07.txt volume maskfield.mgz

# patch the 'field|' record: set the mask flag to 1 and append a mask that is 1 for x index 0..3
python3 - <<'EOF'
import struct, zlib, numpy as np
b = open('mk0.tm3d','rb').read(); p = 0; out = bytearray()
while p < len(b):
    tag, = struct.unpack_from('<i', b, p); ln, = struct.unpack_from('<q', b, p+4); d = b[p+12:p+12+ln]; p += 12+ln
    if tag == 3:
        raw = zlib.decompress(d); n, = struct.unpack_from('<I', raw, 0)
        if raw[4:4+n] == b'field|':
            q = 4+n+1; w,h,dd = struct.unpack_from('<3i', raw, q); q += 12 + 3*w*h*dd*4
            mask = np.zeros((dd,h,w), np.uint8); mask[:,:,:4] = 1
            raw = raw[:q] + b'\x01' + mask.tobytes()
        d = zlib.compress(raw, 9)
    out += struct.pack('<iq', tag, len(d)) + d
open('mk1.tm3d','wb').write(out)
EOF

applyMorph --template tmpl.mgz --transform mk1.tm3d vol ramp.mgz mk1_applied.mgz linear
applyMorph --template tmpl.mgz --transform mk0.tm3d vol ramp.mgz mk0_applied.mgz linear
```

Chain evaluation per output voxel `i`: `pt.x = i + 0.7` (affine), then the masked field. By the documented intent (nearest-neighbour mask), `i = 0, 1, 2` are valid (nearest mask voxel `i+1 <= 3`) and `i = 3` is invalid (nearest voxel 4 has mask 0).

Observed, `ramp` sampled along x at fixed (j,k):

| `i` | 0 | 1 | 2 | 3 | 4 | 5 |
|-----|---|---|---|---|---|---|
| masked chain (`mk1`) | 105.7 | 106.7 | 107.7 | **105.2** | 0 | 0 |
| same chain without mask (`mk0`) | 105.7 | 106.7 | 107.7 | 105.2 | 104.7 | 105.7 |

`applyMorph` reported `Valid = 4096`, `Invalid voxels = 28672` for `mk1` (4 x-indices x 32 x 32 valid; with nearest-neighbour sampling it would be 3 x 32 x 32 = 3072). At `i = 3` the point `3.7` has trilinear mask weight `0.3 · 1 + 0.7 · 0 = 0.3`, which is non-zero, so it is accepted; its displacement is `0.3 · 5 + 0.7 · 0 = 1.5` instead of 5 (or "invalid"), and the output is `ramp(3.7 + 1.5 = 5.2) = 105.2`. The same voxel with the correct rule would be left at 0.

## Root Cause

The mask and the displacement frames share one interpolation mode, `m_interpolation`, and the constructor default is trilinear ([`fem_elastic/morph.cpp:404`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L404)). The author intended a separate nearest-neighbour lookup for the mask (comment at [`fem_elastic/morph.cpp:421`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L421)) but reused the field's mode in the call at [`fem_elastic/morph.cpp:424`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/morph.cpp#L424). `MRIsampleVolumeFrameType` falls back to nearest only when the three coordinates are exact integers, so the error is invisible at grid points and only appears at fractional ones, which is the normal case for a chain that starts with an affine step.

## Impact

- **What is affected.** Points within one voxel of the boundary of the valid region of a masked delta field: the outer rim of the FEM mesh domain and unresolved folded elements. In a CVS run this is evaluated at every FEM step when `surf2vol -compress` rebuilds the boundary conditions, and again when `exportGcam` / `applyMorph` evaluate the saved morph.
- **Magnitude.** At most a one-voxel band; the displacement there is damped, not wrong in direction. The band lies mostly outside the brain, so the scientific effect is expected to be small, but it was not quantified on real data.
- **Why severity 2.** The CVS default path is reached, but the effect is confined to a boundary rim with little consequence for the primary results, and fits the schema's "latent / boundary" tier. It is not a regression (2008 import).

## Recommended Fix

Sample the mask with nearest neighbour explicitly:

```diff
--- a/fem_elastic/morph.cpp
+++ b/fem_elastic/morph.cpp
@@ DeltaTransform3d::doOwnImg
   // sample the mask first - do this on a nearest neighbor method
   if ( m_mask )
   {
-    MRIsampleVolumeFrameType( m_mask, pt(0), pt(1), pt(2), 0, m_interpolation, &val );
+    MRIsampleVolumeFrameType( m_mask, pt(0), pt(1), pt(2), 0, SAMPLE_NEAREST, &val );
     if ( !val )
```

Tests: the `mk1` chain above must report `Valid = 3072` and leave output voxel `i = 3` at 0; a `surf2vol -compress` run on `cvs_avg35` (fixed = moving) should be compared before and after to quantify the effect on the exported `.m3z`.

### Alternative Fixes Considered

Use the rounding rule of `DenseDisplacementField` (`std::floor(value + .5) != 1` on a trilinearly interpolated mask). It gives the same validity region as nearest neighbour to within ties and keeps one code path for both classes. Interpolating the displacement only from valid corners (renormalising the weights, as `MRIsampleVolumeFrameMasked` does, [`utils/mri.cpp:9164`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/mri.cpp#L9164)) would additionally remove the damping at the rim, but changes numerical results more and needs validation.

## Workarounds (If Any)

None from the command line: the interpolation mode is not stored in the file and no option reaches it.
