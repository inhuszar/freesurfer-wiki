# [severity-2] [bug-00053] `MRIaddExtraCerebralCSF` — UCHAR guard misses the `out == NULL` path

> [!bug] Synopsis
> `MRIaddExtraCerebralCSF`
> ([`utils/mri2.cpp:4568-4610`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L4568-L4610))
> writes the `CSF_ExtraCerebral = 257`
> ([`include/cma.h:227`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/cma.h#L227))
> label into voxels that fall outside the seg but
> within `nDil` dilations of it. The guard at
> [`:4573`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L4573):
>
> ```cpp
> if (seg->type == MRI_UCHAR && out != NULL && out->type == MRI_UCHAR) {
>   printf("ERROR: MRIaddExtraCerebralCSF(): passed seg/out is of type UCHAR\n");
>   return (NULL);
> }
> out = MRIcopy(seg, out);
> ```
>
> The guard only fires when *both* `out != NULL` and
> `out->type == MRI_UCHAR`. The `out == NULL` path
> escapes the check; `MRIcopy(seg, NULL)` then allocates
> `out` with `seg`'s type. If `seg->type == MRI_UCHAR`,
> `out` becomes UCHAR. The subsequent
> `MRIsetVoxVal(out, c, r, s, 0, CSF_ExtraCerebral)`
> writes 257 into a UCHAR, which saturates / wraps to a
> small value (1 in the wrap case) — silently corrupting
> the segmentation.
>
> Defect is **latent** for the in-tree callers: both
> [`mri_compute_volume_fractions.cpp:142`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_fractions.cpp#L142)
> and
> [`mri_rbvpvc/mri_rbvpvc.c:1837`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_rbvpvc/mri_rbvpvc.c#L1837)
> call as `MRIaddExtraCerebralCSF(aseg, ndil, aseg)` —
> in-place — and `mri_compute_volume_fractions.cpp`
> explicitly converts `aseg` to `MRI_INT` at
> [`:131`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_fractions.cpp#L131)
> before calling. The bug only fires for a caller that
> passes `(MRI_UCHAR seg, ndil, NULL)`.

## Affected Artefacts

- **Sole tools that call:**
  [[mri_compute_volume_fractions]] and `mri_rbvpvc`
  (the older RBV PVC binary). Both pass `out == seg`
  in-place.
- **Pipeline stage(s):** none in default `recon-all`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.
- **Triggering configuration:** caller passes a UCHAR
  `seg` and `out == NULL`. No in-tree caller does this.

## Detailed Description

```cpp
MRI *MRIaddExtraCerebralCSF(MRI *seg, int nDil, MRI *out)
{
  ...
  if (seg->type == MRI_UCHAR && out != NULL && out->type == MRI_UCHAR) {  /* :4573 */
    printf("ERROR: MRIaddExtraCerebralCSF(): passed seg/out is of type UCHAR\n");
    return (NULL);
  }
  out = MRIcopy(seg, out);                                                /* :4577 */
  ...
  for (...) {
    ...
    MRIsetVoxVal(out, c, r, s, 0, CSF_ExtraCerebral);                     /* :4602 */
  }
}
```

`MRIcopy(seg, NULL)` at `:4577` clones `seg`'s type.
With UCHAR `seg`, `out` becomes UCHAR.
`MRIsetVoxVal(out, c, r, s, 0, 257)` then writes
`(unsigned char)257` — wraps to `1`, the same
numerical value as
`Left_Cerebral_White_Matter`. Voxels that should be
`CSF_ExtraCerebral` are silently mislabelled as WM.

The correct guard should also fire when `out == NULL`
and `seg->type == MRI_UCHAR` (since the function would
then implicitly produce a UCHAR `out`).

## Root Cause

The guard was written to protect against the explicit
in-place case but did not consider the implicit UCHAR
propagation through `MRIcopy(seg, NULL)`.

## Impact

- **Currently latent.** No in-tree caller exercises the
  `(MRI_UCHAR seg, NULL)` form.
- **If exercised:** voxels meant to be
  `CSF_ExtraCerebral (257)` are silently mislabelled
  due to UCHAR truncation / wrap. With C's
  `(unsigned char)257 = 1`, the affected voxels become
  label 1 (`Left_Cerebral_White_Matter`). Downstream
  PVF and RBV computations would treat these voxels as
  white matter rather than extra-cerebral CSF.

## Recommended Fix

```diff
--- a/utils/mri2.cpp
+++ b/utils/mri2.cpp
@@ -4570,7 +4570,9 @@ MRI *MRIaddExtraCerebralCSF(MRI *seg, int nDil, MRI *out)
   int c, r, s, n, nxcsf;
   MRI *mask = NULL;

-  if (seg->type == MRI_UCHAR && out != NULL && out->type == MRI_UCHAR) {
+  /* Guard against UCHAR output: CSF_ExtraCerebral = 257 does not fit. */
+  if ((seg->type == MRI_UCHAR && out == NULL) ||
+      (out != NULL && out->type == MRI_UCHAR)) {
     printf("ERROR: MRIaddExtraCerebralCSF(): passed seg/out is of type UCHAR\n");
     return (NULL);
   }
```

A stronger fix would replace the error with an
automatic upcast: when `seg` is UCHAR and `out` is
NULL, allocate `out` as `MRI_INT` instead. That makes
the function safe for any caller.

## Workarounds

Convert `seg` to `MRI_INT` (or any non-UCHAR integer
type) before calling (which `mri_compute_volume_fractions`
already does at
[`:131`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_compute_volume_fractions/mri_compute_volume_fractions.cpp#L131)).

## Provenance and Discovery

- **Discovered:** 2026-04-30 by agent (CSF-ExtraCerebral
  type audit; `CSF_ExtraCerebral=257` flagged as a
  value that cannot fit in UCHAR).
- **Evidence:** the guard at `:4573` checks both `seg`
  and `out` types but only when both are non-NULL on
  the `out` side; `MRIcopy(seg, NULL)` at `:4577`
  propagates the UCHAR type silently.
