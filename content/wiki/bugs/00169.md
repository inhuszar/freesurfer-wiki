# [severity-3] [bug-00169] talsegprob — duplicate `case "--seg"` shadows the label-number path, breaking `--seg <N>`

> [!bug] Synopsis
> `scripts/talsegprob` has **two** `case "--seg":` labels in its argument
> `switch`. The first (aliased with `--segmentation`) sets `segmentation =
> $argv[1]` — i.e. it treats the argument as a segmentation **file name**.
> The second, later one is the documented label-number path: it appends
> the argument to `SegNos`. In a tcsh `switch`, the first matching `case`
> wins and `breaksw` exits the block, so `--seg <N>` always hits the
> first label and the second is dead code. As a result the tool's core
> feature — selecting which label numbers to map (`--seg 12`,
> `--seg 12 --seg 51`, exactly as the help text describes) — is
> unreachable. Worse, because `--seg <N>` quietly overwrites
> `segmentation` and leaves `SegNos` empty, `check_params` then aborts
> with `ERROR: need to specify a segmentation or --vote`.

## Affected Artefacts

- **Tool(s):** [[talsegprob]] — a standalone tcsh tool that builds a
  per-voxel probability map (in MNI305/fsaverage space) of how often a
  chosen segmentation label appears across a set of subjects.
- **Pipeline stage(s):** _N/A_ — not invoked by [[wiki/pipelines/recon-all|recon-all]]; run by
  hand.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — purely shell argument parsing.
- **Triggering configuration:** any use of `--seg <labelnumber>` (the
  primary, documented way to drive the tool). The `--left-hippo`,
  `--right-hippo`, and `--hippo` shortcuts append to `SegNos` directly
  and are unaffected, as is `--vote` mode.

## Detailed Description

`talsegprob` distinguishes two concepts:

- `segmentation` — the **name** of the segmentation volume to read
  (`subject/mri/$segmentation.mgz`), default `aseg`; intended to be set
  by `--segmentation <file>`.
- `SegNos` — the list of **label numbers** to extract from that volume;
  intended to be set by `--seg <N>` (repeatable).

The `switch` block contains both of these `case` labels, but `--seg`
appears twice:

1. **First `--seg`**, grouped with `--segmentation`
   ([`scripts/talsegprob:264-273`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L264-L273)),
   executes `set segmentation = $argv[1]`.
2. **Second `--seg`**
   ([`scripts/talsegprob:285-293`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L285-L293)),
   executes `set SegNos = ($SegNos $argv[1])`.

tcsh evaluates `case` labels top-to-bottom and stops at the first match;
the `breaksw` at
[`scripts/talsegprob:273`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L273)
leaves the switch. So `--seg` is **always** handled by site (1) and never
by site (2). Site (2) is unreachable dead code.

The help text is unambiguous that `--seg <N>` is the label-number path:
[`scripts/talsegprob:447-448`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L447-L448)
("`--seg segno : segmentation number`" / "`<--seg segno : 2nd
segmentation number>`") and the BEGINHELP block at
[`scripts/talsegprob:504-508`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L504-L508)
("left putamen would be specified with `--seg 12`. The left and right
putamen would be specified with `--seg 12 --seg 51`"). The
**file-name** path is separately documented as `--segmentation segfile`
([`scripts/talsegprob:452`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L452)).
The duplicate label collapses the two distinct flags into one and keeps
only the wrong behaviour.

### Expected Behaviour

`--seg 12` should append `12` to `SegNos`; `--seg 12 --seg 51` should
build `SegNos = (12 51)`. The tool should then binarise the segmentation
to those labels and produce the probability map.

### Observed Behaviour

`--seg 12` sets `segmentation = 12` (so the tool would look for
`subject/mri/12.mgz`) and leaves `SegNos` empty. `check_params`
([`scripts/talsegprob:412-415`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L412-L415))
then tests `$#SegNos == 0 && ! $DoVote`, which is true, and the script
exits:

```
ERROR: need to specify a segmentation or --vote
```

The documented invocation is therefore not merely degraded — it fails
outright (unless the user also supplies `--vote`, or uses one of the
`--hippo` shortcuts, which bypass `--seg`).

### Reproducer

```bash
export SUBJECTS_DIR=/tmp/tsp_repro_sd
rm -rf $SUBJECTS_DIR
mkdir -p $SUBJECTS_DIR/subjA/mri

talsegprob --subjects subjA --seg 12 --p /tmp/out.mgz
# → ERROR: need to specify a segmentation or --vote
```

Observed (v8.2.0): the run aborts with `ERROR: need to specify a
segmentation or --vote`, proving `--seg 12` did **not** populate
`SegNos` (it set `segmentation` instead). Verified 2026-06-09 against
`/usr/local/freesurfer/8.2.0/bin/talsegprob`.

## Root Cause

A duplicated `case` label. The first `case "--seg"` was almost certainly
meant to be only `case "--segmentation"` (the file-name flag); somebody
either added `--seg` as an alias of `--segmentation` by mistake, or
copy-pasted the case and forgot to delete the spurious `case "--seg":`
line. Because tcsh `switch` honours the first matching label and the
block ends with `breaksw`, the genuine `--seg`→`SegNos` case below is
permanently shadowed.

## Impact

- **Primary functionality broken behind a flag.** `--seg <N>` is the
  documented, principal way to select which label(s) to map. With the
  duplicate case, every `--seg <N>` invocation either fails immediately
  (`need to specify a segmentation or --vote`) or — if the user also
  passes `--vote` — silently looks for a non-existent segmentation file
  named after the number (`subject/mri/<N>.mgz`). Either way the user
  cannot select arbitrary labels via `--seg`.
- **Workable subset remains.** `--vote` with the default `aseg`, and the
  `--hippo` / `--left-hippo` / `--right-hippo` shortcuts (which append to
  `SegNos` directly and never touch `--seg`), still work. So the tool is
  not wholly dead.
- **Severity 3 (medium).** This is a standalone auxiliary tool, not a
  default pipeline, and the defect is gated behind a specific flag
  (`--seg`); the default-ish `--vote`/`--hippo` paths are unaffected. Per
  the rubric, a defect gated behind a specific flag/mode is medium.

## Recommended Fix

Remove the spurious `case "--seg":` from the `--segmentation` group so
that `--seg` falls through to the label-number case:

```diff
-    case "--seg":
     case "--segmentation":
       if ( $getting_subjects ) then
         # got em all, from --subjects variable arg loop
         set getting_subjects = 0;
         shift;
       endif
       if ( $#argv == 0) goto arg1err;
       set segmentation = $argv[1]; shift;
       breaksw
```

After this change, `--seg <N>` reaches the second case at
[`scripts/talsegprob:285`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/talsegprob#L285)
and appends to `SegNos`, while `--segmentation <file>` continues to set
the file name. Both documented behaviours are then realised.

### Alternative Fixes Considered

Merge the two cases into one that disambiguates numeric vs. non-numeric
arguments. This is fragile (it second-guesses the user) and unnecessary,
because the script already provides a separate `--segmentation` flag for
the file-name case. The single-line deletion above is the correct fix.

## Workarounds (If Any)

- Use the built-in shortcuts when applicable: `--hippo` (17 and 53),
  `--left-hippo` (17), `--right-hippo` (53), which populate `SegNos`
  without `--seg`.
- For other labels, patch the script locally (delete the spurious
  `case "--seg":`), or pre-build the binary label volume and feed it via
  `--vote` against a custom `--segmentation` file.
