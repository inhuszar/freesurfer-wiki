# [severity-2] [bug-00105] `MRIsampleVolumeFrameType` default-case `ErrorReturn` is unreachable; unknown interp types silently fall back to nearest-neighbour

> [!bug] Synopsis
> The interpolation-dispatch switch in
> `MRIsampleVolumeFrameType`
> ([`utils/mri.cpp:9442-9461`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L9442-L9461))
> ends with a `default:` case whose body is
>
> ```cpp
> default:
>   break;                                              /* :9456 — exits switch */
>   ErrorReturn(ERROR_UNSUPPORTED,
>               (ERROR_UNSUPPORTED,
>                "MRIsampleVolumeFrameType(%d): unsupported interpolation type", type));
>   /*E* add SAMPLE_CUBIC here? */                      /* :9459 — author note */
>   /*    return(MRIsincSampleVolume(mri, x, y, z, 5, pval)) ;*/
> ```
>
> The `break;` exits the switch immediately,
> making the subsequent `ErrorReturn` dead
> code. Control then falls through to lines
> `:9463` onwards, which perform a **nearest-
> neighbour** sample (rounding `x, y, z` to
> ints and reading the voxel directly).
>
> So any unknown interp type — including
> `SAMPLE_CUBIC`, which the switch does not
> handle — is silently treated as
> `SAMPLE_NEAREST` rather than producing the
> intended `ERROR_UNSUPPORTED`.

## Affected Artefacts

- **Tool:** any caller of
  `MRIsampleVolumeFrameType` that passes an
  interpolation type other than the four
  handled cases (`SAMPLE_NEAREST`,
  `SAMPLE_TRILINEAR`, `SAMPLE_CUBIC_BSPLINE`,
  `SAMPLE_SINC`). Notable in-tree callers that
  pass user-supplied `interpcode`:
  - [[GradUnwarp]]'s
    [`utils/GradUnwarp.cpp:851`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/GradUnwarp.cpp#L851)
  - [`utils/resample.cpp:2970`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/resample.cpp#L2970)

  The author of `GradUnwarp` left a comment at
  [`:827`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/GradUnwarp.cpp#L827)
  noting the limitation:
  *"MRIsampleVolumeFrameType() only supports
  SAMPLE_NEAREST and SAMPLE_TRILINEAR"* — but
  the underlying `default` branch is supposed
  to error out, not silently degrade.
- **Pipeline stage(s):** none in default
  `recon-all`. Affects gradient-unwarp and
  `mri_vol2vol`-style resampling when a user
  passes `--interp cubic` for a path that
  routes through this function.
- **Triggering configuration:** any caller
  passing an interpolation type the switch
  doesn't handle.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/mri.cpp:9434-9461 */
int MRIsampleVolumeFrameType(
    const MRI *mri, const double x, const double y, const double z,
    const int frame, int type, double *pval)
{
  ...
  switch (type) {
    case SAMPLE_NEAREST:
      break;                                            /* fall through to NN block */
    case SAMPLE_TRILINEAR:
      return (MRIsampleVolumeFrame(mri, x, y, z, frame, pval));
    case SAMPLE_CUBIC_BSPLINE:
      ErrorReturn(ERROR_UNSUPPORTED, ...);
    case SAMPLE_SINC:
      ErrorReturn(ERROR_UNSUPPORTED, ...);
    default:
      break;                                            /* :9456 — exits switch */
      ErrorReturn(ERROR_UNSUPPORTED, ...);              /* :9457 — DEAD */
      /*E* add SAMPLE_CUBIC here? */
  }
  /* falls through to NEAREST sampling block — :9463-9501 */
}
```

Two compounding issues:

1. **The `break;` makes `ErrorReturn`
   unreachable.** Removing the `break;`
   exposes the `ErrorReturn` and gives the
   correct semantic.
2. **`SAMPLE_CUBIC` is not in the switch**
   despite being a documented FreeSurfer
   interp type. The author's `/*E* add
   SAMPLE_CUBIC here? */` comment confirms
   they noticed but didn't implement.

The combined effect: a user passing
`SAMPLE_CUBIC` to a tool that calls this
helper gets a silent nearest-neighbour
sample. The output looks like a 3D-staircased
"resampled" volume rather than the
smooth cubic-interpolated result the user
asked for.

## Root Cause

Refactoring artefact. The `default` case
likely once read

```cpp
default:
  ErrorReturn(...);
```

A subsequent edit added a stray `break;` on
its own line above the `ErrorReturn` —
possibly intended as a placeholder to "fall
through to NN as a safe default" — without
removing the `ErrorReturn` that no longer
matched the new behaviour. The result is
neither: the `ErrorReturn` is dead, and the
fall-through to NN is silent rather than
loudly erroring or producing the documented
behaviour.

## Impact

- **Silent degradation to nearest-neighbour:**
  a user passing `SAMPLE_CUBIC` to a tool
  that routes through this helper gets
  staircased output instead of cubic.
- **No diagnostic:** the function returns
  `NO_ERROR`, so the caller has no signal
  that the interpolation type was unsupported.
- **`SAMPLE_NEAREST` itself is correct:** the
  intentional `case SAMPLE_NEAREST: break;` at
  `:9443-9444` is the reason the post-switch
  block exists — it implements the
  nearest-neighbour sample.
- **Severity:** 2 — silent failure on a
  flag-gated input; specific impact depends on
  which tool is invoked with which interp.

```diff
+++ b/utils/mri.cpp
@@ -9452,11 +9452,9 @@ int MRIsampleVolumeFrameType(
   case SAMPLE_SINC:
     ErrorReturn(ERROR_UNSUPPORTED,
                 (ERROR_UNSUPPORTED, "MRIsampleVolumeFrameType(%d): unsupported interpolation type", type));
   default:
-    break;
     ErrorReturn(ERROR_UNSUPPORTED,
                 (ERROR_UNSUPPORTED, "MRIsampleVolumeFrameType(%d): unsupported interpolation type", type));

-    /*    return(MRIsincSampleVolume(mri, x, y, z, 5, pval)) ;*/

```

The single-line removal exposes the
`ErrorReturn` and makes unknown interp types
loud failures rather than silent degradation.
A follow-up patch can add a real `SAMPLE_CUBIC`
case (the author's `/*E* add SAMPLE_CUBIC here?
*/` note), routing to a per-frame cubic
sampler.

## Workarounds

Callers should validate `type ==
SAMPLE_NEAREST || type == SAMPLE_TRILINEAR`
before dispatching to this function, or use
the per-type entrypoints
(`MRIsampleVolumeFrame` for trilinear,
`MRIcubicSampleVolumeFrame` for cubic, etc.)
directly.
