# [severity-2] [bug-00165] reg-feat2anat — --inorm/--no-inorm set Inorm but the script never reads it; --fslmat/--fsreg are dead

> [!bug] Synopsis
> In `scripts/reg-feat2anat`, the `--inorm` and `--no-inorm` flags assign to
> a variable spelled `Inorm`, but the only intensity-normalisation variable
> declared in the script is `INorm` (different capitalisation, set to `1` at
> declaration). Neither variable is ever read: the script hard-codes
> `--inorm` directly on two `tkregister2_cmdl` command lines, so `--no-inorm`
> cannot turn it off. The flag is a complete no-op. Separately, the
> `--fslmat` and `--fsreg` flags are parsed into variables (`fslmat`,
> `fsreg`) that the body never uses, so those two flags are dead as well.

## Affected Artefacts

- **Tool(s):** [[reg-feat2anat]] — registers an FSL-FEAT `example_func` to a
  FreeSurfer anatomical.
- **Pipeline stage(s):** _N/A_ — standalone FEAT/FreeSurfer interop helper,
  not on the default [[wiki/pipelines/recon-all|recon-all]] path.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — pure tcsh variable handling.
- **Triggering configuration:** any invocation that passes `--no-inorm`
  (expecting intensity normalisation to be turned off in the manual
  `tkregister2` views), or `--fslmat`/`--fsreg` (expecting them to have an
  effect). All three flags are no-ops.

## Detailed Description

`reg-feat2anat` declares an intensity-normalisation toggle at
[`scripts/reg-feat2anat:41`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/reg-feat2anat#L41):

```tcsh
set INorm = 1;
```

The flag handlers, however, assign a differently-capitalised variable
`Inorm`:

```tcsh
    case "--inorm":
      set Inorm = 1;
      breaksw

    case "--no-inorm":
      set Inorm = 0;
      breaksw
```

There are two problems here, both of which make the flag a no-op:

1. The handler writes `Inorm`, not the declared `INorm`. tcsh is
   case-sensitive, so these are two distinct variables.
2. **Neither** `INorm` nor `Inorm` is ever read anywhere in the script. The
   intensity-normalisation option is instead hard-coded as a literal
   `--inorm` token on the two manual-view `tkregister2_cmdl` command lines,
   at
   [`scripts/reg-feat2anat:153`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/reg-feat2anat#L153)
   and
   [`scripts/reg-feat2anat:172`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/reg-feat2anat#L172):

   ```tcsh
   set cmd = ($TKR  --tag --s $subject  --inorm\
             --targ $refvolcor --mov $stdbrain --volview mov\
             --reg $anat2std_regdat --fslreg $std2anat_fslmat)
   ```

So `--inorm` is always on (in the std2anat and func2std manual views), and
`--no-inorm` does nothing — the usage text's promise "do not inorm when
running tkregister2" at
[`scripts/reg-feat2anat:638`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/reg-feat2anat#L638)
is not honoured.

The same class of defect affects two more flags. `--fslmat` and `--fsreg`
parse into `fslmat` and `fsreg`
([`scripts/reg-feat2anat:456-464`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/reg-feat2anat#L456-L464)),
but the body never reads either variable — it uses its own internally-derived
paths (`exf2anat_fslmat`, `$outvol.fsreg.dat`, etc.). These two flags are
not even documented in the usage block; they are parsed but inert.

### Expected Behaviour

`reg-feat2anat --no-inorm ...` should suppress the `--inorm` option on the
`tkregister2` command lines it builds, so the manual registration views do
not intensity-normalise.

### Observed Behaviour

`--no-inorm` sets `Inorm = 0` (a variable nothing reads). The
`tkregister2_cmdl` invocations still contain the literal `--inorm`. Intensity
normalisation stays on. The flag has no effect. Likewise `--fslmat` and
`--fsreg` change nothing.

### Reproducer

```bash
# Isolated demonstration that --no-inorm fails to clear the consumed variable:
cat > /tmp/repro.csh <<'CSH'
#!/bin/tcsh -f
set INorm = 1
set flag = "--no-inorm"
switch($flag)
  case "--inorm":
    set Inorm = 1;
    breaksw
  case "--no-inorm":
    set Inorm = 0;
    breaksw
endsw
echo "Inorm (set by parser) = $Inorm"
echo "INorm (declared var)  = $INorm   <-- unchanged; and body reads neither"
CSH
tcsh -f /tmp/repro.csh
# prints: Inorm=0  INorm=1   (the declared variable is untouched)
```

Inspection of the body (`grep -in 'norm' reg-feat2anat`) confirms the only
in-body uses of intensity normalisation are the two literal `--inorm` tokens
at lines 153 and 172 — never a `$INorm`/`$Inorm` reference.

## Root Cause

Two related defects:

1. **`--inorm`/`--no-inorm` toggle was never wired up.** The handler writes a
   mis-capitalised `Inorm`, and even the correctly-named `INorm` is never
   consulted — the option is hard-coded as a literal `--inorm` on the
   `tkregister2_cmdl` lines. The toggle has no consumer.
2. **`--fslmat`/`--fsreg` are vestigial.** They parse into variables the body
   ignores.

## Impact

- `--no-inorm` silently fails to disable intensity normalisation in the
  manual `tkregister2` views (`--manxfm std2anat` and `--manxfm func2std`).
  This affects only the interactive QC display, not the registration matrices
  that `reg-feat2anat` writes — those `tkregister2_cmdl` calls are
  `--volview mov` viewers used during manual inspection. The computed
  `anat2exf.register.dat` and the FSL matrices are unaffected.
- `--fslmat`/`--fsreg` accept an argument and then ignore it, which can
  mislead a user into thinking they redirected an output.
- Severity is **2 (low)**: the defects are latent under typical use — they
  affect a diagnostic/QA display option and two inert flags, not the tool's
  primary output. `reg-feat2anat` is a standalone helper, not on a default
  pipeline.

## Recommended Fix

Wire `--inorm`/`--no-inorm` to a single variable that the consumer reads, and
gate the literal `--inorm` on it. Minimal change: assign the declared
`INorm`, then build the option conditionally at both consumer sites.

```diff
     case "--inorm":
-      set Inorm = 1;
+      set INorm = 1;
       breaksw

     case "--no-inorm":
-      set Inorm = 0;
+      set INorm = 0;
       breaksw
```

and, at each of the two manual-view command builders (lines 153-155 and
170-172), replace the hard-coded `--inorm` with a conditional append, e.g.:

```diff
-  set cmd = ($TKR  --tag --s $subject  --inorm\
+  set cmd = ($TKR  --tag --s $subject\
             --targ $refvolcor --mov $stdbrain --volview mov\
             --reg $anat2std_regdat --fslreg $std2anat_fslmat)
+  if($INorm) set cmd = ($cmd --inorm)
```

Separately, either remove the dead `--fslmat`/`--fsreg` cases or wire them to
the intended outputs; at minimum they should not silently swallow an
argument.

### Alternative Fixes Considered

If the intent is that intensity normalisation is *always* desired for these
manual views, then `--inorm`/`--no-inorm` (and the `INorm` declaration)
should simply be removed and the usage text corrected. The audit cannot tell
which intent is correct — see the gap callout.

## Workarounds (If Any)

To inspect the registration without intensity normalisation, run
`tkregister2` (or `tkregister2_cmdl`) by hand on the relevant volumes and
omit `--inorm`. There is no command-line way to make `reg-feat2anat` itself
honour `--no-inorm` without a code change.

> [!gap] Intended design unclear
> The audit cannot determine whether intensity normalisation in the manual

> unwired) or always-on (in which case the flag should be removed). Either
> way the current `--inorm`/`--no-inorm` flag is a no-op; a developer should
> confirm the intent before choosing between the two fixes above. The
> `--fslmat`/`--fsreg` flags are unambiguously dead (parsed, never read,
