# [severity-3] [bug-00183] trac-paths — longitudinal endpoint stats run against the base subject ($subj) instead of the timepoint ($subj_t)

> [!bug] Synopsis
> In the longitudinal branch of `trac-paths`, the per-timepoint loop
> (`foreach subj_t ($tplist)`) projects each tract's endpoints onto the
> cortical surface of the **timepoint** subject and computes anatomical
> statistics with `mris_anatomical_stats`. Every step in that loop passes
> the timepoint id `$subj_t` — except the `mris_anatomical_stats`
> invocation, which passes `$subj` (the cross-sectional / base/template
> subject id) as the subject argument. The endpoint label was created on the
> timepoint's surface, but the surface morphometry it is overlaid on belongs
> to the base subject, so the resulting `endpt?.surf.stats` are computed
> against the wrong subject's anatomy in longitudinal TRACULA.

## Affected Artefacts

- **Tool(s):** [[trac-paths]] — the path-statistics stage of TRACULA,
  invoked by [[wiki/pipelines/trac-all|trac-all]] during `-stat`.
- **Pipeline stage(s):** [[wiki/pipelines/trac-all|trac-all]] longitudinal
  statistics. The defect is reached only when `trac-paths` runs in
  longitudinal mode (`$dolong == 1`, i.e. a non-empty `$tplist` is set by
  `trac-all -long`).
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`.
- **Platforms:** all — pure shell logic.
- **Triggering configuration:** longitudinal TRACULA only. The
  cross-sectional branch (the `else` of `$dolong`) uses `$subj`
  consistently and is correct; this bug fires only on the longitudinal path,
  for every timepoint, for every cortical endpoint.

## Detailed Description

`trac-paths` contains two near-identical blocks that reconstruct path
endpoints and gather endpoint morphometry: a cross-sectional block (single
subject `$subj`) and a longitudinal block that loops over timepoints
(`foreach subj_t ($tplist)`). In longitudinal mode, `$subj` is the
base/cross-sectional subject id (used for `$dtroot/$subj` and
`$SUBJECTS_DIR/$subj`), while each `$subj_t` is an individual timepoint id
(e.g. `tp1.long.base`), with its own FreeSurfer surface reconstruction under
`$SUBJECTS_DIR/$subj_t`.

For each cortical endpoint the longitudinal block:

1. `mri_vol2surf` projects the endpoint PD volume onto the **timepoint**
   surface — `--srcsubject $subj_t --trgsubject $subj_t`.
2. `mri_cor2label` / `mri_label2label` create and clean a label on the
   **timepoint** surface — `--surf $subj_t ...`, `--s $subj_t ...`.
3. `mris_anatomical_stats` is supposed to overlay that label on the
   **timepoint** surface and write `endpt?.surf.stats`.

Steps 1 and 2 correctly use `$subj_t`. Step 3 passes `$subj`.

### Expected Behaviour

In the longitudinal block, `mris_anatomical_stats` should be called with the
timepoint id, exactly like the surrounding commands:

```tcsh
set cmd = ($cmd $subj_t $hemi)
```

so that the endpoint label (created on the `$subj_t` surface) is measured
against the `$subj_t` surface's geometry and parcellation — i.e. the
timepoint's own white/pial surfaces, thickness, and curvature.

### Observed Behaviour

The longitudinal block calls:

```tcsh
set cmd = ($cmd $subj $hemi)
```

`mris_anatomical_stats <subject> <hemi>` reads
`$SUBJECTS_DIR/<subject>/surf/<hemi>.white`, `.pial`, `.thickness`, etc. With
`<subject> == $subj` (the base subject), it loads the **base** subject's
surfaces and applies the timepoint-derived label
(`endpt$pt.surf.label`) to them. Because the timepoint and base surfaces have
the **same vertex topology** (longitudinal surfaces are resampled from the
base/template), the vertex indices in the label still resolve and the command
does **not** error — it silently produces statistics for the base subject's
anatomy. The reported per-endpoint area, thickness, and curvature therefore
describe the base/template surface rather than the timepoint, defeating the
purpose of the longitudinal stream (detecting change across timepoints).

By contrast, the cross-sectional block at
[`scripts/trac-paths:679-682`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L679-L682)
correctly passes `$subj` because there `$subj` *is* the subject whose surface
the label was built on.

### Reproducer

> [!gap] Reproducer requires a completed longitudinal TRACULA run
> The defect is established by static reading and by comparison with the
> matching cross-sectional block. A direct demonstration needs a longitudinal
> TRACULA dataset (a base/template plus ≥1 longitudinal timepoint with
> completed `recon-all -long` and `trac-preproc`/`bedpostx`):
>
> ```bash
> # In longitudinal mode, after path reconstruction:
> trac-all -stat -c dmrirc.long
> # Inspect any timepoint's endpoint stats:
> #   $dtroot/<subj_t>/dpath/<tract>_<avg>/endpt?.surf.stats
> # The "subject" recorded in the stats header / the surface measures will
> # correspond to the base subject <subj>, not the timepoint <subj_t>.
> ```

## Code Reference (Unambiguous)

- **File:** `scripts/trac-paths`
- **Function:** longitudinal statistics block — `foreach subj_t ($tplist)`
- **Lines:** defect at `1134–1137` (the `$subj` at `1137`); enclosing
  per-timepoint loop opens at `978`
- **Commit:** `d932c45`

```tcsh
          set cmd = mris_anatomical_stats 
          set cmd = ($cmd -l $pathdir/endpt$pt.surf.label)
          set cmd = ($cmd -f $pathdir/endpt$pt.surf.stats)
          set cmd = ($cmd $subj $hemi)              # ← should be $subj_t in the longitudinal loop
          echo $cmd |& tee -a $LF |& tee -a $CF
          if ($RunIt) then
            $cmd |& tee -a $LF
            if ($status) goto error_exit
          endif
```

The same loop uses `$subj_t` everywhere else, confirming the intent:
`dmri_pathstats --subj $subj_t`
([`:1029`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L1029)),
`mri_vol2surf --srcsubject $subj_t ... --trgsubject $subj_t`
([`:1076`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L1076),
[`:1079`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L1079)),
`mri_cor2label --surf $subj_t`
([`:1116`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L1116)),
and `mri_label2label --s $subj_t`
([`:1125`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L1125)).
The cross-sectional twin block uses `$subj` correctly at
[`scripts/trac-paths:682`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L682).

## Root Cause

Copy-paste error introduced when the cross-sectional endpoint-stats block
was duplicated to create the longitudinal block. The duplication mechanically
substituted `$subj` → `$subj_t` throughout the timepoint loop but missed the
`mris_anatomical_stats <subject>` positional argument at
[`scripts/trac-paths:1137`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/scripts/trac-paths#L1137).
Because both subjects share the longitudinal surface topology, the stale
`$subj` does not raise an error — it just measures the wrong surface.

## Impact

- **Wrong morphometry in longitudinal TRACULA.** Every cortical-endpoint
  statistics file (`endpt?.surf.stats`) written by the longitudinal stream
  reflects the base/template subject's surface, not the timepoint's. Any
  longitudinal comparison of endpoint area / thickness / curvature across
  timepoints is invalidated — all timepoints effectively report the base
  surface's values.
- **Silent.** The command succeeds (matching topology), so there is no error
  or warning; the stats files are written and look valid.
- **Scope.** This is gated behind longitudinal mode (`-long`), which is an
  opt-in TRACULA workflow, hence medium (3) rather than critical (5): the
  default cross-sectional `trac-all` path is unaffected. The whole-path and
  along-path FA/MD statistics from `dmri_pathstats` are unaffected (they
  correctly use `$subj_t`); only the surface endpoint morphometry is wrong.

## Recommended Fix

Use the timepoint id, matching every other command in the loop:

```diff
           set cmd = mris_anatomical_stats 
           set cmd = ($cmd -l $pathdir/endpt$pt.surf.label)
           set cmd = ($cmd -f $pathdir/endpt$pt.surf.stats)
-          set cmd = ($cmd $subj $hemi)
+          set cmd = ($cmd $subj_t $hemi)
           echo $cmd |& tee -a $LF |& tee -a $CF
```

No other change is needed: the label, the surface projection, and the
output path (`$pathdir` derives from `$outdir_t = $dtroot/$subj_t/...`) are
already timepoint-scoped.

### Alternative Fixes Considered

None — the loop variable `$subj_t` is unambiguously the correct subject for
this block, and a single-token edit suffices.

## Workarounds (If Any)

Until patched, a user running longitudinal TRACULA can re-run
`mris_anatomical_stats -l <pathdir>/endpt<pt>.surf.label
-f <pathdir>/endpt<pt>.surf.stats <subj_t> <hemi>` by hand for each
timepoint/endpoint to regenerate correct stats. There is no flag that
selects the correct subject.

## Confidence and Gaps

> [!gap] Surface-topology assumption
> The claim that the buggy command does not error relies on longitudinal
> timepoint surfaces sharing the base subject's vertex topology (true for
> `recon-all -long` output, which resamples each timepoint from the base).
> If a timepoint surface had a different vertex count, the stale `$subj`
> would instead mismatch the label and likely fail loudly. Either way the
> longitudinal stats are wrong; only the failure mode (silent vs. loud)
> depends on this assumption.
