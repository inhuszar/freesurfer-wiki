# [severity-2] [bug-00016] MRIcopyHeader — register_mat MatrixCopy return discarded; fresh destinations lose the matrix silently

> [!bug] Synopsis
> `MRIcopyHeader` in `utils/mri.cpp` is the primitive that copies a
> volume's header fields from one `MRI` to another; it is called
> from `MRIclone`, `MRIalloc*`-style wrappers, and every header-aware
> allocation path in the codebase. When the source carries a
> non-null `register_mat`, the copy is attempted with
> `MatrixCopy(src->register_mat, dst->register_mat)` — but the return
> value is **discarded**. On the common case of a freshly-allocated
> `mri_dst` whose `register_mat` is `NULL`, `MatrixCopy` allocates
> the new matrix internally and returns it, but that returned
> pointer is never written back into `mri_dst->register_mat`. The
> destination volume therefore ends up with `register_mat == NULL`
> and the freshly-allocated matrix is leaked. The same statement,
> for all five other matrix fields copied in the same function
> (`i_to_r__`, `r_to_i__`, `AutoAlign`, `origRas2Vox`), correctly
> captures the return value; `register_mat` is the odd one out.

## Affected Artefacts

- **Tool(s):** any tool that clones a volume whose `register_mat`
  is set and then reads that field after the clone. The primary
  in-tree caller is [[mri_ms_fitparms]] (multi-spectral FLASH
  fitting), which stores scanner vox2ras matrices in
  `mri_flash[j]->register_mat` and later reads them back via
  `MatrixCopy(mri_flash[j]->register_mat, NULL)` — see
  [`mri_ms_fitparms/mri_ms_fitparms.cpp:1421`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_ms_fitparms/mri_ms_fitparms.cpp#L1421),
  [`:1653`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_ms_fitparms/mri_ms_fitparms.cpp#L1653),
  [`:1851`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_ms_fitparms/mri_ms_fitparms.cpp#L1851),
  [`:2063`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_ms_fitparms/mri_ms_fitparms.cpp#L2063),
  [`:2368`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_ms_fitparms/mri_ms_fitparms.cpp#L2368).
- **Pipeline stage(s):** _N/A_ for standard [[wiki/pipelines/recon-all|recon-all]].
  `mri_ms_fitparms` is a specialised quantitative-MRI tool and
  is not invoked by recon-all.
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit
  `d932c45b79`.
- **Platforms:** all — purely C pointer semantics.
- **Triggering configuration:** every call to `MRIcopyHeader`
  (or any function that delegates to it, including `MRIclone`,
  `MRIcopy`, and `MRIallocSequence` init-paths) where the source
  has `register_mat != NULL` and the destination's
  `register_mat` is `NULL`.

## Detailed Description

`MatrixCopy(const MATRIX *mIn, MATRIX *mOut)` follows the standard
FreeSurfer in-out idiom:

- if `mOut == NULL`, allocate a fresh matrix and return it;
- if `mOut != NULL`, copy `mIn` into `mOut` in place and return
  `mOut`.

Callers are therefore required to capture the return value when
the destination might be `NULL`. Every similar field in
`MRIcopyHeader` does so:

```cpp
mri_dst->i_to_r__    = AffineMatrixCopy(mri_src->i_to_r__,    mri_dst->i_to_r__);
mri_dst->r_to_i__    = MatrixCopy     (mri_src->r_to_i__,    mri_dst->r_to_i__);
mri_dst->AutoAlign   = MatrixCopy     (mri_src->AutoAlign,   NULL);
mri_dst->origRas2Vox = MatrixCopy     (mri_src->origRas2Vox, NULL);
```

Three lines earlier, the `register_mat` branch does not:

```cpp
if (mri_src->register_mat != NULL)
  MatrixCopy(mri_src->register_mat, mri_dst->register_mat);   // ← return discarded
else
  mri_dst->register_mat = NULL;
```

Because `mri_dst` is almost always freshly allocated when
`MRIcopyHeader` is called, `mri_dst->register_mat` is initially
`NULL`; `MatrixCopy` allocates a new matrix, fills it, and
returns it; the return is thrown away. The destination's
`register_mat` stays `NULL`, and the allocation is leaked.

### Expected Behaviour

After `MRIcopyHeader(src, dst)`:

- `dst->register_mat` should be `NULL` if `src->register_mat` is
  `NULL`, or point to a freshly-allocated copy of `src->register_mat`
  otherwise.
- No allocations should be leaked.

### Observed Behaviour

- If `src->register_mat == NULL`: `dst->register_mat` is
  explicitly set to `NULL` (line 6271). Correct.
- If `src->register_mat != NULL` and `dst->register_mat == NULL`
  (common): `MatrixCopy` allocates a new matrix and returns it;
  the return is discarded; `dst->register_mat` stays `NULL`; the
  allocation is **leaked**.
- If `src->register_mat != NULL` and `dst->register_mat != NULL`
  (rare — happens when the destination is an existing volume
  being re-headered): `MatrixCopy` copies into the pre-existing
  `dst->register_mat` in place, and the return value points to
  the same pre-existing matrix. Correct, purely by coincidence.

### Reproducer

> [!gap] Reproducer not yet constructed
> A unit-style demonstration:
>
> 1. Allocate `MRI *src = MRIalloc(64, 64, 64, MRI_FLOAT)`; set
>    `src->register_mat = MatrixIdentity(4, NULL);` (any
>    recognisable matrix).
> 2. `MRI *dst = MRIclone(src, NULL);`
> 3. `assert(dst->register_mat != NULL);` — fails, because
>    `MRIclone` → `MRIcopyHeader` dropped the allocation.
> 4. Under `valgrind`, the 4×4-float allocation inside
>    `MatrixCopy` is reported as leaked.

```cpp
MRI *MRIcopyHeader(const MRI *mri_src, MRI *mri_dst)
{
  /* ... header fields elided ... */

  if (mri_src->register_mat != NULL)
    MatrixCopy(mri_src->register_mat, mri_dst->register_mat);     // ← discards return

```

The contrast with the four lines below is stark: every other
matrix field captures the return of `MatrixCopy` / `AffineMatrixCopy`;
only the `register_mat` branch does not.

And the `MatrixCopy` contract that makes this a defect:

- **File:** `utils/matrix.cpp`
- **Function:** `MatrixCopy()`
- **Lines:** `150–181`
- **Commit:** `d932c45b79`

```cpp
MATRIX *MatrixCopy(const MATRIX *mIn, MATRIX *mOut)
{
  /* ... */
  if (!mOut)
    mOut = MatrixAlloc(rows, cols, mIn->type);      // ← allocates here
  else if (mOut->rows < mIn->rows || mOut->cols < mIn->cols)
    return (NULL);
  /* ... copy ... */
  return (mOut);                                    // ← caller must capture this
}
```

## Root Cause

A copy-paste of the "matrix copy" pattern from the adjacent lines
that lost its left-hand-side assignment. The `i_to_r__`,
`r_to_i__`, `AutoAlign`, and `origRas2Vox` lines all read
`dst->X = MatrixCopy(src->X, dst->X);` or
`dst->X = MatrixCopy(src->X, NULL);`. The `register_mat` line
reads `MatrixCopy(src->register_mat, dst->register_mat);`, with
the leading `mri_dst->register_mat =` missing.

## Impact

- Any consumer of the destination `MRI` that expects
  `register_mat` to be populated after a header copy gets `NULL`
  back. For `mri_ms_fitparms` (the only active in-tree consumer),
  an allocate-then-copy flow silently drops the registration
  matrix, and the downstream `MatrixCopy(mri->register_mat, NULL)`
  calls see `NULL` as input, which `MatrixCopy` returns as `NULL`
  — the failure propagates without any diagnostic.
- On every call where `mri_dst` is freshly allocated and `src`
  has a non-null `register_mat`, the `MatrixAlloc` inside
  `MatrixCopy` leaks the allocation. The leak is small (one 4×4
  float matrix + bookkeeping) but occurs on every header copy, so
  long-running tools that clone many volumes accumulate
  proportionally to the number of clones.
- Standard [[wiki/pipelines/recon-all|recon-all]] subjects are unaffected because none of
  the volumes handled by recon-all carry a non-null
  `register_mat` at the points they pass through
  `MRIcopyHeader`.

## Recommended Fix

Capture the return value, matching the idiom used for the
adjacent matrix fields:

```diff
-  if (mri_src->register_mat != NULL)
-    MatrixCopy(mri_src->register_mat, mri_dst->register_mat);
-  else
-    mri_dst->register_mat = NULL;
+  if (mri_src->register_mat != NULL)
+    mri_dst->register_mat = MatrixCopy(mri_src->register_mat,
+                                       mri_dst->register_mat);
+  else
+    mri_dst->register_mat = NULL;
```

With the fix in place, a freshly-allocated `mri_dst` receives
the newly-allocated matrix, and an already-populated
`mri_dst->register_mat` is overwritten in place (the previous
pre-existing allocation gets re-used rather than leaked). On
`mri_src->register_mat == NULL` the else-branch still runs and
`mri_dst->register_mat` is set to `NULL` as before.

### Alternative Fixes Considered

Free any pre-existing `mri_dst->register_mat` first and always
reassign from the return of `MatrixCopy(src, NULL)`, matching
the `AutoAlign` and `origRas2Vox` styles. That is cleaner but
changes behaviour when the caller passed a pre-existing
`mri_dst` with an independent `register_mat` that should have
been freed separately. The minimal one-line fix above is the
safer choice.

## Workarounds (If Any)

Callers who need `register_mat` on a cloned volume can copy it
by hand immediately after `MRIclone` / `MRIcopyHeader`:

```cpp
MRI *dst = MRIclone(src, NULL);
if (src->register_mat != NULL)
  dst->register_mat = MatrixCopy(src->register_mat, NULL);
```
