# [severity-2] [bug-00082] `fMRItemporalAR1` leaks `var` and `covar` working volumes

> [!bug] Synopsis
> `fMRItemporalAR1`
> ([`utils/fmriutils.cpp:193-229`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fmriutils.cpp#L193-L229))
> computes lag-0 (variance) and lag-1 working
> volumes via `fMRIcovariance` and divides them
> voxelwise to produce the AR(1) coefficient:
>
> ```cpp
> var   = fMRIcovariance(fmri, 0, DOFAdjust, mask, NULL);  /* :199 */
> covar = fMRIcovariance(fmri, 1, DOFAdjust, mask, NULL);  /* :200 */
> ...
> MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;
> ...
> return (ar1);                                            /* :228 */
> ```
>
> Both `fMRIcovariance` returns are freshly-
> allocated `MRI_FLOAT` volumes the same shape as
> `fmri`. Neither is freed before the `return`,
> leaking `2 × width × height × depth × 4` bytes per
> call.

## Affected Artefacts

- **Tools:**
  - [[mri_glmfit]] when invoked with `--tar1`
    ([`mri_glmfit/mri_glmfit.cpp:2102`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_glmfit/mri_glmfit.cpp#L2102)) —
    fMRI residual AR(1) for variance smoothing.
  - [[mri_concat]] when invoked with `--tar1`
    ([`mri_concat/mri_concat.cpp:546`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_concat/mri_concat.cpp#L546)).
- **Pipeline stage(s):** none in default
  `recon-all`. Used by FsFast / fMRI workflows.
- **Triggering configuration:** any invocation
  that requests AR(1) output. Always-on within
  the function — there is no path that frees
  `var`/`covar`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/fmriutils.cpp:193-229 */
MRI *fMRItemporalAR1(MRI *fmri, float DOFAdjust, MRI *mask, MRI *ar1)
{
  int c, r, s;
  double voxvar, voxcovar;
  MRI *var, *covar;

  var   = fMRIcovariance(fmri, 0, DOFAdjust, mask, NULL);  /* allocates */
  covar = fMRIcovariance(fmri, 1, DOFAdjust, mask, NULL);  /* allocates */

  if (ar1 == NULL) {
    ar1 = MRIallocSequence(fmri->width, fmri->height, fmri->depth, MRI_FLOAT, 1);
    ...
  }

  for (c = 0; c < fmri->width; c++) {
    for (r = 0; r < fmri->height; r++) {
      for (s = 0; s < fmri->depth; s++) {
        ...
        voxvar   = MRIFseq_vox(var,   c, r, s, 0);
        voxcovar = MRIFseq_vox(covar, c, r, s, 0);
        MRIFseq_vox(ar1, c, r, s, 0) = voxcovar / voxvar;
      }
    }
  }

  return (ar1);                                /* leaks var, covar */
}
```

For a typical 4-D fMRI of shape 64×64×40×200,
the leak is `2 × 64 × 64 × 40 × 4 ≈ 1.3 MB` per
call; for 96×96×60×400 it is `4.4 MB`. The
function is typically called once per run, so
the leak is bounded — but the process never
gets the memory back, and tools that wrap many
runs (e.g. simulation harnesses) accumulate.

`var` and `covar` are local variables and have
no other use after the per-voxel division, so
freeing them just before the `return` is safe
and obvious.

## Root Cause

`fMRIcovariance` returns a freshly-allocated
volume when its `covar` argument is `NULL`. The
two calls in `fMRItemporalAR1` pass `NULL` and
therefore receive new allocations, but the
function never adds the matching `MRIfree` calls
before returning — the local pointers go out of
scope and the volumes leak.

## Impact

- **Memory:** leak of 2 × full fMRI float volume
  per call. Bounded for typical single-run
  invocations of `mri_glmfit --tar1` /
  `mri_concat --tar1`; cumulative for harnesses
  that loop the function in-process.
- **Output correctness:** unaffected. The AR(1)
  values written to `ar1` are unchanged by the
  leak.
- **Severity:** low (leak only, no wrong output;
  always-on within a flag-gated path).

## Recommended Fix

```diff
+++ b/utils/fmriutils.cpp
@@ -224,6 +224,8 @@ MRI *fMRItemporalAR1(MRI *fmri, float DOFAdjust, MRI *mask, MRI *ar1)

   }

+  MRIfree(&var);
+  MRIfree(&covar);

```

The same fix should be applied alongside
[[00046]]'s missing-`continue`/`else` patch so
that the `voxvar == 0` early-write does not skip
the cleanup (the proposed patch in [[00046]]
leaves the cleanup at function exit, so this
diff composes cleanly).

## Workarounds

For long-running harnesses that invoke
`fMRItemporalAR1` repeatedly, fork a child
process per call to reclaim memory at exit.
