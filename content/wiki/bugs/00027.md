# MRIunion uses UCHAR-only direct access and frame 0 only, silently diverging from sibling set ops

> [!bug] Synopsis
> The set-operation family in `utils/mriset.cpp` (`MRIunion`,
> `MRIintersect`, `MRIcomplement`, `MRIand`, `MRIor`, `MRIxor`)
> shares the same signature shape — `(mri1, mri2, mri_dst[, ...])`
> — and the same `MRIcheckVolDims` preamble. Five of the six use
> the type-aware `MRIgetVoxVal` / `MRIsetVoxVal` accessors and
> iterate frames; **only `MRIunion`** uses the legacy
> `MRIvox` macro (a `BUFTYPE *` UCHAR direct access that ignores
> the frame parameter and the storage type). For any non-UCHAR
> input, `MRIunion` aliases the wrong-type storage as bytes and
> writes byte-garbled output; for any multi-frame input, only
> frame 0 is touched. Latent under standard [[recon-all]]
> (single-frame UCHAR masks), but a real correctness hole the
> moment a caller passes float, int, or multi-frame data.

## Detailed Description

### Expected Behaviour

By symmetry with the other set-operation primitives in the same
file, `MRIunion(a, b, dst)` should compute the per-voxel maximum
across all frames, treating any supported MRI data type and
preserving multi-frame structure. The sibling routines exhibit
this contract:

- [`MRIintersect`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L142-L163)
  iterates `for (f = 0; f < mri_dst->nframes; f++)` and uses
  `MRIgetVoxVal` / `MRIsetVoxVal`.
- [`MRIcomplement`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L171-L195)
  iterates frames and uses the type-aware accessors.
- [`MRIand`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L203-L230)
  and
  [`MRIor`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L238-L265)
  iterate frames and use `MRIsampleVolumeFrame` / `MRIsetVoxVal`.
- [`MRIxor`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L306-L331)
  uses `MRIgetVoxVal` / `MRIsetVoxVal` (single-frame, but at
  least type-aware).

### Observed Behaviour

`MRIunion` at
[`utils/mriset.cpp:108-134`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L108-L134)
opens row buffers with `MRIvox`, which is the legacy UCHAR
single-frame macro:

```cpp
for (z = 0; z < depth; z++) {
  for (y = 0; y < height; y++) {
    pdst = &MRIvox(mri_dst, 0, y, z);   /* BUFTYPE *, frame 0 only */
    p1   = &MRIvox(mri1,    0, y, z);
    p2   = &MRIvox(mri2,    0, y, z);
    for (x = 0; x < width; x++) {
      v1 = *p1++;
      v2 = *p2++;
      *pdst++ = MAX(v1, v2);
    }
  }
}
```

`MRIvox(mri, x, y, z)` is defined at
[`include/mri.h:1480`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mri.h#L1480)
as

```cpp
#define MRIvox(mri,x,y,z)   (((BUFTYPE *)mri->slices[z][y])[x])
```

— a per-byte alias on `slices[z][y]`. Two consequences:

1. **Type-blind.** Whatever the underlying `mri->type`, the
   pointer is reinterpreted as `unsigned char *` and the read
   pulls one byte from the storage. For `MRI_FLOAT` storage
   (4 bytes per voxel), each "voxel read" picks up one of the
   four IEEE-754 bytes — silent garbage. The per-byte read is
   _within_ the allocated buffer (not a memory error), so no
   ASan hit and no segfault.
2. **Frame-blind.** `slices[z]` (no `+ f * depth` offset) is
   the z-th slice of frame 0. Frames 1..nframes-1 are not
   read or written.

For UCHAR single-frame inputs (the common recon-all case),
both consequences vanish and `MRIunion` produces the correct
voxel-wise max. For any other input shape, the result is
silently broken.

### Reproducer

```c
/* Reproduces frame-blind behaviour with a 2-frame UCHAR mask. */
MRI *a = MRIallocSequence(4, 4, 4, MRI_UCHAR, 2);
MRI *b = MRIallocSequence(4, 4, 4, MRI_UCHAR, 2);
MRIsetVoxVal(b, 1, 1, 1, 0, 0);    /* frame 0: zero */
MRIsetVoxVal(b, 1, 1, 1, 1, 100);  /* frame 1: nonzero */
MRI *out = MRIunion(a, b, NULL);
double v0 = MRIgetVoxVal(out, 1, 1, 1, 0);   /* expect 0   — observed 0   ✓ */
double v1 = MRIgetVoxVal(out, 1, 1, 1, 1);   /* expect 100 — observed 0   ✗ frame 1 untouched */
```

```c
/* Reproduces type-blind behaviour with FLOAT inputs. */
MRI *a = MRIalloc(4, 4, 4, MRI_FLOAT);
MRI *b = MRIalloc(4, 4, 4, MRI_FLOAT);
MRIsetVoxVal(a, 1, 1, 1, 0, 1.5f);
MRIsetVoxVal(b, 1, 1, 1, 0, 2.5f);
MRI *out = MRIunion(a, b, NULL);
double v = MRIgetVoxVal(out, 1, 1, 1, 0);
/* expect 2.5; observed: garbage byte aliased back into the float bit pattern */
```

```cpp
MRI *MRIunion(MRI *mri1, MRI *mri2, MRI *mri_dst)
{
  int width, height, depth, x, y, z;
  BUFTYPE *p1, *p2, *pdst, v1, v2;          /* ← UCHAR-only assumption */

  MRIcheckVolDims(mri1, mri2);               /* checks dims, NOT type */

  width = mri1->width;
  height = mri1->height;
  depth = mri1->depth;

  if (!mri_dst) mri_dst = MRIclone(mri1, NULL);

  for (z = 0; z < depth; z++) {              /* ← no frame loop */
    for (y = 0; y < height; y++) {
      pdst = &MRIvox(mri_dst, 0, y, z);     /* ← MRIvox: BUFTYPE *, frame 0 */
      p1 = &MRIvox(mri1, 0, y, z);
      p2 = &MRIvox(mri2, 0, y, z);

        v1 = *p1++;
        v2 = *p2++;
        *pdst++ = MAX(v1, v2);
      }
    }
  }
  return (mri_dst);
}
```

Sibling for comparison
([`utils/mriset.cpp:142-163`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L142-L163)):

```cpp
MRI *MRIintersect(MRI *mri1, MRI *mri2, MRI *mri_dst)
{
  /* ... */
  for (f = 0; f < mri_dst->nframes; f++)             /* ← frame loop */
    for (z = 0; z < depth; z++)
      for (y = 0; y < height; y++)
        for (x = 0; x < width; x++) {
          v1 = MRIgetVoxVal(mri1, x, y, z, f);       /* ← type-aware */
          v2 = MRIgetVoxVal(mri2, x, y, z, f);
          MRIsetVoxVal(mri_dst, x, y, z, f, MIN(v1, v2));
        }
  return (mri_dst);
}
```

The two functions differ in essentially nothing except the
operator (`MAX` vs `MIN`) and the accessor strategy. The
divergence is unintentional drift, not deliberate API design.

## Root Cause

`MRIunion` predates the type-aware refactor that introduced
`MRIgetVoxVal` / `MRIsetVoxVal`; the rest of the file was
updated when those accessors were standardised but `MRIunion`
was missed. There is no comment, no type guard, and no
documented contract that limits inputs to UCHAR — the
restriction is implicit in the body's choice of `MRIvox`.

## Impact

- **Standard [[recon-all]] is unaffected.** All in-tree call
  sites pass single-frame UCHAR masks (`mri_fill`,
  `mri_ventricle`, `mri_lv`, `mri_T1` after conformation,
  `mri_labeled` masks). The voxel-wise `MAX` is computed
  correctly on these inputs.
- **Non-default flows silently break.** Any caller — internal
  refactor or external dependent — that supplies a `MRI_FLOAT`
  working buffer or multi-frame label series gets
  byte-aliased garbage with no error, no warning, and no
  visible difference until the corrupted volume is examined.
- **API drift.** `MRIunion` cannot be substituted into a
  generic set-operation pipeline next to `MRIintersect`. A
  consumer expecting symmetric behaviour from the family is
  surprised.
- **Latent buffer-strange-but-not-OOB.** The per-byte reads
  stay within the allocated buffer (the size of `slices[z][y]`
  in bytes is `width * sizeof(voxtype)`, of which the loop
  reads `width` bytes — always within bounds). No segfault,
  no sanitiser hit. Only the values are wrong.

This brings `MRIunion` to symmetric form with `MRIintersect`
(the closest sibling, differing only in `MAX` vs `MIN`) and
restores the implicit family contract.

`MRIxor` at
[`utils/mriset.cpp:306-331`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L306-L331)
also hard-codes frame `0` (`MRIgetVoxVal(..., 0)`) and would
benefit from the same multi-frame extension, though it is at
least type-aware. That can be batched into the same patch or
deferred.

### Alternative Fixes Considered

- **Document the UCHAR/single-frame restriction.** Add a comment
  and an `if (mri1->type != MRI_UCHAR) ErrorExit(...)` guard.
  Cheaper than rewriting the body but contradicts the implicit
  family contract; rejected.
- **Add a fast UCHAR specialisation _alongside_ the generic
  body.** Mirrors the
  [`MRIerode`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mriset.cpp#L491)
  pattern of two paths. Speed-vs-uniformity trade-off; the
  recommended fix above prioritises uniformity.

## Workarounds (If Any)

- Callers passing non-UCHAR volumes can pre-convert with
  `MRIchangeType(..., MRI_UCHAR, ...)` (lossy for floats) or
  bypass `MRIunion` and write the per-voxel max inline.
- Callers with multi-frame inputs must split the volume by
  frame, call `MRIunion` per frame, and reassemble — there is
  no in-tree primitive that does this safely today.
