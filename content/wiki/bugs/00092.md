# [severity-3] [bug-00092] `GTMmgxpvc` `Target == 2` mishandles `subcort_gm-mid` (subtracts but does not normalise)

> [!bug] Synopsis
> `GTMmgxpvc`
> ([`utils/gtm.cpp:1577-1666`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gtm.cpp#L1577-L1666))
> implements GLM-based Müller-Gärtner PVC by:
>
> 1. Building `betaNotTarg` (a copy of `gtm->beta`
>    with the **target** segs zeroed out) — the
>    first loop at
>    [`:1588-1610`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gtm.cpp#L1588-L1610).
> 2. Computing `ydiff = y − X * betaNotTarg` (the
>    PET signal attributable to target tissue).
> 3. Normalising each voxel by the sum of
>    `X[r, target_segs]` (the target-tissue
>    fraction) — the second loop at
>    [`:1618-1656`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gtm.cpp#L1618-L1656).
>
> The two loops must agree on what counts as a
> "target seg." For `Target == 2` (subcortical
> grey matter), they don't:
>
> ```cpp
> /* First loop, :1597-1602 — Target == 2 OR Target == 3 */
> if (Target == 2 || Target == 3) {
>   if (strcmp("subcort_gm",     cte->name) == 0) continue;
>   if (strcmp("subcort_gm-lh",  cte->name) == 0) continue;
>   if (strcmp("subcort_gm-rh",  cte->name) == 0) continue;
>   if (strcmp("subcort_gm-mid", cte->name) == 0) continue;   /* mid IS a target */
> }
>
> /* Second loop, :1629-1633 — Target == 2 only */
> if (Target == 2) {
>   if (strcmp("subcort_gm",    cte->name) != 0 &&
>       strcmp("subcort_gm-lh", cte->name) != 0 &&
>       strcmp("subcort_gm-rh", cte->name) != 0)
>     continue;                                                /* mid is NOT included */
> }
> ```
>
> A voxel containing `subcort_gm-mid` therefore
> has its contribution **removed** from
> `yNotTarg` (treated as target) but the
> normaliser `sum` does **not** include the
> `subcort_gm-mid` column of `X`. The
> "corrected" PET intensity for those voxels is
> divided by a too-small sum (or by zero, in
> which case `mgx_gmthresh` zeros the voxel).
>
> For `Target == 3` ("any GM") both loops
> include `subcort_gm-mid` consistently
> (`:1601` and `:1641`), so that target is
> unaffected. Targets 4–8 are
> single-class lateralised variants and are
> internally consistent.

## Affected Artefacts

- **Tool:** [[mri_gtmpvc]] when invoked with
  `--mgx <gmthresh>`
  ([`mri_gtmpvc/mri_gtmpvc.cpp:1552`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_gtmpvc/mri_gtmpvc.cpp#L1552)).
  The bug only affects the `Target == 2` call
  at
  [`:869`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_gtmpvc/mri_gtmpvc.cpp#L869),
  whose output is written to
  `mgx.subctxgm.nii.gz`.
- **Pipeline stage(s):** none in default
  `recon-all`. PET PVC analyses only.
- **Triggering configuration:** GTM
  segmentation that contains a `subcort_gm-mid`
  tissue class (this is a standard tissue-type
  in the GTM ctab — typically used for
  midline structures like brainstem-grey or
  fourth ventricle adjacent regions).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

The MGx PVC formula is
`PVC(r) = (y(r) − X(r,non-target) · β(non-target))
/ Σ_target X(r, target_seg)`.

For the first loop's view of "non-target
segs," `subcort_gm-mid` is excluded (zeroed in
`betaNotTarg`). So `X · betaNotTarg` is the
contribution from cortex, WM, CSF, etc. — but
not from any subcort GM.

For the second loop's `sum`, `subcort_gm-mid` is
excluded. So `sum` is `X[r, subcort_gm] +
X[r, subcort_gm-lh] + X[r, subcort_gm-rh]` —
missing the `-mid` column.

For a voxel `r` whose tissue distribution is,
say, 40% `subcort_gm-mid`, 20% `subcort_gm-lh`,
40% WM:

- `yNotTarg(r)` ≈ 0.4 · WM_β  
  (subcort GM contributions all zeroed)
- `ydiff(r)` ≈ y(r) − 0.4 · WM_β  
  (the "target signal", which legitimately
  includes both lh and mid contributions)
- `sum(r)` = `X[r, subcort_gm-lh]` ≈ 0.2  
  (mid is excluded)
- `mgx(r)` = `ydiff(r) / 0.2`

But the legitimate normaliser is 0.6 (lh + mid
fractions). The output is therefore inflated by
a factor of 3 — and worse, treats the recovered
signal as if it came purely from `subcort_gm-lh`
when 2/3 of it actually came from `mid`.

When the missing-mid voxels have *only* `mid`
content (no other subcort GM), `sum == 0`, the
threshold check at
[`:1652`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gtm.cpp#L1652)
fires (`sum < mgx_gmthresh`), and the voxel is
zeroed. So the output map shows zero where the
PET signal in mid-line subcortical structures
should appear.

## Root Cause

Copy-paste asymmetry. The two loops were
clearly meant to be inverse views of the same
target-set membership predicate, but the
second loop's `Target == 2` block was written
without the `-mid` clause that the first loop
has. The neighbouring `Target == 3` block
correctly mentions all four subcort GM
variants in both loops.

## Impact

- **`mgx.subctxgm.nii.gz`:** voxels that contain
  `subcort_gm-mid` are biased upward (because
  their contribution is removed but not
  normalised) or zeroed (when `sum < gmthresh`
  due to the missing `-mid` column).
- **Downstream PET analyses** that use
  `mgx.subctxgm.nii.gz` as input (regional
  uptake summaries, partial-volume-corrected
  ROI averages) inherit the bias.
- **Other targets unaffected:** `Target == 1`
  (cortex), `Target == 3` (any GM), and
  `Target == 4..8` (single-class lateralised)
  are internally consistent.
- **Severity:** 3 — flag-gated (`--mgx`),
  affects a specific output of an auxiliary
  tool. Real correctness defect in the
  affected target.

## Recommended Fix

```diff
--- a/utils/gtm.cpp
+++ b/utils/gtm.cpp
@@ -1626,11 +1626,12 @@ MRI *GTMmgxpvc(GTM *gtm, int Target)
       if(Target == 2){ // asking for subcort
 	if(strcmp("subcort_gm",cte->name)!=0 && 
 	   strcmp("subcort_gm-lh",cte->name)!=0 &&
-	   strcmp("subcort_gm-rh",cte->name)!=0) continue; // but this is not subcort
+	   strcmp("subcort_gm-rh",cte->name)!=0 &&
+	   strcmp("subcort_gm-mid",cte->name)!=0) continue; // but this is not subcort
       }
```

This adds `subcort_gm-mid` to the second
loop's `Target == 2` membership, matching the
first loop. The fix mirrors how `Target == 3`
already handles `-mid` in both loops.

## Workarounds

For PET analyses that need correct subcortical
GM PVC, use `--mgx` with `Target == 3`
(`mgx.gm.nii.gz`) and accept that cortex and
subcort are jointly normalised, or post-
process by re-running PVC on a
`subcort_gm-mid`-renamed segmentation.
