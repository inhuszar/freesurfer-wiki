# [severity-3] [bug-00024] Three VOL_GEOM equality implementations disagree on whether shear participates

> [!bug] Synopsis
> The `VOL_GEOM` struct has six direction-cosine columns (`x_r,x_a,x_s`,
> `y_r,y_a,y_s`, `z_r,z_a,z_s`), three centre offsets (`c_r,c_a,c_s`),
> and three shear components (`s_r,s_a,s_s`). FreeSurfer ships **three
> implementations** of "are these two `VOL_GEOM`s equal":
> the C-style free function `vg_isNotEqualThresh`, the member method
> `VOL_GEOM::isNotEqualThresh`, and the static method (also named
> `isNotEqualThresh`, used by `operator==`). Two of the three skip
> the shear components; only the static method (and therefore
> `operator==`) checks them. As a result, two `VOL_GEOM`s that differ
> only in shear are reported "equal" by `vg_isEqual()` and `vg.isEqual(&other)`
> but "not equal" by `vg == other`. The C-style routine is the one
> wired into `LTAconcat`, `LTAreduce`, `LTAmodifySrcDstGeom`, and
> surface-to-LTA validity checks, so this is the version that actually
> influences pipeline behaviour.

## Detailed Description

### Expected Behaviour

The single contract "two `VOL_GEOM`s are equal iff their geometric
content matches within tolerance" should be implemented once and
used by every caller. The three named entry points
(`vg_isEqual` / `vg_isNotEqualThresh`, the member methods, and
`operator==`) should agree, byte-for-byte, on what "equal" means.

### Observed Behaviour

The three implementations check different subsets of the struct:

| Entry point | File | Fields checked |
|-------------|------|----------------|
| `vg_isNotEqualThresh()` (free C function) | `utils/transform.cpp:600-622` | 19: valid, w/h/d, vox-sizes, x_r/a/s, y_r/a/s, z_r/a/s, c_r/a/s |
| `VOL_GEOM::isNotEqualThresh()` (member) | `utils/vol_geom.cpp:350-372` | 19: same as above |
| `VOL_GEOM::isNotEqualThresh()` (static) | `include/mri.h:379-404` | **22**: same 19 + s_r, s_a, s_s |

`vg_isEqual()` and `VOL_GEOM::isEqual()` both delegate to their
respective `isNotEqualThresh`, so they inherit the 19-field
behaviour. `operator==` delegates to the static method, so it
honours the 22-field behaviour. The same expression
`a.isEqual(&b)` and `a == b` therefore can give different verdicts.

The C function is the one used by every recon-all-relevant caller:

- [`utils/transform.cpp:3425-3427`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L3425-L3427)
  in `LTAconcat`: decides whether the new LTA's `xforms[0]` chains
  forward (`vg_isEqual(&prev->dst, &new->src)`) or needs inversion
  (`vg_isEqual(&prev->dst, &new->dst)`). A shear-only mismatch
  passes the forward check silently — the resulting concatenation
  is geometrically wrong.
- [`utils/transform.cpp:3494-3496`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L3494-L3496)
  in `LTAreduce`: same chain-match logic at the per-step level
  inside an existing LTA.
- [`utils/transform.cpp:3600`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L3600)
  in `LTAmodifySrcDstGeom`: decides whether the user-supplied `MRI`
  geometry matches the LTA's stored `src` / `dst` `VOL_GEOM`. A
  shear-only difference is treated as equal and the LTA is left
  with the wrong shear — a silent geometry corruption.

### Reproducer

```c
// Two VOL_GEOMs that differ only in shear:
VOL_GEOM a, b;
initVolGeom(&a);
initVolGeom(&b);
a.s_r = 0.05; a.s_a = -0.02; a.s_s = 0.0;   /* nontrivial shear */
b.s_r = 0.0;  b.s_a = 0.0;   b.s_s = 0.0;
printf("vg_isEqual:           %d\n", vg_isEqual(&a, &b));   /* 1 (equal) */
printf("a.isEqual(&b):        %d\n", a.isEqual(&b));        /* 1 (equal) */
printf("a == b:               %d\n", a == b);               /* 0 (not equal) */
```

```cpp
int vg_isNotEqualThresh(const VOL_GEOM *vg1, const VOL_GEOM *vg2, const double thresh)
{
  if (vg1->valid != vg2->valid) return (1);
  if (vg1->width != vg2->width) return (2);
  if (vg1->height != vg2->height) return (3);
  if (vg1->depth != vg2->depth) return (4);
  if (!FZEROTHR(vg1->xsize - vg2->xsize, thresh)) return (5);
  if (!FZEROTHR(vg1->ysize - vg2->ysize, thresh)) return (6);
  if (!FZEROTHR(vg1->zsize - vg2->zsize, thresh)) return (7);
  if (!FZEROTHR(vg1->x_r - vg2->x_r, thresh)) return (8);
  /* ... y_r, y_a, y_s, z_r, z_a, z_s, c_r, c_a, c_s ... */
  if (!FZEROTHR(vg1->c_s - vg2->c_s, thresh)) return (19);
  return (0);                                  /* ← returns "equal"
                                                  even if s_r/s_a/s_s differ */
}
```

Same omission at
[`utils/vol_geom.cpp:350-372`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/vol_geom.cpp#L350-L372)
(`VOL_GEOM::isNotEqualThresh` member). The static-method
counterpart at
[`include/mri.h:379-404`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mri.h#L379-L404)
shows the intended idiom — the same body extended with three more
checks:

```cpp
if (!FZEROTHR(vg1->s_r - vg2->s_r, thresh)) return (20);
if (!FZEROTHR(vg1->s_a - vg2->s_a, thresh)) return (21);
if (!FZEROTHR(vg1->s_s - vg2->s_s, thresh)) return (22);
return (0);
```

`VOL_GEOM` has had the shear fields since at least the move-from-MRI
refactor referenced in the comment at
[`include/mri.h:204-205`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mri.h#L204-L205);
the shear comparison in the static method was added with the
fields. The two older equality routines were not updated to match.

## Root Cause

When the shear fields `s_r`, `s_a`, `s_s` were added to `VOL_GEOM`
(see [`include/mri.h:201`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/include/mri.h#L201)),
only the new static method in `include/mri.h` was extended to check
them. The two pre-existing equality routines (the C free function
in `utils/transform.cpp` and the member method in
`utils/vol_geom.cpp`) were left checking the original 19 fields.
There is no test or contract document that pins all three
implementations together, and the duplicated bodies have drifted.

The shear-handling design is also inconsistent on the write side:
[`utils/transform.cpp:452-465`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L452-L465)
(`writeVolGeom`, the LTA-text-format serialiser) does **not** write
shear, so a round-trip through an LTA file silently zeroes the
shear. By contrast, the binary `fstagsio` path at
[`utils/fstagsio.cpp:294, 714, 1046`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/fstagsio.cpp#L1046)
**does** persist shear. So shear is sometimes preserved, sometimes
dropped, and the equality routine that's wired into the LTA chain
checks ignores shear in either case.

## Impact

- **`LTAconcat` chain validation
  ([`utils/transform.cpp:3421-3439`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L3421-L3439)).**
  The concat decides whether step _n_ chains forward off step
  _n − 1_'s `dst`, or needs to be inverted, based on
  `vg_isEqual(&prev->dst, &next->src)`. A shear-only mismatch is
  silently accepted as a forward chain — the concatenated transform
  no longer represents the composed warp because the geometry on
  either side of the join differs in shear.
- **`LTAreduce`
  ([`utils/transform.cpp:3490-3503`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L3490-L3503)).**
  Same logic at the intra-LTA level. A multi-step LTA reduced to
  one matrix may quietly drop shear differences between
  consecutive steps.
- **`LTAmodifySrcDstGeom`
  ([`utils/transform.cpp:3582-3640`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L3582-L3640)).**
  Decides whether to overwrite the LTA's stored `src` / `dst` from
  the user-supplied `MRI`. Shear-only differences are reported as
  equal, so the stored `VOL_GEOM` retains its (possibly stale)
  shear while the rest of its rotation/scale/centre is in sync —
  a hybrid geometry that does not correspond to either input.
- **Surface validity check
  ([`utils/mrisurf_metricProperties.cpp:2101-2102`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisurf_metricProperties.cpp#L2101-L2102)).**
  Diagnostic print under `Gdiag`; cosmetic but misleading.
- **GCAM atlas-LTA validation
  ([`utils/gcamorph.cpp:16358-16359`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/gcamorph.cpp#L16358-L16359)).**
  Diagnostic print used during `mri_ca_register`; same issue.
- **`operator==` vs `isEqual()` semantic split.** Any caller that
  relies on `a == b` and a peer that relies on `vg_isEqual(&a, &b)`
  will disagree on the same pair when shear differs. Users
  switching between idioms (or between C and C++ portions of the
  codebase) get inconsistent answers.
- **`writeVolGeom` round-trip drops shear.** A volume whose shear
  has been preserved through `MRIcopy` and propagated into an LTA
  loses the shear when the LTA is serialised to disk. On reload,
  the reload's `VOL_GEOM` differs from the in-memory original only
  in shear — and `vg_isEqual` reports them equal. The pipeline
  cannot detect the data loss.

## Recommended Fix

Make all three implementations share one body. Either:

(a) extend the two short-form routines with the missing shear
   checks, matching the static method:

```diff
   if (!FZEROTHR(vg1->c_s - vg2->c_s, thresh)) return (19);
+  if (!FZEROTHR(vg1->s_r - vg2->s_r, thresh)) return (20);
+  if (!FZEROTHR(vg1->s_a - vg2->s_a, thresh)) return (21);
+  if (!FZEROTHR(vg1->s_s - vg2->s_s, thresh)) return (22);
   return (0);
```

Apply this patch to both
[`utils/transform.cpp:600-622`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L600-L622)
and
[`utils/vol_geom.cpp:350-372`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/vol_geom.cpp#L350-L372).

(b) (preferred long-term) collapse the three implementations into
   one — make the C function a thin wrapper around the static
   method, and have `VOL_GEOM::isNotEqualThresh` (member) call the
   static method too. This eliminates the drift surface entirely.

In addition, fix the writer
[`utils/transform.cpp:452-465`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L452-L465)
(`writeVolGeom`) to persist shear, and the reader
[`utils/transform.cpp:467-...`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/transform.cpp#L467)
(`readVolGeom`) to parse it. Otherwise even a fixed equality test
will trip on shear that disappears across LTA round-trip.

### Alternative Fixes Considered

- **Drop shear from the static method instead.** This makes all
  three agree but loses the only correct equality test, and stales
  the binary serialisation of shear. Rejected.
- **Document the divergence and add a comment.** Documentation
  doesn't fix the LTA chain-validation defect; rejected.

## Workarounds (If Any)

- A caller that wants a shear-aware comparison from C code can
  invoke the static method directly: `VOL_GEOM::isNotEqualThresh(&a,
  &b, thresh)`.
- A caller that wants to ensure shear is zero before comparing can
  call `shearless_components()` on both inputs first — but note
  that this routine has the positive-shear-only gating defect
  documented in [[00015]] and skips negative shears.
