# [severity-3] [bug-00158] histo_compute_joint_density — second volume's pyramid is built from the first volume (copy-paste source)

> [!bug] Synopsis
> When `histo_compute_joint_density` builds its multi-resolution Gaussian
> pyramid, the level-`L` reduction of the **second** volume is computed
> from the **first** volume's pyramid instead of the second's:
> `mri2_pyramid[level] = MRIreduce2D(mri1_pyramid[level-1], NULL)`. Only
> the base level (`level 0`) of volume 2 is its own data; every reduced
> level is a down-sampled copy of volume 1. The joint density estimated at
> any level above 0 is therefore the auto-density of volume 1, not the
> cross-density of the two volumes. The defect only matters when more than
> one pyramid level is actually used (`-nlevels > 1`); the default
> `nlevels = 1` reads only level 0 and is unaffected.

## Affected Artefacts

- **Tool(s):** [[histo_compute_joint_density]]. The estimated densities
  feed [[histo_register_block]] as the coarse-to-fine cost model, so a
  wrong coarse-level density propagates into the block-to-histology
  alignment when a multi-level registration is run.
- **Pipeline stage(s):** _N/A_ — this is a standalone histology /
  block-face registration helper, not part of
  [[wiki/pipelines/recon-all|recon-all]].
- **FreeSurfer version(s):** confirmed in `8.2.0` at commit `d932c45`;
  earliest known: _unknown_.
- **Platforms:** all — purely a wrong array index in the pyramid build.
- **Triggering configuration:** `histo_compute_joint_density -nlevels N
  vol1 vol2 density` with `N >= 2`. With the default `nlevels = 1` only
  `density_level0.den` is written, and level 0 of volume 2 is correct, so
  the defect is latent.

## Detailed Description

`main()` reads two input volumes (`mri1`, `mri2`), reserves intensity 0 for
background in each, and then constructs a fixed-depth (`MAX_LEVELS = 10`)
Gaussian pyramid for both, storing the levels in `mri1_pyramid[]` and
`mri2_pyramid[]`. Level 0 of each pyramid is the corresponding input
volume; each higher level is meant to be the `MRIreduce2D` (2-D Gaussian
reduce) of the **same** volume's previous level.

The reduction loop builds `mri1_pyramid[level]` correctly from
`mri1_pyramid[level-1]`, but builds `mri2_pyramid[level]` **also** from
`mri1_pyramid[level-1]`. So for every `level >= 1`, `mri2_pyramid[level]`
is a reduced copy of volume 1, identical (up to the same reduction) to
`mri1_pyramid[level]`. Only `mri2_pyramid[0] = mri2` carries volume 2's
data.

The density loop then calls
`DensityHistogramEstimate(mri1_pyramid[level], mri2_pyramid[level], ...)`
for `level = nlevels-1 .. 0`. At any `level >= 1` the two arguments are
effectively the same image (both derived from volume 1), so the "joint"
density is really the joint density of volume 1 with itself — concentrated
on the diagonal — rather than the intended cross-modality density of
volume 1 vs. volume 2.

### Expected Behaviour

For each pyramid level `L`, `mri2_pyramid[L]` should be the `MRIreduce2D`
of `mri2_pyramid[L-1]`, so that
`DensityHistogramEstimate(mri1_pyramid[L], mri2_pyramid[L], ...)` estimates
the joint intensity distribution of the two distinct volumes at that
resolution. The level-`L` density file should describe how volume-1
intensities co-occur with volume-2 intensities at scale `L`.

### Observed Behaviour

`mri2_pyramid[L]` for `L >= 1` is a down-sampled copy of volume 1. The
density written to `density_levelL.den` (for `L >= 1`) is the auto-density
of volume 1, with all mass on or near the diagonal, instead of the true
cross-density. Level-0 output (`density_level0.den`) is correct because it
uses `mri1_pyramid[0] = mri1` and `mri2_pyramid[0] = mri2`. The loop also
unconditionally builds all `MAX_LEVELS` levels and writes debug volumes
`h%d.mgz` / `b%d.mgz`; the `b%d.mgz` files (purporting to show volume 2's
pyramid) are actually volume 1's reductions, which is a visible symptom.

### Reproducer

> [!gap] Reproducer not executed end-to-end
> A direct demonstration with two visibly different 2-D inputs:
>
> 1. Take two distinct single-slice volumes `vol1.mgz` and `vol2.mgz`
>    (e.g. a Nissl histology slice and its block-face photograph).
> 2. Run `histo_compute_joint_density -nlevels 3 vol1.mgz vol2.mgz out`.
> 3. Inspect the side-effect files `b1.mgz` / `b2.mgz`: they are reduced
>    copies of `vol1`, identical to `h1.mgz` / `h2.mgz`, instead of
>    reductions of `vol2`.
> 4. Compare `out_level0.den` (correct cross-density) with
>    `out_level1.den` / `out_level2.den` (collapsed onto the diagonal,
>    i.e. auto-density of `vol1`).

## Root Cause

A copy-paste error in the second `MRIreduce2D` call: the source argument
was left as `mri1_pyramid[level-1]` instead of being updated to
`mri2_pyramid[level-1]`. The two lines are otherwise identical, which is
the classic signature of a duplicated-then-incompletely-edited statement.

## Impact

- For multi-level runs (`-nlevels >= 2`), every density file above
  level 0 is wrong: it describes volume 1 against itself rather than
  volume 1 against volume 2. A coarse-to-fine registration in
  [[histo_register_block]] that consumes those files therefore optimises
  against a meaningless coarse cost at the upper pyramid levels, which can
  mis-seed or destabilise the fine-level alignment.
- The default invocation (`nlevels = 1`) writes only `*_level0.den`,
  which is correct, so the most common usage is unaffected. The bug is
  **gated behind the `-nlevels` flag**, which fixes the severity at
  **3 (medium)** rather than 4: wrong output only when the user opts into
  the multi-resolution mode.
- No crash and no error message — the wrong densities are written
  silently, so a user running multi-level registration would have no
  obvious signal that the coarse models are degenerate.

## Recommended Fix

Reduce the second pyramid from the second volume's own previous level:

```diff
   for (level = 1 ; level < MAX_LEVELS ; level++) {
     mri1_pyramid[level] = MRIreduce2D(mri1_pyramid[level-1], NULL) ;
-    mri2_pyramid[level] = MRIreduce2D(mri1_pyramid[level-1], NULL) ;
+    mri2_pyramid[level] = MRIreduce2D(mri2_pyramid[level-1], NULL) ;
     sprintf(fname, "h%d.mgz", level) ;
     MRIwrite(mri1_pyramid[level], fname) ;
     sprintf(fname, "b%d.mgz", level) ;
     MRIwrite(mri2_pyramid[level], fname) ;
   }
```

After the change, each volume's pyramid is built from its own data and the
level-`L` density estimate is a genuine cross-density.

### Alternative Fixes Considered

None needed — the single index correction fully addresses the defect.
(Optionally, the loop could build only `nlevels` levels rather than all
`MAX_LEVELS`, avoiding wasted `MRIreduce2D` work and stray `h*/b*.mgz`
debug files, but that is an efficiency/cleanup concern, not part of this
bug.)

## Workarounds (If Any)

Run only at the default single level (`nlevels = 1`), where level 0 is
correct, and avoid the multi-resolution path until the index is fixed.
