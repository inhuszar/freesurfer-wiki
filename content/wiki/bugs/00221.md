# [severity-2] [bug-00221] `exportGcam` — `GCAMwrite` result ignored; `--test` aborts with `--bbox_threshold`

> [!bug] Synopsis
> `exportGcam` calls `GCAMwrite(gcam, out)` and discards the return value.
> `GCAMwrite` returns an error without writing for an output name whose
> extension it does not recognise (for example `.txt`) and when the file
> cannot be opened, so the tool prints a progress message, exits with status
> 0 and leaves no output; shell callers that test `$status` (as
> `mri_cvs_register` does) cannot detect it. Two further input-validation
> gaps in the same driver: `--test` together with `--bbox_threshold` always
> aborts (exit 252) in the verification step, after the m3z has been
> written; and a `--bbox_threshold` that selects no voxel gives a bounding
> box with negative dimensions that is passed unchecked to `GCAMalloc`.

## Affected Artefacts

- **Tool(s):** [[exportGcam]]; [[mri_cvs_register]] is the only in-tree caller (it never uses `--test` or `--bbox_threshold`, and passes an `.m3z` name)
- **Pipeline stage(s):** `mri_cvs_register` elastic step (the missing-file case would pass the script's status check); see Impact
- **FreeSurfer version(s):** confirmed in 8.2.0; the unchecked `GCAMwrite` dates from the addition of `exportGcam` (commit `b357df5fd81`, 2008-06-17), the `(... || 1)` condition from `4c4093f4911` (2010-04-20)
- **Platforms:** all
- **Triggering configuration:** (a) `--out_gcam` with an extension other than `.m3z`/`.m3d`/`.mgz`/`.nii`/`.nii.gz`, or in a directory that does not exist or is not writable; (b) `--test` with `--bbox_threshold`; (c) `--bbox_threshold N` with `N` greater than or equal to the maximum of the fixed volume.

## Detailed Description

### Expected Behaviour

A failed export must give a non-zero exit status and no (or a clearly
flagged) output; options that the tool accepts together must not abort the
tool; an empty bounding box should be diagnosed.

### Observed Behaviour

**(a) Failed write is silent.** `GCAMwrite` selects the container from the
output file name ([`utils/gcamorph.cpp:352-363`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/gcamorph.cpp#L352-L363)):
`mri_identify` classifies the name, `.m3z`/`.m3d` go to `__m3zWrite`,
`.mgz`/`.nii` to the warp-field writer, anything else returns
`ERROR_BADPARM` with nothing written. `__m3zWrite` also returns an error
when the file cannot be opened
([`utils/gcamorph.cpp:387-391`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/gcamorph.cpp#L387-L391)).
`main()` does not look at the return value, continues with the intensity
normalisation, and returns 0.

The sibling call sites in `surf2vol -gcam` ignore the return value in the same way
([`fem_elastic/fsurf2vol.cpp:660-661`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L660-L661), [`fem_elastic/fsurf2vol.cpp:716-717`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L716-L717)); they are not covered by this page's reproducer.

**(b) `--test` with `--bbox_threshold` aborts.** The verification step
resamples the moving volume with `GCAMmorphToAtlas(mriMoving, gcam, mriFixed,
...)`, passing the full-size fixed volume as output buffer. With a bounding
box the GCAM atlas is smaller, and `GCAMmorphToAtlas` calls `ErrorExit` when
the output size differs from the atlas size. The condition guarding the step,
`params.doTest && (!params.useBoundingBox || 1)`, is always true for
`--test`, so the combination can never work. The m3z has already been written
at that point, so the file exists but the exit status is non-zero.

**(c) Empty bounding box.** `MRIboundingBox` initialises the box origin to
the far corner and the maximum to 0, so when no voxel exceeds the threshold
the computed dimensions are `max - origin + 1 < 0`. `VolumeMorph::exportGcam`
adds the padding and passes the negative sizes to `GCAMalloc`, which fails
(out-of-memory style message) and the process exits non-zero without a
file. The failure is loud but the cause (an empty box) is never diagnosed.

### Reproducer

Synthetic: a 32^3 fixed volume equal to 100 in the block `[8:24, 10:22,
6:26]` (zero elsewhere), a 32^3 moving volume, and a hand-built `.tm3d`
holding one `id` (identity) transform with valid geometries
(`ident.tm3d`). `<W>` is an absolute scratch directory.

```bash
C="--fixed fixed.mgz --moving moving.mgz --morph ident.tm3d"
# (a) unknown extension, and a non-existent output directory
exportGcam $C --out_gcam <W>/bad.txt            ; echo "rc=$?" ; ls <W>/bad.txt
exportGcam $C --out_gcam /nonexistent_dir/x.m3z ; echo "rc=$?"
# (b) --test with a bounding box
exportGcam $C --out_gcam <W>/t.m3z --test --bbox_threshold 0 ; echo "rc=$?" ; ls -l <W>/t.m3z
# (c) empty box
exportGcam $C --out_gcam <W>/big.m3z --bbox_threshold 1000   ; echo "rc=$?" ; ls <W>/big.m3z
```

Observed with the installed 8.2.0 binary:

| Case | Exit status | File | Messages |
|------|-------------|------|----------|
| (a) `bad.txt` | **0** | none (`ls: cannot access`) | only the progress line `GCAMwrite(<W>/bad.txt)`; no error text |
| (a) `/nonexistent_dir/x.m3z` | **0** | none | `error: GCAMwrite(/nonexistent_dir/x.m3z): could not open file`, then normal completion messages |
| (b) `--test --bbox_threshold 0` | 252 | `t.m3z` written (22 270 bytes) | `applying morph`, `width = 18`, `error: invalid input MRI size for GCAMmorphToAtlas()` |
| (c) `--bbox_threshold 1000` | 254 | none | `box = 30 , 30 , 30 / -28 , -28 , -28`, `error: Cannot allocate memory`, `error: GCAMalloc: could not allocate nodes` |
| control: plain run, `ok.m3z` | 0 | written (130 612 bytes) | |

(For (a), an unwritable existing directory was also tried: it exited 0 and
produced no file, but printed no error text in my run; the reason was not
investigated.)

## Root Cause

(a) `GCAMwrite` reports failure through its `int` return value (and, for
open failures, a printed error), but `main()` ignores it and has no other
check that the file exists. (b) The condition that gates the verification step contains an `|| 1`
(this form comes from commit `4c4093f4911`, "Fixed the testing option"), so
the step runs also when the GCAM atlas is a cropped box, for
which `GCAMmorphToAtlas` cannot work with a full-size output volume. (c) The
box returned by `MRIboundingBox` is not tested for `dx, dy, dz > 0` before it
is used as the GCAM size.

## Impact

- **Silent missing output, exit 0 (case a).** The only in-tree caller always
  passes an `.m3z` file in the output directory it has created, so the case
  does not arise in `mri_cvs_register` unless the filesystem refuses the
  write; there the script's `if($status) exit 1` after `exportGcam` would
  not trigger, and the failure would surface only when a later step reads the
  missing `.m3z`. A user script with a mistyped extension is told nothing.
- **Cases (b) and (c) are loud** (non-zero exit with an error message) and
  only affect diagnostic/opt-in options; (b) leaves a valid m3z behind (see
  [[00212]] for its node positions).
- **Severity 2, not 3.** No default pipeline path or in-tree invocation
  triggers any of the three cases; (b) and (c) fail visibly and (a) needs a
  caller error (bad extension, unwritable location) that the one in-tree
  caller does not make, so this is "latent under typical conditions". The
  silent exit-0 of (a) is the reason it is recorded as a bug and not merely a
  gotcha.

## Recommended Fix

Check the write, and make the option combination and the box valid:

```diff
-  GCAMwrite( gcam,
-             const_cast<char*>
-             (params.strGcam.c_str()));
+  if ( GCAMwrite( gcam,
+                  const_cast<char*>
+                  (params.strGcam.c_str())) != NO_ERROR )
+  {
+    std::cerr << " Failed writing GCAM " << params.strGcam << std::endl;
+    exit(1);
+  }
```

```diff
-  if ( params.doTest && (!params.useBoundingBox || 1) )
+  if ( params.doTest && !params.useBoundingBox )
```

and, in `VolumeMorph::exportGcam`, after the box and padding are computed:

```diff
+  if ( box.dx <= 0 || box.dy <= 0 || box.dz <= 0 )
+    throw "VolumeMorph exportGcam -> empty bounding box (threshold too high?)";
```

(`exportGcam.cpp` currently does not wrap that call in a `try/catch`, so
the `throw` should be caught in `main()` and turned into exit status 1.) A
`GCAMwrite` error on `NULL gcam` (when `exportGcam()` returns NULL) should be
checked in the same place. Regression tests: the four commands above must
give exit 1 for (a) and (c), and exit 0 for (b) without crashing.

## Workarounds (If Any)

Use an `.m3z` name in an existing writable directory and check that the file
exists after the call (do not rely on the exit status); do not combine
`--test` with `--bbox_threshold`; choose `--bbox_threshold` below the maximum
of the fixed volume.
