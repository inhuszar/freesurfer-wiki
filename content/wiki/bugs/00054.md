# [severity-2] [bug-00054] `MRIvol2surfVSM` — `VSMvox2vox` allocation never freed

> [!bug] Synopsis
> `MRIvol2surfVSM`
> ([`utils/mri2.cpp:3294-3523`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L3294-L3523))
> resamples a volume onto a surface, optionally
> applying a voxel-shift map (VSM) for EPI distortion
> correction. When the caller supplies a non-NULL
> `vsmlta`, the function allocates `VSMvox2vox` at
> [`:3336`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L3336):
>
> ```cpp
> if(vsmlta){
>   LTA *ltacopy = LTAcopy(vsmlta,NULL);
>   LTAchangeType(ltacopy, LINEAR_VOX_TO_VOX);
>   VSMvox2vox = MatrixCopy(ltacopy->xforms[0].m_L,NULL);   /* :3336 */
>   LTAfree(&ltacopy);
> }
> ```
>
> The cleanup block at
> [`:3516-3518`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L3516-L3518)
> frees `ras2vox`, `valvect`, and `bspline` but never
> frees `VSMvox2vox`. Each call leaks one MATRIX (4×4
> double, ~150 B with header).
>
> The function is called inside the BBR cost gradient
> in [`mri_segreg`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segreg/mri_segreg.cpp)
> ([`mri_segreg.cpp:2182`,
> `:2183`,
> `:2188`,
> `:2189`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_segreg/mri_segreg.cpp#L2182-L2189)
> per Powell iteration × hemisphere × {white,
> pial}). Powell optimisation typically takes hundreds
> to thousands of cost evaluations, so the leak grows
> proportionally.

## Affected Artefacts

- **Tool:** [[mri_segreg]] when `--vsm` is used
  (i.e. EPI distortion correction during boundary-based
  registration). Also any other consumer that calls
  `MRIvol2surfVSM` with a non-NULL `vsmlta` (e.g.
  `mri_vol2surf` in some configurations).
- **Pipeline stage(s):** none in default `recon-all`.
  fMRI / DWI registration pipelines that pass a VSM
  trip the leak.
- **Triggering configuration:** any `MRIvol2surfVSM`
  call with `vsmlta != NULL`. Calls with `vsmlta ==
  NULL` are unaffected (the alloc at `:3336` is
  guarded).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

Allocation:

```cpp
if (vsm) {
  ...
  if(vsmlta){
    LTA *ltacopy = LTAcopy(vsmlta,NULL);
    LTAchangeType(ltacopy, LINEAR_VOX_TO_VOX);
    VSMvox2vox = MatrixCopy(ltacopy->xforms[0].m_L,NULL);    /* :3336 */
    LTAfree(&ltacopy);
  }
}
```

Cleanup:

```cpp
MatrixFree(&ras2vox);
free(valvect);
if (bspline) MRIfreeBSpline(&bspline);
return (TrgVol);                                              /* :3516-3522 */
```

`VSMvox2vox` is consumed inside the per-vertex loop at
[`:3452`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L3452):
`vsmcrs2 = MatrixMultiplyD(VSMvox2vox, vsmcrs, NULL);` —
where the *output* `vsmcrs2` is correctly freed each
iteration. The matrix that needs to survive across
iterations (`VSMvox2vox`) lacks a corresponding
`MatrixFree` at function exit.

## Root Cause

The cleanup block at function exit was written before
the VSM LTA support was added; the `VSMvox2vox` alloc
was inserted at `:3336` but the matching `MatrixFree`
was never appended.

## Impact

- **Per call:** one ~150 B matrix leak.
- **`mri_segreg` BBR with VSM:** Powell optimisation
  typically performs N ≈ 500–5000 cost evaluations.
  Each evaluation calls `GetSurfCosts` once, which
  calls `MRIvol2surfVSM` 4× (lh white, lh pial, rh
  white, rh pial). Total leak: ≈ 4 × N × 150 B ≈
  300 KB – 3 MB per registration. Not a crash trigger,
  but visible in long-running pipelines (e.g.
  per-subject longitudinal BBR).
- **No correctness defect** — only memory pressure.

## Recommended Fix

```diff
--- a/utils/mri2.cpp
+++ b/utils/mri2.cpp
@@ -3514,6 +3514,7 @@ MRI *MRIvol2surfVSM(...)
   #endif

   MatrixFree(&ras2vox);
+  if (VSMvox2vox) MatrixFree(&VSMvox2vox);
   free(valvect);
   if (bspline) MRIfreeBSpline(&bspline);
```

`VSMvox2vox` is initialised to `NULL` at
[`:3307`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri2.cpp#L3307),
so the conditional free is safe whether or not
`vsmlta` was supplied.

## Workarounds

Run `mri_segreg` (or any pipeline using
`MRIvol2surfVSM` with VSM) under a memory budget large
enough to absorb the leak. For long-running batch
pipelines, restart the process between subjects.

## Provenance and Discovery

- **Discovered:** 2026-04-30 by agent (memory-leak
  audit on resampling utilities).
- **Evidence:** allocation at `:3336`; cleanup block
  at `:3516-3518` lists every other tracked matrix
  except `VSMvox2vox`.
