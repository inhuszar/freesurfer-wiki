# [severity-3] [bug-00057] `HISTOrobustGaussianFit` — asymmetric narrow-window expansion

> [!bug] Synopsis
> `HISTOrobustGaussianFit`
> ([`utils/histo.cpp:1667-1750`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/histo.cpp#L1667-L1750))
> fits a Gaussian to the central region of a histogram
> bracketed by `[min_bin, max_bin]`. When the
> candidate window is narrower than `MIN_BINS = 12`,
> the function widens it symmetrically:
>
> ```cpp
> if (max_bin - min_bin < MIN_BINS) {
>   max_bin += (MIN_BINS - (max_bin - min_bin)) / 2;     // :1713
>   min_bin -= (MIN_BINS - (max_bin - min_bin)) / 2;     // :1714
>   min_bin = MAX(0, min_bin);
>   max_bin = MIN(hz->nbins - 1, max_bin);
> }
> ```
>
> Line 1714 reads `(max_bin - min_bin)` **after** line
> 1713 already grew `max_bin`. Suppose the initial
> width is 4 and `MIN_BINS = 12`: the intended
> expansion is to add 4 to each side. Actual
> behaviour:
>
> - line 1713: `max_bin += (12-4)/2 = 4`. Width is now 8.
> - line 1714: `min_bin -= (12-8)/2 = 2`. Width is now 10.
>
> Result: a 10-bin window, not the intended 12. The
> expansion is asymmetric and short-of-target. For
> very narrow input windows (width 0..2), the
> shortfall is larger.

## Affected Artefacts

- **Function call sites:** `HISTOrobustGaussianFit` is
  used by class-statistics and intensity-normalisation
  helpers. Direct callers in-tree:
  - `utils/histo.cpp` itself (uses `HISTOrobustGaussianFit`
    indirectly).
  - `utils/mrifilter.cpp:5508` (`MRIcomputeClassStatistics`)
    debug branch.
  - Various `utils/mri_em_register.cpp` and `utils/gca.cpp`
    paths.
- **Pipeline stage(s):** indirect; affects any tool
  whose intensity normalisation depends on a robust
  Gaussian fit to a narrow histogram window.
- **Triggering configuration:** any input where the
  initial `[min_bin, max_bin]` window from
  `HISTOfindBin(hz, ±thresh)` is narrower than 12
  bins (i.e. when the histogram has a sharp peak with
  very little spread, common for tightly-clustered
  intensity classes).
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

The shape of the bug — read-after-write of the same
expression — produces a deterministic shortfall:

| Initial width | Intended add | Actual add | Final width |
|--------------:|-------------:|-----------:|------------:|
| 0             | 6 + 6        | 6 + 3      |  9          |
| 2             | 5 + 5        | 5 + 3      |  10         |
| 4             | 4 + 4        | 4 + 2      |  10         |
| 6             | 3 + 3        | 3 + 1      |  10         |
| 8             | 2 + 2        | 2 + 1      |  11         |
| 10            | 1 + 1        | 1 + 0      |  11         |

The window is always biased toward higher bin indices
(more bins added to the `max_bin` side) and falls
short of `MIN_BINS = 12`. The two `MAX/MIN` clamps at
`:1715-1716` then constrain the final indices to the
histogram bounds.

Concretely: the Gaussian fit operates on a smaller
window than intended, with a slight bias toward the
right tail. For a symmetric distribution this biases
the fitted mean toward higher values; for a skewed
distribution the effect depends on which side the
asymmetry lies.

## Root Cause

Read-after-write on the expression `(max_bin -
min_bin)`. The author wrote both adjustments inline
without caching the deficit, so the second
adjustment sees a different window width than the
first.

## Impact

- **Within `HISTOrobustGaussianFit`:** the Gaussian
  fit window is up to 25 % narrower than intended for
  the most extreme initial-width-0 case, with a slight
  rightward bias. The fit is still bounded and
  produces a valid `sigma`; the impact on `sigma`
  precision depends on histogram shape and is
  typically < 1 bin.
- **Downstream:** any consumer of the returned
  `sigma`/`mean` sees a slight bias. Class-statistics
  computation in surface placement uses this for the
  white/gray boundary detection — sub-pixel impact.
- **Magnitude:** small; this is a numerics-quality
  defect, not a correctness defect.

## Recommended Fix

Cache the deficit before applying:

```diff
--- a/utils/histo.cpp
+++ b/utils/histo.cpp
@@ -1710,8 +1710,9 @@ int HISTOrobustGaussianFit(HISTOGRAM *h, double max_percentile, double *poffset,
   }
 #define MIN_BINS 12  // need enough data to estimate parameters of gaussian
   if (max_bin - min_bin < MIN_BINS) {
-    max_bin += (MIN_BINS - (max_bin - min_bin)) / 2;
-    min_bin -= (MIN_BINS - (max_bin - min_bin)) / 2;
+    int deficit = MIN_BINS - (max_bin - min_bin);
+    max_bin += deficit / 2;
+    min_bin -= deficit - (deficit / 2);   // ensure full deficit is split, rounding to min_bin side
     min_bin = MAX(0, min_bin);
     max_bin = MIN(hz->nbins - 1, max_bin);
   }
```

Using `deficit / 2` and `deficit - deficit / 2`
guarantees the full deficit is consumed even for odd
`deficit`. The final `min_bin = MAX(0, ...)` and
`max_bin = MIN(nbins-1, ...)` clamps still apply.

## Workarounds

None — the fit returns a usable answer; the
sub-bin-precision bias is hard to observe without an
A/B test.
