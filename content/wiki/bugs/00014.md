# [severity-2] [bug-00014] MRISisSurfaceValid — diagnostic printout double-counts single-face and multi-face edges

> [!bug] Synopsis
> `MRISisSurfaceValid` walks every vertex of a surface and, for each
> of that vertex's one-ring neighbours, counts how many faces contain
> the edge `(n, vnop)`. The loop explicitly knows it visits each edge
> twice — once from each endpoint — and divides the raw edge total
> `nedges` by `2` at the end to compensate. It forgets to apply the
> same division to the defective-edge counters `nffs` (single-face
> edges) and `nffm` (edges in more than two faces). Both counters
> therefore emerge at exactly twice the true number of defective
> edges, and the "Surface Diagnostics" printout that quotes them
> reports 2× the actual problem count. The binary return value
> (valid vs. invalid) is unaffected because any non-zero defect
> count, doubled or not, trips the "invalid" verdict.

## Detailed Description

Inside `MRISisSurfaceValid`, the outer loop visits every vertex `n`
of the surface and walks its one-ring:

```cpp
nffm = nffs = 0;
nedges = 0;
for (n = 0; n < mris->nvertices; n++) {
  VERTEX_TOPOLOGY const * const vn = &mris->vertices_topology[n];
  nedges += vn->vnum;
  for (p = 0; p < vn->vnum; p++) {
    vnop = vn->v[p];
    /* counts the # of faces that contain the edge n<-->vnop */
    cf = 0;
    for (m = 0; m < vn->num; m++) { ... count ... }
    if (cf < 2) { nffs++; }
    if (cf > 2) { nffm++; }
    ...
  }
}
nedges /= 2;
```

Each undirected edge `{n, vnop}` is encountered twice: once when
the outer loop reaches `n` and the inner loop reaches `vnop`, and
once the other way around. The author recognises that on the
`nedges` total and divides it by `2` on line 1748 to recover the
true edge count. The same correction is **not** applied to `nffs`
and `nffm`, even though they were incremented inside the same
edge-visiting loop.

### Expected Behaviour

The diagnostic printout should show the true number of defective
edges: one for each single-face or more-than-two-face edge in the
surface. A surface with exactly one "hole seam" contributing one
single-face edge should report `1`, not `2`.

### Observed Behaviour

The line

```
   # of edges with single face          %d
   # of edges with more than 2 faces    %d
```

always reports twice the true count. A surface that actually has
`k` edges incident to only one face prints `2k`; one with `k`
edges shared by more than two faces prints `2k`.

The binary return value of `MRISisSurfaceValid` is unaffected —
`nffs != 0` ⇔ `2 * nffs != 0`, so the "valid / invalid" verdict is
correct regardless of the doubling.

- **File:** `utils/mrisurf_topology.cpp`
- **Function:** `MRISisSurfaceValid()`
- **Lines:** `1688–1833` (full function); key defect window at
  `1714–1747` (the counting loop) and `1748–1824` (the
  half-corrective divide and the printout that forgets it)
- **Commit:** `d932c45b79`

```cpp
int MRISisSurfaceValid(MRIS *mris, int patch, int verbose)
{
  int n, m, p, q, vnop, nfound, mark;
  int euler, nedges, nvf, nffm, nffs, cf, nvc;
  FACE *fm;

  /* ... nvf pass elided ... */

  // check if some faces have more than 2 neighbors
  if (verbose == 2) {
    fprintf(stderr, "\nchecking for single or multiple faces...\n");
  }
  nffm = nffs = 0;
  nedges = 0;
  for (n = 0; n < mris->nvertices; n++) {
    VERTEX_TOPOLOGY const * const vn = &mris->vertices_topology[n];
    nedges += vn->vnum;
    for (p = 0; p < vn->vnum; p++) {
      vnop = vn->v[p];
      /* counts the # of faces that contain the edge n<-->vnop */
      cf = 0;
      for (m = 0; m < vn->num; m++) {
        fm = &mris->faces[vn->f[m]];
        for (q = 0; q < 3; q++) {
          if (fm->v[q] == vnop) { cf++; break; }
        }
      }
      if (cf < 2) { nffs++; }
      if (cf > 2) { nffm++; }
      if (verbose == 2) {
        if (cf < 2 && patch == 0) {
          fprintf(stderr, "edge %d <--> %d : single face\n", n, vnop);
        }
        if (cf > 2) {
          fprintf(stderr, "edge %d <--> %d : multiple face\n", n, vnop);
        }
      }
    }
  }
  nedges /= 2;                                      // ← halves nedges only
  euler = mris->nvertices - nedges + mris->nfaces;
  /* ... nvc pass elided ... */

  if (verbose)
    fprintf(stderr,
            "Surface Diagnostics:       \n"
            "   eno=%d (nv=%d, nf=%d, ne=%d)\n"
            "   # of border vertices [ #v ~ #f ]     %d \n"
            "   # of edges with single face          %d \n"
            "   # of edges with more than 2 faces    %d \n"
            "   # of corner configurations           %d\n",
            euler,
            mris->nvertices,
            mris->nfaces,
            nedges,
            nvf,
            nffs,                                   // ← not halved
            nffm,                                   // ← not halved
            nvc);

  if (patch && (nffm || nvc)) { return 0; }
  else if (nvf || nffs || nffm || nvc) { return 0; }
  return 1;
}
```

Note that the inner `verbose == 2` block at
[`utils/mrisurf_topology.cpp:1738–1744`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/mrisurf_topology.cpp#L1738-L1744)
also prints each defective edge twice (once per endpoint), which
confirms the double-visit pattern.

## Root Cause

The original author understood the double-visit structure of the
vertex-ring walk — `nedges /= 2;` on line 1748 is an explicit
correction for it. The same correction was simply not propagated
to the two defect counters added to the same loop body. The
inner `verbose == 2` edge-by-edge printout was likewise never
deduplicated, which is why enabling `verbose == 2` visibly prints
each defective edge twice.

## Impact

- The "# of edges with single face" and "# of edges with more
  than 2 faces" lines in the surface-diagnostic printout are
  always exactly twice the true counts.
- `mris_topo_fixer`'s log after topology correction therefore
  over-reports the residual defect count; a user eyeballing the
  log to check whether the fixer succeeded will see, for example,
  "4 edges with single face" when the surface actually has two.
- The `return` value at
  [`utils/mrisurf_topology.cpp:1826–1832`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/mrisurf_topology.cpp#L1826-L1832)
  is binary (`0 / 1`) and is computed from `nffs || nffm` etc.,
  which is invariant to the factor-of-2 doubling — so the
  valid/invalid verdict returned to [[mris_topo_fixer]] is still
  correct.

## Recommended Fix

Divide `nffs` and `nffm` by `2` alongside `nedges`:

```diff
-  nedges /= 2;
+  nedges /= 2;
+  nffs   /= 2;
+  nffm   /= 2;
   euler = mris->nvertices - nedges + mris->nfaces;
```

The `verbose == 2` edge-by-edge prints could also be gated with
`if (vnop > n)` so that each defective edge is reported only
once, but that is a cosmetic improvement and not required for
the numbers to be correct.

### Alternative Fixes Considered

Restructure the loop to iterate edges once (using the standard
`vnop > n` trick on the inner loop, exactly as the existing
`MRIScomputeEulerNumber`
([`utils/mrisurf_topology.cpp:528–559`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/utils/mrisurf_topology.cpp#L528-L559))
already does). That eliminates the double-count at source and
simplifies the logic, but is a larger change than the one-line
division and disturbs the surrounding `corner configuration`
check which is keyed off the same vertex-ring walk.

## Workarounds (If Any)

Users reading `mris_topo_fixer` logs should halve the reported
"single face" and "more than 2 faces" counts.

## Confidence and Gaps

> [!gap] Surfaces with boundaries (patches)
> The fix assumes the surface is a closed manifold, where every
> defective edge is guaranteed to be visited from both endpoints.
> On open patches (`patch != 0`), a boundary edge may have one
> endpoint rip-flagged or otherwise unwalked; whether this
> violates the double-visit assumption is worth verifying for
> the `patch == 1` code path in `mris_topo_fixer`.
