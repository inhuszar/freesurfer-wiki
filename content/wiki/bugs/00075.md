# [severity-3] [bug-00075] `MRIremoveVolumeIslands` — keeps clusters by peak value, not by size

> [!bug] Synopsis
> `MRIremoveVolumeIslands`
> ([`utils/volcluster.cpp:2056-2103`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/volcluster.cpp#L2056-L2103))
> is documented as "Binarizes mask, then keeps `nKeep`
> largest islands." The implementation calls
> `clustGetClusters` and then writes back voxels
> whose cluster index is `<= nKeep`. The cluster
> indices come from `clustClusterList2Vol` in the
> order returned by `clustGetClusters`, which sorts
> the cluster list at
> [`:862`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/volcluster.cpp#L862)
> by **peak intensity** (`clustSortClusterList` keys
> on MaxValue), not by **cluster size**.
>
> For a binary mask — the typical input — every
> cluster's peak intensity equals the binarisation
> on-value (e.g. 1), so the sort key is uniform
> across all clusters and the resulting order is
> implementation-defined by the underlying sort.
> Which `nKeep` clusters survive is therefore
> arbitrary, not size-ranked.

## Affected Artefacts

- **Tool:** [[mri_volcluster]] when invoked with
  `--remove-islands` / `--match`
  ([`mri_volcluster/mri_volcluster.cpp:1113`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_volcluster/mri_volcluster.cpp#L1113)).
- **Internal caller:** `MRIremoveVolumeHoles`
  ([`:2153`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/volcluster.cpp#L2153))
  passes the inverted mask through
  `MRIremoveVolumeIslands` to keep `nKeep` largest
  background components — same wrong-sort-key
  defect.
- **Pipeline stage(s):** none in default
  `recon-all`. Affects user post-processing of
  binary masks.
- **Triggering configuration:** any caller
  expecting "keep N largest islands" semantics on a
  binary mask.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION`.

## Detailed Description

Walk-through of the call chain:

```cpp
/* MRIremoveVolumeIslands :2080 */
VOLCLUSTER **ClusterList = clustGetClusters(
    mask, 0, thresh, 0, 0, 0, NULL, &nClusters, NULL);
MRI *ocn = clustClusterList2Vol(ClusterList, nClusters, mask, 0, 0);
...
if (v <= nKeep) keep;
```

```cpp
/* clustGetClusters :862 */
ClusterList2 = clustSortClusterList(ClusterList2, nclusters, NULL);
```

```cpp
/* clustSortClusterList — sorts by MaxValue (peak intensity) */
```

```cpp
/* clustClusterList2Vol :720 */
MRIsetVoxVal(vol, ..., 0, nthvc + 1);   /* index = position in (peak-sorted) list */
```

For binary masks: peak intensity is identical across
all clusters → sort key is uniform → resulting
cluster order is determined by the sort
implementation. With `qsort` (typical), ties resolve
to the first-found order; with quicksort tie-
handling vagaries, the order can vary across
glibc / build platform.

To get the **largest** islands, the function would
need to sort by `nmembers` (member count), not by
`MaxValue`.

## Root Cause

`clustGetClusters` is a general cluster utility used
both for `mri_volcluster`'s threshold-based
clustering (where peak-intensity sort makes sense
because clusters have distinct peaks) and for
binary-mask island removal (where peak-intensity
sort is meaningless because all peaks are equal).
The reuse path silently inherits the wrong sort key
for the binary-mask use case.

## Impact

- **Binary masks:** `MRIremoveVolumeIslands` does
  *not* return the `nKeep` largest islands. It
  returns `nKeep` islands in implementation-
  defined order (typically the order in which the
  underlying `qsort` reorders ties).
- **Non-binary input:** if used on a continuous-
  valued input (unusual), the function returns
  `nKeep` islands sorted by peak intensity — which
  is also wrong-by-the-doc but at least
  reproducible.
- **Severity:** low. The function does prune
  islands, just not the *largest* ones. For
  topology-cleanup pipelines the difference is
  usually invisible because real data has one
  dominant island.

## Recommended Fix

Add an explicit sort by member count after
`clustGetClusters` returns:

```diff
--- a/utils/volcluster.cpp
+++ b/utils/volcluster.cpp
@@ -2079,8 +2079,17 @@ MRI *MRIremoveVolumeIslands(MRI *mask, double thresh, int nKeep, MRI *outvol)

   int nClusters;
   VOLCLUSTER **ClusterList = clustGetClusters(mask, 0, thresh, 0, 0, 0, NULL, &nClusters, NULL);
+
+  /* Sort by member count (largest first) so that nKeep means "N largest islands". */
+  for (int i = 0; i < nClusters; i++) {
+    for (int j = i + 1; j < nClusters; j++) {
+      if (ClusterList[j]->nmembers > ClusterList[i]->nmembers) {
+        VOLCLUSTER *t = ClusterList[i]; ClusterList[i] = ClusterList[j]; ClusterList[j] = t;
+      }
+    }
+  }
+
   MRI *ocn = clustClusterList2Vol(ClusterList, nClusters, mask, 0, 0);
```

A cleaner refactor would expose a `clustSortBySize`
helper next to the existing `clustSortClusterList`
(by max value), and have `MRIremoveVolumeIslands`
call the size-sort variant.

## Workarounds

To actually keep the largest island, threshold the
mask, run `clustGetClusters` directly, sort the
returned list by `nmembers` manually, and keep the
top-N.
