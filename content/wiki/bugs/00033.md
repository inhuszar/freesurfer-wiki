# mri_concat --paired-* loop reads frame nframes when nframes is odd

> [!bug] Synopsis
> The `--paired-avg`, `--paired-sum`, `--paired-diff`,
> `--paired-diff-norm`, `--paired-diff-norm1`, and
> `--paired-diff-norm2` modes of `mri_concat` walk frames with
> stride 2: `for (f = 0; f < mriout->nframes; f += 2)` and read
> the pair `(f, f+1)`. The output is allocated with
> `mriout->nframes / 2` frames. When `nframes` is **odd**, the
> last iteration `f = nframes − 1` reads
> `MRIgetVoxVal(mriout, c, r, s, nframes)` (one past the last
> frame) and writes to `mritmp` frame `nframes/2` (one past the
> last allocated output frame). Both are silent out-of-bounds
> accesses; `MRIgetVoxVal` does not bounds-check positive frame
> indices, so the read returns whatever is at the next slice's
> first row and the write corrupts adjacent allocations. No
> parity guard rejects odd-nframes inputs.

## Affected Artefacts

- **Tool(s):** [[mri_concat]] when invoked with any
  `--paired-...` flag and an odd-frame-count concatenated input.
- **Pipeline stage(s):** _N/A_ for default [[recon-all]];
  user-facing.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_.
- **Platforms:** all
- **Triggering configuration:** any
  `mri_concat --paired-{avg,sum,diff,diff-norm,diff-norm1,diff-norm2}
   FILE1 FILE2 ... FILEK --o OUT.mgz`
  where the **total number of frames** across the inputs is odd.
  Realistic for: ASL paired tag/control series accidentally
  concatenated with a stray reference, paired statistical
  contrasts where one side has one extra orphan, or any
  user-built concat where the parity invariant was not enforced.

## Detailed Description

### Expected Behaviour

The `--paired-*` modes pair frames `(0, 1), (2, 3), …` and emit
one output frame per pair. The mode is by definition
**paired**, so the input frame count must be even. The expected
behaviour for an odd input is one of:

- Reject the input with an explicit error
  ("`mri_concat: --paired-* requires an even number of frames`"),
  or
- Silently drop the trailing odd frame and process pairs only.

The current help text documents the modes as
"compute average / sum / difference of pairs of frames" with no
hint of how odd inputs are handled — the natural reader
assumption is that odd inputs are rejected or ignored, not
passed through with OOB accesses.

### Observed Behaviour

The pair-processing loop at
[`mri_concat/mri_concat.cpp:455-491`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_concat/mri_concat.cpp#L455-L491):

```cpp
mritmp = MRIcloneBySpace(mriout, -1, mriout->nframes/2);   /* nframes/2 output frames */
for (c = 0; c < nc; c++) {
  for (r = 0; r < nr; r++) {
    for (s = 0; s < ns; s++) {
      fout = 0;
      for (f = 0; f < mriout->nframes; f += 2) {            /* ← bound is nframes, not nframes-1 */
        v1 = MRIgetVoxVal(mriout, c, r, s, f);
        v2 = MRIgetVoxVal(mriout, c, r, s, f + 1);          /* ← OOB at f = nframes-1 when odd */
        v = 0;
        if (DoPairedAvg)        v = (v1+v2)/2.0;
        if (DoPairedSum)        v = (v1+v2);
        if (DoPairedDiff)       v = v1-v2;
        if (DoPairedDiffNorm) { v = v1-v2; vavg = (v1+v2)/2.0;
                                if (vavg != 0.0) v = v/vavg; else v = 0; }
        /* ... */
        MRIsetVoxVal(mritmp, c, r, s, fout, v);             /* ← OOB write at fout=nframes/2 */
        fout++;
      }
    }
  }
}
```

For `nframes = 5`:
- Allocation: `mritmp` has `5 / 2 = 2` frames.
- Loop iterations: `f = 0, 2, 4` (3 iterations).
  - `f = 0`: read frames 0 and 1, write to `mritmp` frame 0. ✓
  - `f = 2`: read frames 2 and 3, write to `mritmp` frame 1. ✓
  - `f = 4`: read frames 4 and **5** (OOB), write to `mritmp`
    frame **2** (OOB). ✗

`MRIgetVoxVal` only bounds-checks negative coordinates
([`utils/mri.cpp:1628-1632`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L1628-L1632)),
so the read of frame `nframes` goes through the access macro to
`((BUFTYPE *)mri->slices[s + nframes*depth][r])[c]`, which
indexes past the last frame's slice-pointer array — typically
into either the next allocation in heap or an unmapped page.
The write to `mritmp` frame `nframes/2` indexes
`mritmp->slices[s + (nframes/2)*depth][r]` with the same
overrun.

## Root Cause

The pair-processing loop was written assuming an even
`nframes` invariant but the invariant is not enforced. A
defensive parity check at CLI parse time (`if (DoPaired &&
mriout->nframes % 2 != 0) ErrorExit(...)`) or a tighter loop
bound (`f + 1 < mriout->nframes`) would prevent the OOB.

## Impact

- **Silent OOB read of one frame past `mriout`.** For a chunked
  `MRI` allocation, frame `nframes` resolves to slice indices
  starting at `nframes * depth` in the `slices[]` array.
  `slices` was allocated with `(depth * nframes)` entries, so
  `slices[nframes * depth]` is one past the array — an
  unmapped page or unrelated heap region. The behaviour
  depends on the allocator and address-space layout: typically
  garbage values, occasionally a `SIGSEGV`.
- **Silent OOB write to `mritmp` at frame `nframes/2`.** The
  output volume is allocated with `nframes/2` frames; writing
  to frame `nframes/2` overwrites the next allocation. For a
  fresh `mritmp` immediately after `MRIcloneBySpace`, the next
  allocation is whatever the allocator placed nearby — often
  the row-pointer array or another `MRI` struct.
- **Unsafe even when no crash.** The output's last
  in-bounds frame is correct; the OOB write to "frame `nframes/2`"
  silently corrupts adjacent memory and may surface later as
  a totally unrelated bug elsewhere in the program.
- **Latent for default [[recon-all]].** `recon-all` does not
  invoke `mri_concat --paired-*`. Fires on any user-facing
  invocation with an odd-frame-count input.

## Recommended Fix

Two equivalent fixes; either is sufficient. Both:

```diff
   if(DoPaired)
   {
+    if (mriout->nframes % 2 != 0) {
+      printf("ERROR: --paired-* requires an even number of input frames; got %d\n",
+             mriout->nframes);
+      exit(1);
+    }
     printf("Combining pairs\n");
     mritmp = MRIcloneBySpace(mriout,-1,mriout->nframes/2);
     for (c=0; c < nc; c++) {
       for (r=0; r < nr; r++) {
         for (s=0; s < ns; s++) {
           fout = 0;
-          for (f=0; f < mriout->nframes; f+=2) {
+          for (f=0; f + 1 < mriout->nframes; f+=2) {
             v1 = MRIgetVoxVal(mriout,c,r,s,f);
             v2 = MRIgetVoxVal(mriout,c,r,s,f+1);
             /* ... */
           }
         }
       }
     }
   }
```

The parity check is the user-friendly fix. The tighter loop
bound is the defensive fix that drops the orphan silently. The
two are not mutually exclusive — keeping both is safest.

### Alternative Fixes Considered

- **Drop the trailing orphan with a warning.** Print
  `"WARNING: --paired-* dropping orphan frame %d"` when
  `nframes` is odd and continue. Friendlier than a hard error
  but masks user mistakes; the explicit ErrorExit is preferred.

## Workarounds (If Any)

- Manually verify that the concatenated input has an even
  number of frames before invoking `mri_concat --paired-*`.
- Use `mri_convert --frame F1 F2 …` to pre-select an even
  subset.
