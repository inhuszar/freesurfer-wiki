# [severity-3] [bug-00119] `FCDwriteLabels` reuses one `std::stringstream` across all iterations; only the first label gets a valid path

> [!bug] Synopsis
> ```cpp
> /* utils/fcd.cpp:578-595 */
> int FCDwriteLabels(FCD_DATA *fcd, char *dir)
> {
>   int s;
>   std::stringstream label_name;       /* :581 — declared once */
>
>   for (s = 0; s < fcd->nlabels; s++) {
>     if (fcd->labels[s]) {
>       label_name << dir << "/fcd"     /* :585 — appends! */
>                  << std::setw(2) << std::setfill('0') << s
>                  << "_" << fcd->labels[s]->name;
>       LabelWrite(fcd->labels[s], label_name.str().c_str());
>     }
>   }
>   ...
> }
> ```
>
> `std::stringstream::operator<<` appends
> to the stream's existing contents.
> Without a `label_name.str("")` (or
> declaring `label_name` *inside* the
> loop), each iteration's path
> accumulates on top of the previous.
>
> For `fcd->nlabels = 3` with `dir =
> "/out"` and label names "a", "b", "c":
>
> | iteration | `label_name.str()` |
> |-----------|--------------------|
> | s=0       | `/out/fcd00_a`     |
> | s=1       | `/out/fcd00_a/out/fcd01_b` |
> | s=2       | `/out/fcd00_a/out/fcd01_b/out/fcd02_c` |
>
> The first label is written to a valid
> filename. Each subsequent label is
> written to a malformed path. Most
> filesystems reject such paths
> (multiple `/` segments where
> intermediate directories don't exist),
> so `LabelWrite` errors out — but the
> function returns `NO_ERROR` regardless
> (no propagation of LabelWrite's
> return value).
>
> Net effect: when an FCD analysis
> produces > 1 cluster label, only the
> first one is saved.

## Affected Artefacts

- **Tool:** [[freeview]] — `LayerFCD::Save`
  calls `FCDwriteLabels` at
  [`freeview/LayerFCD.cpp:566`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/freeview/LayerFCD.cpp#L566).
- **Pipeline stage(s):** none in
  default `recon-all`. FCD is a
  research workflow for focal
  cortical dysplasia detection.
- **Triggering configuration:** any
  FCD analysis with more than one
  detected label/cluster.
- **FreeSurfer version(s):**
  confirmed in `$FREESURFER_VERSION`
  (commit `d932c45b79`).

## Detailed Description

### Why typical testing might miss this

Single-label FCD outputs (the
simplest test case) work correctly
because the first iteration's
label_name is valid. The bug only
fires for nlabels ≥ 2.

The function returns `NO_ERROR`
regardless of `LabelWrite`'s
outcome (no return-value
propagation at `:588`), so the
caller sees a "successful" save
even when most labels weren't
written.

### Sister stringstream patterns elsewhere

Most FreeSurfer code uses one of:

- `sprintf(fname, ...)` with a
  char buffer reset by each call.
- `std::ostringstream` declared
  inside the loop (fresh each
  iteration).

`FCDwriteLabels` is the outlier
that declares `label_name` outside
the loop without resetting.

## Root Cause

The author likely thought
`label_name` would be implicitly
cleared at the start of each
loop iteration (as in some other
languages or with
`std::string`'s `=` operator).
But `std::stringstream::operator<<`
always appends.

## Impact

- **`freeview` FCD save with > 1
  label:** only the first label is
  written. Subsequent labels go to
  malformed paths and fail
  silently.
- **Severity:** 3 — research
  workflow, real silent
  data-loss bug for the
  multi-label case.

## Recommended Fix

Move the declaration inside the
loop (preferred) or explicitly
clear:

```diff
--- a/utils/fcd.cpp
+++ b/utils/fcd.cpp
@@ -579,10 +579,10 @@ int FCDwriteLabels(FCD_DATA *fcd, char *dir)
 int FCDwriteLabels(FCD_DATA *fcd, char *dir)
 {
   int s;
-  std::stringstream label_name;

   for (s = 0; s < fcd->nlabels; s++) {
     if (fcd->labels[s]) {
+      std::stringstream label_name;
       label_name << dir << "/fcd"
                  << std::setw(2) << std::setfill('0') << s
                  << "_" << fcd->labels[s]->name;
       LabelWrite(fcd->labels[s], label_name.str().c_str());
     }
   }
```

## Workarounds

For users running FCD analysis
through freeview: after `Save`,
inspect the output directory.
Only `fcd00_*` will be present.
Re-run the analysis with a
filter that keeps only one
label, or apply the patch and
rebuild.

## Provenance and Discovery

- **Discovered:** 2026-05-10 by
  agent (audit of stringstream
  patterns in IO functions).
- **Evidence:**
  - `std::stringstream` declared
    once at `:581`, outside the
    loop at `:583-590`.
  - No `label_name.str("")` or
    `.clear()` call in the
    loop body.
  - `LabelWrite`'s return value
    is ignored at `:588`.
  - C++ `operator<<` on
    stringstream appends (does
    not replace).
