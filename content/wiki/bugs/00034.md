# MRIcorify uses uninitialized stack arrays for segidlist / firstframe / lastframe

> [!bug] Synopsis
> `MRIcorify(MRI *seg, double corethresh)` declares three
> 10000-element `int` arrays on the stack —
> `segidlist`, `firstframe`, `lastframe` — and uses them
> immediately as if they were zero-initialised. They are not.
> The "first-time-seen-this-segid" guard
> `if (segidlist[segid] == 0)` reads whatever happens to be on
> the stack at that address, so the `firstframe[segid] = f` and
> `lastframe[segid] = f` initialisations almost never fire. The
> subsequent `firstframe[segid] > f` / `lastframe[segid] < f`
> updates only narrow the range when the (garbage) initial
> value happens to be on the wrong side of the observed `f`.
> The downstream corification loop then iterates
> `for (f = firstframe[segid]; f <= lastframe[segid]; f++)` with
> garbage bounds — a few unlucky stack states produce
> billion-iteration loops or out-of-frame reads of the source
> volume.

## Affected Artefacts

- **Tool(s):** [[mri_cluster]] when invoked with the
  `--corify SEGVOL THRESH COREVOL` flag (a documented
  user-facing option at
  [`mri_cluster.cpp:508`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_volcluster/mri_cluster.cpp#L508)).
- **Pipeline stage(s):** _N/A_ for default [[recon-all]].
  Fires under user-facing flag.
- **FreeSurfer version(s):** confirmed in `$FREESURFER_VERSION`;
  earliest known: _unknown_.
- **Platforms:** all
- **Triggering configuration:** `mri_cluster --corify SEG.mgz
  THRESH OUT.mgz` where `SEG.mgz` has more than one frame
  (`seg->nframes > 1`). The function early-returns at
  [`:91`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_volcluster/mri_cluster.cpp#L91)
  for single-frame inputs, so the bug fires only on multi-frame
  segmentations — the **intended use case** for corification
  (longitudinal core extraction).

## Detailed Description

### Expected Behaviour

The function should:

1. Zero-initialise `segidlist[]`, `firstframe[]`, `lastframe[]`.
2. Fill `segidlist[segid]` with the count of voxels per segid.
3. Track the **first** and **last** frame each segid appears
   in, so the corification loop knows the per-segid frame
   range.

The `if (segidlist[segid] == 0)` guard is a "first time we've
seen this segid" check; its outcome should be deterministic.

### Observed Behaviour

The function declaration at
[`mri_volcluster/mri_cluster.cpp:64-65`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_volcluster/mri_cluster.cpp#L64-L65):

```cpp
MRI *MRIcorify(MRI *seg, double corethresh){
  int segidlist[10000], firstframe[10000], lastframe[10000];
  /* No memset / calloc / explicit zero-init. */
```

The C standard says local automatic arrays without an
initialiser hold **indeterminate values** — typically whatever
the stack memory contained from previous function calls.

The first-pass loop at
[`:69-85`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_volcluster/mri_cluster.cpp#L69-L85):

```cpp
for(int f=0; f < seg->nframes; f++){
  for(int c=0; c < seg->width; c++){
    for(int r=0; r < seg->height; r++){
      for(int s=0; s < seg->depth; s++){
        int segid = MRIgetVoxVal(seg,c,r,s,f);
        if(segid > segnomax) segnomax = segid;
        if(segidlist[segid] == 0){           /* ← compares against garbage */
          firstframe[segid] = f;
          lastframe[segid] = f;
        }
        segidlist[segid]++;
        if(firstframe[segid] > f) firstframe[segid] = f;
        if(lastframe[segid]  < f) lastframe[segid]  = f;
      }
    }
  }
}
```

For each segid:
- `segidlist[segid] == 0` fires only if the stack happened to
  hold `0` at that offset. For the typical case (any non-zero
  garbage), the initialisation block is never entered.
- `firstframe[segid] > f` only updates `firstframe` when the
  garbage exceeds the current frame `f`. For garbage =
  `INT_MAX`, all updates fire and `firstframe[segid]` correctly
  ends up at the smallest `f` observed. For garbage =
  `INT_MIN` or any large negative value, the comparison is
  always false and `firstframe[segid]` retains the negative
  garbage.
- Symmetrically for `lastframe[segid]`.

The downstream corification loop at
[`:93-119`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/mri_volcluster/mri_cluster.cpp#L93-L119):

```cpp
for(int segid = 1; segid <= segnomax; segid++){
  if(segidlist[segid] == 0) continue;
  /* ... */
  for(int f=firstframe[segid]; f <= lastframe[segid]; f++){
    int val = MRIgetVoxVal(seg,c,r,s,f);
    /* ... */
  }
}
```

uses `firstframe[segid]` and `lastframe[segid]` directly as
loop bounds. Garbage values produce one of:

- **Empty loop** when garbage `firstframe > lastframe`. The
  segid's voxels are never written to the output `core`.
- **Negative-start loop** when garbage `firstframe < 0`.
  `MRIgetVoxVal(seg, c, r, s, f)` for negative `f` returns
  `mri->outside_val` per the bounds check at
  [`utils/mri.cpp:1628-1632`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mri.cpp#L1628-L1632);
  the loop body's `nmiss++` increments per-iteration, and the
  final `nmiss > corethresh*nf` test uses `nf = lastframe -
  firstframe + 1` (also garbage) so the threshold logic is
  arbitrary.
- **Past-end loop** when garbage `lastframe ≥ seg->nframes`.
  `MRIgetVoxVal(seg, c, r, s, f)` for `f >= nframes` reads OOB
  on positive coordinates (no positive-side bounds check) —
  silently returns whatever lies past the slice-pointer
  array.
- **Long loop** when garbage `firstframe ≪ lastframe`. Up to
  `INT_MAX − INT_MIN ≈ 4 × 10⁹` iterations per voxel. Each
  iteration is a `MRIgetVoxVal` call. Effectively a hang.

## Root Cause

The author wrote local stack arrays expecting them to be
zero-initialised. C / C++ does not zero-initialise local
automatic arrays — they hold whatever was at the stack address
from prior calls. The intended check
`if (segidlist[segid] == 0)` requires the array to start as
all-zero.

## Impact

- **Nondeterministic output.** The same input segmentation can
  produce different `core` outputs across runs of the same
  binary, because the stack state varies. `firstframe[segid]`
  and `lastframe[segid]` may end up holding any value.
- **Silent wrong corification.** When the garbage state
  produces narrow `[firstframe, lastframe]` ranges, the
  function under-corifies (some segids get empty output
  cores). When ranges are wide, the function over-corifies
  (writes are based on out-of-range frame reads via
  `MRIgetVoxVal`'s `outside_val`).
- **Pathological hangs.** When garbage produces
  `firstframe < 0` and `lastframe = INT_MAX`, the inner loop
  runs `~4 × 10⁹` iterations per voxel × the volume size — a
  practical hang.
- **Latent for default [[recon-all]].** `mri_cluster
  --corify` is not on the default recon-all path.

## Recommended Fix

```diff
 MRI *MRIcorify(MRI *seg, double corethresh){
-  int segidlist[10000], firstframe[10000], lastframe[10000];
+  int segidlist[10000]  = {0};
+  int firstframe[10000] = {0};
+  int lastframe[10000]  = {0};

   // For each seg, get the first and last frame it appears in
   int segnomax = -1;
```

The C99-style `= {0}` initialiser zero-fills the entire array.
Equivalent: `memset(segidlist, 0, sizeof(segidlist)); …`.

Optionally, add a defensive bounds check on `segid` to guard
against the array's hard-coded 10000 limit:

```diff
       int segid = MRIgetVoxVal(seg,c,r,s,f);
+      if (segid < 0 || segid >= 10000) {
+        printf("ERROR: MRIcorify: segid %d out of range [0, 10000)\n", segid);
+        return NULL;
+      }
       if(segid > segnomax) segnomax = segid;
```

The 10000-segid limit silently fires for any aseg containing a
segid ≥ 10000 — for example, custom labels above the standard
4035 ceiling, but worth guarding regardless.

### Alternative Fixes Considered

- **Replace the static-size arrays with a `std::vector<int>`
  sized at `seg->nframes * MAX_SEGID + 1` after a quick
  pre-scan.** Cleaner but a larger diff.
- **Move the arrays to the heap with `calloc`.** Equivalent
  zero-initialisation; slightly less elegant than C99
  `= {0}`.

## Workarounds (If Any)

- For users who need `mri_cluster --corify` to work
  reproducibly: pass `--frame F` for each frame of interest
  separately, or use a single-frame input (the function
  early-returns for `nframes == 1` and produces a clean
  pass-through copy).

## Confidence and Gaps

> [!gap] Empirical incidence
> The bug's observable effect varies by stack state. On a
> freshly-launched process the stack near the callee may be
> all-zero (Linux ASLR randomises stack base, but the bytes at
> a particular relative offset can be zero by coincidence), in
> which case the function happens to work correctly. On a
> long-running process with many prior calls, the stack is
> arbitrary and the bug fires.

> [!gap] 10000-segid limit
> The hard-coded `[10000]` limit is not enforced anywhere. A
> seg with `segid ≥ 10000` writes past the array — additional
> stack corruption beyond the uninitialised-read defect.
