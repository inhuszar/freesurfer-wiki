# [severity-2] [bug-00089] `VectorCrossProduct` shape check uses AND where OR is required

> [!bug] Synopsis
> Both `VectorCrossProduct`
> ([`utils/matrix.cpp:2530-2549`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L2530-L2549))
> and its long-double sibling
> `VectorCrossProductD`
> ([`:2557-2576`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L2557-L2576))
> guard against non-3-vector inputs with
>
> ```cpp
> if (v1->rows != 3 && v1->cols != 1)
>   ErrorReturn(NULL, (ERROR_BADPARM, "VectorCrossProduct: must be 3-vectors"));
> ```
>
> The intent is "fail if either dimension is
> wrong," but `&&` only fires when **both**
> dimensions are wrong. The truth table:
>
> | `rows` | `cols` | check fires? |
> |--------|--------|--------------|
> | 3      | 1      | no (correct: shape is right) |
> | 3      | 2      | **no** (BUG: shape is wrong) |
> | 4      | 1      | **no** (BUG: shape is wrong) |
> | 4      | 2      | yes |
>
> A `4×1` vector or a `3×N` matrix passes the
> validation. The function then reads
> `VECTOR_ELT(v1, 1..3)` and writes
> `VECTOR_ELT(vdst, 1..3)` regardless. For most
> 1-based VECTOR layouts these accesses happen
> to land on real memory, so the function
> silently returns a "cross product" computed
> from the first three elements only — but with
> no diagnostic.

## Affected Artefacts

- **Tool:** none currently observable. In-tree
  callers all pass properly-shaped 3×1 vectors:
  - [`utils/mrisutils.cpp:1464`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisutils.cpp#L1464),
    [`:1467`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisutils.cpp#L1467),
    [`:1470`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/mrisutils.cpp#L1470)
  - [`utils/DICOMRead.cpp:6356`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/DICOMRead.cpp#L6356),
    [`:7655`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/DICOMRead.cpp#L7655)
- **Pipeline stage(s):** none — defect is
  latent because no caller exercises the
  failing shapes.
- **Triggering configuration:** any future call
  that passes a non-3-vector. The library
  contract advertises shape validation but
  doesn't actually enforce it on most wrong
  shapes.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/matrix.cpp:2530-2549 — VectorCrossProduct */
VECTOR *VectorCrossProduct(const VECTOR *v1, const VECTOR *v2, VECTOR *vdst)
{
  float x1, x2, y1, y2, z1, z2;

  if (v1->rows != 3 && v1->cols != 1)             /* :2534 — should be || */
    ErrorReturn(NULL, (ERROR_BADPARM, "VectorCrossProduct: must be 3-vectors"));

  if (!vdst) vdst = VectorClone(v1);

  x1 = VECTOR_ELT(v1, 1);
  ...
  return (vdst);
}
```

```cpp
/* utils/matrix.cpp:2557-2576 — VectorCrossProductD */
VECTOR *VectorCrossProductD(const VECTOR *v1, const VECTOR *v2, VECTOR *vdst)
{
  long double x1, x2, y1, y2, z1, z2;

  if (v1->rows != 3 && v1->cols != 1) return(NULL);   /* :2561 — should be || */
  ...
}
```

The same defect appears in both variants. Note
also that neither function validates `v2`'s
shape — only `v1` is checked. Even with the
operator fix, a 3×1 `v1` and a 4×1 `v2` would
pass the guard.

The contract advertised by the function name
("3-vectors") and the error string is
unambiguously "both inputs must be 3×1." The
check as written enforces neither claim
correctly.

## Code Reference

- **File:** [`utils/matrix.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp)
- **Defect 1:**
  [`VectorCrossProduct:2534`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L2534)
- **Defect 2:**
  [`VectorCrossProductD:2561`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/matrix.cpp#L2561)
- **Companion `DVectorCrossProduct`** in
  [`utils/dmatrix.cpp:801-808`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/dmatrix.cpp#L801-L808)
  uses `||` correctly (split into two separate
  `if` statements that check both `v1` and `v2`)
  — the established convention in the codebase
  is the stricter check.
- **Commit:** `d932c45b79`

## Root Cause

Classic De Morgan typo. The intended
predicate is "shape is invalid," i.e.
`!(rows == 3 && cols == 1)`, which expands to
`rows != 3 || cols != 1`. The author wrote the
expansion with `&&` instead of `||`, accidentally
inverting one of the De Morgan terms.

## Impact

- **Today:** none — every in-tree caller passes
  a properly-shaped 3×1 vector, so the check
  doesn't matter.
- **Defensive contract:** future callers that
  pass a wrongly-shaped vector receive a
  silently truncated cross-product computed
  from the first three `VECTOR_ELT` accesses,
  with no diagnostic. The function appears to
  succeed (returns `vdst`) and writes apparently-
  reasonable numbers; the bug is invisible
  except to a careful reader.
- **Severity:** 2 — latent, validation-only
  defect.

## Recommended Fix

```diff
--- a/utils/matrix.cpp
+++ b/utils/matrix.cpp
@@ -2531,7 +2531,8 @@ VECTOR *VectorCrossProduct(const VECTOR *v1, const VECTOR *v2, VECTOR *vdst)
 {
   float x1, x2, y1, y2, z1, z2;
 
-  if (v1->rows != 3 && v1->cols != 1) ErrorReturn(NULL, (ERROR_BADPARM, "VectorCrossProduct: must be 3-vectors"));
+  if (v1->rows != 3 || v1->cols != 1 || v2->rows != 3 || v2->cols != 1)
+    ErrorReturn(NULL, (ERROR_BADPARM, "VectorCrossProduct: both inputs must be 3x1"));
 
   if (!vdst) vdst = VectorClone(v1);
@@ -2558,7 +2559,8 @@ VECTOR *VectorCrossProductD(const VECTOR *v1, const VECTOR *v2, VECTOR *vdst)
 {
   long double x1, x2, y1, y2, z1, z2;
 
-  if (v1->rows != 3 && v1->cols != 1) return(NULL);
+  if (v1->rows != 3 || v1->cols != 1 || v2->rows != 3 || v2->cols != 1)
+    return(NULL);
 
   if (!vdst) vdst = VectorClone(v1);
```

The fix also extends the check to `v2`, which
should have been validated in the original
implementation. Note that `DVectorCrossProduct`
in `dmatrix.cpp` already validates both
operands separately and is the convention to
match.

## Workarounds

Callers should validate input shapes themselves
before calling these functions until the patch
lands.
