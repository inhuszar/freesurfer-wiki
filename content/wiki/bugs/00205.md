# [severity-2] [bug-00205] `surf2vol` — exits 0 after caught exceptions and failed output writes, ignores the return of `IoParams::parse()`, and leaves `compress` uninitialised

> [!bug] Synopsis
> [[surf2vol]]'s `main()` wraps the whole registration in a `try` whose
> `catch (const char*)` and `catch (std::exception)` handlers only print a
> message; execution then falls through to `PetscFinalize()` and
> `return 0`. A failed `MRIwrite` of `-out` is not checked at all, a failed
> `-out_mesh` save is caught locally and printed, and the return value of
> `IoParams::parse()` is ignored — so a PETSc option-parsing error (for
> example `-fem_steps 17.5`) is printed but the run continues with every later
> option left at its default. Each of these ends with exit status 0, so
> callers that test the status — [[mri_cvs_register]]'s `if($status) exit 1`
> — cannot detect the missing output (the next command, [[exportGcam]], then
> fails on the absent `.tm3d`). The `compress` member is additionally never
> initialised by the constructor.

## Affected Artefacts

- **Tool(s):** [[surf2vol]]; its callers ([[mri_cvs_register]]) and the next stage ([[exportGcam]])
- **Pipeline stage(s):** [[mri_cvs_register]] elastic stage
  ([`mri_cvs_register/mri_cvs_register:408-415`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_cvs_register/mri_cvs_register#L408-L415)) — failure path only
- **FreeSurfer version(s):** confirmed in 8.2.0; present since the 2008-04-18 import (`9761aeb9b6b`).
- **Platforms:** all
- **Triggering configuration:** a runtime failure after option parsing
  (output path not writable, `std::bad_alloc`, `const char*` throw from the
  morph code), or a PETSc option parse error. The CVS options all parse
  cleanly, so the default path is not affected unless a runtime error occurs.

## Detailed Description

### Exit status after caught exceptions

```cpp
  catch (const char* msg)
    {
      std::cout << " caught const char exception \n"
		<< msg << std::endl;
    }
  catch (const std::exception& e)
    {
      std::cout << " Master-net caught exception\n"
		<< e.what() << std::endl;
    }
  
  std::cout << " releasing Petsc resources\n";
  // RELEASE PETSC resources
  ierr = PetscFinalize();
  CHKERRQ(ierr);
  
  std::cout << " process performed in " << timer.minutes() << " minutes\n";
  printf("surf2vol done ");PrintMemUsage(stdout);  
  printf("#VMPC# fsurf2vol VmPeak  %d\n",GetVmPeak());

  return 0;
}
```

Whatever is thrown inside the `try` block (it starts before the step loop and
covers the volume write, `-gcam`, `-out_mesh` and `-out_affine`), the handlers print
a line to **stdout** and the function returns 0. Inside the block the `-out_mesh`
and `-out_affine` writers have their own `try`/`catch` that also only print
([`fem_elastic/fsurf2vol.cpp:677-692`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L677-L692) for `-out_mesh`).

### Unchecked writes

The warped volume is written with the return value ignored, and so is the
`-gcam` write:

```cpp
      MRI* warped = morph.apply_transforms(mri_moving);

      MRIwrite(warped,
               const_cast<char*>( params.strOutput.c_str())  );

      // 02/07/13: orig location has a bug...needed to write it here...
      if( !params.strGcam.empty() ) {
	GCA_MORPH* gcam = morph.exportGcam(mri_moving, FALSE, 0);
	GCAMwrite(gcam, const_cast<char*>( params.strGcam.c_str()));
      }
```

### `parse()` return value ignored

```cpp
  IoParams params;

  //std::string errMsg = params.parse(argc, argv);

  std::string errMsg;
  params.parse(errMsg);

  if ( !errMsg.empty() )
  {
    std::cerr << " Error parsing the cmd-line\n"
    << errMsg << std::endl;
    exit(1);
  }
```

`IoParams::parse()` returns an `int` error code: every PETSc call in it is
followed by `CHKERRQ(ierr)`, which returns from `parse()` immediately on
failure ([`fem_elastic/fsurf2vol.cpp:1246-1260`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1246-L1260) shows the signature and the first
checks). `main()` only inspects the string `errMsg`, which PETSc errors never
set, so the failure is swallowed and parsing stops half-way through the
option list:

```cpp
  ierr = PetscOptionsHasName( NULL, "-compress",
                              &petscFlag);
  CHKERRQ(ierr);
  compress = static_cast<bool>(petscFlag);

  ierr = PetscOptionsGetInt( NULL, "-fem_steps",
                             &iSteps, &petscFlag);
  CHKERRQ(ierr);
  ierr = PetscOptionsGetInt( NULL, "-fem_end_step",
                             &iEndStep, &petscFlag);
  CHKERRQ(ierr);

  ierr = PetscOptionsHasName( NULL, "-topology_old",
                              &petscFlag );
  CHKERRQ(ierr);
  bUseOldTopologySolver = static_cast<bool>(petscFlag);

  ierr = PetscOptionsHasName( NULL, "-use_pial_for_surf",
                              &petscFlag);
  CHKERRQ(ierr);
  bUsePialForSurf = static_cast<bool>(petscFlag);
  
  return 0;

```

Everything that comes after the failing option is left at the constructor
default.

### `compress` is never initialised

The constructor ([`fem_elastic/fsurf2vol.cpp:1219-1244`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1219-L1244)) initialises the other options but not the
`bool compress` member (declared at [`fem_elastic/fsurf2vol.cpp:107`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L107)); its only
assignment is `compress = static_cast<bool>(petscFlag);` at
[`fem_elastic/fsurf2vol.cpp:1475`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L1475), which `parse()` reaches only if it gets that far.
`IoParams params;` lives on the stack ([`fem_elastic/fsurf2vol.cpp:286`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/fem_elastic/fsurf2vol.cpp#L286)), so an early return would
leave `compress` indeterminate. In the tested PETSc 2.3.3 build no option
before line 1472 produced a parse error (for example `-poisson abc` was
accepted silently), so this is currently latent.

### Expected Behaviour

A tool that cannot produce its requested outputs, or that could not parse its
command line, should exit non-zero so that the calling script stops.

### Observed Behaviour

All of the following were run with the installed 8.2.0 `surf2vol` on
`cvs_avg35` (fixed = moving = `mri/norm.mgz`, `-fixed_surf lh.white`,
`-moving_surf` = the same surface translated +3 mm in x, identity cached
affine, CVS-style options `-lin_res 20 -penalty_weight 1000 -topology_old
-compress -young 1000 -pc_type jacobi -ksp_type preonly -elt_vol 30
-fem_steps 1 -fem_end_step 0`, `-poisson .3` unless noted); the exit status
was read from the shell:

| change to the command | log | result |
|---|---|---|
| `-out /nonexistent_dir/out.mgz` | `error: mghWrite(/nonexistent_dir/out.mgz, -1): could not open file`, run continues to `FEM error … releasing Petsc resources` | **exit status 0**, no `out.mgz` |
| `-out_mesh /nonexistent_dir/el_reg` | `exception caught while trying to write transform` / `VolumeMorph save - failed to open output stream` | **exit status 0**, no `.tm3d` |
| `-fem_steps 17.5` (and `-topology_old` on the command line) | PETSc error traceback `Input string 17.5 has no integer value (do not include . in it)!`, then the run proceeds: one step plus the default extra step, `using new topology solver` (the requested `-topology_old` was never read), outputs written | **exit status 0** |

## Root Cause

Error handling in `main()` is "print and carry on": the catch blocks do not
record that a failure happened, `return 0` is unconditional, library return
codes (`MRIwrite`, `GCAMwrite`, `IoParams::parse`) are not tested, and
`IoParams::IoParams()` omits one member from its initialiser list. PETSc's
`CHKERRQ` convention (return the error code) is used inside `parse()` but the
code returned is dropped by `main()`.

## Impact

- **Output affected:** only in failure situations: missing or incomplete
  outputs with exit status 0. In [[mri_cvs_register]] the `if($status) exit 1`
  after the surf2vol call ([`mri_cvs_register/mri_cvs_register:408-409`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_cvs_register/mri_cvs_register#L408-L409) and
  [`mri_cvs_register/mri_cvs_register:435-436`](https://github.com/freesurfer/freesurfer/blob/v8.2.0/mri_cvs_register/mri_cvs_register#L435-L436)) cannot catch the failure; the following
  `exportGcam` then fails on the absent `.tm3d`, so the user sees a confusing
  secondary error. A PETSc option parse error silently changes the run
  configuration (fewer steps, wrong topology solver) while still producing
  output, and the output looks plausible.
- **Why 2:** it concerns diagnostic/robustness behaviour on failure paths; the
  CVS options parse cleanly and the user's primary results are unaffected in a
  successful run, so it is not on the default success path (the schema's
  severity 2: latent under typical conditions; results unaffected). It is not
  higher because the first visible symptom (a missing file) usually surfaces
  one command later.

## Recommended Fix

Record failures and return a non-zero status; honour `parse()`; initialise
`compress`:

```diff
--- a/fem_elastic/fsurf2vol.cpp
+++ b/fem_elastic/fsurf2vol.cpp
@@ IoParams::IoParams()
     strOutputAffine()  
 {
+  compress = false;
   eltVolMin = 2;
@@ main()
   IoParams params;
 
   std::string errMsg;
-  params.parse(errMsg);
+  if ( params.parse(errMsg) != 0 && errMsg.empty() )
+    errMsg = "option parsing failed (see the PETSc message above)";
 
   if ( !errMsg.empty() )
@@
+  int exitStatus = 0;
   try
   {
@@
-      MRIwrite(warped,
-               const_cast<char*>( params.strOutput.c_str())  );
+      if ( MRIwrite(warped,
+                    const_cast<char*>( params.strOutput.c_str()) ) != NO_ERROR )
+        throw "failed to write the output volume";
@@
   catch (const char* msg)
     {
       std::cout << " caught const char exception \n"
 		<< msg << std::endl;
+      exitStatus = 1;
     }
   catch (const std::exception& e)
     {
       std::cout << " Master-net caught exception\n"
 		<< e.what() << std::endl;
+      exitStatus = 1;
     }
@@
-  return 0;
+  return exitStatus;
```

The `-out_mesh` / `-out_affine` local catch blocks, and the `GCAMwrite`
call, should set `exitStatus = 1` in the same way. (Sketch; not compiled
against the tree.) A test should assert a non-zero status for an unwritable
`-out` and for `-fem_steps 17.5`.

## Workarounds (If Any)

Check for the expected output files after the run (for example `test -s
el_reg_to<template>.tm3d`) instead of relying on the exit status, and read the
log for `PETSC ERROR`.
