# [severity-2] [bug-00080] `DMatrixAddMul` — null-handling promised by docstring is not implemented

> [!bug] Synopsis
> The doc-comment for `DMatrixAddMul`
> ([`utils/dmatrix.cpp:619-623`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/dmatrix.cpp#L619-L623))
> states:
>
> > Computes `v1*m1 + v2*m2` so it can be used for
> > adding, subtracting, and scaling. **If a matrix
> > is NULL or its value is 0, it is ignored.**
>
> The implementation only honours the second half
> of that contract (the `v1 != 0` / `v2 != 0`
> guards). It cannot honour the first half: if
> `m1 == NULL` and `mOut == NULL`, line
> [`:633`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/dmatrix.cpp#L633)
> calls `DMatrixAlloc(m1->rows, m1->cols, m1->type)`
> and crashes; even if `mOut` is supplied, the loop
> bound at
> [`:648`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/dmatrix.cpp#L648)
> reads `m1->rows`, which crashes for `m1 == NULL`.

## Affected Artefacts

- **Tool:** none — all in-tree callers in
  [`utils/surfgrad.cpp`](https://github.com/freesurfer/freesurfer/blob/v$FREESURFER_VERSION/utils/surfgrad.cpp)
  pass non-NULL `m1` (see `:955-970` and the
  `DMatrixScalarMul` wrappers throughout the
  file).
- **Pipeline stage(s):** none.
- **Triggering configuration:** any external call
  with `m1 == NULL`.
- **FreeSurfer version(s):** confirmed in
  `$FREESURFER_VERSION` (commit `d932c45b79`).

## Detailed Description

```cpp
/* utils/dmatrix.cpp:624-668 */
DMATRIX *DMatrixAddMul(DMATRIX *m1, DMATRIX *m2, double v1, double v2, DMATRIX *mOut)
{
  int row, err;
  if(m1 && m2){
    err = DMatrixCheckDims(m1, m2, 3, stdout, "DMatrixAddMul(): ");
    if(err) return(NULL);
  }
  if (!mOut) {
    mOut = DMatrixAlloc(m1->rows, m1->cols, m1->type);   /* :633 — m1 NULL deref */
    if(!mOut) return (NULL);
  }
  ...
  for(row = 1; row <= m1->rows; row++) {                 /* :648 — m1 NULL deref */
    ...
    for(col = 1; col <= m1->cols; col++) {
      val = 0;
      if(m1){ if(v1 != 0) { ... } }                      /* m1-NULL guard */
      if(m2){ if(v2 != 0) { ... } }                      /* m2-NULL guard */
      mOut->rptr[row][col] = val;
    }
  }
  return(mOut);
}
```

The body's *inner* logic is consistent with the
docstring (it guards `if(m1)` and `if(m2)` before
adding contributions), but the *outer* logic — both
the allocation fallback and the loop bound — only
considers `m1`'s shape. A caller passing
`(NULL, m2, 0, 1, NULL)` to compute `m2` into a
freshly-allocated output crashes immediately.

## Root Cause

The "NULL is treated as zero" contract was added to
the inner loop's element-by-element accumulator but
not propagated to the outer scaffolding. The
function originally required both operands; the
docstring documents an extension the implementation
only half-applies.

## Impact

- **In-tree callers:** none affected. Every call
  site in `surfgrad.cpp` passes a non-NULL `m1`.
- **External callers:** anyone trusting the
  docstring will get a segfault on
  `DMatrixAddMul(NULL, m2, 0, 1, ...)`.
- **Severity:** low (latent, doc-vs-code
  mismatch).

narrow the doc. Fixing the implementation:

## Workarounds

Always pass a non-NULL `m1`. To compute `v2 * m2`
alone, call `DMatrixScalarMul(m2, v2, mout)`, which
internally puts `m2` in the `m1` slot.
