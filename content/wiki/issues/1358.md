# mri_convert loses information on image reorientation

> [!issue] Synopsis
> When [[wiki/tools/mri_convert|mri_convert]] is invoked with `--out_orientation` on a volume
> whose dimensions are even, any axis that flips between the input and
> the requested output orientation is pivoted around voxel index `N/2`
> instead of the geometric centre `(N−1)/2`, shifting the output grid
> by exactly one voxel in each flipped axis. The reporter demonstrates
> this on a 256³ volume of ones: the `RAS→LIA` resample leaves a
> one-voxel rim of zeros on the two flipped axes (130 816 zero
> voxels), whereas the equivalent `--reorder` path produces the
> correct output. Source reading confirms the defect: the culprit is
> a missing `c_ras` update after the direction cosines of the output
> template are rewritten. Verdict: **plausible**, high confidence.

## Original Report

> I believe there is an unexpected behavior in `mri_convert` that
> technically affects the options `--out_orientation` and might proxy
> to all cases, where the image is being resampled.
>
> In my analysis, this is due to the fact that the affine gets
> initialized incorrectly during this procedure by virtue of
> "Center RAS", which the MGH format is built on does not actually
> refer to the center of the image, but refers to the `Ni/2` (see

## Agent Analysis

### Relevant Code

The `--out_orientation` path in `mri_convert` updates only the
direction cosines of the output template; `c_ras` is inherited from
the input untouched:

- **File:** `mri_convert/mri_convert.cpp`
- **Function:** `main()`
- **Lines:** `3052–3056`
- **Commit:** `d932c45b79`

```cpp
  if (out_orientation_flag)
  {
    printf("Setting output orientation to %s\n",out_orientation_string);
    MRIorientationStringToDircos(mri_template, out_orientation_string);
  }
```

The helper deliberately rewrites *only* `x_r…z_s` on its argument and
says so in its docstring — "This should only be used to get the
direction cosines 'about right'":

- **File:** `utils/mri.cpp`
- **Function:** `MRIorientationStringToDircos()`
- **Lines:** `15256–15319`
- **Commit:** `d932c45b79`

```cpp
int MRIorientationStringToDircos(MRI *mri, const char *ostr)
{
  /* … builds Mdc from the three-letter orientation string … */
  mri->x_r = Mdc[0][0];
  mri->x_a = Mdc[1][0];
  mri->x_s = Mdc[2][0];
  mri->y_r = Mdc[0][1];  mri->y_a = Mdc[1][1];  mri->y_s = Mdc[2][1];
  mri->z_r = Mdc[0][2];  mri->z_a = Mdc[1][2];  mri->z_s = Mdc[2][2];
  return (0);
}
```

With the Mdc rewritten and `c_ras` unchanged, the resample grid is
assembled by `MRIgetResampleMatrix`, which explicitly uses the
voxel-corner pivot `(width/2., height/2., depth/2.)` — documented in
its own comment block:

- **File:** `utils/mri.cpp`
- **Function:** `MRIgetResampleMatrix()`
- **Lines:** `12006–12008`
- **Commit:** `d932c45b79`

```cpp
  Note the convention c_(r,a,s) being defined in
  terms of c_v = (width/2., height/2, depth/2.),
  not ((width-1)/2, (height-1)/2, (depth-1)/2).
```

The contrast is with the pure-reorder path, which constructs the
output vox2ras from `Msrc * Q` with an explicit `N−1` correction when
an axis is flipped:

- **File:** `utils/mriio.cpp`
- **Function:** `MRIreorderVox2RAS()`
- **Lines:** `11579–11617`
- **Commit:** `d932c45b79`

```cpp
int MRIreorderVox2RAS(MRI *mri_src, MRI *mri_dst, int xdim, int ydim, int zdim)
{
  MATRIX *Q, *Msrc, *Mdst;

  Msrc = MRIxfmCRS2XYZ(mri_src, 0);

  Q = MatrixConstVal(0, 4, 4, NULL);
  Q->rptr[1][abs(xdim)] = ISIGN(xdim);
  Q->rptr[2][abs(ydim)] = ISIGN(ydim);
  Q->rptr[3][abs(zdim)] = ISIGN(zdim);
  Q->rptr[4][4] = 1;
  if (xdim < 0) Q->rptr[1][4] = mri_src->width - 1;
  if (ydim < 0) Q->rptr[2][4] = mri_src->height - 1;
  if (zdim < 0) Q->rptr[3][4] = mri_src->depth - 1;

  Mdst = MatrixMultiply(Msrc, Q, NULL);
  MRIsetVox2RASFromMatrix(mri_dst, Mdst);
  /* … free … */
  return (0);
}
```

The `Q->rptr[·][4] = mri_src-><dim> - 1` translations are exactly the
`N−1` pivot correction that the `--out_orientation` path is missing.

### Plausibility

The defect reproduces arithmetically from the cited code. For the
reporter's `ones` volume with an identity input vox2ras:

1. The input vox2ras (built from `c_ras = (128, 128, 128)` and
   `Mdc = I` at pivot `(128, 128, 128)`) is the identity, so input
   voxel `(i, j, k)` sits at scanner RAS `(i, j, k)`.
2. `MRIorientationStringToDircos(mri_template, "LIA")` sets the
   template's Mdc to `[[-1,0,0],[0,0,1],[0,-1,0]]` and leaves
   `c_ras = (128, 128, 128)`.
3. The template's translation, computed by `extract_i_to_r` as
   `s = c_R − m·c_v` with `c_v = (128, 128, 128)`, evaluates to
   `(128,128,128) − (−128, 128, −128) = (256, 0, 256)`.
4. The resample matrix is therefore
   `[[-1,0,0,256],[0,0,1,0],[0,-1,0,256],[0,0,0,1]]`. Applied to
   destination voxel `(0, j, k)` it yields source voxel
   `(256, k, 256−j)` — both `x=256` and `z=256−j` fall **off** the
   input grid (valid indices `0…255`) on two of the three axes, so
   trilinear interpolation returns `0`.

The two slabs of out-of-grid samples are size `256 × 256 = 65536`
each, minus their intersection `256`, giving exactly `2·65536 − 256 =
130816` zero voxels — which matches the reporter's measured count
bit-for-bit, with `50.10%` concentrated at output `x = 0` and
`50.10%` at output `z = 0`.

The `--reorder` path (path B in the reporter's test) avoids the
defect because `MRIreorderVox2RAS` supplies the `N−1` correction,
placing destination voxel `(0, 0, 0)` at source `(255, 0, 255)` —
inside the input grid. The 1.0-mm header offset between path A and
path B that the reporter observes (`c_r`, `c_s` values of 128 vs. 127
and vox2ras translations 256 vs. 255) is exactly this correction.

The defect is purely a function of the parity of each dimension. For
odd `N`, `N/2` is a half-integer that coincides with the geometric
centre, so the pivot mismatch is zero; the bug does not manifest on
odd-sized volumes. For even `N`, it shifts flipped axes by exactly
one voxel.

## Recommendation

The minimal fix is to reuse the `Msrc·Q` machinery that
`--reorder` already relies on, instead of rewriting only Mdc. When
`--out_orientation` is set:

1. Derive from the input's current direction cosines and the
   requested output orientation string a signed permutation
   `(xdim, ydim, zdim) ∈ {±1, ±2, ±3}³` (the same format
   `--reorder` accepts).
2. Call `MRIreorderVox2RAS(mri, mri_template, xdim, ydim, zdim)`
   to set both Mdc and `c_ras` on the output template with the
   correct `N−1` pivot correction.
3. Skip the standalone `MRIorientationStringToDircos(...)` call
   (its Mdc output is already set by step 2).

Sketch of the change at
`mri_convert/mri_convert.cpp:3052–3056`:

```diff
   if (out_orientation_flag)
   {
     printf("Setting output orientation to %s\n", out_orientation_string);
-    MRIorientationStringToDircos(mri_template, out_orientation_string);
+    /* Derive the signed-permutation (xdim, ydim, zdim) that takes
+       the input's current orientation to `out_orientation_string`,
+       then set the full output vox2ras — including c_ras — through
+       MRIreorderVox2RAS, which applies the N-1 pivot correction for
+       any flipped axis. Rewriting only the direction cosines (as
+       MRIorientationStringToDircos does) leaves c_ras pinned at
+       the input's N/2 pivot and shifts the resampled data by one
+       voxel per flipped axis on even-N volumes (GitHub #1358). */
+    int xdim, ydim, zdim;
+    MRIcomputeReorderFromOrientations(mri, out_orientation_string,
+                                      &xdim, &ydim, &zdim);
+    MRIreorderVox2RAS(mri, mri_template, xdim, ydim, zdim);
   }
```

`MRIcomputeReorderFromOrientations` is a new helper whose body can
be built from `MRIdircosToOrientationString` (already in
`utils/mri.cpp`): read the input's three-letter orientation,
compare letter-by-letter against `out_orientation_string`, and
translate each `(letter_in, letter_out)` pair into the matching
signed dim index.

### Alternative Fixes Considered

- Compensate `c_ras` in place after `MRIorientationStringToDircos`
  by adding, for each flipped axis, a +1-voxel shift along that
  axis's scanner-RAS direction. This is arithmetically equivalent
  but duplicates knowledge of the pivot convention at the call
  site; the `Msrc·Q` construction localises it to one function.
- Change the project-wide pivot convention to `(N−1)/2`. This is
  not realistic: it would rewrite the interpretation of every MGH
  header FreeSurfer has ever produced, and is documented in
  `MRIgetResampleMatrix` as intentional.

### Draft Reply to Reporter

> Thanks for the detailed reproducer — the 130 816-zero count
> isolates the defect cleanly. Confirmed against
> `mri_convert/mri_convert.cpp:3052–3056`: the `--out_orientation`
> branch only rewrites the output's direction cosines and inherits
> `c_ras` from the input. Because FreeSurfer's pivot convention is
> `c_v = (N/2, N/2, N/2)` (see the comment in
> `utils/mri.cpp:12006`), any flipped axis on an even-sized volume
> then shifts the output grid by one voxel — exactly the 1.0 you
> see in `c_r` / `c_s` relative to the `--reorder` path. We plan to
> route `--out_orientation` through `MRIreorderVox2RAS` so the
> `N−1` correction already used by `--reorder` applies to both
> paths. Odd-sized volumes are unaffected.

## Verdict

**`plausible`** — Source reading reproduces the defect arithmetically
and matches the reporter's measured zero count exactly. The fix is
localised to the `--out_orientation` branch of `mri_convert` and the
corresponding helper; `--reorder` already does the right thing and
can be used as a reference implementation.

## Confidence and Gaps

> [!gap] Scope of impact on `recon-all`
> `recon-all` reaches `mri_convert` primarily via `--conform`, which
> produces a 256³ volume in a fixed orientation without user-supplied

> (e.g. `mri_normalize` and `mri_watershed` intermediate steps) use
> `mri_convert` with orientation flags. A focused audit of the
> pipeline scripts to identify even-N reorientations that hit this
> code path is warranted before claiming the default pipeline is
