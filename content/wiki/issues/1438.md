# Bug in SuperSynth's inference script

> [!issue] Synopsis
> In [[mri_super_synth]]'s inference script, the soft-segmentation
> postprocessing step at `inference.py:277–279` sets
> `seg[0][~Mdilated] = 1` and then immediately overwrites it by
> looping `for l in range(seg.shape[0])` — starting at `l = 0` — and
> zeroing every channel at `~Mdilated`. The end state is
> `seg[:, ~Mdilated] = 0`, not the intended `seg[0, ~Mdilated] = 1`
> and `seg[1:, ~Mdilated] = 0`. The reporter's fix (`range(1,
> seg.shape[0])`) is correct. Verdict: **plausible**. Impact on the
> default CLI output is nil, because the discrete segmentation is
> built by `argmax` before this step and the only downstream
> consumer (`vols[0]` → `volumes.csv`) filters out the background
> label.

### Plausibility

The defect reproduces by direct reading of the three-line block:

1. Line 277 assigns `seg[0][~Mdilated] = 1`.
2. Line 278 opens a loop `for l in range(seg.shape[0]):`, which in
   Python iterates `l = 0, 1, 2, …, C − 1` (inclusive of `0`).
3. Line 279 assigns `seg[l][~Mdilated] = 0` for every `l` in the loop
   — including `l = 0`.

The first iteration (`l = 0`) undoes the assignment from line 277.
After the loop completes, `seg[:, ~Mdilated]` is the all-zero vector
at every outside-brain voxel. The intended end state — a one-hot
distribution placing all probability mass on the background class —
is not achieved. The reporter's diagnosis is exact.

**Impact on the shipped output**, however, is essentially nil under
the current inference pipeline:

- **`seg_discrete` (the discrete label volume written to disk as
  `seg_discrete_np` at `inference.py:372`)** is built at lines
  234–243 via `argmax(seg, 0)`, which runs *before* the buggy
  postprocessing. The primary user-facing output file is therefore
  unaffected.
- **`seg` itself is never written to disk.** A grep of `seg` in
  `inference.py` from line 280 to end of file shows exactly one
  remaining use: `vols = seg.sum(dim=[1, 2, 3]).detach().cpu().numpy()`
  on line 280.
- **`vols[0]` (background-class probability mass) is under-counted**
  by `(~Mdilated).sum()` voxels. But `volumes.csv` at lines 283–306
  writes one row per label and guards each row with
  `if (lab > 0) and (lab != 24) and (lab < 900) and (lab != 99)` on
  line 299. `lab > 0` strips the background entry, so `vols[0]` is
  never serialised.
- **`vols[l]` for `l ≥ 1`** is unchanged by the bug: the loop zeros
  those channels outside the mask as intended (what was wrong is
  only the redundant `l = 0` iteration overwriting line 277, not
  the behaviour for `l ≥ 1`).

The bug is therefore a **latent logic error**: the postprocessed
`seg` tensor fails to represent a valid probability distribution
outside `Mdilated`, but no downstream consumer in the shipped
pipeline cares. A future change that exports `seg` (e.g. to write a
soft-probability volume, compute entropy maps, or feed `seg` to
another network) would silently inherit the bug.

## Recommendation

Apply the reporter's proposed one-line fix:

- **File:** `mri_super_synth/SuperSynth/scripts/inference.py`
- **Lines:** `277–279`

```diff
                     # postprocess soft segmentations and compute volumes
                     seg[0][~Mdilated] = 1
-                    for l in range(seg.shape[0]):
+                    for l in range(1, seg.shape[0]):
                         seg[l][~Mdilated] = 0
                     vols = seg.sum(dim=[1, 2, 3]).detach().cpu().numpy()
```

No test change is strictly required (the bug does not surface in any
current output), but a single assertion in a test that runs the
inference pipeline end-to-end would catch any future regression:

```python
assert torch.allclose(seg.sum(dim=0), torch.ones_like(seg[0]))
```

### Alternative Fixes Considered

Equivalent alternative — zero everything first, then set the
background channel:

```python
for l in range(seg.shape[0]):
    seg[l][~Mdilated] = 0
seg[0][~Mdilated] = 1
```

This is functionally identical and arguably clearer about intent
(the one-hot assignment happens last), but the reporter's form is
more localised (single-character edit) and equally correct.

## Verdict

**`plausible`** — The three-line code block exhibits exactly the
logic error the reporter describes; the reporter's fix is correct
and minimal. Severity is `cosmetic` because no user-facing output of
`mri_super_synth` is affected by the bug today, but the fix should
still be applied because the postcondition "`seg` is a valid
probability distribution after postprocessing" is clearly intended
and is currently violated.
