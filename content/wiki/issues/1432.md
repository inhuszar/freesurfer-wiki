# recon-all crash in v8.2.0 when using expert options

> [!issue] Synopsis
> Two trivially-fixable shell-script defects conspire to abort
> [[wiki/pipelines/recon-all|recon-all]] at the surface-registration stage in stable
> **v8.2.0** whenever the user supplies `-expert <file>`. First,
> `scripts/recon-all:4220` guards its `--expert` propagation with
> `if($XOptsFile)` — tcsh's arithmetic `if`, fed a file path, dies
> with `if: Expression Syntax.`. Second, after that is patched,
> `scripts/rca-surfreg` accepts only `-expert` (single dash) in its
> argument parser, so the `--expert` that `recon-all` now passes
> trips the parser's `default:` clause with
> `ERROR: Flag --expert unrecognized.`. Every other flag in
> `rca-surfreg` has both spellings; only `-expert` is missing its
> `--expert` alias. The reporter's two-line fix set is correct.
> Verdict: **plausible**, high confidence, severity high (stable
> release, common flag, hard crash, no workaround without local
> patching).

## Original Report

> Hello FreeSurfer developers,
>
> I encountered two reproducible bugs in the latest update, Stable
> 8.2.0 release (Mar 18 2026), when running recon-all with an expert
> options file on a 0.7 mm 7T MP2RAGE dataset (-hires flag used, run
> on WSL2/Ubuntu 22.04).
>
> ### **Issue 1**
>
> recon-all crashes after mris_sphere because it evaluates
> `if($XOptsFile)`, which expands to the expert-options path and
> triggers tcsh's `if: Expression Syntax.` error.
>
> **Suggested fix**
> Replace:
>
> ```
> if($XOptsFile)
> ```
>
> with
>
> ```
> if($#XOptsFile):
> ```
>
> ### **Issue 2**
>
> After patching the first issue locally, recon-all proceeds further
> but then passes `--expert` to `rca-surfreg`. However, `rca-surfreg`
> currently recognizes `-expert` but not `--expert`, which causes:
> `ERROR: Flag --expert unrecognized.`
>
> **Suggested fix**
> In `rca-surfreg`, add support for `--expert`, e.g.:
>
> ```
> case "--expert":
> case "-expert":
> ```
>
> These issues were reproduced with an expert options file
> containing only `mris_inflate -n 60`. I will also submit a pull
> request with proposed fixes for both issues. Thank you for
> continuing to develop and maintain FreeSurfer.
>
> Best regards,
> Sophocles Goulis

## Agent Analysis

### Relevant Code

**Defect 1 — `scripts/recon-all:4220`.** The `DoSurfReg` stage (lines
`4208–4227`) builds the `rca-surfreg` command line and conditionally
appends `--expert $XOptsFile`:

- **File:** `scripts/recon-all`
- **Function / stage:** `DoSurfReg` (Stage 28 of `autorecon3`, per
  the pipeline-page walkthrough at
  `wiki/pipelines/recon-all.md:874`)
- **Lines:** `4208–4227`
- **Commit:** `d932c45b79`

```tcsh
#----------------                      -------------------#
#---------------- Surface Registration -------------------#
##---------------       -surfreg       -------------------#
#----------------                      -------------------#
if($DoSurfReg) then
  set cmd = (rca-surfreg --s $subjid --threads $OMP_NUM_THREADS \
   --tif-path $AvgCurvTifPath --tif-name $AvgCurvTif)
  if($#hemilist == 1) set cmd = ($cmd --$hemilist)
  if($longitudinal) set cmd = ($cmd --long $longbaseid)
  if($UseNoNeg) set cmd = ($cmd --usenoneg)
  if($JosaReg) set cmd = ($cmd --josa)
  if($ForceUpdate) set cmd = ($cmd --force)
  if($XOptsFile) set cmd = ($cmd --expert $XOptsFile)
  echo "#@# Surf Reg  `date`" |& tee -a $SF |& tee -a $LF |& tee -a $CF
  if($RunIt) then
    echo $cmd |& tee -a $LF
    $fs_time $cmd |& tee -a $LF
    if($status) goto error_exit;
  endif
endif
```

The buggy guard is the sixth of seven sister guards. The preceding
six use numeric/boolean tests (`$#hemilist == 1`, `$longitudinal`,
`$UseNoNeg`, `$JosaReg`, `$ForceUpdate`) that are all either
integer-valued counters or 0/1 flags — safe for tcsh's arithmetic
`if`. Only `$XOptsFile`, which holds a file *path* string, is
unsafe.

The same file already uses the correct idiom `if($#XOptsFile)` in
five other places, confirming the intended pattern:

- **File:** `scripts/recon-all`
- **Lines:** `1142`, `1655`, `8639`, `8672` (plus the guard at
  `1148` for `$GlobXOptsFile`)
- **Commit:** `d932c45b79`

```tcsh
1142:   if($#XOptsFile != 0) then
1148:   if($#GlobXOptsFile != 0) then
1655:     if($#XOptsFile) set cmd = ($cmd --expert $XOptsFile)
8639:     if($#XOptsFile == 0) then
8672:     if($#XOptsFile != 0) then
```

Grep confirms that line `4220` is the **only** occurrence of the
buggy bare `if($XOptsFile)` form anywhere in `scripts/recon-all`:

```
$ grep -nE 'if *\(\$XOptsFile\)' scripts/recon-all
4220:  if($XOptsFile) set cmd = ($cmd --expert $XOptsFile)
```

**Defect 2 — `scripts/rca-surfreg:251`.** The argument parser
iterates over `argv`; every supported flag is listed with both its
`--` and `-` spellings, except `-expert`:

- **File:** `scripts/rca-surfreg`
- **Function:** argument-parser `while` loop
- **Lines:** `180–315` (with the relevant case at `251–257` and
  the `default:` clause at `308–312`)
- **Commit:** `d932c45b79`

```tcsh
while( $#argv != 0 )
  set flag = $argv[1]; shift;
  switch($flag)
    case "--s":
    case "-s":
      ...
    case "--threads":
    case "-threads":
      ...
    case "--josa":
    case "-josa":
      ...
    case "--lh":
    case "-lh":
      ...
    case "-long":
    case "--long":
      ...
    case "--usenoneg":
    case "-usenoneg":
      ...
    case "-expert":                      # ← ONLY -expert; no "--expert" alias
      if( $#argv < 1) goto arg1err;
      set XOptsFile = $argv[1]; shift;
      fsr-checkxopts $XOptsFile
      if($status) goto error_exit;
      set XOptsFile = `getfullpath $XOptsFile`
      breaksw
    case "--force":
      ...
    default:
      echo ERROR: Flag $flag unrecognized.
      echo $cmdline
      exit 1
      breaksw
  endsw
end
```

The `default:` clause is what the reporter's `ERROR: Flag --expert
unrecognized.` comes from. Every other case label is doubly-spelled;
this is a single-character omission.

### Plausibility

Both defects reproduce by direct reading of the cited lines. The
crash trace unambiguously matches:

1. **`autorecon3` flow** reaches `DoSurfReg` right after
   `mris_sphere` finishes (`scripts/recon-all:4212`), consistent
   with the reporter's observation "crashes after mris_sphere".
2. The seven guards inside `DoSurfReg` execute in order. Guards
   1–6 use numeric/boolean conditions and pass safely. Guard 7
   (line `4220`) calls `if ($XOptsFile)` with `$XOptsFile` holding
   an absolute path to the user's `-expert` file (the value is
   established at line `7626`: `set XOptsFile = \`getfullpath
   $XOptsFile\``). tcsh attempts to evaluate the path as an
   arithmetic expression, fails, and emits the exact diagnostic
   the reporter quotes: `if: Expression Syntax.`
3. With `:4220` patched to `if($#XOptsFile)`, the if-guard
   evaluates the array length of `$XOptsFile` (1 after a `-expert`
   call, 0 otherwise) and correctly appends `--expert $XOptsFile`
   to the command line.
4. The constructed command line is
   `rca-surfreg ... --expert <path>`. `scripts/rca-surfreg`
   enters its `while`/`switch` loop, and for the `--expert` token
   falls through every enumerated case label (all of which are
   double-dashed for double-dashed flags and single-dashed for
   single-dashed flags; `--expert` matches none of them) and hits
   the `default:` clause at line `309`, emitting `ERROR: Flag
   --expert unrecognized.` — verbatim the reporter's second error.

Scope:

- **Defect 1 is the only place in `scripts/recon-all` that guards
  `$XOptsFile` incorrectly** (grep above), so patching line `4220`
  resolves the first crash without needing a broader sweep.
- **Defect 2 affects all callers of `rca-surfreg` that pass
  `--expert`.** The only such caller in the tree is
  `scripts/recon-all:4220`; `scripts/xhemireg:313` calls
  `rca-surfreg` but without `--expert`, so it is not affected.

Neither defect is specific to the reporter's `-hires` flag or to
`mri_inflate -n 60` as the expert-options content; any non-empty
expert options file would trigger Defect 1, and any
post-Defect-1-patch invocation would trigger Defect 2.

## Recommendation

Apply both fixes as proposed by the reporter. They are
independently minimal and independently correct.

**Patch 1 — `scripts/recon-all:4220`** (one character):

```diff
   if($ForceUpdate) set cmd = ($cmd --force)
-  if($XOptsFile) set cmd = ($cmd --expert $XOptsFile)
+  if($#XOptsFile) set cmd = ($cmd --expert $XOptsFile)
   echo "#@# Surf Reg  `date`" |& tee -a $SF |& tee -a $LF |& tee -a $CF
```

This matches the convention already used at
`scripts/recon-all:1655` for the same `--expert $XOptsFile`
append, and at `:1142, :1148, :8639, :8672` for every other
`XOptsFile`/`GlobXOptsFile` guard.

**Patch 2 — `scripts/rca-surfreg:251`** (one case label):

```diff
     case "-dontrun":
     case "--dontrun":
       set RunIt = 0;
       breaksw

+    case "--expert":
     case "-expert":
       if( $#argv < 1) goto arg1err;
       set XOptsFile = $argv[1]; shift;
       fsr-checkxopts $XOptsFile
       if($status) goto error_exit;
       set XOptsFile = `getfullpath $XOptsFile`
       breaksw
```

This matches the double-/single-dash pairing that every other case
label in the same switch statement already uses.

No test change is strictly required, but the smoke test is
trivial:

```bash
touch /tmp/xopts.txt
echo "mris_inflate -n 60" > /tmp/xopts.txt
recon-all -s SUBJ -all -hires -expert /tmp/xopts.txt
# Expected: the DoSurfReg stage runs rca-surfreg to completion with
# --expert /tmp/xopts.txt instead of crashing at line 4220 or in the
# rca-surfreg parser.
```

### Alternative Fixes Considered

- **Alternative for Defect 1**: use `if ("$XOptsFile" != "")` (the
  string-comparison form). Functionally equivalent to
  `if($#XOptsFile)` once `$XOptsFile` is either empty or a single
  path; the array-length form is preferred because every other
  guard in the same file already uses it and consistency aids
  future maintenance.
- **Alternative for Defect 2**: change the caller at
  `scripts/recon-all:4220` to pass `-expert` (single dash) instead
  of adding the `--expert` case to the parser. Also
  functionally correct, but it is inconsistent with
  `rca-surfreg`'s double-dash convention for every other flag —
  adding the alias is the idiomatic choice and also future-proofs
  against any other caller that passes the double-dash form.

## Verdict

**`plausible`** — two independent, co-reported shell-script defects
that together abort `recon-all -expert <file>` deterministically in
stable v8.2.0. Both are verified by direct reading of the cited
lines at commit `d932c45b79`, and the reporter's proposed fixes are
the minimal idiomatic corrections that match the surrounding code's
conventions. Severity **high** because this is a hard crash in a
stable release on a commonly-used flag combination (`-hires` +
`-expert`), with no workaround available short of local patching.
